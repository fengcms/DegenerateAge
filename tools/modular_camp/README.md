# 模块化营地结构实验场

这是51号方案的可运行模块化实验场，现已接入首批写实地面、道路、墙、树和棚屋；尚非完整美术包。不加载整图背景，不修改正式地图或存档。

从仓库根目录运行：

```sh
python3 tools/modular_camp/launch.py
```

依赖Python3与Godot4。启动器优先使用PATH中的godot，macOS回退到/Applications/Godot.app。启动时创建临时项目，复制现有Iso、FlatTileMesh、CaveLayout源码与所需运行素材，导入后运行，关闭后删除临时项目。无需安装Python第三方库。

- Tab：切换同一资产包拼出的两种16×16格布局。
- 左键：使用既有CaveLayout路径和平滑算法移动至可达目标。
- WASD：直接移动，真实CharacterBody2D半径12碰撞。
- B：显示布局同源碰撞区域。
- M：移动一段墙，同时重建该小样板布局、碰撞、物件位置和导航，清空旧路线。

角色只是静态表现，不代表行走动画。墙/树/棚屋的美术轮廓与占地仍需精修匹配；门洞是墙段之间的通行间隙，不是棚屋室内。

## 数据与实现

`layouts.json`为两份样板的道路行和物件位置事实源。物件种类、占地、视觉尺寸在main.gd的DEFINITIONS中集中维护。道路按八邻接规范化成47种形状，基础和道路各一个合批网格。物件按世界Y排序；占地生成物理菱形和CaveLayout输入。未另写寻路或战斗系统。

每次加载/布局切换重建256格场景，属于开发样板，尚非正式地图局部编辑系统。运行中无地面逐格重绘或纹理重复加载。临时项目的compiled_layout.json只在切换布局时写入，与玩家存档无关。

## 验证

```sh
python3 tools/modular_camp/launch.py --verify
python3 tools/modular_camp/launch.py --verify --capture /tmp/modular-camp-review
```

检查256邻域规范化与47种形状、固定随机排列相邻道路边的alpha连续性、两布局256格通行与碰撞一致性、真实物理长路径、门洞通行、墙体正面阻挡、绕墙到达以及移动墙后旧格释放/新格阻挡/旧路线清空。

成功必须出现 `MODULAR_CAMP_VERIFY_OK`；断言失败或超时不算通过。截图为真实Godot窗口输出。headless结果不用于证明画面或GPU性能。

## 2026-11-17：写实首批试装

当前默认已换用 `assets/environment/camp_modular_v1` 的土壤、夯土道路、短墙、树、棚屋；木箱仍沿用旧素材。构建前请保留源稿目录：

```sh
python3 tools/modular_camp/launch.py --build-assets
```

地面4×4周期相位对应16块，不应随机置换；道路47形状×16相位与地面共用1024×1536图集。构建在离线执行，进入样板只加载运行图集。新增检查全部768图集格的中心与透明角。棚屋占地从结构阶段2×2调整为4×4；仍是封闭外部建筑，不表示可以进入门内。

## 草土层与墙角更新

两套布局新增独立grass行数据（与roads互斥）、另一轴向墙段与一种L墙角。三层地面分别合批，草土渐变宽于道路渐变。保持原Tab、B、M、点击和WASD操作。

验证同时覆盖两图集共1536格中心/透明角、两套边宽共边连续、草路互斥、全部原物理与导航断言。带--capture时增加树前后定点截图与脚底z顺序断言；这些定点截图只验遮挡，不冒充人物从树后走到树前的动画录屏。

## 局部遮挡淡出与贴花

每布局新增12处草根/碎石贴花，仍是16×16格。树与棚屋添加SampleOccluder：人物在其后方且头身区域与上部不透明像素重叠时，在人物附近约0.2秒淡出；前方或离开时恢复。只改上部局部alpha，不取消碰撞。使用人工轮廓蒙版保护主干、根部、墙面与门柱；没有室内或登屋顶玩法。

`--verify --capture`会让物理角色实际寻路到可通行的遮挡点，再截图检查；另定点检查恢复、远处不误触发、导航版本及碰撞数量不变。仍保留全部道路、图集、物理绕障测试。角色动画依然是静态占位，不能把物理移动录像当成新动画验收。

## 轮廓蒙版维护

`occlusion_regions.json`以运行图片左上角为原点，单位为像素：size约束图片尺寸，include定义允许淡出的多边形，protect定义优先保护区，protected_samples与reveal_samples用于构建检查。build_assets.gd将区域与源图可见像素相交，生成tree_reveal_mask.png及shelter_reveal_mask.png。换图时必须重新审查轮廓；尺寸和抽样检查不能识别所有同尺寸美术变化。

运行时CPU探测与shader使用同一蒙版；淡出仍只作用于人物附近。它不是拆分出的独立树冠/屋顶美术，也不会修改碰撞。截图模式额外输出相同人物位置的*_opaque.png和*_reveal.png用于对照，*_restored.png验证恢复。两套布局依次验收，遮挡截图同名文件最终保留后一套。
