# 模块化营地真实战斗场

`python3 tools/camp_combat/launch.py` 打开可操作场景。WASD移动、点击敌人追击、F自动战斗、G自动拾取、R重开。两只怪物击败后可继续移动探索；R会重新创建本场临时角色。使用现有800经验成长到三级的演示角色，不读取真实存档。

`--verify` 运行无窗口完整战斗；`--verify --capture /tmp/camp-combat-review` 运行窗口并采集战斗/结束画面。要求正式追击发生位移、两怪被正式攻击击杀、玩家被反击、掉落拾取和金币入账、经验变化、死亡后释放以及成功标记。源码和数据复制进临时项目，资产也复制，避免导入元数据写回仓库；项目随机身份与user目录退出清理。

场景复用 PlayerCharacter、Monster、AutoBattle、Combat、Loot、GroundItem 和 GameState.pickup_loot，未复制战斗规则或改正式地图。地面是模块化样板，ground.gd只把同一CaveLayout交给现有导航接口。art.gd继承正式表现接口，攻击从接触帧开始以对齐即时伤害，死亡结算立即发生，原有清理流程等待0.90秒倒地再淡出。

主角、腐化野狼和裂壳虫均已接入八方向的待机、行走、攻击、受击、倒地。两类怪物共80张运行图集，七个新增方向独立生成，不镜像伪造方向。源稿不进入运行依赖。本场暂未接坐骑、打坐、技能专属外观或正式地图迁移，缺口不影响本次普攻闭环验证。

预算：一玩家、两怪物、两遮挡对象；图集区域按种类在装配期缓存，实例只切引用，切图释放节点，进程退出释放共享纹理。热路径无加载/裁图/逐帧全图寻路，攻击和拾取保持正式调用频率。性能验收使用下述正常窗口三轮实战，具体实测见素材设计93号记录。

`--soak` 连续完成三次真实战斗与场景重开，逐轮检查掉落清空、尸体释放、结束节点数一致，记录实际绘制帧、帧间隔分位数和内存。不可与截图并用，窗口未持续绘制或任一轮失败不得通过。三轮是短时重复进入验收，不代表长时间挂机覆盖。

`--review --capture /tmp/camp-art-review` 输出三种角色的八方向×五状态原尺寸对照表，共四个动作阶段、12张图；与实战共享图集加载入口。`python3 tools/camp_combat/check_assets.py` 检查两类怪物80张图集的尺寸、来源和方向完整性。

## 外围连续路线

`python3 tools/camp_combat/launch.py --route` 启动64×16格外围路线，三级角色从安全营地出发，穿过三处窄口，遭遇三组狼/甲虫，再返回营地。顶部按钮发送正式寻路移动指令；F自动战斗，X或休整按钮调用原有恢复规则，R重新开始。休整暂用待机外观，HUD显示状态。

route_layout.json维护土草路、独立物件及占地；route_map.json维护独立ID camp_route_trial、安全矩形[0,0]～[10,15]、六个刷新点、60秒刷新和普通怪上限10。两者尺寸一致64×16；主路y=7/8，窄口x=12/28/45、y=6～9。刷新点由正式MonsterSpawner装配、统计预算及计时，实际活动数取决于距离。此配置仅追加到隔离进程内存，不写入正式data/maps或存档。

`--verify-route` 以真实移动完成三组战斗和返营，`--verify-route --capture /tmp/route-review` 在窗口复核返回画面。`--controls` 验证正式玩家绕箱、移动接管、受击恢复和死亡复活。`--stress-route` 使用12刷新点、普通怪上限10、额外30000经验的独立测试角色，持续120秒战斗并重新开场；与普通三级路线难度分开，不修改正式模板。

成本：1024地块仍为三层网格，不逐地块建活动节点；物件占地同步生成碰撞与导航，静态贴花共用图集。遮挡仅遍历本场8个棚屋/树对象，HUD5Hz更新；刷新器复用每轮预算快照，图集缓存按3种角色共享。性能、首轮尖峰定位边界和完整验证见95号交付记录。
