# 步行出口路标美术设计方案

本文件评估地图间步行出口的现状，并提出一套可先做样图、确认后再接入的视觉方案。调查日期：2026-10-21。本轮只分析与设计，不制作或替换运行素材。

## 现象与实测依据

玩家看到的“切图 NPC”实际是 `TravelExit`，不是角色 NPC。`scripts/world/travel_exit.gd:51-61` 用矩形、直线和箭头现场绘制牌面，`10-24` 行另建动态目的地标签；因此主体边缘平滑、形状扁平，缺少与现有像素建筑一致的体积、磨损和等距透视。`scripts/world/game.gd:240-248` 依据地图配置逐个创建出口，交互时仍由 `MapService.request_walk()` 决定能否切图；美术可以独立替换，不必改变拓扑、位置或切图规则。

对当前 `data/maps/ch*/*/map.json` 的只读统计：**38 张地图、74 个步行出口**，每图 1–3 个；其中 **21 个出口配置了本方向的 `requiresUnlock`**。所有 74 个都有格坐标。`scripts/world/travel_exit.gd:34-36` 的当前点击范围是局部 `76×84` 像素；`autoload/map_service.gd:21, 414-435` 的交互范围是 1.5 逻辑格，抵达后还有 1000 毫秒防误返冷却。上述是代码和配置事实，不是窗口视觉实测。

视觉状态还有一处接入前需解决的口径差异：当前标签只按目的地图 `MapService.is_unlocked()` 改文案（`travel_exit.gd:38-49`），最终切图还会检查本方向出口锁和目标入口门禁（`map_service.gd:417-423`）。如果美术直接沿用标签判断，可能出现“发亮可用、点击却被拒绝”。状态应来自同一条出口的实际可用判定，不能只看目的地图。大地图/小地图标记仍须保持步行出口与车夫有别，见 `docs/游戏创意/08-免费步行与车夫直达详细产品方案.md` 第 9 节。

## 建议：一套“行旅界碑式路标”

**选择低矮路标，不做人物 NPC，也不做传送门。** 步行出口是免费道路的末端；传送门会暗示魔法传送和一个需要穿过的门洞，人物 NPC 则会暗示对话。界碑用明确的双向箭形铭牌告诉玩家“这里连接另一张地图”，保留当前地图标记的双向箭语义；目的地名称、等级和封锁原因继续用代码文字显示，**不烘进图片**。

主体是一根略倾斜的旧木/铁立柱，顶端钉着短而厚的双向箭形牌，脚下是一块不规则石座。牌面不是屏幕正对的长矩形：上沿、右侧厚度和石座按照游戏 **64×32 的等距地面**画成 45 度俯视。纹理以旧木褐、灰石、少量暗铁为主，局部用一小块清楚的浅色箭形镶片提高辨识度；不使用大面积荧光绿边框、矢量轮廓或模糊光晕。它与营地木建筑、野外土路相容，在洞穴和工业地图也能作为人工留下的导路标识。若样图在后期地图明显不协调，只替换石座或金属包边的小层，核心轮廓和读图方式不变。

| 部位 | 建议规格 | 原因 |
|---|---|---|
| 运行画布 | 64×64 透明 PNG；主体约 44–52 像素宽、48–55 像素高 | 与现有 76×84 点击范围、角色和 64×32 地面规格接近；尺寸以同屏样图复核后定稿 |
| 锚点 | 画布底部中央约 `(32,60)`，石座接地阴影为扁菱形 | 落在当前出口格中心，不让直立物漂浮 |
| 状态 | 常态、靠近、封锁三种表现；同一主体复用 | 常态清楚但克制；靠近只增强箭形镶片；封锁加缺口/小锁片并降低亮度，不能仅靠颜色区分 |
| 文字 | 目的地名常显；靠近时显示 `E`、推荐等级或封锁原因 | 动态数据与本地化仍由代码绘制；长中文名不得挤到牌面 |
| 动效 | 可先无循环动效；靠近时最多做 2–3 帧轻微亮度变化 | 74 个配置点共用少量纹理，避免大量常驻动态节点 |

车夫继续是人和马车/车轮的交通服务，路标只表示免费步行出口。若一个地点有两条出口，仍是两根独立路标、各自对应现有 `exit_id`；不把两条数据压进一块牌，避免点击目标含糊。

## 与现有实现的衔接

1. 先画 **营地→试炼野外** 和 **腐化源头→灰烬之地** 两处的同屏样图，分别验证浅色土路与暗洞穴背景。附 1:1、2× 和带玩家的预览；先确认轮廓、尺寸、标签位置，再制作运行图。
2. 接入时只在 `TravelExit` 中以共享纹理替换 `_draw()` 的几何箭头，并保持最近邻采样。`Game._spawn_exits()`、地图 JSON、入口落点、1.5 格交互距离和 `request_walk()` 规则不动。视觉对象不新增实体碰撞：路标所在格目前可走，若给石座加碰撞，会制造“看得见出口但走不到交互格”的风险。
3. 将标签置于牌顶上方，随世界文字倍率调整；点击区域覆盖真实路标主体，并核对放大倍率下不会误点旁边 NPC/怪物。状态读取要统一本方向出口锁、目的地图锁和入口门禁；封锁时仍可读目的地及原因，不制造“可用”假象。近距只点亮当前最近的一个出口。
4. 样图通过后，一次接入全图共享资产。对营地双出口、野外单出口、洞穴回程、后期三出口、已解锁与封锁状态分别做窗口截图。运行 `SmokeTest` 与地图/切图相关测试，实际走通正反向路线，验证任务自动导航、点击与 `E` 键、抵达防误返、小/大地图标记以及 0.8/1/1.5 地图倍率。

## 取舍与验收

这一方案的优势是语义明确、素材数量少、对现有规则侵入小；代价是单一木石材质在高等级异质地图可能需要少量外观变体。故先用最难兼容的浅营地与暗洞穴做同屏样图，确认视觉语言后再扩展。**本轮不建议直接为 74 个出口逐一生成独立素材**：它们指向不同地图，但交互职责相同，文字已能提供目的地区分。

样图验收以实际窗口为准：玩家在行走时能在地面上找到路标，1:1 像素边缘清楚，斜向厚度与地面投影一致；牌面文字不被地图物体或世界提示盖住，封锁状态一眼可辨；点击和键盘交互仍能准确触发原有逻辑。加载、纹理占用及帧时间须在接入阶段实测，本文件不据画布尺寸宣称性能提升。
