# 模块化营地双怪待机实机采样记录

2026-11-18，在dc4202a4的临时隔离快照中比较两类怪物待机开启/关闭的显示成本。只保留结论，临时探针不进入运行项目或仓库。

## 采样口径

Godot 4.7.2，OpenGL Compatibility，Apple M1 Max，1280×800窗口；关闭垂直同步、解除FPS限制。每套布局按“关闭→开启→关闭”顺序，每段预热0.75秒，再采样3秒，覆盖3fps四帧待机的两个完整循环。场景含一个静止主角、两只怪物、现有地面/物件与新木箱木桶，不截图、不移动、不读写存档。初次240帧短采样未覆盖完整待机周期，因此不用于结论。

在RenderingServer.frame_post_draw之间使用Time.get_ticks_usec记录墙钟间隔，并读取Performance的绘制调用、节点数与纹理内存。此数值是窗口渲染帧提交间隔，含CPU调度等影响，**不是独立GPU执行耗时或显示器实际呈现帧率**。未做正式密集战斗和长时间挂机。

## 结论与限制

本次两个怪物的待机开关没有增加绘制调用或节点数，帧提交间隔中位数相近。开启数值略小属于噪声范围，**不能解读为开启动画提升性能**。院落关闭前测出现73.429ms单次尖峰，原因未定位；因此不能以较小中位数宣称始终稳定60FPS。

当前样板使用共享图集、只切换纹理区域，没有逐帧文件读取、纹理生成或地图重建。对这两个实例未观察到持续性提交间隔恶化；结论不外推到正式游戏、更多怪物、战斗AI或GPU峰值。若后续扩大实例数，应重新采样并定位尖峰，而不是直接乘本次平均值。

复核需对相同提交创建临时隔离项目，保持窗口、视角、动作状态与顺序一致；预热后以至少3秒窗口采集frame_post_draw间隔，输出原始样本量及中位/P95/最大值，同时记录节点、绘制调用和纹理内存。截图和PNG编码应在采样之外执行。
