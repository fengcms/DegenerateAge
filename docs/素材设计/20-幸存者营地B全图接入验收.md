# 幸存者营地 B 全图接入与验收

本记录对应既定计划的**第三节点**。正式营地现加载 B 风格的分层地图。原来的参考画布为 1672×941、游戏世界为 3200×1800、通行网格为 110×110；地图尺寸、NPC 配置、7 个实体足迹和 15 段既有围栏/岩带碰撞均未改动。地图的唯一布局源仍为 `data/map_art/camp_whitebox_v1.json`，可通行性仍由原导航与原碰撞决定。

## 产物与取舍

- [全图运行清单与素材](../../assets/maps/camp_style_full_b/)：一张 1024×1024 的 B 地纹循环图集，一张 1672×941 的透明道路/贴地阴影层，以及与原布局逐条对应的 22 个整体美术对象。铁匠铺、货郎摊、仓库、镇灵灯、长老树、马车、火堆均有像素互斥的背层和前沿层；围栏与岩带按原障碍的每一段整体制作，没有拆成单格瓦片。
- [美术源图](../../art_source/environment/camp_style_full_b/)和[可重建工具](../../tools/build_camp_style_full_b.py)：源图仅用于制作，运行时只读取清单列出的 PNG。新地纹以 512×512 有效图像镜像成 1024×1024 循环图集，解决小样板地纹直接铺满全图时显眼的周期重复；道路留在单独的真透明层。首次生成全图概览后，把长老树树冠改为向左舒展，保持树根锚点与碰撞不动，使仓库侧既有可走路线上的角色可辨。
- [固定全图概览与四条实走截图](样板/幸存者营地B全图/)：覆盖仓库/长老树、镇灵灯、马车、训练场火堆。概览用于检查整体构图，四张实际运行截图用于检查玩家、NPC 与前沿遮挡。

源图由 OpenAI ImageGen 在本项目中生成；构建工具使用 ImageMagick 并复用已验收 B 样板的部分实体。所有结构性位置都取原白盒数据，不让贴图反过来改通行、NPC 或障碍。

## 功能与视觉自检

[CampFullArtAcceptanceTest](../../tests/CampFullArtAcceptanceTest.tscn)在正式 `Game` 场景验证地图矩形和网格、全部 22 个原碰撞体/美术对象、7 个整体实体的前沿/背层互斥、独立道路层 alpha、5 个 NPC 的配置坐标，并扫描原多边形内的 **1155 个格心**均不可走。玩家分别沿仓库、镇灵灯、马车和训练场火堆周围的真实导航路线移动，行程约 **917 / 316 / 1024 / 226 世界像素**，每物理帧确认脚底在可走格，四条路线均抵达目的地。实际窗口复核截图中，角色没有立在屋顶、树枝或岩带上；前沿遮挡按脚底深度覆盖角色。此检查并不宣称已覆盖玩家所有可能路线，后续视觉微调仍以同一测试为基础。

地图相关回归均通过：`CampFullArtAcceptanceTest`、`CampLiveIntegrationTest`、`MapTextureBatchTest`、`ChapterOneMapArtTest`、`CampStyleTraversalTest`、`CampStyleSampleTest`。原白盒的 9 个目标仍可达；实际窗口的全图测试和 `MapRenderBenchmark` 也通过。曾尝试跑全仓库测试；它在共享工作区遇到 `Guardian display scale keeps foot pivot`、`Unmade icons must preserve fallback` 两项与本地图无关的旧断言，随后因用时较长停止。单独的 `SmokeTest` 还因另一个任务正在编辑的第三章地图/怪物、装备数据交叉引用报错，因此本次**不宣称全仓库绿灯**，也没有把那些数据文件混入提交。

## 运行成本与限制

本全图新目录含 25 张运行 PNG，文件总量约 **3.3 MiB**；按 RGBA8 原始像素计算约 **22.64 MiB**，其中部分图层为透明像素。它还引用 B 样板的铁匠铺、货郎摊、北西围栏和西侧岩带资源；这两个数字都不是完整游戏显存。原 B 局部样板 A/B 的 100%–200% 清晰度、加载、帧时间与纹理监视器实测见[第二节点规格](19-幸存者营地B全图生产规格与实测.md)。

在同一 macOS Retina 设备、GL Compatibility、1280×800 逻辑窗口上，使用未接入全图的已提交快照和本工作区分别跑两轮 `MapRenderBenchmark`。测试固定为正式主场景的营地，冻结玩法，140 个真实绘制帧中先预热 20 帧：

| 指标 | 旧正式图两轮 | B 全图两轮 | 代价 |
| --- | ---: | ---: | ---: |
| 正常画面帧间隔中位数 | 1.025 / 1.049 ms | 1.316 / 1.198 ms | 增加约 0.15–0.29 ms |
| 正常画面 P95 | 1.198 / 1.341 ms | 1.577 / 1.357 ms | 增加约 0.02–0.38 ms |
| 平均绘制调用 | 169.2 / 169.2 | 225.2 / 225.2 | 增加 56 次 |
| 正式营地场景装配 | 60 ms（旧图一次） | 77 / 76 ms | 约增加 16–17 ms；样本少 |

这些帧间隔的轮次波动较明显，不能据此预测密集战斗 FPS；60 FPS 的整帧预算仍应在实际玩法中持续复测。场景装配数字只计导入已完成后的进程内装配，不等于冷盘启动。全图没有增添逐帧生成工作；加载一次装配静态实体，切图后随场景释放。若未来扩充围栏细节或动态特效，先复测绘制调用、纹理监视器与战斗帧时间，不能只依据 PNG 体积判断成本。

目前各段围栏按原不可走多边形生成，能维持玩法边界；几处直立短段的装饰细节比手绘焦点实体更简洁。若后续再精修这些短段，只替换清单中的对应透明整体图，复跑实走与性能基准，不改白盒事实源。
