# 统一面板 UI 视觉修复验收记录

日期：2026-10-15。按已确认的[修复方案](06-统一面板UI视觉修复方案与防偏差原则.md)，本轮修复共用面板外框、标题圆钮与操作按钮的视觉偏差，不调整物品、设置或 NPC 的业务规则。

## 本轮结果

| 原问题 | 修复与复核结果 |
|---|---|
| 帮助和关闭按钮为椭圆 | 标题按钮改用含符号的正方形 SVG 纹理；实际按钮分别为 36×36、40×40，标题行变高时不再纵向拉伸。新增 `PanelChromeLayoutTest` 在高标题行验证最终尺寸。 |
| 四角金线为直角 | 共用外框的四个内侧角饰改成“短竖—斜段—短横”折线，窗口长边伸缩不拉伸角部。 |
| 操作按钮缺少高光 | 从用户修订 SVG 的三段渐变与上沿高光制作局部运行素材；普通、主要、悬停、按下、禁用状态均使用同一层级结构，文字仍由 Godot 动态绘制。标题带也恢复纵向渐变。 |
| 标题下出现多条线 | 标题线由 `PanelChrome` 绘制一次；背包、人物、技能、坐骑、设置、商店、铁匠在原位置只保留布局间隙。背包摘要等内容分组线仍保留；任务和车夫在 NPC 介绍下方的内容分组线也保留。 |

运行素材位于 [`assets/ui/panel_chrome`](../../assets/ui/panel_chrome/README.md)，可由 [`tools/generate_panel_chrome_assets.py`](../../tools/generate_panel_chrome_assets.py) 重建。SVG 导入比例为 2.0；按钮端部按九宫格保形，中段随动态文案伸缩。

以下为 Godot 4.7.2、1280×800 窗口、100% UI 倍率下的独立面板实机渲染。背景使用纯色以突出框体；背包为默认空包状态，非完整世界场景截图。

- [背包运行预览](样板/统一面板UI-v1/背包-修复后运行预览.png)：检查四角、圆钮、标题分隔和长短操作按钮。
- [人物运行预览](样板/统一面板UI-v1/人物-修复后运行预览.png)：检查共用外框在较宽面板上的拉伸。
- [设置运行预览](样板/统一面板UI-v1/设置-修复后运行预览.png)：检查共用标题、关闭按钮和页签衔接。

另以 150% 等比缩放目视检查背包组件，圆钮、角饰与按钮端部未见拉伸变形。该独立预览没有模拟完整游戏的 200% 自适应布局，因此不能替代玩家在目标分辨率下的最终目视验收。

## 验证

- Godot 项目重新导入新增 SVG，脚本与资源加载无错误。
- `PanelChromeLayoutTest`：通过。它使用比常规标题更高的标题行，检查按钮**最终尺寸**仍为正方形。
- `SettingsTest`、`MenuFlowTest`、`HotbarUiTest`：通过，覆盖设置、菜单和快捷栏关联行为。
- `SmokeTest`：先有一次自动拾取优先级断言失败；随后单独重跑通过，未改动相关游戏逻辑。用改动前已提交快照再跑也通过。该断言存在一次未定位的间歇失败，不能据此宣称广泛回归始终稳定。
- 操作按钮的渐变、角饰和分隔线已经在上述实际渲染截图中核对；自动化布局测试不冒充像素级视觉验收。

仍需由玩家在真实游戏画面中检查不同 UI/文字倍率、浮窗并排、NPC 服务以及各按钮的悬停、按下、焦点表现；若与确认稿仍有可见差异，应按[防偏差原则](06-统一面板UI视觉修复方案与防偏差原则.md)记录并继续修正。
