# 营地真实战斗闭环接入

## 问题与实现

此前F8是真实试走，但样板没有真实伤害、AI和奖励。本次直接装配正式Player、Monster场景；AutoBattle驱动Player的既有追击和攻击，Monster使用既有AI，死亡走原经验/掉落/地面物结算，拾取走GameState入口。800经验通过既有成长函数生成三级演示角色，不改正式角色或怪物模板。

样板墙、屋、树与通行掩码沿用模块化营地，IsoGround子类只提供已有导航接口。表现适配器继承MonsterActorArt，宿主攻击/受击/死亡事件进入新图集；攻击从接触阶段开始，与原即时伤害同帧，不增加前摇。死亡仍立即结算，倒地0.90秒后由原Monster流程淡出释放。玩家步态按真实位移，图集缓存按种类持有。

初次接入发现Monster场景默认ai_enabled=false，正常由Spawner开启；样板装配显式开启后反击检查通过。另修正适配器局部变量类型推断错误。正式游戏源码未改。

## 实测

Godot4.7.2。无窗口完整闭环：两怪死亡、19次正式攻击事件、4次拾取、金币14；GL Compatibility窗口：两怪死亡、19次攻击事件、3次拾取、金币15，主角由134血降至约104后恢复。数量差异来自正常掉落随机，不改掉落表或把奖励固定。

两次均输出CAMP_COMBAT_VERIFY_OK且无脚本错误，验证实际移动、反击受伤、经验变化、拾取入账和死亡释放。窗口抽查可见血条、目标圈、挥剑与怪物，地形由独立模块构成。临时截图只用于检查，按仓库规则清理，可用启动命令重新采集。

## 限制与后续

两怪目前仍只有左前方向美术，屏幕明确标识，正在补方向；不会把单方向表现称为完整美术验收。头顶信息与角色比例继续精修。当前只两怪普攻场，不代表技能、满预算遭遇、长期挂机或正式地图迁移通过。

隔离启动器复制代码/数据/资产，随机项目名隔离user://并清理；没有修改真实存档、NPC、地图配置、装备和掉落概率。复核与操作方式见tools/camp_combat/README.md。
