# 装备穿戴等级角标显示方案

本文分析背包和人物面板中装备等级难以辨认的问题，给出显示方案，并记录落地后的验证情况。

## 现象与证据

61 级以后的装备复用既有素材，仅看图标无法判断具体穿戴等级。玩家需要悬停查看详情；在背包中挑选、人物面板中核对装备时，这增加了重复操作。这个体验结论来自玩家试玩反馈，尚未通过用户测试量化。

代码核对结果：

| 位置 | 当前事实 | 对方案的意义 |
| --- | --- | --- |
| `scripts/systems/item_factory.gd` | 61 级起动态装备复用模板，但实例带有 `requiredLevel`；十级一档内按部位偏移生成具体穿戴等级，如武器 61、鞋 62。实例等级上限为 9999。 | 角标应读取**装备实例的 `requiredLevel`**，不能读取复用模板的等级、物品 ID、怪物等级或套装档位。 |
| `scripts/systems/equipment.gd`、`scripts/systems/item_util.gd` | 穿戴门槛和装备名称均已使用实例 `requiredLevel`。 | 新角标与现有规则可保持同一口径，不需要新增物品字段或改存档。 |
| `scripts/ui/inventory_panel.gd`、`scripts/ui/character_panel.gd` | 背包格使用 `ItemSlot`，人物装备格使用其子类 `EquipmentSlot`；两者常规格子均为 52×52。 | 可以在公共格子绘制层实现，一次覆盖两处；数据变化后沿用现有格子刷新。 |
| `scripts/ui/item_slot.gd` | 左上已有收藏星标，右上已有更强装备箭头，左下可能出现合成「已选」，右下数量仅在 `count > 1` 时显示；装备数量为 1。 | 右下角最适合放穿戴等级，且不需要挤占现有三个角。 |
| `scripts/systems/settings_runtime.gd` | 界面缩放与文字缩放是两条轴，文字最终倍率由现有 `SettingsRuntime` 应用。 | 角标文字须纳入相同缩放流程，不能用固定像素字体绕开设置。 |

根因属于**显示信息缺位**：装备实例已有准确等级，但格内只显示图标、品质及部分状态角标。并非装备等级数据错误或素材加载错误。

## 推荐交互与视觉规则

1. 在**所有装备**的背包格和人物装备格右下角显示实际穿戴等级的纯数字，如 `61`、`64`。统一规则比“仅 61 级以上显示”更容易理解，也能在背包与人物面板间保持一致；普通物品和空槽不显示。
2. 数字位于紧贴右下角的小方块中，底色为约 75% 不透明的黑色，白色或浅灰文字；不使用品质色，以免和品质框混淆。外边距、内边距及圆角保持极小，让装备图标仍是视觉主体。
3. 角标贴格子内侧右下，随数字位数自适应宽度，覆盖 1—9999 级；不能把宽度写死为只容纳两位数。52×52 的基准格先以两位数约 18—22 逻辑像素宽为样稿，四位数按实际字体测量扩展，并检查仍可辨认图标。高度以一行数字加少量上下留白为准。
4. 装备右上角已有的绿色或灰色升级箭头继续表示“比当前穿戴评分高以及是否达到穿戴等级”；右下数字只表示“需要达到的等级”。两种提示不得互相替代。
5. 悬停详情中的 `Lv`/“需要等级”继续保留完整文本，供核对。角标作为快速扫描信息，不承载能否穿戴、品质、强化星级等其他含义。
6. 拖拽时的物品跟随图像也应显示同一角标，让拿起和放下前后的视觉一致。仓库、商店和铁匠若复用 `ItemSlot`，建议统一显示；若局部格子小于 52×52，则按该格尺寸检查角标及图标遮挡，不能直接沿用固定宽度。

建议示意（仅表示位置，非最终美术）：

```text
┌──────────┐
│★       ↑ │
│  装备图标 │
│已选   ▣61│
└──────────┘
```

## 实现路径与边界

- 在 `ItemSlot` 中增设只读显示角标，内容在 `item` 赋值时刷新。条件仅为 `item.kind == "equip"` 且 `requiredLevel >= 1`；空槽、药品、材料和金币隐藏。人物面板的 `EquipmentSlot` 自动继承，不另做一套等级推算。
- 等级采用 `Equipment.level_req(item)` 或直接读取同一实例字段，绝不从 `itemId` 的模板查等级。异常数据不显示虚假的默认 `1`，在数据校验处处理异常；UI 可隐藏角标并保留日志/测试可定位性。
- 角标背景与文字作为一个不接收鼠标的控件，不抢格子的悬停、点击和拖放。控制绘制顺序，确保角标压在图标上，但拖动原位的遮罩仍能盖住它。
- 角标控件只在格子创建时建立一次；装备变更、背包移动、换装时只改文字与显隐。无需每帧更新，也无需独立缓存。实例/设置变化按现有 `inventory_changed`、`equipment_changed`、`settings_changed` 路径刷新；拖拽副本同样使用实例数据。
- 字号基于格子逻辑尺寸和现有文字缩放系统设置，验证界面与文字各为 100%、150%、200% 时不裁字、不溢出。特别注意两条缩放轴叠加时不可将字体重复放大。
- 本改动只增加视觉信息，不改变装备生成、强化、合成、穿戴门槛、评分、掉落与存档结构。

## 验收清单

| 场景 | 预期结果 |
| --- | --- |
| 背包中 61 与 64 级装备使用相同图标 | 分别显示 `61`、`64`，且与详情页穿戴等级一致。 |
| 人物面板已穿戴装备；背包与人物面板间换装 | 角标随**装备实例**移动，空槽无残留数字。 |
| 低等级装备、高等级未达标装备、收藏/合成已选装备 | 数字正确；右上箭头、左上星标、左下“已选”均可辨认。 |
| 拖拽装备、仓库存取、商店/铁匠相关格子 | 跟随图像及目标格的数字一致，不阻断投放。 |
| 非装备、空槽、数量大于 1 的可叠加物品 | 无等级角标；原有右下数量保持不变。 |
| 100%、150%、200% 界面和文字设置，以及四位数等级 | 角标不裁字、不越出格子，不严重遮挡装备图标。 |
| 存档读取、换图后重开面板 | 角标由实例重建，数字与现有装备详情一致。 |

装备与 UI 相关自动测试已运行；仍需在实际游戏窗口检查不同缩放和拖拽。上表包含尚未通过人工验收的视觉标准。

## 成本、取舍与风险

每个格子新增一个绘制控件，创建成本与**已创建的物品格数**线性相关；数字仅在物品或设置变化时更新，运行时无逐帧计算。实际新增节点数和帧时间仍需在 40 格及扩容背包、仓库同开场景测量。四位数在 52×52 中占用图标面积较大，是主要可读性风险；若实测拥挤，优先微调字号、背景内边距或格子布局，不截断等级数字。仅对 61 级以上显示可以减少低等级阶段的视觉密度，但会使同一角标规则随等级突然变化，暂不推荐。

## 实施与验证记录

- 已在 `scripts/ui/item_slot.gd` 的共用格子中增加右下角黑色半透明等级角标；从实例 `requiredLevel` 取值。背包、人物装备位、仓库/交易格和拖拽副本沿用同一实现。空格、非装备或非法等级不显示。
- 角标使用一个不接收鼠标事件的子控件绘制；格子建立时创建，实例或设置变化时重画，不增加逐帧更新。按界面与文字设置的相对倍率选字号，并按格子尺寸收缩四位数文字。
- 新增 `EquipmentLevelBadgeTest`，覆盖 61/64/71 级实例、人物装备位、拖拽副本、空格复用、非装备与无效等级，以及 100%、150%、200% 和文字大于界面的倍率组合。该测试及 `InventoryUpgradeBadgeTest`、`WarehouseSlotVisualTest`、`SettingsTest`、`DynamicEquipTest`、`SmokeTest` 均通过。
- `QualityFrameTest` 的「slot artwork fills canvas」和「equipment icon trims transparent padding」断言在本次修改前的 `HEAD` 提交快照上同样失败；当前 `SampleArt.decorate()` 将 `icon_max_width` 固定为 34，与该测试期待的格宽不一致。此既有问题不在本次角标改动范围内。
- 尚未完成真实游戏窗口中的视觉手感验收，也未测量新增控件对帧时间或内存的影响；这两项不以自动测试通过代替。
