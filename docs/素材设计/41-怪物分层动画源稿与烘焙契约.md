# 怪物分层动画源稿与烘焙契约

本文件落实[40 号正式动画方案](40-11至60级怪物正式动画制作方案.md)的 F0 源稿格式。目的是让八方向结构板、逐帧部件姿势与运行图集有可复现的转换关系；工具通过只能说明文件结构正确，**不能代替美术验收**。

## 目录和坐标

每只怪物的可编辑源稿放在 `art_source/chapters/chNN/monsters/<id>/animation/`：

```text
animation/
  rig.json
  directions/
    s/body__base.png
    s/far_legs__base.png
    s/far_legs__lift.png
    ...                         # sw、w、nw、n、ne、e、se 同结构
  animations_v1/              # 离线生成；审核前不可登记为正式资源
    animation.json
    idle_atlas.png
    walk_atlas.png
    attack_atlas.png
    hit_atlas.png
    death_atlas.png
```

每张部件 PNG 是**同一大小的完整透明画布**，坐标以左上角为原点，脚底/悬浮锚点不随帧变。`layer_order` 从后向前合成；每个方向的部件都必须独立绘制，不能直接镜像后把错误的铜阀、武器手、主光或近远侧脚留在背面。部件名与变体名只用英文小写、数字及下划线；部件外沿须透明。普通怪起点为 80×80、锚点 `[40,64]`，精英为 112×112、`[56,88]`，首领为 192×192、`[96,152]`；实际轮廓不合时在该 ID 的全部状态与方向统一改尺寸，不单帧裁切。

`rig.json` 的最小结构如下。示例仅说明格式，不是一只合格怪物的动画：

```json
{
  "id": "c2_spirit_larva",
  "frame_size": [80, 80],
  "pivot": [40, 64],
  "directions": ["s", "sw", "w", "nw", "n", "ne", "e", "se"],
  "layer_order": ["far_legs", "body", "near_legs", "valves", "head"],
  "states": {
    "idle": {
      "fps": 8,
      "loop": true,
      "visual_contact_frame": 0,
      "frames": [
        {"parts": {}},
        {"parts": {"head": {"offset": [0, -1]}, "valves": {"variant": "pulse"}}}
      ]
    }
  }
}
```

空的 `parts` 表示所有层使用 `base` 且偏移为 `[0,0]`；某层可给出 `variant`、整数像素 `offset` 或 `visible:false`。源稿需为每个实际使用的方向、部件和变体提供 `<layer>__<variant>.png`。工具只合成透明层与整数平移，故步行必须画出抬足/着地等**真实变体**；单纯把整只怪上移下移不构成正式动作。转身、受击、死亡与首领技能也必须有可信关键姿势。分层变形若像纸片，直接另画该方向和状态的关键部件变体，不靠插值掩盖。

实际源稿须有 `idle/attack/hit/death`；可移动怪还必须有 `walk`。首领按当前事件增补专属状态。每状态的方向顺序固定为行 `s/sw/w/nw/n/ne/e/se`，时间帧在列；`visual_contact_frame` 是**画面标注**，不会改动伤害时刻。普通近战的现有逻辑即刻结算伤害，动画从接触帧向后摇播放；远程和首领动作另按真实现有事件复核。

## 导出和准入

在仓库根目录执行：

```bash
/Applications/Godot.app/Contents/MacOS/Godot --headless --path . --script tools/bake_monster_layered_animation.gd -- art_source/chapters/ch02/monsters/c2_spirit_larva/animation/rig.json
```

烘焙器核对方向、帧尺寸、锚点、层序、源 PNG、透明外沿、帧数与接触帧，再生成每状态图集和 `animation.json`。缺层或坏姿势会以非零状态退出，已存在的图集在源输入校验失败时不覆盖。工具不检查“是否真的是背面”“近远足是否正确”或动作质量；这些必须在原生 80/112/192 像素和 Godot 实窗人工审查。

审核通过后，才把 `animations_v1/animation.json` 的路径登记到 `data/monster_animation_packs.json`，运行 `node tools/build_monster_animation_assets.mjs` 和 `--check`；然后将该怪外观档案切为 `animation_pack` 并同步 `data/monster_appearances/README.md`、制作矩阵及原资产清单。未通过者继续使用现有三格临时图；概念稿、方向候选与预览图不参与游戏加载。

工具链用独立临时目录做过两层、八向、五状态的合成探针：每状态两帧得到 160×640 RGBA 图集；故意缺少部件时烘焙返回退出码 1，不写坏图集。这只是**格式测试**，不计入 F1 三只怪物的视觉通过数。
