# 03 素材清单与制作验收

## 1. 制作顺序

| 批次 | 内容 | 完成条件 |
|---|---|---|
| A 风格样板 | 玩家静态八向、狼静态八向、营地地砖4张、短刃/红药/灵能碎片图标、HUD局部与配色板 | 同一场景100%/80%倍率可读，风格一致后再批量 |
| B 核心战斗 | 玩家/狼/虫完整基础动作，教学木桩、基础刀光/受击、主HUD、背包装备图标 | 现有第一章基础循环所需状态齐全 |
| C 第一章地图 | 4套环境模块、5类NPC、游魂、精英、Boss三阶段、出口/车夫/墓碑 | 地图辨识明确、预警匹配实际范围、无出口遮挡 |
| D 系统补齐 | 全部面板、药品/如意/杂项、技能图标、坐骑收藏图、掉落品质层、菜单/存档/加载 | 系统状态清楚、全清单有资源或明确储备标记 |
| E 扩展储备 | 未接线技能特效、坐骑世界动画、音频、发布宣传素材 | 分开记录制作完成与接入完成，不宣传未实现功能 |

A批仅建立美术样板，不要求改现有代码。本次交付到规范阶段；上述是下一步实际制作排期，不是已完成清单。

## 3. 单个素材制作单模板

复制以下模板后填写；没有数据ID时用明确的表现ID，不能临时添加玩法模板。

```yaml
asset_id: weapon_starter_icon
category: equipment_icon
data_id: weapon_starter
batch: A
implementation_status: not_integrated
purpose: 背包、装备槽、商店和比较面板的主体图标
style: 复古像素、旧铁短刃、左上光、柄左下刃右上
canvas_px: [48, 48]
subject_bounds_px: [4, 4, 40, 40]
anchor_px: [24, 24]
transparent: true
palette: 旧铁灰、旧布、少量青白刻纹
output_path: assets/sprites/equip/weapon_starter.png
source_path: 待制作时填写
variants: 无，品质框由UI叠加
animation: null
forbidden: 文字、品质边框、数量、星级、背景、照片质感
license_provenance: 待制作时记录
review_status: planned
```

动画单追加 frame_size、direction_order、各状态frame_count/FPS/loop、锚点、命中帧和接地帧。建筑单追加占地格数、基座/上层文件、遮挡参考线、是否纯装饰。图标单追加32px缩略图检查。所有单均注明“制作完成”和“接入完成”，两者分别验收。

## 4. AI生成与人工整理规范

后续使用AI生成时，先基于A批批准样板建立参考；相同品类共享参考图、色板、光照、画布与比例。不得把独立生成的多张图片直接拼成最终帧动画：角色脸、装备、体型和透视容易漂移，必须逐帧校正。

提示词骨架：

> 为《末法纪元》制作[对象]的[用途]。复古像素等距2D，64×32地面比例，屏幕左上主光，使用[色板]。主体[轮廓与材质]，方向[屏幕方向]，透明背景，完整主体，固定脚底锚点[坐标]。不含文字、数字、UI边框、水印、场景背景、平滑3D或照片纹理。与提供的样板保持同一像素密度和造型语言。

明确尺寸与透明要求只是生成目标，最终仍需核验实际输出并用像素编辑流程整理。生成大图不等于合格48px图标；禁止简单缩小照片式素材后称像素画。首次方向图定型后，再生产动作关键帧和补间。

推荐流程：制作单→参考与配色→静态剪影→八向一致性→动作关键帧→像素修整→按锚点导出→图集元数据→场景实测→状态标记。每轮留预览和变更理由，下一批沿用已通过样板。

## 5. 交付与验收清单

### 5.1 文件验收

- 文件路径、ID和大小写与资源表相符；数据声明路径真实存在，现有SVG引用未被误删。
- PNG透明通道正常，无白底/棋盘格烘焙，无半透明黑边；检查深底、浅底和实际地图底色。
- 图标主体安全区、动画帧格与统一锚点符合制作单；所有帧无裁手、裁武器或脚底漂移。
- 原图、分层源文件、资源表、授权记录和预览齐全；没有中文正文、数值、键位烘在图中。
- 八向方向/图集行序/循环/关键帧完整；图集边界不串帧；未知/缺失资源有明确兜底图。

### 5.2 视觉验收

- 玩家与狼/虫/游魂不看名称也能辨认；灰烬背景上能找到游魂，紫色背景上能看清Boss。
- 普通/精英/Boss靠轮廓和身份标识区分；装备5品质色与现有实现逐项对照。
- 48px图标和32px预览都能分辨武器/如意/卷轴、红蓝药及3档瓶型；去色后仍可按形状判断类别。
- 64×32砖拼接无缝、道路连续、建筑透视统一；不同地图有明确色调和地标，重复砖不形成强烈棋盘。
- 树冠与建筑不掩盖出口、玩家、留地物；装饰不误示可交互、可通行或可攻击。
- Tooltip比较双面板、交易双面板、拖动幽灵、数量、冷却与禁用标记不会相互遮盖。

### 5.3 接入后验收（后续制作阶段执行）

在真实Godot窗口中检查，而不是只看静态设计稿：

1. 1280×800与1440×900正常布局；1920×1080和2x高分辨率清晰。UI200%与长中文文本下可重排/滚动，关闭按钮可达。
2. 地图倍率0.8/1/1.5下，玩家/物品轮廓可读，世界文字保持可读；素材变化不影响碰撞、射程或拾取距离。
3. 密集战斗约30敌人＋通常特效场景，目标圈、危险范围与高品质掉落可见；参考1440×900目标60FPS，在实际设备记录帧率、帧耗时与纹理内存，不能仅凭素材尺寸宣称性能达标。
4. Boss阶段变化与实际行为一致；践踏预警0.8秒、范围与判定一致；无敌/受击、死亡/复活动画不重复结算事件。
5. 掉落正常入包、满包留地、飞行动画关闭三种路径分别截图；稀有/史诗/传说名称与特效正确，拾取提示时机不变。
6. F/G开关、手动接管倒计时、面板打开/暂停、冷却/耗尽/补货、存档读取均显示真实状态。
7. 音量、屏震与强闪开关只在工程确实接线后验收；安静模式仍能看见危险提示。

每批制作记录至少附：100%比例预览、缩小预览、深浅底检查、实际场景截图（接入后）、未通过项、资源数量、完成/储备/已接入状态。功能未接线时记录“素材验收通过、集成待办”，不能写“游戏验收通过”。

## 6. 完成标准与后续维护

第一章正式美术完成需清单内所有当前玩法资源通过文件、视觉和接入验收；扩展储备单独统计。新增章节沿用统一品质/UI/坐标规则，环境色板与敌人剪影可以扩展。新资源类型或锚点变化先更新本规范与制作单，再批量生产。

下一步最适合开始A批样板：先确认实际游戏尺度与风格，再制作完整动作、地图和系统图标，避免一次性产出大量不一致或无法接入的素材。
