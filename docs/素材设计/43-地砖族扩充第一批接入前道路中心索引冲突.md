# 43 地砖族扩充第一批接入前发现：道路中心下标与族变体数冲突

日期：2026-10-17
执行方：我方（接入前预检，未改动任何 `assets/`）
触发时机：wild/ash 接入动手前复核 `ground.gd` 的选砖与道路链路
结论性质：**阻断性发现**——[35 号 §6.2](35-地砖族扩充第一批复核.md) 与 [41 号 §7.1 第 3 条](41-地砖族扩充cave脚本派生小样与验收.md) 建议的「清掉 `ASH_TILES[3]` 死位」按原样执行会让 **wild_trial 与 ash_land 的道路消失**，需要先裁决再动手。

## 1. 结论速览

| 项 | 结论 |
|---|---|
| 下标 3 的真实身份 | **道路中心砖**（不是「死位/未使用位」） |
| 网络证据 | wild_trial 857 格、ash_land 874 格、corruption_source 538 格被标为道路 |
| 若照原计划直接扩块 | wild 道路由**浅褐土路**变成**绿草**、ash 道路由 `road_soft` 变成**普通灰土**，两图道路可视性消失 |
| 建议处置 | **方案 A：道路中心独立成槽**（族砖 N + 道路中心 1 + 八张边缘 8），道路贴图保持现状，**观感零变化** |
| 附带待确认 | 另有一处**轻微色差**（八张 `road_edge_*.png` 由旧砖烘成），可延后到 B 批，见 §5.2 |

## 2. 事实链（逐条可复现）

1. **道路行数据**：`data/map_art/chapter1_v2/<map>.json` 的 `road_rows` 中，`wild_trial` 有 857 个 `1`、`ash_land` 有 874 个、`corruption_source` 有 538 个。
   ```bash
   python3 -c "import json;d=json.load(open('data/map_art/chapter1_v2/ash_land.json'));print(sum(r.count('1') for r in d['road_rows']))"
   ```
2. **[ground.gd](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/world/ground.gd#L529-L549) 的 `_chapter_one_road_tile_index()`** 对上述格返回 **3**（中心），对邻接道路格返回 4–11（八向边缘）。
3. **[ground.gd](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/world/ground.gd#L516-L517) 的 `_road_atlas_index(road_index, theme_size)`** 为 `3 if road_index == 3 else ...` —— **中心恒回落到图集下标 3**。
4. 图集由 `_draw_tile_floor()` 组装为「本族砖 + 八张道路边缘」，因此**每张图的下标 3 = 该图族砖数组的第 3 个元素**，即 `*_TILES[3]`。
5. [42 号 §3.1](42-地砖族扩充cave-9变体接入验收.md) 的映射表也把下标 3 明确记作「**族砖 3（道路中心）**」——上一批已认定该位是道路中心，只是 cave 的道路中心与地面同材质，视觉上无差别，所以未暴露问题。
6. **目视证据**（8× 点采样，左→右：旧 `wild/tile_3`｜新 `_packed/wild/tile_3`｜现 `ash/tile_3`｜`ash_land/road_soft`）：旧 `wild/tile_3` 是**浅褐土路**，新 3×3 的 `tile_3` 是**绿草**；`ash_land/road_soft` 是**压暗后的灰烬路面**。

   ![旧道路砖 vs 新变体](_verify/road_index_conflict_8x.png)

## 3. 35 号 §6.2 的误判点

原文：

> `ASH_TILES[3] = chapter1_v2/ash_land/road_soft.png`（**该位是道路砖，不是地面变体**）……`_chapter_one_road_rows` 非空 → 地块索引由道路行机制覆盖，`tile = 3` 分支在该图根本不会被命中，即 `ASH_TILES[3]` 实际是死位。扩到 8 地面变体时可直接用 `tile_0..7` 占满。

误判在于**把两个不同的 `3` 混为一谈**：

| 名称 | 位置 | 是否被命中 |
|---|---|---|
| 「`tile = 3` 兜底分支」 | [ground.gd](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/world/ground.gd#L489-L493) 无 `road_rows` 时给中心带的兜底 | road_rows 非空时**不命中** ✅（35 号这句没错） |
| 「图集下标 3」 | `_road_atlas_index(3, theme_size)` 对**道路中心的正常映射** | **每张图都被命中** ❌（35 号把它漏了） |

所以 35 号 §6.2 的结论「`ASH_TILES[3]` 是死位」不成立；`tile_3` 在 4 变体时代**从来不是地面变体**，而是「3 块地面（0/1/2）+ 1 块道路（3）」（`_pick_theme_tile(…,4)` 只返回 0/1/2 也印证了这一点）。

## 4. 三种处置

| 方案 | 做法 | 观感变化 | 改动面 | 评价 |
|---|---|---|---|---|
| **A 道路中心独立成槽**（推荐） | 图集改为 `族砖(N) + 道路中心(1) + 八张边缘(8)`；`_road_atlas_index(3,N)=N`、`(4..11)=N+1..N+8` | **零变化**（道路仍用现役贴图） | `_draw_tile_floor` 组合逻辑 + 每图一个道路常量 | 语义干净，四图统一，道路与地面彻底解耦 |
| B 下标 3 保留为道路 | 族砖占用 `0,1,2,4…N+2`，跳开 3；`_pick_theme_tile` 返回映射后的绝对下标 | 零变化 | 只需改 `_pick_theme_tile` 与数组 | 改动更小，但族砖数组内有「洞」，可读性差 |
| C 照原计划直接扩块 | 族砖占满 `0..N-1`，下标 3 变成地面变体 | **wild/ash 道路消失或串色** | 最小 | 不推荐，属可见回归 |

## 5. 影响面（若照原计划执行会坏在哪）

### 5.1 道路本体

- **wild_trial**：857 格道路由「浅褐土路」变成新 3×3 的 `tile_3`（绿草）→ 路径与周围草地同色，道路读不出来。
- **ash_land**：874 格道路由 `road_soft`（压暗灰烬）变成普通灰土块 → 道路同样消失。

### 5.2 附带项：八张道路边缘砖的底色

`chapter1_v2/<map>/road_edge_*.png` 由 [build_chapter_one_v2_art.py](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/tools/build_chapter_one_v2_art.py#L55-L75) 以「该图 `tile_0`（地面）+ `tile_3`（道路）」烘焙而成。换掉 wild/ash 族砖后：

- 道路边缘格的**底色仍是旧砖**，与新的地面族砖存在**轻微色差**（wild 新砖偏绿偏冷、ash 均值持平，见 35 号 §4.1/§6.1）。
- 该项**不影响道路本体读识**，且 [35 号 §7](35-地砖族扩充第一批复核.md) 已把「L1 过渡边缘」的介入划到 B 批，**建议延后到 B 批统一重烘**，本批不动。
- 若要在本批一并重烘，需重跑 `build_chapter_one_v2_art.py`；注意它同时会重烘 camp（砖未变→产物一致）与 cave（砖已变→边缘随之变化），属于额外评审面。

### 5.3 不受影响

camp 正式画面（走 B 全图分层地纹，不经 `_draw_tile_floor`）、cave 道路（材质本身不区分道路/地面）、碰撞与寻路（只用掩码，不涉贴图）。
