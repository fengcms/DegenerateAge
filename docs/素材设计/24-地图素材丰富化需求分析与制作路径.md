# 24 地图素材丰富化：需求分析、失败根因与制作路径

本文件针对「现有地图素材太少、想按游戏风格做一批丰富素材（草皮、地砖、石子路、花木、小桥、湖泊、山石、地下、岩壁、房子、破烂等）、并参考传奇/征途/传世的地图组织方式（非抄袭）」这一需求，做需求拆解、失败根因定位、方法选型与分批制作清单。

本文件是**分析方法与制作路径**，不生成运行素材、不修改数据与代码。文中「建议/样板」是方向性结论，最终制作规格需按本文件第五节流程逐批验证后确定。

---

## 一、需求拆解

你列出的目标素材，本质不是「一批图」，而是**一套按用途分层的模块化素材体系**。按依赖关系归位如下（这也是后面分批制作的顺序依据）：

| 你提出的素材 | 归入层 | 用途 |
|---|---|---|
| 草皮、地砖、地面基础 | L0 基础地面 | 铺底，决定画面基调 |
| 湖泊水面、水边 | L0' 水域地面 | 水面与浅滩 |
| 石子路、道路 | L2 道路模块 | 连接与引导 |
| 小花木、草丛、碎石 | L3 贴地装饰 / L4 立体小物件 | 地面细节与体积点缀 |
| 山石、岩壁 | L6 地形边界 | 高差、封边、封闭感 |
| 小桥 | L5 大型整体物件 | 跨水/跨沟的连接体 |
| 房子 | L5 大型整体物件 | 地标与遮挡主体 |
| 破烂（箱、木桶、断车、破布等） | L3/L4 杂物装饰 | 废土氛围 |
| 地下（洞窟） | 主题环境包 | 独立一套洞窟地面＋洞壁＋入口 |

**你没列、但必须补的**（这套体系缺一不可）：L1 **地形过渡边缘**、L6 **悬崖/坡道**、L5 的**背层/前沿遮挡层**、以及路牌、栅栏、台阶、篝火、水井、墓碑、藤蔓、倒木、洞穴入口等地标件。**L1 过渡边缘正是「拼接像棋盘」的元凶**，也是绝大多数人做地图素材时最容易漏的一层。

## 二、两天没成功的根因

结合项目现状（营地此前为「整图烘焙」路线）与素材生成记录，失败不是提示词写得不好，而是**路线与流程问题**，共五条：

1. **把「地图」当「一张图」做。** 项目历史路线是把整张底图烘焙出来（`clean_plate.png` 1672×941 铺到 3200×1800 世界矩形），后果是：高分屏发糊、遮挡不可靠、角色能站到屋顶/石头上。见 [16-幸存者营地地图贴图风格重设建议](16-幸存者营地地图贴图风格重设建议.md)。**任何新的尝试只要还走「生成一张完整地图」，就必然重蹈覆辙。**

2. **缺风格锚点（style anchor）。** 项目此前**成功**生成 35 个图标、4 只怪物、特效与品质框，全靠一条固定骨架：**一张固定参考图 + 固定提示词模板**（见 [素材交付说明](../素材/README.md) 与 `docs/素材/sources/generation_manifest.json`）。你的地图尝试若每次都在重新描述风格，产出之间必然无法累积、也无法统一——两天的时间就消耗在反复重定义风格上。

3. **只做了最上面一层（地砖），缺四层配套。** 只生成地砖，拼出来一定是「一格一格」的棋盘感；缺 L1 过渡边缘、L2 道路、L3 贴地装饰、L4/L5 立体物件，画面就没有层次。

4. **等距 2:1 菱形瓷砖的无缝拼接 + 跨素材色调一致，是图像生成的先天弱项。** 生成器不是为「可平铺、边缘对齐、跨图同色」设计的。**必须用「生成大块循环纹理 + 后处理重排/统一色板」的方式绕过**，而不是期望单张一生成就能直接拼。项目营地 B 二版已经验证了可行做法：生成 1024×1024 原生像素裁片 → 同向重复为 2048×2048 循环纹理（不翻转），接缝只在四边 48px 窄带柔和处理。

5. **规范与参考对象存在风格冲突，导致左右摇摆。** 现行 [01-视觉与技术统一规范](01-视觉与技术统一规范.md) 定的是**复古像素**（有限色阶、地形低对比）；而传奇/征途/传世是**预渲染彩绘**（高细节、笔触、较高对比）。两者在色阶密度与笔触上完全不同。**如果不明确选一条，每次生成都会在两者之间漂移，产出「像素不像素、彩绘不彩绘」的四不像。**

## 三、必须先定的方向：风格锚点（本次已出对照样张）

这是所有后续工作的**唯一前置决策**——它直接决定提示词的底层参数（色阶数、笔触、对比度）。已按两个方向各出一张「四地形对照样张」，位于 [样板/地图素材-风格锚点-v1](样板/地图素材-风格锚点-v1/README.md)：

- `style_anchor_A_pixel.jpg`（复古像素方向）
- `style_anchor_C_painterly.jpg`（传奇式预渲染彩绘方向）

两张都验证了同一件事：**2:1 等距菱形 + 四地形 + 过渡边缘 + 左上主光**的结构是可以被稳定生成的——你之前缺的不是「能不能生成」，而是「路线 + 锚点 + 流程」。

三个方向选项与取舍：

| 方向 | 画面语言 | 与现有像素角色的关系 | 取舍 |
|---|---|---|---|
| **A 严格像素** | 沿用角色的像素簇与有限色阶 | 天然统一 | 制作与性能风险最低；地面变体不足时易显简陋 |
| **B 克制的高精度像素插画（推荐）** | 保留像素轮廓与废土暖色，减少细碎写实笔触；地面用成组可重复纹理，大型物件用独立整体精灵 | 基本统一（人物仍是像素） | 兼顾精致与辨识度；对规范执行要求最高 |
| **C 传奇式预渲染彩绘** | 高细节、彩绘笔触、暖饱和 | **与现存像素角色/UI 冲突**（尺度与笔触脱节） | 画面最丰富；若选它，角色/NPC/UI 也需重新评估，属于全项目美术转型 |

**关于「参考传奇/征途/传世」：借鉴的是它的「构成方式」与「环境丰富度」，不是画风。** 具体说：

- **构成方式**：连续地形（悬崖、岩壁、河岸）不是一张大图，而是由**一套模块化连接件**连续拼装而成（直线段＋内角＋外角＋端帽＋崖顶＋脚底收口…），详见 §四.1。多层地形、成网道路、大量可摆放杂物、成片水域与植被，都是这套拼装体系的产物。
- **环境丰富度**：靠层数 × 变体数 × 地标件密度提升，不靠提高地面对比。
- **画风**：仍取 A/B 的像素语言（原因见根因 5：彩绘地面会与像素角色打架）。

> **已拍板：方向 A（严格像素）。** 后续所有素材以 [`样板/地图素材-风格锚点-v1/style_anchor_A_pixel.jpg`](样板/地图素材-风格锚点-v1/style_anchor_A_pixel.jpg) 作为锁定风格参考图，逐批产出。

## 四、破局方法：模块化地图素材体系（七层）

把「地图」拆成**可复用、可拼装、可维护的层**，替换掉「整图烘焙」路线。每张地图 = 若干层的拼装，而不是一张画。

| 层 | 名称 | 内容 | 交付形态 | 是否有碰撞 |
|---|---|---|---|---|
| L0 | 基础地面 | 草地/泥土/夯土/沙地/石板等基础纹理 | 可循环平铺纹理 **或** 64×32 等距瓦片图集 | 否 |
| L0' | 水域地面 | 水面、浅滩、水底 | 可循环纹理 + 动态水面（后续） | 部分 |
| L1 | 过渡边缘 | 草→土、土→石、石→水、草→水 等交界贴片 | 自由绘制过渡贴片 | 否 |
| L2 | 道路 | 石子路直/弯/T/十字/尽头，2:1 对齐 | 独立精灵 | 否 |
| L3 | 贴地装饰 | 草簇、小花、碎石、车辙、裂纹、苔痕 | 独立精灵（低对比、可踩） | 否 |
| L4 | 立体小物件 | 小石头、木桩、灌木、小花木、木桶、箱子 | 独立精灵 | 是（薄轮廓） |
| L5 | 大型整体物件 | 房子、树、桥、马车、摊位、遗迹；含**背层 + 前沿遮挡层** | 多格整体精灵，可分层 | 是（轮廓多边形） |
| L6 | 地形边界 | 岩壁、悬崖、山体、坡道、洞壁、洞穴入口、崖顶 | **模块化连接件集**（见 §四.1） | 是 |

三条硬纪律（沿用 [16 号](16-幸存者营地地图贴图风格重设建议.md) 的结论，不因扩充素材而被推翻）：

1. **立体物件的承重脚底必须落在真实碰撞轮廓内**；屋檐/树冠可外伸，但必须由独立遮挡层表达。可走地面上只放「踩上去仍是地面」的平面装饰。
2. **真分层，不复印整图**：底层只含可踩地面与道路；大型物件单独交付背层与前沿遮挡层，按角色脚底深度排序。
3. **物件与地形分两种构成方式**：L5 大型物件（房子/树/桥）是整体实体，有确定脚底锚点与固定障碍轮廓，不碎成 1×1 瓦片；L6 连续地形（悬崖/岩壁）则按**模块化连接件**拼装，由多张不同素材连续接合构成一条完整崖壁（见 §四.1）。L0–L3 用瓦片/图集。

### 四.1 悬崖/岩壁模块集（传奇式拼装构成）

悬崖不是一张大图，而是**一套可连续接合的模块**——这正是你说的「连续多张不同素材构成悬崖峭壁」。参照 2:1 等距地形的连接件（autotile）思路，一套崖壁至少包含：

| 模块件 | 作用 |
|---|---|
| 侧壁直线段（顶/中/底） | 崖壁垂直面主体，可纵向重复 |
| 崖顶平面段 | 崖顶可站立平面的边沿与内部 |
| 内角件 / 外角件 | 崖体转折处的凹角与凸角 |
| 端帽（左右端 / 上下端） | 一条崖壁两端的收口 |
| 上下过渡件 | 高地↔低地的高差过渡 |
| 脚底收口件 | 崖壁与地面相接的接地线 |
| 洞口件 | 崖壁上的洞穴入口 |

拼装纪律：① 光照与色阶与锚点一致（左上主光，崖顶亮、崖底暗）；② 相邻件接缝的地纹与明暗可对齐，接上后看不出断点；③ 崖顶、崖脚分别对应真实通行/碰撞掩码，不靠视觉暗示；④ 每件登记尺寸、锚点、可接合边（4 边各自能否续接）。

## 五、生产流程闭环（这是「两天没成功」的直接解药）

不要一次全量生成。按下面闭环逐层推进，每层先出 1 张验证，再扩展变体：

1. **锁定锚点**：确定方向（A/B/C）→ 生成 1 张「四地形 + 过渡」测片 → 与像素角色同屏比对 → 固定**色板、色阶数、像素簇大小、光照方向、边缘处理规则**，存为唯一风格参考图。
2. **单批验证**：每一大类（地面→过渡→道路→装饰→物件→边界）先只出 **1 张**，确认与锚点一致后再做变体。
3. **拼接测试**：每批做完做**拼接/平铺测试**（地面纹理重复平铺看接缝，道路模块首尾相接看连续），检查接缝与色调，不合格就回炉。
4. **模板复用**：把验证通过的提示词固化为模板，同批所有变体只替换 `[主体描述]` 一句。
5. **接入验收**：导出后按 [03-素材清单与制作验收](03-素材清单与制作验收.md) 的文件/视觉/接入三关，在真实 Godot 窗口检查清晰度、遮挡与碰撞。

**关键：每批第 1 张先给你确认，再批量。** 这样任一批风格跑偏都只损失 1 张，不会重演「两天白做」。

## 六、地图素材提示词模板

基于项目**已验证成功**的骨架（见 `generation_manifest.json`）改造为地图专用版。结构固定为七段，同批只改第 5 段：

```text
[1 用途] <asset type> for a retro-pixel isometric dark-fantasy RPG map.
[2 透视] Isometric 2:1 diamond layout (tile ratio 64x32), 30-degree top-down angle, no perspective vanishing point.
[3 风格] Match supplied reference: deliberate chunky pixel clusters, hard pixel edges, strict limited palette of ~<N> flat colors (<palette tokens>); no gradient, no blur, no soft shading, no antialiasing, no photographic texture.
[4 光照] Upper-left light source; terrain kept low-contrast and quiet so player characters read on top.
[5 主体] <本张素材的具体描述>.
[6 拼接/透明] Seamless tileable edge / clean transparent RGBA background, complete subject, no cropped edges.
[7 负面] No characters, no creatures, no text, no letters, no numbers, no UI, no watermark, no border frame, not smooth vector, not photorealistic.
```

要点：**「Match supplied reference（匹配所提供的参考图）」必须带一张固定的锚点图**，这是跨素材一致性的核心，也是你此前最缺的一环。地面纹理段把第 6 段换成「seamless repeating texture, tileable on all four edges, no directional flip」；道路/物件段换成「transparent background」。

## 八、与现行规范的冲突处理

你说「文档限制比较死」——这句话部分成立、部分需要澄清：

| 规范条文 | 处理建议 | 理由 |
|---|---|---|
| 「每图起步：基础地砖 4 变体…」视为**下限预算** | **放宽**：按第七节扩大变体清单 | 该数字是预算不是上限；丰富度靠变体数与层数提升 |
| 「地形低对比，角色中高对比」 | **保留** | 这是可读性纪律，不是限制丰富度；丰富来自**层次与变体**，不是提高地面对比 |
| 「64×32 菱形、30°等距、左上光」 | **保留** | 与角色/碰撞/投影一致，改动面极大 |
| 「复古像素」风格 | **已定 A（严格像素）** | 沿用像素簇与有限色阶；不引入彩绘笔触，与角色/UI 天然统一 |
| 「不把拟议地砖系统说成已存在」 | **保留** | 当前 `IsoGround` 与营地循环纹理两套并存，制作前先定用哪套 |

**结论：丰富度不用靠改风格换。** 现行规范真正卡的只有「风格画风」一处；「地形低对比」「2:1 等距」等是必须保留的一致性基石。第七节的模块体系可以在不改画风的前提下，把素材量扩充数倍。

## 十、M1 试制验证记录（2026-10-16）

**试制品**：`样板/地图素材-风格锚点-v1/` 下 `m1_01_grass_base.jpg`（草地基底）、`verify_01_grass_3x3.jpg`（3×3 平铺接缝检查）、`verify_02_density_compare.jpg`（三档密度 + 角色对照）。

**验证结论（制作流程必须处理项）**：

1. **可确认**：色板与像素簇方向成立——草地色阶、碎石灰、左上主光与角色/锚点协调，方向 A 无异议。
2. **必须修正·接缝**：3×3 平铺可见明显网格线，**当前纹理不是无缝的**（图像四边存在差异）。→ 下批生成增加「seamless wrap on all four edges、边缘不留暗带」约束，导出后做接缝混叠处理。
3. **必须修正·重复感**：大面积米色裸土斑块平铺后**逐块重复**，形成墙纸感。→ 打散大幅低对比色块、缩小可重复特征（不超过单块 25%），并按地形再出多套变体交替使用。
4. **密度选档**：对照三档（平铺尺寸 640/320/160），**160 档最接近角色尺度**（草叶约 3–6px，与 64×80 角色腿部比例协调）；640 档草叶过大，不可用于近景。

**处置**：以上均属「生成大图 → 点采样缩到游戏尺度 → 无缝化/打散去重」的既定后处理环节，不是路线问题。下一批 M1 生成按修正 2/3 调整提示词，目标交付密度取 160–240 档。
