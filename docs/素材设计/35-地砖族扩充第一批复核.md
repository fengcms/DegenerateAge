一句话根因：**cave 的族边色与打包脚本里写死的填色 `#D1B787` 不再匹配，`edge < 0.22` 的边缘混色把外圈刷成一层平底色，铺装后连成可辨菱形格线**——这正是本项目此前驳回过一次的同类缺陷。wild / ash 的边色恰好与各自填色接近，所以没触发。

## 2. 复核方法（可复现）

1. **基线**：现行已通过的第一章地砖源稿 `art_source/environment/{wild,ash}_tiles.png`、`cave_tiles_v2.png`，逐格测 alpha 包围盒。
2. **打包**：用 `tools/build_environment_art.gd::_pack_tiles` 的四步口径（alpha 硬阈 → trim → 点采样 64×32 → 菱形掩码 + 填底）**原样**处理新源稿，只把 2×2 换成 3×3，产物落 `art_source/environment/ground_tiles_v1/_packed/<fam>/tile_N.png`，**未触碰 `assets/`**。
3. **形态**：`magick <f> -alpha extract -threshold 50% -format "%@" info:` 逐格测 bbox。
4. **铺装**：按真实等距网格铺 9×9 块地面（`x=(col−row)×32−32`、`y=(col+row)×16−16`，画家序按 `col+row` 递增），同图同角色同接地影，**不用正方形 `tile:` 平铺**（[27 号](27-M1-1a复核与等距呈现验证.md) 纪律）。
5. **选砖**：旧幅完全复刻 `ground.gd` 现役公式；新幅用 9 变体加权散列，保证是真随机散列、非规则排布。

> 说明：铺装图未施加腐败源头洞穴地砖在 `ground.gd` 里的 `Color("a9aaae")` 调制（约 ×0.66 灰调）。该调制只压低绝对亮度，**不改变格线处的相对对比**，故结论不受影响。

- 变体确实读得出来（干黄、湿绿、碎石的区分成立），单调感较旧 3 变体明显改善——本轮目标达成。
- 但**铺装后相邻块之间的暗边会连成可见菱形格线**，且九块在单格尺度上互相拼贴，出现「拼布被」观感（[30 号 §4.3](30-M1第二批复核与四变体判据.md) 记载的同类现象）。

### 4.3 处置（建议不重生成）

1. **分布加权**：把九块按「主基调 / 次基调 / 低频点缀」分档，主基调与次基调合计 ≥60%，避免 3 成以上面积被点缀块占据（见 §8）。这一条是压掉拼布感的主要手段，且**零生成成本**。
2. **暖度回补（可选）**：若实机仍觉偏绿，在 `ground.gd` 对 wild 地砖给一个极轻暖色 modulate（例如 `Color("fff2d8")`）即可，一次改动、可回退。**不建议为此重出一批。**
3. 保留「干黄」「碎石」两类点缀（与旧稿 21% 的干黄块同源，属既有风格）；把最亮、最绿的两块压到最低频。

## 5. cave 洞穴族（9 块）：退回重出

### 5.1 三条硬伤

**硬伤一：暖棕边框连成菱形格线（决定性问题）**

| 证据 | 数据 |
|---|---|
| 族边色 vs 打包填色 | 新稿内部主色 `#BFAF98`(191,175,152)；打包填色 `#D1B787`(209,183,135)；差 **(18, 8, −17)** |
| 旧稿主色 vs 打包填色 | `#C7AD7F`–`#CDB383`(199–205,173–179,127–131)；与填色差 ≤10 → 混色不可见 |
| 近填色像素数（64×32 单块） | 旧稿最多 7px；新稿 **26px**（约 3.7×） |
| 目视 | [铺装图](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/art_source/environment/ground_tiles_v1/_verify/cave_iso_paving_old_top_new_bottom_2x.png) 下部新幅出现**连续平底暖棕菱形格线**，旧幅为连续细石灰岩面 |

根因：`_pack_tiles` 对 cave 额外执行 `edge < 0.22 → lerp(fill)` 的边缘混色，其填色是**写死的 `#D1B787`**。旧稿的族边色恰在此色附近，混色等于没混；新稿把族边色换成了灰米色，混色立刻把外圈刷成一层平底色。相邻块各自的平底边贴合后即构成整片格线。

**硬伤二：材质身份漂移**

| 项 | 旧 cave（已通过） | 新 cave |
|---|---|---|
| 9/4 块均值 R 区间 | 222.6–226.9（**极窄，spread 4.3**） | 200.5–223.2（spread 22.7） |
| 冷暖（R−B） | 34–37（暖白石灰岩） | 15–23（灰绿） |
| 观感 | 干净的暖白石灰岩 + 极细矿物渍 | 灰绿底 + 大块深色斑块，读作「脏/发霉的灰岩」 |

族内一致性是达标的（九块确实是同一材质），**但那是另一种材质**：腐败源头洞穴地图的整体观感会从现在的暖白变成灰绿暗斑。现行 cave 贴图属用户已确认满意的部分，不应在扩变体时顺带改掉。

**硬伤三：形态与流程偏差**

- 逐格 bbox 489×283 / 489×285 / 489×287，宽高比 **1.704–1.728**。虽然形式过 `33 号 §6` 的 1.70 下限，但打包形变达 **15.8%–17.4%**，是基线 7.2% 的两倍多；且行间纵向位置不一致（+187 / +160 / +136），说明 3×3 排版本身不齐。
- 生成器实际输出 1254×1254，源稿是**非整数 nearest 放大 1.225×** 到 1536×1536 的产物（[34 号](34-地砖族扩充第一批制作回报.md) 自述）。虽然经打包约 7.6× 点采样下采样后影响有限，但属于流程偏差，需一并纠正。

### 5.2 退回给「制图大师」的修改点（只改这三处，其余不动）

1. **边缘色锁**：九块的外圈 2–3 像素带必须落在 `#CBB182`–`#D1B787` 区间（即现行 cave 族的边色），以保证打包混色不可见。提示词里加一句：`Keep the outermost rim of every diamond in a warm pale tan close to #CBB182 – #D1B787, consistent across all nine tiles.`
2. **去掉把族带跑偏的措辞**：删掉 `packed grey rock dust`（正是它把族色拉灰）、删掉 `heavily stained / darker grey patches` 这两档（正是它们产生大片深色斑块）。九变体只在窄带内变：`fine mineral speckle density: none → light`、`surface: dry matte → faint cool sheen`，**不出现大面积深色斑块**。
3. **形态**：九格 bbox 宽高比 ≥ 1.80（目标 1.86，与现行族一致），并且**直接输出 1536×1536**，不要再 1254 再放大。

### 5.2.1 可直接粘贴的重出提示词（cave · rev2）

拼装顺序与 [33 号 §2](33-地砖族扩充第一批制作单-A层变体扩充.md) 一致：`开头一句 → [风格锁定] → [等距菱形排版] → [主体] → [像素密度与边缘纪律] → [负面]`。
其中 `[风格锁定]`、`[等距菱形排版]`、`[像素密度与边缘纪律]`、`[负面]` 四段**一字不改**照抄 33 号 §2 原文，**只替换 `[主体]` 段**为下面这段。

```text
Subject: nine variations of ONE single ground material — warm pale limestone cave floor, pale warm
stone with fine mineral speckle. All nine tiles must obviously be the SAME material, sharing one
palette and one edge tone; they differ ONLY along three narrow axes: (1) fine mineral speckle
density, from almost clean pale stone to a light sprinkled staining — never a large dark blotch;
(2) dampness, from dry matte to a faint cool sheen; (3) amount of tiny pale rubble specks, from
none to a light scatter. Keep every tile inside the same narrow pale warm value band: no tile may
be notably darker or greyer than the others.
Spread across the nine cells in roughly this order: clean pale / dry / no specks; clean pale / dry /
few specks; light speckle / dry / few specks; light speckle / slightly damp / moderate specks;
medium fine speckle / slightly damp / no specks; medium fine speckle / damp sheen / no specks;
slightly more speckle / damp sheen / few specks; medium speckle with faint pale mottling / damp /
no specks; light speckle / dry / moderate specks. Ground tiles only: flat, no height, no objects,
no glowing crystals, no violet veins rising above the ground surface.
Keep the outermost rim of every diamond in a warm pale tan close to #CBB182 – #D1B787, consistent
across all nine tiles.
```

**相对 33 号 §4.2 原文必须删掉的措辞**（这三处就是本批漂移的来源）：

1. `over packed grey rock dust` —— 正是这句把整族基色拉向灰调；
2. `heavily stained` 与 `darker grey patches` 两档 —— 正是它们产生大片深色斑块；
3. 任何把 `grey` 当作族基色的表述。

**形态硬约束（同时写进下发消息）**：九格 bbox 宽高比 ≥ 1.80（目标 1.86）；直接输出 1536×1536；禁止 rotate / 镜像 / Y 轴压缩 / 二次非整数点采样放大。

### 5.3 打包脚本侧的根治（顺带做，见 §7）

把 `_pack_tiles` 里写死的 `fill` 常量改成**从该族源图内容边界自动取样中位色**。这样任何一个族换了边色都不会再触发格线，cave 只是第一个撞上的。这一改动的收益大于逐族手填常量。

## 8. 选砖分布建议（替代现役 4 变体硬编码）

现役公式（[ground.gd](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/world/ground.gd#L479-L480)）：

```gdscript
var variation := posmod(col * 73 + row * 37 + col * row * 11, 19)
var tile := 1 if variation < 4 else 2 if variation == 5 else 0   # 0:74% / 1:21% / 2:5%
```

实测：现行 wild 地图**实际只用 3 块**（`tile_3` 在道路行机制生效的图里是死位），且 74% 面积压在单一块上——这才是「太单一」的量化根因。

建议改为同一散列、9 档加权（真随机散列、非规则排布）：

| 档位 | 占比 | 角色 |
|---|---|---|
| tile_0 | 38% | 主基调 |
| tile_1 | 24% | 次基调 |
| tile_2 | 10% | 常见点缀 |
| tile_3 | 7% | 点缀 |
| tile_4 | 6% | 点缀 |
| tile_5 | 5% | 低频 |
| tile_6 | 4% | 低频 |
| tile_7 | 3% | 低频 |
| tile_8 | 3% | 低频 |

主/次基调合计 62%，与旧稿 74% 的「单一基调感」接近，但点缀档从 5% 扩到 38% 且分布在 7 块上——**既有变化，又不至于拼布**。
