更新日期：2026-10-25。适用范围：本项目的视觉规范、角色/怪物/地图/图标/UI 素材及其制作验收。**本文件只供新的美术会话使用**，不替代、覆盖或修改 `docs/工程文档/08-开发交接文档.md`。玩法、数值、存档和功能开发仍以根目录 [AGENT.md](../../AGENT.md)、当前代码和相应产品/工程文档为准。本文的数字以本次读取的仓库状态为准；新会话开始时应重新检查 Git 状态和清单，不把旧记录当作实时进度。

## 一句话现状

玩家满意目前 51—60 级阶段人物 `look_06` 的**造型**，不满意其走路、打怪和打坐等**动作**。已尝试用 Blender 程序化几何制作三维动作试点，但新模型严重偏离原画，用户明确不接受。该试点**未接入游戏**；怪物后续制作仍按用户要求暂停。美术工作的当前焦点是：在保留 `look_06` 人物身份与游戏画风的前提下，找到能实际产出更好动作的制作方式，先过原生尺寸静帧与单方向动作小样，再讨论批量化。

## 用户已经确认的设计取向

- 游戏是 2D 等距斜角、复古像素风的末法幻想世界。人物在场景中要清楚，地形相对克制；不能因为技术上容易渲染就换成光滑塑料感或方块玩具感。底层规范见 [01-视觉与技术统一规范](01-视觉与技术统一规范.md)和[02-分类素材设计规范](02-分类素材设计规范.md)。
- 腐化源头洞穴曾按用户参考经历外形、洞壁层级、暗地面、锯齿墙段等多次迭代，现阶段用户认可当前效果。后续美术不得回退成纯矩形活动区域或“山顶崖边”的视觉误读。参考 [洞穴布局样板](样板/腐化源头洞穴布局-v2/README.md)及对应地图/地砖验收文档。
- HUD、目标卡、小地图、快捷栏与经验条、共用面板曾由用户逐项审看和修正。**用户自己修改的 SVG 是细节基准**，不能只提取颜色/几何大意；尤其注意微小装饰、切角、层级、间距、按钮高光。相关源稿位于 `docs/素材设计/样板/HUD布局-v1/`、`小地图概念-v1/`、`快捷栏与经验条概念-v1/`、`统一面板UI-v1/`。经验条宽度随快捷栏，不全屏拉伸；快捷键字符从用户设置读取，不能烘在图里。共用面板的设计偏差与修复原则见 [05](05-统一面板UI视觉还原偏差分析.md)、[06](06-统一面板UI视觉修复方案与防偏差原则.md)、[07](07-统一面板UI视觉修复验收记录.md)。
- 用户已接受 21—60 级装备/任务物图标和 79 只怪物的现有**简化试玩表现**，也曾接受汲灵幼虫的八方向试玩质量作为后续基准；这不等于完整逐帧动画合格。用户随后明确**暂停后续怪物制作**，直到重新决定动画方法。本次又明确“先不做怪物”，新会话不要自行恢复怪物批量生产。
- 对已满意的 `look_06` 人物定稿，改的是动作而非重新设计角色。三维只是候选制作手段，不能把它当成比原画还重要的目标。用户最近表示程序化三维试点不符合想象，应先读[具体偏差分析](60级人物三维试点偏差分析-2026-10-25.md)。

## 下一轮美术工作建议：先证明方法，不扩大数量

1. 先读[偏差根因分析](60级人物三维试点偏差分析-2026-10-25.md)，把用户认可的原画、八向站立母版和当前游戏 64×80 首帧并排，列出真正不能丢的轮廓、比例、脸、披风、剑环与材质。不要从现有方块 `.blend` 继续批量做动作。
2. 对制作路线做**一角色、一个方向、一个动作**的真实小样。若坚持三维，第一关是原生尺寸静态造型；造型通过再做一个 8 帧行走循环。可同时比较分层二维/逐关键帧修补，但必须用同一原画、同一游戏尺寸和同一实际地图判断，避免只在高清图里看起来漂亮。
3. 把评审拆成两次：静帧“像同一个人物”→ 动作“脚接地、握持和遮挡连续”。任何一关失败，保留现有游戏素材，修正该阶段，不生成全部八向六状态凑进度。
4. 通过后才逐方向补全六状态、确定贴图构建与 `CharacterLook` 登记，做实窗 100% 和常用缩放对照、攻击时序和存档/换装回归。每个通过的小节点按 `AGENT.md` 的 Conventional Commits 中文说明本地提交；不自动 push。

> 请先读仓库根目录 `AGENT.md`、`docs/素材设计/美术专项交接-2026-10-25.md`、`docs/素材设计/60级人物三维试点偏差分析-2026-10-25.md`。当前只做 51—60 级人物 `look_06` 的动作美术方法验证；原有形象和运行素材要保留，怪物制作继续暂停。请先用现有定稿和八向源稿做原生尺寸造型对照，选一个方向制作可审查的走路动作小样，达到身份、接地和动作质量门槛后，再讨论八向与游戏接入。不要把 `3d_pilot` 的方块模型当成正式模型，也不要在未通过造型审稿时批量出动作帧。

## 文件、验证与提交边界

- 美术源稿和试验放 `art_source/` 或本目录的样板；只有审过、裁切并导入验证的图集进 `assets/`。设计稿、生成预览与可运行素材须分开。详细规则见 [AGENT.md §3、§10](../../AGENT.md)。
- 图片存在、模型能转动、GIF 能播放均不是正式验收；按 64×80、八方向、脚底锚点、武器握持、真实地图与显示倍率逐项看。Godot 的 headless 测试可验证路径和逻辑，不能证明画面质量。
- 当前三维技术试点提交为 `3d04d048`；本交接不更改游戏逻辑、图集、怪物或功能开发交接文件。新会话开始先执行 `git status --short`，尊重其他会话在共享工作区中的修改。
