# 左前站走与三方向试装验收记录

2026-11-18。本轮将71号记录中的左前候选接入隔离营地，并生成同方向独立站姿。仅用于美术试装，未登记正式 CharacterLook；左后候选仍因头部与脚尖朝向不一致而拒绝接入。

## 制作与接入

源稿位于 `art_source/actors/hero_walk_sw_trial_v1/`。四帧行走沿用 candidate.png，配套 idle_source.png 使用内置 image_gen 参考同角色生成，完整提示词与来源见 idle_prompt.json。没有镜像其他方向，没有逐帧移动脚底来掩盖漂移。

构建参数统一登记于 `art_source/actors/hero_walk_pilot_v3/build.json`，通过 `tools/modular_camp/build_assets.gd` 离线缩放、打包。左前行走源图2048×768，四列512×768，统一缩放0.14、源锚点(275,710)；站姿1024×1536，缩放0.066、源锚点(520,1410)。输出行走 hero_walk_sw_v1.png 为112×512，站姿 hero_idle_sw_v3.png 为112×128；运行帧112×128，共用锚点(56,112)。生成清单仍沿用 hero_walk_se_v3.json 名称，其 directions 已明确列出 se/ne/sw。

样板 U 键复现左下寻路，P/O 保留右下/右上，I 保留前后站姿对照，H统一回退原图。三个方向分别以屏幕(2,1)、(2,-1)、(-2,1)为中心、约±22.5度接受动作；未制作方向回退。动画按真实位移每64px循环一次，顶墙无位移时停帧并保留对应站姿。依然使用既有导航、CharacterBody2D半径12和150px/s移动速度。

## 实测与复核

在 Godot 4.7.2 Compatibility / Apple M1 Max 环境执行：

```sh
python3 tools/modular_camp/launch.py --build-assets
python3 tools/modular_camp/launch.py --verify --capture /tmp/camp-sw-walk
```

构建四项成功标记齐全；真实窗口验收退出码0，输出 `MODULAR_CAMP_VERIFY_OK: 256 masks / 47 shapes / 2 layouts / physics routes / moved wall`，无 SCRIPT ERROR。

新增覆盖两布局左前真实移动四帧、抵达目标、停步清零与站姿保留、无镜像、H回退与恢复；在既有左侧边界角持续输入，要求实际接近后连续12物理帧位移小于0.01px且发生接触。原两方向、道路、绕障、门洞、移墙、补给物件碰撞、怪物待机及遮挡检查保留，属于扩展覆盖，没有放宽断言。

人工检查 left_idle_0.png 与 left_walk_0_2.png：站姿与步行人物尺度接近，脚底落在道路上，透明背景没有形成色块，按U提示完整显示。截图留在临时目录，不进入运行依赖。静态截图不能证明动作流畅性，四帧覆盖检查也不能代替步态精修。

## 成本和限制

新增行走RGBA8理论224KiB、站姿56KiB，合计280KiB；三方向站走纹理合计840KiB，不含原图、驱动及导入开销。新增四个AtlasTexture区域引用，纹理由缓存共享；不增加节点、碰撞或导航更新。每次运动更新最多增加一次方向点积，加载时创建区域，切换布局释放实例。验收最多暂存四张1280×800截图约15.625MiB，写出后清空；普通运行不采集截图。本轮未重测帧时间，不据此宣称FPS改善。

步幅、脚尖漂移、布料细节与站走过渡仍需精修。当前只完成三个斜向试装，不能当作八方向角色包。怪物仍仅待机，没有攻击、受击、死亡；正式地图、战斗规则和玩家存档未修改。后续先继续合格方向与动作制作，再按正式外观清单及事件时序接入。
