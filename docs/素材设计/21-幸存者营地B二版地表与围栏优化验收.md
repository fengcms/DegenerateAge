# 幸存者营地 B 第二版地表与围栏优化验收

本轮依据实机反馈调整正式营地：已认可的铁匠铺、仓库、货郎摊和长老树保持原风格与尺寸；重做地面、道路与内部围栏，撤除四周栅栏和岩带，缩小马车并校正中央灯比例。运行入口为 `scripts/world/ground.gd` 的 `CAMP_FINAL_ART_MANIFEST`，第二版素材清单在[运行目录](../../assets/maps/camp_style_full_b_v2/)，[源图](../../art_source/environment/camp_style_full_b_v2/)与[生成器](../../tools/build_camp_style_full_b_v2.py)可重建。旧 B 全图保留作前后对照，不由正式场景加载。

## 现象、原因与改法

前版地纹将较小源图缩小、降对比并模糊，再以 1024×1024 循环，细节丢失且重复明显；道路由两层宽笔刷和模糊阴影叠成，缺乏可辨的铺装结构。围栏用 SVG 多边形与纯色填充，视觉上像矢量图；岩带把源图旋转并拉伸到长条多边形，产生严重形变。马车运行矩形为 365×200 参考像素，与 315×201 的仓库同级甚至更宽；中央灯将原图裁切后拉伸到 76×170，压窄了约 20%。

第二版使用保留原生像素的斜向铺石地表源图，裁出 1024×1024 的有效区并镜像为 2048×2048 循环纹理。原图含石片、压实泥土、少量碎石与枯草变化；生成时不再模糊。道路只在原控制线附近零散铺设小块等距石片，透明区保持 alpha 0，避免形成一整条发亮的笔刷色带。内部训练场四段围栏使用与铁匠铺木材质相近的像素源图，以最近邻缩小、逐跨拼接，并降低高度，使玩家和 NPC 不再看起来站在栏杆上。九段外围栅栏/岩带及训练场和马车外侧的两段围栏从布局、美术清单、碰撞和寻路中一起撤除；营地仍由原世界矩形边界限制，不在屏幕外继续移动。

马车运行矩形缩为 **220×125**，相对仓库宽度为 **70%**、高度为 **62%**；承重碰撞足迹随之收紧，没有留下旧尺寸的隐形障碍。中央灯改为 **84×150**，宽高比 **0.56**，与透明源图裁切后的约 **0.555** 基本一致。两者仍按整体背层与前沿层参与遮挡。

## 布局与行为自检

新布局源为 `data/map_art/camp_whitebox_v2.json`；`tools/build_camp_whitebox.py` 将它编译为营地 `maps.json` 配置及 `data/layouts/camp.json`。世界尺寸仍为 **3200×1800**，通行网格仍为 **110×110**。对旧掩码逐格比较，可走格 **4027 → 4894**，新增 **867** 格，没有把旧可走格改为不可走。5 个 NPC 的格坐标、两处出入口、马车旅行落点及地图服务点均与改前一致；测试对 11 处撤除位置逐点检查可走和无物理碰撞，对 7 个实体及 4 段训练场围栏检查一个实体对应一个整体碰撞与前沿美术。

旧 `camp-whitebox-v1` 存档的世界坐标仍有效，升级时只更新布局版本标记，保留玩家位置、营地迷雾与未领取战利品。更早的旧景观存档仍按原有迁移流程回到白盒出生点；这两条路径由 `CampLiveIntegrationTest` 检查。

`CampFullArtAcceptanceTest` 的四条正式玩家路线覆盖仓库、中央灯、马车、训练场，逐物理帧确认脚底在可走格，并在实际窗口保存局部图。[第二版全图概览、四条实走及 200% 地表截图](样板/幸存者营地B二版/)供视觉复核。200% 固定窗口截图中，石片轮廓、枯草和木栅的像素边缘保持可辨，未见前版整片地纹的模糊涂抹。最终定向回归：`CampFullArtAcceptanceTest`、`CampLiveIntegrationTest`、`MapTextureBatchTest`、`CampWhiteboxAcceptance`、`ChapterOneMapArtTest`、`ChapterOneAcceptance`、`MapCanvasCacheTest`、`MapLoadingCacheTest`、`SmokeTest` 全部通过；白盒九个目标实际移动可达。`ChapterTwoRoutesTest` 的沉井镇双向道路断言在本轮开始前的已提交快照中同样失败，不是这次营地改动造成；该项未算作通过。

## 运行成本

在同一 macOS Retina 设备、GL Compatibility 路径、1280×800 逻辑窗口，旧 B 全图使用本轮开始前的已提交快照，第二版使用本工作区；各独立进程跑两轮 `MapRenderBenchmark`。测试冻结玩法，只比较正式主场景的营地静态画面，每轮预热 20 帧、采样 120 个真实绘制帧：

| 指标 | 旧 B 全图 | 第二版 | 判断 |
| --- | ---: | ---: | --- |
| 正常画面中位帧间隔 | 1.253 / 1.207 ms | 1.144 / 1.222 ms | 差异落在轮次波动内 |
| P95 帧间隔 | 1.509 / 1.439 ms | 1.459 / 1.631 ms | 第二轮略高，不能宣称改善 |
| 平均绘制调用 | 182.2 / 182.2 | 181.2 / 181.2 | 少 1 次 |
| 正式营地场景装配 | 75 ms | 137 ms | 增加约 62 ms；各为一次独立进程测量 |

旧运行清单引用 31 张唯一纹理、约 **3.47 MiB** PNG 和 **27.48 MiB** 理论 RGBA8；第二版引用 20 张、约 **7.90 MiB** PNG 和 **30.78 MiB** 理论 RGBA8。2048×2048 地纹图集自身按 RGBA8 为 16 MiB，但撤掉外围素材抵消了部分内存增长。以上像素乘四是统一口径的**未压缩估算**，不冒充 Godot 纹理监视器的实测显存；磁盘体积也不是加载后的内存。所有纹理装配及道路散铺在构建或场景加载阶段完成，不在玩家移动时重建。静态基准不能代表密集战斗 FPS，正式战斗与长时间探索仍需在后续玩法验收中复测。

## 后续地图制作原则

先确定画面内真正需要的阻挡物，再让单一布局源同时驱动通行、碰撞与视觉清单；四周边界如果不是场景叙事所需，不靠长条石墙或栅栏填满。地面先建立与游戏镜头一致的斜向纹理及足够大的变化周期，道路通过局部材质变化或独立铺石表达，避免宽笔刷涂抹。整体物件先按角色、房屋比较尺寸并固定脚底锚点，随后用实际行走截图检查碰撞和前沿遮挡。最后在固定窗口复测清晰度、加载、纹理和帧时间，把增加的画质与成本一起记录。
