# UI 面板美化现状与改造清单

日期：2026-10-15。本轮**只梳理现状、不修改游戏代码或素材**。目标是确定还有哪些窗口没有接入共用面板外观，并给每个窗口标注缺口、目标形态与改造优先级，供后续逐项施工与验收使用。

## 1. 目的与判定口径

[04 设计规划](04-统一面板UI设计规划.md) 定义了三类使用形态（独立浮窗 / 居中模态 / NPC 对话），[06 修复方案](06-统一面板UI视觉修复方案与防偏差原则.md) 圈定的复用范围只覆盖了其中一部分面板。本文回答两个问题：

1. 除已改造的面板外，游戏里**还有多少窗口是原生或没有美化的**；
2. 这些窗口分别缺什么、改到什么程度算达标。

判定只看**是否实际应用了共用外观**，不看面板是否出现设计稿：

| 判定 | 含义 |
|---|---|
| **A 已接入** | 调用了 [`PanelChrome`](../../scripts/ui/panel_chrome.gd) 的外框与控件样式（切角、双层描边、标题横带、标题圆钮、金属操作按钮） |
| **B 自建简化** | 没有调用 `PanelChrome`，用局部 `StyleBoxFlat` 自绘了一个圆角描边外框，按钮仍走主题默认外观 |
| **C 完全原生** | 既没有 `PanelChrome`，也没有任何 `StyleBoxFlat` 覆盖，容器与按钮都是引擎默认外观 |

**关键事实**：项目主题 [`default_theme.tres`](../../assets/themes/default_theme.tres) 只定义了等宽字体（`mono_font.tres`），**没有为 `Panel` / `PanelContainer` / `Button` 定义任何样式**。因此只要不主动加样式覆盖，容器就是引擎默认灰面板——C 类不是"样式退化"，而是"从未做过"。

## 2. 共用外框组件的构成（A 类的判定基准）

| 部件 | 入口 | 作用 |
|---|---|---|
| 可伸缩外框 | [`PanelChrome._init()` / `_draw()`](../../scripts/ui/panel_chrome.gd#L24-L76) | 切角轮廓、双层描边、标题横带与四角金饰 |
| 标题 | [`style_title` / `title_text`](../../scripts/ui/panel_chrome.gd#L77-L88) | 标题菱形前缀与文字层级 |
| 圆钮 | [`style_close` / `style_help`](../../scripts/ui/panel_chrome.gd#L89-L96) | 关闭、帮助按钮使用正圆纹理 |
| 操作按钮 | [`style_action`](../../scripts/ui/panel_chrome.gd#L97-L108) | 金属渐变、高光、端部圆角的九宫格按钮 |
| 内容卡片与分组线 | [`style_card` / `style_section` / `style_separator`](../../scripts/ui/panel_chrome.gd#L173-L193) | 内容区低对比底框与分组线 |
| 浮窗管理 | [`floating_window.gd`](../../scripts/ui/floating_window.gd) | 标题栏拖动、点击置顶、Esc 取最上层 |

`PanelChrome` 只管外观，不承载玩法状态；[`FloatingWindow`](../../scripts/ui/floating_window.gd) 只管拖动与叠放。两者可独立接入——居中模态面板只需要前者。

## 4. B 类：自建简化样式，未接入共用外观（6 个）

这些面板用一小块 `StyleBoxFlat` 做了圆角描边底框，观感与共用外观**明显不同**：没有切角轮廓、没有双层描边与标题横带、标题没有菱形前缀、关闭按钮是原生方形按钮、操作按钮没有金属纹理。

| 面板 | 宿主节点 | 当前做法 | 主要缺口 | 目标形态 |
|---|---|---|---|---|
| **存档** | `Main/UI/SavePanel` | [`save_panel.gd#L74-L147`](../../scripts/ui/save_panel.gd#L74-L147)：`PanelContainer` + 圆角 `StyleBoxFlat` 卡片、纯 `Label`/`Button` | 外框、标题、关闭按钮、卡片全部为简化版；**覆盖确认是原生弹窗**（[`#L144`](../../scripts/ui/save_panel.gd#L144-L147)）；源码注释自述为「占位素材（R5）」「避免引入模态对话框（M4 才做统一对话框）」 | 改用 `PanelChrome`：外框 + 标题 + 关闭圆钮 + `style_card` 卡片 + `style_action` 按钮；覆盖确认纳入统一确认弹窗 |
| 仓库 | `Main/UI/WarehousePanel` | [`warehouse_panel.gd#L68-L90`](../../scripts/ui/warehouse_panel.gd#L68-L90) | 同上；背包/仓库是同一组格子控件（`ItemSlot`），两窗外观却不一致 | 改用 `PanelChrome`，与背包保持同款 |
| 升星 / 如意 | `Main/UI/UpgradePanel` | [`upgrade_panel.gd#L62-L85`](../../scripts/ui/upgrade_panel.gd#L62-L85) | 同上；另用**原生 `OptionButton`** 选装备（[`#L98`](../../scripts/ui/upgrade_panel.gd#L98-L100)） | 改用 `PanelChrome`；下拉控件样式需单独立项 |
| 大地图 | `Main/UI/MapBigPanel` | [`map_big_panel.gd#L57-L80`](../../scripts/ui/map_big_panel.gd#L57-L80) | 同上；面板内是自绘 `MapCanvas` + 图例文本 | 改用 `PanelChrome`，保留投影与缓存架构（[AGENT.md](../../AGENT.md) §2） |

| 装备更换确认 | `Main/UI/EquipmentConfirmation` | [`equipment_confirmation.gd#L29-L45`](../../scripts/ui/equipment_confirmation.gd#L29-L45) | 自建 `StyleBoxFlat` 一套；含 `CheckBox`、`ScrollContainer` | 改用 `PanelChrome`；须保持"暂停期间 UI 持续处理"与 `pending` 确认流程 |

## 7. 改造优先级建议

排序依据：玩家可见频次 > 观感落差 > 改造耦合度。

| 批次 | 范围 | 理由 |
|---|---|---|
| **P0** | 死亡选择、流程反馈 | 完全原生，且分别出现在每局死亡与开局加载 |
| **P1** | 存档、主菜单 / 暂停 | 入口必经路径；存档是用户已明确指出的窗口 |
| **P2** | 仓库、升星 / 如意、大地图 | 高频功能窗；仓库与背包应成对一致 |
| **P3** | 装备更换确认 | 已有自建样式，改造收益相对小 |
| **并行** | 原生弹窗统一（§6 前两项） | 与 P1 存档改造强相关，建议同期立项 |

## 8. 施工约束（来自现有规则，不得违反）

1. **不改交互语义**：[06 §1](06-统一面板UI视觉修复方案与防偏差原则.md) 明确「装备拖拽、窗口叠放、Esc、设置改键、背包容量和交易规则保持原样」。接入外观不得顺带改写模态、暂停、Esc 与焦点逻辑。
2. **面板互斥与模态语义保持**：存档 / 设置 / 死亡 / 流程反馈各有 `set_panel_open` 与互斥规则（如 [`save_panel._on_panel_opened`](../../scripts/ui/save_panel.gd#L66-L70)），只换外观不改状态机。
3. **共用外观的唯一入口**：样式集中在 `PanelChrome`，不允许各面板再复制一套颜色常量；B 类面板中局部 `COL_*` 常量（如 [`save_panel.gd#L17-L24`](../../scripts/ui/save_panel.gd#L17-L24)）在接入后应删除。
4. **不新增每帧成本**：外框为 `_draw()` 一次性绘制，接入不得引入逐帧重建、重复 `preload` 或全量节点重建（[AGENT.md](../../AGENT.md) §2 / §6）。
5. **必须补中文文件说明与函数说明**：按 [AGENT.md §8](../../AGENT.md) 要求，改动到的源码同步补齐。

## 9. 验收口径

- 外观：目标面板在 1280×800、界面倍率 100% 下与已确认样稿一致（无重复标题线、无切角留白被矩形底填充、关闭/操作按钮为共用纹理）。
- 回归：`PanelChromeLayoutTest`（共用外框布局）、`SmokeTest`（数据与流程冒烟）、`--quit` 启动回归（0 SCRIPT ERROR + 「配置校验通过 ✅」）。
- 交互：逐个开窗确认拖动、叠放、Esc、面板互斥与模态暂停与改造前一致。
- 交付：按 [AGENT.md §10](../../AGENT.md) 说明改了什么、保持了哪些行为、测试结果与已知限制；每个面板独立提交。
