## 结论摘要

需求可行，但要动三个环节，且第 1、2 项是**前置条件**：

1. **美术资产必须先拆层**：现有守护者图集把身体、披风、护甲、武器烘焙在同一张图里（[guardian_atlas.png](../../assets/sprites/player/guardian/guardian_atlas.png)），无法只更换衣服或武器。按决策 5，该图集**放弃重制**，`body_base` 从零画一套裸装男性。
2. **打包工具必须去掉自动裁剪**：[build_art_sample.gd](../../tools/build_art_sample.gd#L62-L86) 对每一格做 `get_used_rect()` 裁剪并按各层自身尺寸重新缩放——衣服层与身体层的裁剪范围与缩放系数都不同，**必然错位**。
3. **渲染侧**要在玩家身上从 1 层精灵变成 3 层精灵（含按方向调序），并让面板与头像共用同一份外观解析。

两个重要利好：

- **不需要改存档 schema**——外观由 `itemId → 模板 → 外观 ID` 推导，存档早已保存装备 `itemId`（schema 13），老存档读档后形象自动正确；
- **`EventBus.equipment_changed` 信号已存在**（[event_bus.gd#L37](../../autoload/event_bus.gd#L37)），三处（世界 / 面板 / 头像）共用同一刷新入口。

## 1. 需求口径

| 项 | 规则 |
|---|---|
| 影响外观的槽 | **只有 2 个**：护甲(`armor`)、武器(`weapon`) |
| 无护甲 | 角色（世界、面板、头像）**只穿裤衩** |
| 有护甲 | 穿上衣服 |
| 无武器 | 空手 |
| 有武器 | 手持武器，且**任何方向都不穿透身体** |
| 其余 12 槽 | 头盔、盾牌、鞋子、项链、护腕×2、护膝×2、手镯×2、戒指×2——**一律不影响形象** |
| 生效位置 | ①游戏世界中的玩家精灵 ②人物面板中间的形象区（复用世界素材并放大） ③HUD 头像 |

## 2. 现状勘察（证据）

### 2.1 世界形象：单层整体精灵

[player.gd#L218-L219](../../scripts/entities/player.gd#L218-L219) 在 `_ready()` 挂上 [sample_actor_art.gd](../../scripts/entities/sample_actor_art.gd)：

| 项 | 当前值 |
|---|---|
| 节点 | `SampleActorArt`（`extends Sprite2D`，子节点名 `SampleArt`） |
| 图集 | 3 张：主 `guardian_atlas.png`(512×640)、受击/打坐 `guardian_hit_sit_atlas.png`、行走 `guardian_walk_atlas.png` |
| 帧网格 | `hframes = 8`、`vframes = 8 / 2 / 4`（随图集切换） |
| 锚点 | `offset = -pivot`，`pivot = (32, 64)` → 脚底锚点 |
| 缩放 | `display_scale = ART_SCALE = 1.5` |
| 过滤 | `TEXTURE_FILTER_NEAREST` |
| 姿态 | 由 `_show()` 逐帧写 `frame_coords`，`_process()` 内叠加 `rotation` / `scale` / `position` 微形变 |

**运行时的帧坐标契约是 `frame_coords = (方向, 姿势帧)`**，即 **列 = 方向、行 = 姿势**：`facing` 依次为 `s, sw, w, nw, n, ne, e, se`（与 [01 §4](01-视觉与技术统一规范.md#L67) 方向顺序一致）；行序按 `_show()` 调用为 idle 0/1、walk 0–3、attack 5/4、hit 6、death 6/7。

> ⚠️ **工程里其实并存两套图集约定**（均已核实到代码）：①**玩家与普通怪**（[sample_actor_art.gd#L51](../../scripts/entities/sample_actor_art.gd#L51) 的 `frame_coords = Vector2i(facing, row)`）——**列＝方向（8 列）、行＝姿势帧**；②**精英与 Boss**（[monster_actor_art.gd#L51-L52](../../scripts/entities/monster_actor_art.gd#L51-L52) 的 `frame_coords = Vector2i(phase, facing)`，文件头注释"time on X, screen direction on Y"）——**列＝时间帧、行＝方向（固定 8 行）**。[01 §4](01-视觉与技术统一规范.md#L84) 原文只写了"每行一个方向"（描述的是第 ② 套），且举例误用了玩家图集尺寸，已按实测改正为"两套约定各自适用范围 + 各自举例"。**本方案的三层素材属于第 ① 套**，制作单必须写明这一点，否则整批素材会做反。

造型内容：单张图里同时包含披风、护甲片、护手与单手短刃，**没有任何分层信息**。

### 2.2 面板形象：静态一帧且从不刷新

[character_panel.gd#L114-L131](../../scripts/ui/character_panel.gd#L114-L131)：展示框 `custom_minimum_size = 172×410`：

```gdscript
var portrait := TextureRect.new()
var atlas := AtlasTexture.new()
atlas.atlas = preload("res://assets/sprites/player/guardian/guardian_atlas.png")
atlas.region = Rect2(0, 0, 64, 80)
portrait.stretch_mode = TextureRect.STRETCH_KEEP_ASPECT_CENTERED
```

- 取世界图集**第 0 列（方向 s，正面）、第 0 行（idle 起始帧）**；
- `EXPAND_IGNORE_SIZE + KEEP_ASPECT_CENTERED` → 按控件规则推算实际显示约 **172×215**（按宽度受限），即画布 64×80 被放大 **≈2.69 倍**（非整数）；
- `_refresh()`（[#L158-L186](../../scripts/ui/character_panel.gd#L158-L186)）只更新标题、身份行、14 个槽位与属性文本，**完全没有触碰这个 TextureRect** → 换装后面板形象不会变。

面板左侧列宽：`equip.custom_minimum_size.x = 315`（= 52 + 172 + 52 + 间距双 8+5），实测面板整体宽 **720**。

### 2.3 HUD 头像：场景内静态纹理

- 资源：`assets/ui/portraits/guardian.png`，实测 **96×96**；
- 使用：`Hud.tscn` 里 `StatusPanel/Portrait/PortraitImage` 直接 `texture = ExtResource("3_portrait")`（[Hud.tscn#L127-L137](../../scenes/ui/Hud.tscn#L127-L137)），显示区 `offset 8..80` → **72×72**，带圆形遮罩 material（`portrait_mask`），外圈装饰由 [hud_portrait_ornament.gd](../../scripts/ui/hud_portrait_ornament.gd) 绘制；
- 目标头像 `TargetPanel/TargetPortrait` 是同结构（怪物用，不在本次范围）；
- 结论：头像纹理**写死在场景里**，没有任何代码路径能按装备更换它。

### 2.5 打包工具：现阶段最大的技术障碍

[build_art_sample.gd](../../tools/build_art_sample.gd#L52-L87) 的 `pack_actor()`：

1. `bands()` 按不透明像素行数**自动探测横向条带**得到"姿势行"（[#L29-L46](../../tools/build_art_sample.gd#L29-L46)）；
2. 每格取 `get_used_rect()` **裁剪到内容包围盒**；
3. 用整张图集最大宽高算一个 `factor`，`resize` 后按 `pivot` **重新居中**贴回。

对"单张整体角色"可用，对分层素材是**致命**的：衣服层与身体层的 `used_rect` 不同 → 裁掉的边缘不一致；各自算 `factor` → 缩放系数不一致；居中贴回后谁包围盒更大谁更靠锚点 → **逐帧错位**。

## 3. 美术方案

### 3.1 分层结构

```
body   —— 躯干/头/腿/非持械手臂；持械手臂区域挖空（见 §3.5）
arm    —— 持械手臂 + 武器；空手时使用「空手臂」设计
cloth  —— 护甲外观（覆盖躯干/腿，不改手脚轮廓）
```

三层都不含脚底阴影（[01 §3](01-视觉与技术统一规范.md#L46)：脚底阴影单独交付、可运行时复用）。
**头像**另立两层的规格，见 §3.8。

### 3.2 对齐契约（本次最关键的美术约定）

| 约束 | 值 |
|---|---|
| 画布 | 三层统一 **64×80** |
| 锚点 | 三层统一**脚底 (32,64)** |
| 帧网格 | 三层统一 `hframes = 8`（列＝方向）、`vframes` 随图集（行＝姿势帧） |
| 帧序 | 沿用现有行序：idle 0/1、walk 0–3、attack 5/4、hit 6、death 6/7 |
| 方向序 | 列序沿用 `s, sw, w, nw, n, ne, e, se` |
| 缩放 | **三层共用同一个 factor**；禁止逐帧裁剪、禁止逐层单独缩放 |
| 透明边 | 图集帧边留透明安全区（[01 §5](01-视觉与技术统一规范.md#L92)） |
| 挖空区 | `body` 的持械手臂挖空范围必须 ≥ 所有 `arm` 设计的手部绘制范围，不能出现破洞 |

判定标准：**三层逐格叠合，任意方向任意帧上，身体轮廓的肩、肘、膝、脚底与 `arm`、`cloth` 完全重合，误差 0 像素。**

### 3.3 每个外观设计要交付的文件

与现有 3 张图集一一对应，**每个设计 3 张 PNG、共 112 帧**：

| 图集 | 网格 | 帧数 |
|---|---|---|
| 主（idle/attack） | 8 列 × 8 行 | 64 |
| 受击/打坐 | 8 列 × 2 行 | 16 |
| 行走 | 8 列 × 4 行 | 32 |
| 合计 | | **112** |

### 3.4 首批范围（只跑通初始装备）

| 设计 | 用途 | 帧数 |
|---|---|---|
| `body_base` 裸装男性身体（**从零重画**，现有图集已放弃） | 恒在的基础层，含持械手臂挖空 | 112 |
| `arm_empty` 空手臂 | 无武器时的 `arm` 层 | 112 |
| `cloth_cloth` 布革胸甲（对应 `armor_starter`） | 装 `armor_cloth` / `c2_road_armor` 时显示 | 112 |
| `arm_weapon_starter` 短直刃 + 持械手臂 | 装 `weapon_iron` / `c2_road_blade` 时显示 | 112 |
| 合计 | | **448 帧** |

比只做"恒在上层"的 MVP 多出 112 帧（`arm_empty` + 武器层独立成手臂层），这是决策 2（不穿透）的直接成本。素材规模按"每个护甲/武器设计各一套"逐个扩，**不做全组合包**。

### 3.5 不穿透的层序设计（决策 2）

**问题**：八向视角下持械手相对躯干有近侧/远侧之分。近侧方向武器应盖住躯干（`arm` 在最上），远侧方向武器应被躯干遮住（`arm` 在最下）。任何固定的单层顺序都会在另一半方向穿透。

**推荐方案：3 层 + 1 张方向顺序表**

| 方向组 | 绘制顺序（下→上） |
|---|---|
| 近侧（持械手在身体近侧） | `arm` → `body` → `cloth` |
| 远侧（持械手在身体远侧） | `body` → `cloth` → `arm` |

- `cloth` 相对 `body` **恒在上层**（衣服穿在身上）；
- `arm` 只在最下与最上两个位置之间切换 → 运行时只需 `move_child` 一次，且**只在 `facing` 变化时调用**，无每帧成本；
- 近侧/远侧的取值见下方"**方向顺序表初值**"，程序只读这一张常量表；
- `body` 必须按 §3.2 挖空持械手臂，否则远侧方向时身体自带的手臂像素会盖住武器；
- 空手时 `arm` 使用 `arm_empty`，此时顺序切换无视觉差异，逻辑不必特判。

**方向顺序表初值（程序侧定规则与初值，美术成图后逐列复核）**

判定规则：右手持械时，持械手相对躯干的深度只由**屏幕朝向的左右**决定——**面向屏幕右半 → 持械手在镜头近侧 → `arm` 在最上；面向屏幕左半 → 在远侧 → `arm` 在最下**；正下 / 正上两个方向手臂落在躯干轮廓外侧、与躯干齐平，层序无观感影响。

| facing | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|---|
| 屏幕朝向（[01 §4](01-视觉与技术统一规范.md#L67) 顺序，s 起） | s 下 | sw 左下 | w 左 | nw 左上 | n 上 | ne 右上 | e 右 | se 右下 |
| 持械手深度（右手持械） | 与躯干齐平 | 远 | 远 | 远 | 与躯干齐平 | 近 | 近 | 近 |
| `arm` 层位置（**初值**） | 最上 | 最下 | 最下 | 最下 | 最下 | 最上 | 最上 | 最上 |

- **谁定**：机制（3 层 + 8 项常量表）与初值由**程序侧**定；美术**只需在造型稿 / 成图后逐列目视复核一次**。若画出来的手与表不符，**改表＝改一行常量，零返工**，所以这项不必等美术先给答案。
- 依据：`facing` 的持械手方向＝屏幕朝向顺时针 90°（`(-f.y, f.x)`，已用 [iso.gd](../../scripts/systems/iso.gd) 的投影与 [sample_actor_art.gd#L43](../../scripts/entities/sample_actor_art.gd#L43) 的 `face()` 反推核对）；据此 `e / ne / se` 的手在镜头近侧，`sw / w / nw` 在远侧。
- **若最终改为左手持械，整表翻转**（近侧 ↔ 远侧）。
- 制作单须逐列登记"该列角色面向屏幕的哪个方向"（上表第二行），从源头避免美术按世界方向画反而整套出错。
- 0 / 4 两列按"面向镜头归近侧"取值；即便取反，这两列的观感差异也只在像素级，不影响验收。

**代价与残留限制（必须如实说明）**：

- 层级只能决定"**整层**放在身体前还是后"；**帧内的遮挡仍需美术逐帧画对**（例如挥砍时刀身从身前扫过、抬手时手臂压在护肩上）。这是像素画的固有边界，不是可以由代码解决的。
- 若后续发现"肩甲/披风应该盖住近侧手臂"，可升级为**身体前后拆分**方案：`body_back` / `body_front` 两个文件，`arm` 恒在中间。代价是身体层从 3 张变 6 张图集，且需逐帧拆分前后 —— 建议先按推荐方案做通，实机试玩后再决定是否升级。

### 3.6 面板形象：复用 + 放大（决策 1）

复用世界分层素材（`s` 方向、`idle` 第 0 行），**不另做精修立绘**，从而天然满足 [02 §2.1](02-分类素材设计规范.md#L49) "展示图不能另换画风"的底线。但需要"放大"，做法与约束：

已定案：**整数倍 ×4**。

| 项 | 现值 | ×4 目标 | 说明 |
|---|---|---|---|
| 展示倍率 | ≈2.69（按宽受限，非整数） | **恰好 4** | [01 §5](01-视觉与技术统一规范.md#L91)：非整数缩放的像素粗细会变化 |
| 画布显示尺寸 | 约 170×212 | **256×320** | 三层共用同一倍率；正好落在 [02 §2.1](02-分类素材设计规范.md#L49) "展示图建议 256×320" 的既有口径上 |
| 展示盒内区宽 | 170 | **必须恰好 256** | 见下方硬约束 |
| 展示框最小尺寸 | 172×410 | **258×410** | = 256 + 左右各 1px 边框（`StyleBoxFlat.set_border_width_all(1)`） |
| 面板整体宽 | 720 | 约 **806**（+86） | 目标分辨率 1280×800 仍可容纳；面板是浮窗可拖动，并排观感需实机确认 |
| 对齐方式 | 等比居中 | **保持脚底对齐、三层共用同一锚点与倍率** | 换装时形象不跳动 |
| 过滤 | `TEXTURE_FILTER_NEAREST` | 保持 | 像素画必须最近邻 |

**硬约束（做错就白做）**：展示用的 `TextureRect` 是 `EXPAND_IGNORE_SIZE + STRETCH_KEEP_ASPECT_CENTERED`，Godot 的缩放系数为 `min(盒宽/64, 盒高/80)`，因此**盒内宽必须恰好是 64 的整数倍**：

- 盒内宽 256 → `min(256/64 = 4, 410/80 = 5.1)` = **4**（整数）✅
- 盒内宽 272 → `min(272/64 = 4.25, 5.1)` = 4.25（非整数）❌ —— 恰好重现 [01 §5](01-视觉与技术统一规范.md#L91) 警告的像素粗细不均

高度只需 `盒高/80 ≥ 4`（即 ≥320），系数由宽度决定，现有 410 已足够（HBox 会按两侧槽列高度拉伸展示框，只影响高度）；同时展示框**不得加 `SIZE_EXPAND`**，否则宽度被容器撑开就会破坏整数倍。

参考量级：世界精灵里人形主体高约 48px（[01 §3](01-视觉与技术统一规范.md#L52) 的 40–48），×4 后在面板中约 **192px** 高，相比现状（约 129px）明显更大。

**世界玩家的 `ART_SCALE`（本次不动）**：现为 1.5（非整数缩放）。它只影响 3 处——精灵显示倍率（[player.gd#L219](../../scripts/entities/player.gd#L219)）、刀光起点高度（[player.gd#L539](../../scripts/entities/player.gd#L539)）、脚底阴影半径（[player.gd#L600](../../scripts/entities/player.gd#L600)），与碰撞、攻击距离、存档、面板、头像**全部解耦**；若改动需同步 [chapter_one_art_test.gd#L18](../../tests/chapter_one_art_test.gd#L18) 的断言（`display_scale == 1.5`）。因为素材按 64×80 制作、倍率只是运行时参数，**先做素材后调倍率零返工**，故本次保持 1.5，列为素材接入后的打磨项（实机对比 1.5 与 2 再定）。

## 4. 程序方案

### 4.1 数据：外观 ID 映射（推荐独立表）

| 方案 | 做法 | 评价 |
|---|---|---|
| A：装备表加字段 | `equipments.json` 每个模板加 `appearance` | 字段与装备语义混在一起；同档位多模板共用同一外观会重复登记 |
| **B（推荐）：独立外观表** | 新增 `data/appearance.json`：`{"armor_starter": {"layer": "cloth", "design": "cloth_cloth"}}` | 符合 [AGENT.md §5](../../AGENT.md#L59) "模板/实例/显示数据分开"；多模板共用只登记一次；外观缺失集中回退 |

配套一个**唯一解析入口**（例如 `Appearance.for_equipment(GameState.equipment) -> {body, arm, cloth}`）：

- 只读 `kind == "armor"` 与 `kind == "weapon"`，其余 12 槽直接忽略；
- 无武器时返回 `arm = arm_empty`；无护甲时 `cloth = ""`（不加载）；
- 该入口供**世界玩家、人物面板、HUD 头像三处共用**，避免各写一套映射；
- 就近顺序表也在同一处提供（`Appearance.draw_order_for_facing(facing) -> 顺序枚举`），常量表写在代码里但注明"取值来自美术确认"。

### 4.2 渲染：从 1 层精灵到 3 层精灵

在 [sample_actor_art.gd](../../scripts/entities/sample_actor_art.gd) 内新增 3 个子 `Sprite2D`：

| 要点 | 说明 |
|---|---|
| 挂载位置 | 作为 `SampleActorArt` **自身的子节点**（不是演员的子节点），自动继承它的 `rotation` / `scale` / `position` 微形变，**三层永远同步** |
| 对齐参数 | 子层同样 `offset = -pivot`、同 `hframes` / `vframes`、同 `texture_filter`、`centered = false` |
| 同步时机 | `_show()` 每次改 `frame_coords` 时**同步写三层**；切图集时三层同时切到对应状态文件 |
| 层序 | 按 §3.5 的顺序表，在 `facing` 变化时用 `move_child` 调整 `arm` 层位置（**不在 `_process()` 里做**） |
| 缺层处理 | `visible = false` 且**不加载纹理**，不是加载透明图 |
| 接口 | `attach()` 增加外观参数，或新增 `set_appearance(resolved)` |

> 反例警戒：不要让三层各自跑 `_process()` 做微动，也不要让每层独立做 `face()` 判断——那会把"同一次姿态决定"复制成三份逻辑，迟早不同步。

### 4.3 刷新时机、缓存与失效

| 触发点 | 入口 | 动作 |
|---|---|---|
| 穿戴/卸下装备 | `EventBus.equipment_changed` | 解析外观 → **ID 变化才切换纹理**，ID 相同不做事 |
| 读档 / 新档 | 玩家节点重建 → `_ready()` | 按 `GameState.equipment` 初始化三层 |
| 切换地图重建玩家 | 同上 | 同上 |
| 打开人物面板 / 装备变化 | `character_panel._refresh()` | 刷新面板三层形象 |
| HUD 初始化 / 装备变化 | `hud.gd`（或 `Hud.tscn` 的挂载脚本） | 刷新头像层 |
| 退出 / 切图 | 节点释放 | 释放层纹理引用 |

缓存要求（[AGENT.md §6](../../AGENT.md#L75) 要求说明键、所有者、生命周期、失效事件）：

- **键** = 设计 ID + 状态（main / hit_sit / walk）；头像键 = 设计 ID；
- **所有者** = 外观资源层（模块级缓存），不是每个玩家实例；
- **生命周期** = 首次用到时加载，之后复用；**禁止每次穿脱 `load()`**；
- **失效** = 设计 ID 集合变化、切图或读档导致缓存键不再需要时清理；
- 同一设计 ID 在不同实体间共享同一纹理实例（[AGENT.md §3](../../AGENT.md#L35) 禁止复制图片）。

### 4.4 面板改造

- 把 [character_panel.gd#L123-L131](../../scripts/ui/character_panel.gd#L123-L131) 的单个 `TextureRect + AtlasTexture` 换成 **3 个 `TextureRect` 叠放**（顺序 身体 → 衣服 → 手臂；面板只有正面，不需方向调序）；
- 固定取**方向 0（s，正面）、行 0（idle）**，三层用同一 `AtlasTexture.region`（64×80）；
- 按 §3.6 落实 ×4：[character_panel.gd#L122](../../scripts/ui/character_panel.gd#L122) 的 `portrait_frame.custom_minimum_size` 由 `172×410` 改为 **`258×410`**（内区恰好 256），`equip.custom_minimum_size.x` 由 315 改为 **378**（52 + 8 + 258 + 8 + 52），面板整体宽随之约 **806**；展示框不得加 `SIZE_EXPAND`；
- 建议抽共用控件（例如 `PaperDollView`），与 §4.1 的解析入口配对，让面板与世界的"外观→层文件"映射只有一份实现；
- 刷新合并：与 §4.3 同源，避免为一次穿脱重建整张面板（[AGENT.md §5](../../AGENT.md#L61)）。

### 4.5 打包工具改造（前置必做）

新增"网格打包"路径，替换 `pack_actor()` 的自动裁剪逻辑：

| 项 | 现做法 | 必须改为 |
|---|---|---|
| 切格 | `bands()` 自动探行 | 固定网格：`cell = 64×80`，按 `(col*64, row*80)` 直接取格 |
| 裁剪 | `get_used_rect()` 裁到包围盒 | **不裁剪**，保留整格空白 |
| 缩放 | 按各图集自身最大尺寸算 `factor` | 一个角色一个 **factor**，三层共用 |
| 贴回 | 按 pivot 居中 | 直接 `blit` 到 `(col*64, row*80)`，锚点由运行时 `offset` 承担 |

配套校验脚本（纳入验收）：逐层逐格检查锚点处的包围盒，输出**三层叠合校验图**供人工确认。

### 4.6 头像改造

- `Hud.tscn` 的 `PortraitImage` 不再依赖场景内 `ExtResource("3_portrait")`（按决策 5 该图已放弃），改由代码按 §4.1 解析结果设置纹理；
- 结构：`PortraitImage` 之下叠 2 个 `TextureRect`（`head_base` + `cloth`），**保持现有圆形遮罩 material 与 72×72 显示区**，装饰圈不动；
- 换装刷新与 §4.3 同一入口，一次穿脱只更新变化的层；
- 场景引用的静态纹理路径移除后，需同步清理 `assets/ui/portraits/guardian.png` 与 `.import`。

### 4.7 回退与容错

- 外观文件缺失 → 只画 `body`（+ `arm_empty`），按 [AGENT.md §3](../../AGENT.md#L41) 的限频日志机制报一次，不在每实例/每帧重复输出；
- 外部表缺条目 / 字段非法 → 回退默认（无衣服、空手），不阻塞玩法；
- **`body` 与 `arm_empty` 是必需层**，缺失应视为素材事故而不是静默降级；
- 方向顺序表缺项 → 回退"近侧"（`arm` 在最上），保证至少不出现武器消失。

### 4.8 存档

**不需要改 schema。** 外观完全由 `GameState.equipment` 的 `itemId` 推导，不新增存档字段；读档时按 §4.3 重建。老存档天然兼容。
