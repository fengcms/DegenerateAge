# 背面步态候选审查与阻塞记录

2026-11-18连续开发阶段，使用内置image_gen以已接入背面站姿生成四帧右上行走候选。源稿、提示词与审片参数保存在art_source/actors/hero_walk_ne_trial_v1。

## 证据与结论

四列512×768、2048×768源稿；第1、3帧均表现左侧腿向左下拖后、右侧腿向右上前伸，没有相反的接触姿势。第2、4帧虽有不同抬腿，但拼成循环仍不具备可靠交替步态。固定锚点的棋盘底审片能直接看到重复，不接受“有四张不同图片就等于完成行走”。

审片命令：`python3 tools/motion_review/launch.py --source art_source/actors/hero_walk_ne_trial_v1 --verify --capture /tmp/hero-rear-rejected`。Godot 4.7.2 Compatibility实机退出0，输出MOTION_REVIEW_VERIFY_OK与ART_NOT_APPROVED。此验证只证明审片工具播放、暂停、切帧和透明角可用，不证明动作质量。

## 影响与后续

候选状态明确为rejected_for_runtime，不复制到隔离营地或正式运行资源。背面暂保持现有单帧站姿；地图、移动、碰撞不受影响。源图理论RGBA8为6MiB，仅审片器加载，游戏新增成本为0。

阻塞是生成结果未遵守左右接触姿态，非播放器功能缺失。后续可针对第3帧纠正，或使用明确的背面骨架姿态约束重做。不能镜像整个人物（会换持剑手），也不能用代码缩放晃动代替真实姿态。按用户连续推进要求，修正尝试期间继续两类怪物待机素材和展示开发。
