# Boss技能表现美化方案

日期：2026-10-31。状态：设计方案，未制作素材或修改运行代码。

## 1. 现状与目标

本次静态检查了monster.gd、BossAction、GroundFx以及六章怪物配置。现有17个Boss的表现入口分为：第一章腐化巨兽的独立阶段行为；第二章三Boss硬编码的横扫/直线/圆圈/多点爆发；第三至六章13Boss的BossAction共享线/扇/圈与二阶段环击。第七章复用既有Boss时，应继承对应皮肤和技能语义，不额外复制一套特效。

monster.gd目前大量使用基础填充、轮廓和粗线表现预警；BossAction已经有锁定→预警→命中→后摇的时间结构，以及共用geometry。表现显得原始的原因主要是缺少材质主题、蓄力节奏、命中瞬间和消散层，而非缺少更多技能判定。

目标：让玩家一眼看懂危险在哪里、何时落下、哪一部分安全，并能区分不同Boss。第一期只改表现：伤害、范围、命中次数、锁定方向/坐标、阶段阈值、预警时长、动作间隔与安全通路全部沿用现有规则。没有实机截图/帧时间采样，本方案中的成本和观感判断为代码分析与设计建议，不代表已验证效果。

## 2. 统一视觉语言

危险预警采用深色地面底纹、稳定危险边缘和少量主题纹理。危险轮廓使用统一暖红/琥珀高对比语义；Boss主题色只放在内部纹理、实体出招和非判定碎屑中，避免绿地上的绿色危险圈难以辨认。静音或色觉差异下也能靠边界、形状与收束进度判断。

每次技能分四拍：

1. **锁定与起手**：武器/身体对应部位蓄光，地面危险边界立即完整显示。不要用逐渐扩大的轮廓冒充真正伤害范围。
2. **预警蓄力**：外围静态实线不动，内部符文/裂纹向命中点收束，或从中心填满。进度由原预警计时计算，不增加额外等待。
3. **命中**：伤害事件同一时刻触发短促亮芯、主形态冲击和局部碎屑。亮芯建议约0.05—0.10秒，主体约0.15—0.30秒，均为表现建议，需在实际帧率下验证。
4. **消散与后摇**：危险轮廓随本段判定结束退去，残留暗纹约0.25—0.50秒并迅速变淡。残留不继续使用危险色/进度条，明确它不会再次造成伤害。

地面圆必须通过GroundFx保持64×32等距投影下的2:1椭圆。屏幕空间的竖向冲击、火花和刀光可以抬高，但它们不能改变或掩盖地面的判定轮廓。

## 3. 五种共用形态

| 形态 | 预警美化 | 命中美化 | 可读性约束 |
|---|---|---|---|
| 直线/带状 | 两侧实线、内部箭头/刻痕向前推进、起点蓄光 | 沿锁定轴线扫出光带/地裂/根刺 | 整条危险区从一开始就完整可见；装饰推进不是沿途分段伤害 |
| 扇形横扫 | 清楚的两条半径边和弧边，内部低透明度纹理 | 贴合扇角的刀弧/爪痕/风刃 | 不旋转真实轮廓、不超出原扇角造成“视觉打到但实际没伤害” |
| 圆形落点 | 外环固定、中心符号收束，必要时显示本段序号 | 短促地面爆发＋竖向尘柱/孢团 | 落点锁定后不追玩家；避免柱体挡住下一段预警 |
| 局部环击 | 危险环带清楚填充，中心安全区不填危险纹理 | 从内边界到外边界的薄环冲击 | 中心不能被亮片、浓烟或全屏闪光误涂成危险区；继续复用现有内外半径 |
| 多段/多落点 | 当前段实线，后续位置仅在原规则允许时出现弱提示 | 每段各自命中、各自消散 | 不提前泄露原本未锁定的未来段；上一段命中后按原delay开始下一段 |

已有组件的“线”是带宽矩形、环击是环带。纹理必须适配真实几何，不用圆形贴图近似全部技能。

## 4. 17个Boss的视觉主题

以下仅为现有技能换表现，不新增追踪、弹幕、持续伤害或击退。

| Boss | 主题与现有招式包装 | 重点 |
|---|---|---|
| 腐化巨兽 | 爪击短爪痕；践踏龟裂土环＋暗红腐化脉冲；狂暴增加肩背腐光，召唤点短促灰尘 | 第一章教学预警最干净，践踏边界不能被尘土盖住 |
| 镇井监工·铁臂 | 横扫为沉重铁臂弧痕；直线为铆钉轨迹/冲压裂痕；召唤使用机械启动火星 | 金属火花短小、不能铺满整个扇面 |
| 炉渣吞噬者 | 直线为炉渣喷发带；三落点为暗裂纹蓄热后橙红爆芯 | 火焰不表现成额外持续火池 |
| 百臂汲灵机 | 圆形抽取阵、直线汲灵导管光流，阶段转换用短暂机械通电 | 不把装饰导管延伸到安全区造成范围误解 |
| 闸印守卫 | 双线采用闸印导轨、封条点亮，环击为闸门刻印冲击 | 两条线独立分段，左右锁定清楚 |
| 沉沙母螯 | 三落点为砂面下陷后螯刺/砂柱；环击为贴地砂浪 | 尘雾低而薄，中心安全区可见 |
| 空壳总督 | 三向扇形用空壳刃片与残影，环击用破碎面具纹 | 三次扫击不要合成误导性的全圆危险盘 |
| 无声巡林者 | 双扇扫为枝刃/叶片切痕，内纹偏苔青，危险边仍暖色 | 暗林场景用浅边缘托底，不用纯绿色危险提示 |
| 孢灯育巢 | 落点用孢囊鼓胀后短促荧光孢团，环击用孢纹波环 | 孢团及时散去，不遮挡后续落点 |
| 缠根守门者 | 双直线用根脉爬行蓄力、根刺瞬时齐发；环击用树龄环纹 | 地面完整线预警先于装饰根脉，防止误判仅根尖危险 |
| 驭潮号将 | 宽直线为潮纹推进、瞬间浪锋；环击为泡沫潮环 | 浪墙高度受控，不能盖住玩家脚底 |
| 裂舟噬骨者 | 四落点用船板裂痕与骨刺逐点爆出，环击为碎骨/水纹 | 保留四段节奏，不提前画出所有未来危险位置 |
| 逆风军团长 | 双扇用斜向风纹蓄力、双层切风刃；环击为贴地风带 | 装饰风丝可以淡出范围，主刀弧必须贴合真实扇区 |
| 裂隙统帅·执灯者 | 三扇用灯火投影与撕裂光弧，环击为破灯封印阵 | 主色暗金/紫黑，危险边界仍统一清楚 |
| 守誓审判体 | 同轴双线为刻印充能后两次审判落光，环击为誓印环 | 第二次命中必须有独立预警，不能只留第一次残光 |
| 前代残响 | 双扇用半透明旧影摆姿和刃痕，环击为记忆裂片 | 残影无碰撞、短寿命，不让玩家误认新怪物 |
| 裂隙主宰·空天之眼 | 三扇使用瞳纹/裂隙刃；环击是分明的内外瞳环；第三阶段加快视觉脉冲但沿用原预警 | 高级感来自节奏和层次，不靠全屏闪白；三阶段只改变已有间隔表现 |

BossAction共享phaseB逻辑可以共用环带骨架，但内部纹理、爆发材质和音色按上述主题替换，避免所有Boss的二阶段看起来完全相同。

## 5. 层级、声音与反馈

显示优先级：当前危险边界和玩家脚底可读性最高，其次Boss实体、命中主体，最后装饰碎屑。落地残纹贴地、实体爆发参与既有遮挡；不把所有VFX强行置顶。危险区重叠不能因特效预算被隐藏，重叠时优先降低内部填充透明度、减少装饰，保留全部有效边缘。

建议配套三类声音：起手材质提示、命中短冲击、阶段转换识别音。重复技能可有轻微音色变化，但音量并发限额且不能靠音频才能判断安全。镜头震动默认克制，只由玩家附近的重大命中触发并设全局冷却；密集Boss不能把震动线性叠加。提供或复用减弱闪光/震动选项，禁用后危险轮廓仍完整。

第一批优先做视觉，声音只登记事件与素材需求；音效制作和震动设置作为独立节点，不让缺音频阻塞可读性验收。

## 6. 实现结构

保留BossAction与现有第一/二章结算逻辑，新增表现适配层把三套入口转换为统一事件：cast_start、warning_progress、impact、recover、cancel。事件携带Boss/技能/段编号、锁定地面几何与施法ID。表现层不得根据当前玩家位置重新推导已锁定范围，也不得自行驱动伤害。

BossAction.geometry为第三至六章几何事实源；第一/二章先抽取其当前锁定几何的只读描述，适配显示和原判定，不借美化重新标定面积或改计时。GroundFx负责几何投影和危险轮廓，新的BossSkillVisual负责材质/动画皮肤；不能用装饰ring替代玩法outline。

建议使用Boss外观ID/技能表现ID关联视觉清单，登记纹理图集、帧率、锚点、地面/抬升层、色板和持续时间。没有清单的技能回退到当前基础几何，玩法继续可用。配置不复制怪物伤害、半径和预警秒数。素材设计源稿放art_source/或素材设计目录，只有裁切打包的运行图集进入assets。

阶段终止、Boss死亡/脱战/复位、切图/读档、节点释放时通过施法ID取消关联表现。暂停和游戏速度沿用同一玩法时间源，表现不能在暂停时自行提前消散。攻击动画命中帧对齐结算事件，不等动画播完才伤害。

第一期优先程序几何＋共享小图集：纹理主要表达裂纹、符文、爪弧、砂/孢/水/裂隙材质。复用现有Boss实体动画，不给17只Boss各做一整套巨大逐帧全屏特效。确需新抬臂/攻击姿势时，按现有外观动画清单单独补帧并明确脚底锚点与命中帧。

## 7. 性能边界

以百首禁域密集Boss、长时间自动战斗为正常场景。危险提示不能因降级消失，降级只影响可替代装饰。

建议初始装饰预算：每段1个主体特效、最多1层地面残纹，单次小碎屑8—16个；全屏装饰碎屑先设总量约128的候选预算，通过实测调整。远离屏幕的Boss不创建纯视觉装饰，但战斗和命中状态照常更新；进入画面时按当前阶段恢复必要预警。仅剔除表现，不借此改变战斗。

资源共享，首次进入相关地图预热所需图集，避免第一次放技能时加载文件。缓存按视觉ID/皮肤版本持有，切图释放无使用资源；几何在锁定或段切换时生成，不逐帧解析JSON/重建网格。预警每帧只更新少量进度参数。特效随时限/施法取消释放；只有实测实例化尖峰后才考虑有上限对象池。

GL Compatibility为现行验收后端，不默认依赖昂贵屏幕扭曲、全屏泛光、动态灯光或大面积多层透明叠加。不改变渲染后端。纹理尺寸按实际屏幕显示制作，裁掉透明边缘，评估解码显存而非PNG体积。

同设备、分辨率、UI/地图缩放、Boss数量和行进路线，改造前后记录整帧P50/P95/P99/峰值、脚本/物理/渲染耗时、绘制调用、显存和节点数。headless只验逻辑/CPU；窗口测GPU表现。先测试单Boss，再密集Boss与30分钟挂机；不能用关闭预警或缩小判定换性能。

## 8. 推荐实施顺序与验收

**节点一：清单与样板。** 建立17Boss技能表现映射，记录原技能时序与锁定几何；先做“腐化巨兽践踏＋闸印守卫双线＋一个环击”三类样板。提供真实游戏尺寸的静帧和完整动效录屏，确认材质方向和可读性后再铺量。节点完成commit。

**节点二：共享表现骨架。** 完成事件、取消清理、投影、进度与缺素材回退，覆盖线/扇/圈/环/多段；旧逻辑的命中次数、范围、预警和安全区回归。节点完成commit。

**节点三：主题批次。** 分为腐化/工业、沙地/林地、潮汐/裂隙三批接入，每批真实窗口验收并单独commit。每个Boss至少有起手、命中主体、消散和阶段转换识别；不只替换一个颜色就算完成。

**节点四：密集场景收口。** 多Boss重叠、玩家与地形遮挡、暗/亮地图、最大地图倍率、低帧、暂停/变速、死亡复位/读档切图、长挂机资源增长；完成性能对照和回归后commit。音效与震动可单独作为后续节点。

具体判定：玩家从预警首帧就能看清完整危险轮廓；命中与结算对齐；安全中心始终不填危险色；装饰消退不掩盖下一段；色彩不依赖单一红绿区分；取消后无残留活动节点。每种几何在多方向测“画与判同源”，不接受截图好看但动作时序错位。

建议先做3个样板确认，再投入全量17Boss。样板阶段优先交付可在实际游戏内观察的动效，不仅是放大的概念图。
