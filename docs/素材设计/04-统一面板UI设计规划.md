# 统一面板 UI 设计规划（待确认）

本文件规划背包、人物、技能、坐骑、NPC 对话与设置面板的共同视觉语言和接入顺序。**本阶段只确定方向与验收口径，不制作效果图、不改场景或玩法。**尺寸是 1280×800、界面倍率 100% 下的设计起点；下一步先做可编辑 SVG 样稿，经确认后再成为正式制作规范。

## 1. 现状与设计目标

目前 HUD 已采用暗铁、旧金属、浅金刻纹和少量冷色灵能光；小地图、头像与快捷栏的细框和内暗面已有质感。弹出面板仍多由各脚本分别生成：人物、技能、设置约用 `#11171d` 底和灰色细框，背包与 NPC 面板又有各自颜色、字号、内距和关闭按钮。功能可用，但同一游戏里的窗口看起来不像同一套器物。

本轮希望形成一套**「旧铁框架＋深色内衬＋克制的鎏金/刻纹」**面板语言，延续已确认的 HUD 质感。面板主体要留出安静、清楚的内容区域；装饰集中在外沿、标题两端、当前选项卡和重要操作上，不用大面积纹理压住文字和物品。优先改善层级、对齐、字体与状态辨识，而不是增加厚重底座。

现有交互是设计约束：背包、人物、技能、坐骑可同时打开、拖动、点击置顶，Esc 关闭最上层；货郎交易时背包与货郎并排。设置、地图、存档和 NPC 会话属于关闭式/模态流程。统一的是**组件视觉与排版规则**，不是把所有窗口强行改为相同尺寸、相同选项卡或相同开关逻辑。

依据：[视觉规范](01-视觉与技术统一规范.md)、[分类素材规范](02-分类素材设计规范.md)、[UI 与交互产品规范](../产品文档/09-UI与交互规范.md)；实现入口包括 `scripts/ui/floating_window.gd`、`inventory_panel.gd`、`character_panel.gd`、`skill_panel.gd`、`mount_panel.gd`、`settings_panel.gd`、`quest_panel.gd`、`shop_panel.gd`、`carter_panel.gd`、`blacksmith_panel.gd`。

## 2. 共用骨架与三种使用形态

```text
╔═ 左上刻纹 ── 标题 / 可选副标题 ───────── 帮助  关闭 ═╗
║  可选选项卡：当前页 / 其他页 / 溢出入口                 ║
╠══════════════════════════════════════════════════════╣
║                                                      ║
║  内容区：格网、属性、列表、预览、NPC 台词或设置控件   ║
║  由具体面板提供，必要时只让内容区滚动                 ║
║                                                      ║
╠══════════════════════════════════════════════════════╣
║  可选底栏：状态说明 / 金币 / 主要动作与次要动作        ║
╚═ 下角金属收口 ───────────────────────────────────────═╝
```

| 形态 | 面板 | 共用外观如何使用 | 交互边界 |
|---|---|---|---|
| 独立浮窗 | 背包、人物、技能、坐骑 | 标准框、标题栏、内容槽、可选底栏 | 标题栏仍可拖动；各自关闭；叠开不叠加暗色遮罩 |
| 居中模态 | 设置、大地图、确认弹窗、任务/车夫/铁匠等服务面板 | 同款框体，按内容调整宽高；危险确认可用更明显的边框 | 保留现有焦点、Esc、遮罩、暂停/不暂停语义，不用视觉统一改写逻辑 |
| NPC 对话 | 当前 NPC 自我介绍与功能菜单，未来逐句推进 | 共用框体与标题，内容区换成头像/姓名/台词/继续或服务动作 | 逐句对话是后续功能，现阶段只预留其布局；不把未实现分支画成可点击选项 |

共用框体不承载玩法状态。内容、数值、选中项、锁定原因和键位全部由运行时文本/控件显示，不烘进贴图。背包/人物的装备拖拽与比较浮层、设置改键冲突弹窗等保持现有独立逻辑。

## 3. 视觉令牌与尺寸草案

基准配色沿用旧有 [01 规范](01-视觉与技术统一规范.md)，以下值供样稿试色，确认后再固化为主题资源。与已确定的品质色、HP/MP、任务状态色分开；不以金色表示所有可交互内容。

| 层次 | 建议 | 用途 |
|---|---|---|
| 外轮廓 | 深墨 `#171A21`、旧铁 `#353B46`、少量旧金 `#A89978` | 双层细框、角部铆钉/刻纹，避免整圈高亮 |
| 主内容底 | 近黑蓝灰 `#11171D`，局部抬层 `#1B242B` | 护住文字，避免地图纹理透过正文 |
| 正文与弱文 | 骨白 `#E6DDC6`、冷灰 `#A7B0B5` | 正文/数值；说明、时间、未选中信息 |
| 强调 | 浅金 `#D6BA7F`、灵能青 `#78D8D0` | 当前页、主要动作、小面积选中或可拖来源 |
| 警告 | 危险橙 `#FF623A` | 不可逆操作和拒绝原因；品质色继续由现有系统决定 |

基准外框建议 2–3 px 视觉厚度，角件控制在约 20–28 px；正文区域内距 16–20 px，标题栏高约 44–52 px，区块间距按 4 px 网格取 8/12/16 px。框角可有斜切/轻微如意刻纹，但中段是可伸缩的直边。贴图采用角件＋边件或九宫格，避免拉伸刻纹；与 HUD 金属细节相似，不能比物品与角色更亮。浮窗在并排交易或 200% UI 缩放时允许收窄，不能用固定大 PNG 作为整张窗口。

已有面板宽度约为：人物 670、技能 600、坐骑 620、设置 650、任务 620、车夫 560、铁匠 430 px；背包由格数和操作行决定。这些是现状参考，样稿按**内容所需宽度**分别定稿，不强制六种面板同宽同高。

## 4. 共用部件规范

| 部件 | 设计与内容规则 | 必备状态 |
|---|---|---|
| 标题栏 | 左侧标题；可选人物等级、NPC 身份等副信息；右侧帮助（如有）和关闭。标题可拖动的浮窗必须保留完整可抓取区域，按钮不触发拖动 | 常态、窗口置顶、失焦；关闭悬停/按下/键盘焦点 |
| 选项卡 | 与面板上边框衔接的矮页签；当前页用浅金底缘/小刻纹，未选页用低对比铁灰。标题是运行时文字，随文字倍率变化 | 默认、悬停、选中、键盘焦点、禁用；页数多时滚动/换行或明确溢出，不能挤小字体 |
| 内容槽 | 同一暗色内衬，可分单栏、双栏、格网和图文区；局部浅分割线。信息量大时仅内容区滚动，标题与关键动作保持可见 | 空、加载/无数据、选中、可操作、禁用、错误提示 |
| 常规按钮 | 深铁底、旧金边；主要动作可加暖金高光，危险动作加橙红提示。按钮文字不烘图 | 默认、悬停、按下、焦点、禁用；禁用须给原因 |
| 表单控件 | 滑条、复选框、下拉、键位按钮和滚动条共用边框/焦点形状；滑条填充用少量青色 | 含已改动、冲突、等待按键、禁用状态 |
| 信息提示 | 物品比较浮层、帮助提示、错误行使用同一色值与字级；数字与品质/警告颜色遵循原系统 | Tooltip 位于面板上方；拖拽幽灵位于所有面板上方 |

**选项卡只用于真实存在的内容分类。**设置维持「音频、画面、游戏、控制、数据」五页，商店保留已有购买/出售页签。背包的筛选仍是展开区域，人物的装备与属性仍同屏，坐骑列表与预览仍同屏；技能先保留当前可用/未接线内容展示，不为了视觉对称制造空页。NPC 的「继续」和服务动作是对话流程，不伪装成页签。

## 5. 文字与信息层级

当前工程主题是 16 px 等宽系统字体，中文通过回退显示。样稿先沿用现有字形，重点统一**字号、字重、行距、留白**；若将来更换中文字体，需单独核对许可、字符覆盖和中英文对齐。

| 文本角色 | 100% 基准建议 | 规则 |
|---|---:|---|
| 主标题 | 20 px、加粗或视觉加重 | 一行优先；长 NPC/地点名可省略并提供完整悬停，不覆盖关闭按钮 |
| 选项卡/区块标题 | 15–16 px、略加重 | 当前页靠线条/刻纹与颜色共同辨识，不只换文字颜色 |
| 正文/表单标签 | 15–16 px | 中文段落建议行高约 1.35–1.5；列表名称与数值列对齐 |
| 数值/按钮 | 15–16 px | 金币、等级、属性使用等宽优势；主次动作区别靠框和位置 |
| 辅助说明/禁用原因 | 13–14 px | 可读但弱于正文；锁定、金币不足等原因不可只靠 Tooltip |

文字不能烘进边框或页签 SVG。长说明允许换行，面板内容列可以滚动；技能详情卡应完整自然撑高，不设置卡片内部滚动条。禁用理由与重要状态用文字＋形状双重表达。文字倍率由现有 `SettingsRuntime` 统一处理，尤其要覆盖运行中新建行、`TabContainer` 内部 TabBar、原生悬浮提示和改键按钮；界面倍率与文字倍率不得重复叠乘。

## 6. 面板内容编排

| 面板 | 主体布局建议 | 需要特别保留的行为 |
|---|---|---|
| 背包 | 上方容量/金币摘要；整理、扩容、出售、筛选组成简洁工具行；下方物品格网为视觉主角 | 格子数量动态变化、滚动、数量/品质/冷却；交易并排与拖入出售托盘；满包与 Lv15 限制 |
| 人物 | 中央角色形象，左右 14 装备槽；属性列表独立窄列 | 与背包并开才能穿脱；装备对比与槽位编号清楚；不添加怪物列表 |
| 技能 | 紧凑单列行卡常驻图标、名称、阶数、基础冷却与状态；详细效果、升阶对比和三种冷却口径放入与 UI 同层、无内部滚动的完整浮层，自动红/蓝药独立分区（细则见《49-技能面板信息分层与冷却展示改版方案》） | 技能与自动红/蓝药仍可作为快捷栏来源；未解锁项不可拖放；升级按钮和打开面板后的自动战斗保持原行为 |
| 坐骑 | 左侧收藏列表，右侧大图、名称、速度加成、来源与骑乘动作 | 未拥有/等级不足仍可查看；按钮禁用原因明确；不新增飞行等能力 |
| 设置 | 固定标题＋五页页签；每页表单行标签/控件/当前值对齐；「控制」页单层滚动键位列表 | 改键等待状态、冲突交换确认、即时生效与原有本机/存档设置边界 |
| NPC 对话/服务 | NPC 名称与可选头像在标题附近；短台词居中/靠左阅读；底部「继续」或现有服务入口。任务、商店、车夫、铁匠可切换各自内容模板 | 任务状态、费用/不可达、交易背包并排、升星入口各照现有逻辑；逐句台词与分支待另行定义 |

本计划的「NPC 对话面板」首先统一**视觉容器和单句/功能菜单的布局位置**。当前任务、车夫、货郎、铁匠分别由不同面板实现，铁匠已有简单「继续→升星」流；完整逐句推进尚未成为共用系统。若后续要合并交互逻辑，应单独设计会话状态、关闭与任务推进，本轮美术接入不顺手重写。

## 7. 响应式、遮挡与验收

- 以 1280×800 为基础，再看 1440×900、1920×1080、4K；至少覆盖界面 80/100/150/200% 与文字 100/150/200% 的关键组合。依据实际**逻辑可用尺寸**收窄面板；内容可滚动或从双栏改为上下排，关闭、确认、取消永远留在可见区域。不要缩小正文来掩盖溢出。
- 浮窗叠开、背包＋货郎并排、设置打开、NPC 会话、拖物品至快捷栏都需各拍一张实机图。遮罩只出现于原本的模态流程；多窗不重复叠暗。Tooltip、比较卡、拖拽幽灵、Toast 的层级不得被外框压住。
- 选项卡与按钮需要鼠标和键盘焦点可辨；Esc 与可重绑快捷键行为保持原样。按键捕获期间显示正在等待的动作，冲突时清楚写出交换双方；不能因新样式让「控制」页再次空白。
- 检查长 NPC 名、长技能说明、40 格以上背包、空坐骑收藏、已拥有/未拥有、金币不足、未解锁/未接线、任务完成/未领取、滚动条到底、关闭后重开、读档后数据刷新。
- 仅改视觉与排版时，装备结算、物品拖放、交易、任务、旅行、坐骑和设置保存应保持不变。复用现有数据与信号，不在 `_process()` 重建面板；静态框和图标共用导入资源。

## 8. 建议交付顺序与确认点

1. **视觉样稿**：在 `docs/素材设计/样板/统一面板UI-v1/` 做可编辑 SVG：标准浮窗（人物/背包并排示意）、设置五页之一及页签状态、NPC 对话/服务样式各一张；另附局部放大图展示角件、按钮、焦点、禁用和文字。先给你看图，可直接在 SVG 上修改。
2. **确认设计令牌**：你确认框体厚度、金属明暗、标题字级、页签样式、内容留白后，整理最终尺寸与切片清单。此时再决定需不需要新增专门中文字体。
3. **制作共用资源与主题**：输出九宫格/角边件、按钮、页签、滚动条、表单状态；在 Godot 做一张组件预览场景，先验证拉伸、文字倍率与低分辨率。
4. **逐面板接入**：先背包＋人物（最能暴露并排、拖拽和信息密度问题），再技能＋坐骑，随后设置，最后 NPC 对话/任务/商店/车夫/铁匠。每批保留旧交互并单独截图、测试、提交。
5. **统一复核**：对所有面板做多窗、模态、键鼠、缩放、长文字和功能回归；再决定是否扩展到仓库、强化、大地图、存档和其他确认弹窗。

**本次请先确认方向**：是否采用这套与现有 HUD 呼应的「轻薄旧铁＋暗色内衬＋少量旧金刻纹」；是否同意四个常驻窗口保留自由叠放、设置和 NPC 使用同款框体但维持模态；以及下一步先看三张可编辑 SVG 样稿。确认后才进入效果图制作与游戏接入。
