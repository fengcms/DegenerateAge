# 姿态约束行走试制与透明检查记录

2026-11-17。本轮完成可重建的四姿态约束图、第二版动作候选及审片工具扩展；正式行走动画仍未通过，营地和正式游戏未改动。

## 这次改变了什么

58号试制仅用自然语言要求左右脚交替，未得到可靠结果。这次先用Blender建立显式的左右肢体和足部目标：前方为-Y，左肢蓝、右肢红；第1/3姿态分别左脚/右脚前伸，第2/4姿态分别左/右支撑。大腿、小腿各0.46米，用解析双骨解求膝盖位置，脚底高度以0为接触平面。

这只是姿态参考，不重用旧look_06不合格三维人物，不改变已认可美术方向。图像生成仍使用内置image_gen，未以简单几何冒充主角美术。

## 实测结果

Blender5.2.3运行build_pose_guide.py，退出0并输出POSE_GUIDE_OK。所有骨段长度与0.46米误差小于1e-6；第2姿态左脚、第4姿态右脚接触高度误差小于1e-6米。其余坐标见art_source/actors/hero_walk_pose_v2/pose_checks.json。它仅验证四个关键姿态，不验证连续移动时脚锁定、重心或步态自然度。

图像生成共四次：姿态+身份双参照、姿态单参照、背景移除、平光重制。选第二次作为代表候选。目视第1/3姿态已不像V1直接重复同一侧腿的前伸，说明姿态约束有帮助；但胸甲失去原稿圆环特征，披布与剑角度不同，帧间位置仍漂移，未达到身份一致和循环质量标准。双参照稿的帧角透明检查失败，未放宽断言或接入。

运行Godot4.7.2 Compatibility，Apple M1 Max真实窗口，命令：

```sh
python3 tools/motion_review/launch.py --source art_source/actors/hero_walk_pose_v2 --verify --capture /tmp/hero-motion-pose-v2
```

退出0，输出MOTION_REVIEW_VERIFY_OK及ART_NOT_APPROVED。原有暂停、切帧、慢放、循环、资源共享验证保留；新增底色状态、姿态条带独立切换及棋盘底截图颜色差异验证通过。V1默认输入的逻辑回归也通过。

## 透明度判断的更正

生成预览看似有大面积棕色光晕，但Godot浅色底合成没有显示同样现象；源图(90,220)、(470,400)、(1000,250)的alpha均为0。不能把预览中的RGB外观直接当作运行时的alpha合成结果，因此取消“明显光晕”作为该候选的确定性否决原因。

另一方面，Godot检测四帧非零alpha包围盒分别为(9,9,503,739)、(0,9,512,743)、(0,9,512,743)、(0,29,506,739)。部分弱透明像素触及格边，并非干净紧裁的运行图集；三个零alpha采样点不足以证明所有背景无污染。没有自动裁掉这些区域或用阈值处理原稿，后续应在实机背景中复核边缘和串帧。

## 交付范围与代价

tools/motion_review新增--source、G姿态对照、B深浅/棋盘底，支持独立候选复核。新源图、生成提示词、姿态图和检查数据在art_source/actors/hero_walk_pose_v2，未加入assets或营地资源复制。新增一张姿态图约6MiB理论RGBA8显存；它与四个区域共享引用，切换条带不复制纹理。背景只在切换时重新记录绘制命令，但保留命令仍有渲染成本；审片器不承担正式游戏性能验收。

本轮成功的是姿态约束与可复核工具，角色行走仍未完成。下一步应在保持原主角胸甲、腰摆、武器位置的前提下，分别修正关键姿态，再检查整段循环；不扩八向，不追加攻击帧掩盖基础动作问题。
