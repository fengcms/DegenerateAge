# 营地模块化地图落地方案

日期：2026-11-17。纠正49、50号方案执行中的偏差。用户认可的是美术风格，不是整图地图实现。本文件规定接下来的地图生产与接入方式；不宣称以下模块已经制作完成。

## 1. 纠偏结论与证据

上一轮把空营地概念图作为查看器背景，只拆出了角色。它能看颜色与尺寸，无法验证地形拼接、建筑遮挡、路线编辑或碰撞，因此不属于可用地图样板。继续缩放这张背景不能解决问题。该图从此只作风格参考，不作为下一版地图的运行依赖。

仓库24号《地图素材丰富化》已经记录过整图路线的问题，本轮没有把该经验落实到制作入口，这是执行上的错误。其历史像素风结论已被本轮用户认可的写实风格取代，但模块化分层原则仍适用。

| 当前入口 | 已有能力/边界 | 本次处理 |
|---|---|---|
| `scripts/systems/iso.gd::grid_to_world` | `(col-row)*32, -(col+row)*16`，64×32菱形 | 完全保留；网格方向不能误当屏幕上下左右 |
| `scripts/world/ground.gd::_draw_tile_floor` | 图集加FlatTileMesh，逐格选图但批量绘制 | 复用底层合批，不改成每格节点 |
| 同文件 `_chapter_one_road_tile_index` | 四邻位掩码；明确处理0、1、2、4、8、3、6、12、9，其余回退中心 | 新主题采用完整过渡规则；旧主题保持原表现 |
| 同文件 `_load_camp_final_art` | 循环地纹、大画幅road_overlay、back/front实体、foot_y | 不把新营地继续烘成全图道路；新增显式模块主题入口，与旧营地资源兼容 |
| `scripts/world/chapter_one_map_art.gd`、`sample_camp_props.gd` | 独立对象按脚底世界Y排序 | 复用坐标和排序口径，禁止另建互相冲突的深度体系 |
| `sample_actor_art.gd`、`monster_actor_art.gd` | 玩家/怪物按世界Y设置z_index | 新场景物件与其共用绝对z口径，而非只在查看器里开y_sort |
| `ground.gd::_load_camp_whitebox`、`_add_camp_collision` | 布局版本检查、白盒碰撞 | 新素材摆放必须与同源布局绑定，不能独立画一套视觉障碍 |

上述为源码核对；本轮不新增实机与性能测量。上一轮独立查看器的截图只能证明静态贴图能显示。

## 2. 地图怎样组成

运行地图由以下数据和小资产组合：

```text
地形格表 ──> 64×32基础地砖 ───────────> 地面合批网格
道路格表 ──> 邻接规则选择透明过渡砖 ──> 道路合批网格
贴花实例 ──> 草根、碎石、磨损补丁 ───> 贴地静态层
物件实例 ──> 墙段、树、棚屋、木箱 ───> 脚底排序层
同源占地 ──> 通行掩码与碰撞 ────────> 既有寻路和移动
```

建筑可以是一栋独立贴图；不能把整片地图画成一张图。可复用的墙段必须分件；需要让人物从不同部分穿过的长建筑/拱门必须分段或拆前后层。基础地面、道路、草、墙、屋分别可替换和移动，互不要求重画全图。

## 3. 第一批最小资产包

先做16×16格拼装实验区（256格，地面投影外接范围约1024×512），包含一个十字路口、一个转角、一条窄路、一个棚屋院落。画布可为建筑向上外扩，不能因此改变网格尺寸。

| 类型 | 首批数量 | 运行规格与制作要求 |
|---|---:|---|
| 低对比土底 | 4变体 | 64×32 RGBA；相邻边采用共同纹理边界约束，变化集中在内部 |
| 灰绿草底 | 4变体 | 同上；和土底同光照同亮度体系 |
| 土草过渡 | 47种连接形状 | 64×32透明覆盖砖；由一个草材质母版和统一掩码构建，不单独生成47张互不一致的画 |
| 踩实道路 | 2中心纹理＋47种连接形状 | 64×32透明砖；原始道路形状来自道路格表，材质与过渡mask分离 |
| 草根/碎石/磨损贴花 | 每类2，共6件 | 64×32或128×64；透明底，可跨格，无碰撞；限制密度，禁止遮盖全部拼缝掩饰失败 |
| 低石墙连接件 | 8件 | 两个网格轴向直段、四个转角、两个端头；占地一格宽，长度一或两格；建议画布64×96/128×128，以实际裁切为准 |
| 石块 | 2件 | 一小一中；足部锚点、占地与碰撞明确，不能随机旋转带光照贴图 |
| 树 | 1套 | 树干/树冠分层，共同锚点；画布初始上限256×320，根部占地约2×2格，树冠不形成同等面积障碍 |
| 棚屋 | 1套 | 墙体背层、屋顶/前檐等必要前层；占地暂定4×3格，门口留空；画布上限384×320，按最终轮廓裁切 |
| 木箱、木桶、灯柱 | 各1 | 独立透明物件；木箱/桶占地，灯柱细碰撞；第一版灯火烘焙，不引入动态光 |

47形状指标准八邻接连接组合：某个对角仅在相邻两条正交边均连接时有效；规范化256个邻域得到47种。使用网格N/E/S/W和对角编码，再经Iso投影，不按图片屏幕方向命名。孤岛、端头、直段、转角、T口、十字与内凹角都要有明确定义。它是待实现的新主题规则，不是当前代码已经支持的能力。

47张是程序根据材质和审核后的遮罩构建的结果，不是47次AI生成。第一步先用纯色mask验证所有连接，再贴真实材质。内角/外角纹理跨边一致；过渡带带少量自然破口，但破口不得断开道路视觉中心。单格窄路另设检查，不能由当前“其他组合返回中心”覆盖问题。

## 4. 尺寸、坐标与资产契约

统一以实际显示高度约96px的成年角色为标尺，门洞净高先取110～125px，仅作视觉起点；门口通行宽度由当前角色碰撞半径12和既有导航间隙验证。禁止因画布宽大就推断占地宽大，也不按画面缩放反改角色碰撞。

每个模块必须提交：`id`、纹理路径、像素尺寸、`pivot_px`、网格占地、排序锚点、前/背层关系、碰撞类别、材质族和来源。拟议物件定义与实例分开：

```json
{
  "definition": {
    "id": "camp_wall_axis_c_01",
    "texture": "res://assets/environment/camp_modular/wall_axis_c_01.png",
    "size_px": [128, 96],
    "pivot_px": [64, 80],
    "footprint_cells": [[0, 0], [1, 0]],
    "collision_kind": "layout_blocker"
  },
  "instance": {"id": "courtyard_wall_01", "module_id": "camp_wall_axis_c_01", "cell": [6, 9]}
}
```

这是待落地的schema示例，不能直接塞进现有地图JSON假定加载器会读取。实例cell经Iso得到脚底世界坐标，贴图左上为脚底减pivot。占地旋转、贴图朝向、碰撞三者必须一起变；本阶段制作两个真实墙段方向，不用图像旋转代替。

物件清单是可编辑事实源，构建器输出地形/道路表、导航阻挡与碰撞，并校验一致性；运行时继续通过既有布局和CaveNavigator访问，不新建一套寻路。正式营地迁移时保留现有出口、NPC、安全区和任务位置；迁移失败则旧地图继续可用。

## 5. 遮挡与碰撞的可执行规则

- 地面与贴花永远在角色下方，不使用逐对象Y排序制造贴地穿插。
- 墙、树干、木箱以脚底世界Y排序，使用现有绝对z_index范围；不得混入另一个只对局部对象生效的y_sort组。
- 长墙分段，每段有自己的脚底锚点；不能用长墙中心Y让一端错误盖住人物。
- 棚屋背层与前檐分开；门洞留出真实导航和碰撞空间。第一版只做外部可绕行棚屋，不额外开发室内切层玩法。
- 树冠可以按同一树脚底排序；若遮住可交互目标，再依据实际遮挡做淡出。淡出只是视觉，不能改变碰撞。
- 树碰撞围树根，房屋碰撞围落地墙体，屋檐和树冠不扩张障碍；落地碎石明确区分纯装饰和阻挡物。
- 全部关键通路用现有角色实际行走验证；仅图层拖动或鼠标命中测试不算通过。

## 6. 生产流水线

1. 先用现有地砖和简单调试形状建立16×16格拼装场，验证道路规则、网格轴向和碰撞。调试形状只验结构，不代替正式美术。
2. AI基于已认可的风格图分别制作平光材质母版、独立树、棚屋与墙段；不再请求完整营地作为地图资产。每次只生成一类资产，记录光向与相机。
3. 用确定性的构建工具完成裁切、投影、alpha遮罩、共边约束和图集打包。母版边界不连续则先修复母版/边界，不靠随机平铺“碰碰运气”。
4. 输出基础砖和连接砖的编号表、3×3重复预览、包含全部邻接情况的拼缝检查图；浅底与深底检查透明边缘。
5. 将资产替换进同一个拼装场，调整颜色与密度，不重新生成一幅场景。
6. 用相同资产另拼一张布局：道路换方向、棚屋换位置、墙围出另一形状。无需生图即可完成才证明资产可复用。
7. 地图结构过关后再放入主角与两类怪物检查尺寸和战斗可读性；连续动画独立过质量闸门，未完成时明确标为静态占位，不能借此拖延地图拼接验证。

图集间隔与过滤需要同步设计：当前地面图集把64×32砖紧排，若新风格切换线性过滤，应补2px挤出边和UV内缩并回归合批；不得只改过滤导致串色。保持现有过滤时也要检查实际缩放下锯齿。是否调整由对照画面决定，不默认全项目切换。

## 7. 工程改动边界与顺序

| 步骤 | 计划改动 | 验收产物 |
|---|---|---|
| 结构样板 | 提取/复用Iso与FlatTileMesh，在隔离测试场读取地形、道路和实例清单；不用整图背景 | 可编辑16×16格场景、全部道路mask检查图 |
| 主题规则 | 为新主题增加47连接形状选择与图集索引；旧主题沿旧分支 | 对所有256邻域做规范化与旋转一致性检查；旧图基线不变 |
| 美术包接入 | 地砖、过渡、贴花、墙屋树小物件逐类接入 | 两套不同布局的实机截图及素材联系表 |
| 正式营地迁移 | `ground.gd`增加显式主题选择，避开旧大画幅road_overlay路径；复用物件和布局入口 | 营地README、配置、布局与美术清单一致，旧存档切图正常 |
| 战斗样板 | 既有玩家、怪物与技能流程，放入隔离战斗场 | 行走绕墙、怪物追踪、预警与遮挡录屏 |

不默认更换TileMap、引擎或渲染后端。也不把已有营地白盒的画像素坐标直接当成新的网格坐标；迁移明确经旧转换函数转世界坐标，再对照网格落点。

## 8. 完成标准、成本和停止条件

下一次交付必须至少包含：独立素材联系表、同套素材拼出的两种布局、可运行地图场景，以及沿墙绕树/穿门的验证记录。**单张整图、整图裁成若干矩形、在整图上拖角色，都不算完成。**

检查孤立路块、单格直路、内外角、T口、十字、相对边、边界；无接缝、黑边、明显棋盘。关掉装饰后地形仍连续；移动一个墙实例后视觉、阻挡和导航同步；角色位于墙前后时遮挡正确。每个物件能在另一布局复用。

样板规模固定256地格、至多256道路覆盖格、贴花上限48实例、立体物件上限24实例；地面/道路在加载时构建合批网格，不每帧重建，立体对象共享纹理。局部编辑只重建受影响层及其邻接数据；地图退出释放场景资源。实际draw call随遮挡与材质而变，不承诺“三次绘制”。

单张2048×2048 RGBA8图集理论16MiB，mipmap另计；首批以必要尺寸打包，不因上限就申请整张最大图。首批小砖不足一张大图集，建筑单独按材质与排序需求打包；避免为了合批打乱半透明顺序。运行依赖排除概念整图。

逻辑回归沿用AGENT.md中的MapTextureBatchTest、FlatTerrainMeshTest、CaveNavigationTest、CaveAutoBattleTest等适用入口；正式地图改动执行地图目录检查。窗口固定设备/镜头/分辨率对照帧时间、加载和纹理占用，密集战斗另测，不用静态样板宣称60FPS。

地面或道路拼缝未过，暂停生产建筑；尺寸和遮挡未过，暂停扩全营地；缺少合格动画时如实单独标记，不生成伪帧冒充完成。此次规划完成不等于上述实现完成。
