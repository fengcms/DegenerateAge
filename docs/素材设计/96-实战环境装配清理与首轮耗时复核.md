# 实战环境装配清理与首轮耗时复核

2026-11-18。在原16×16两怪实战场按环境、主角和怪物分段计时，并检查被创建后立即删除的动作预览对象。目标是删除明确的装配浪费，不以单次帧率变化推断首轮卡顿根因。

## 实现

modular_camp新增environment_only开关，默认false保留原预览功能。实战入口设为true，跳过预览规格、主角/两怪预览对象和永远隐藏的碰撞调试覆盖层。相同菱形碰撞共享一个不可变ConvexPolygonShape2D，各格只平移身体节点；不合并障碍、不改格子占地、不缩小角色半径。

controls验收逐一查询所有阻挡格中心的真实物理碰撞，随后正式玩家绕箱、攻击移动接管、受击恢复、死亡复活均通过。原两套16×16样板完整验收也通过，原断言未放宽。

取消预览后部分首次纹理加载成本转移到主角/怪物阶段，环境阶段的54ms减少不能直接当作总启动收益。总装配只小幅变化，缺乏多次冷启动统计，不能宣称启动性能显著提升。明确收益是少94个节点、少120376字节纹理持有，碰撞与正式实战仍通过。

首轮246.094ms尖峰仍存在，所以未解决最初卡顿问题；未通过降低绘制标准或改变战斗规则制造结论。一次共享形状试跑因窗口未持续绘制被拒绝，后续将soak窗口置前并保持显示后重测通过，失败样本未计入上表最终列。还修正了_report_wave失败后外层继续重开导致的后续数组越界：现在直接以失败退出，不继续记录波次。

## 复核和范围

`python3 tools/camp_combat/launch.py --soak` 输出COMBAT_SETUP_TIMING、慢帧上下文及三轮COMBAT_WAVE；要求CAMP_COMBAT_SOAK_OK和完整战斗完成标记。`--controls`检查实际碰撞与玩家控制；原样板使用modular_camp/launch.py --verify。

仅改变隔离样板的环境装配，未改变正式地图。首轮GPU/驱动/调度等原因仍未由当前证据定位，不在本报告中猜测。临时日志已将关键数值记录后清理。
