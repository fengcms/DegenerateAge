# 主角右下四帧营地试装记录

2026-11-17。本轮在V2姿态基础上修正人物服装，完成单方向四帧图集，并接入两套隔离营地的实际移动。成果是可运行的动作试装，不是完整主角动画验收；正式地图、CharacterLook、存档和战斗规则未变。

## 美术与打包

内置image_gen以V2候选为编辑对象、已认可原画为身份参考，补回圆环胸饰、斜背带、腰包、甲片腰摆与破布。源稿及完整提示词在art_source/actors/hero_walk_pilot_v3。两次落脚已具不同姿态，实际尺寸中主角的主要装备特征比V2更接近原稿；这不表示逐处纹样、脸部和循环自然度已完全一致。

build.json固定四格512×768源帧、0.15统一缩放、112×128运行帧和(56,112)锚点，输出112×512一列四行图集。无逐帧裁边缩放、镜像或靠单图位移伪造肢体动作。帧格、锚点、状态帧数沿既有角色资源口径；只有se方向，故未登记完整八向外观。

## 实机行为

SampleWalkSprite接收move_and_slide后的真实位移，以64个世界屏幕像素推进一次四帧循环。角色速度保留150px/s，直线时约9.375帧/秒；清单6fps对应96px/s基准。显示不驱动角色坐标、碰撞、寻路或结算。

方向以屏幕(2,1)为中心约±22.5度，只有该范围播放。停步、零位移、未制作方向或关闭试装时恢复原静态图并清空相位，不在原地踏步、不倒放冒充另一方向。P从两布局共用空地开始右下实际寻路，H切换原图对照；切换布局保留开关。

## 验证

```sh
python3 tools/modular_camp/launch.py --build-assets
python3 tools/modular_camp/launch.py --verify --capture /tmp/camp-walk-v3-final
```

Godot4.7.2、Compatibility、Apple M1 Max真实窗口。构建输出HERO_WALK_BUILT: (112,512)及MODULAR_ASSETS_BUILT。启动器现在检查完整构建标记与脚本错误，避免断言中断却误认为构建成功。

窗口验证要求两布局真实路线都覆盖四帧并到达目标；停步恢复、反向移动回退、关闭动作和零位移检查均通过。全部既有图集、道路边界、草路互斥、实际长路径、门洞、墙体阻挡、绕墙、移动墙导航失效和两布局遮挡断言保留，通过后输出MODULAR_CAMP_VERIFY_OK并退出0。

截图目视：营地中可见抬脚和相反落脚姿态，树、房屋及两类怪物保持原显示。源图预览的背景外观不用于代替实机alpha合成检查。截图是临时验收产物，不入库。

## 运行与验收成本

新增运行图集RGBA8理论224KiB，四个AtlasTexture共享同一缓存纹理；主角仍只有一个Sprite2D表现节点，切图释放旧区域资源。每物理帧计算一次实际位移和方向，仅帧变化时更新纹理引用；无热路径图片处理或资源加载。原96px主角与单帧怪物保留。

仅开启--capture时，将最多24张试走抽样、4张关键帧及1张停步截图暂存在内存，结束本段路线后写盘并清空，避免PNG编码阻塞每个行走帧。1280×800下该调试缓存理论上限约113.3MiB，两布局串行复用，普通启动不分配。配套walk_demo_<布局>.json记录采样时刻；截图回放不用于证明FPS或帧时间。未测完整游戏P95/P99，不承诺大地图性能。

## 当前限制

只有右下四帧，整体节奏偏简化，脚与地面的锁定未作逐像素运动分析。站走切换仍使用旧静态图，角度与轮廓可能有轻微变化；64px步幅为样板调校值，不是已经验收的完整步态。两类怪物仍静态，无攻击、受击、死亡动作。后续先精修当前方向与站走过渡，再扩方向，不能用这一试装代替完整动画交付。
