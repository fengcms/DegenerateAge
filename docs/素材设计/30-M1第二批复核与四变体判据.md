## 三、逐项核验

### 3.1 无缝：三张通过，但 1a 掉队

| 变体 | 左右边均值差 | 上下边均值差 | 说明 |
|---|---|---|---|
| M1-1a 干草地 | **7.02** | **14.43** | 未做窄带混合，与其余三张口径不同 |
| M1-1b 湿润深绿 | 0.00 | 0.00 | 48px + 12px 方向保持窄带混合后 |
| M1-1c 荒草枯黄 | 0.00 | 0.00 | 同上 |
| M1-1d 碎石车辙 | 0.00 | 0.00 | 同上 |

两条要记住：

- 这个 `0.00` 是**人工修缝结果**，不是生成器原生无缝。生成器确实没有真 wrap/tile 开关，29 号如实记录了，值得肯定。
- **1a 与新三张口径不一致**（P1-1）。这是本批次规格上的唯一硬伤：1a 数值上的接缝在菱形铺装、对角边分散后目视不明显，但与 b/c/d 混铺时会重新暴露。修法成本很低——对 1a 的 160 件补做同口径窄带混合即可。

### 3.2 色调：同批一致，无漂移

实测 160×160 RGB 均值（0–255）：1a `125/128/73`、1b `93/103/64`、1c `103/89/74`、1d `116/98/83` —— 与 29 号自报数值逐项一致。

色板并排图 [`_verify/preview_variants_palette.png`](../../art_source/environment/map_m1/_verify/preview_variants_palette.png) 目视：四张同属一套低对比像素簇语言、同一左上主光、同一有限色板，**没有一张掉到另一套画风**。差异化方向（湿绿 / 枯黄土 / 灰棕车辙）符合预期。

### 3.3 验证口径：已纠正

三张等距验证图（`M1-1b/c/d_*_iso_3x.png`）确认为 384×224 画布铺装后 3× 点采样，未出现正方形平铺的墙纸感，角色有接地影。27 号纠正的呈现口径已被正确执行。

## 四、四变体交错铺装（最终判据）

产出（我方生成）：

| 文件 | 用途 |
|---|---|
| [`_verify/preview_grass_ab_iso_3x.png`](../../art_source/environment/map_m1/_verify/preview_grass_ab_iso_3x.png) | 仅 a/b（近义草皮）真随机散列 —— **常态用例** |
| [`_verify/preview_grassgroup_iso_3x.png`](../../art_source/environment/map_m1/_verify/preview_grassgroup_iso_3x.png) | a/b/c 三变体散列 |
| [`_verify/preview_variants_iso_3x.png`](../../art_source/environment/map_m1/_verify/preview_variants_iso_3x.png) | a/b/c/d 四变体散列（含裸土与车辙）—— **极端压力测试** |

### 4.1 结论一：常态用例完全成立

`preview_grass_ab_iso_3x.png`：a/b 随机散列铺开后读作**一片自然的草地色差**——无墙纸感、无可见接缝、无规则格阵、无瓦片形状色块，角色落地清晰。

**这证明 27 号判定成立：M1 的接缝与重复问题，在正确呈现 + 正确混铺口径下不构成障碍。** M1 地面基座（L0）判定为**成立、可用**。

### 4.2 结论二：混铺必须是「真随机」，不能用规则排布

我先用 4×4 规则表（同变体不正交相邻）做过一版，**目视出现明显的斜向条纹**；换成「一次+二次项取模」的散列，**仍然是条纹**（取模后奇偶性必然成阵）；只有换成**固定种子真随机**才干净。

→ **流程要求：变体散列必须用随机（或蓝噪声），禁止用线性/Latin-square 式规则排布；按 `(r, c)` 求模的伪散列同样禁止。** 这条要写进 25 号与后续制作单，否则会重演。

### 4.3 结论三：语义跨度大的变体不能按单格混铺（新发现，需定规则）

`preview_variants_iso_3x.png`（四变体散列）目视：**裸土（1c）与车辙（1d）按单格铺散后，形成大量瓦片形状的连贯色块，整体像拼布被**——不是条纹，而是「一格的色块」。

原因不是素材缺陷，是**用法错配**：草（1a/1b）与裸土（1c）、车辙（1d）在语义上不是同一地形的变体，它们之间需要 **L1 过渡边缘**才能衔接；直接用 1 格粒度硬切，等于把「没有过渡的地形突变」放大成图案。

→ **流程要求（二选一，推荐先做前者）**：

1. **补 L1 过渡边缘**（正是 24 号 §七 批次 M2 的第一项，也是 §一 点名「最易被忽略、最关键」的一层）：草→土、土→石 等交界贴片。有了它，1c/1d 才能在草地上做「斑块状裸露」。
2. 在过渡件到位前，**1c/1d 只按区域使用**（整片荒地区 / 道路与车辙带），不与草组做单格混铺。

### 4.4 1d 的额外问题：强方向性

`M1-1d_gravel_rut_iso_3x.png` 与四变体图均可确认：1d 的车辙是**近乎贯穿纹理的横向线**，菱形铺装后仍可辨。大面积平铺会形成连续横带。29 号自己也提示了这一点，判断正确。

→ **建议：1d 定位为「道路/车辙带专用件」**，沿道路走向摆放，不进地面随机池。若要作为地面件，需重出低方向性版本。

## 六、流程改进：Codex 完成自动检测

此前「等 Codex 完成」只能靠人盯，本次实测它在本轮 00:01 起跑、00:08 就完成并提交，空等无意义。已把检测沉淀进技能：

```bash
python3 .trae/skills/codex-handoff/scripts/wait_for_codex.py --thread <UUID> \
  --expect docs/素材设计/<NN>-<name>.md \
  --expect art_source/environment/... \
  --interval 20 --timeout 3600
```

- 原理：Codex 每轮结束会在 `~/.codex/sessions/**/<thread>.jsonl` 里写一条 `task_complete`；脚本增量读该文件计数，并同时校验 `--expect` 产物是否出现。
- 不读 `~/.codex/*.sqlite`（app 持有写锁）。
- 退出码：`0` 完成且产物齐备；`2` 超时/完成但产物缺失；`3` 疑似停滞（rollout 静默，常见于队列未被消费）。
- 已同步写入 [.trae/skills/codex-handoff/SKILL.md](../../.trae/skills/codex-handoff/SKILL.md) 的「Wait for completion」与「Judge what came back」两节。
