# 32 第一章地面贴图「原始范式」与 M1 偏差对照

日期：2026-10-17
性质：**逆向调查与范式对照**。本文件回答一个问题——「当初 Codex 是怎么做出你满意的那些地面贴图的」，并据此定位我们后续（M1、营地）跑偏的位置与回归方法。本文件不改素材、不改代码、不改数据。

结论先行：**你满意的那批地砖，等距视角是「生成阶段直接画出来的」，后处理只做了裁边与点采样；而我们后来的 M1 是「生成阶段画一张正俯视噪声方图，再靠程序 rotate45 + Y×0.5 硬投影」。两者是根本不同的范式。**

---

## 一、调查结论（一句话版）

| | 原始范式（wild / ash / cave，你满意） | M1 范式（草地基座，你觉得零碎） |
|---|---|---|
| 等距视角从哪来 | **生成器直接画成菱形地面**（提示词明确要 3/4 等距视角、菱形铺满整格） | 生成器画**正俯视**方纹理，等距由**程序投影**造出来 |
| 交付形态 | 一张 **2×2 图集 = 4 块完整菱形地面**，各自带自己的边缘 | 一张 **160×160 无缝方纹理**，再被投影成菱形 |
| 后处理 | alpha 硬阈 → trim → **近似等比**点采样到 64×32 → 菱形掩码 + 平底色填隙 | `放大 2× → rotate 45 → trim → 压成 64×32`（**逐格、各向异性 2 倍压缩**） |
| 提示词对细节的要求 | 「**低分辨率像素簇，适合最终 64×32 放大**」「四块菱形边色统一，避免亮缝」「**大石/高草不得跨越瓦片边界**」 | 「**均匀**微观细节分布」「草叶仅几像素宽，**全图均匀密度**」「**禁止大面积平底留白**」 |
| 无缝口径 | 不需要方形无缝——每块砖本身就是**完整菱形岛**，菱形网格天然无缝 | 追求「方纹理无缝」→ 再投影，**背了一个本来不存在的问题** |

## 二、证据链

### 2.1 打包脚本：后处理到底做了什么

权威实现是 [build_environment_art.gd](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/tools/build_environment_art.gd#L12-L37) 的 `_pack_tiles(theme)`。逐行看：

```gdscript
var cell := image.get_size() / 2            # 1536×1024 → 每格 768×512
var fill := Color("515a42") ...             # wild 底绿 / ash 底灰 / cave 底黄
var piece := image.get_region(...)          # 取一格
_clear_faint(piece)                         # alpha < 0.5 → 全透明（硬阈，无羽化）
piece = piece.get_region(piece.get_used_rect())   # trim 到内容
piece.resize(64, 32, Image.INTERPOLATE_NEAREST)   # 点采样 → 64×32
for y in 32, x in 64:
    edge := 1 - |(x+0.5-32)/32| - |(y+0.5-16)/16|
    if edge < 0: 透明                            # 菱形外裁掉
    elif a < 0.5: 填 fill                       # 菱形内空隙填平底
```

**关键事实：全程没有 `rotate`，没有 `Y × 0.5`，没有 `squeeze`。** 后处理只承担四件事：硬阈去杂边、裁到内容、点采样、菱形掩码+填底。等距形状是**原画自带的**。

### 2.2 源图实测：生成器画的就是 ~2:1 的菱形

用 magick 量四张源图（均为 1536×1024，2×2 排版，每格 768×512）的**每格内容包围盒**：

| 源图 | 四格内容尺寸 | 宽高比 |
|---|---|---|
| `wild_tiles.png` | 698×372 / 700×371 / 689×380 / 696×382 | ≈ 1.88 / 1.89 / 1.81 / 1.82 |
| `ash_tiles.png` | 724×400 / 726×400 / 724×403 / 726×404 | ≈ 1.81 / 1.82 / 1.80 / 1.80 |
| `cave_tiles_v2.png` | 698×374（四格一致） | ≈ 1.87 |

内容包围盒**天然接近 2:1**（目标 64×32 = 2:1）。所以 `resize(64,32)` 的水平/垂直压缩比是 10.9× 与 11.6×——**两者相差仅约 6%，基本是等比缩放**，形状与结构被完整保留。

对照 M1：`-resize 256x256! -rotate 45 -trim -resize 64x32!`，362→64 是 5.66×，362→32 是 11.31×，**垂直比水平多压一倍**；对 160 源而言净压缩是水平 2.5×、垂直 5×。**逐格做这个变换，邻格边缘像素重复采样，还会叠出菱形格线**（此前 `preview_warp_N_vs_G` 已实测）。

### 2.3 提示词：两种范式在源头就分叉

**原始范式**的成文范例是 [可玩样板-v1/prompts.json](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/docs/素材设计/样板/可玩样板-v1/prompts.json) 里的 `camp_tiles`（与 wild/ash 地砖同为 2026-10-13 产物），原文关键句：

```text
Create ONE production terrain atlas, strict 2 columns x2 rows with four FLAT 2:1 diamond isometric
ground tiles on truly transparent background. Each equal rectangular cell has a diamond spanning the
full cell width and full cell height, diamond points at exact midpoint of each edge. No gap, no
floating cube sides, no shadows, no outlines, no labels. ... LOW resolution pixel clusters
appropriate for final 64x32 tiles enlarged nearest neighbor; subdued warm brown, muted olive, gray
stone, top left light. Match ground edge color warm soil consistently across four diamonds to avoid
bright seam. No large rocks or tall grass crossing tile boundary. Exact 2:1 overall canvas ratio,
four tiles only.
```

[第一章场景-v1/README.md](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/docs/素材设计/样板/第一章场景-v1/README.md#L19-L21) 记录了同批次 wild/ash 的提示词方向：**「统一指定 3/4 等距视角、左上方光源、清晰像素边缘、四格互不重叠、无文字」以及「地面降低对比度，让角色始终成为视觉焦点」。**

**M1 范式**则相反。[25 号](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/docs/素材设计/25-地图素材提示词包-M1地面基座.md#L23) 第 6 条明确规定交付「160×160 无缝方纹理（正俯视）」，并写道「**等距菱形化属呈现/引擎侧，提示词也不要写等距角度**」；`[无缝]`/`[主体]`/`[负面]` 段进一步要求「**Uniform micro-detail distribution**」「individual grass blades only a few pixels wide, **even density over the whole tile**」，并禁止「**no large flat empty color patches**」。

于是：**原始范式让生成器「画一块有形的草地」；M1 让生成器「画一张均匀的噪声纸」**，再让程序去扭它。零碎感由此而来。

### 2.4 视觉证据

见 [compare_origin_vs_m1.png](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/art_source/environment/map_m1/_verify/compare_origin_vs_m1.png)（同尺度 8× 放大，左二为 wild 原砖，右一为 M1 现行管线投影砖）：

- 原砖是**有形的簇与柔和色阶**——可见成片的草簇形状、深浅带状过渡、以及一圈稳定的基色边；
- M1 砖是**均匀撒播的椒盐点**——深浅像素等概率、等间距铺满全图，看不到任何成形的结构。

> 说明（诚实标注）：在 64×32 单砖尺度上，两者的灰度标准差、3×3 局部标准差、低频分量等**统计量数值接近**（原砖 macro/hi ≈ 0.52–0.68，M1 ≈ 0.58）。也就是说，M1 的单砖并不「更噪」；它的问题在于**结构为零**——画面由等概率噪声铺满，人眼读不到任何可命名的东西，铺到整张地图上就是「脏」。**这是结构性判断，不是数值判断**，不要再用「标准差不达标」当整改依据。

## 三、原始范式复盘（五步，可直接复刻）

1. **提示词阶段就锁定等距**：要「2 列 × 2 行 = 四块 FLAT 2:1 菱形地面，透明底；每格菱形铺满整格宽高、四个尖角落在格边中点；无缝隙、无立方体侧面、无投影、无描边」。
2. **锁定像素密度**：明确「LOW resolution pixel clusters appropriate for final 64x32 tiles enlarged nearest neighbor」——即让生成器按「将来会被缩到 64×32」的密度作画，而不是画一张高密度噪声纸。
3. **锁定边缘纪律**：四块菱形**边色统一**（避免亮缝）、**大石与高草不得跨越瓦片边界**、四格互不重叠。
4. **锁定主光与对比**：屏幕左上主光、低对比，让角色始终是焦点。
5. **后处理只用四条**：alpha 硬阈 → trim → **等比**点采样到 64×32 → 菱形掩码 + 平底色填隙（[build_environment_art.gd](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/tools/build_environment_art.gd#L12-L37)）。

这套流程还有一个**隐性红利**：每块砖是一整块菱形岛，菱形网格本身就是无缝镶嵌——**根本不存在「方形平铺接缝」这个问题**，也就没有后来那一串「无缝模式 / 后处理补缝 / 菱形格线」的连锁返工。

## 四、给「想多加点元素」这个原始诉求的正解

你的原话是「一开始 codex 制作的地图我是满意的，我只是觉得**元素太少、太单一**」——所以真正的缺口在**装饰层**，不在**地面基座层**。按模块化分层，回归方式应当是：

- **L0 地面基座**：直接用现役 `assets/tiles/{wild,ash,cave}/tile_0..3.png`，**不动**。若确需新地类（泥地、夯土、沙地、石板），用**同一范式**（§三）新生成一套「整菱形砖」，而不是把原砖重做成方噪声纹理。
- **L1 过渡边缘**：草→土、土→石。已有实现先例——[build_chapter_one_v2_art.py](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/tools/build_chapter_one_v2_art.py#L55-L75) 的 `build_road_transitions` 用菱形坐标 `(u,v)=(x-31.5)/32, (y-15.5)/16` 反推格位，逐像素生成 4 边 + 4 角过渡砖。这是「拼接像棋盘」的根治层。
- **L3/L4 装饰**：草簇、小石、碎屑、花木、破布、断车等，作为**独立小精灵**铺在地砖之上——**这才是「增加元素」的正确落点**，它不会污染基座，也随时可增删。
- **L2 道路**：沿用现役 `tile_3` + `road_edge_*`（wyld/ash/cave 各自一套已就绪）。

## 六、可直接使用的提示词（原始范式，供你本地 Codex 出图）

新地类（如泥地 / 夯土 / 沙地 / 石板）按此拼装；`[主体]` 段替换、其余不动：

```text
Use case: stylized-concept. Asset type: production terrain atlas for a 2D isometric pixel-art
dark-fantasy RPG. Create ONE atlas, strict 2 columns x 2 rows, four SEPARATE FLAT 2:1 diamond
isometric ground tiles on a truly transparent background. Each equal rectangular cell has a diamond
spanning the full cell width and full cell height, diamond points at the exact midpoint of each
edge. No gap, no floating cube sides, no shadows, no outlines, no labels. 

Subject: [主体 · 例如 packed damp clay earth with sparse embedded pebbles and faint hoof scuffs,
the four tiles varying only in density and pebble scatter].

LOW resolution pixel clusters appropriate for final 64x32 tiles enlarged with nearest neighbor,
screen-upper-left light, muted low-contrast earthy palette so player characters read clearly on top.
Match the ground edge color consistently across the four diamonds to avoid a bright seam. No large
rocks or tall grass crossing the tile boundary. No text, no letters, no watermark, no border. Exact
2:1 overall canvas ratio, four tiles only, no grid lines drawn between cells.
```

生成后，**不要**再走 `rotate45 / Y×0.5`；直接交给打包脚本（或按 [build_environment_art.gd](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/tools/build_environment_art.gd#L12-L37) 的 `_pack_tiles` 口径：硬阈 → trim → 点采样 64×32 → 菱形掩码 + 填底）。
