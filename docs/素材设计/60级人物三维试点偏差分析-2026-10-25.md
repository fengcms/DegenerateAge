# 60 级人物三维试点偏差分析

日期：2026-10-25。分析对象是提交 `3d04d048` 中的 `look_06` 三维试验，**不是游戏里现用的人物图集**。本文件回答：为什么三维试验能播放动作，却与已确认的 60 级人物形象相差很远；结论以仓库源码、图片尺寸和实际输出为准。

## 现象与对照

用户认可的是 [原画定稿](样板/11-51级角色形象/look_06_lv51_final.png)和现有 `look_06` 的身份设计：黑色乱发、可见的人类面容、旧沙色围巾、灰白旧石甲、暖金分流纹、镇脉长剑和开口旁路环。当前不满意的是走路、攻击、打坐等动作；上一轮三维试验却连人物的体型与画风都改变了，呈现为块状、近似玩具或机械人的造型。

实测对照：现有游戏 `look_06_idle_atlas.png` 第一格的非透明包围盒为 **18×48 px，左上角 (23,16)**；三维试验缩到同样 64×80 后，站立包围盒为 **30×61 px，左上角 (17,8)**。试验人物约宽 1.67 倍、高 1.27 倍，下缘到 y=69；现有素材下缘到 y=64。这不是只因盔甲纹理缺失而产生的主观差异，连屏幕占比和脚底位置也未对齐。检测方法：分别裁出现有图集首格和打开 [试验缩小图](../../art_source/player/look_06/3d_pilot/look_06_native_64x80.png)，以非零 alpha 像素计算包围盒；精确脚底应以既有锚点 `(32,64)` 为准。

连续帧亦有可测问题：128×160 的攻击预览在第 4、5 张（`attack_04/05.png`）非透明区域从 **x=0** 开始，说明剑/动作贴到左画布边界，有裁切风险。打坐预览从 `sit_00` 的非透明下缘 **y=138** 移到 `sit_04` 的 **y=154**，坐下时整体落点偏移 16 px；这与固定脚底锚点要求不符。上述数值是图像边界证据；具体哪一个像素是脚或剑尖，仍需逐帧人工复核。

## 根因：先在造型源头偏离，再把动作做在错误模型上

1. **没有把已确认的图片转化为建模约束。** [试验脚本](../../tools/player_3d/build_look_06_pilot.py)没有读取原画或 `art_source/player/look_06/` 的八向母版，也没有形体比例、正侧背轮廓或局部特征的对照测量；它只是依文字印象用立方体、球、圆锥和曲线重造一名“有这些装备的人”。`cube/sphere/cone` 函数见脚本第 54—92 行，角色部件见第 123—204 行。**保留几个名词不等于保留原角色。**
2. **几何和材质层级不足以表现定稿。** 面部是球体和两枚眼睛、乱发是规则排布的锥体、披风是六条矩形片、甲片大多是倒角方块；材质是纯色 Principled 参数，没有 UV、原画纹理或手绘磨损层。相应证据见脚本第 21—41、144—157、182—187 行。定稿最能辨认的脸形、碎发、破边披风、非对称甲片与裂纹因此消失。渲染器或 Blender 版本不是主要原因；输入模型本身就没有这些信息。
3. **动作只是在简化枢轴上旋转零件。** 脚本的腿只绕髋部转动，手臂只绕肩部转动，没有膝/肘、足部接地约束、重心转移或剑的完整挥砍轨迹；披风也只绕单个枢轴摆动。见第 125—133、207—257 行。曲线插值使帧与帧连续，但不等于自然走路或合乎力学的攻击；脚滑、浮脚、穿插和打坐时剑尖位置错误由此产生。它甚至尚不是可用于正式动画的完整角色绑定。
4. **投影和运行规格没有在第一阶段校准。** 试验相机从 `(4,-6,4.3)` 朝角色看，先输出 320×400 审稿图，再额外缩出一张 64×80；脚本没有按游戏八向次序烘焙正式图集、没有把 `(32,64)` 当作固定落点校正，也没有在当前地面和显示倍率中做 A/B 目视。相机、输出见第 260—320 行。`root` 逐 45° 旋转只证明一套模型能周转，不证明每一方向的原画轮廓和屏幕方向都正确。
5. **生产顺序错了。** 在原生尺寸站立轮廓未通过时，就同时做了行走、攻击、打坐和八向渲染；第一个必要的造型验收被跳过。动作产量看似完整，实际上是在放大早期错误。上一轮我说“保留现有造型”并不准确；我只保留了部分颜色和道具概念，应该在看到第一张站立图时停止动作制作并先返工模型。

另有**接入前的时序阻断**：试验攻击时间轴第 49 帧中立、第 54 帧蓄势、第 58 帧挥砍（脚本第 237—241 行），而当前 [角色表现脚本](../../scripts/entities/sample_actor_art.gd) 的 `attack()` 在角色发起攻击时从图集第 0 帧显示接触姿，伤害也由角色逻辑当次结算。三维试验没有接入游戏，因此没有造成结算错误；若直接把蓄势摆在第 0 帧，会出现“先扣血、剑后到”的错位。必须单独决定是保持现有当帧接触视觉，还是经过功能设计与回归后调整结算时机。

## 责任与影响范围

问题是本次制作方法和验收顺序选择错误，**不是用户原画格式不对，也不是‘三维路线天然做不到’**。一张高质量二维图无法凭立方体规则自动还原成同等质量的可动画三维角色；现有八向母版至少能提供侧背轮廓参考，但本次并未利用。是否借助专业建模、贴图制作或更适合的图像到三维工具，需用**同一角色的实际样本**验证，不能预先保证自动生成会达到定稿精度。

影响只在 `art_source/player/look_06/3d_pilot/`、该试验脚本及试验说明。正式 `assets/sprites/player/stage_looks/look_06/`、`CharacterLook` 登记、存档、碰撞与战斗结算没有被改动。当前三维工程可作为机位和导出工具练习，**不可作为高质量模型或正式角色资源接续开发**。先前的[试点记录](47-60级人物三维动作试点与质量闸门.md)所说“八方向一致”“连续动作”，仅指技术可输出，不代表原画还原与动作质量通过；以本文件的质量判定为准。

## 修正路线与复核方法

1. **先冻结形象基准。** 以定稿、八向站立母版和现有游戏首格做并排表；记录头身比、肩宽、披风外轮廓、剑环相对位置、可见脸部范围、有效高度与脚底。任何新模型先给正面、侧面、背面静帧和 64×80 实际尺寸；不过关就不做动作。
2. **建立可动画的造型。** 模型需独立头发、甲片、围巾、披风、手臂、膝腿、剑和环，保留原画的非对称关系与旧石/布/金线材质。可以采用高质量三维模型加手绘纹理，也可评估分层二维骨骼/关键帧路线；无论方法，先让静帧与现有角色“是同一个人”。不把本次方块模型直接细化当作默认路线。
3. **单方向动作小样。** 先做一个完整的 8 帧走路循环并检查脚掌接地、重心、披风和剑环随动；再做攻击与打坐。动作在高分辨率和 64×80 下都看，记录每帧脚底包围盒与裁切。攻击命中视觉须与当前当帧结算一致，除非另立玩法变更。
4. **最后烘焙八向并接入。** 固定正交机位、主光、角色尺度和脚底锚点，按 `s, sw, w, nw, n, ne, e, se` 导出透明图；统一帧格、检查剑不跨格/不换手、所有帧不触边，再做 Godot 同地图、同倍率 A/B。通过后才替换运行图集，并跑 `CharacterLookTest`、`ArtSampleTest` 和涉及攻击/坐姿的实际试玩。

下一轮第一个可审查成果应当是**造型对照板**，而不是完整动画包。若拿不到与定稿接近的静态三维模型，应该明确暂停三维路径，评估逐帧二维或分层二维方案，不以“已经能转身”掩盖角色身份损失。
