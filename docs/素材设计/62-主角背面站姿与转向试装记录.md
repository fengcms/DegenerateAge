# 主角背面站姿与转向试装记录

本阶段继续模块化营地的角色表现试装，补充屏幕右上背面站姿。仅修改隔离样板及美术源稿，不登记正式角色外观，不修改地图数据、战斗、碰撞或存档。

## 问题与处理

此前只有右下行走与配套站姿，向右上走时会恢复旧正面图，人物朝向缺失。原因是该方向尚无素材，不能用镜像或倒放右下帧补齐。

以已生成的右下站姿为身份参考，使用内置image_gen生成独立背面。源稿与完整提示词在`art_source/actors/hero_walk_pilot_v3/rear_idle_source.png`、`rear_idle_prompt.json`。保留发髻、旧铜甲、围巾与右手低持剑，背面增加可见的背带与破布轮廓。未引入商业游戏图像。仍是待扩展的原创角色试装，不代表最终全方向一致性已验收。

## 规格与实现

- 原稿1024×1536，统一缩放0.069，源脚底标定(530,1390)。
- 运行图112×128，锚点(56,112)，与右下站姿及行走共用帧格；没有逐帧拉伸、位置补偿或透明混合。
- `build.json`是构建事实源，`build_assets.gd`统一打包站姿。`idleDirections`记录se/ne，行走`directions`仍为se。
- `walk_sprite.gd`记忆移动意图的已制作朝向；右上为屏幕(2,-1)约±22.5度，右下为(2,1)约±22.5度。无输入保留朝向，其余方向回退旧图。
- 右上移动与停止均显示背面单帧，不冒充背面步态；右下四帧仍仅由碰撞后的实际位移推进。
- I清空点击路线并原地前后转身；H关闭/开启保留朝向；持续键盘输入仍优先控制朝向。两类怪物保持静态展示。

## 验证与观察

构建入口：`python3 tools/modular_camp/launch.py --build-assets`，输出`HERO_WALK_BUILT`与`MODULAR_ASSETS_BUILT`。

窗口验证入口：`python3 tools/modular_camp/launch.py --verify --capture /tmp/camp-rear-idle-v3`。环境Godot 4.7.2、GL Compatibility、Apple M1 Max。两布局检查实际右上路线、停止保留背向、原地转身不改变物理位置、关闭恢复旧图再开启恢复背面、没有水平/垂直翻转。保留原图集拼接、通行、碰撞、移墙、四帧覆盖、顶墙停帧和遮挡断言。调整审查路线后的完整复测退出码0，输出`MODULAR_CAMP_VERIFY_OK`。

初次实机对照发现终点与狼展示点重合，虽没有改变碰撞规则，但遮住腿部，不利于美术审查。因此把本专项审查路线调整为(4,7)至(8,7)，不移动实际布局中的怪物，不放宽通过条件。验收图输出`rear_idle_0/1.png`与`front_idle_0/1.png`，截图保留在临时目录，不入库。

前后站姿实机观察人物高度接近，脚底没有明显整体跳动，剑保持右手；衣摆和背布细节仍应在后续多方向序列中复核。锚点数值相同不等于每根足尖像素完全一致，单帧转向也不等于平滑转身动画。

## 成本与限制

新增一张112×128 RGBA8贴图，理论56KiB；两张站姿与四帧行走合计336KiB，前阶段280KiB。不含旧回退图、驱动/导入开销。新增图仅加载一次，由样板纹理字典持有，切图复用，退出临时项目释放；源稿不复制进运行项目。

同时只有一个活动主角、两个静态怪物。每个物理帧新增固定次数朝向点积和状态选择，无新节点、逐帧I/O、纹理创建或全地图扫描。测试截图仅在验证模式读取显存，不能用本次截图运行宣称60FPS或性能提升；未测正式密集战斗。

下一阶段应补右上行走的受控姿态，再扩展侧后方向与两类怪物动作。当前不具备完整八向、攻击、受击或死亡动画，不能直接作为正式角色美术包替换。
