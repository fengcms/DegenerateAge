# 11—60 级装备、任务物与怪物美术开发计划

本计划把 [93-新增资源梳理与美术提示词](../游戏创意/21-60级内容规划/93-21-60级新增装备物品怪物梳理与美术提示词.md) 转成一次完整的美术生产任务。用户已确认按清单连续制作、逐批自检并提交。下面保留原定八向动画的最终验收标准；当前进度及临时交付修订以[制作记录](制作记录/11-60级/README.md)为准。

**2026-10-17 交付修订**：在汲灵幼虫的多方向动画样本未通过后，用户选择“先接入简化版，后续补动画”。因此第二至六章 79 只怪物先交付独立单体三格静态图与游戏外观档案；其 `integration` 标为 `temporary_static`，不得记为下表 P3/P4 的完整动画通过。50 张装备图标、21 张任务物图标和 79 只临时怪物外观的接入事实、测试与限制见[临时怪物接入验收](制作记录/11-60级/临时怪物接入验收.md)。原计划中的八向必要状态包与首领专属动作仍是后续制作目标。

**本轮“全部完成”的定义**：50 个装备型号、21 个任务道具和 79 个怪物模板各有可追溯的美术设计与验收状态；装备与道具各有正式可用的运行图标；怪物各有可辨的外观方案及与当前行为相配的运行表现包。怪物可以共享动作形体族，但精英需有结构差异，16 个 Boss 必须有独立剪影和关键动作。只有通过接入检查的资源才标为“游戏已使用”。

## 3. 统一美术方向与资产规格

沿用 [01-视觉与技术统一规范](01-视觉与技术统一规范.md)、[02-分类素材设计规范](02-分类素材设计规范.md)，以及第二章 [16-美术AI制作计划](../游戏创意/16-第二章美术AI制作计划.md) 和第三至六章 [91-美术AI制作与接入计划](../游戏创意/21-60级内容规划/91-美术AI制作与接入计划.md)。统一为复古像素、2:1 等距末法幻想、左上主光、清楚像素簇和透明底；避免照片材质、平滑 3D、文字、烘焙 UI 边框及大面积发光。先核对游戏里已通过的第一章资产在原尺寸下的线宽、色阶和阴影，再定整批参考板。

| 章节 | 可辨材质和配色 | 必须保留的差异 |
|---|---|---|
| 第二章 | 旧铜、铆钉铁、布革、炉灰；少量紫寄生 | 工业磨损和供灵刻纹，不能画成现代机械 |
| 第三章 | 渠铜、赭石、白布、盐痕 | 水位刻度与干渠/水务器物 |
| 第四章 | 深绿藤衬、灰白测量石、褪红信旗 | 根藤的生长方向和驿路封签 |
| 第五章 | 关卫铁、灰石、褪红军旗、局部紫潮 | 军令/断旗与紫潮侵蚀分层，不全身涂紫 |
| 第六章 | 灰白旧石、暖金分流、紫黑侵入 | 守誓/回流刻纹与裂隙，暖金只用于秩序结构 |

### 装备与任务物

- **50 个装备主体**：每个数据 ID 一张 `48×48` 透明 PNG，实际 34px 左右的背包显示尺寸也能读出部位；源稿可更大，但须经人工像素修整后导出。主体保留至少 2px 透明安全边，武器左下柄—右上刃；护腕、护膝、手镯、戒指各一张型号图供左右槽复用。外形须区分本章同部位与相邻章节的升级变化。
- **21 个任务物**：每个 ID 一张同规格图标，以零件、签牌、拓片、封签、军报等真实物件轮廓区分。任务数量和名称由 UI 绘制，图标不含数字、字、任务框。它们目前保存在 `GameState.quest_items`，**不占背包格**；本轮不要求 21 张地面装备表现图。
- **品质/星级**：主体图保持中性章节材质；普通/优秀/稀有/史诗/传说边框与升星由现有 UI 叠加，不画五套相同装备。不同奖励实例的名字、等级和属性不写入图片。
- **生成提示词**：装备使用 [93 §2、§4](../游戏创意/21-60级内容规划/93-21-60级新增装备物品怪物梳理与美术提示词.md) 的逐件主体句和固定约束；任务物以 §3.2 的任务锚点补充“可一眼识别的物件形状、材质、朝向”。每个 ID 保存最终提示词、参考图、修改记录，不把 AI 初稿直接当 48px 成品。

### 怪物

- **79 个怪物模板必须逐只可辨**：普通怪可共享兽/甲壳/蜥/蛾/人形卫/游魂/傀儡/定点寄生等形体族的动作结构；第二章虫、炉渣体、机甲按其自身功能补族。共享“运动规律”不等于复用同一张图换名字，至少有头部/背甲/武器/尾部等两处剪影特征区别。精英在同族基础上增加体量、真实结构件和身份徽记；16 个 Boss 独立剪影、阶段姿态和专属攻击动作。
- **单体概念先于动画**：每只留轮廓正侧/八向关键视角、体量对照、色板、材质和禁用特征；单纯概念图不记为运行动画完成。先用原尺寸与玩家、普通/精英/Boss 同屏审查，避免缩小后失去辨识。
- **动画按实际行为制作**：可移动攻击者以 `idle/walk/attack/hit/death` 为基本状态；定点怪按数据行为省去不使用的移动态；远程起手、冲锋、治疗连接和 Boss 技能追加独立表现清单。方向顺序 `s, sw, w, nw, n, ne, e, se`，帧数/FPS/循环/接触帧/脚底锚点逐 ID 记录；攻击和伤害仍以游戏逻辑为准，不由贴图重复结算。
- **运行图集契约**：新怪优先用现有 `animation_pack`（方向在行、时间在列）及 `appearanceId` 档案；制作前先用一只普通、一只精英、一只 Boss 验证读取链路和特殊动作字段。现有 `MonsterAnimationLibrary.PACKS` 与构建脚本仅登记第一章包，必须扩为从 manifest 构建/校验新包，不能只把 PNG 放进目录就标“已接入”。第二章幼虫的东南向局部帧只作候选源稿，八向/受击/死亡/锚点齐全后才可替换 `placeholder`。
- **性能边界**：按实际帧尺寸、帧数、8方向、RGBA 解码量和同屏并发估算图集内存；预览大图不进入运行资源。形体族可共用动作方案并离线烘焙变体，不能为每个怪物运行时复制纹理；先实测一章的峰值再扩量，遇到显存或加载尖峰则优化图集/帧数/预加载策略，不牺牲碰撞和战斗反馈。

按 01 规范的每只 `8方向×(4+8+6+2+6)=208` 帧作**不复用的粗略上界**，41 个 80×80 普通怪、22 个 112×112 精英和 16 个 192×192 Boss 的 RGBA 原始像素约 **895 MiB**，还未计入专属招式、图集边距与导入副本。这是估算，不是当前游戏实测显存；它说明必须在 P1 确认动作复用、压缩/裁切和按地图加载策略，不能把“79 个设计”机械等同于“79 套完全独立的 208 帧常驻纹理”。

## 4. 确认后的一次性制作流程

“一口气制作”指一次确认后连续完成以下阶段，内部按资产包审核和提交，不在每章停下等待新的口头许可。数量和质量关口仍然存在；不通过就修正该批再进入下一批。

| 阶段 | 工作与交付 | 内部通过条件 |
|---|---|---|
| P0 冻结清单与契约 | 从运行数据导出 150 行资产 manifest（50+21+79），每行含 ID、章、名称、用途、参考、预期路径、状态；测现有图标格、怪物渲染和章节行为 | 与上表数量、ID、93 逐项一致；记录当前半成品与缺口 |
| P1 统一参考板 | 五章色板；装备 10 部位和任务物的图标构图板；普通/精英/Boss 原尺寸对比板；从第二章选代表性怪物验证 8 方向和图集元数据 | 48px/34px 图标可读，怪物不漂脚、不裁切；工程读取契约已验证 |
| P2 图标全量 | 按章连续制作 **50 装备＋21 任务物**，每章 10 装备和 4/4/4/5/4 任务物；导出正式 PNG、源稿、拼版审查图 | 71/71 尺寸、透明、安全边、命名和章节辨识合格；无品质框/文字烘焙 |
| P3 普通怪全量 | 按形体族建立动作母版，逐章完成 **41** 个普通怪的设计和需要的运行状态 | 41/41 有独立可辨轮廓、八向/必要状态与元数据；同屏目标可识别 |
| P4 精英与 Boss 全量 | 以已通过族为基础完成 **22** 精英结构变体，独立制作 **16** Boss 和数据要求的技能表现 | 22/22 与普通怪有结构区别；16/16 独立剪影、接触/预警时序明确 |
| P5 资源接入与总验收 | 配置 50 装备图标的导出依赖、21 任务物的图标读取入口、79 怪物 `appearanceId` 与包清单；导入 Godot 并检查场景 | 150/150 状态可追溯；正式资源可加载，缺图有明确回退；存档/掉落/任务不变 |

P1 是同一次制作中的技术校准，不是新增的用户确认关口。P2—P4 可在工作时按章节和形体族并行推进，但不把尚未通过 P1 的格式批量复制 79 次。若实际工具无法直接产出透明、逐帧一致的像素动画，先生成设计底稿，再以像素编辑/程序化整理和逐帧校正完成运行包；不能将静态单帧误报为完整动画。

每个阶段作为独立可回退节点提交本地 Git；仅提交本阶段文件，不混入共享工作区其他改动，不自动 push。整批交付清单记录 `planned → designed → exported → reviewed → integrated` 五种状态，图片存在只到 `exported`，不等于接入。

## 5. 文件结构、映射与自动检查

| 类型 | 源文件与记录 | 运行文件 / 数据入口 |
|---|---|---|
| 装备 | `art_source/chapters/chNN/equip/<id>/`、`docs/素材设计/制作记录/11-60级/` | `assets/sprites/equip/<id>.png`；`data/equipments.json` 的 `icon`；导出包加载清单 |
| 任务物 | `art_source/chapters/chNN/quest_items/<id>/`、同上 | `assets/sprites/items/<id>.png`；按任务 UI 的正式图标读取入口登记，不修改任务袋计数规则 |
| 怪物 | `art_source/chapters/chNN/monsters/<id>/`、同上 | `assets/sprites/monsters/<appearance_id>/` 图集和 `animations.json`；`data/monster_appearances/` 档案与 `data/monsters/chNN/monsters.json` 的引用 |

每条 manifest 至少登记：`data_id`、`appearance_id/asset_id`、章、中文名、类别/档次、来源、关键轮廓、色板、源稿、正式路径、画布、帧数/方向/FPS/锚点/接触帧、生成方法/授权依据、审查结果、接入状态与版本。素材能共享则显式登记多个 data ID 到同一个 asset ID 的映射，不复制同名文件；Boss 不以共享外观替代其独立设计。Godot `.import`/`.uid` 由导入流程产生，禁止手写。

自动检查至少包括：ID 集合双向比对；全部资源路径存在且可导入；50 张装备和 21 张任务图标均为 48×48 RGBA；动画各方向尺寸/帧数一致、锚点统一、状态完整；无白底/棋盘格、无文字/边框烘焙；`appearanceId` 不再意外落回占位。装备图标的字符串路径还须进入真实导出依赖，不能仅在编辑器可见。

## 6. 最终验收和明确限制

1. **美术**：71 张图标在原生 48px、实际约 34px 的背包显示、深浅底和五品质框下可分辨；79 个怪物在场景倍率 0.8/1/1.5 与密集战斗中可辨；16 Boss 的预警、攻击和阶段变化不遮住玩家、出口或目标提示。
2. **功能**：背包、仓库、商店、掉落与比较面板显示同一装备图标；任务物继续走独立计数与保存；怪物刷怪、攻击、死亡、掉落和任务计数不因换图改变。执行数据/资源校验、怪物动画测试、任务/物品回归与完整冒烟测试。
3. **性能**：每章导入后记录图集文件大小、解码纹理内存估算、首次加载与热加载、密集战斗帧耗时和节点增长。headless 测试只验证逻辑；渲染/显存结论以 GL Compatibility 实窗为准。未测得的性能不写“已达 60 FPS”。
4. **交付**：不采用按“图片文件数”虚报完成度；最终按 **150 个数据 ID**核对 manifest，其中 50 装备、21 任务物、79 怪物。每 ID 有预览、正式路径、生成与授权记录、测试结论及已知限制；失败或未接入项单列，不以占位图凑数。

本计划只覆盖 [93](../游戏创意/21-60级内容规划/93-21-60级新增装备物品怪物梳理与美术提示词.md) 的装备、任务物和怪物。若要为旧创意中的七件第二章特殊奖励另制专属图标、为所有装备制作地面模型、为每个怪物提供独立头像或追加角色换装，须先调整数据与资产清单；当前制作不会擅自扩成这些内容。
