# 视频抽帧制作角色八向动画：可行性分析与提示词方案

日期：2026-10-19。状态：**分析稿，待用户裁决**。本文只做可行性与生产方式判定，不改代码、不生成素材、不动现有图集。

## 0. 结论摘要

| 结论 | 内容 |
|---|---|
| 能力对比 | 助手内置 `GenerateVideo` 与豆包视频同属字节视频生成族，**质量可比，但控制精度同档**。问题不在生成质量，在**格式与控制精度**。 |

## 2. `GenerateVideo` 的真实参数边界

| 参数 | 可选值 | 对本次需求的意义 |
|---|---|---|
| `resolution` | `480p` / `720p` | 720p 单帧约 720×720，主体人形约占 400–500px 高，需再降到 64×80，压缩比约 6–8 倍 |
| `ratio` | 含 `1:1` | 你要的 1:1 可用 |
| `duration` | 整数秒 4–15 | **只能按秒给，不能按帧给**；无 fps 参数 |
| 其他 | 无 | **没有** alpha/格式选项、**没有**起始角度、**没有**角速度、**没有** seed、**没有**机位锁定、**没有**比例锁定 |
| 输出 | 本地 MP4 | H.264 有损，**无 Alpha 通道** |
| 调用限额 | 每轮 1 次，不可并行 | 6 段视频 ≠ 6 次调用，返工代价高、节奏慢 |

## 3. 可行性逐项判定

### 3.1 阻断项（决定"不能作为素材来源"）

| # | 阻断项 | 依据 |
|---|---|---|
| B1 | **无 Alpha 通道**。输出 MP4/H.264 不携带透明信息，必须抠像。抠像会引入半透明毛边、色溢、暗边，而项目规范明确要求「透明 RGBA PNG，实色轮廓避免半透明毛边」「检查黑白底无暗边」 | [01-视觉与技术统一规范 §5](01-视觉与技术统一规范.md) |
| B2 | **帧数与角度不可控**。只能给整数秒时长，模型输出的帧相位与角速度自行决定。无法保证第 N 帧恰好落在 8 个基准角度上，也无法保证 8 帧一循环闭合 | §2 参数表 |
| B3 | **比例与身份漂移**。这正是你担心的"一会儿大一会儿小"。扩散视频在数秒内会缓慢漂移身高、武器长度、披风形态，且**没有任何参数能锁住** | §2 参数表 |
| B4 | **有损压缩污染像素**。帧从帧间预测解码而来，带块效应与残差噪声；再点采样到 64×80 会把噪声放大成可见杂色 | [01-视觉与技术统一规范 §5](01-视觉与技术统一规范.md)（世界像素默认 Nearest） |
| B5 | **风格越界**。项目要求像素风、实色轮廓，**禁止矢量光滑感**；视频模型输出是抗锯齿的光滑渲染，没有像素级输出档位 | [01-视觉与技术统一规范 §5](01-视觉与技术统一规范.md) |
| B6 | **投影坐标系不一致**。游戏是 2:1 等距世界，转身视频的机位/地面倾角/透视与游戏网格不同源，脚底接地关系无法直接对齐 | 01 规范 §3；等距投影须在世界空间一次性完成（既有教训） |
| B7 | **与已定生产方式直接冲突**。40 号文档已明确「不再把整张八向多帧图集交给图像生成工具一次完成」「不能用低质图凑齐数量」；八向动作交付说明已明确「导出过程中没有绘制程序动画、**旋转人物**、镜像人物或**插值补帧**」。视频抽帧本质就是旋转人物 + 插值补帧 | [40 号 §1](40-11至60级怪物正式动画制作方案.md)、[八向动作交付说明](../../docs/素材/monsters/八向动作交付说明.md) |
| B8 | **成本与迭代效率**。每次调用产出整段视频、无法局部修正、不可复现（无 seed）、每轮限额 1 条。项目已有教训：多轮生成迭代无法收敛时的反复重出无实际收益 | 记忆库工程教训 |

### 3.2 有利面（值得保留的用法）

| # | 有利点 | 依据 |
|---|---|---|
| P1 | **真实背面**。转角视频天然经过背面与侧面，恰好补上图像生成的最大短板——项目已记录「多视角生成容易重复正面、缺失真正背面」 | [制作记录 README](../../docs/素材设计/制作记录/11-60级/README.md)、[40 号 §1](40-11至60级怪物正式动画制作方案.md) |
| P2 | **造型与孤立部件草稿**。40 号文档明确允许「图像生成可辅助产出造型和孤立部件草稿」 | [40 号 §1](40-11至60级怪物正式动画制作方案.md) |
| P3 | 连续转身的**比例自洽性**在"单段视频内"通常尚可，足以支撑人工描绘，而不必承担跨图不一致 | 视觉判断，非实测结论 |

## 4. 判定

- **作为可抽帧的运行素材来源：不可行。** B1/B2/B4 属于格式与参数层面的硬约束，不是提示词能绕过的；B3/B5/B6 属于模型与项目规范的同源冲突。
- **作为转身参考物：可行且推荐。** 用 1 张设计稿生成 1 段匀速转身视频，只作人工绘制 8 个方向时的参照，**不从中抽帧入库**。成本一次调用，收益是拿到可靠的背面/侧面比例与遮挡关系。
- **八个方向的单帧（站立/打坐）根本不需要视频**：那是 8 张独立图，视频只会引入抠像与相位问题。

## 5. 三条生产路线

### R0 视频抽帧（不推荐，仅作验证用）

如果仍想亲手验证，规格必须收紧到极限，并设硬性终止判据：

- 规格：`ratio=1:1`、`resolution=720p`、`duration=4`、纯色平整背景（建议 `#00FF00`）、固定正交机位、无推拉摇移与变焦、恒角速度、全身入画、四周留边 ≥15%、无地面无投影无文字。
- 终止判据（任一不达标即停）：
  1. 8 个基准角度能精确对应到某 8 帧；
  2. 全片主体包围盒高度波动 ≤2%（即 64×80 帧内 ≤1.6px）；
  3. 抠像后边缘 alpha 只能取 0/1，黑白底各查一次无暗边与色溢。
- 即便三项全达标，仍要面对"在 64×80 帧内逐格重绘像素"这一步——工作量约等于直接绘源稿，**收益低于 R1**。

### R1 分层源稿 → 装配 → 离线烘焙（推荐主路径）

完全沿用 [40 号文档 §3](40-11至60级怪物正式动画制作方案.md) 的可执行生产线，把对象从怪物换成玩家：

1. 以设计稿为造型参考，逐方向建立 **s/sw/w/nw/n/ne/e/se** 的真实轮廓（真背面、非对称部件不镜像、主光固定左上）。
2. 按状态建立可编辑分层源稿（Aseprite/PSD/Krita 任一层格式），**交付分层源文件**，不保留扁平 PNG。
3. 在 Godot 中装配与预览，按状态×方向离线烘焙为 PNG 图集。
4. 在原生尺寸逐帧修补关节穿透、轮廓破碎、主光跳变、脚底漂移。
5. 收纳：源稿进 `art_source/`，运行图集进 `assets/sprites/player/<角色>/<look_id>/`，并按 `LOOKS` 表登记。

**输出契约（套用 `SampleActorArt`）**：

| 项 | 值 |
|---|---|
| 布局 | 列＝方向（8 列，`s, sw, w, nw, n, ne, e, se`），行＝姿势帧 |
| 帧格 / 锚点 | 64×80 / (32,64)；坐骑 128×128 / (64,104) |
| 图集尺寸 | 宽固定 512（8×64）；高 = 80×帧数（坐骑 宽 1024、高 128×帧数） |
| 格式 | 透明 RGBA PNG，sRGB，最近邻，关 mipmap，实色轮廓 |
| 每状态一图 | `idle` / `walk` / `attack` / `hit` / `death` / `sit` / 坐骑 `idle` `walk` |
| 另需 | 人物面板展示图 `look_XX_panel.png`（固定 ×4 整数倍约束） |

**若采纳你的帧数口径，需要先改的代码位置**：

| 目标 | 需改动 |
|---|---|
| 站立/打坐 1 帧 | 图集 `frames: 1` 即可运行（`clampi` 会把相位夹到 0），但会失去呼吸感且与现有 look 不一致；**建议对齐 4 帧** |
| 战斗 8 帧 | [sample_actor_art.gd#L201](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/entities/sample_actor_art.gd#L201) 的 `mini(5, int(...*6.0))` 与 [#L170](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/entities/sample_actor_art.gd#L170) 的旧路径映射；须保证命中时序不被动画改变 |
| 骑乘走路 8 帧 | [sample_actor_art.gd#L95](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/entities/sample_actor_art.gd#L95) 的硬编码 `frames = 4`，并同步 `LOOKS.mounts` 帧数登记 |
| 骑马战斗 | **先做玩法设计**：是否允许骑乘攻击、坐骑与角色如何同图、`hit/death` 如何表现；再改 [#L92](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/entities/sample_actor_art.gd#L92) 的状态选择逻辑 |

### R2 3D 白盒渲染（备选）

用 3D 角色 + 正交相机按 8 个角度、逐帧渲染透明 PNG，再像素化。优势是**帧数、角度、缩放的确定性最强**，且天然带 Alpha。代价是需要建模与绑定（人、马、骑乘战斗姿势），工作量大；40 号文档已记录本机未发现 Blender，且方案不以新增商业软件为前提。

适用条件：当"真实背面与连续转身的几何准确性"优先于"手绘像素质感"时启用。

**路线选择判据**：目标是"能直接进游戏的正式素材" → R1；目标是"先把转身比例和背面搞清楚" → 视频参考 + R1；目标是"批量、多套 look、要求几何绝对一致" → R2。

## 6. 提示词组织方案

### 6.1 视频提示词模板（只用于生成转身参考）

按工具要求，中文提示词用 `<图片1>` 指代首张参考图。模板：

```text
以 <图片1> 中的角色设计稿为唯一造型依据，严格保留其服装配色、发色体型、武器外形与配饰，
不要重新设计。角色原地匀速自转一整圈（360 度），单圈完成，全程角速度恒定，
不加速、不减速、不停顿、不反向。
固定正交机位，平视，无推拉、无摇移、无变焦，相机绝对静止，角色始终位于画面正中。
1:1 方形画幅，角色全身完整入画，头顶与脚底各留不少于 15% 的边距，主体在画面中的高度占比全程恒定。
背景为纯净平面单色 #00FF00，无渐变、无地面、无阴影、无投影、无道具、无第二个人物、无文字与字幕。
光照恒定不变，无闪烁、无明暗跳动，轮廓清晰干净。
负面要求：不要变焦、不要换装、不要改变身高与体型比例、不要改变武器长度、不要中途停顿、
不要文字水印、不要边框、不要地面倒影、不要特效光斑。
```

### 6.2 图像源稿提示词模板（逐方向）

单帧的站立/打坐**直接用这个模板逐方向出图**，不要用视频。每条提示词只改"方向角"一项，其余全部固定：

```text
游戏角色美术源稿，用途为八方向角色动画的逐方向源稿。
以 <图片1> 中的角色设计稿为唯一造型依据，保留服装、配色、发色、体型、武器与配饰，不重新设计。
视角：<方向角>（正面朝镜头 / 45 度侧前 / 正侧面 / 45 度后侧 / 正背面 / 45 度后侧另一侧 / 另一侧正侧面 / 45 度侧前另一侧），
正交投影、平视、无透视缩短、无广角变形。
姿势：<单一姿势描述，如自然站立的呼吸首帧 / 盘腿打坐>，脚底水平接地，身体中线垂直。
主体在画面正中，四周留出均匀边距，角色高度占画面约 70%。
背景完全透明，不绘制任何地面、阴影、投影、道具、文字、边框与 UI。
风格：干净清晰的轮廓，主光固定来自左上。
负面要求：不要正面代替背面、不要镜像复制、不要画面中出现第二个角色、不要半透明毛边、
不要渐变背景、不要水印与文字。
```

**必须显式写「不要正面代替背面」**：这是项目已记录的实际失败模式（多视角生成重复正面、缺失真正背面）。若背面仍不成立，就用 §6.1 的转身视频作参照，人工描绘背面轮廓。

### 6.3 多帧动作的提示词

走路/战斗这类多帧：

- **不要**要求"一次生成一张八向多帧的完整姿态表"——40 号文档已把这条判为失败路线。
- 正确做法：**逐方向、逐帧**单独生成姿势草稿（每条只改"方向角 + 帧相位"两个变量），或生成一张"姿态序列参考图"仅作人工描绘依据，随后在分层源稿里逐格重绘。
- 每条提示词固定机位、固定画布、固定锚点，并注明"本帧是第 N/8 帧，处于<起势/发力/收势>"，让跨帧的姿势描述本身构成连续节拍。

### 6.4 通用负面约束清单（所有提示词共用）

```text
不要重新设计角色、不要换装换色、不要改变体型与身高比例、不要改变武器长度或形状、
不要镜像复制、不要用正面代替背面、不要透视变形、不要半透明毛边、不要渐变或场景背景、
不要地面与投影、不要文字水印边框 UI、不要第二个角色、不要特效光斑与镜头光晕、
不要矢量光滑感（目标为清晰实色轮廓）。
```

## 8. 交付口径（若采纳 R1）

- 每状态一个图集、每 look 一套（`idle` `walk` `attack` `hit` `death` `sit` + 坐骑 `idle` `walk`），另交人物面板展示图。
- 源文件保留分层；运行图集为透明 RGBA PNG，宽固定 512（坐骑 1024），高 = 帧格高 × 帧数。
- 逐 look 登记 `LOOKS` 表（纹理 preload + `frames` + 帧格 + 锚点），多套 look 保持同作者同画风。
- 素材不得直接放入 `assets/`：先入 `art_source/`，经重排脚本产出运行图集后再登记。
- 验收：尺寸/通道/透明安全边/方向序/锚点自动检查，逐方向人工复核背面与非对称部件，再进 Godot 实窗看八向转身、全部状态与 0.8/1/1.5 倍率。
- 相关测试入口沿用现有角色与冒烟测试，改动帧数口径时须补跑战斗时序相关回归。
