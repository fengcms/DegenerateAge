# `look_01` 地面六状态八向动画样板 B

本目录对应 [初始角色形象补全规划](../../17-初始角色形象补全规划.md) 的 B 节点。2026-10-17 制作；A 节点人物造型已由用户确认。六状态图集现已接入正式游戏 `look_01`；以下保留审稿时的制作和验证记录。

## 交付规格与来源

| 状态 | 帧/方向 | 运行图集（均 8 列、64×80 单帧） | 帧序与来源 |
|---|---:|---|---|
| `idle` | 4 | `assets/sprites/player/guardian/animations/guardian_idle_atlas.png`，512×320 | 四排新绘呼吸姿态，6 FPS 循环 |
| `walk` | 8 | `guardian_walk_atlas.png`，512×640 | 现有四张行走关键帧与四排新绘中间帧交错，10 FPS 循环 |
| `attack` | 6 | `guardian_attack_atlas.png`，512×480 | 五排新绘挥剑与一排现有守护者收势姿态，12 FPS 预览；首帧即接触/有效动作 |
| `hit` | 2 | `guardian_hit_atlas.png`，512×160 | 两排新绘受击与恢复姿态，10 FPS 非循环 |
| `death` | 6 | `guardian_death_atlas.png`，512×480 | 五排新绘倒下过程与现有最终倒地姿态，8 FPS 非循环 |
| `sit` | 4 | `guardian_sit_atlas.png`，512×320 | 四排新绘打坐呼吸姿态，6 FPS 循环 |

总计 **8 个方向 × 30 张时间帧 = 240 个有像素的动作格**。方向列固定为屏幕 `s, sw, w, nw, n, ne, e, se`；脚底锚点固定 (32,64)。攻击与死亡的 AI 源稿只给出五排有效姿态，因此末帧明确取自现有图集，不把这两张混报为六排全部新绘。部分相邻帧动作幅度较小，正式接入时需按实际窗口观感决定是否调整节奏。

六张 AI 源稿位于 `art_source/player/look_01/animation_sources/`，以现有 `guardian` 世界精灵作为身份、方向与色板参考生成。新稿保留黑短发、炭灰衣物、旧布披肩、银灰护甲、皮带包和短刃青色细节；没有使用外部第三方素材。`tools/build_guardian_animations.gd` 记录各源稿的行界限、裁切、透明阈值、统一缩放及打包规则，可以从源稿和现有图集重新构建六张运行 PNG：

```bash
/Applications/Godot.app/Contents/MacOS/Godot --headless --path . --script tools/build_guardian_animations.gd
```

## 可运行预览

在 Godot 中打开并运行 `GuardianAnimationPreview.tscn`；按数字 **1—6** 切换待机、行走、攻击、受击、死亡、打坐，八个方向同时显示。此场景只用于审稿，不修改正式游戏的角色状态或伤害时刻。`guardian_idle_runtime_preview.png` 是实际窗口 1280×800 下录得的待机预览帧。

## 自检结果与进入下阶段的条件

- 六张运行图尺寸与预期完全相符；240 个图格全部有图，按方向逐行计算没有完全重复的时间帧。各帧不透明下沿均为 **y=64**，没有越出 64×80 格子的部分。
- Godot 4.7.2 GL Compatibility 完成新 PNG 导入；预览场景 headless 启动无脚本/资源错误，实际窗口录帧可见八方向与统一脚底线。headless 启动只证明脚本与资源可加载，视觉结论来自实际窗口截图和图集审看。
- 目视复查六张图集：八方向识别特征基本一致；打坐低矮、死亡伏地、攻击侧向挥剑可辨。攻击第五帧到现有收势帧、死亡第五帧到现有倒地帧仍需在完整循环中实机判断顺滑度；此处不宣称已经完成正式玩家状态机验收。
- 后续先按规划制作 `look_01` 骑乘样板，再在 D 节点把六状态动画和独立高清面板图一起接入正式玩家，并测试装备切换、伤害时机、坐骑切换、遮挡、存档与性能。
