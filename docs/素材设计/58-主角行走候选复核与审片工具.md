# 主角行走候选复核与审片工具

2026-11-17。本轮尝试主角单方向行走，结果是美术候选未通过，独立审片工具完成。营地中的原主角、两类怪物与地图保持不变，没有接入不合格动作。

## 现象与证据

内置image_gen共尝试四次：带原主角参考的六帧循环、四帧重制、四帧局部修正、两帧相反步态补制。首稿出现光晕与支撑腿重复；后续虽然消除了明显光晕，但没有可靠交换前后半周期的支撑腿。

保留代表候选art_source/actors/hero_walk_trial_v1/candidate.png用于审片。它是2172×724四列源稿，每格543×724。窗口原尺寸及3倍对照显示：第1与第3帧仍同侧腿前伸；第2帧抬膝偏高，第4帧不足以构成相反的完整半周期。与左侧原主角对照，裙甲、披布和武器角度也有变化。该结论来自逐帧目视，不是由图片差异率推断“动作合格”。

原因判断：自然语言要求“左右交替”没有让生成结果稳定遵循同一角色的肢体关系，且长裙甲遮住腿部连接，使自动生成和检查都更困难。这是当前结果反映的制作限制，不代表所有模型或方法都无法生成动画。

## 已完成工程

新增tools/motion_review隔离审片器，加载固定候选与review.json：原尺寸、三倍同步预览、四帧条带、静态主角对照、暂停/切帧/慢放。所有帧共用倍率及锚点，保留源稿中的漂移，不用单帧裁边归一化掩盖问题。

运行命令：

```sh
python3 tools/motion_review/launch.py
python3 tools/motion_review/launch.py --verify --capture /tmp/hero-motion-review
```

Godot4.7.2、Apple M1 Max、Compatibility真实窗口验证退出0；输出MOTION_REVIEW_VERIFY_OK并明确ART_NOT_APPROVED。覆盖共享图集、透明角、同步切帧、暂停不推进、手动步进、半速、循环与固定位置/倍率。目视检查frame_2.png：说明文字完整，原尺寸与放大图可辨，四帧排布无裁断。窗口截图在临时目录，未作为游戏资源入库。

## 成本及边界

四个AtlasTexture共享一张2172×724源图，RGBA8理论约6.0MiB（另有小尺寸静态对照），不按预览实例复制像素。工具有两个动态预览、四个静态帧和一个参考精灵；按配置6fps或3fps换帧，正常进程每帧只累计时间，只有帧改变才更新两处纹理引用和状态文字。资源在工具退出释放，不增加营地加载时间、显存或节点。

这里的pivot是审片统一标尺，不是已经验收的动画地面接触点；没有角色碰撞、血条、命中帧或结算时序。工具通过不等于美术通过。未运行正式游戏回归，因为本轮无正式游戏或营地代码变更，也未宣称FPS改善。

## 后续制作闸门

先用清晰姿态参考锁定左右两种相反落脚姿态，检查支撑腿是否交换、右手武器和服装是否一致，再补经过/抬脚帧。必要时改用可控骨架姿态作为生成约束，而不是反复整张重抽。只有在原尺寸循环中确认无单腿重复、明显跳变和脚滑，才输出固定帧尺寸图集，并沿既有角色动画接口绑定实际移动。单向通过后再扩方向；本轮不扩八向、不宣称怪物或攻击动画完成。
