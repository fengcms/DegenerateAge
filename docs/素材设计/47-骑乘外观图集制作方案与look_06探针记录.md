# 骑乘外观（坐骑）图集制作方案与 look_06 探针记录

日期：2026-10-19。状态：**look_06 探针已跑通并通过验收，待决定是否推广到 look_02—look_05**。

本文记录玩家「骑乘外观」图集的生产线、提示词、烘焙规则与 look_06 的探针实测结果，
供后续把同一套流程复制到其余阶段形象。代码契约以 `character_look.gd` 与 `sample_actor_art.gd` 为准。

## 0. 结论摘要

| 结论 | 内容 |
|---|---|
| 缺口 | `look_02`—`look_06` 原本没有骑乘美术，20 级后骑乘时世界图回退成步行形象 |
| 探针结果 | look_06 已产出 `idle`/`walk` 两张 1024×512 图集并登记进 `LOOKS["look_06"].mounts`，运行链路可用 |
| 生产线 | 内置 image_gen 出「品红底八向母版」→ ImageMagick 全局色键去背 → GDScript 逐状态归一、剔碎块、对齐脚底 → 打包 128×128 帧格 |
| 关键修正 | 母版原生绘制比例不一致（idle 单行母版人物约 852px、walk 四行母版约 440px），**必须逐状态各算一次缩放比例**，否则 idle↔walk 切换时主体跳大小一倍 |
| 遗留 | `w`/`e` 两列仍偏四分之三视角；walk 母版行距偏紧，个别方向有邻行羽片渗入（已由剔碎块兜住） |

## 1. 背景与缺口

- [18 号文档](18-11至51级主角阶段形象定稿与制作记录.md) 明确记录 `look_02`—`look_06` **无骑乘美术**。
- 骑乘玩法与后面形象已经存在：`mount_corrupted_wing`（第一章坐骑「腐化之翼」）20 级可骑，移速 ×1.3。
- 运行时的回退逻辑见 [sample_actor_art.gd](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/entities/sample_actor_art.gd#L67-L77)：
  `_mounts` 取 `definition.get("mounts", {})`，未登记坐骑的形象 `_mount_id` 直接置空 → 骑乘时仍显示步行图集。
- 因此 20 级以后换到 `look_02`—`look_06` 的玩家，骑上坐骑后视觉上「马没了」。

| 项 | 值 | 出处 |
|---|---|---|

| 脚底锚点 | (64, 104) | `LOOKS[*].mounts.pivot` |

| 帧数 | idle 4、walk 4（**硬编码**） | [sample_actor_art.gd#L95](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/entities/sample_actor_art.gd#L95) |
| 骑乘可切换的状态 | 仅 `idle` / `walk`；攻击走未骑乘的 `attack` 图集（游戏内不存在骑马战斗） | [#L92](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/entities/sample_actor_art.gd#L92) |
| 参照实拍 | look_01 坐骑图集内容量：walk 逐帧 45–49 宽 × 48–56 高；角色本体 64×80 帧内约 48 高 | 本文 §5 实测 |

人物 `look_06` 本体（对照用）：idle 逐格 18–19 宽 × 48 高、walk 33–46 宽 × 48 高，脚底均在帧内 y=64。
即坐骑与角色本体应是同一量级（约 48–56px 高），不能明显更大或更小。

## 3. 生产线

沿用 [40 号文档](40-11至60级怪物正式动画制作方案.md) 的分层源稿→装配→离线烘焙思路，落成五步：

1. **生成八向母版**：以定稿设计稿为唯一造型依据，用内置 image_gen 出「纯品红底、人物带腐化之翼」的八向母版
   （idle 为 1 行 8 列，walk 为 4 行 8 列）。
2. **去背**：ImageMagick 全局色键 + alpha 腐蚀，产出透明源稿，落在 `art_source/player/look_XX/mount_sources/`。
3. **切分**：按「8 列＝方向、rows 行＝姿势帧」切格，逐格裁掉透明边。
4. **归一与对齐**：逐状态各算一次缩放比例 → 点采样缩放 → 剔掉与主体不相连的邻格渗漏碎块 →
   按「主体中间 50% 竖带最低实心行」估脚底线，把脚底对齐锚点 y=104。
5. **打包与登记**：输出 1024×512 图集，在 `CharacterLook.LOOKS[look_id].mounts[mount_id]` 登记
   `idle`/`walk` 纹理与 `frame`/`pivot`。

工具：[build_player_mount_looks.gd](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/tools/build_player_mount_looks.gd)
（`extends SceneTree`，只构建坐骑图集，不接入玩法、不改骑乘规则）。

## 4. 提示词与命令

### 4.1 生成提示词（本轮实际参数的等价复现）

本轮在对话中直接调用内置 image_gen，**原始提示词文本未留档**；以下按 46 号文档 §6.2 的模板
与本轮母版实测参数（画幅、列序、品红底色 `srgb(252,22,168)`、双翼形态）还原为可复现的等价文本。

**idle（1 行 8 列）**：

```text
游戏角色美术源稿，用途为八方向骑乘形象母版。
以 <图片1> 中的角色设计稿为唯一造型依据，保留服装、配色、发色、体型与武器外形，不重新设计。
在角色背后增加一对腐化之翼：深紫黑色羽翼，左右对称，自肩胛向两侧展开、翼尖下垂，不遮住躯干正面。
一行八列，横向依次为：正面朝镜头 / 45 度侧前 / 正侧面 / 45 度后侧 / 正背面 / 45 度后侧另一侧 / 另一侧正侧面 / 45 度侧前另一侧。
姿势：自然站立持剑，脚底水平接地，身体中线垂直，脚底在同一水平线上。
正交投影、平视、无透视缩短、无广角变形；八列人物等高、构图等距分布。
背景为纯净平面单色品红 #FC16A8，无渐变、无地面、无阴影、无投影、无道具、无文字与边框。
风格：干净清晰的实色轮廓，主光固定来自左上。
负面要求：不要正面代替背面、不要镜像复制、不要画面中出现第二个角色、不要半透明毛边、不要水印与文字。
```

**walk（4 行 8 列）**：

```text
游戏角色美术源稿，用途为八方向骑乘行走母版。
以 <图片1> 中的角色设计稿为唯一造型依据，保留服装、配色、发色、体型与武器外形，不重新设计。
在角色背后增加一对腐化之翼：深紫黑色羽翼，左右对称，自肩胛向两侧展开、翼尖下垂。
四行八列：四行是同一段行走动作的四个连续相位（起势 / 迈步 / 发力 / 收势），
每列自上而下为这四个相位，节拍连续可辨；每行内八列方向依次为
正面朝镜头 / 45 度侧前 / 正侧面 / 45 度后侧 / 正背面 / 45 度后侧另一侧 / 另一侧正侧面 / 45 度侧前另一侧。
正交投影、平视、无透视缩短；八列人物等高、脚底在同一水平线上；行与行之间留出足够间距，人物不得跨行溢出。
背景为纯净平面单色品红 #FC16A8，无渐变、无地面、无阴影、无投影、无道具、无文字与边框。
风格：干净清晰的实色轮廓，主光固定来自左上。
负面要求：不要正面代替背面、不要镜像复制、不要画面中出现第二个角色、不要半透明毛边、不要水印与文字、不要让相邻人物互相重叠或跨行穿插。
```

> 本轮 walk 母版行距偏紧，出现过邻行羽片渗入（见 §5 遗留）。下一轮同族母版应把
> 「行与行之间留出足够间距、人物不得跨行溢出」写得更重，或直接把行数降到 2 行分两批出。

### 4.2 去背与烘焙

去背由工具内部调用（`_master_image`），命令等价于：

```bash
# 全局色键去背 + 腐蚀最外圈被背景污染的描边；不用 floodfill（人物轮廓围出的孔洞连不到画面四角）
magick <name>_<state>_raw.jpg -alpha set -fuzz 18% -transparent "srgb(252,22,168)" \
  -channel A -morphology Erode Disk:2 +channel -strip <name>_<state>_source.png
```

烘焙（重跑会重写 `_source.png` 与两张图集）：

```bash
/Applications/Godot.app/Contents/MacOS/Godot --headless --path . \
  --script tools/build_player_mount_looks.gd
```

新增形象时只需在工具顶部 `MOUNTS` 常量里补一条 `look_id → mount_id → state` 记录，不改打包逻辑。

### 4.3 登记

`CharacterLook.LOOKS["look_06"]` 的 `animations` 之后新增：

```gdscript
		"mounts": {
			"mount_corrupted_wing": {

```

## 5. 探针实测（look_06）

### 5.1 输入母版

| 文件 | 尺寸 | 体积 |
|---|---|---|
| `corrupted_wing_idle_raw.jpg` | 4096×1536（1 行 8 列） | 768,995 B |
| `corrupted_wing_walk_raw.jpg` | 4096×2048（4 行 8 列） | 1,422,727 B |
| `corrupted_wing_idle_source.png` | 去背后源稿 | 5,492,892 B |
| `corrupted_wing_walk_source.png` | 去背后源稿 | 10,438,168 B |

### 5.2 输出图集

| 图集 | 尺寸 | 体积 | 逐状态缩放比例 | 逐格内容量 |
|---|---|---|---|---|
| `corrupted_wing_idle_atlas.png` | 1024×512 | 117,235 B | 0.06572769953052 | 21–32 宽 × 54–56 高 |
| `corrupted_wing_walk_atlas.png` | 1024×512 | 167,387 B | 0.12334801762115 | 46–55 宽 × 51–56 高 |

- 两档主体高度都落在 54–56px，与 look_01 坐骑（48–56px）同量级；idle↔walk 不再跳大小。
- 逐格实测脚底均落在锚点线 y=104 附近（±2px，差异来自剑尖/下摆在中间竖带之外多探出的 1–2px）。
- 4 倍放大逐列目视：八向齐全、无品红残点、无孤立碎块；第 5 列（`n`）为真背面（看不到面部与胸前护甲，双翼对称展开）。

### 5.3 关键修正（本轮踩到的坑）

初版工具用「全状态单一比例」：取 idle+walk 所有格的最大高度当参考。结果
idle 主体 56px、walk 主体只有 28px——因为两张母版对同一角色画得不一样大
（idle 母版单行、人物约 852px；walk 母版四行、人物约 440px）。统一比例反而把 walk 压成一半。

修正为**逐状态各算一次比例**，并且**参考高度只取未顶到行边界的格**：walk 母版行距不足时，
格内容会顶到行边界并被邻行羽片撑大，这类格的高度不能参与取基准。
修正后 walk 比例由 0.0657 提到 0.1233，主体高度与 idle 对齐。

### 5.4 验收

```bash
python3 tools/run_isolated_tests.py CharacterLookTest MountShortcutTest SmokeTest
python3 tools/run_isolated_tests.py --rendered MountShortcutTest
```

- `CharacterLookTest`：新增覆盖，对所有登记了 `mounts` 的 look 校验 `frame == (128,128)`、`pivot == (64,104)`、
  `idle`/`walk` 纹理尺寸 == 1024×512。
- `MountShortcutTest`：新增覆盖，51 级装备六章长剑切到 `look_06` 后骑乘，校验世界图集确为本档 `mount_corrupted_wing`
  的 `idle`/`walk`（`vframes == 4`、`offset == -pivot`）。
- 三项 headless 定向回归与一次实际窗口运行均通过。

## 6. 已知局限

| # | 局限 | 影响 | 处置 |
|---|---|---|---|
| L1 | `w` / `e` 两个正侧面列仍偏四分之三视角 | 侧向移动时朝向不够「薄」 | 沿用既有结论：图像生成难以稳定产出严格正侧面，先接受；如需可单列重出 |
| L2 | walk 母版行距偏紧，部分格被邻行羽片渗入 | 已在打包阶段剔除，未进最终图集 | 剔碎块已兜住；下一轮把行距要求写重 |
| L3 | 母版同一动作的跨帧比例有轻微漂移 | 四帧之间体量差 ±2–3px | 逐状态归一后已压到可接受范围 |
| L4 | 去背用全局色键，距人物紫色件较近 | fuzz 过高会啃轮廓、过低留品红描边 | 定档 `fuzz 18% + Erode Disk:2`，本轮已目视确认无描边、无残点 |

## 7. 验收清单（复用到其他 look 时照跑）

- [ ] 图集尺寸 1024×512（idle/walk 各一张），帧格 128×128、锚点 (64,104)。
- [ ] 逐格内容量在 45–60px 高区间，且同一 look 的 idle 与 walk 主体高度一致。
- [ ] 逐格脚底落在 y=104（±2px）。
- [ ] 4 倍放大逐列目视：八向齐全、真背面成立、无品红残点、无孤立碎块。
- [ ] `LOOKS[look_id].mounts` 登记与图集路径一致。
- [ ] 跑 `CharacterLookTest` / `MountShortcutTest` / `SmokeTest`，再跑一次 `--rendered`。
