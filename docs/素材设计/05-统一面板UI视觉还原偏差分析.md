# 统一面板 UI 视觉还原偏差分析

日期：2026-10-15。本文对照用户修订的 [背包与人物浮窗 SVG](样板/统一面板UI-v1/01-背包与人物浮窗.svg)、[组件细节 SVG](样板/统一面板UI-v1/04-组件细节.svg)、本次提供的设计与游戏截图，以及当前 Godot 实现。本文只分析原因和后续验收方法，不修改游戏界面。

## 结论

这些差异主要是**实现和验收过程造成的还原不足**，不是 Godot 无法绘制，也不是用户提供的 SVG 有错误。此前实现优先搭起可伸缩、可复用、功能可用的面板结构，却把设计稿中的局部几何、渐变、高光和线条层级改写成较简单的 `StyleBoxFlat` 与脚本绘线；完成后又主要检查功能和整幅界面，没有按组件放大对照设计稿。我此前把这版实现描述为按修订 SVG 接入，表述过于充分；视觉细节实际没有达到同等还原度。

SVG 是固定 1280×800 画布上的视觉源稿，含大量路径、渐变和描边。它可以准确说明目标效果，但不能直接充当所有窗口尺寸、按钮状态和动态文本共用的 Godot 控件布局文件。需要先把框角、标题栏、按钮等元素拆为组件规格或运行素材，再在实际控件尺寸下核对。这一步当时没有做完整。

## 四项差异的直接原因

| 用户指出的问题 | 设计稿与当前实现的证据 | 形成机制 |
|---|---|---|
| 帮助、关闭按钮变成椭圆 | SVG 中两者是圆形图案。[`PanelChrome.style_help()` 与 `style_close()`](../../scripts/ui/panel_chrome.gd)只设置 26×26、30×30 的**最小**尺寸和圆角；按钮被加入背包标题行的 `HBoxContainer`。运行时量到帮助按钮实际为 26×40、关闭按钮为 30×40。 | 标题行把按钮纵向拉高，圆角半径不会强制控件保持正方形，因此圆框随实际矩形尺寸变成竖椭圆。属于布局约束遗漏，不是圆形画不出来。 |
| 四角金线成了直角 | SVG 的角饰是短横线、斜切连接、短竖线的连续折线；[`PanelChrome._draw()` 第 40–46 行](../../scripts/ui/panel_chrome.gd)分别画水平和垂直线，两线在同一坐标直接相接。 | 外框八边形的切角已实现，但内侧角饰被另行手画成直角；把“外框切角”和“角饰切角”当成了一项，漏掉后者。 |
| 按钮缺少高光等质感 | SVG 按钮包含渐变填充、上沿亮线和多层边框；[`PanelChrome.style_action()` 与 `_button_style()`](../../scripts/ui/panel_chrome.gd)为各状态只设置单一底色、单像素边框和圆角。 | 为快速共用和缩放，使用了纯色 `StyleBoxFlat` 近似原稿，未提取高光/渐变层，也未制作对应运行素材。禁用、悬停、按下状态虽有不同底色，但不是设计稿的视觉结构。 |
| 标题下看到多条线 | SVG 视觉上是一组标题分隔线，细亮线与紧贴的暗侧线共同构成一个分隔效果，并非完全只有一条路径；[`PanelChrome._draw()` 第 38–39 行](../../scripts/ui/panel_chrome.gd)画了两条相隔 2 像素的线，[`inventory_panel.gd` 第 183–185 行](../../scripts/ui/inventory_panel.gd)又在标题行下添加一个 `HSeparator`。 | 共用外框和背包内容各自负责标题分隔，叠加后产生额外横线及更大的间距；没有指定唯一的绘制归属。 |

上述控件尺寸来自本地只读运行检查；未改动项目文件。其他面板共用 `PanelChrome`，所以圆形、角饰和按钮的问题可能在多个界面重复出现；额外 `HSeparator` 的具体数量仍需逐面板核查，不能由背包截图推断所有面板相同。

## 为什么 SVG 没有自动保证还原

设计稿足够表达这些细节。固定画布、路径化文字和渐变定义使它适合审美确认，却不自动包含响应式尺寸、九宫格拉伸区域、控件最小/最大尺寸、悬停/按下/禁用状态或动态文案规则。开发时必须把视觉定义转成可复用组件；选择直接运行 SVG 切片、制作九宫格贴图，或用 Godot 绘制命令重建都可以实现，但每种方式都要确认裁切、缩放和状态表现。

这次的偏差不应归因于“SVG 格式有问题”。更准确的归因是：**没有建立从 SVG 图层到游戏组件的逐项映射，也没有把细节对照列为完成条件**。尤其是角饰、按钮高光和分隔线，源码中都能找到明确的简化或重复绘制位置。

## 过程上的缺口与下一步验收依据

[统一面板 UI 设计规划](04-统一面板UI设计规划.md)原定先整理视觉参数，再制作共享边框、按钮、选项卡组件预览，最后逐面板接入和视觉复核。实际上功能面板和共用样式先落地，中间的组件级视觉预览与逐项验收没有完成。功能测试能确认面板打开、交互与数据更新，却无法发现椭圆、折线转角或高光缺失；整幅截图也容易掩盖数像素级细节。

后续修复前，建议以用户修订 SVG 为基准建立组件核对表，至少明确：外框与四角折线、标题栏及唯一分隔线、帮助/关闭按钮直径与布局约束、操作按钮四种状态及渐变/高光、不同 UI 缩放档位。把 Godot 实际截图与设计稿按相同显示尺寸对齐，再分别放大检查四角、标题区和按钮；功能回归与视觉验收分开记录。采用贴图或脚本绘制属于实现选择，应以实测的清晰度、缩放效果和运行成本决定，当前没有证据表明存在技术不可行或性能阻碍。

本轮仅记录偏差及原因，**未修复上述视觉问题**。
