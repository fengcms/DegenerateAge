# 初始角色 `look_01` 形象补全规划

日期：2026-10-17。本文只规划初始阶段形象 `look_01` 的素材与接入验收，不制作图片、不改游戏代码，也不扩展 `look_02` 或更高阶段形象。这里的“1 级人物”指初始外观 `look_01`，不表示只处理角色等级为 1 时能触发的动作。

## 现状、证据与问题

| 项目 | 当前证据 | 影响 |
|---|---|---|
| 世界形象 | `guardian_atlas.png` 为 512×640、`guardian_walk_atlas.png` 为 512×320、`guardian_hit_sit_atlas.png` 为 512×160；帧格都是 64×80，八列对应八方向 | 已有八向关键姿态，但并非六种状态都有完整的逐帧动画 |
| 动作播放 | `scripts/entities/sample_actor_art.gd` 使用少量姿态，再用位移、旋转和缩放表现呼吸、攻击、受击、死亡和打坐；行走图集每方向有四张步态 | 运动可用，但近看有动作跳变；“八向已完成”不能等同于“八向全动画已完成” |
| 人物面板 | `scripts/systems/character_look.gd::panel_texture()` 截取主图集的方向 0 首帧（64×80）；`scripts/ui/character_panel.gd` 的展示框是 258×410，内宽 256 | 细节只来自 64×80 的世界图，放大后无法获得新的清晰度，人物在框内也偏小 |
| 骑乘 | `data/mounts.json` 登记两个坐骑，等级要求均为 20；`autoload/game_state.gd::ride_mount()` 设置骑乘状态，`scripts/entities/player.gd` 使用移速加成，但世界角色没有骑乘图 | `look_01` 在以后达到骑乘条件时仍可能使用，届时缺八向骑乘表现。此项属于初始外观的缺口，不属于 1 级即时可见内容 |

根因是当前美术以验证八向渲染、换装和动作链路为主，世界图集保留了关键帧，面板直接复用世界首帧，骑乘尚无世界素材契约。现行 [视觉与技术统一规范](01-视觉与技术统一规范.md) 与 [阶段形象方案](15-角色形象与素材方案（阶段形象·八向单层）.md) 继续作为风格和八向单层的依据；**本文只修订 `look_01` 面板“裁首帧放大”的做法**。

## 成品范围与规格

1. **统一角色基准**：先以现有 `guardian` 造型做八向定稿。保留头身比例、衣物、护具、武器持握、色板、左上方主光和两三个辨识特征；八方向固定为屏幕 `s, sw, w, nw, n, ne, e, se`，不靠水平镜像拼出带武器的另一侧。世界帧格暂保持 64×80、脚底锚点 (32,64)、主体高度约 40–48 像素；若动作确实越界，整套统一改规格并同步接入定义，不能单帧裁切或移动脚底。
2. **独立人物面板图**：绘制与 `look_01` 同一角色、同一装备和站立气质的高清全身展示稿，透明底、无文字和预烘焙面板背景。它必须是独立重绘的较高信息量素材，不能将 64×80 首帧或其高分辨率插值结果另存为“高清图”。以展示框内约 256×408 的可用区域为目标，首版运行图建议 **256×400**，可编辑母版至少 **512×800**；人物占画面主要高度，保留头顶、脚底和武器安全边。面板 100% 显示以接近 1:1 的运行图验收，150%–200% 则实测像素观感并决定是否需要从母版导出更高密度版本。`look_01` 使用独立路径；`look_02` 暂沿用现有回退。96×96 HUD 头像不在本轮重做范围。
3. **地面六状态补帧**：按现行规范制作 `idle` 4、`walk` 8、`attack` 6、`hit` 2、`death` 6、`sit` 4 张独立时间帧，每状态各八方向，共 **240 张世界帧**。保留现有帧格和方向列、时间行的图集约定；建议按状态拆成六张图集，分别为 512×320、512×640、512×480、512×160、512×480、512×320。它们是生产上限与验收目标，不把当前两姿势加程序变形误算为六张独立画帧。攻击帧标出接触瞬间，但伤害仍由原有战斗逻辑结算；死亡、暂停、打坐和攻击中断必须与现行状态机一致。
4. **`look_01` 骑乘表现**：当前两种坐骑都允许在 `look_01` 外观下使用，制作清单需分别登记 `mount_corrupted_wing` 与 `mount_furnace_beast` 的八方向组合形象。先做第一种坐骑的待机、行走与转向样板，再确认两个坐骑的造型、遮挡与脚底锚点。暂以规范中的 128×128、锚点 (64,104) 作为样板起点，实测主体是否能容纳，不在此时锁死尺寸。现有流程允许骑乘时攻击、受击和死亡，打坐也未自动下马；正式接入前必须逐一给这些状态提供一致的骑乘表现。优先沿用现有玩法并补相应表现；如果评审后决定打坐或死亡时下马，应作为**单独玩法变更**提出和测试，不能为省图偷偷修改。骑乘帧数、图集尺寸在样板通过并确定复用方式后锁定，避免提前承诺两种坐骑各重画全部地面帧。

世界新图集的解码 RGBA 粗估为 240×64×80×4 ≈ **4.69 MiB**，不含导入格式、mipmap、面板图、骑乘图和旧图保留期；这只是数量级估算，不是实测显存。制作时保留分层源稿于 `art_source/`，运行 PNG 放 `assets/`，登记来源、生成方式、帧序和锚点。像素边缘需在深浅背景下检查透明毛边。

## 分阶段制作与审稿点

| 节点 | 交付物 | 进入下一步的条件 |
|---|---|---|
| A. 造型与面板样板 | `look_01` 八向站姿对照、独立 256×400 面板图、同屏世界/面板预览 | 角色识别一致；面板清晰且人物占比合适；不存在放大世界首帧的块状感。**先审这一关，再批量补动画** |
| B. 地面动画 | 六状态八向图集、帧序/接触帧/锚点清单、游戏内状态切换样板 | 240 帧清单逐项对应；八向转身和走停不跳脚；攻击、死亡、打坐的可读性通过实机审看 |
| C. 骑乘样板及扩展 | 第一种坐骑的八向待机/移动样板，确认后扩展两种坐骑及现行可触发状态 | 骑乘与人物、场景风格统一；两个坐骑在转向、前后遮挡和状态切换中不露出空帧 |
| D. 接入与回归 | `CharacterLook` 的面板独立纹理入口、玩家状态动画接入、资源清单和验收记录 | 首次加载、换装、骑乘、存档恢复、100%–200% 窗口显示及性能验收完成 |

每个节点独立提交，仅包含本任务的源稿、运行图、接入代码、测试与说明。A 阶段未通过之前不批量生产 B/C。原世界图集保留为接入过程中的回退资源，确认新图完整后再整理依赖；不改装备数值、技能伤害、碰撞半径、移动速度、武器 `look` 字段或存档结构。

## 接入与复核方法

- 面板：`CharacterLook.panel_texture()` 改为返回一般 `Texture2D`，`look_01` 返回独立图；其他外观仍可裁首帧作过渡。人物面板随武器 `look` 变化，但不依赖世界动画当前帧；UI 打开和切装时验证纹理切换。`character_panel.gd` 中“固定放大四倍”的注释和尺寸依据须随实现更新。
- 世界：玩家使用的动画定义扩展为“状态→图集/帧数/帧率/锚点”；同一帧资源由实例共享，状态切换不加载文件、不重建图集。`SampleActorArt` 也被怪物使用，改造时须保持怪物旧图集的解释方式，或为玩家建立明确的兼容分支。骑乘表现从当前 `active_mount` 读稳定 ID，检查上马、下马、跨图、死亡/复活、换装与读档；不能仅以速度变化代替视觉切换。
- 自动复核：在现有 `CharacterLookTest`、`MountShortcutTest` 基础上增加能发现缺方向、缺帧、错误尺寸、错误锚点与资源路径的素材清单校验；状态逻辑测试应证明动画切换不重复结算攻击、不改变碰撞。图像质量仍需人工审看，自动检查无法判定风格好坏。
- 实机复核：固定窗口与同一地图路线，按 100%、150%、200% 观察面板和世界形象；逐方向检查待机→行走→攻击→受击→死亡→打坐及骑乘切换，尤其验证角色与房屋/树木前沿遮挡。记录冷加载时间、稳定帧时间中位/P95、纹理内存与新增资源解码占用，再与旧版同场景比较；目标仍是稳定 60 FPS，不能用 headless 测试推断 GPU 表现。

本文件是制作规划，尺寸与帧数中凡标注“建议”“样板起点”的部分要通过 A/C 样板和实机观察复核。当前没有新素材或运行测试结果，不将预估值写成已通过验收。
