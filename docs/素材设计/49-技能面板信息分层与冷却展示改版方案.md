# 技能面板信息分层与冷却展示改版方案

> 2026-10-21。依据玩家提供的技能面板截图、现行技能升阶实现与产品文档 03 §3.3 制定。本文件是待确认方案，尚未修改游戏界面或技能数值。

## 一、现象与根因

截图中的面板同时列出六个技能、自动红药和自动蓝药。每项技能的名称、解锁等级、可用状态、阶数、原始描述和当前效果都常驻在行内；已经 5／5 阶的五个技能仍各占一个灰色“升级”按钮。由于文字放大后每行至少占两三行，面板变得很高，而同一技能的描述与当前效果又部分重复。玩家快速找技能、拖入快捷栏时，这些细节反而降低了扫描效率。

代码证据：`scripts/ui/skill_panel.gd::_refresh()` 为每个技能创建图标、长描述和升级按钮；`_skill_row_text()` 拼入原始描述、当前效果以及下一阶信息。`scripts/ui/panel_skill_row.gd` 使用单列横向行卡。现有图标浮层只显示“拖动到快捷栏”，没有技能说明。数据表 `data/skills.json` 已有基础 `cooldown`、耗蓝、范围与描述；`SkillProgression.current()` 给出生效阶数；`GameState.cooldown_after_cdr()` 按装备等属性算施放时冷却；`PlayerCharacter.skill_cooldown()` 提供当前剩余秒数。快捷栏 `HotbarSlot` 已显示剩余秒数，但技能面板没有展示基础／有效冷却。因此这是**信息布局与呈现缺口**，无需重做冷却规则或存档。

## 二、推荐界面：精简行卡 + 一张结构化技能浮层

面板仍为可拖动浮窗，保持技能与背包等面板并开、Esc 只关最上层的既有行为。技能区保留单列行卡，避免 200% 文字倍率下双列过窄。每行只放玩家做决定所需的信息：

```text
┌──────────────────────────────────────────────────┐
│ [图标] 裂地斩       5/5 阶     CD 4 秒    已满阶 │
│ [图标] 灵刃风暴     3/5 阶     CD 15 秒   [升级] │
│ [图标] 未解锁技能   Lv40 解锁  CD 15 秒   锁定   │
├──────────────────────────────────────────────────┤
│ 快捷栏工具  [自动红药]  [自动蓝药]                │
└──────────────────────────────────────────────────┘
```

- 图标和名称仍可识别、可拖到快捷栏；阶数与状态常驻。基础斩击显示“普攻间隔”，不虚构独立技能冷却。已满阶用文字状态替代灰色升级按钮；尚未解锁显示解锁等级，图标保持不可拖；可升阶时保留明确的“升级”按钮。自动红／蓝药移入独立的“快捷栏工具”小区，仍可重新拖回快捷栏，避免与六个战斗技能混排。
- 行卡的 `CD` 是**技能基础冷却**，便于横向比较。若正在冷却，图标上用现有快捷栏的倒数样式覆盖“剩余 Ns”；鼠标悬停时显示精确到一位小数的剩余时间。普攻显示“当前攻击间隔”，受攻速／Buff 影响，不称作固定 CD。
- 悬停图标、名称或升级按钮时显示同一张结构化技能浮层；键盘聚焦这些控件时也能看到。浮层按“名称与阶数 → 技能作用 → 伤害／增益 → 耗蓝、范围和冷却 → 下一阶”排序。长文案限定最大宽高，必要时内部滚动，不允许像曾经的装备浮层那样被文字撑成整屏。按钮灰态的原因留在浮层中，并在按钮上提供简短提示。
- 点击“升级”维持当前的一次购买流程；点击行卡本身不施放技能，拖动图标仍只产生快捷栏载荷。鼠标移动到按钮时，浮层不应意外遮挡按钮或吞掉点击。界面保持无额外全屏遮罩，自动战斗在面板打开时照常运行。

浮层示例（数字由运行态生成，不写死在文案中）：

```text
裂地斩 · 2/5 阶
前方范围攻击，最多命中 3 个目标
当前伤害系数 1.44×       下阶 1.48×（+0.04×）
耗蓝 15 · 范围 2.5 格 · 基础冷却 4.0 秒
当前属性下施放冷却 3.2 秒（冷却缩减 20%）
当前剩余 1.4 秒
升至 3 阶：Lv25、3,000 金币
```

满阶时不显示“下阶”区块；未解锁时显示解锁等级和基础效果，但不暗示可以施放。战意觉醒改用攻击／攻速增益、持续时间的当前／下阶对照；灵刃风暴保留“单段系数 × 3 段”的表达，避免把单段数值误认作总伤害。自动药品的浮层只解释自动吃药、拖放与对应药品冷却，不借用技能升阶样式。

## 三、冷却显示口径

| 名称 | 数据入口 | 显示规则 |
|---|---|---|
| 基础冷却 | `SkillProgression.current(id).cooldown`；普攻例外 | 行卡 `CD Ns` 和浮层“基础冷却”；升阶不会改它 |
| 当前属性下的下次施放冷却 | `GameState.cooldown_after_cdr(base)` | 浮层显示“当前属性下施放冷却”；CDR 变化时重新计算，不能改写已开始的冷却 |
| 正在进行的剩余冷却 | `PlayerCharacter.skill_cooldown(id)`，与 `GameState.skill_cooldowns` 同一运行态字典 | 冷却中才显示；浮层保留一位小数，图标上向上取整显示秒数；到零立即隐藏 |
| 普攻间隔 | `PlayerCharacter.effective_attack_interval()` | 标为“攻击间隔”，受当前战意增益影响；不把 `_attack_cd` 误当成可升级技能的独立 CD |

冷却跨地图继续计时、暂停冻结、读档重置的现行规则保持不变。玩家在冷却期间更换带冷却缩减的装备，只改变**下一次施放**的冷却；浮层同时显示原有剩余秒数和新条件下的预计施放冷却，避免数字看似矛盾。角色不存在（主菜单／切图瞬间）时只显示静态基础冷却，不伪造“剩余 0 秒”。

## 四、技术实现与成本

1. 在 `skill_panel.gd` 中把技能行拆成简短摘要与详情数据；摘要与浮层均从 `SkillProgression.current/resolve/step` 取值，购买状态仍通过 `GameState.buy_skill_rank()` 判断，不复制一套数值。`_refresh()` 继续只在等级、阶数、数据重载时重建行；金币、装备、Buff 和冷却变化只更新现有控件。
2. 新增一张可复用的技能详情浮层控件，使用已有 `PanelChrome` 色彩与字号规则，限制宽高并按视口边缘自动选择左右落点。浮层只在悬停／聚焦时创建或更新，离开、拖拽、切图或面板关闭时释放；不用每个技能永久挂一份复杂节点。参考 `ItemSlot._make_custom_tooltip()` 的结构化卡与 `EquipmentComparisonTooltip` 的实时刷新思路，但不复用装备属性排版。
3. 面板可见且有冷却时，只刷新六个图标的倒数文本；浮层打开时最多以约 10 次／秒刷新**一张**浮层的剩余秒数。静态基础说明走事件更新，不能把整张列表放进 `_process()` 重建。总量固定为六个技能和两个快捷栏工具，不新增数据文件、贴图或存档字段。
4. 缩放与布局按逻辑视口处理：100%／150%／200% UI、文字倍率，以及 1280×800、2280×1425 和较窄窗口均检查面板不越界、按钮可点击、浮层可见并可滚动。若窄窗连单列都放不下，面板内容纵向滚动，标题与关闭按钮始终可见。

## 五、开发顺序和准出检查

1. 更新产品文档 03 的技能面板展示规则及现有 UI 设计规划，明确“行卡摘要、浮层详情、三种冷却数字”的口径；仅改文档，独立提交。
2. 完成紧凑行卡与自动药品分区，保持拖放、购买、满阶、未解锁的行为；对比截图中的行高和面板总高度，独立提交。
3. 完成结构化浮层和冷却显示，包括 CDR、进行中的倒计时、普攻间隔与战意 Buff；独立提交。
4. 扩展 `SkillRankPanelTest`、`HotbarUiTest` 和 `SettingsTest`，覆盖 100%／200% 缩放、浮层边界、冷却冻结／归零、跨图、升级、拖放与按钮点击。隔离 Godot 测试后，在原生窗口进行一次长文案与鼠标操作验收；通过后提交测试与修正。

验收判据：玩家不悬停也能找到技能、阶数和能否升级；悬停能看全基础效果、当前／下一阶、蓝耗、范围及冷却；不同冷却数字的语义清楚且与实际施放一致；200% 放大时浮层不遮住整面板或越出屏幕；拖技能、点击升级和面板背后的自动战斗均保持现行行为。真实 UI 高度和操作手感须在实施后原生截图复测，本文件不声称已完成视觉验收。
