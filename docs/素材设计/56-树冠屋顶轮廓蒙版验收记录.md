# 树冠屋顶轮廓蒙版验收记录

本轮将模块化营地样板的水平高度蒙版替换为人工轮廓蒙版。范围为隔离样板，正式地图、存档和战斗规则未变。

## 问题与实现

旧实现只按纹理纵坐标决定哪些像素能淡出，无法区分同一高度的枝叶与主干、屋顶与墙面。新配置tools/modular_camp/occlusion_regions.json标注允许区域及优先保护区域；build_assets.gd结合原图透明度离线生成黑白蒙版。原图不修改，地图仍由地面图集和独立物件组合。

树的主干与根部、棚屋的墙面、门和支柱被保护。occluder.gd使用同一蒙版探测人物头身的9个采样点，reveal.gdshader只在允许区域及人物附近淡出，最大降低82%不透明度，过渡约0.2秒。脚底排序、导航与物理不受影响。图像尺寸不符、保护/淡出抽样点不符会使构建断言失败。

## 实测与复核

2026-11-17，Godot 4.7.2，Apple M1 Max，Compatibility真实窗口运行：

```sh
python3 tools/modular_camp/launch.py --build-assets
python3 tools/modular_camp/launch.py --verify --capture /tmp/modular-camp-contour
```

构建检查通过；窗口验证退出码0，输出MODULAR_CAMP_VERIFY_OK。覆盖256邻域到47形状、两套布局、地面图集、草路互斥、真实物理路线、墙体阻挡、门洞、绕墙及移动墙后的导航失效。遮挡验证让角色实际寻路到可达遮挡点，检查淡出、前方恢复、远处不触发，以及导航版本、阻挡格、碰撞数量不变。

同位置opaque/reveal窗口截图对照：棚屋屋顶局部淡出后可见角色，门与墙保留；树的主干继续遮挡角色下半身。截图只用于验收，留在临时目录，不加入运行依赖。当轮遮挡专项实际只对第一布局执行，通行与物理断言覆盖两布局。57号接入时发现并更正此记录，同时将遮挡专项扩展至两布局，重新通过窗口验证；扩展后同名遮挡截图最终保留第二布局。

## 成本与限制

新增两张蒙版共182360像素，RGBA8理论显存约0.70MiB；CPU缓存蒙版替代同尺寸原图缓存。每个受影响片元增加一次蒙版采样，无全屏采样、动态灯光和新物理节点。每套布局一树一屋，人物位置变化时每对象最多9点探测，物理帧仅推进尚未完成的过渡；切换布局释放旧对象及材质，纹理按现有缓存复用。未实测完整游戏帧时间，不声称FPS提升或可直接扩大到大地图。

轮廓是人工多边形近似，不是逐枝逐瓦分层；同尺寸换图也须人工重审，抽样检查不能证明整个轮廓匹配。树干仍可能挡住部分身体，这是保护结构的结果。屋后的角色与屋顶在屏幕投影重叠，不表示能登屋顶或进屋。角色仍是静态占位，两类怪物与角色动作未在本轮交付。下一阶段仍需完善素材方向、锚点与角色动画，再讨论正式地图接入。
