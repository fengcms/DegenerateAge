# 模块化营地动态样板阶段交付

本记录汇总当前可运行局部样板，区分已实现、已验证与正式接入缺口。它不是全游戏美术改造完成声明。

## 已实现

- 两套16×16格营地由地形、道路、贴花和独立墙、棚屋、树、箱桶拼装。地面64×32等距投影，窗口1280×800，窗口尺寸不是地图格数。Tab切换布局，M移动墙时同步导航与碰撞，B显示占地。
- 主角八向站立、行走、攻击、受击、倒地均有独立运行素材和加载期区域缓存；不镜像替代不对称持剑。行走随实际位移推进，攻击和反应只做预览，不改变正式伤害时机。F/C按当前朝向受击/倒地，V重置。
- 两怪有待机、攻击、步态、受击、倒地；F8沿已有左前朝向真实试走，Z原地审查，X/E/Q反应和复位，K/L暂停逐帧。两怪目前仍为单方向，不等于八向怪物完成。
- 北角接触抖动已修正，恢复八向顶墙完整覆盖。截图验收主动绘制，避免等待未发生的绘制信号。

## 验证与成本

运行 `python3 tools/modular_camp/launch.py --verify`；窗口完整验收使用 `--verify --capture /tmp/camp-review`。两布局无窗口与GL Compatibility窗口均通过：八向主角攻击、受击、倒地各64张实际采样；真实行走、八向顶墙、撤销输入、物件碰撞、绕障、门洞、动态墙、遮挡和切图释放均保留断言。两怪真实试走覆盖四帧、抵达、暂停、死亡和关闭取消。

动作清单运行 `python3 tools/modular_camp/check_motion_catalog.py`。主角动作理论RGBA8为7616KiB，两怪1920KiB，合计9536KiB；不是整场显存。正常窗口基线使用独立 `--benchmark`，结果见工程文档《营地动态样板性能基线》。截图验收的主动绘制不计入正常帧率结论。

交付仍在 tools/modular_camp 隔离项目，不读取正式存档，不替换现有玩家look、地图或怪物外观档案。所有关键阶段分别本地提交，未推送。

## 仍待完成的正式接入条件

1. 两怪其他朝向及帧间解剖/材质一致性精修，不能用单方向试走冒充全方向追踪。
2. 将精简帧数和逐帧时长适配既有角色/怪物动画契约；现有主角还有打坐、骑乘等状态，当前样板未提供完整替代。
3. 正式营地按现有地图配置、NPC、出口、任务与存档迁移，不能直接把16×16试验场覆盖正式地图。
4. 既有战斗流程中的命中、死亡清理、掉落、怪物预算与密集特效持续验收。当前30秒/布局移动采样不替代满预算战斗或长期挂机。

上述属于后续正式接入范围，不能因清单全勾选或一次性能样本通过而跳过。当前样板可独立运行、复用素材重排、检查动作和真实碰撞。
