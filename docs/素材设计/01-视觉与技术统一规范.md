# 01 视觉与技术统一规范

## 1. 风格与造型

采用 **复古像素的等距末法幻想**。本次建议以东方器物语言（如意、镇脉刻纹、布革护具）结合废土生存材料，不默认添加宗门、仙宫、现代枪械或赛博设施。

- 像素簇清楚，轮廓优先，材质依靠有限色阶和块面；不使用照片纹理、平滑 3D 渲染或柔焦涂抹。
- 人类：布、皮、旧铁、铜、木、补丁与绑带。文明器物刻纹采用有秩序的短线与闭合几何。
- 腐化：紫色裂痕、错位骨板、尖锐晶体、不规则分叉；面积逐图递增，避免所有表面都发光。
- 灵能：小面积青白流线与粒子；与大面积紫色腐化形成区别。青白是美术建议，不改技能属性。
- 装饰保留磨损与修补，但小尺寸不能堆满裂纹。每个主体先建立 2–3 个辨识特征。
- 地形低对比，角色中高对比，危险信号最高对比；环境不可使用与交互标记同亮度的大量闪点。

## 3. 透视、光照与尺度

- 地面为 2:1 菱形（64×32），视觉采用约 30° 的等距斜角，不混入正俯视或透视消失点。
- 世界主光固定屏幕左上，暗面在右下；脚底阴影单独交付，可运行时复用，不烘焙大型投影进角色。
- 所有尺寸均为 **100% 地图倍率下的世界像素**，不是物理屏幕像素。高分辨率通过运行时显示策略适配，不把整张地图做成 Retina 大图。
- 建议首轮角色可见高度 40–48 px，比当前小型占位更清晰；必须在现有碰撞半径和密集战斗中验证，不随图片自动扩大碰撞。首轮若遮挡过多应缩减造型，而非改数值。

| 类型 | 推荐导出画布 | 推荐有效主体 | 锚点 |
|---|---|---|---|
| 玩家/NPC | 64×80 | 人形高 40–48 | 脚底 (32,64) |
| 普通狼/虫 | 80×80 | 宽 36–56、高 24–40 | 接地中心 (40,64) |
| 游魂 | 64×80 | 高 40–48 | 虚拟脚底 (32,64) |
| 精英狼王 | 112×112 | 普通狼约 1.3–1.5 倍 | (56,88) |
| 腐化巨兽 | 192×192 | 高约 96–128 | (96,152) |
| 坐骑世界表现（储备） | 128×128 | 骑乘组合高约 64–88 | (64,104) |
| 地面物 | 32×32 | 16–24 | (16,24) |
| UI 物品/技能图标 | 48×48 | 32–40，四周留 4 px 以上 | 居中 |
| 头像 | 96×96 | 脸和肩部 | 圆形裁剪安全区 |

尺寸是本规范制作起点，非已有加载器契约。动作超出画布时可扩画布，但所有方向/帧统一扩展并重新登记锚点，不能逐帧自动裁剪。

## 4. 方向与动画契约

方向使用 **屏幕方向**，顺序固定 `s, sw, w, nw, n, ne, e, se`；避免与网格 col/row 方向混淆。转向按实际屏幕运动向量判定。武器、盾、非对称伤疤不允许随意镜像；对称普通怪可镜像，但需重做主光和标志性细节。

| 状态 | 建议帧数 | 预览 FPS | 循环 | 要求 |
|---|---:|---:|---|---|
| idle | 4 | 6 | 是 | 呼吸幅度小，脚底不漂 |
| walk | 8 | 10 | 是 | 接地、摆臂、武器随动 |
| attack | 6 | 12 | 否 | 蓄势→命中→收势，标记命中帧 |
| hit | 2 | 10 | 否 | 短促，不遮盖原有硬直逻辑 |
| death | 6 | 8 | 否 | 最后一帧可停留/淡出 |
| sit（玩家） | 4 | 6 | 是 | 与现有打坐状态对应 |
| interact（NPC） | 4 | 6 | 否 | 点头、递物等简短表现 |

可移动战斗角色按八向制作；玩家普通包为 8×(4+8+6+2+6)=208 帧，打坐按八向另加 32 帧。NPC 首批静止不需要 walk；木桩只需 idle/hit/death，无追击或攻击动作。

FPS 是美术预览速度。接入时攻击动画要适配代码攻击间隔，受击适配实际硬直。命中帧仅作为表现标记，不得由播放回调重复结算伤害；Boss 0.8 秒预警以运行时参数为准。暂停时战斗动画暂停，纯 UI 动画是否继续按现有菜单行为处理。

建议按状态独立图集：每行一个方向、每列一帧，例如玩家 walk 图集 512×640（8列×8行，每帧64×80）。静态道具不放八行空白。每份制作单登记状态、行序、帧数、帧尺寸、锚点、命中/接地标记、循环与时长。

## 5. 文件交付与 Godot 接入

- 世界像素、图标、帧动画：透明 RGBA PNG，sRGB。实色轮廓避免半透明毛边；特效允许渐进透明，检查黑白底无暗边。
- SVG 仅用于简单可缩放 UI 符号、logo 或现有矢量素材复用；世界角色/地砖维持像素纹理，不能混成光滑矢量风。
- UI 装饰边框采用独立角块/边块和九宫格资源；正文、数量、键位、等级、属性、冷却数字和任务文字全部由代码绘制。
- 源文件保留分层（Aseprite/PSD/Krita 等实际所用格式），导出文件与源文件分开；不提交生成缓存作为正式素材。
- 世界像素默认建议 Nearest、关闭 mipmaps；平滑 UI 矢量/文字使用适合各自的过滤。非整数缩放的像素粗细会变化，需要实机检验，不强行修改现有缩放范围。
- 图集帧边留透明安全区，使用 AtlasTexture/region 时配置过滤边界；不为图集排版缩放角色。透明边不纳入碰撞。
- 建筑、树冠、脚底、阴影分层；角色与建筑按脚底位置排序，不按图片上缘。注意 `Iso.depth()` 注释与负 Y 坐标的关系，接入时以实际前后遮挡验收，不能直接照搬文字改排序。
- 图片纹理不自动替代 `_draw()`；后续需增加 Sprite2D/AnimatedSprite2D、图标加载和状态绑定。禁止以“路径写入 JSON”当作已接入。

建议目录（后续制作时创建，保留已有配置路径）：

```text
assets/sprites/player/guardian/
assets/sprites/npcs/<role>/
assets/sprites/monsters/<monster_id>/
assets/sprites/equip/<equipment_id>.png
assets/sprites/skills/<skill_id>.png
assets/sprites/items/<item_id>.png
assets/sprites/mounts/
assets/sprites/fx/<effect_id>/
assets/tiles/<map_id>/
assets/ui/{frames,icons,cursors,portraits,menus}/
assets/audio/{music,sfx,ambience}/
docs/素材设计/制作记录/             # 清单、元数据、验收截图
art_source/                         # 后续可创建的可编辑源文件目录
```

ID 与数据完全对应；文件名小写英文加下划线，例如 `wolf_corrupted_walk.png`。正式路径不加版本号，源文件/制作记录可加版本号；Godot `.import`/`.uid` 由工程流程生成，不手写。

每批附资源表，至少含：asset_id、data_id、类型、文件路径、尺寸、锚点、动画元数据、源文件、作者/生成方式、授权依据、依赖、审核状态、接入状态。字体须覆盖中文、英文、数字与符号，有可分发许可；不用像素字体承载长篇中文正文。
