# 怪物等级与 Boss 独立状态栏美化方案

日期：2026-11-06。怪物头像等级已实现，提交 `996f5b17`；本文 Boss 美化部分为待评审设计，未替换现有 Boss 状态栏。配套[矢量示意稿](2026-11-06-Boss独立状态栏方案.svg)展示视觉层次，另附同源PNG预览用于直接查看；数值为示例，头像为主体占位符，不是游戏截图或最终 Boss 美术。

## 已实现：普通目标头像等级

普通/精英怪物头像右下角加入金边等级徽章，直接继承人物的徽章绘制、13号字、深色描边及四位数字宽度适配。数字来自 Monster 实例的 level，不取模板默认等级。目标切换时更新，NPC/空目标清空，不增加逐帧测量。目标血条起点右移10像素，为徽章保留边界；等级底部在目标卡局部70像素处，避开既有跨级提示。

窗口验证实例等级1234以及1/999/1000/9999，检查字宽、血条边界、NPC/空目标切换和 Boss 不重复出现普通卡；实际查看9999级截图。HudTargetLevelTest、HudLiveTooltipTest、HudBuffTest、EquipmentGapUiTest、BossMultiTargetTest 五项通过。测试使用独立项目和 user://，临时截图不入库。

## Boss 当前问题

`scripts/ui/boss_health_bar.gd` 自绘矩形血条，宽480、条体高18、行距56，最多3条。独立状态表已保存实例id、血量、阶段和实际等级，但当前没有头像和等级徽章；血量数字与阶段名处在同一行，大数值时可能争抢空间。`Hud.gd` 会隐藏选中 Boss 的普通目标卡，因此只给普通头像加等级并不能解决 Boss 等级展示。

同名 Boss 分实例、已有条目原位更新、逐条过期和死亡淡出都已有实现，应直接沿用。现有普通怪头像只为少量早期模板配置路径，Boss 头像不能照搬这段硬编码名单。

## 推荐方向：旧铜与暗血

与玩家头像共用旧铜金色和细雕边，Boss 增加低矮的冠饰/断角作为专属识别；头像及血量底色用深灰黑，血量为暗红到朱红的轻微纵向层次，浅米色文字加深色描边。金色负责身份与框架，红色负责生命信息。不要在 HUD 中复用地面的危险圈或大面积红光，以免混淆技能预警。

| 部位 | 建议表现 |
|---|---|
| 头像 | 64×64逻辑像素，铜环与低矮冠饰；使用各 Boss 真实外观裁切，缺失时用统一首领轮廓 |
| 等级 | 头像右下角，与已上线人物/怪物徽章同源；完整数字和字宽适配 |
| 名称 | 独立首行，米金色17–18号字；长名省略并保留完整悬停提示 |
| 生命条 | 保持横向条体，暗红填充、细铜边；当前血量立即更新，可选一次短暂受伤余量反馈 |
| 数值 | 独立文字行，完整当前值/上限；百分比靠右，不与阶段标题叠写 |
| 阶段 | 名称行右侧的小型铭牌；只显示已有实际阶段，没有对应阶段就不虚构 |
| 跨级提示 | 独立最下行，沿用 EquipmentGap 真实结果，无提示时留稳定行高或不绘制文字 |
| 当前选中 | 边框适度提亮，附小型指示符；切换目标不重排血条 |

阶段刻度必须来自真实技能/阶段阈值：首章的60%/30%不能一律复制给所有 Boss。SVG 为首章阶段示意；其他模板应按各自动作数据决定是否显示刻度和名称。

## 布局与多 Boss

建议基准卡宽560逻辑像素：头像与留白约76，条体约460。首行详细卡高88，其余两行紧凑卡高60，间距8；最多3行总高224。示意稿按较大展示比例绘制，实际接入按这些逻辑尺寸排布。

保留现有“新实例首次插入顶部、已有实例不重排”的模型。显示槽1固定为详细卡，槽2/3为紧凑卡；选中其他条目只高亮，不交换位置或改变槽位高度。紧凑卡显示头像/等级、名称、血条、百分比与阶段，完整血量及跨级详情可悬停查看。大血量例如百亿以上必须在详细卡实测字宽，优先独立两列或两行，不能缩小到难以阅读。

当前1280×800下，普通目标卡占横向316–548、纵向24起，其跨级提示延伸到约130。直接在旧顶部位置加宽 Boss 卡会与它相撞。推荐先将 Boss 堆栈置于屏幕水平中心、逻辑y=140附近，右缘避开小地图；普通目标卡、人物状态区均保持原位置。该位置和最多三行的遮挡程度需要放回实际战斗画面评审，不能只凭本独立示意稿定稿。

小窗口或150% UI缩放下，根据实际逻辑视口的空闲区域收窄条体。若三行已侵入主要战斗区域，整体切换固定行高的紧凑模式，仍显示3个实例，不能静默少显示Boss。切换显示模式由视口/设置事件触发，并验证普通目标卡、小地图、任务追踪和技能预警的共存。

## 动态与实现边界

- 接战时做一次约0.15秒透明度进入；死亡继续沿用现有0.6秒停留、0.3秒淡出，不反复新建Tween。阶段变化可一次短暂铜边提亮，避免持续闪光和粒子。
- 不新增会影响战斗判断的技能读条。若以后需要施法信息，应由实际技能状态驱动，不能靠动画猜测倒计时。
- 数据表仍由 BossHealthBar 管理，单行表现可以提取 BossStatusRow；以实例id绑定，最多3行。头像通过 appearanceId 共用一个裁切入口，按外观缓存纹理/区域，按切图或数据revision失效；不在血量事件或_draw中反复解码图像。
- 背景与装饰优先复用StyleBox/少量矢量绘制，保持GL Compatibility；不为每条卡片加入屏幕采样、实时模糊和独立大图特效。
- 仅血量/阶段/装备等事件更新对应文本；动画结束后停止处理。先量冷加载、P95/P99、绘制与内存，再谈性能结论。

## 分步落地及复核

1. 先做单 Boss 详细卡与头像等级，验证1/999/1000/9999级、长中文名、极大血量、缺图回退；用实际战斗窗口确认空间占用。
2. 再做3槽固定布局、同名不同实例、选中高亮、逐条过期与死亡淡出；沿用 BossMultiTargetTest，补充文字不重叠和缩放边界验收。
3. 最后增加受伤/阶段的一次性反馈，并在百首禁域18只混合Boss、召唤和连续切图下做窗口采样，复核头像缓存释放、节点数量与地面预警可读性。

每个完成节点独立提交。当前普通怪等级功能已完成；Boss 部分交付设计稿与实施方案，尚未更改运行时样式。
