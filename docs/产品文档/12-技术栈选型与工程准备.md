# 12 技术栈选型与工程准备

本章记录 R3 技术栈决策结论，并系统列出正式开发前需要完成的准备工作。产品需求基线（00–11 + 附录A）定义的全部机制与系统，均据此技术栈落地。

## 12.1 R3 决策结论：采用 Godot 4

- **决策时间**：2026-10-11。
- **选型结果**：采用 **Godot 4** 作为游戏引擎；首版使用 **GDScript**（语法简洁、AI 协作友好、零额外 SDK），仅在需要强类型或性能热点时引入 **C#**（需 .NET / Mono 运行环境）。
- **选型依据（摘要）**：
  - 构建与开发最轻量：单文件下载、秒级启动、项目即文件夹、首次导入无编译负担。
  - 免费资源最友好：引擎 MIT 开源，社区素材默认免费可商用；通用免费 2D 等距素材（Kenney、OpenGameArt）对 Godot 零导入摩擦。
  - **项目纯文本化对 AI 协作是决定性优势**：场景 `.tscn`、资源 `.tres`、配置 `project.godot`、脚本 `.gd` 均为文本，AI agent 可直接读写，无需依赖二进制 GUI 搭建。
  - 三平台原生导出：macOS / Windows / Linux 玩家端包一键导出，Linux 导出最干净（一等公民）；编辑器在 macOS（Apple Silicon）原生可用，契合本机开发。
- **排除项**：
  - Swift / SpriteKit：仅 Apple 平台、无法原生导出 Windows / Linux，与 R4（macOS 首发、后期跨平台）硬冲突，排除。
  - Unity：工具链与素材总量、C# 语料更强，但安装重、免费资源偏付费、`.prefab` / `.unity` 场景为二进制或混 GUID 的 YAML 对 AI 直接读写不友好，作为备选保留（仅当未来需要重 3D 或大型商业素材管线时启用）。
- **跨平台说明**：首发 macOS，后期按 R4 视情况跨 Windows / Linux；输入 / UI 已抽象（见 9.3 / 9.10 / 9.11），Godot 的导出模板覆盖三平台，无需为跨平台另写分支。

## 12.2 开发前准备工作（分类清单）

准备工作按七类组织，前四类为"启动即做"项，后三类为流程与基线确立。

### A. 环境与工具链
- 下载 Godot 4 标准版（macOS Apple Silicon 原生）；若采用 C# 则下载 Godot 4 .NET（Mono）版并安装 .NET SDK。
- 初始化 Git 仓库，添加 Godot 专用 `.gitignore`：忽略 `.godot/`（导入缓存）、二进制导入产物；保留 `*.import` 元数据或一并忽略（以仓库整洁为准）；不提交运行时生成的 `imported/`。
- IDE：Godot 内置脚本编辑器（GDScript 高亮 / 补全可用）+ 可选 VS Code（`godot-tools` 插件）或 JetBrains Rider（C#）。
- **AI 协作接入**：部署 `godot-mcp`，使 AI agent 能读取 / 生成 `.tscn` / `.gd` / `.tres` / `.json`，确立"AI 直接读写文本项目"的工作流（本选型的核心收益点）。

### B. 工程脚手架
- 目录结构（`res://` 下）：`scenes/`（场景）、`scripts/`（GDScript）、`assets/`（美术 / 音频）、`data/`（14 个 JSON 配置）、`autoload/`（全局单例）、`addons/`（插件）。
- 项目设置：渲染器默认 2D；默认分辨率 **1280×800**（见 9.11 最小分辨率），窗口可自由缩放；开启 Retina（2x）清晰渲染。
- 输入映射（InputMap）注册 PRD 快捷键：移动 WASD、普攻 Space、Tab 目标切换（见 3.15）、自动战斗 F、自动拾取 G、暂停 Esc、交互 E、快捷栏 `1 2 3 4 5 6 7 8 9 0 - =`；全部键位在设置面板可重映射（见 9.3）。
- 核心 Autoload 单例：`GameState`（全局状态）、`DataLoader`（读 JSON + 校验）、`SaveManager`（原子存档，见 10.3）、`EventBus`（解耦事件总线）。
- 接入数据层：实现 JSON 配置加载与启动校验（ID 唯一 / 引用合法 / 等级范围，吸收 GDD 既有数据驱动骨架的校验原则）。

### C. 美术与素材（R5 占位策略）
- 制定像素 / 斜角 2D 规范：等距瓦片 **64×32**（见 7.1），精灵锚点与深度排序约定，调色板基线。
- 获取免费占位素材：Kenney Isometric Tiles / Characters、OpenGameArt；先占位，框架成型后购商业 / 自制（R5）。
- 建立 `assets/` 目录与命名规范、Sprite Sheet 切分流程与 Godot 2D 导入预设（像素保持、不滤波模糊）。

### D. 数据驱动落地（复用第 10 章）
- 将第 10 章 14 个 JSON Schema 落成实际 JSON 文件，置于 `data/`。
- 先填**第一章示例数据**：地图（测试营地 / 试炼野外 / 灰烬之地 / 腐化源头）、怪物模板（腐化野狼 / 裂壳虫 / 灰烬游魂 / 裂爪狼王 / 腐化巨兽）、技能（基础斩击 / 裂地斩 / 旋风斩 等）、掉落表、任务 Q001–Q005、货郎 / 铁匠 / 车夫 / 任务官 / 仓库、药水、升星参数、坐骑 / 如意（预留）。
- 实现配置校验框架（启动校验，见 10.4），保证数据非法时明确报错而非静默。

### E. AI 协作工作流
- 确立**单一事实源**：PRD（设计事实源）→ 14 个 JSON（数据事实源）→ Godot 工程（运行事实源）。
- 约定：AI 改动以文本文件（`.tscn` / `.gd` / `.tres` / `.json`）为主，不依赖手动 GUI 生成二进制；提交前运行配置校验；PRD 设计变更需同步对应 JSON。
- 通过 `godot-mcp` 让 AI 能直接创建 / 修改场景与脚本，最大化本选型的 AI 友好收益。

### F. 验证基线（对齐 10.5）
- 建立 MVP 验收清单，覆盖 16 项测试场景（T01–T16：八向移动、撞墙、禁斜切、单次结算、升级结转、穿戴属性、掉落合法、不可达改选、手动接管、背包满、冷却 / MP 回退、Boss 首杀唯一、暂停无收益、死亡关自动、切图 / 读档清旧实体、存档损坏恢复）。
- 性能基线：2D 等距普通战斗稳定 60 FPS、约 30 同屏敌人 + 常规特效无持续卡顿；存档原子写入、数据校验通过。

### G. 分阶段实施路线（最小闭环，依据 R2 排期原则）
- **阶段 0 脚手架**：环境 + 目录 + 输入映射 + Autoload 单例 + 数据校验框架（即本准备阶段产出）。
- **阶段 1 货郎经济闭环**：移动 / 相机 / 基础战斗（普攻）/ 掉落 / 拾取 / 货郎买卖 / 金币 / 背包 / 存档。
- **阶段 2 任务系统**：任务官 / 任务链 Q001–Q005 / 任务列表 UI / 奖励结算。
- **阶段 3 多图与车夫**：多地图 / 战争迷雾 / 车夫跨图 / 完整 NPC 体系 / 精英 / Boss 阶段。
- **阶段 4 坐骑 / 升星 / 铁匠**：升星十字面板 / 仓库 / 坐骑 / 如意 / 完整 HUD 与四面板。
- 每阶段以 10.5 验收标准中的对应场景为出口条件。

## 12.3 准备工作优先级与建议起步

- **立即（本阶段产出）**：A 环境 + B 脚手架 + D 第一章 JSON 骨架 + 配置校验框架。
- **随后**：C 占位素材 → 进入阶段 1 可玩 Demo。
- **下一步动作候选**：直接搭建工程脚手架（A + B）并生成第一章 14 个 JSON 示例数据；此后即可进入阶段 1 的可玩 Demo 开发。
