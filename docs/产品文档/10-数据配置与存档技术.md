# 10 数据配置与存档技术

本章定义数据驱动原则、配置文件清单与 Schema、存档机制、技术约束，以及质量与验收标准。产品需求与具体引擎 / 语言解耦，技术栈已定为 Godot 4（R3 决策），不影响本章定义的产品范围与机制，本章配置 Schema 在 Godot 4 下直接落地。

## 10.1 数据驱动原则

核心原则：**装备 / NPC 商品 / 任务 / 对话 / 怪物 / 掉落 / 地图 / 坐骑 / 如意 / 仓库 / 杂项物品 全部文本可编辑**。开发期可直接改 JSON，不硬编码。新增物品 / 怪物只需加 JSON 条目 + 对应图标，无需改代码。

```
JSON 配置 (equipments / skills / monsters / ...)
本地化文案 (localization.json)        ─┐
存档 (save slots, 原子写入)            ├─→ 引擎加载 → 运行时实体 / 实例
                                     ─┘
模板 ID 与实例 ID 分离：同模板可不同词条；实例属性永久保存，不每次重随。
```

## 10.2 配置文件清单与 Schema

| 配置文件 | 覆盖 | 关键字段 |
|---|---|---|
| `equipments.json` | 装备模板 | id, name, slot, tier, levelReq, quality, baseAttrs{atk,def,hp,mp}, pctAttrs[](可空), affixes[](可空), price, icon, desc |
| `skills.json` | 技能 | id, name, unlockLevel, kind(attack/buff), coefficient, cooldown, manaCost, shape, range, targetType, desc, icon |
| `monsters.json` | 怪物 | 见 7.5 字段 |
| `dropTables.json` | 掉落表 | id, entries[{kind(coin/potion/equip/rune), qualityWeight{}, chance, goldRange/itemId/itemIds/levelRange}] |
| `quests.json` | 任务 | id, type(main/side), giver, objective{kind,targetId,count}, reward{gold,xp,item}, mapScope |
| `shops.json` | 货郎 | npcId, buyItems[{itemId,price,tier}], sellEnabled |
| `upgrade.json` | 升星 | successRate[13], costParams{UP_BASE,UP_R} |
| `mounts.json` | 坐骑 | id, name, speedBonus, dropBossId, icon |
| `runes.json` | 如意 | id, name, successBonus, dropBossOnly=true |
| `warehouse.json` | 仓库 | baseSlots, expandSlots, expandBase, expandRate, cap |
| `miscItems.json` | 杂项 | id, name, useType(playAnimation), animation, desc |
| `potions.json` | 药水 | id, kind(red/blue), tier, restoreAmount, cooldown, price, stackMax |
| `affixes.json` | 精英词缀 | id, name, attackPct/attackSpeedPct/defensePct/moveSpeedPct, slowPct/slowDuration, lifeStealPct, summonId/summonCount（按效果选配） |
| `maps.json` | 地图 | id, name, size, tierRange, carterLinks[], spawnPoints[{monsterId,respawnTime}], bossSpawn |
| `localization.json` | 文案外置 | key→text（首版中文，预留多语言） |

Schema 约定：所有数值字段可配；`quality` 枚举 common/uncommon/rare/epic/legendary；`tier` 由等级推导(4.5)；新增物品 / 怪物只需加 JSON 条目 + 对应图标，无需改代码。

> **金币事实源（M1 校准落定）**：怪物金币**以掉落表 `coin` 条目为唯一事实源**（拾取时入账，受 6.2 金币上限约束）；模板 `goldReward` 仅为**无 `dropTableId` 时的回退值**（如教学木桩），有表时被静默忽略——避免"改了模板值却不生效"的维护陷阱。

## 10.3 单机存档与数据可靠性

> M4-3 存档版本为 schema 3，新增 `warehouse: [背包物品实例或 null]` 与 `warehouseExpansions`；旧档迁移为 40 格空仓库。仓库格数必须与扩容次数及配置相符，物品采用与背包相同的合法性校验。M3-3 的 schema 2 曾新增 `exploredMaps: {地图ID: [区块ID]}`；旧档缺字段默认未探索，读档过滤未知地图、重复及非法区块。

存档记录：`schemaVersion / slotId / savedAt`、角色信息 / 等级 / 经验 / 血、技能解锁、背包物品实例、已穿戴实例、仓库物品与扩容次数、金币、当前地图与坐标、任务状态、首杀标记、用户设置与自动开关。

> **口径说明（M1-10 落定）**：「自动开关」指设置项里的默认值 `autoBattleDefault / autoPickupDefault`；
> F / G 切开的**运行态开关不写存档**——两者是不同对象，以免与下一条「重启后自动战斗默认关闭」冲突。
> 「坐标」以世界像素存为 `[x, y]` 数组（JSON 无向量类型）；读档时越界坐标会被夹回地图可用范围。

- **重启后自动战斗默认关闭**（即使退出前开启）。
- **保存策略**：关键事件即时存（升级 / 重要物品 / 穿戴 / 任务 / 切图 / 首杀）；常规每 **120 秒**自动存；退出存；**原子写入**（临时文件成功后再替换主档）+ 至少 1 份最近有效备份；写入失败提示不静默丢失；不持久化运行时节点对象。
  - 补充（M1-10）：关键事件存以 **0.6 秒去抖**合并连续变更，避免频繁写盘；自动存**成功静默、失败必提示**。
  - 补充（M1-10）：**新游戏（未手选过存档槽）不做自动写盘**，防止覆盖已有存档；玩家手动存 / 读某槽后该槽成为活动槽。
  - 补充（M1-10）：启动时按「上次使用的槽」自动续档（对应 9.4 主菜单的「继续」语义），因此「退出重进」无需手动读档即一致。
- **旧档迁移**：未知 / 损坏数据明确错误提示并保留备份；版本更新经 `schemaVersion` 递增，新增字段给默认值（见 4.5 版本化内容 + 旧档导入）。

## 10.4 技术约束与原则

- **技术栈已定：Godot 4**（R3 决策）：产品需求机制与引擎解耦，本章配置 Schema 与机制在 Godot 4 下直接落地；选型依据与工程准备见《12-技术栈选型与工程准备》。
- **性能**：1440×900 普通战斗稳定 60 FPS；约 30 同屏敌人 + 常规特效无持续卡顿。
- **等距渲染**：64×32 瓦片 + 坐标公式（见 7.1）；遮挡按深度排序。
- **寻路**：静态网格 + 节流；自动战斗 / 怪物共用同一移动 / 寻路 / 技能接口。
- **输入抽象**：键鼠输入已抽象（4.6），后期可加手柄映射不阻塞首版。
- **配置校验**：启动校验 ID 唯一 / 掉落权重 / 引用合法 / 等级范围（吸收既有数据驱动骨架的校验原则）。

## 10.5 质量与验收标准

- 1440×900 普通战斗稳定 60 FPS（记录负载与机型）。
- 约 30 同屏敌人 + 常规特效无持续卡顿。
- 开背包 / 切图 / 连续击杀不持续增长内存、不重复注册事件 / 计时器。
- 退出重进后等级 / 背包 / 装备实例属性 / 金币 / 任务 / 地图位置一致。
- 自动打怪连续 30 分钟不卡墙、不无限重选不可达目标、不无限拾取满背包。
- 覆盖 16 项测试场景（T01–T16）：八向移动、撞墙、禁斜切、单次结算、升级结转、穿戴属性、掉落合法、不可达改选、手动接管、背包满、冷却 / MP 回退、Boss 首杀唯一、暂停无收益、死亡关自动、切图 / 读档清旧实体、存档损坏恢复。

### 第一轮审阅后的存档验收规则

当前 schema 2 必须提供完整进度字段与正确类型；校验角色等级、经验、HP/MP、金币、地图、坐标、背包物品、装备槽与任务状态。无版本/未来版本或缺失当前版本字段不会静默补成新游戏。明确的 v0 保留历史最小角色格式迁移；完整 v1 补探索及已知新增设置/解锁字段。只在版本迁移后完整校验通过时读入；未知探索区块仍按既有规则过滤。装备上限变化后的 HP/MP 仍在应用阶段收敛，而非误判为坏档。

无效主档不会覆盖有效备份；备份通过临时文件替换，复制失败保留旧备份并停止保存。主档缺失/损坏时尝试备份，恢复写盘失败会明确提示。直接应用坏档不会改变当前进度。
