# 10 数据配置与存档技术

本章定义数据驱动原则、配置文件清单与 Schema、存档机制、技术约束，以及质量与验收标准。产品需求与具体引擎 / 语言解耦，技术栈已定为 Godot 4（R3 决策），不影响本章定义的产品范围与机制，本章配置 Schema 在 Godot 4 下直接落地。

## 10.1 数据驱动原则

核心原则：**装备 / NPC 商品 / 任务 / 对话 / 怪物 / 掉落 / 地图 / 坐骑 / 如意 / 仓库 / 杂项物品 全部文本可编辑**。开发期可直接改 JSON，不硬编码。新增物品 / 怪物只需加 JSON 条目 + 对应图标，无需改代码。

```
JSON 配置 (equipments / skills / monsters / ...)
本地化文案 (localization.json)        ─┐
存档 (save slots, 原子写入)            ├─→ 引擎加载 → 运行时实体 / 实例
                                     ─┘
模板 ID 与实例 ID 分离：同模板可不同词条；实例属性永久保存，不每次重随。
```

## 10.2 配置文件清单与 Schema

| 配置文件 | 覆盖 | 关键字段 |
|---|---|---|
| `equipments.json` | 装备型号 | id, name, slot, tierBases{所属套起点:原始基础属性}, requiredLevel, affixPool, price, icon, desc；品质与星级不绑定型号 |
| `equipmentRules.json` | 装备三轴规则 | tiers[1,11], slotOrder[十部位], qualities{倍率,词条数}, fixedAffixes, percentAffixes, starMult, maxStar |
| `skills.json` | 技能 | id, name, unlockLevel, kind(attack/buff), coefficient, cooldown, manaCost, shape, range, targetType, desc, icon |
| `skillProgression.json` | 玩家技能升阶 | skillId, ranks[{rank,unlockLevel,goldCost,coefficientMultiplier 或 effects}]；只登记五个可升级技能，普攻不在表内 |
| `monsters/index.json` + `monsters/chNN/monsters.json` | 具体怪物；按章节登记加载路径，`DataLoader` 聚合为原 `monsters` 表；章节 README 记录用途与清单 | id, name, level, hpBase, attack, defense, dropTableId, appearanceId, bossSkill 等；见 7.5 字段 |
| `monster_appearances/index.json` + `monster_appearances/<外观 ID>.json` | 可复用的怪物表现；一档案可供多种具体怪物引用，未接入美术用 `placeholder` | id, renderer, 图集/生成包引用、锚点、头顶血条高度等；不含伤害和奖励 |
| `dropTables.json` | 掉落表 | id, entries[{kind(coin/potion/equip/rune/misc/mount), qualityWeight{}, chance, goldRange/itemId/itemIds/levelRange/tierStart}] |
| `quests.json` | 任务 | id, type(main/side), giver, objective{kind,targetId,count}, reward{gold,xp,item}, mapScope |
| `shops.json` | 货郎 | npcId, buyItems[{itemId,price,tier}], sellEnabled |
| `upgrade.json` | 升星 | successRate[13], costParams{UP_BASE,UP_R} |
| `mounts.json` | 坐骑 | id, name, speedBonus, levelReq, dropBossId, icon |
| `runes.json` | 如意 | id, name, successBonus, dropBossOnly=true |
| `warehouse.json` | 仓库与背包容量（共用） | baseSlots, expandSlots, expandBase, expandRate, geoCap, tailStep, cap |
| `miscItems.json` | 杂项 | id, name, useType(playAnimation), animation, desc |
| `potions.json` | 药水 | id, kind(red/blue), tier, restoreAmount, cooldown, price, stackMax |
| `affixes.json` | 精英词缀 | id, name, attackPct/attackSpeedPct/defensePct/moveSpeedPct, slowPct/slowDuration, lifeStealPct, summonId/summonCount（按效果选配） |
| `maps/index.json` + `maps/chNN/<地图 ID>/map.json` | 地图；清单决定加载顺序，每图独立配置，同目录 README 说明用途和关键参数 | id, name, size, tierRange, kind(hub/spoke), hubId, hubLinks[], carterFare{hub,spoke}, carterFares{目标ID:金币}, carterArrival, exits[], entrances{}, spawnPoints[{monsterId,respawnTime}], bossSpawn |
| `localization.json` | 文案外置 | key→text（首版中文，预留多语言） |

Schema 约定：所有数值字段可配；`quality` 枚举 common/uncommon/rare/epic/legendary。装备实例须保存 `equipmentRuleVersion=4`、`requiredLevel`、`rawBaseAttrs`、品质和星级倍率快照、已抽定词条与唯一实例 ID；`requiredLevel` 用于显示和穿戴，所属套起点用于基底、词条档与售价倍率。来源只决定合法型号/档位/品质，生成共用工厂；缺档不得回退到低档伪装高等级。

怪物模板按设计章节归属管理，地图刷新等级可覆盖模板等级，但不改变模板所属文件。地图、任务、掉落和存档继续引用稳定的具体怪物 `id`，不可用显示名称或章节数组位置代替。具体怪物通过 `appearanceId` 使用独立表现档案；换外观不改变伤害、技能冷却、任务或奖励。修改章节数据后运行 `python3 tools/check_monster_catalog.py`，并同步章节 README；设计边界见 `docs/工程文档/38-怪物配置分章与表现复用方案.md`。

> **金币事实源（M1 校准落定）**：怪物金币**以掉落表 `coin` 条目为唯一事实源**（拾取时入账，受 6.2 金币上限约束）；模板 `goldReward` 仅为**无 `dropTableId` 时的回退值**（如教学木桩），有表时被静默忽略——避免"改了模板值却不生效"的维护陷阱。

## 10.3 单机存档与数据可靠性

> 原三轴模型首次上线时不读取 schema 0—10。逐级穿戴目录使用 schema 13，并迁移 schema 11—12 的现有角色装备；主档和备份按既有原子写入流程保留。

存档记录：`schemaVersion / slotId / savedAt`、角色信息 / 等级 / 经验 / 血、技能解锁、背包物品实例、已穿戴实例、仓库物品与扩容次数、背包扩容次数及装备出售预设（旧数字阈值只为旧档兼容保留）、装备实例可选收藏标记、坐骑收藏 ID 列表与当前骑乘 ID、金币、当前地图与坐标、任务状态、首杀标记、用户设置、12 格快捷栏配置与自动开关。

> **技能升阶 schema 15**：`skillRanks: {技能ID: 2—5阶}` 只保存已购买阶数；没登记的已解锁技能按角色等级视为 1 阶，未解锁为 0 阶。schema 11—14 旧档迁入时补空字典，保留现有进度；schema 15 拒绝未知技能、非整数、超阶以及角色等级尚未达到相应门槛的记录。技能冷却与当前 Buff 仍是运行态，不写存档。

> **M6-3 schema 9**：新增 `visitedMaps: [地图ID]`，记录世界装配成功后实际到访的地图。新档从 `camp` 开始；v8 及更早存档迁移为 `camp` 与合法的当前地图。未知地图 ID 拒绝读档。车夫可列出本集群及相邻枢纽，未到访目的地不能乘车（营地→试炼野外免费教学线例外）。第一章费用按 `carterFares` 逐对配置；缺显式对时按所属枢纽的 `carterFare` 目标类型报价。步行和乘车只有在目标世界装配成功后才提交到访、切图事件和自动存档；失败退还车费并恢复原图。

> **M4-8 schema 6**：`hotbar` 为定长 12 的数组，元素为 `null` 或 `{kind, id}`。`kind` 限 `auto_potion`、`potion`、`skill`、`item`，ID 必须在对应数据表中且具备已接通的使用效果；自动选药只允许 `red` / `blue`。旧档迁移为默认红药、蓝药、普攻和 9 个空格；配置只记录模板引用，不记录背包下标、实例或数量。配置变更走关键事件自动存档。

> **口径说明（M1-10 落定）**：「自动开关」指设置项里的默认值 `autoBattleDefault / autoPickupDefault`；
> F / G 切开的**运行态开关不写存档**——两者是不同对象，以免与下一条「重启后自动战斗默认关闭」冲突。
> 显示偏好（界面 / 地图 / 文字倍率、显示适配、全屏、窗口大小）独立保存在本机，主菜单先于读档应用；角色存档仍保留旧 settings 字段用于兼容和首次导入。其他设置沿用槽位数据。
> 「坐标」以世界像素存为 `[x, y]` 数组（JSON 无向量类型）；读档时越界坐标会被夹回地图可用范围。

- **重启后自动战斗默认关闭**（即使退出前开启）。
- **保存策略**：关键事件即时存（升级 / 重要物品 / 穿戴 / 任务 / 切图 / 首杀）；常规每 **120 秒**自动存；退出存；**原子写入**（临时文件成功后再替换主档）+ 至少 1 份最近有效备份；写入失败提示不静默丢失；不持久化运行时节点对象。
  - 补充（M1-10）：关键事件存以 **0.6 秒去抖**合并连续变更，避免频繁写盘；自动存**成功静默、失败必提示**。
  - 补充（M4-7）：新游戏先选择三槽之一，确认覆盖已有槽后创建新档；写盘成功后该槽成为活动槽。写盘失败保留旧存档，未选槽时不自动写盘。
  - 补充（M4-7）：启动先显示主菜单；「继续」读取上次使用的有效槽，「读取存档」可任选有效槽。返回主菜单前保存当前活动槽，世界停止模拟。
- **装备三轴上线的旧档边界**：当前 schema 13 读取现行实例，也接受并迁移 schema 11—12：旧型号按部位归入第一套或第二套，同一实例的 ID、品质、星级与词条不变，基底统一重建；不满足新穿戴等级的已穿戴装备安全卸下。schema 0—10 继续明确拒读，主档/备份保留。

## 10.4 技术约束与原则

- **技术栈已定：Godot 4**（R3 决策）：产品需求机制与引擎解耦，本章配置 Schema 与机制在 Godot 4 下直接落地；选型依据与工程准备见《12-技术栈选型与工程准备》。
- **性能**：1440×900 普通战斗稳定 60 FPS；约 30 同屏敌人 + 常规特效无持续卡顿。
- **等距渲染**：64×32 瓦片 + 坐标公式（见 7.1）；遮挡按深度排序。
- **寻路**：静态网格 + 节流；自动战斗 / 怪物共用同一移动 / 寻路 / 技能接口。
- **输入抽象**：键鼠输入已抽象（4.6），后期可加手柄映射不阻塞首版。
- **配置校验**：启动校验 ID 唯一 / 掉落权重 / 引用合法 / 等级范围（吸收既有数据驱动骨架的校验原则）。

## 10.5 质量与验收标准

- 1440×900 普通战斗稳定 60 FPS（记录负载与机型）。
- 约 30 同屏敌人 + 常规特效无持续卡顿。
- 开背包 / 切图 / 连续击杀不持续增长内存、不重复注册事件 / 计时器。
- 退出重进后等级 / 背包 / 装备实例属性 / 金币 / 任务 / 地图位置一致。
- 自动打怪连续 30 分钟不卡墙、不无限重选不可达目标、不无限拾取满背包。
- 覆盖 16 项测试场景（T01–T16）：八向移动、撞墙、禁斜切、单次结算、升级结转、穿戴属性、掉落合法、不可达改选、手动接管、背包满、冷却 / MP 回退、Boss 首杀唯一、暂停无收益、死亡关自动、切图 / 读档清旧实体、存档损坏恢复。

### 第一轮审阅后的存档验收规则

当前 schema 13 必须提供完整进度字段与正确类型；校验角色等级、经验、HP/MP、金币、地图、坐标、背包物品、仓库、坐骑收藏与骑乘状态、装备槽、任务状态及 12 格快捷栏。无版本、未来版本或 schema 0—10 均不会静默补成新游戏。当前版本缺少后增设置键时仍按默认值补齐；未知探索区块仍按既有规则过滤。装备上限变化后的 HP/MP 在应用阶段收敛，而非误判为坏档。

无效主档不会覆盖有效备份；备份通过临时文件替换，复制失败保留旧备份并停止保存。主档缺失/损坏时尝试备份，恢复写盘失败会明确提示。直接应用坏档不会改变当前进度。
