## 1. 需求原话与形式化

用户原话：

> 「车夫，可以实现不同的城镇之间的快速传递，以及当前城镇的附属地图的传递。而不是到达所有的地方。如 A 城镇包含 a1 a2 a3 a4 等附属地图，B 城镇包含 b1 b2 b3 b4 等地图。那么，在 A 城镇的车夫，可以传送到 a1 a2 a3 a4 和 B 城镇。B 城镇的车夫，可以传送到 b1 b2 b3 b4 和 A 城镇。」

形式化：

- 地图分两级：**枢纽（城镇）** 与 **附属地图**。
- **集群** = 一个枢纽 + 它的全部附属地图。
- **车夫目的地 = 本集群全部地图 ∪ 相邻枢纽 − 当前地图**。
- **不含**其他集群的附属地图（要到别的镇，先到那个镇再换乘）。

```text
集群 A                    镇间连线              集群 B
┌───────────────────┐                        ┌───────────────────┐
│ 枢纽 A             │◄──── 相连（双向）──────►│ 枢纽 B             │
│  ├─ a1  ├─ a2      │                        │  ├─ b1  ├─ b2      │
│  ├─ a3  └─ a4      │                        │  ├─ b3  └─ b4      │
└───────────────────┘                        └───────────────────┘
A 的车夫 → a1 a2 a3 a4 + B（不到 b1~b4）
B 的车夫 → b1 b2 b3 b4 + A（不到 a1~a4）
```

## 3. 通用规则

### 3.1 概念定义

| 概念 | 定义 | 数据 |
|---|---|---|
| **枢纽 / 城镇** | 具备车夫与完整功能 NPC 的安全区（如幸存者营地） | `kind="hub"` |
| **附属地图** | 从枢纽辐射的野外 / 关卡图 | `kind="spoke"` + `hubId` |
| **集群** | 一个枢纽 + 它的全部附属（由 `hubId` 反查） | 推导 |
| **镇间连线** | 枢纽 ↔ 相邻枢纽 | `hubLinks` |

### 3.2 车夫规则

- **目的地解析**：`(集群(当前图) ∪ hubLinks(所属枢纽)) − 当前图`。
- **跳数 ≤ 2**：本集群 1 跳；其他集群的**枢纽** 1 跳；其他集群的**附属**＝先到其枢纽再换乘（2 跳）。
- **到访门控**：目标需**已到访**（或满足 `requiresUnlock` 剧情条件）；**教学线除外**。
- **教学线**：营地 → 试炼野外 0 金币且始终可用。
- 菜单按"枢纽 / 附属"分组；未到访项置灰，提示「先步行到访，开放直达」。

### 3.3 步行（免费）

- 沿**道路边**行走，边分两类：**集群内边**（枢纽 ↔ 附属；附属之间按纵深链）与**镇间边**（枢纽 ↔ 相邻枢纽）。
- 免费、**无金币门槛**；**金币不足时始终保留步行返程**。
- 步行是**首次探索**的路径；车夫是**到访后的付费捷径**。

### 3.4 费用

- 按**目的地类型**定价（避免 N×N 矩阵膨胀）：`carterFare = { spoke: 低价, hub: 高价 }`，可对单点覆盖。
- **与出发地无关**（同一集群内统一报价）；报价即**整段直达总价**，不另收中转费。
- 教学线 0 金；营地→野外保持 0 金。

> ⚠ **生效范围修订（2026-10-13，D-1-A 拍板）**：上面「按目的地类型统一报价、与出发地无关」**自第二章起生效**（用于新城镇集群，避免 N×N 矩阵膨胀）。**第一章沿用 `08 §4` 的逐对矩阵**（与出发地相关，即本文件 §4 那张表，**数值不变**）。
>
> **解析优先级**：`carterFares[目的地]`（显式对）＞ `carterFare[目的地类型]`（按类型兜底）＞ 报错（由启动校验拦下）。**第一章只配显式对**；第二章起可只配类型价、个别点用显式对覆盖。
>
> 依据：`08 §4` 是开发交接用的执行起点，且本文件 §4 明确要求"第一章数值不变"；类型统一报价无法复现出发地相关的第一章矩阵（见工程文档 19 §4.1 冲突分析）。

### 3.5 与任务辖区解耦 ⚠

- **任务范围不由车夫拓扑推导**，继续使用任务显式 `mapScope`（延续 05 §6 / 08 §10 的警告）。
- 否则"集群"一旦扩大（如第一章 3 张附属），会把 S001/S002 的范围**被动撑大**——这正是 08 遗留的 🔴 风险点。

## 5. 数据模型与校验

`maps.json` 每图新增：

| 字段 | 取值 | 说明 |
|---|---|---|
| `kind` | `"hub"` / `"spoke"` | 枢纽 / 附属 |
| `hubId` | 图 id | 所属枢纽；hub 填自身 |
| `hubLinks` | `[图 id]` | **仅 hub**：相邻枢纽（镇间连线） |
| `carterFare` | `{spoke:int, hub:int}` | **仅 hub**：按目的地类型的报价 |
| `carterFares` | `{图 id:int}` | 可选：单点覆盖价（兼容现有 `carterFees`） |
| `carterFree` | `[图 id]` | 可选：0 金教学线 |

**实现**：`MapService.destinations()` 改为按 §3.2 解析；`carterLinks` 保留为"相邻枢纽"的兼容别名，或迁移为 `hubLinks`。

**启动校验**：`kind` 合法；`hubId` 存在且指向 hub；`hubLinks` **双向配对**且两端都是 hub；每个 hub 至少 1 个 spoke；价格非负整数；教学线必须在同集群内。
