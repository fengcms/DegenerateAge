# 工程开发 AI 交接计划

2026-10-15，产品内容版本 `2026-10-15-content-v1`。本文件描述如何实施已交付的四章产品方案，不代表本轮已经开发。所有数量、ID、坐标、奖励可从制作工具/内容总表.json读取；该文件是设计交换格式，不可原封不动覆盖正式data表。

## 1. 阅读与事实源

先读工作台00、能力决策04与全量审阅92，再读03登记；按第三章00—05做样板。故事看00，人物和对白看01，地形和点位看02与地图JSON，敌方行为看03，任务看04，数值和奖励看05。逐级总表02用于跨章一致性。

正式接入前冻结当前代码/素材快照，检查项目根AGENT.md及当前接口。工作区已有其他AI改动，不能假定本文基线就是最新实现，也不能回退已完成的逐级装备、UI、地图或性能优化。

## 3. 地图与交通转换

设计坐标为正交逻辑格，左上原点，x向右、y向下；JSON中obstacles为不可走实心多边形，边界外不可走。不能把SVG当地图碰撞或直接当等距地面纹理。使用既有CaveLayout/导航/地面图集入口编译同一掩码。

每图routes为产品侧四邻接参考路线，不可当运行时预计算路径永久复用。工程用真实玩家/怪物半径验证窄口、出口、拐角、首领复位和NPC自动接近。动态门禁变更继续更新导航版本，相关路径/地图缓存失效。大型静态地形继续网格合批，禁止逐格新建场景/绘制调用。

沉井镇需要追加到c3_map00的步行出口、目标到达保护区以及相邻hubLinks；设计候选落点[80,27]须与当前沉井镇实际掩码/NPC核查。新图出口已成对列出目标及到达点。返回出口无新增任务锁；正向门禁只在任务rewarded时解除。到达点周围至少12逻辑格不放普通刷新，UI交互不得自动触发重复旅行。

车夫本集群附属图要求已访问且门禁已开，相邻枢纽要求章节已解锁；不跳过主线第一次探索。不从C3枢纽直传C4野外。目的地费用按章节图表报价，免费步行永远可以完成主线。

## 4. 同屏数量、时钟与自动战斗

25图共1544普通刷新位、42精英位、13首领位；单图普通上限10、精英2、首领1是候选预算。普通邻近激活6、接敌3—4，Boss场与普通分离；不是1544只同时运行。单图加载，不给离图怪运行AI。

保留每轮预算统计一次、同轮增退场更新；距离筛选后做连通判断，实际选中目标再构造路线。普通18秒、精英90秒、Boss600秒，统一世界时钟跨图持久，不能切图重置刷Boss。远处静态点不应分配活动计时器或独立UI。

自动战斗优先当前可见可达目标，无目标继续既有巡游；静态图给出四区可循环路线。连续两轮目标为无超8秒的原地等刷新；工程若发现路线空挡，先改刷新区/巡回点而非突破总预算。进入新地图、读档、门禁变化时失效旧目标与路线，不能沿上一张图方向穿墙。

Boss可由玩家手动接管，不强制关闭自动开关。自动巡游点不能落进未主动挑战的首领圈。新首领预警需在怪群、掉落雨和4K设置下仍能辨识。

## 5. 敌方行为与结算

各章03包含13只Boss的形状、尺寸、时刻、系数、阶段与脱战。工程先实现共享Action定义：锁定、预警、命中、后摇、结束；A/B共享动作锁，不叠加整场不可避预警。多格线和扇只对同一目标结算一次；每个多段动作明确段号，不能每物理帧扣血。

这里的沙圈、舟骨、根臂、凝视等都是主题表现，同一底层线/扇/圈逻辑复用。第一版不召唤、不放真实动态阻挡、不做飞行层。未完成技能不静默降成不可读瞬发伤害。精英使用共享低频单招，当前普通近战/远程职责维持既有统一伤害入口。

敌方数值为固定内容候选；不要把“用等级公式生成”实现成“每次按玩家战力缩放”。当前怪物生成等级若只缩放HP，不能让它额外重复缩放已按本包公式生成的模板HP。本包首版每模板用固定表级和固定数值；同图混合早晚模板形成强弱层次，地图推荐级不代表全图每只同级。

## 6. 任务、发奖与保存

只使用kill/collect/talk。野外对话由现场人物发布且talkOnAccept；与导航相遇本身不自动接取。所有任务前置、地图范围、目标/来源、数量、奖励和解锁已有明确记录。

collect是任务计数：指定图指定怪100%给1，够数停止；普通装备掉落独立，不以关键线索替代原装备槽。放弃按该任务清计数，重接重新做，不清其他任务。任务计数与装备库存分离，17种道具不加入商业杂物堆叠表造成背包挤压。

需要补齐/核实：奖励随机实例在首次有效结算计划中生成并持久化，后续失败重试复用同一实例和词条。所有资源与容量验证完再一次提交金币、经验、装备、解锁与rewarded。满包清晰提示且结果不变；不同任务、不同存档槽的发奖计划独立。任务节点未领奖，后续地图和下一个任务不能误开。

NPC全程原地留驻，章末只变对白，不迁走旧章服务。对于全新人物的任务服务和交易兼任，需要现有NPC菜单入口支持多功能，不要为同一角色复制两个重叠实体。

所有新状态/注册内容使用稳定ID；schema版本以实施时SaveManager实际值递增，不照抄历史文档。旧存档默认新任务锁定、地图未访问、新章标记未开；已有C2Q12 rewarded的角色应能看到C3入口。不要重发前章奖励或迁移现有装备数值。

## 7. 成长数值准出

- 使用现有XP曲线、基础成长、品质/星级公式与升星成本。新增四套21/31/41/51基底及真实requiredLevel；不要把Lv30项链当31套或错误使用30作为售价档。
- Lv25破甲、Lv40风暴未接入可施放列表，本包最低输出不依赖它们；不得只为图标亮起就宣称技能已实现。需要开发时单独验证穿透、减防、多段命中、蓝耗、冷却和自动决策。
- 按章末稀有+2、中性词条模型核算，并用章初上一套混穿复测；禁止用全传说+12作为难度证明。金币/药耗和任务XP参考总表02，差异可调整候选敌方经验/伤害，但要记录而非改曲线掩盖。
- 背包筛选、评分箭头、比较、低品质确认、升星预览和售价继续用统一服务。显示等级为实际穿戴要求，星级不抬高等级。

## 8. 具体工程验收矩阵

| 场景 | 预期 |
|---|---|
| C2尾声旧档接C3 | 正确显示相邻枢纽，未访问野外不能车夫跳关 |
| 所有四章主线 | 50节点全部可完成，完全不接支线也能通结局 |
| 提前杀Boss/晚接任务 | 既有刷新计时正确，等刷新可再做，不永久死锁 |
| 主线未领奖就点出口 | 锁定并说明交付人；返回路不锁 |
| 任务物品/装满包 | 任务计数正常，装备发奖失败不扣/不重抽，清空间再领 |
| 普通刷两圈 | 预算不超10、不扫描全图做A*、不原地等超过目标窗口 |
| 大量装备雨/G开关/满包 | 真实奖励保留、认领唯一，表现峰值受控、读档不丢 |
| 新招式多段与死亡 | 单段不重复命中、死亡/切图释放预警/动作状态 |
| 终章首领击杀后退出 | 杀敌目标完成可保存，未交付不标campaign_complete |
| 终章领奖后重复读档 | 结局和奖励只一次，等级/金币/装备不回退，旧地图/支线仍可达 |
| 新章未发布 | 只给线索，不开放空目标或跳入错误地图 |

逻辑回归选择既有隔离运行器与相应装备/任务/地图/导航/掉落测试；新增所需针对性用例由工程编写。本创意阶段没有运行上述游戏测试。

性能测试固定设备、Godot/GL后端、分辨率/设置、角色和同一路线。记录冷加载、热加载、初次巡游、开大地图、全部迷雾探索、满活动预算、Boss技能＋装备雨的帧时间P50/P95/P99与峰值、绘制调用、节点和纹理内存。headless只证明逻辑/CPU，窗口采样才看渲染；每个代表场景至少测三次。

新章样板与最终版本各做一次4小时自动战斗/拾取/探索循环，含跨图、死亡、满包、存读；每10分钟记节点/内存，预热后不能持续单调增长。若有波动，给对象归属与上界，不能只给“未崩溃”。目标60FPS是项目目标，达不到需报告具体瓶颈和产品代价，不假报性能通过。
