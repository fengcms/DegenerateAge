# 双槽装备智能替换、降品质确认与“更强”提示方案

日期：2026-10-14。版本：v1.1，产品执行规格与实现记录。

本方案经用户确认后已进入实现。覆盖装备双击、拖入人物槽位、浮动属性对比和本次游玩的提示偏好。品质与评分是两种判断，需明确区分。

## 1. 当前问题及依据

| 功能 | 当前实现 | 用户反馈对应问题 |
|---|---|---|
| 自动选槽 | Equipment.auto_slot_for优先空槽，否则固定返回同类第一个槽 | 两戒指都满时总换ring_1，不考虑ring_2更差 |
| 穿戴入口 | 背包双击调用GameState.equip_from_inventory，拖拽传入指定slot_id | 两入口都需经过同一替换确认规则 |
| 交换 | Equipment.equip_from_inventory直接在背包格与人物槽之间交换 | 尚无本次降品质确认与临时忽略偏好 |
| 装备浮层 | ItemSlot._make_custom_tooltip展示背包装备及同类已穿戴卡片 | 可复用对比展示，增加评分、默认替换目标和“更强”标识 |
| 旧升级判断 | GameState.is_upgrade_over_worn比较同类已穿戴的最高分；还用于出售界面警示 | 不能直接作为这次双槽比较依据，否则仍漏掉只比弱戒指好的装备 |

依据为当前文件阅读，未运行游戏复现。双击装备目前需人物面板与背包并开，本方案沿用这个入口条件，不隐式修改面板行为。

## 2. 品质、评分与星级的职责

品质顺序固定：普通common < 优秀uncommon < 稀有rare < 史诗epic < 传说legendary。

自动选槽首先遵循用户明确的“换低品质那只”；降品质确认也只看品质高低。评分用于同品质选更弱槽，以及展示“更强”。装备等级、星级和词条通过真实属性影响评分，不另外拿出售价格、图标颜色深浅或名字决定强弱。

采用当前Equipment.score作为首版公共评分来源，不在tooltip另写公式。后续装备三轴模型（创意19）实施后，评分必须跟随统一有效属性结算；当前评分只有部分属性权重，不能承诺它完整覆盖所有流派收益。界面标注“按装备评分比较”。

## 3. 双击智能选槽

适用所有双槽类型：戒指、手镯、护腕、护膝，不能只修戒指。单槽装备继续选择对应唯一槽。

自动目标选择步骤：

1. 获取该类型可用的装备槽，按SLOT_DEFS固定顺序排列。
2. 有空槽时，优先第一个空槽，直接穿入，不替换已穿戴物品。
3. 全满时，先找品质最低的已穿戴装备。
4. 若最低品质相同，再选择评分最低者。
5. 品质和评分均相同，选择固定顺序靠前槽，确保重复查看/操作结果一致。

这一步先确定目标，再判断新物品是否降品质、是否评分更强。不会因候选物品低分就禁止用户穿戴，确认后仍允许主动配装。

| 身上两槽 | 背包候选 | 双击目标 | 结果 |
|---|---|---|---|
| 传说戒指、普通戒指 | 稀有戒指 | 普通那只 | 替换普通，不弹降品质框 |
| 普通戒指、传说戒指 | 稀有戒指 | 普通那只 | 不依赖弱戒指在第几格 |
| 稀有评分120、稀有评分80 | 稀有评分100 | 评分80那只 | 同品质比评分 |
| 传说评分60、史诗评分100 | 稀有评分110 | 史诗那只 | 先品质后评分；候选品质更低，弹确认 |
| 一只传说、一空槽 | 普通戒指 | 空槽 | 保留传说，补空位 |
| 两只评分/品质全同 | 任意同类 | 固定第一个槽 | 结果稳定 |

**拖到哪个槽就请求替换哪个槽。**不在拖拽松手后擅自换成另一个弱槽；目标由用户明确指定，同样接受校验和降品质确认。

## 4. 降品质确认规则

实际目标槽有装备、候选品质严格低于目标品质、本次游玩未关闭此提示时弹框。比较的是实际目标，不是同类最高品质那只。

同品质或更高品质不弹此框，即使评分降低；本轮不额外增加“降评分确认”。空槽不弹。物品类型错误、等级不足、物品已移走等失败先报具体原因，不先询问一个无法完成的操作。

弹框前不交换物品、不变属性、不发equipment_changed、不写成功存档。拖拽松手后的幽灵消失，物品仍在原背包格等待决定。

### 对话框内容

标题：`确认更换低品质装备？`

正文示例：

```text
你准备换上的装备品质低于当前装备。

目标：戒指②
当前：史诗 铜戒指 Lv10 +3    评分：120
换上：稀有 铜戒指 Lv10 +5    评分：135

品质：史诗 → 稀有
评分：120 → 135
品质和评分独立比较，请确认本次配装。

□ 下次不再提示（仅本次游玩，重开或读档后恢复）

[取消]    [确定更换]
```

评分下降时同样显示实际数值，不用绿色“升级”措辞掩盖品质下降。卡片和名字采用对应品质色，但正文必须写明品质名，不能只看颜色。

取消、Esc和右上角关闭均为取消。默认焦点在取消，避免重复输入直接批准。确定后只交换一次，旧装备回到候选腾出的背包格；即使背包满，也不需要额外空格，不把旧装备扔地。

### 弹框期间

建议该确认作为短时模态决策暂停世界战斗与刷新，关闭时恢复弹框前暂停状态，不改变F/G开关。这样玩家阅读选择时不受自动打怪死亡干扰。普通背包/人物面板保持既有可边打边看的规则，不能把所有面板都改成暂停。

需要处理嵌套暂停：用户原本已暂停时，关闭确认不能擅自恢复战斗；死亡/切图/读档有更高状态优先级，不因关闭确认改变它们的状态。

## 5. “下次不再提示”的生命周期

默认未勾选。只有勾选后点击确定，并且实际交换成功，才关闭后续降品质提示；取消、校验失败或请求失效不改变偏好。

该标记是运行态，不写角色存档、settings或设备偏好文件。适用于本次游玩的所有部位和双击/拖拽入口，不只当前戒指。

| 事件 | 标记行为 |
|---|---|
| 关闭面板、切图、死亡/复活 | 保持本次选择 |
| 保存游戏 | 不保存该标记 |
| 成功读档/重新载入当前档 | 恢复为需要提示，取消旧待确认请求 |
| 读档失败 | 保持当前会话偏好，不伪造已重新载入 |
| 新游戏、返回标题后重新进入、重开程序 | 恢复需要提示 |

勾选不是允许跳过所有校验：即使不提示，穿戴门槛、来源实例校验、类型匹配与原子交换仍必须执行。

## 6. 背包浮层中的“更强”

鼠标悬停背包装备时，在背包装备卡上醒目显示“更强”，使用独立文字与向上符号。触发条件为候选评分严格高于**双击默认目标槽内的装备评分**，不是要求高于两只已穿戴装备的最高分。

浮层同时显示候选评分、目标评分、差值和比较目标：例如“更强 ↑　评分100（+20）”“默认替换：戒指②”。同类两张已穿戴卡继续保留，并明确标为戒指①/②，默认目标卡增加“默认替换”标记，不能两张都只写“戒指”。

| 情况 | 展示 |
|---|---|
| 候选评分严格高于默认目标 | 显示“更强”，注明按评分比较 |
| 候选等分或更低 | 不显示“更强”；仍显示评分和差值 |
| 同类有空槽 | 显示“可装备至戒指②”等，不把空槽虚构成已穿戴装备 |
| 等级未满足但评分更高 | 可显示“更强”，并同时醒目标明“需LvX，当前不可穿戴” |
| 非装备、身上装备自身浮层 | 不参与背包升级提示 |

品质降低但评分更高时，“更强”与降品质框可同时成立，必须在浮层写“评分更高，品质低于默认替换装备”。不能把“更强”理解成所有维度绝对更好。

浮层不预言用户将拖入的其他槽。玩家若把物品拖到高品质槽，按该指定槽重新比较并弹确认；双击预览提示不覆盖显式拖拽意图。

装备变动、升星、背包整理或读档后，正在显示的浮层应刷新或关闭重建，不能继续引用旧槽位。浮层在大UI/文字倍率下保持可读，不仅依赖颜色提示。

## 7. 统一请求与过期保护

建议把流程组织成：`读取候选 → 选定目标 → 校验 → 生成替换预览 → 必要时确认 → 复核 → 一次交换 → 更新UI/保存`。

预览信息至少包括候选instanceId、当前背包位置、目标slotId、目标原instanceId、双方品质/评分与会话版本。背包格索引不足以表示物品身份，必须校验实际实例。

确认前后发生整理、移物、升星、角色等级/装备变化时重新计算。候选仍在背包但移动格，可按instanceId定位；物品丢失/转仓库则取消。目标槽换了物品，不得把旧确认用于新目标；关闭原框，提示“装备已变化，请重新操作”。

自动选槽的目标在对话框展示后固定，确认时不悄悄切换到另一槽。勾选关闭提示后也不保存“对这个slot永远允许”的授权；它只是本会话省略弹窗。

所有玩家穿戴入口共用同一请求通道，不能只在背包双击回调里加框而让拖拽绕过。读档恢复穿戴属于恢复状态，不弹玩家换装确认。底层交换保持无UI职责，防止弹框期间先修改数据再回滚。

## 8. 与现有评分及出售规则的边界

现GameState.is_upgrade_over_worn用于商店警示，语义是高于同类最高评分。不能为这次tooltip直接复用，也不能直接改该函数后意外改变一键出售/手拖警示。

推荐增加明确的“装备替换预览”结果给双击、拖拽和浮层共用；出售规则若后续也需要保护“只优于弱槽”的装备，应单独评审并同步。当前批量出售的等级/品质筛选不由本方案擅自改写。

评分本轮沿用当前公式，后续三轴重构时切到统一有效属性。品质顺序、评分权重、星级倍率不要在UI各存一份。品质非法或来源实例缺失先拒绝操作并提示数据问题，不把非法品质当普通悄悄交换。

## 9. 建议落地顺序

1. 提取公共预览：品质排序、空槽优先、最低品质/评分选槽、指定槽比较。
2. 双击与拖拽共用请求通道，加入模态确认、会话标记和过期复核。
3. 浮层增加评分、“更强”、默认目标与槽序号，关联装备变化刷新。
4. 在新游戏/读档/返回标题生命周期重置标记，隔离旧出售辅助逻辑。
5. 同步产品05、09和工程交接，按下表验收；与三轴模型实施顺序协调，但无需等待全套新装备模型才能修复选槽。

## 10. 开发验收矩阵

| 场景 | 预期 |
|---|---|
| 第一只强、第二只弱，候选居中 | 双击换第二只，浮层按第二只比较 |
| 第一只弱、第二只强 | 换第一只，与位置无关 |
| 同品质不同评分 | 选低评分槽；同分固定顺序 |
| 双槽含空位 | 先填空，不弹降品质框 |
| 双击或拖拽低品质装备 | 两入口均有确认；取消不变数据 |
| 拖到高品质槽、另一槽更弱 | 尊重指定槽并弹框，不偷偷改目标 |
| 低品质但高评分 | 可显示“更强/按评分”，仍弹品质确认 |
| 同品质低评分 | 不显示更强，不新增降品质框 |
| 勾选并成功更换 | 本次之后所有部位省略降品质提示 |
| 勾选后取消/失败 | 后续仍提示 |
| 切图或复活 | 省略偏好保留 |
| 重开、成功读档、新游戏 | 恢复提示，旧确认请求作废 |
| 确认中装备或背包变化 | 不替换错误实例，重新操作 |
| 背包满时正常换装 | 原位交换，不丢旧装、不要求额外空格 |
| 未达到穿戴等级 | 明确提示原因，不先确认再失败 |
| 关闭确认/恢复暂停 | 恢复原暂停与自动开关状态，不能擅自开战 |

## 11. 实现记录（2026-10-14）

- `Equipment.auto_slot_for / replacement_preview`：公共选槽与替换预览，品质顺序取自 `ItemUtil.QUALITIES`，评分沿用 `Equipment.score`。
- `GameState.equip_from_inventory / confirm_equipment_change`：双击和拖放共用入口，确认期间不交换，按实例 ID 重新定位候选，并检查候选与目标完整快照；失效请求取消且不设置免提示偏好。满背包仍使用原位交换。
- `EquipmentConfirmation`：主场景 UI 最上层的模态确认，支持取消、关闭、Esc；暂时暂停世界，保留先前暂停状态并照顾死亡、菜单、加载状态。
- 会话偏好只放在 GameState 运行态；新游戏/返回标题的重置与成功读档均清零，切图只取消待确认请求，不清除偏好。
- `ItemSlot / equipment_comparison_tooltip.gd`：显示双方评分、默认目标、“更强 ↑”和等级警示；装备、背包、升星及设置变化时重建浮层，按可用宽度排列卡片。
- 产品文档 05、09 已同步。本轮没有实施创意 19 的装备三轴重构，出售比较仍使用原有独立规则。

检查情况：Godot 编辑器导入并打开 Main 场景，未报告脚本或场景加载错误；完成静态流程检查。尚未执行自动化测试或交互试玩，上方验收矩阵留作后续试玩清单。
