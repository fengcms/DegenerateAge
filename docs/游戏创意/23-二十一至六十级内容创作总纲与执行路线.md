# 21—60 级内容创作总纲与执行路线

日期：2026-10-15。版本：v1.0，用户已确认并授权完成；G1—G8设计成果已交付，入口见[内容工作台](21-60级内容规划/00-工作台与进度.md)。

本文是第三至第六章创意工作的总纲、范围约定和持续执行入口。覆盖用户所说的“30、40、50、60 相关内容”，按 **21—30、31—40、41—50、51—60 级四个完整区间**规划。以下保留确认时的执行规格，当前成果和限制以工作台及审阅92为准。

产品侧负责故事、人物、地图布局、遭遇、任务、装备与奖励设计，以及工程和美术交接文档。本阶段不开发游戏、不修改正式配置、不制作最终运行素材。设计图与结构化配置草案属于交付范围。

## 1. 最终要交付什么

最终成果应让接手的工程 AI 与美术 AI 能逐章实施，并能追溯每个 NPC、地图、任务、敌人和奖励的设计依据。玩家从第二章尾声进入第三章，一直走到 Lv60 主线结局，故事、路线与成长连续。

完成标准不是“四篇章节故事”：

1. 四章有共同的世界真相和因果链，每章也有可以独立收束的生活危机。
2. 每张地图有明确用途、尺寸、连通方式、地标、障碍、怪群和服务位置，产品侧提供布局示意。
3. 每个任务能定位到具体 NPC、地图、怪物/交互目标、前置和奖励，能检查是否死锁。
4. 每个等级有明确的装备部位节点，整段成长能解释经验、金币、升星与战斗压力。
5. 每种精英和 Boss 有可辨识的外观、战斗职责、可读预警与掉落定位。
6. 每个设计注明“可复用、需核实、需新增”能力；新机制有不阻断故事的简化方案。
7. 有总目录、内容登记表、决策记录、进度表和收尾检查，换上下文后能够继续。

### 2.2 整个项目持续遵守的设计边界

- 世界观延续灵气衰竭、过度开采、屏障损坏与异族入侵，不另起一套与前两章无关的灾难起源。
- 线性主线、一个正式结局；支线丰富人物和探索，不用多结局分支扩大生产量。
- 故事主要通过任务文本、NPC 对话、地标和战斗结果表现；不依赖长过场、配音、经营系统或复杂护送 AI 才能成立。
- 装备每十级一套十种名称，五品质，仅升星至十二星。任务、首领不增加同档同部位专名型号，不新增升品、改装、宝石、洗练或套装奖励。
- 武器一尾级、鞋子二尾级，后续按创意 22 的顺序逐级开放。双槽同类共享穿戴要求。
- 大地图须有实际可走的横向空间、绕行与循环刷怪路线。服务 NPC 集中，跑图长度不能取代内容密度。
- 小怪追求持续接战，精英提供多件收获，Boss 有明显的装备雨与好品质追求。真实奖励不因视觉节流丢失。
- 剧情关键道具与推进条件有确定获得路径，不依赖低概率装备掉落；自动打怪不会自动提交关键剧情选择。
- 终章故事中的“回注灵能”不清空等级、装备、金币或星级，不重置玩家成长成果。

## 3. 四章共同的故事骨架

### 3.1 主线方向

**第二章留下账簿 → 第三章找出被隐瞒的警报 → 第四章找到回流方法 → 第五章夺回实施方法的通道 → 第六章修复屏障并击败侵入核心。**

| 区间／章节 | 本章要解决的现实问题 | 核心调查与人物冲突 | 章末答案与下一步 | 区域／终章 Boss 候选 |
|---|---|---|---|---|
| Lv21—30／三：无雨之城 | 恢复居民能用的水路 | 输灵指标压过了停采警报；维护秩序的人、藏起记录的人和等水的人各有诉求 | 证实旧守护计划存在，取得林海观测站的去向；把账簿从指控变成证据 | 干涸水城、高架渠、封闭档案区／空壳总督 |
| Lv31—40／四：逆流林海 | 打通被根系吞没的联络线路 | 守护者记录证明回流可行，但前代实施失败；幸存者害怕重演 | 得到回流步骤及失败原因；说明需要夺回边境通道和核心控制权 | 根海、废弃驿路、观测站／缠根守门者 |
| Lv41—50／五：紫潮边境 | 救出关隘与撤离线上的居民 | 异族统帅控制裂隙通道；承认异界也在衰竭，同时明确其主动入侵的责任 | 夺得进入镇脉核心的机会与必要凭据；第三、四章的证据转化为行动 | 失陷关隘、破碎前线、裂隙桥头／执灯者 |
| Lv51—60／六：最后的镇脉台 | 让最后一次修复有机会完成 | 主角能力、旧守护体和汲灵系统的关系完整揭示；清除侵入核心，完成回流 | 屏障修复、主线正式完结；展示前五章救下的生活如何延续 | 镇脉前哨、旧核心设施、屏障内环／空天之眼 |

这些名称和揭示顺序是本纲领的候选主张，确认后作为细化工作的共同基础。各章完整故事、配角姓名、主支线与地图名在后续交付，不在本轮伪装成定稿。

### 3.2 必须提前设计的跨章线索

建立“埋下—误解—证据—回收”登记：至少覆盖旧刻纹、跨城指标、守护体不参与采收、前代回流失败、主角吸收灵能、裂隙统帅的目的六条线索。

每条记录首次出现、谁知道、玩家何时知道、何处证实、最终回收位置。第三章的人不能无依据说出第四章才发现的事实；终章也不能临时加入此前毫无线索的万能装置。

每章先写“居民今天需要什么”，再写“世界真相揭示什么”。四章分别以水、联络、撤离、屏障为生活目标，避免连续四次“收零件—开机器—打机器”。

口径说明：

- 具名 NPC 计章内出场名额，跨章复用人物会重复计入；41 不等于必须制作 41 个全新角色。正式登记另列去重人数、功能兼任与模型复用。
- 敌人模板不等于新骨骼或新动画套数，33 种普通怪不要求 33 套完全独立动画；必须分别统计配置模板、外形家族与运行素材。
- 支线表中按任务节点计数，后续须注明哪几项组成同一条连续故事，不能把六个节点又扩成六条多节点链。
- Boss 数量指独立遭遇设计，刷新位数量、召唤物、阶段实体另列，不借多个阶段暗增首领数量。
- 25 张图是四章总量，并非同时加载。最终主机室允许布置在一张完整地图内，不为每个小房间另建一张图。
- 第五章多一图、一首领与两主线节点，用来承载撤离线和前线突破；其余章节通过空间与任务组织区分，不能换皮复制六图模板。

首轮不写死总游玩小时数。先建立当前经验曲线与代表配装基准，再给每章主线、探索、支线、必要刷怪的时间预算，标明目标与实测之别。

## 5. 每个专业方向的交付深度

### 5.1 故事与 NPC

每章交付：完整梗概、分幕因果、场景顺序、关键对白、尾声、下一章连接，以及至少一条生活支线和一条真相补充支线。

每名 NPC 记录稳定草案 ID、姓名/称谓、地图与位置、功能、动机、掌握的信息、人物关系、任务职责、剧情前后对白、外观要点、离开/死亡/移动影响。车夫、药品交易、装备交易、升星、仓库、任务服务明确归属；同一人可兼任，避免只有对白没有功能入口的空城。

不能让必需商店 NPC 因剧情离场永久失联。需要角色转移时列出前置、目的地与功能替补。

### 5.2 地图与出行

每图有：逻辑格尺寸、约 16:9 的横向可走范围、视觉风格、可通行区域、障碍、主路、回路、侧路、Boss 场地、出入口、到达保护区、NPC 点、刷新分区、任务点、车夫落点、门禁与捷径。

以已有野外 176×99 至 240×135 格为尺寸参考，安全枢纽参考 96×54；逐图根据通行时间与内容密度选尺寸。大于既有上限的地图需另写理由与代价，不能每升一章就按比例放大。尺寸为设计候选，尚不代表性能通过。

为全部 25 图提供由产品侧生成的标注示意、纯布局参考及结构化坐标说明。用户无需画图。图面表达正交逻辑布局，等距渲染、64×32 地面瓦片和最终美术视觉由交接规格约束，不混用坐标。

地图连接须有双向出口/落点配对；任务解锁状态与地图门禁一致。先证明主线可走，再安排可选旁支；关键功能点不能藏在首次到达必死的敌群里。

### 5.3 普通怪、精英、Boss 与刷怪密度

每怪记录：生态与故事用途、等级范围、外观轮廓、行为职责、有效攻击方式、属性目标、技能/预警、弱点、产出池和刷新归属。普通、精英、Boss 必须同时从轮廓、名称/血条、行为和掉落体验区分。

每张战斗图单列四种数字：**刷新位总数、同时存活上限、邻近可激活量、预期一波接敌量**，并说明刷新周期、巡回路线与连续接战目标。用户希望怪多，不应把数百个刷新位直接当数百只同时战斗。

Boss 每只交付遭遇卡：场地坐标、进入/退出方式、主线或可选、阶段、招式时间与范围、预警、躲避窗口、重试路径、自动战斗应对边界、首通与复刷奖励、不可达/脱战复位。难度来源优先可读组合，不依靠全屏不可躲攻击或强制关闭自动战斗。

现有预算和机制不能直接承诺支持所有设计。对新行为列出简化版本，例如先用明确的范围预警与攻击节奏，不让召唤、追踪弹或复杂多层导航成为故事上线的唯一前置。

### 5.4 任务与对白

每个任务有可供工程配置的卡片，至少包含：

`ID、名称、主/支线、推荐等级、发布人、交付人、前置、解锁标记、目标类型、目标 ID/数量、地图范围、接取/进行/完成文本、追踪文本、奖励、重复性、异常恢复、所依赖能力。`

交谈、击杀、收集、调查、机关交互须对照当前任务服务核实；不能把旧文档的“尚未实现”原样复制，也不能将新目标类型写完就算工程已有支持。目标/奖励数量精确到任务，金币和经验需有统一推导依据。

主线不可放弃，默认一次性领奖；可选首领不作为隐藏主线前置。支线放弃、重接、背包满、已杀首领、目标物品已持有等情况写清，关键道具不靠稀有掉率。

### 5.6 终章及通关后

第六章需要明确：最终首领击杀与交任务的区别、正式结局触发点、NPC/地图状态、玩家可以回去哪里、剩余支线如何完成，以及保存/重载后的状态。

主线结束后可以继续既有地图与成长；首通故事不重复播放。首领复刷要说明现有刷新机制与叙事如何共存。61 级以上无限成长仅定义兼容边界，不在本项目内扩展第七章、赛季、刷层或新的终局系统。

## 9. 最终一致性与完成标准

| 检查面 | 必须通过的检查 |
|---|---|
| 故事 | 每章目标/行动/结果闭环；重要揭示有前置证据；前两章线索和六章结局一致 |
| 等级 | 21—60 全四十级有记录；装备部位按固定尾数，不误成整套同级或按玩家等级随机 |
| 地图 | 二十五图均有规格和布局；主路连通、出口配对、到达安全、免费步行可完成主线 |
| 交通 | 车夫属于本集群与相邻枢纽；任务范围显式定义，不被车夫直达范围误扩张 |
| NPC | 发布与交付人存在且可达；功能服务有归属；迁移/离场不导致任务或交易永久中断 |
| 遭遇 | 模板、刷新点、存活上限、实际接敌量口径清楚；首领外观/行为/奖励可辨 |
| 任务 | 无循环前置、无可选任务卡主线、无必需稀有随机门槛；奖励唯一，失败/满包可恢复 |
| 数值 | 经验与首通目标等级有预算；收入与药品/车费/升星支出可解释；代表配装不过度依赖传说高星 |
| 内容引用 | ID 唯一，NPC/地图/怪物/道具/解锁引用完整；文字、表格、布局与数量汇总一致 |
| 能力与成本 | 新机制均有能力状态、工程需求、简化路径；活动量、刷新/更新频率、内存与释放责任可交接 |
| 美术 | 图标/角色/动画/地图/特效区分源稿与运行资源；复用关系、尺寸、锚点、方向、时序和版本明确 |
| 结局 | 主线完结与继续游玩兼容；不会因故事回注扣掉等级和装备；存读不重复发结局奖励 |

“设计完成”指文档内部一致、能被工程和美术执行，不表示新增地图已跑通、数值已平衡或性能已达标。最终交付须分别列出：已完成设计、需工程验证、需试玩校准、待用户决定；必要内容仍写“以后再定”时不能宣称全量设计完成。

正式工程测试与性能验收由开发阶段在隔离环境执行；本创意项目提供具体场景和验收要求，不使用玩家真实存档。本轮没有运行游戏测试。
