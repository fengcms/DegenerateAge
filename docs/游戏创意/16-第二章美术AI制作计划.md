## 1. 美术目标与参考

《枯井仍在呼吸》采用现有“复古像素、等距末法幻想”风格，以旧铜、铆钉铁、砖石、布革、输灵刻纹和少量紫色寄生物表达被过度使用的采灵工业。保留东方器物语言，不做现代工厂照片、赛博城市或泛欧洲蒸汽朋克。

先读素材设计01—03，结合创意11故事、12尺寸、13六图示意。工程计划15给出接口依赖。现有第一章角色、地砖、UI和品质框可作风格参照；不要重做全套UI或替换其他AI已在制作的怪物动画。

总体递进：沉井镇暖灰和炉火 → 断管坡灰褐与铜管 → 横向双井冷灰铜绿 → 工坊暗灰与稀疏炉光 → 炉房暖橙与黑渣 → 井心冷紫和人造封印。危险预警始终最高对比，不能被环境紫光/炉火淹没。

新版参考已去掉黑菱形外框，以横向16:9地图本体为主要画面。正式地图不绘入红出口圆点、浅色路线或标签，也不能自行恢复旧菱形展示框。正交图只用于布局；最终地面与道具按2:1等距表现。不能把正交16:9当作屏幕最终轮廓比例，不横向拉伸人物、瓦片或已完成资产。旧井横向双井通过井壁与桥影表达高度感，不额外要求工程开发跨层通行。

### 地图资源预算

首轮共6套地面族：每族4个基础随机变体、至少4个道路/边缘过渡，作为制作预算；工程选择的拼接方式确定后补齐必要内角/外角，不把8张当作完整通用自动地形集。

另做3组可复用障碍族：岩壁/洞口、砖墙/门框、管道/设备；每族按直段、转角、端头、缺口、内外角拆分。模块数以样板对接清单为准，不能简单拉伸单块造成像素密度不一致。

装饰优先复用：箱、煤袋、工具、残板、工牌、灯、阀门、断管和补丁布。按“挡路物”“不挡路装饰”“前景遮挡”标注类型，工程决定实际碰撞；美术说明建议占地，不改导航。

### 镇状态变体

危机：主炉仍有蒸汽但主管漏气，汤棚冷清；备用炉点燃：备用炉暖光、药房/汤棚供暖恢复；主机停转：主管不再异常闪烁、纪念册和工牌台出现。复用底图，只提供差分装饰/动画，不做三张不能对齐的镇地图。

## 4. NPC与场景人物

9个故事人物：陆衡（工程装、手套、图纸）、白芷（药围裙、药包）、许铸（护目/铁匠围裙）、米仓（钥匙与账册）、老辙（沿用车夫辨识）、阿絮（货袋与布卷）、祁言（笔册/工牌盒）、苗苗（汤勺和小围裙）、石岑（维修工具、补丁护具）。

每人必需：世界待机、简短交互动作、头像；首版常驻NPC无需批量制作八向走路。老辙可复用既有车夫，新增衣物/道具变体须保留识别。四个无姓名驿站车夫可共用一个基础变体，不按每张地图重做角色。

祁言的纪念册、苗苗汤棚、许铸备用炉工具单独作为场景物，便于随章节状态更换。角色不需要把整个建筑画进待机图集。

## 5. 物品、装备与特效

装备共27模板：20制式/改装基础模板（10类各2）、4固定任务奖、3Boss传说。全部需要48×48透明UI图标，前期背包尺寸沿素材设计01；世界地面图按32×32独立输出。普通模板的随机品质框由UI叠加，不为五品质各画一套同物品。

四固定奖：巡检护甲、备用炉之刃、隔热学徒护腕、炉渣护盾。三传说：监工的铁臂、炉心护盾、归流长刃。固定奖可在基础图标上增加真实结构细节，传说必须有独特轮廓，不能只有紫边。

任务物至少区分调压片、旧工牌（主线与支线可复用图、数据ID分开）、耐热组件；安全锁与账簿有剧情展示图，但是否实体进背包由工程任务结构决定，不能先按道具槽数量假设。

驮炉兽坐骑为后批可选制作项：收藏图标优先，世界骑乘表现是否实现需工程确认；不把现有纯速度加成误当作已具备骑乘组合动画。

必需新增特效族：喷渣弹/命中、侍虫连接、冲锋扬尘、机械落锤、炉渣爆点、汲灵波、核心熄灭、备用炉点燃。复用现有品质光柱、装备雨、通用受击和UI提示，避免重复制作。

危险范围由工程绘制/控制，美术提供纹样和动画层；预警不得先在贴图中扩大成实际伤害范围，不能在光效结束回调再次扣血。

## 6. 技术交付契约

沿用素材设计01的世界尺度与主光：64×32地砖、左上光、独立脚底阴影、透明RGBA PNG、sRGB、清楚像素簇。普通12—20实色、Boss可到32色是风格起点，不用平滑缩放掩盖不一致。

| 资源 | 起始画布/脚底锚点 | 说明 |
|---|---|---|
| 人形/NPC | 64×80 / (32,64) | 有效主体40—48高 |
| 普通虫/兽 | 80×80 / (40,64) | 游魂用64×80 /(32,64)；越界需统一扩帧 |
| 精英 | 112×112 / (56,88) | 按真实轮廓调整，不能逐帧裁剪 |
| 铁臂、吞噬者 | 192×192 / (96,152) | 先做单帧进游戏确认体量 |
| 主机 | 主体建议256×256，锚点先由装配清单确定 | 机械臂分层，不强塞人形脚底 |
| 图标/地面物 | 48×48 / 32×32 | 按已有图标与地面规范 |

正式动画建议按状态分图集：方向行序s/sw/w/nw/n/ne/e/se；idle4帧@6FPS、walk8@10、attack6@12、hit2@10、death6@8。NPC首批只做idle/interact；非对称机械臂不得任意镜像。

这些是素材规范建议，当前SampleActorArt读取方式与之不同。**A0与工程E0先确认读取契约再批量生成**：manifest必须记录方向位于行或列、帧数、帧尺寸、透明留白、脚底锚点、循环、FPS、攻击姿势和接触帧。建议工程适配正式元数据；若采用过渡格式，清单写清转换流程和受影响资产。

伤害在工程逻辑结算，动作FPS仅为预览节奏。交付攻击接触帧供对齐，不要求工程把既有攻击次数改成动画次数。

## 8. 交付目录与资源清单

建议本工作流源文件/概念图：`art_source/chapter2/`；元数据、提示词、预览和审核记录：`docs/素材设计/制作记录/第二章/`。正式资产沿用项目目录：`assets/tiles/<map_id>/`、`assets/sprites/monsters/<monster_id>/`、`assets/sprites/npcs/<npc_id>/`、`assets/sprites/equip/`、`assets/sprites/items/`、`assets/sprites/fx/<effect_id>/`。

新增目录在实际制作时创建；本计划不要求提前建立空目录。路径先和工程清单一致，禁止临时把源图堆进其他AI的第一章动画目录。

每批manifest至少包含：asset_id、data_id、类型、版本、源文件、导出路径、尺寸、锚点、方向/帧序、动画状态/FPS、建议占地、是否遮挡、生成/授权依据、预览、审核状态、工程接入状态。可复用资源引用原路径，不复制多个内容相同但名字不同的文件。

图像生成时保存提示词和所用参考；实际生产遵守可用图像工具与资源来源规则，不猜测授权。Godot.import/.uid交给工程导入流程，不手写。共享工作区提交只包含本批明确资产与记录，不提交游戏代码或其他AI修改。

## 10. 审核与工程对接

先在100%地图倍率检查主体大小、接地和像素密度，再看80%与150%显示、不同UI倍率和高分辨率窗口。密集怪群场景检查角色轮廓和危险提示，不只看大图单体漂亮。

地图建筑不会把原通路堵死；可走地面、障碍和前景层可独立调整。Boss每阶段有可辨状态，动作不越界裁切；退出战斗/死亡后特效无残留。物品图标在实际48格内辨识，不靠放大截图验收。

每批交给工程：新增/替换清单、ID、版本、预览、已知问题、要求工程适配的项目。工程反馈缺锚点、帧序或路径时修正对应项，不重做整章。正式完成需区分“已制作”“已审核”“已接入”，不能仅有图片就写已可玩。

本计划覆盖完整章资产。音频、长过场、主角新职业、全套UI换肤不在本批默认范围，若后续需要再单独立项。

## 11. 本轮布局修订的返工边界

六图旧近方形/竖向概念图停止用于摆放，采用原目录中已更新的landscape-v2参考。已完成的角色、地砖、图标和模块仍可复用，按新坐标重新摆放；只重做不适配新布局的整图构图、独占地标组合与过渡块。不得通过把旧整图横向拉伸来获得16:9，这会破坏像素密度和等距瓦片。
