# 第一章四图美术补全与游戏接入计划

日期：2026-10-14。执行状态：**四图素材、运行接入与定向验收已完成**；实机截图、测试结果和已知基线问题见 [v2 验收记录](../素材设计/制作记录/第一章/v2-验收记录.md)。适用地图：`camp`、`wild_trial`、`ash_land`、`corruption_source`。布局基线为 `2026-10-14-landscape-v2`。

## 1. 现状判断与边界

第一章四图的运行尺寸、出入口、关键点、刷新数据和可通行掩码已经切到横向布局：营地 64×36，野外 176×99，灰烬 192×108，源头 160×90。数据入口是 `data/maps.json` 与 `data/layouts/<map_id>.json`，规划依据是 [统一规格17](17-两章横向16比9地图统一规格与交接.md)及四张 `第一章地图重设计示意图/*-布局参考.json`。本批以**美术补全和正确接入**为目标，不重做已升级的地图几何、剧情、怪物预算、车夫价格或战斗规则。

目前运行地面每图只有 4 张 64×32 地砖，`scripts/world/ground.gd` 用合批网格铺设；道路仍由“地图中间三行”的旧规则决定，无法表现新版商路、环路、长街和洞室。营地只有营火与木箱装饰，位置沿用旧样板；野外和灰烬各 4 张 80×80 小地标、固定 8 个旧坐标，覆盖不了新图，也不跟新版布局的障碍与道路对应。源头已有 4 张洞穴地砖和程序绘制的墙面；因为地图已有 `layoutPath`，旧 `cave_props.gd` 的条件分支不再加载，正式场景缺少计划中的封印、门、洞室及 Boss 区地标。现有大部分地标是纯装饰，不能据其外观推断阻挡。

仓库中另有其他工作正在改装备、任务与掉落数据。本批只改第一章地图、美术、接入和对应测试文件；每个阶段单独提交，只暂存本批文件，不混入其他工作区改动。

## 2. 视觉与数据契约

- 延续现有复古像素等距末法幻想：64×32 的 2:1 地面、屏幕左上主光、清楚的像素簇、低对比地面与清晰角色剪影。营地暖土与火光、野外灰绿土黄、灰烬炭灰与少量余烬、源头冷灰紫逐图递进。复用已合格的地砖、角色、怪物、UI 与特效，不拉伸，也不把示意图文字画进素材。
- **地面、路面、边缘、过渡、小草、小石、碎屑**按 1×1 瓦片或单格装饰处理。道路贴片应覆盖直路、转弯、交叉、边缘和破损变化，按新版布局参考的路线摆放；不再以固定中间三行代替实际道路。
- **房屋、棚、岩坡、岩脊、断墙、岩堆、大树、祭台和大型设施**作为独立多格实体。一个实例在摆放数据中只有一条记录：稳定 `instance_id`、`asset_id`、`map_id`、布局版本、格坐标、占地宽高、底部中心锚点、视觉层及遮挡策略。非矩形外观仍标矩形占地范围，另记实际阻挡轮廓；长墙/岩脊可由一个实体持有多个视觉段，不拆成独立的 1×1 占地记录。
- 阻挡实体使用**与现有 `walkable_rows` 一致的整体碰撞轮廓**：每个大型实体对应一个合并轮廓，不为其每格再造一个独立碰撞。凹形/不规则轮廓须选用引擎可用的多边形实现并实测，不能用粗略矩形堵路；现有地面阻挡碰撞在实体覆盖范围内去重，未实体化的天然边界保留原有方案。装饰性遮挡不改变导航；如确需改掩码，连同寻路、碰撞、出生/刷新/出口验证一起改，不能只改贴图。
- 大型物件图片与逻辑占地分开：透明画布的宽高不自动等于占地格数。角色按脚底深度排序；屋顶、树冠、洞壁前景在挡住玩家、掉落或危险预警时做前后层拆分或局部淡化。所有地图都在 80%、100%、150% 地图缩放与大视口下检查边缘、接缝和可读性。
- 每图维护资源清单和实例摆放文件；清单记录源稿、运行图、尺寸、锚点、授权/生成方式、资源用途和审核状态。摆放文件以运行布局版本为键；一个实体一条记录，避免代码内固定坐标与新版布局再次漂移。地图碰撞、导航和视觉摆放需通过自动校验保持一致。

## 4. 一次执行的阶段与提交点

确认本计划后按下列顺序连续完成全章，中途遇到普通素材取舍自行按本契约决策，不停在样板图或素材候选阶段。

1. **基线与映射**：固定当前提交、四图布局版本、出口、NPC/任务点、掩码和性能基线；生成“布局障碍 ↔ 美术实体”对照表，检查现有自动测试的旧坐标假设。交付基线记录，单独提交。
2. **野外完整样板**：先完成地面道路、北坡/岩脊、多格障碍和重点地标；在真实地图中接入，验证锚点、道路净宽、前后遮挡、导航/碰撞一致性和密集接敌。这里形成四图共用的地面选择、实体摆放与资源清单约定。样板通过后单独提交。
3. **灰烬和源头**：按同一契约完成两图的地面、转接、阻挡外观、地标和摆放；源头重点核对封印与 Boss 战场。两图分别验证、分别提交。
4. **营地与跨图统一**：补齐服务街、建筑/灯/训练区和出入口引导，检查 NPC/车夫交互及第二章连接处；统一四图色阶、道路边界、远景密度与提示可读性。单独提交。
5. **整章收尾**：清单和生成源稿可追溯，删除未使用的运行依赖，更新第一章场景文档；完成隔离测试、原生窗口逐图验收、性能对照和旧档检查。修正发现的问题后提交最终整合及测试记录。仅提交本批改动，不夹带装备、任务、掉落等并行工作。

## 5. 工程接入和测试门槛

- 沿用 `IsoGround` 当前 64×32 纹理图集与网格合批，扩展其**按布局数据选地砖**的能力；不把每个地面格改成独立节点。增加可追溯的实体摆放加载入口，按需复用纹理和碰撞形状。静态素材在载图时准备，移动中不重建全图底图。
- 对四图每个大型实体自动校验：实例 ID 唯一、占地在地图内、锚点与导出图对应、阻挡区与掩码一致、不能盖住入口/出口/NPC/木桩/怪物刷新位和 Boss 预警区。检测视觉落点不合法、透明边与地砖接缝。道路与可行走区保持一致，但不把全部可走格都绘成道路。
- 更新旧的 `MapTextureBatchTest` 道路选择断言，新增真正验证**新版路线与布局匹配**、实体单记录/单合并碰撞、无重复阻挡、角色转角净宽的测试。保留并运行 `ChapterOneArtTest`、`ChapterOneAcceptance`、`CaveLayoutTest`、`CaveNavigationTest`、`MapCanvasCacheTest`、`MapLoadingCacheTest`、`MapTextureBatchTest`、`MapPerformanceTest`、`SmokeTest` 等适用回归；旧测试的过期坐标要按新版事实更新，但不得删除行为断言来制造通过。
- 用隔离存档走新档四图主线和旧档恢复；实际测试步行往返、车夫、入口防抖、自动寻路/自动战斗、怪群与 Boss、掉落拾取、读档后的玩家与迷雾位置。资源接入不应改变掉率、费用、怪物数量、任务奖励或 Boss 结算。
- 在真实窗口按固定设备、分辨率、缩放与路线，记录四图的载入时间、帧时间中位/P95/P99、绘制调用、节点数与纹理内存；对比改动前基线。大视口、已探索地图、满刷新预算和持续自动战斗/拾取都要实测。以稳定 60 FPS 为目标；任何明显退化先定位并修复，不能靠删碰撞或降低玩法频率过关。Headless 只证明逻辑，不冒充 GPU 验收。

## 6. 完成判定

四张图均在游戏内显示本批正式素材，而不只存在于 `docs/` 或样板场景；地面、道路、阻挡、大型地标与关键点符合新版布局；所有大型物件有明确多格实体记录和与导航一致的合并碰撞，纯装饰不会误导通行；跨图、新旧档、四图战斗与性能回归通过，并提供四图原生截图、资源清单、测试结果、性能对照和各阶段提交号。未通过的事项明示为未完成，继续修复后再交付。
