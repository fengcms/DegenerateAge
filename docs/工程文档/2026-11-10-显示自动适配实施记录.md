# 显示自动适配实施记录

按已确认的《启动窗口最大化与显示自动适配方案》分节点实施；所有回归使用隔离项目和 user://，不修改真实玩家设置与存档。

## 节点一：偏好来源与旧值保护

- 本机显示偏好升级为 v2，在原七项值之外记录三轴来源、窗口策略和显式自定义尺寸；来源不进入角色存档校验。
- 旧值包括 100% 均按 legacy 保留，缺失轴自动；最近旧角色的显示配置先标记来源再保存，保持迁移优先级。
- 设置变更透传字段，改变音量不会标记显示自定义；界面、地图、文字均有恢复自动入口。
- 对损坏 JSON 保留诊断副本，未来版本拒绝降级覆盖；写入临时文件、检查错误并原子替换，失败向玩家提示。
- `DisplayPreferencesTest`、`SettingsTest`、`NanGuardTest` 通过。新测试覆盖旧值/类型/来源、跨角色、临时文件无法写入、损坏备份及未来版本保护；现有设置断言未放宽。

## 节点二：启动窗口

- 新增 DisplayEnvironment，只在进程首次启动或主动修改窗口选项时执行窗口策略；普通 apply_all 不再改窗口。
- 默认最大化当前显示器工作区，异步校验外框；异常时扣除原生装饰后夹紧。固定/自定义窗口同样居中并夹紧，负坐标显示器可用。
- 无头与 --wid 编辑器嵌入跳过原生窗口操作。新增“使用当前窗口尺寸”，拖动仅本次会话有效。
- `WindowStartupTest`、`SettingsTest`、`MenuFlowTest` 无头回归通过；`WindowStartupTest` 实际 macOS 窗口通过，验证最大化外框占满工作区、改音量与重复初始化不改窗口、自定义尺寸恢复及固定尺寸优先。
- 多显示器负坐标、嵌入参数属于合成测试，未将其描述成多屏/编辑器实机验证。

## 节点三：三轴自动推荐

- 缓存当前屏幕参数，每 0.75 秒检查跨屏/系统缩放/工作区变化；同屏拖动不参与倍率签名，不写配置、不重建世界。
- 已校准 macOS + HiDPI + disabled + 内容系数 1 路径使用系统密度推荐，档位上限 200%；未知后端保持 100%，不把 4K 标签直接等同于 200%。
- 新手动轴直接采用百分比；legacy 保持原值乘高级系数（含旧 300% 组合）；自动轴不受高级系数影响。保留文字/UI、世界文字/地图及弹窗原有补偿。
- 设置页显示各轴生效值、来源与当前启动策略；旧全局设置改称“高级统一系数”，解释其对逐轴来源的影响。
- 新增 `DisplayScalingTest`，覆盖合成 2K/100%、4K/100/150/200%、未知平台、无效密度、跨屏、手动 100%、无重复相乘和自动值不落盘。
- 上述测试及 DisplayPreferencesTest、SettingsTest、NanGuardTest、MenuBackgroundTest、BossStatusPresentationTest 通过。SettingsTest 仅同步已改变的卡片/选项文案，并以显式字段变更模拟高级系数操作，原倍率和布局断言保留。
- 连续运行发现 JSON 版本数字读回为浮点时 Array.has 类型严格导致第二次保存被误拒绝，已改为数值相等判断并补重复保存测试。

## 节点四：实际窗口与完整回归

### 生命周期与窗口边界补强

- 旧角色迁移结束、Main 装配完成后，首次建立缺失的 v2 本机文档。写入的是 auto 来源和保留原值，不是屏幕推荐快照；避免新角色下次启动时被旧槽迁移误标为 legacy。
- 新增首次建立、再次启动、重复启动不改文档的断言；MenuFlowTest 保留显示偏好文件并验证新建、继续、返回菜单、读取不会改掉来源。
- 全屏切换保留先前自定义窗口尺寸；显式选择其他窗口档位才清除自定义尺寸。窗口化后等待原生装饰更新再夹紧，异步请求带序号，过期请求不覆盖新选择。
- 记住窗口的保存失败不再同时显示成功提示；设置关闭圆钮保留文字 Tooltip，支持可识别的实际输入测试。

### 实机检查方法

新增永久回归 `DisplayAcceptanceTest`，列入只能 `--rendered` 运行的场景集合：装配正式 Main，检查主菜单随机背景、设置页有效倍率、经过视口输入路由点击关闭按钮、背包、三 Boss 状态条、四位等级和 150% 手动 UI / 自动文字组合。截图只输出到显式指定的临时目录，不打包进游戏。

真实窗口测试在本机 Godot 4.7.2 / macOS / GL Compatibility 上执行；独立 WindowStartupTest 验证外框占满工作区、普通设置更新不改窗口、自定义尺寸保存恢复、全屏进入退出和固定窗口。macOS 全屏动画须等待完成后取值。

性能场景采用百首禁域真实刷新器的 18 席混合 Boss，集中到玩家附近，保留完整 HUD 与技能预警；测试角色固定且无敌。先预热，再采样固定 1280×800 / 三轴 100%，以及工作区最大化 / 自动三轴 200%；后者连续三段，各 6 秒。检查实际渲染次数、角色存活及世界未暂停。该场景不是持续击杀、拾取或长期自动探索测试。

### 最终独立性能采样

初轮发现窗口被遮挡时 macOS 会停绘，且等待 frame_post_draw 可能悬挂，因此未采纳这些样本。最终测试在采样阶段关闭自动渲染循环，每个 process_frame 调用一次 force_draw(false)，断言“采样帧数 = 实际绘制帧数”，避免停绘假快和重复绘制。此方式用于稳定对照 CPU 主循环与绘制提交开销，没有交换原生缓冲，不代表包含系统合成/VSync 的最终呈现 FPS；正式游戏不更改渲染循环。[Godot RenderingServer 文档](https://docs.godotengine.org/en/stable/classes/class_renderingserver.html#class-renderingserver-property-render-loop-enabled)

本机 Apple M1 Max；隔离运行器上限 120 帧/秒，最终采样期间没有并行运行其他 Godot 测试。

最大化纹理内存增加约 99.84 MiB，符合大尺寸渲染表面的额外成本；短时静态内存和特效节点在小范围内波动，没有持续增长趋势。绘制调用是不同技能阶段的时点值，不能据此宣称最大化减少绘制或提升性能。新 DisplayAcceptanceTest 全部断言通过；SettingsTest、MenuFlowTest、WindowStartupTest 也通过真实窗口执行。

### 复现与范围

```sh
python3 -B -u tools/run_isolated_tests.py --all
python3 -B -u tools/run_isolated_tests.py --rendered DisplayAcceptanceTest WindowStartupTest SettingsTest MenuFlowTest
```

需要人工复核截图时，先创建临时目录，再设置 `DA_DISPLAY_CAPTURE_DIR`。临时截图已查看并清理，正式目录只保留回归脚本与记录。

实际硬件验证仅覆盖当前 macOS 单屏，不能宣称已经实测 Windows/Linux、另一块 2K/4K 显示器、热拔插、编辑器嵌入或导出安装包。未知平台当前自动推荐保守为 100%；这些场景的算法边界由合成输入覆盖。未做数小时挂机泄漏或长期自动探索验收。

旧版本已保存的显示倍率会继续保留，包括 100%。希望改用屏幕推荐时，在设置“画面”中点击某项“恢复自动”，或“三项全部使用自动推荐”；全屏、固定窗口及明确记住的窗口尺寸保持优先。
