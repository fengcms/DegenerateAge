## 0. 一句话结论

全校非 UI 的 `draw_circle / draw_arc` 共 **55 次调用**，归并后 **20 个视觉元素在画地面**（占 39 次调用），**全部应改为椭圆**；
已有 **5 处**用了正确的 `draw_set_transform(..., Vector2(1, 0.5))`（脚下阴影），说明问题不是不会写，而是**从没沉淀成公共原语**。

这 20 个元素里 **10 个直接参与伤害判定**（Boss 预警四形态、跺地、扫击、连爆），另外 **10 个纯表现**。
纯表现可以立刻改；**判定类必须先定口径**——只改画不改判定，会把「不好看」升级成「明明在圈外却被劈」，属于公平性倒退。

另外还有 **5 个同根因的问题**（地面菱形画成 1:1、环击内圈用深色实心「挖洞」会在实机上留一块黑斑等），
其中 **D-1 / D-2 比椭圆本身更该先修**——那是「画错了」，不只是「画得不协调」。

## 1. 根因

### 1.1 投影本身是 2:1 压扁的

`scripts/systems/iso.gd`：

```
screenX = (col − row) × 32      # HALF_W = TILE_W/2 = 32
screenY = −(col + row) × 16     # HALF_H = TILE_H/2 = 16
```

即「地面上的 1 个单位长度」在屏幕上：横向占 1，纵向只占 **0.5**。
于是**地面上的正圆 → 屏幕上必须是 2:1 的椭圆**（长轴横向、短轴纵向，比例恰好 `HALF_H / HALF_W = 0.5`）。

这个比例是**严格可推导的**，不是美术手感：

| 地面形状 | 屏幕投影 |
|---|---|
| 1 格菱形 | 宽 64、高 32（现成瓦片） |
| 地面正方形（格对齐） | 宽 2k、高 k 的菱形 |
| 地面正圆（半径 r） | 宽 2r、高 r 的椭圆 |

摄像机只做等比 `zoom`（`settings_runtime.gd::apply_map_scale_to`，`Vector2.ONE * 倍率`），不会引入新的各向异性 ⇒ 0.5 是唯一正确的压扁比。

### 1.2 直接调用的是屏幕空间 API

`draw_circle` / `draw_arc` 的坐标系就是屏幕（画布）坐标系。直接调用 = 画一个「正对镜头的圆盘」，
在等距地面上看起来就是一张竖起来的圆片。**不协调感的来源就是这里，不是颜色或线宽。**

### 1.3 没有公共原语，于是每个文件各写各的

现状是三种写法并存：

| 写法 | 出现处 | 是否正确 |
|---|---|---|
| `draw_set_transform(zero, 0, Vector2(1, 0.5))` + `draw_circle` | `npc.gd:121`、`ground_item.gd:391` | ✅ 正确 |
| 同上但比例写 **0.45** | `monster.gd:1104`、`player.gd:758` | ⚠ 差 10%，与瓦片对不齐 |
| 手写 `sin(a) * 0.5` | `ground_item.gd:467`（传说底座星形） | ✅ 正确但不可复用 |
| 直接 `draw_circle` | 其余 20 个元素（§2.1 全部） | ❌ 平坦 |

`Iso` 里只有 `grid_to_world / tile_points / depth`，**没有任何「地面圆 / 地面扇 / 地面带」工具**——这是根因。

### 2.4 D 类：同根因下的其他问题（比椭圆更该先修）

**D-1 地面菱形画成了 1:1 的旋转正方形** 🔴
`monster.gd:1201-1202` `_draw_ground_mark()` 四顶点 `(0,-r)(r,0)(0,r)(-r,0)` → 屏幕上是**对角线相等**的菱形。
等距地面上的正方形投影必须是 **2:1**（高 = 宽的一半）。现在这块「地面标识」看起来像一块斜立的方形牌，不是贴地的。

**D-2 环击内圈用深色实心「挖洞」，实机是一块黑斑** 🔴
`boss_action.gd:297` `canvas.draw_circle(inner, Color(0.06,0.04,0.05,0.9))`。
Canvas 绘制无法「挖洞」，这行等于在预警环中心糊上一块 90% 不透明的近黑色圆盘。
暗色地图上看不出来，**营地和第一章亮地面上会非常明显**。B 招触发时玩家会看到「地上凭空多一个黑洞」。
正确做法：**环带切片**——把环拆成 N 个凸四边形（内圈点 `i`、内圈点 `i+1`、外圈点 `i+1`、外圈点 `i`），逐片填充。
不要用「外圈正向 + 内圈逆向拼成一个多边形」的写法：那是自交多边形，Godot 的三角化结果不保证正确，容易出破洞。

**D-3 圈的圆心与阴影圆心不重合**
`ground_item.gd` 阴影在 `y=8`，persistent 圈在 `y=8`（✅），高亮圈在 `y=4`（❌ 差 4px）；
`npc.gd` 阴影在 `y=8`，高亮圈在 `y=0`（❌ 差 8px）。
压扁成椭圆后，横向不变、纵向只有一半，「差 4px」会变成视觉上明显的错位。

**D-4 阴影比例 0.45 / 0.5 不统一**
`monster.gd:1104`、`player.gd:758` 用 0.45，`npc.gd:121`、`ground_item.gd:391` 用 0.5。
同一屏上角色和 NPC 的阴影压扁比不同，属于「说不清但看着别扭」的那一类。

**D-5 敌方弹道没有地面投影**
`monster_projectile.gd` 只画空中球体，没有脚下椭圆阴影，读不出高度。属于可选打磨项，不建议本轮做（会引入「影子先于本体到达」的新观感问题，需要单独评估）。

## 3. 投影口径定标

落地前先把三个常量钉死，避免又出现 0.45：

| 常量 | 值 | 位置 | 说明 |
|---|---|---|---|
| `Iso.GROUND_SQUASH` | `HALF_H / HALF_W` = **0.5** | `iso.gd` | 地面纵向压缩比，唯一来源 |
| 阴影半径比 | 1.0（不改） | — | 只改纵向比例，不改大小 |
| 椭圆折线段数 | 32（小圈）/ 48（大圈 > 120px） | `GroundFx` | 1px 描边下无可见折角 |

> 为什么不用 0.45：0.45 与 64×32 的地砖对不上，椭圆底边会「浮」在菱形格上方，
> 压得越扁反而越像贴纸。统一到 0.5 后，圆的四个极值点正好落在瓦片边界上。

## 4. 关键选择题：判定要不要跟着改

这是本文唯一需要拍板的地方。三种口径的差别只在**正南 / 正北（屏幕纵向）**方向体现。

### 4.1 三方案对比（以半径 r=128 的跺地圈为例）

| 方案 | 视觉 | 判定 | 纵向可见半径 | 纵向实际命中半径 | 玩家「看着在外面却被打」的最坏超出 | 危险面积 | 平衡影响 |
|---|---|---|---|---|---|---|---|
| **C 现状** | 圆 r=128 | 圆 r=128 | 128 | 128 | 0% | 100% | — |
| **B 只改画** | 椭圆 128×64 | 圆 r=128 | 64 | 128 | **+100%** | 100% | 无（但公平性倒退） |
| **A 画+判定同源** | 椭圆 128×64 | 椭圆 128×64 | 64 | 64 | 0% | **50%** | 纵向难度明显下降 |
| **A′ 同源+等面积补偿** | 椭圆 181×90.5 | 椭圆同上 | 90.5 | 90.5 | 0% | 100% | 面积不变，形状变扁 |

（A′ 的半径 = `r × √2`，横向 1.414r、纵向 0.707r，椭圆面积 = π·r²，与原圆相等。）

### 4.2 推荐：A′（同源 + 等面积补偿）

理由：

1. **底线是「看见就是打到」**。B 方案把最坏偏差从 0 拉到 100%，等于要求玩家凭记忆背判定范围，不能接受。
2. **A 会让所有 Boss 的纵向威胁腰斩**，实测体感是「boss 变弱了」，会污染后续 D-17 经济与战斗不变量（123.7）之外的手感基线。
3. **A′ 面积不变**：击杀次数、承伤期望不受影响，只是「躲的方向换了」——从绕圈变成上下走位。
   而上下走位在等距视角里**视觉位移只有实际距离的一半**，本来就该是主要躲闪方向，这条改动反而顺了操作直觉。
4. A′ 的椭圆仍是标准 2:1，视觉上完全符合等距投影，不会出现「为了补偿而画胖」的怪相。

### 4.3 唯一例外：玩家技能范围提示（#15）

`skill_range_fx` 的半径同时被三处复用：施法门控（`player.gd:574`）、**命中集合筛选**（`player.gd:616/629`）、提示绘制（`player.gd:586`）。三者现在都是屏幕度量，彼此一致。

若只把提示压扁成椭圆，会出现「怪站在椭圆外却被技能打到」。但这和 Boss 预警的方向**正好相反**：

| 谁 | 画小了的后果 | 该不该容忍 |
|---|---|---|
| Boss 预警 | 玩家**挨打** | ❌ 不能容忍，必须同源 |
| 玩家技能提示 | 玩家**多打到**（看起来打不到，其实打到了） | ✅ 可容忍，属于"保守提示" |

结论：**FX 椭圆化、三处度量都不改**，在注释里写明「提示范围刻意小于实际命中范围，宁画小不画大」。
另外 `skill_range_fx` 只存在 0.3 秒，属瞬时提示，玩家不会拿它当尺子量。

### 4.4 明确不动的东西

- 玩家 / 怪物的移动、寻路、拾取距离（`ground_item.PICKUP_RANGE_PX`）、普攻距离 —— **全部保持屏幕度量**。
  改成地面度量等于重做整个移动手感，且会连带影响 `AutoBattle` 评分与 `PaceTest` 不变量。
- 自动战斗的技能评分 `skill_value = coefficient × hits` 与几何无关，不动。

## 5. 优化方案

### 5.1 第一步：`Iso` 增加地面原语（几何唯一来源）

```gdscript
# scripts/systems/iso.gd 追加
const GROUND_SQUASH := HALF_H / HALF_W          # 0.5，地面纵向压缩比（唯一来源）

## 屏幕坐标 -> 地面坐标（y 反向放大，使地面圆在地面坐标里是正圆）
static func to_ground(p: Vector2) -> Vector2:
    return Vector2(p.x, p.y / GROUND_SQUASH)

## 地面坐标 -> 屏幕坐标
static func from_ground(p: Vector2) -> Vector2:
    return Vector2(p.x, p.y * GROUND_SQUASH)

## 地面正圆 -> 屏幕椭圆点集（闭合，末点不重复首点）
static func ground_ellipse(center: Vector2, radius: float, segments: int = 32) -> PackedVector2Array

## 地面圆弧（用于扇 / 环的描边），角度按地面坐标定义
static func ground_arc(center: Vector2, radius: float, from_angle: float, to_angle: float,
        segments: int = 24) -> PackedVector2Array

## 地面圆是否包含某点（椭圆判定；与绘制同源）
static func ground_contains(center: Vector2, radius: float, p: Vector2) -> bool

## 地面环带是否包含某点
static func ground_ring_contains(center: Vector2, inner: float, outer: float, p: Vector2) -> bool

## 地面距离（用于线宽 / 扇角判定）
static func ground_distance(a: Vector2, b: Vector2) -> float

## 地面正方形（2:1 菱形）四点，替代 1:1 手写菱形
static func ground_diamond(center: Vector2, half_width: float) -> PackedVector2Array
```

### 5.2 第二步：`GroundFx` 绘制门面（杜绝各写各的）

```gdscript
# scripts/systems/ground_fx.gd（新文件，静态方法，不挂节点）
class_name GroundFx
extends RefCounted

## 地面圆填充：内部用 set_transform 压扁，代价最低
static func fill(canvas: CanvasItem, center: Vector2, radius: float, color: Color) -> void:
    canvas.draw_set_transform(center, 0.0, Vector2(1.0, Iso.GROUND_SQUASH))
    canvas.draw_circle(Vector2.ZERO, radius, color)
    canvas.draw_set_transform(Vector2.ZERO)

## 地面圆描边：用折线保证**线宽各向同性**（set_transform 会把 2px 描边压成 1px）
static func outline(canvas: CanvasItem, center: Vector2, radius: float, color: Color,
        width: float = 2.0, segments: int = 32) -> void

## 地面环带（带洞）：拆成 N 个凸四边形逐片填充，**不要**拼自交多边形
static func band(canvas: CanvasItem, center: Vector2, inner: float, outer: float,
        color: Color, segments: int = 48) -> void

## 地面扇形（中心 + 弧点，按地面角度）
static func sector(canvas: CanvasItem, center: Vector2, dir: Vector2, radius: float,
        arc_rad: float, color: Color) -> void

## 地面矩形带（用于 line 预警：四点在地面坐标构造再投影）
static func band_quad(canvas: CanvasItem, from: Vector2, to: Vector2, half_width: float,
        color: Color) -> void
```

> 为什么填充用 `set_transform`、描边用折线：`draw_arc` 的 `width` 是屏幕像素，
> 经过 `Vector2(1, 0.5)` 变换后会变成「横向 2px、纵向 1px」的粗细不均边线；
> 大圈（半径 > 100px）肉眼可辨。折线走 `draw_polyline(..., width, antialiased)` 则始终均匀。

### 5.3 第三步：判定同源改造

`BossAction` 增加「地面空间几何」，让 `hits()` 与 `draw()` 吃同一份数据：

```gdscript
## 地面空间几何（y 放大 2 倍）。hits() 与 draw() 只认这一份。
func geometry_ground() -> Dictionary:
    if stage != Stage.TELEGRAPH: return {}
    var tc := float(Iso.TILE_W)
    if move == Move.B:
        return {"kind": "ring", "center": Iso.to_ground(_origin),
                "inner": float(phase_b.get("inner", 2.0)) * tc * COMPENSATE,
                "radius": float(phase_b.get("radius", 5.0)) * tc * COMPENSATE}
    ...
```

`COMPENSATE := sqrt(2.0)`（§4.2 的等面积补偿，集中在一个常量里，方便回退成 1.0）。
`hits(point)` 改为先 `Iso.to_ground(point)`，再在平面坐标里用普通 `distance / 角度 / 点到线段` 计算；
`draw()` 改为 `Iso.from_ground(每个点)` 后落笔。

`monster.gd` 的 4 种章 Boss 预警同理：把 `_special_warn == "sweep"` 的 `135` / 章 Boss 的 `170/88/66/340/96`
从「绘制魔法数」收敛到一个 `_warn_geometry()` 返回字典，绘制与 `_resolve_chapter_boss_warn()` 共用。

## 6. 🔴 风险

- 🔴 **P2 是玩法口径变更，不是美术修复**。`radius` 的语义从「屏幕半径」变成「地面半径」，
  所有 JSON 里的 `radius / inner / length / width` 数值含义都会变。必须在 `boss_action.gd` 头注释与
  `data/monsters` 相关注释里写清，否则下一个改数值的人会按屏幕半径去调。
- 🔴 **`tests/boss_action_test.gd` 会红，且红在哪取决于选 A 还是 A′**。逐条核对过（配置取自 `data/monsters` 的 c3_boss01/02/03）：

| 断言 | 内容 | A（同源不补偿） | A′（√2 补偿） |
|---|---|---|---|
| `:77-78` | 双线带内 `(100,-160)` / 通道 `ORIGIN` | 绿（带在斜向，纵向压扁不影响） | 绿 |
| `:83-84` | 第二段右线 | 绿 | 绿 |
| `:98-99` | 首圈**圆心**命中 / `(0,256)` 圈外 | 绿（圆心与远点，与度量无关） | 绿 |
| `:122` | 扇半径 `== 384.0` | 绿 | 🔴 变 `543.0` |
| `:140-141` | 环内 `==128.0` / 外 `==320.0` | 绿 | 🔴 变 `181 / 452` |
| `:142` | 环带内 `(0,192)` | 🔴 384 > 320，翻成**不命中** | 绿（384 < 452） |
| `:143-144` | 圆心安全 / `(0,384)` 圈外 | 绿 | 绿 |

  即：**A 只红 1 条命中断言，A′ 只红 3 条数值断言**——两者都不需要重写整个测试，成本可控。
  但「红在哪」必须提前写进方案，否则实施时容易误判成「改坏了」。
- ⚠ `tests/chapter_three/four/five_combat_test.gd` 的 `_point_inside()` 取的是圆心 / 中点，**与口径无关，应保持绿**；
  若这批红了，说明几何容器本身被改坏了，不是断言问题。
- ⚠ `warnings_as_errors` 开着：新写的辅助函数里 `var x := <Variant>` 会**编译失败**，一律显式标注类型。
- ⚠ `Iso` 是 `class_name` 静态工具，**不要在里面引用 `GameState` / `SettingsRuntime`**（`--check-only` 下 autoload 不可见）。
- ⚠ `_draw()` 里禁止 `instantiate / get_tree / 查组`；椭圆点集每帧重建是可行的（几十个点），
  但大圈（Boss 环击 320px）建议缓存 `PackedVector2Array`，半径不变就不重建。
- ⚠ 世界文字锚点依赖半径：`monster.gd:1096` 的跺地文案在 `center + Vector2(-50, -_stomp_radius - 8)`，
  压扁后圈顶抬到 `-radius × 0.5`，文案会**飘在圈上方 60px**，必须改成 `-_stomp_radius * Iso.GROUND_SQUASH - 8`。
- ⚠ D-2 改法会改变 B 招的视觉重心（从「黑盘 + 亮环」变成「空心亮环」），实机要确认可读性没有下降。
- ⚠ 不要顺手把 UI 的圆改椭圆 —— 「统一」的边界是**世界空间的地面**，不是整个游戏。

## 8. 验收方式

**能自动化验证的只有几何，不是像素。** 所以把几何从 `_draw()` 里抽出来（R1 / R7 / R8），然后按项目的四层流程跑：

1. `--import`
2. `python3 tools/run_isolated_tests.py`（当前 47 项，本轮不新增场景，只在 `dynamic_equip_test` 之外的既有场景里加用例函数，或在 `boss_action_test` 内加）
3. `SettingsTest`
4. `--quit`（「配置校验通过 ✅」+ 0 SCRIPT ERROR）

新增断言（举例）：

- `Iso.ground_ellipse(c, 100, 32)` 的 32 个点，`max(|x−cx|) / max(|y−cy|) ≈ 2.0`（±0.01）
- `Iso.ground_contains(c, 100, c + Vector2(99, 0))` 为真，`c + Vector2(0, 99)` 为**假**
- `Iso.to_ground(p).distance_to(Iso.to_ground(q)) == 2 × |py − qy|`（纯纵向）
- `BossAction.hits()` 与 `geometry_ground()` 自洽：对每种形态取「圆心 / 带中线中点 / 扇心」必中，
  取几何外 1px 必不中（**两个方向都断言，防「恒真」假绿**）

负向验证（每条都必须「有牙」且与真 bug 同形）：

| 编号 | 注入的错误 | 期望 |
|---|---|---|
| N-1 | `GROUND_SQUASH` 改回 1.0 | 椭圆比例断言红（≥4 条） |
| N-2 | 只改 `draw()` 不改 `hits()`（B 方案） | 「可见范围外 1px 必不中」红 |
| N-3 | `band()` 内外圈半径写反（inner / outer 对调） | 环带包含断言红：圆心必不在环带内 |
| N-4 | `ground_contains` 用屏幕欧氏距离（漏 `to_ground`） | 纯纵向包含断言红（这一条是「假绿」高风险点，必须做） |

实机复验清单（无法自动化的部分）：

- 营地亮地面：史诗掉落的双圈底座、NPC 高亮圈、打坐圈是否为贴地椭圆
- `c7_arena`：Boss 环击是否还有黑斑、环形是否与地面齐平
- `c3` 沙圈三连：站在椭圆正上方边缘外 1px 是否确实不受伤
- 一只精英怪的「地面菱形标识」是否为 2:1
