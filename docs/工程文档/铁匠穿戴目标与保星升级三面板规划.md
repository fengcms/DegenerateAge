# 铁匠穿戴目标与保星升级三面板规划

## 现状与范围

- 装备重铸的 `scripts/ui/reforge_panel.gd:369` 和装备升星的 `scripts/ui/upgrade_panel.gd:170` 都先遍历穿戴槽，再扫描背包追加目标。两个下拉菜单出现背包装备来自这段显式枚举。当前实现为静态代码核对，尚未进行窗口测量。
- 装备重铸的精炼材料及两项服务的如意仍由背包提供。穿戴限制适用于被操作的主装备。保星升级是独立的换装流程，继续支持穿戴旧装备与背包新装备，沿用成功后自动穿戴逻辑。
- `scripts/ui/equipment_fusion_panel.gd:137` 广播通用合成模式，`scripts/ui/inventory_panel.gd:143` 据此打开背包。人物面板已有并开许可（`autoload/game_state.gd:2267`），缺少保星升级入口的主动打开动作。

## 节点一　限定重铸和升星的主装备来源

沿现有槽位顺序列出穿戴目标，保留现有装备资格和失败说明。同步收紧确认入口，提交前校验穿戴槽与实例 ID。换下或替换已选目标时清除选中及依赖它的预览，要求重新选定。无穿戴目标时禁用提交并提示先穿戴装备。检查背包直达、拖入及结算调用方，确保各入口应用同一规则；更新依赖旧背包目标的测试夹具。候选列表由穿戴变更驱动，背包变化继续刷新相关材料状态。

复核混合背包和穿戴、空穿戴、同槽换件、过期选择以及正常扣费和材料消耗。拒绝请求时核对金币和材料数量。

## 节点二　保星升级联动三面板

在保星升级服务入口通过现有窗口打开接口联动人物面板，复用背包自动打开和并开规则。城镇与随身铁匠共用路径。已打开窗口直接复用，布局完成后统一安排人物、工作台和背包，优先保证装备拖入区域和确认按钮可见。宽屏验证三窗并排，空间不足时按可用视口重排，并保留源装备与对应目标格之间的拖拽路径。独立关闭和焦点沿用窗口管理规则。

在普通窗口、小窗口和高 UI 缩放下核对窗口边界和拖拽命中。覆盖从全关闭或部分已打开状态进入、重复开关、自动拾取后保留合法选择、穿戴旧装备升级成功后自动穿戴。回归其他铁匠菜单的打开行为。两个节点分别验收并提交。
