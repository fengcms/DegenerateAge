# 90 - 重铸面板显示装备评分：需求分析与实施方案（待确认）

> 状态：**分析已完成，等你拍板，未动一行代码。**
> 提出：2026-10-22。用户原话：「装备重铸界面，应该要显示当前选择的装备的评分是多少，便于玩家确认效果。你规划一下。」
> 结论一句话：**缺的不是「一个数字」，是「这个数字变了多少」** —— 只把评分贴上去，玩家仍然不知道自己刚花的 52,500 金买到了什么。

---

## 1. 需求拆解

「便于玩家确认效果」这句里其实有两个不同的诉求，混在一起做容易只做一半：

| # | 诉求 | 玩家心里的问题 | 只做静态数字能不能回答 |
|---|---|---|---|
| A | **选谁** | 「这三件里我该洗哪件？」 | ✅ 能（评分横向可比） |
| B | **值不值** | 「刚洗完这次，是变好还是变差？」 | ❌ **不能** —— 评分是绝对值，玩家长按记忆里的旧数字去比，比不出来 |

现有面板已经用 `p008` / `p015` 打印了「旧词条 → 新词条」的**文本**对比，但词条是四行不同属性的文字，
「攻击 +12 换成防御 +9」到底划不划算，靠读文字判断不了 —— 这正是评分存在的意义（产品 05 §5.9）。

**所以本方案的主线是 B**：静态评分是顺带的（A），增量对比才是需求的落点。

## 2. 现状证据链

### 2.1 评分已经存在，且已有三处展示

| 位置 | 代码 | 文案 |
|---|---|---|
| 背包 / 仓库 / 商店物品卡 | `scripts/ui/item_slot.gd:575` | `ui.equip_tip.score` = `评分：%.1f` |
| 人物面板已穿戴槽 | `scripts/ui/character_panel.gd:306` | 同上（工程 78 Q3 对齐口径） |
| 换装提示「属性更高」 | `autoload/game_state.gd:1885` `is_upgrade_over_worn()` | 不展示数字，只用比较 |

**重铸面板一处都没有**（`scripts/ui/reforge_panel.gd` 全文 615 行，无 `Equipment.score` 调用）。

### 2.2 面板的现有结构

```
标题行（×）
说明 _hint              p001
选择装备 _picker         OptionButton（穿戴 + 背包全部装备）
当前词条 _affix_title    p003  ← 下面接 N 行「词条 + 锁」
锁说明 _lock_hint        p011
精炼材料 _refine_head / _refine_row（4 格）/ _refine_hint
费用 _price              p014 / p006
重铸按钮 _button          p004 / p017
反馈 _feedback           p008 / p009 / p015
```

`_refresh_details()` 是唯一刷新入口，被 `_on_selected` / `_on_items_changed` / `_on_gold_changed` /
`_on_lock_toggled` / `_on_reforge` 后的 `_refresh_choices()` 反复调用 —— **这一点决定了增量基准不能写在它里面**（见 R4）。

### 2.3 探针实测：面板已经顶到边了（关键）

临时探针（已删除，不入库）在 macOS 上实量：

```
viewport = 1422 × 800
box      = 570 × 623      content 自然高 = 581
一件传说项链的 score = 166.4
content_scroll = <null>   ← 面板完全没接 F-P2-3
```

| UI 缩放 | 逻辑视口高 | 面板高 | 结果 |
|---|---|---|---|
| 1.00 | 800 | 623 | 余量 177 |
| 1.25 | 640 | 623 | **余量仅 17** |
| 1.50 | 533 | 623 | **溢出 90（底部按钮出屏）** |
| 2.00 | 400 | 623 | **溢出 223** |

`SettingsRuntime.UI_SCALE_MAX = 2.0`，也就是说**这不是理论风险，是现存的缺陷**：
玩家把 UI 缩放拉到 1.5 以上，重铸面板底部的费用行与「重铸」按钮就在屏幕外，且没有滚动条。

> 这与刚刚修完的铁匠面板同源（08 §7 第 44 条：滚动区写死上限＝把内容预算锁进代码）。
> 现在要往这个面板里**再加东西**，顺手接上 `FloatingWindow.set_content_scroll` 是唯一合理的时机。

### 2.4 一个容易踩的口径问题：破损件

- `Equipment.score()` 走 `EquipmentMath.attrs_for_use()`，**破损件只算基底，词条全部失效**（工程 88）。
- 产品 05 §5.9 / §8 明确「升星 / 重铸 / 保星可正常操作破损件」，`Reforge.can_reforge()` 也**不拦破损件**。
- ⇒ **破损件重铸后，词条真的变了，但评分一个点都不会动。**

如果只贴一个评分，这个场景下玩家看到「评分 631.0 → 631.0」会直接判定「花 5 万金币买了个寂寞」，
而实际上是「修好之后新词条才生效」。这不是理论推导，是三条既有规则叠加出来的必然结果。

## 3. 设计

### 3.1 放在哪：叠在「当前词条」标题行右侧（0 增高）

`_affix_title` 现在是独占一行的 Label。改成 HBox：左「当前词条」，右「评分 166.4」。

理由（不是审美，是实测倒逼）：
- 面板已经 623 / 800，独立一行要 +26px，在 uiScale 1.25 的 17px 余量下**当场顶穿**；
- 语义正确：「这些词条合起来值多少分」，与下面四行词条是同一个块；
- 右对齐不打断原有纵向节奏，视觉上和面板里已有的「标题 + 右侧控件」同构（精炼区就是 `_refine_head` 这么做的）。

### 3.2 怎么表达「变化」

```
评分 166.4（较上次 +22.8）        ← 涨：金色 GOLD_LIGHT
评分 166.4（较上次 -9.3）         ← 跌：警示色 COL_WARN
评分 166.4（与上次持平）           ← 持平：弱化色 MUTED
```

- 基准 = **上一次重铸前的评分**；换装备 / 关闭面板即清零（回到只显示绝对值）。
- 连续重铸 N 次，每次相对上一次 —— 符合「我这次的操作有没有用」的直觉。
- 只在**重铸成功后**写基准。失败（金币不足 / 校验拒绝）不写，否则下次成功时会拿一个很旧的基准去比。

**不做**：预测重铸后的期望值。重铸是随机的，任何「预计评分 +38」都是在承诺做不到的事。

### 3.3 破损件

评分行后面追加一句弱化色提示：`耐久破损：词条不生效，评分只含基底`。
只在 `Durability.is_broken(item)` 为真时出现，且**只占评分行下方一行**（这是唯一允许增高的场合，
因为它只在破损件上出现，不是常驻布局）。

### 3.4 空态

无候选装备（`_choices` 为空）时整行隐藏，不显示「评分 0.0」——
0 分会让玩家以为「这件装备一文不值」，而真实原因是「你还没有装备」。

## 4. 决策点（Q1—Q5，全部给了推荐值）

| # | 问题 | 推荐 | 理由 | 选另一条的代价 |
|---|---|---|---|---|
| **Q1** | 要不要做「较上次 ±N」的增量对比？ | **A：做** | 需求的落点就是 B（见 §1）；只贴绝对值等于回答了半个问题 | 玩家仍然要比记忆，重铸的经济闭环反馈不成立 |
| **Q2** | 评分放哪？ | **A：当前词条标题行右侧** | 0 增高（实测余量 17px 时唯一可行）；语义同块 | B（独立一行）在 uiScale≥1.25 时顶穿；C（下拉项里带）会把 520px 的下拉撑破 |
| **Q3** | 破损件要不要加提示？ | **A：加** | 不加会稳定误导读（§2.4），且误读发生在**唯一**会让评分为 0 增量的场合 | 玩家以为重铸无效，客诉/差评的典型来源 |
| **Q4** | 要不要顺手接 F-P2-3 内容滚动？ | **A：接** | 实测 uiScale≥1.5 已溢出（§2.3），这是现存缺陷；现在不改，下次再加东西就必爆 | 留着这颗雷，且重铸面板成为唯一没接 F-P2-3 的常驻浮窗 |
| **Q5** | 增量基准取哪一刻？ | **A：上一次重铸前** | 与「确认效果」语义一致；连续洗练时天然正确 | B（打开面板那一刻）在连续重铸 3 次后失去意义 |

> Q4 是唯一会扩大改动面的选项（动 `_resize` 的宽度来源）。如果你希望这一批**只做评分**，
> 回 Q4=B，我按「只加评分行」实现，把滚动区另开一批 —— 但**这次加的评分不会顶穿**（0 增高），风险可控。

## 5. 风险

| # | 风险 | 后果 | 对策 |
|---|---|---|---|
| **R1** | 面板自己算一遍评分 | 与 `Equipment.score` 口径分裂（权重改了面板不变），面板显示 166.4、背包浮层显示 172.0 | 只用 `Equipment.score()`，测试直接比对该函数返回值 |
| **R2** | 增量基准写在 `_refresh_details` 里 | 该函数被 `inventory_changed` 等**反复调用**，基准随时被覆盖 ⇒ 永远显示「持平」 | 基准只在 `_on_reforge` 成功分支里写；`_refresh_details` 只读 |
| **R3** | 浮点比较 | `absf(d) < 0.05` 判持平，否则 `+0.0` 抖动 | 统一 `roundf(x*10)/10` 后比较与格式化 |
| **R4** | 无障碍/语言缩放 | 评分行文字随 textScale 放大后 520px 宽放不下，把「当前词条」挤成两行 | 评分 Label `autowrap=OFF` + `SIZE_SHRINK_END`；标题保持 EXPAND_FILL |
| **R5** | 文案 key 撞号 | `localization.json` 重复键**后者静默胜出**（已踩两次） | 加完核对总条数 889→892 + 逐键断言正文 |
| **R6** | 新增 key 带裸 `%` | 带参 `tr_key` 会 `incomplete format`，玩家看到 `%s`，测试照常 PASS（工程 88 铁律） | 新文案只用 `%.1f` / `%s` 作格式符，正文里不出现其他 `%` |
| **R7** | 接 scroll 后重新布局 | `_resize` 用 `_box.get_combined_minimum_size().x` 算并排宽度，包一层 ScrollContainer 会改变最小尺寸来源 | 接完必须实机/测试确认「与背包并排」的 pin 位置不变（`ReforgeSessionTest` 有并开断言） |

## 7. 测试计划

### 7.1 正向（`ReforgeScoreTest`，8 条）

| # | 断言 | 抓什么 |
|---|---|---|
| 1 | 选中装备后评分行可见，文字含 `Equipment.score(item)` 格式化结果 | 行没建 / 数值取自别处 |
| 2 | 换成另一件（评分不同）后数字跟着变 | 只在 `_on_selected` 刷一次就完事 |
| 3 | 重铸成功后出现「较上次」，且增量 == 新 score − 旧 score（**逐字符比对**） | 增量算错 / 符号反了 |
| 4 | 连续重铸两次，第二次的基准是第一次之后的值（不是最初值） | 基准没更新（R2） |
| 5 | 关闭面板再打开，增量消失、只剩绝对值 | 基准跨会话残留 |
| 6 | 破损件：评分 == `Equipment.score(破损件)` 且**严格小于**满耐久时的评分，同时提示行出现 | 评分口径分裂（R1）/ 提示缺失（Q3） |
| 7 | 无候选装备时评分行 `visible == false` | 显示 0.0 |
| 8 | （Q4=A）面板高度 ≤ 逻辑视口高，且滚动条可见性符合预期 | 顶穿（§2.3） |

> 用例 6 必须**双向断**（等于破损件分 **且** 严格小于满耐久分）：
> 只断前者，「把基底砍光」也绿；只断后者，「用满耐久分冒充」也绿。这是工程 88 用例 6 的同型教训。
