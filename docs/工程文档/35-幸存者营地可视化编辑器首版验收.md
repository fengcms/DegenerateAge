# 幸存者营地可视化编辑器首版验收

这是[可视化地图编辑工作流建议](../素材设计/22-可视化地图编辑工作流建议.md)的首个可运行节点。当前项目在 Godot 编辑器内提供「营地地图」主屏幕，直接显示正式营地画面，允许移动既有整体实体和道路节点，并通过显式应用同步重建美术、碰撞及通行。用户操作见[插件说明](../../addons/camp_map_editor/README.md)；[1280×800 实际窗口截图](../素材设计/样板/幸存者营地编辑器/营地编辑器首版.png)展示当前界面。

## 实现边界与数据事实源

开发前的主要风险是位置分散：实体碰撞在 `data/map_art/camp_whitebox_v2.json`，美术矩形曾有部分写死在 `tools/build_camp_style_full_b_v2.py`。现在七个实体的 `art_rect` 和 `art_foot_y` 都存入营地布局源；生成器从这里读取。重新生成后 `assets/maps/camp_style_full_b_v2/manifest.json` 与改造前逐字段一致，现有营地画面和通行没有因编辑器接入而变化。

插件只在 Godot 编辑器加载。画布使用 **1672×941 屏幕矩形坐标**，显示当前 2048×2048 地纹、真透明道路层、整体实体背层与前沿；侧栏列出 7 个实体和 4 段围栏。拖动对象时，编辑模型同步平移其美术矩形、脚底深度、视觉多边形和单个碰撞多边形。道路控制点独立编辑，草稿保存到 `data/map_art/camp_editor_draft.json`，不由游戏读取。地面画笔、增删对象、缩放对象和编辑碰撞顶点尚未开放，避免在这个阶段产生不完整的运行数据。

应用入口 `tools/apply_camp_map_editor.py` 检查正式源 SHA-256，确保没有覆盖其他编辑；仅接受整体平移与原有路点的移动。它沿用白盒构建器的投影与距离几何，先检查 NPC、出入口、出生点、训练场刷新点、车夫落点及四邻连通，再写正式源并运行两套已有生成器。若生成失败，恢复原源文件、`maps.json`、营地通行布局及所有可能改写的运行贴图／清单。成功时删草稿。游戏存档未被编辑器或测试直接读写。

## 本轮验证

- Godot 4.7.2 GL Compatibility 的编辑器无头加载成功，插件完成初始化；`CampMapEditorTest` 在隔离项目内实例化真实面板，验证原样加载、整体美术与碰撞一起平移、道路节点编辑、撤销／重做和带源哈希的草稿保存。真实窗口同一测试通过，并保存上方截图。
- 在临时复制的工程中将铁匠棚平移画布 **(+8,+4)**，通过「应用」完整重建后，运行美术矩形由 `[230,120,310,190]` 变为 `[238,124,310,190]`，通行布局随碰撞重算；正式仓库原文件未变。只改仓库美术矩形、不改碰撞的非法草稿被拒绝且没有改写正式布局。另在临时工程故意移除 ImageMagick 路径，白盒构建后美术构建失败；正式源、`maps.json`、布局和美术清单的 SHA-256 均恢复原值，草稿保留供修复后重试。
- 正式营地 `CampFullArtAcceptanceTest`、`CampLiveIntegrationTest`、`MapTextureBatchTest` 与 `SmokeTest` 通过。未修改营地尺寸、五个 NPC、出入口、当前障碍位置或运行资源引用。编辑插件不在运行场景实例化；只有布局源新增七组位置元数据，运行纹理数量和贴图尺寸不变。本轮未测得、也不宣称游戏帧率提升。

## 后续迭代判据

首版已经能用于调整营地构图，但要让用户用素材库新建整张地图，还需下一节点：为新整体实体定义稳定 ID、脚底与碰撞模板，增加地面和小型装饰笔刷，并提供实际通行遮罩的草稿预览。每新增一种编辑能力，必须先保证「编辑画面 → 导出 → 游戏实走」结果一致，再推广到其他地图。
