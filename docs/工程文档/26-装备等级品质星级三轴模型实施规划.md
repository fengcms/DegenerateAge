# 26 · 装备等级、品质、星级三轴模型实施规划

日期：2026-10-14。状态：执行中。依据：[创意 19](../游戏创意/19-装备等级品质星级三轴模型差距分析与调整建议.md)。用户已明确允许删除历史存档，本轮采用破坏性装备实例升级，不提供旧装备兼容读取。候选平衡数值在节点 0 落定为首版可调参数。

## 结论与边界

**可以实现，无须重做背包、14 个穿戴槽、装备拖放、铁匠交易或装备雨。** 改造重点是把装备型号与穿戴档位、品质、星级分开；所有新装备共用一次生成和一处属性结算。旧装备实例不兼容；测试使用隔离存档，正式玩家档由用户自行删除或新建。仅提高掉率、补一套模板或修改 tooltip，无法解决现有差距。

现有代码已具备五品质、0—12 星和实例 ID，但存在以下实际阻碍：

| 问题 | 目前实现 | 必要改动 |
|---|---|---|
| 等级 | `Loot` 在 `levelRange` 中逐级抽数值；`Equipment.level_req` 读模板门槛，不读实例显示等级 | 明确 Lv1/10/20 穿戴档，实例 `requiredLevel` 同时控制显示、基础和穿戴 |
| 品质 | 除传说外，品质主要影响词条；传说被强制送往独立模板池 | 品质独立决定基础倍率和合法词条数，任何正式型号都能生成五品质 |
| 星级 | `Upgrade.base_attrs` 只放大基础，固定/百分比词条不放大 | 新规则只放大**该件装备**的基础与已抽词条，结算集中在一个入口 |
| 来源 | `Loot._roll_equip` 随机生成，`ItemFactory.make_equip` 为任务/商店直接复制模板 | 掉落只决定来源、型号、档位、品质；共用工厂构造实例 |
| 档位覆盖 | `equipments.json` 只有 Tier1 模板，缺档可回退低档 | 显式补齐正式档位×10 类槽型，缺档报配置错误，不能伪装成高等级装备 |
| 存档 | 当前 schema v10 校验必需 `baseAttrs`，未区分生成规则 | 提高整档 schema，只接受新版实例；旧档明确提示不兼容，不静默改造 |

旧传说专属名称和美术可以保留为型号或外观；其手填高基底不能直接再乘新品质倍率。首轮不新增独特被动、升品、洗练或装备部位。

## 节点 0：先冻结产品口径与数值表

建议采用 **Lv1 新手档，Lv10/20/30…正式档**。怪物等级和装备档位分开：Lv1—9 常规来源提供新手档；Lv10—19 来源提供 Lv10 档；Lv20—29 提供 Lv20 档。章节 Boss、任务可显式提供下一档，但物品必须显示并执行真实穿戴要求。第一章 Boss 若提供 Lv10 装备，玩家未到 Lv10 时允许持有，不允许提前穿戴。不要把第一章全部 `[1,5]`、`[5,9]` 掉落简单取整为 Lv10。由此第二章 Lv11 起的成长主要是 Lv10 装备品质、词条与升星，Lv20 进入下一档；旧的“Lv11 立即换 Tier2”安排需要改写。

品质首版参数如下，试玩后可以按配置调整：

| 品质 | 基础倍率 Q | 随机词条总数 |
|---|---:|---:|
| 普通 | 1.00 | 0 |
| 优秀 | 1.20 | 1 |
| 稀有 | 1.50 | 2 |
| 史诗 | 1.90 | 3 |
| 传说 | 2.40 | 4 |

百分比词条包含在总数内，稀有及以上才可出现，同一件最多一条百分比，同一属性键不重复。首轮只生成现有接通的 `atk/def/hp/mp/hpPercent/mpPercent`；逐型号验证候选池至少能提供该品质所需的互异词条。若某型号不足四条，必须补合法池或调整规则，不能静默少发，也不能用未接通的战斗属性凑数。按部位决定合法池与值域，词条值随档位变化；品质仅决定基底倍率与条数，不再暗含专属强度模板。

首版沿用每星 10% 和最高 12 星；百分比词条概率先沿用稀有/史诗现行 50%，传说也按 50%，每件至多一条。铁匠成功率、金币/如意消耗、失败不降星保持现状。各档×型号白装基底先用现有 Lv1 数值作为起点，Lv10/20 基底做显式配置，再通过样例战斗校准。若实测过强，只调配置，不改三轴职责。

## 新实例契约与统一结算

型号模板保存 `itemId`、名称、槽型、图标、可用档位和合法词条池；档位配置保存 `requiredLevel` 与该型号无品质基底；品质配置保存倍率与词条数量。新实例建议至少保存：

```text
kind, itemId, instanceId, equipmentRuleVersion=2
requiredLevel, level=requiredLevel（过渡期兼容旧读取方）
quality, star, rawBaseAttrs, affixes, pctAttrs, count=1
qualityMultiplierSnapshot, starMultiplierSnapshot
```

`rawBaseAttrs` 是生成当时确定的 0 星、未乘品质的基底；词条也是当时抽定的原值。倍率快照保证日后调整掉率/平衡配置不会悄悄改写玩家已拥有装备。新版不再使用旧 `baseAttrs` 字段，以免重复乘算。`equipmentRuleVersion` 是**物品规则版本**，独立于 SaveManager 的整档 `schemaVersion`。`instanceId` 保持唯一，生成只发生一次；重载、拾取、穿脱、跨图、放仓库均不能重抽。

唯一结算入口（例如 `EquipmentMath.effective_attrs(item)`）返回每件装备的固定和百分比贡献。规则为：

```text
S = 1 + star × starMultiplierSnapshot
固定属性 = S × (rawBaseAttrs × qualityMultiplierSnapshot + 固定词条)
百分比属性 = S × 百分比词条
```

品质只乘基底；星级在最后乘本件装备的全部数值贡献，绝不乘玩家基础属性、其他装备、技能或药水。实例内部保留浮点，装备与角色汇总后按属性统一取整；百分比以现有比例单位累计，再交角色派生公式和上限处理。例：基底攻击 10、固定攻击词条 4、12 星时贡献 `30.8`（每星 10%）；生命 `+5%` 词条成为 `+11%`。tooltip 分项显示原始基底、品质带来的基础增量、词条原值与升星增量，最终合计必须与战斗属性和评分同源。

旧实例不做转换；整档 schema 提升后，旧槽位须明确显示版本不兼容并引导玩家新建存档，不能把坏档判成新游戏或自动覆盖。**不主动删除当前机器上的真实存档文件**，以免误伤其他游玩数据；用户允许直接删除，意味着本批没有向后兼容义务。测试工程内的历史夹具可重建为新实例。

## 存档与交互风险清单

1. `SaveManager` 当前 schema v10 对装备强制要求 `baseAttrs`；新版本仅接受严格的 v2 字段，非法数值和未知规则版本拒读。旧 schema 拒绝时主档/备份不能被新建游戏误覆盖；不用真实槽位跑测试。
2. 装备可能存在背包、已穿戴栏、仓库、商店临时出售托盘、死亡掉装、Boss 未领取物及地图地面物。托盘属于运行时临时容器，应保留同一实例并按现有退回/成交语义处理；持久化容器逐一验证实例 ID、词条和星级没有变化。
3. `ItemUtil.attr_lines`、`Upgrade.base_attrs`、`Equipment.score/bonus`、铁匠预览、背包/仓库/货郎/人物 tooltip 目前各自读取旧字段；不能只改战斗结算而让显示、替换判定或自动卖装读取另一套数字。背包“低于装备等级”筛选读取 `requiredLevel`。
4. 双槽自动选择目前先空位、再最低品质、同品质按评分；这一交互与三轴共存，但评分必须用真实贡献。低品质替换确认和多卡对比也需对新版实例回归。
5. 老传说模板中较高的手填基底、固定词条及独特命名要逐件审表；新型号不能在其上直接叠 2.4 倍。
6. 质量倍率与全词条升星会明显抬高高星装备，尤其百分比属性。上限在角色汇总后生效；需用代表性 Lv1/Lv10/Lv20 套装模拟普通怪、精英、Boss 的击杀时间与承伤，再调数值表。

## 验收矩阵与文档同步

自动化使用隔离项目/存档，至少覆盖：

- 每档每种槽型均可构造五品质；随机词条总数准确、同属性不重复、百分比至多一条；新装备掉落为 0 星且可升到 12 星。
- 同型号同档品质倍率只作用基底；0、1、12 星及固定/百分比词条计算例准确；多件装备汇总后取整，不出现小属性逐件截断。
- 新装显示等级＝基底档＝穿戴要求；等级不足拒穿。Lv1—9 来源不被机械抬为 Lv10；缺档请求可见失败。
- 掉落、任务、商店用同一工厂；Boss 追加传说可覆盖非武器部位，件数/概率独立，重载与重复死亡信号不重复抽奖。
- 新版装备在背包、穿戴、仓库、地面/未领容器中，读档前后属性、外观、门槛、星级、实例 ID 不变；升星只改 `star`。旧 schema 与旧结构明确拒绝。
- 人物属性、tooltip、铁匠预览、双槽比较、低级装备筛选/出售/退回与实际战斗一致；原生窗口复验展示与保存。

节点 0 应同步 `docs/产品文档/04-角色成长系统.md`、`05-装备与背包系统.md`、`10-数据配置与存档技术.md`，并在创意 07、11、15、16 中明确哪些“传说专属池、Lv11 即 Tier2、固定传说模板”段落被新规则替代。保留文档 07 的装备雨件数、追加概率、未领保护。第二章现有“27 模板＝含 3 个传说专属模板”的工作量估算要重算为“型号/档位基底与外观数量”，不要误以为需手工配置每档×五品质×十三星的全部实例。

本轮已采纳 Lv1/10/20 档、上表品质参数和旧存档不兼容口径。数值是首版参数，后续仍可依据试玩调整配置。
