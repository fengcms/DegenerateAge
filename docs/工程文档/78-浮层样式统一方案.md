# 78 · 浮层样式统一方案（原生黑半透明 → 卡片式）

> 状态：**已落地**（2026-10-20，Q1—Q3 全部按建议拍板）｜验证见 §8
> 背景：人物面板装备悬停浮层是「黑色半透明底」的原生样式，用户认为不好看；背包装备浮层（品质描边卡片）是满意样式。
> 本文盘点全项目同类浮层的数量与分布，给出统一改造路径。

---

## 1. 现状：两套浮层体系

Godot 中 tooltip 有两条渲染路径：

| 路径 | 触发条件 | 视觉 | 项目中的分布 |
|---|---|---|---|
| **原生浮层** | `tooltip_text` 非空且 `_make_custom_tooltip()` 返回 null | 引擎默认 `TooltipPanel`：**黑色半透明底**、无描边 | 散落 **48 处**（17 个文件） |
| **自定义浮层** | `_make_custom_tooltip()` 返回 Control | 代码构建卡片：深底 `#111820` + 描边 + 圆角 | 4 个实现（见 1.2） |

### 1.1 满意样式（背包装备浮层）解剖

- 入口 `item_slot.gd` `_make_custom_tooltip()` —— **仅** `role == ROLE_BAG` 且 `kind == "equip"` 时生效，产出 `equipment_comparison_tooltip.gd` 多卡片网格；
- 单卡 `_equipment_tip_card()` 规格：底 `#111820`（不透明）、**品质色 1px 描边**、内边距 10、标题行 `#9baebc`、明细用品质色、字号 `16 × 文字倍率`、`AUTOWRAP_OFF`；
- 附带对比栏（背包候选 + 各穿戴槽）与事件实时刷新（`equipment_comparison_tooltip.gd` 挂 EventBus）。

### 1.2 已是好样式的（本次不动）

| 位置 | 实现 | 壳样式 |
|---|---|---|
| 背包装备悬停 | `item_slot` 对比多卡 | 品质描边卡片 ✅ |
| 4 个面板问号帮助 | `panel_help_button.gd` | 深底 `#111820` + 灰边 `#74818a` + 圆角 5 ✅ |
| 血条 / 蓝条 | `hud_status_bar.gd` | 同上 ✅ |
| 经验条 | `hud_experience_bar.gd` | 同上 ✅ |

### 1.3 根因（两条，缺一不可）

1. **人物面板装备浮层是黑半透明的直接原因**：`ItemSlot._make_custom_tooltip` 第一行门卫
   `if role != ROLE_BAG or kind != "equip": return null`。
   人物面板的 `EquipmentSlot`（role = `ROLE_EQUIP`）被这行挡掉 ⇒ 回退原生浮层。
   **同一件装备**在背包悬停是品质卡片、在人物面板悬停是黑半透明纯文本 —— 差异全在这一行门卫。
2. **其余 40+ 处按钮/状态提示**：只写 `tooltip_text`、从未自定义；项目主题 `assets/themes/default_theme.tres`
   只定义了默认字体（M4-10 等宽字体），**没有覆盖 `TooltipPanel` / `TooltipLabel`** ⇒ 全部落到引擎默认「黑半透明」。

## 3. 改造方案（两阶段）

### 阶段 1 · 全局换壳 —— 一次覆盖 48 处

给原生浮层套上与 `panel_help_button` 同款壳：
**底 `#111820`（不透明）+ 描边 `#74818a` 1px + 圆角 5 + 内边距 10/8 + 文字 `#e1e7ee`**。

实现方式对比：

| 方案 | 做法 | 评价 |
|---|---|---|
| A1 改 `default_theme.tres` | 在主题资源加 `TooltipPanel` / `TooltipLabel` 样式项 | 生效早；但 `.tres` 手改格式敏感，且与文字倍率设置脱节 |
| **A2 代码设置（建议）** | 在 `SettingsRuntime._apply_text_scale()` 同路新增样式设置 | 该函数**已有**给 `TooltipLabel` 设字号的先例与注释（「原生悬浮提示不在 UI CanvasLayer 下，必须单独设」）；与字号缩放同生命周期、设置变更自动重应用、测试可直接断言 `ThemeDB` 项目主题 |

阶段 1 完成后 48 处全部告别黑半透明，与帮助按钮/血蓝条浮层观感一致。

### 阶段 2 · 物品浮层卡片化 —— 5 处

把 `item_slot.gd` 的门卫从「只有背包装备」放宽，新增**单卡模式**：

```
_make_custom_tooltip:
    ROLE_BAG + equip        → 现有对比多卡（保持不动，用户满意基准）
    item 非空（其余角色 / 非装备）→ 单卡
    其余（空槽等）          → null（走原生，阶段 1 已换壳）
```

单卡分两档：

| 档 | 适用 | 内容来源 |
|---|---|---|
| **档 A 结构化卡**（装备类，信息结构固定） | 人物槽 / 仓库 / 合成材料 | 标题（槽位名）+ 物品名品质色 + 耐久行 + 属性行 + 评分 —— 与 `_equipment_tip_card` 同构，**提炼公共构建器**复用 |
| **档 B 文案卡**（面板特有信息） | 出售托盘（售价/单价/提示）、背包非装备（药水说明） | 壳同款，内容沿用面板现成 `tooltip_text`（零文案改动） |

关键取舍：**各面板不再各自拼样式**，只提供内容（文本行），壳统一由 ItemSlot / 公共构建器产出 —— 未来新增物品浮层自动一致。

### 阶段 3（可选）· 内容增强

- 人物面板装备浮层补「评分行」（现有名/耐久/属性，背包卡片有评分，信息不对等）；
- 空槽提示保持原生即可（阶段 1 已好看），不建议空槽也弹大卡。

## 4. 🔴 风险

- 🔴 **门卫改动波及全部 `ItemSlot` 子类**（`EquipmentSlot` / 托盘 / 仓库 / 合成槽）。背包对比多卡是用户满意基准，**必须零回退** —— `smoke_test.gd:213`（双槽三栏对比、文字倍率三档）与 `inventory_upgrade_badge_test.gd`（浮层文案断言）是现成护栏，回归必跑。
- 🔴 **独立弹窗宽度陷阱**：自定义 tooltip 在独立弹窗中，无宽度约束的自动换行会把最小高度算成整屏（`item_slot.gd:542` 已有注释与先例）。单卡必须沿用 `AUTOWRAP_OFF` + 固定宽度 / 手动换行。
- 🔴 **主题样式全局生效**：TooltipPanel 一改，全游戏原生浮层同时变（含未盘点到的动态浮层）——这是期望效果，但实机须把 17 个文件对应面板**逐一悬停走查**。
- ⚠ 半透明 → 不透明：浮层不再透出地图，遮挡略增；换来与面板统一的实底观感（与帮助按钮一致）。
- ⚠ **字号双通道**：卡片字号走 `SettingsRuntime.text_scale_value()`（背包卡先例），原生 `TooltipLabel` 字号已由 `_apply_text_scale` 管理 —— 两通道都必须跟随文字倍率，各补一条断言。
- ⚠ `hotbar_slot.gd:130` 把 `tooltip_text` 复用作拖拽幽灵文案 —— 本次不改文案内容，但后续动快捷栏 tooltip 文案时要记得这层复用。
- ⚠ `boss_token_panel.gd:306` 硬编码中文属已知本地化债（10 处之一），不随本次扩大范围，仅记录。
- ⚠ 不动 `Main.tscn` / 面板结构 ⇒ `settings_test.gd` 的 `panels.size()` / z_index 断言理论无影响，仍以回归结果为准。
- ⚠ 帮助按钮（`PanelHelpButton`）不继承 `ItemSlot`，门卫改动对其无影响；`smoke_test.gd:2447` 的帮助浮层断言不受波及。

## 8. 实施与验证记录（2026-10-20）

### 8.1 实施前源码补查：自定义浮层**也被 TooltipPanel 包裹**

动手前查了 Godot 源码（`viewport.cpp::_gui_show_tooltip_at` + `popup_panel.cpp`），修正了 §3 的一个隐含假设：

- `_make_custom_tooltip()` 返回的自定义控件**不是**直接弹出，而是被放进一个 `PopupPanel`（主题类型 `TooltipPanel`）里；
- `PopupPanel::_update_child_rects()` 会把内容控件**内缩到 stylebox 的 content margin 内** ⇒ TooltipPanel 的描边/底色对自定义卡片也是**可见的容器框**。

影响与处置：换壳后背包对比多卡的**卡片本体零改动**（品质描边卡结构原样），但集群外层会从「半透明黑」变成「深底 + 灰边框 + 内衬」的统一容器。这是全局换壳的必然连带，已如实写进 08 §11.4 第 26 项复验判据，实机若不接受再走「自绘覆盖外壳」的回退方案（负偏移绘制）。

### 8.4 本批教训

- 🔑 **`ItemSlot._ready` 的空槽标签依赖 `slot_id`（`item_slot.gd:245`）**：裸 `ItemSlot` 配 `ROLE_EQUIP` 会 `String(null)` 崩（生产只有 `EquipmentSlot` 走该角色，未触发）。测试里 ROLE_EQUIP 一律用 `EquipmentSlot` 与真机同形。
- 🔑 **门卫分流的判据是 `item` 字典不是 `tooltip_text`**：面板拼好的文案只作档 B 内容源；装备结构化卡完全由 `item` 重建（标题/耐久/属性/评分），面板文案不再回显。
- ⚠ 托盘与合成材料**共用 `ROLE_TRAY`**，只有 `tooltip_as_text` 能区分「要售价行」与「要结构化卡」——角色枚举不够用时加实例开关，不要加角色。
