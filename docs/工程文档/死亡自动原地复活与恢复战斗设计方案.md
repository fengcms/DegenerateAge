# 死亡自动原地复活与恢复战斗设计方案

## 1. 需求

在游戏设置中新增一个开关「死亡后自动原地复活并恢复战斗」。开启后：

- 玩家被怪物击倒时，若背包中有复活卷，则**不弹出死亡选择面板**，自动消耗 1 张复活卷原地复活；
- 若死亡前处于自动战斗（F 挂机）状态，复活后自动恢复自动打怪；
- 背包没有复活卷、或开关关闭时，行为与现状完全一致（弹出死亡面板，由玩家手动选择原地复活或回安全区）。

目标是服务于长时间挂机：死亡不再打断挂机循环，代价是持续消耗复活卷。

## 2. 现状链路（改动前）

死亡到复活的现有实现是一条约定的单向链路，本方案不新增第二条结算路径，只在「是否弹面板」这个既有决策点上分流。

| 环节 | 位置 | 行为 |
|---|---|---|
| 扣血致死 | [game_state.gd](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/autoload/game_state.gd#L329-L337) `damage_player()` | HP ≤ 0 时 `EventBus.player_died.emit()`，返回 true |
| 死亡处理 | [player.gd](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/entities/player.gd#L331-L349) `_begin_death()` | 清增益 / 清移动与攻击意图 / `is_dead = true` / `GameState.set_auto_battle(false)` / 掉落 1 件装备 |
| 死亡面板 | [death_panel.gd](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/ui/death_panel.gd#L57-L64) `_show_after_death()` | 延迟一帧后显示面板、`set_panel_open("death", true)`、`get_tree().paused = true` |
| 原地复活 | [death_panel.gd](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/ui/death_panel.gd#L75-L95) `revive_here()` | 扣 1 张复活卷 → `player._revive()` → 关面板（解除暂停）→ `SaveManager.request_autosave()` |
| 自动战斗 | [auto_battle.gd](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/systems/auto_battle.gd#L161-L168) | `player.is_dead` 时把 F 挂机强制转 off，故复活后不会自动继续 |

关键时序：`player_died` 在 `_begin_death()` **之前**发出（`damage_player()` 先于 `_begin_death()` 调用），而面板的响应是 `call_deferred`，因此面板决策时 `is_dead = true` 且挂机已被关闭。这一时序决定了「开关 + 背包卷」的判定必须在 `_show_after_death()` 内完成。

## 3. 设计

### 3.1 设置项

- **键名**：`autoReviveOnDeath`，布尔，默认 `false`。
- **落点**：[game_state.gd](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/autoload/game_state.gd#L188-L215) `default_settings()`，与 `allowBoss` / `dropFlyAnim` 同组。
- **界面**：设置面板「游戏」页新增复选框，排在「拾取飞行动画」之后，并附一行说明。
- **持久化**：设置随当前存档保存（`EventBus.settings_changed` → `SaveManager.request_autosave()`，见 [save_manager.gd](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/autoload/save_manager.gd#L294)）。
- **旧档兼容**：`_migrate_settings()` 以 `default_settings()` 为模板补齐缺键，旧档不会因新键缺失被判损坏；`bool` 型键由 `_is_valid_save()` 按默认值类型自动校验，**无需**在 `SettingsRuntime.CHOICE_VALUES` 登记（登记只针对 String 枚举止键）。

### 3.2 死亡分流

在 `death_panel._show_after_death()` 开头插入自动复活判定，命中则直接返回，不显示面板、不暂停世界：

```gdscript
func _show_after_death() -> void:
	var player := get_tree().get_first_node_in_group("player") as PlayerCharacter
	if player == null or not player.is_dead:
		return
	if _try_auto_revive(player):
		return
	# 以下为原手动面板路径，保持不变
	visible = true
	GameState.set_panel_open("death", true)
	_refresh()
	get_tree().paused = true
```

`_try_auto_revive(player)` 的判定顺序：

1. `GameState.settings.autoReviveOnDeath` 未开启 → `false`（回落手动面板）；
2. 背包 `misc_revive_scroll` 数量为 0 → `false`（回落手动面板）；
3. 调用既有 `revive_here()` 完成扣卷、`_revive()`、解除暂停、请求存档；失败（玩家非死亡态等）→ `false`；
4. 按死亡前记录的挂机状态决定是否 `GameState.set_auto_battle(true)`；
5. 通过 toast 告知玩家「已自动原地复活（消耗复活卷 ×1）」。

复活卷计数从 `_refresh()` 中抽出为复用函数 `_revive_scroll_count()`，面板显示与自动判定共用同一口径，避免两处各写一遍统计逻辑。

### 3.3 恢复自动战斗

`_begin_death()` 已经主动关闭 F 挂机，因此复活后要「恢复」就必须先记住死亡前的状态：

- [player.gd](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/entities/player.gd#L331-L349) 新增 `auto_battle_before_death`，在 `_begin_death()` 中于 `GameState.set_auto_battle(false)` **之前**赋值；
- 自动复活成功后，若该值为 `true` 才重新开启自动战斗。

**顺序约束**：必须在 `player._revive()`（`is_dead = false`）之后才能开启挂机，否则 `AutoBattle._physics_process()` 会因玩家仍处于死亡态而立刻再次关闭它。

**设计取舍（已确认口径）**：只有「死亡前正在挂机」才恢复挂机。若玩家是手动游玩时阵亡，本选项只做自动原地复活，不会替玩家代开自动战斗，避免手动操作被打断后被强行接管。这样既满足挂机连续续战的目标，也不改变手动玩家的操作预期。如果后续希望改成「只要开关开启就无条件开启挂机」，只需去掉 `auto_battle_before_death` 判断这一处。

### 3.4 不改变的部分

- 死亡掉落（`death_penalty.drop_one()`）仍发生在 `_begin_death()`，掉落物留在原地的地面容器上，挂机自动拾取会在复活后照常回收；
- 复活后的 1.0 秒无敌帧由 `_revive()` 既有实现提供，可防止复活瞬间被同位置怪物二次击杀；
- 存档触发仍沿用 `revive_here()` 内 `SaveManager.request_autosave()`（A-P3-6：复活后唯一的存档触发点），不新增第二条写入路径；
- 关安全区免费复活（`revive_camp()`）逻辑与 UI 完全不动。

## 4. 边界与异常

| 场景 | 预期行为 |
|---|---|
| 开关开启但背包无复活卷 | 正常弹出死亡面板，玩家可回安全区免费复活 |
| 复活卷仅剩 1 张 | 消耗后从背包移除，下一次死亡回落手动面板 |
| 死亡前未挂机 | 自动原地复活但不开启自动战斗 |
| 死亡当帧内怪物重复触发 `player_died` | 第二次延迟调用时 `player.is_dead == false`，直接 return，不会重复扣卷 |
| `_begin_death()` 重复调用（测试直接调用） | `if is_dead: return` 幂等，不影响挂机状态记录 |
| 自动复活期间的世界不暂停 | 只持续到延迟回调执行（同帧末/下一帧），期间玩家 `is_dead`，`_begin_death()` 幂等 |
| 自动战斗掉线式反复死亡 | 每次死亡扣 1 卷，卷耗尽后回落手动面板，不存在无消耗循环 |
