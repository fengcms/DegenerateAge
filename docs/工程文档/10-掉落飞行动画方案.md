## 0. 你的原话

> **问题描述**：怪物掉落的物品，玩家快速自动拾取，帧数太快，导致玩家看不到屏幕上掉落的物品，就被捡起来了。
>
> **问题原解方**：物品掉落地面后，1.2s 内，不能拾取，1.2s 后，玩家自动拾取。
>
> **问题原解方的问题**：玩家在挂机时，打死怪物后，会立即寻找下一个怪物，而不是原地等待拾取物品，因此，玩家在挂机时，会丢失一些物品。
>
> **我的新想法**：怪物掉落后的物品，玩家还是立即拾取。但物品不是原地消失，而是执行一个 1.2 秒的抛物线的动画，最后消失。从掉落起始点开始，物品先向上移动，然后向下移动到玩家所在的位置，最后消失。（参考成熟的其他游戏中的物品掉落动画）

**一句话概括你的方案**：**逻辑上前脚落地后脚入包（不再依赖玩家走近），视觉上用 1.2s 抛物线把"入包"这件事演出来。**

## 1. 现状拆解

### 1.1 当前链路（M1-6 起）

```
怪物 HP≤0
  └─ Monster._settle_rewards()
       ├─ 经验：即时入账
       └─ 掉落表 Loot.roll(tableId) → 每件调 Monster._spawn_drop()
            └─ 在 LootRoot（组 loot_root）下实例化 GroundItem，散落 ±18px

GroundItem（Node2D + ClickArea）
  ├─ 出场：缩放回弹 0.14s
  ├─ 落地弧线 DROP_ARC_TIME=0.32s（从 -46px 高落下）
  ├─ 落地保护期 pickup_delay=1.2s ── 期间不响应自动拾取（左键点击仍可）
  ├─ 玩家 ≤1.5 格(96px) → _try_pickup() → 金币入账 / 物品入背包 → queue_free
  └─ 60s 未被拾取 → 淡出消失
```

### 1.2 症结就在这两行参数的矛盾上

| 参数      | 值                | 出处                                |
| ------- | ---------------- | --------------------------------- |
| 近战普攻射程  | 1.0 格 = 64px     | `skills.json: basic_slash.range`  |
| 自动拾取半径  | 1.5 格 = 96px     | `ground_item.gd: PICKUP_RANGE_PX` |
| 掉落后玩家行为 | **立即改选下一个目标并走开** | `auto_battle.gd: SEARCH_TARGET`   |

**结论**：拾取成立的前提是「玩家还站在掉落物旁边」。而自动战斗的设计恰恰是「击杀后不逗留」——两者直接冲突。玩家一走开，物品只能等 60s 后消失，**这就是你说的"挂机丢物品"**。

而且这个冲突**无法靠调参数解决**：把拾取半径调大到能覆盖"玩家下一个目标点"不现实；把保护期调短回退到"1 帧内被吸走"，又丢掉可见性。**必须把"入包"从"玩家位置"这个条件里解耦出来**——这正是你新想法的价值。

## 3. 方案对比

### 方案 A —— 你的原案：立即入包 + 1.2s 抛物线（**不追踪玩家**）

掉落点 → 向上 → 落到**拾取瞬间玩家所在位置** → 消失。

- ✅ 最简单，公式干净。
- ❌ **挂机时视觉是错的**：玩家 1.2s 内已经走出 200~300px，物品会飞向"玩家刚才站过的空地"然后凭空消失。看起来像"东西掉在地上了"而不是"被捡走了"。
- ❌ 与 G2 的初衷相悖。

### 方案 B —— 动画结束才入包（先飞，后进账）

飞行 1.2s 走完才执行入包。

- ✅ 视觉与逻辑完全同步，最"诚实"。
- ❌ **挂机仍会丢**：玩家跑远后飞行目标失效，物品要么跟丢、要么提前消失，**又回到 G1 未满足**。
- ❌ 飞行期间物品"未入包"，此时背包若被其他拾取占满，落账会失败，需要额外的重试/留地分支，复杂度显著上升。
- ❌ 读档/切图重载场景时，飞行中的物品连同未落账的收益一起蒸发——**这才是真的丢件**。

### 方案 C —— 推荐：**立即入包（不可逆）+ 停驻 + 追踪式抛物线**

1. 生成瞬间先尝试入包（背包满/金币满则**不发生**，回退旧留地语义）；
2. 入包成功后物品"变身"为纯表现节点：**停驻 0.2s** 让玩家看到它存在；
3. 随后 **1.0s 抛物线段**飞向**玩家当前位置**（每帧追踪），曲线为二次贝塞尔；
4. 抵达即回收节点。总计 ≈1.2s，与你给的时间一致。

- ✅ G1 完全满足：落账发生在第 1 帧，此后玩家怎么跑都不影响；
- ✅ G2 满足：停驻期给"看得见"，抛物线段给"被吸走"的动感；
- ✅ G3/G5/G6 满足（见 §5、§6）；
- ⚠️ 唯一"不诚实"处：飞行途中若玩家打开背包，会看到物品**已经在里面了**。1.2s 的窗口，且符合"先入账后演出"的通行做法，判定为可接受——**但这是待你拍板项 Q2**。

> **结论：推荐方案 C**。它 = 你的方案 A 加上「追踪玩家」与「一小段停驻」，本质是把工程文档 `03` 的 `R-风险2`（自动战斗时物品捡不到）从根上消掉。

## 4. 方案 C 技术设计

### 4.1 生命周期状态机

```
GroundItem._ready()
  │
  ├─ 计数「停驻倒计时 hold」与「飞行进度 fly_t」；初始 hold
  │
  ├─【Claim 尝试】if auto_claim:
  │      _try_pickup()
  │        ├─ 成功 → _claimed = true
  │        │       · remove_from_group("ground_items")   ← 关键：AutoBattle 立刻看不见它
  │        │       · 广播 toast（"掉落"）；"拾取" toast 按 Q2 决定时机
  │        │       · 保留 item 副本供绘制，进入 PHASE_HOLD
  │        └─ 失败（背包满 / 金币满）→ _claimed = false
  │               · 走【旧语义】保护期 + 靠近/点击拾取 + 60s 消失（9.9 不变）
  │
  ├─ PHASE_HOLD（0.2s）
  │     静止在原地 + 缩放回弹 + 高亮圈，让玩家看清"掉了什么"
  │
  ├─ PHASE_FLY（1.0s）
  │     P2 每帧 = 玩家当前位置（追踪）；P0 = 掉落点；P1 = 中点抬高 h
  │     pos = bezier2(P0, P1, P2, ease_out(t))
  │     缩小 + 淡出；抵达 → queue_free
  │
  └─ 兜底：FLY_TIMEOUT（fly_time + 0.4s）无论进度如何 → 强制淡出回收（防 tween 被 kill 泄漏）
```

### 4.2 抛物线公式（二次贝塞尔）

```
P0 = 掉落点（固定）
P2 = 玩家当前位置（每帧更新）
mid = (P0 + P2) / 2
h   = clamp(P0.distance_to(P2) * 0.35, 34px, 76px)     ← 距离越远抛得越高
P1  = mid + Vector2(0, -h)                              ← 控制点在中点正上方

pos(t) = (1-t)²·P0 + 2(1-t)t·P1 + t²·P2      t ∈ [0,1]
```

- 天然呈现"先升后降"；距离近时弧线平缓，距离远时拱起更明显；
- `t` 走 **ease-out**（先快后慢），落点是"被吸住"的手感，而不是匀速平移；
- 每帧重算 P1/P2，所以玩家边跑物品边追，不会出现"飞向旧位置"的错位。

### 4.3 参数表（建议初值）

| 常量                    | 建议值              | 说明                                           |
| --------------------- | ---------------- | -------------------------------------------- |
| `HOLD_TIME`           | `0.2s`           | 停驻期：让"掉落"可见（**待拍板 Q1**）                      |
| `FLY_TIME`            | `1.0s`           | 飞行时长（HOLD + FLY = 1.2s，对齐你的原案）               |
| `ARC_MIN` / `ARC_MAX` | `34` / `76` px   | 控制点抬升高度上下限                                   |
| `ARC_RATIO`           | `0.35`           | 抬升高度 ∝ 距离                                    |
| `STAGGER_PER_ITEM`    | `0.07s`          | 同一次掉落多件时，出发时间依次错开（第 i 件延后 `i×0.07`，封顶 0.35s） |
| `FLY_TIMEOUT`         | `FLY_TIME + 0.4` | 强制回收余量                                       |
| `TELEPORT_BREAK`      | `220` px         | 单帧目标点跳变阈值：超过（读档/回城卷/瞬移）→ 直接淡出，不拉长弧           |

> 多件掉落的错开（`STAGGER`）很重要：一次死亡常掉 2~4 件，不错开会叠成一坨分不清个数。

### 4.4 绘制

复用现有 `GroundItem._draw()`：金币仍画圆片、其余画菱形，颜色按品质/品类。飞行段叠加 `scale` 收缩 + `modulate.a` 衰减。

**不新增 CanvasLayer、不改 `LootRoot` 层级**：飞行物仍是 `LootRoot` 的子节点，与地面物同级，天然不遮挡 UI（UI 在 `CanvasLayer(layer=1)`）。

## 5. 与现有系统的关系（重点：**尽量不改别人**）

| 系统                                                      | 影响           | 处理                                                                                                     |
| ------------------------------------------------------- | ------------ | ------------------------------------------------------------------------------------------------------ |
| **AutoBattle 顺路拾取**（`SEARCH_LOOT/PATH_TO_LOOT/PICK_UP`） | **零改动**      | 认领成功的掉落物 `remove_from_group("ground_items")` → `_find_loot()` 遍历的组里直接没有它。三态自然只为「背包满留地的」和（未来的）「玩家丢弃的」服务 |
| **地面 60s 消失**                                           | 保留           | 只对"未认领"的掉落物生效                                                                                          |
| **左键点击拾取**（9.9）                                         | 保留           | 只对"未认领"的有效；飞行中的物品加守卫不响应点击                                                                              |
| **「掉落」toast**                                           | 保留           | 仍在死亡结算时聚合广播（`_announce_drops`）                                                                         |
| **「拾取」toast**                                           | **时机待定**（Q2） | 建议改为**飞行结束**时弹，让"掉→飞→捡"三段在时间上成立；若嫌复杂，也可维持生成瞬间两条连弹                                                      |
| **`pickup_delay` 字段**                                   | 语义变更         | 从"落地保护期"改为 **`HOLD_TIME` 停驻期**，数值 `1.2 → 0.2`。字段名建议一并改为 `hold_time`（保留 `@export` 供测试注入 0）              |
| **`loot_spawned` / `item_dropped` 事件**                  | 语义不变         | 仍在生成时广播                                                                                                |
| **「玩家丢弃物品」**（你的手记 §背包面板 7）                              | 预留           | 新增 `@export var auto_claim: bool = true`；玩家丢弃时传 `false` → 直接走"未认领"旧语义。**这套设计现在就要留好，否则将来要返工**           |

### 5.1 关键收敛点

> `remove_from_group("ground_items")` 这一行，让 AutoBattle、测试工具、任何"找地面物"的代码**全部自动排除已认领的出物**，无需逐个加 `claimed` 判断。这是本方案改动面小的根本原因。

## 7. 🔴 风险

- 🔴 **R-风险1｜口径漂移**：本次改的是**产品语义**（拾取不再依赖玩家位置），涉及 3 份产品文档 + 4 个测试工具。若只改代码不同步文档/测试，会立刻出现"文档说保护期 1.2s、代码里没有"的分裂。**必须一次改齐。**
- 🔴 **R-风险2｜"不诚实"的 1.2s**：飞行中打开背包会看到物品已入账（方案 B 试图解决但代价更大）。**待拍板 Q2**。
- 🟡 **R-风险3｜瞬时节点数上升**：挂机连续击杀时，同时存在多个飞行中节点（每个生命周期 1.2s）。按 600s / 107 杀的压测强度应无虞，但**必须重跑 SoakTest 复核"孤儿节点恒 0"与节点漂移判据**。
- 🟡 **R-风险4｜目标点跳变**：读档 / 回城卷 / 未来传送会让玩家瞬移，追踪曲线被拉成一条长线。已用 `TELEPORT_BREAK` 兜底（超阈值直接淡出）。**注意 9.9 未来接入的"随机券/回城卷"**。
- 🟡 **R-风险5｜自动拾取开关 G 的语义**：G 关闭时，怪物掉落还飞不飞？建议**照飞**（因为已入包，飞行只是表现，与"是否顺路拾取未认领物"是两件事）。**待拍板 Q4**。
- 🟡 **R-风险6｜"看得见"是否真的达成**：0.2s 停驻对快速刷怪场景可能仍偏短。建议保留 `HOLD_TIME` 为可调常量，实机试玩后校准（可参考工程文档 07 的校准流程）。
