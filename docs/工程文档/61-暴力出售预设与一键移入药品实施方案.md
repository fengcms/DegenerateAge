# 装备出售「暴力预设」+ 货郎「一键移入药品」实施方案（工程 61）

> 触发：①背包「出售装备」面板增加**暴力**选项，选中后背包内所有装备一次性卖出，不提示不二次确认；

>
> **状态：方案待确认（2026-10-20）。** 未改任何代码。

## 二、需求一：暴力预设

### 2.1 现有链路在哪儿拦

`SellGearPolicy.entry()` 给每件装备打五类「不建议卖」标记，任一命中就不自动勾选：

| 标记 | 判据 | 暴力下 |
|---|---|---|
| `favorite` | 玩家收藏 | 见 §2.2 口径 |
| `unsellable` | 任务物品 / 无价 | **保留**（见下） |
| `upgrade` | 评分高于已穿戴（同槽） | 跳过 |
| `starred` | 加过星 | 跳过 |
| `quality` | 品质高于预设上限 | 跳过 |
| `level` / `suit` | 等级接近 / 同套或更高档 | 跳过 |

### 2.2 「不进行任何校验」的边界（必须拍板）

字面执行「零校验」会出两个事故，所以我建议划一条线：

- **必须保留**：`Shop.can_sell()` 里「任务物品 / 无价物品」两条。它们回收价是 0（或 ×0.6 得 0），
  卖掉等于**白扔**；更糟的是任务装备消失会让主线节点指向不存在的物品。
  这不算「校验」，是「卖不出东西的东西不卖」。
- **必须保留**：`Lv15` 直卖门槛（`sell_selected_equipment` 既有规则，与预设无关）。
- **必须保留**：清单过期重核（`_stale` / 快照全等）。它不是保护装备，是保护**你这次点的内容和你以为的一样**。
  打开面板后捡了件装备、清单变了，暴力也应当让你重看一遍。
- **建议保留（待你选）**：收藏保护。

| 选项 | 含义 | 代价 |
|---|---|---|
| **A（推荐）** | 暴力 = 跳过全部「价值判断」（升级/星级/品质/等级/旧套），**收藏与任务物品仍不卖** | 只改 `SellGearPolicy` 一处；`can_sell` 不动 |
| B | 连收藏一起卖 | 要给 `can_sell` 加 `ignore_favorite` 参数并逐个复核 8 个调用方（`shop_sell` / `shop_sell_staged` / `_is_material` 等），任何一处漏改就是「收藏在别处也被卖」 |

我推荐 A。真要清收藏，先在背包里批量取消收藏（已有该功能）。

### 2.3 暴力预设要不要写进存档（必须拍板）

这是本次最有产品味道的一处。若暴力被持久化：**你上次选过暴力，下次打开「出售装备」面板时，
40 格装备已经全部勾选好**，一个手滑点「确认出售」就全没了。

| 选项 | 行为 | 改动量 |
|---|---|---|
| **A（推荐）** | 暴力是**一次性**的，不写盘；关闭面板后回落上次的谨慎/标准/积极 | `preview_equipment_sale` / `validate_equipment_sale` 各加一个 `preset_override` 参数（默认空 = 读设置），`set_sell_gear_preset` 拒绝 brutal |
| B | 持久化，下次打开仍是暴力 | 最省事，但要改 `CHOICE_VALUES`（见 §2.4），且把风险留给玩家 |

选 A 还顺带**消灭**了 §2.4 那个存档白名单风险 —— 因为存档里永远不会出现 `brutal`。

### 2.4 🔴 若选 B：存档白名单是硬性前提

`save_manager.gd:1298`：`is_choice_key(key) and not valid_choice(key, value)` → 返回 false → **整档判损坏**。
`CHOICE_VALUES["sellGearPreset"]` 目前只有三个值。

也就是说：**存了 `brutal` 的档，在没登记的情况下会变成「存档损坏」**，而且是玩家点开游戏才发现。
选 B 时必须同批改 `settings_runtime.gd:37`，并补一条「`valid_choice("sellGearPreset","brutal")` 为真」的断言。

### 2.5 具体改动点

### 2.6 货郎「挑选装备」模式的限制

托盘 24 格 < 背包 40 格，暴力一次搬不完时会走 `take_equipment_for_sale` 的
「出售托盘空位不足，请减少勾选」。这条提示是**必要**的（否则静默少搬一半）。
若你要「搬到满为止，剩下的下次再搬」，我可以改成自动截断 + 提示，但那会让「一次性全部卖出」变成「分几次」，
需你点头。

### 3.2 🔴 必须同批修的既有测试


这样「一键移入药品」和「如意告警」两条覆盖都在，且新增了「卷轴不被带走」的断言（原实现里

## 四、风险（🔴）

- 🔴 **选 B 而不改 `CHOICE_VALUES` ⇒ 带暴力的存档被判损坏**，且只在读取时爆发。选 A 则无此问题（推荐的理由之一）。
- 🔴 **暴力 + 持久化 = 默认全选 40 件装备**。这是「一次手滑清空账号」级别的事故面，是本方案最不该省的一处。
- ⚠ 暴力跳过 `upgrade` 判断意味着**比身上更好的装备也会被卖**（这是需求本身要的），
  预览窗里那行「评分可提升」的说明会消失 —— 玩家看到的是一整片全勾。属预期。
- ⚠ 改名 `_on_stage_materials_pressed` 会牵动 `smoke_test.gd:2367` 的调用点，漏改 = Parse/运行期空调用。
- ⚠ 本次不动 `_tray_warn` 的换行问题（工程 60 尚未实施）。暴力一次搬 24 件时，
  那句「珍贵装备：…」在货郎端会更长 —— **建议与工程 60 一起上**。

## 六、验收与负向验证

**正向**
1. 选暴力 → 40 格里 N 件可售装备全部勾选，任务物品仍灰显不可勾；
2. 点一次「确认出售」→ 全部消失、金币 = Σ 单价、无「再次确认珍贵装备」这一步；
3. 关闭面板再打开 → 预设回落（选 A）或仍是暴力（选 B）；
4. 货郎端暴力 → 托盘塞满即提示空位不足，不静默少搬；
5. 「一键移入药品」→ 只带走药水，卷轴 / 如意 / 杂项全部留在背包。

**负向（必须「有牙」）**
| 变异 | 期望 |
|---|---|
| 暴力分支里放回 `favorite` 判断 | 收藏装备不再被选中 → 断言红 |
| 暴力分支里去掉 `can_sell` | 任务物品被卖 → 断言红（这是最关键的牙） |
| `_on_confirm` 不跳过 risky | 「一次点击即成交」断言红（会停在二次确认） |
| `_is_material` 保持 `[potion,misc,rune]` | 「卷轴不得被移入」断言红 |
| 选 A 时让暴力写进 settings | 存档往返断言红（读回被白名单判非法或回落） |

### 拍板结果

### 关键实现点

| 项 | 做法 | 为什么 |
|---|---|---|
| `preset_override` | `preview_equipment_sale` / `validate_equipment_sale` / `sell_selected_equipment` / `take_equipment_for_sale` 各加一个默认空串的参数 | 不落档的预设只能靠调用链传递；**校验层必须收到同一个值**，否则它拿存档预设比对，一律判「清单已变化」 |
| `_active_preset` | 出售预览窗内的局部字段 | 承载「一次性」：只存在这个窗口里，关窗即忘 |
| 理由文案 | 暴力分支仍区分 `favorite` / `unsellable` | tooltip 要说清「为什么这件没被勾上」，统一写 `unsellable` 会把收藏件说成无价件 |
| 托盘接力 | `shop_panel._tray_preset` | 货郎端结算前的风险确认要能认出「这批是暴力清单搬进来的」；手动拖入一件即清空，整批回到按存档预设重判 |

### 新增测试 `SellPresetBrutalTest`（隔离集 48 → 49）

### SmokeTest ③④⑤ 的改写（**不删断言**）

原用例建立在「一键移入材料会带走药水 + 如意」上，改口径后必然红：件数 2 → 1、金额 1512 → 1332。
处理方式是把覆盖**换条路保住**，不是删掉：

- ③ 改成「只搬 1 件且是药水」，并新增「如意与杂项必须留在背包」；
- ④ **手动把如意拖进托盘**（走真实 `_on_tray_drop` 路径），「升星材料」告警覆盖原样保留；
- ⑤ 因为 ④ 补了如意，**金额仍是 1512，断言一个数字都没改**。

若实机后觉得「太容易手滑」，最小改动是给按钮加一个 0.5 秒不可点的冷却，而不是把二次确认加回来（那就违背需求了）。
