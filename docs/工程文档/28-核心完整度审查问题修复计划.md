## 1. 修复原则与约束

1. **只修已识别问题**：本次不夹带任何无关重构、不顺手优化、不改数值调平。审查报告未列的问题不纳入。
2. **逐项单独提交**：依 AGENT.md §10，每一项（或一组不可拆分项）单独 `git commit`，显式指定文件路径，**严禁 `git add -A`**；共享工作区存在协作者改动，提交前必须核对 `git diff` 与暂存范围。
3. **改动最小化**：能局部替换的不整体重构；不改动公开接口签名时优先保证既有回归测试零改动通过。
4. **常量集中**：新增几何/上限/枚举一律进既有单一配置源（`panel_chrome.gd`、`game_state.gd` 常量区、`Iso` 等），不在调用点另起硬编码——延续既有「几何常量集中」教训。
5. **UI 改动沿用工程既有入口**：面板尺寸/边距/按钮走 `panel_chrome.gd` 常量与 `floating_window` 布局入口，不新增散落的逐控件样式覆盖（延续「禁止内联样式」的口径）。
6. **验证门槛**：每次提交前后都要跑隔离回归。判定通过 = 退出码 `0` + 输出含「全部通过/PASS」+ 无 `SCRIPT ERROR`。
   - 隔离运行必须**非沙箱**（Godot 需写 `~/Library/Application Support/Godot`）：
     ```bash
     python3 tools/run_isolated_tests.py
     ```
7. **既有失败基线不得当新问题**：`ArtSampleTest`、`ChapterOneArtTest`、`QualityFrameTest`、`IconIntegrationTest` 在改动前即失败且不在默认集内，其状态变化不计入本次验收。
8. **不做无实测的性能承诺**：涉及性能的改动须给出同场景前后测量或明确标注为「推断」。
9. **临时产物不入库**：探针脚本、截图、中间 JSON 用完即删。
