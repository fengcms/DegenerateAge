# 经验条悬停数字未实时刷新原因与修复

## 现象与影响

鼠标持续停在游戏底部经验条上时，获得经验或升级会改变经验条进度，但已弹出的浮动提示仍显示悬停时的旧数字。移开鼠标再悬停才会读到新值。影响仅限 HUD 经验提示；经验结算、等级和存档数值不受影响。

## 定位证据与根因

- `GameState.add_xp()` 完成经验结算后发出 `EventBus.player_xp_changed`；`Hud._on_xp()` 原本已经更新经验条的当前值、上限及来源控件的 `tooltip_text`。
- 底部 `ExpBar` 原来是普通 `ProgressBar`。Godot 已弹出的原生提示有独立显示节点，修改来源控件的 `tooltip_text` 不会让这个现存节点重建，因此事件链正常、进度条正常，浮动数字却停在旧值。
- 同一 HUD 的血蓝条此前已通过自定义提示节点和弱引用实现持续悬停刷新；经验条没有接入这一机制。修改前运行新增的 `HudLiveTooltipTest` 经验断言，失败为 `ProgressBar` 不存在 `_make_custom_tooltip`，确认经验条尚不支持已打开提示的显式刷新。

## 修复与成本

给经验条挂载 `HudExperienceBar`，沿用血蓝条已验证的轻量提示样式、当前文字倍率和弱引用生命周期。`Hud._on_xp()` 每次收到经验事件后先写入进度、上限与提示文本，再同步仍存活的提示文字。升级时当前经验和下一等级经验上限一并刷新；提示关闭后弱引用不阻止节点释放，重新悬停会创建显示最新值的提示。

经验变化只触发一次常数规模的文字同步，没有逐帧轮询或额外存档字段；同时活动的经验提示最多一个，关闭后由 Godot 释放。

## 复核方法与边界

隔离测试 `HudLiveTooltipTest` 在提示保持打开时依次获得经验、跨级升级，再关闭并重新打开提示，检查当前值和上限；`SmokeTest` 验证广泛功能冒烟。执行：

```bash
python3 tools/run_isolated_tests.py HudLiveTooltipTest SmokeTest
```

手动验收时把鼠标停在底部经验条，击杀怪物获得经验直至升级，数字应无需移开鼠标就更新。隔离测试覆盖节点和事件链，不代替原生窗口下提示位置的视觉检查。
