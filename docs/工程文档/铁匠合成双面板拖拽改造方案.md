# 铁匠合成双面板与拖拽改造方案

日期：2026-10-19。本文只规划交互改造，**不改变**四金合紫、四紫定向、保星升级的品质、档位、星级、词条、费用和结算规则。实施前以[产品装备规则](../产品文档/05-装备与背包系统.md#513-铁匠合成与保星升级)为准。

## 现象、代码证据与原因

目前 `scripts/ui/equipment_fusion_panel.gd` 用四个 `OptionButton` 枚举背包装备。物品多时需要反复打开长列表，仅显示序号和名称，无法像背包格一样直接看图标、品质与悬停属性，也不能把眼前的装备拖过去。玩家在铁匠菜单选中服务后，该面板单独居中；`scripts/ui/inventory_panel.gd::_on_panel_opened()` 会因 `GameState.panels_coexist()` 不允许 `equipment_fusion` 与 `inventory` 并开而关闭背包。

现有可复用基础：`ItemSlot._get_drag_data()` 已提供来源、背包下标、物品及 token，并用 `DragGhost` 保持物品贴着鼠标；货郎的 `ShopTrayGrid` 已实现格子与格间缝隙一起接收投放；`FloatingWindow` 支持背包停靠和小窗口滚动。`GameState.forge_equipment()` 已在确认时按实例 ID 与快照重新核对并一次扣除材料／金币，因此无需重写合成规则。另一个顺手要修的集成缺口是 `GameState.NPC_DIALOG_PANEL_IDS` 目前未列入 `equipment_fusion`，打开该窗口时不能可靠地按 NPC 会话规则暂停自动战斗。

## 建议的玩家体验

铁匠菜单的三个入口继续保留。进入任一服务时，左侧打开**真实背包面板**，右侧打开**合成面板**，间距约 12 个逻辑像素，不叠遮罩。背包仍可滚动、悬停查看属性；合成格显示与背包一致的装备图标、品质框、星数和悬停属性。拖起背包装备投到目标格或格间缝隙，鼠标落在哪个格就放在哪个格；被选中的背包格加“已选材料”标记，避免同一件重复投放。点击合成格右上角的 × 可撤下，也可用另一件符合条件的装备覆盖。撤下、切服务或关闭窗口均不改变背包和金币。

```text
┌──────── 背包（原面板） ────────┐  12px  ┌────── 铁匠：四金合紫 ──────┐
│ 装备、药品、滚动与原有悬停     │        │ [材料1] [材料2]          │
│ 被选装备仅标记，仍在原背包格   │  拖放→ │ [材料3] [材料4]          │
│                               │        │ 输出：最低档 · 随机部位   │
└───────────────────────────────┘        │ [装备合成] [随机放入]     │
                                         └───────────────────────────┘
```

| 服务 | 格子与附加控件 | 按钮 | 放入校验 |
|---|---|---|---|
| 四金合紫 | 四个等尺寸材料格；显示当前**最低档**和“随机部位／随机词条” | `装备合成`、`随机放入` | 仅背包金装；手动可混档、可带星；收藏件禁投。最终仍取最低档 |
| 四紫定向 | 四格 + 目标类型选择（武器、盾牌、戒指等） | `装备合成`、`随机放入` | 仅同档紫装；12 星紫装禁投；其他星级可手动投放；收藏件禁投 |
| 保星升级 | 两格分别固定标明“旧档 12 星紫装”和“相邻高档同类型 0 星紫装”；显示金币与词条重随机提示 | `保星升级`；**不设随机放入** | 不能反放，第二格随第一格检查类型与相邻档；收藏件禁投 |

格子不把物品提前从背包移出，只保存 `instanceId` 与完整快照作为**待选引用**。这让取消、断线式中断、切服务和背包满格时没有退还／丢物风险。确认成功才由现有 `GameState.forge_equipment()` 消耗真实背包材料并写入产物。结算失败保持背包原样，并在面板内说明原因；成功后清空格子、刷新背包和金币。背包整理、穿脱、出售或自动拾取使已选材料变化时，按实例重新定位；丢失或内容变化的材料格自动清空、确认按钮禁用，并提示重新放入，不能静默改选另一件装备。

### “随机放入”的推荐口径

只用于四金和四紫，**每按一次重新挑选四件并替换当前四格选择，绝不立即消耗装备**。为避免误把养成件投入，自动候选默认仅取**未收藏、0 星**的合格背包装备；带星材料依然可手动拖入，沿用现有二次确认。若四金／四紫没有任何同档候选达到四件，按钮可点但给出“没有足够的同档 0 星装备，可手动选择”提示，不改变当前格子。四金手动混档规则不受此快捷功能限制。

“随机”的精确定义：先把合格候选按**装备实例的十级档**分组，筛出至少四件的档；从这些档中等概率抽一档，再从该档的候选中**不重复、等概率**抽四件。四紫额外排除 12 星紫装；四金只考虑金装。若已有手动选择，点击随机放入会完整替换，但按钮旁持续显示“替换当前选择，不会消耗”；玩家可在确认前检查四格并逐格调整。随机数只决定预选材料，不决定产物；现有合成规则的随机类型／词条仍在最终结算时生成。

## 技术改造路径

1. **会话与布局**：新增独立的合成会话信号或状态，打开合成面板时拉起背包；在 `GameState.panels_coexist()` 明确允许 `inventory` 与 `equipment_fusion` 互存，并把合成面板加入 `NPC_DIALOG_PANEL_IDS`。背包与合成面板停靠在左右两个逻辑区域；退出合成保留背包当前可见位置，不用货郎的出售托盘状态。`Esc`／合成窗关闭键关闭合成会话，背包继续保留；背包 `I` 在会话中关闭两窗，避免只剩不能操作的半个工作台。统一处理会话快捷键，避免两个面板各自收到同一次 `Esc` 而一起关闭。切到其他 NPC 服务时清空预选引用。
2. **合成格**：用现有 `ItemSlot` 外观渲染材料，新增只接收背包 `ROLE_BAG` 装备载荷的 `FusionMaterialGrid`（或同等小型控件）。参照 `ShopTrayGrid.slot_at()`，在整张格网接收拖放并按最近格中心确定目标格，覆盖格间空隙；保星两格单独校验角色。不要复用会真正把物品移出背包的货郎 `_on_tray_drop()`。
3. **预选状态**：合成窗以四／两个定长槽保存 `instanceId` 和快照；拖放先检查载荷来源、实例、背包实时位置和模式规则，再替换对应槽。拖动与随机放入都走同一 `_set_material` 路径，统一去重、禁止收藏、禁 12 星紫装与预览更新。四紫跨档的第二件起直接给出解释；保星的第二格给出“需高一档同类型 0 星”提示。
4. **随机选择**：抽取为纯函数，输入只读背包、模式和可注入 RNG，输出四个实例快照；先分组，再抽档、无放回抽样。最多扫描当前背包容量（产品上限 400 格）一次，按钮触发时才计算，绝不逐帧扫描。无解时不修改旧选择。
5. **结算与提示**：预览继续调用 `EquipmentFusion.plan_four()`／`plan_transfer()`；确认继续调用 `GameState.forge_equipment()`。有带星材料时保留二次确认，保星继续明确“两件旧装备及词条消耗，输出重新随机词条”。切换材料、目标类型、背包变动或金币变动后撤销先前的风险确认。
6. **响应式布局**：使用逻辑视口尺寸和现有 UI 缩放；宽度足够时双面板并排，宽度不足（如小窗口配 200%）时改为上下排列并各自滚动，两个面板仍可见、按钮始终在视口内。不能通过缩小文字破坏玩家设置。窗口位置在退出会话时保持稳定。

## 验收与边界

- 从铁匠菜单进入三项服务，背包与合成窗同时可见；关闭合成保留背包及位置，打开其他 NPC 服务正确结束会话。NPC 会话中自动战斗暂停，退出后按既有规则恢复；世界键盘输入遵循现有 NPC 面板约定。
- 拖入指定格、格间缝隙、覆盖、撤下、重复拖同一件、拖错品质、收藏件、跨档紫装、12 星紫装、保星放反、背包整理／物品变化都给出可理解反馈；预选和取消不扣物。
- 随机放入仅取同档四件不重复 0 星候选；多个可选档的抽样可用固定种子复现；无组可选不清空旧槽；手动四金混档仍正常。
- 100%、150%、200% UI 比例及窄窗口下无裁切，背包到合成格的拖拽幽灵位于两面板上方；鼠标落点对应格位，背包悬停属性保持可用。
- 成功与失败结算、金币不足、二次确认、连续点击和存档往返继续通过现有规则／交易测试；新增双面板与拖拽、随机选择的隔离测试。测试不得触碰玩家真实存档。

此次改造主要是 UI 与预选逻辑：同时活动节点约四／两个材料格，随机按钮单次最多遍历 400 个背包格并对合格材料分组，无新纹理和逐帧工作。开发时应把**旧下拉框移除**，避免两套预选状态长期并存。当前仓库还有其他 AI 的美术／工具未提交改动，本方案文档应单独提交，不纳入那些文件。

## 实施记录（2026-10-19）

已接入同档 0 星随机预选、背包并排会话、可拖放材料格与保星两格，旧材料下拉框已移除。随机预选使用纯规则函数，材料格只保存实例快照，最终交易继续调用原有 `GameState.forge_equipment()`。隔离测试覆盖四金、四紫和保星结算、格间命中、背包整理、200% 窄窗口与宽窗口并排，以及 NPC 会话暂停。原生鼠标拖动的手感仍需玩家在实际运行窗口验收；隔离脚本验证的是同一拖拽载荷与投放入口。
