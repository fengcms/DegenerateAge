## 4. 冲突与决策点（🔴 先拍板再动代码）

### 4.1 D-1 费用模型冲突（🔴 必须解决）

**冲突事实**（两份权威文档内部打架）：

| 来源 | 主张 |
|---|---|
| 创意 **08 §4** | 给出一张**与出发地有关**的 4×4 矩阵：营地→灰烬 50，但灰烬→营地 70；野外→营地 20，但营地→野外 0 |
| 创意 **10 §3.4** | "按**目的地类型**定价……**与出发地无关**（同一集群内统一报价）" |
| 创意 **10 §4** | "费用（**沿用 08 §4 矩阵，第一章数值不变**）" |

⇒ §3.4 的类型统一报价**无法复现** 08 §4 的出发地相关矩阵；而 §4 又要求第一章数值不变。**两者不能同时成立。**

**影响面**：`fee_to()` 实现、`maps.json` 字段形态、`CarterPanel` 文案、`ChapterOneAcceptance` 的费用断言（camp→wild 0 / wild→ash 50 / ash→source 100）。

**选项**：

| 选项 | 做法 | 代价 |
|---|---|---|
| **A（推荐）** | 第一章**沿用 08 §4 逐对矩阵**（`carterFares` 显式对，等价现有 `carterFees`）；`carterFare` 类型价仅作**第二章起的缺省兜底**（缺显式对时按目的地类型报价） | 与 10 §3.4 字面冲突，需在 10 或 08 补一句口径修订 |
| B | 采用 10 §3.4 类型统一报价 | 第一章费用**变化**（灰烬→营地 70→50 等），违反 10 §4"数值不变"，且改现有验收 |
| C | 先按 A 落地，把 10 §3.4 的"与出发地无关"降级为**第二章起**的原则 | 同 A，但口径变更写进 10 |

**推荐 A**：数据即现状（最小改动）、08 §4 是"开发交接用"执行起点、10 §4 也明说第一章不变。**待用户确认后再定 D-1，它决定 `maps.json` 字段与 `fee_to()` 写法。**

### 5.2 集群解析：`MapService.destinations()`

```gdscript
## 目的地 = (集群(当前图) ∪ hubLinks(所属枢纽)) − 当前图   （创意 10 §3.2）
## 集群(图) = { hub } ∪ { spoke : spoke.hubId == hub }，hub = 图.hubId（hub 填自身）
func destinations() -> Array:
    var out: Array = []
    var me := GameState.current_map
    var hub := String(current_data().get("hubId", me))
    var cluster: Array[String] = [hub]
    for m in DataLoader.table("maps"):
        if String(m.get("hubId", "")) == hub and String(m.get("id", "")) != hub:
            cluster.append(String(m.get("id", "")))
    for lid in _hub_links(hub):       # hubLinks（hub 的相邻枢纽）
        cluster.append(String(lid))
    for id in cluster:
        if id == me or not exists(id) or out.any(func(d): return d.id == id):
            continue
        out.append(_destination_view(id))   # {id,name,recommendedLevel,cost,unlocked,visited,reason}
    return out
```

- **第一章单集群**：camp 的 `hubLinks=[]`，cluster = `{camp, wild_trial, ash_land, corruption_source}` ⇒ 目的地 = 其余 3 图，与 08 §4 一致。
- `is_linked()` 语义**升级**为"集群可达"（供测试 / 面板用）；旧"相邻"语义若仍需，改名为 `is_adjacent()`（仅步行用）。

### 5.3 出口交互 + 免费步行（08 §2 §3）

- **实体**：新增 `scripts/world/travel_exit.gd`（`Node2D`，绘制路牌 / 双向箭头 + 地面色带），由 `game.gd` 按 `maps.json.exits` 装配（与 NPC 同构：`_spawn_exits()`）。
- **提示**：`Game._process` 取**距离最近**且 ≤ 1.5 逻辑格的出口 → HUD 显示 `E 前往灰烬之地 · 免费 · 推荐Lv6`（**逻辑网格距离**，非菱形屏幕距离；最多显示一条）。
- **触发**：`E` → `MapService.request_travel(to_map, "walk")` → 成功后 `reload_world()`。
- **防抖**：① 抵达后 **1 秒**内禁用出口交互；② 要求**释放 `E` 后再次按下**（长按不连续触发）；③ 面板打开时 `E` 只走面板原有语义，不同时触发出行；④ 死亡 / Esc 暂停 / 后台冻结 / 切图处理中禁止出行。
- **未解锁**：`道路封锁：请先完成「<任务名>」`（原因取自配置，不只显示"无法前往"）。
- **不参与自动寻路**：`AutoBattle`、自动拾取、追怪、怪物碰撞**均不能使用出口**；地图点击出口只走到出口前合法停靠点。

### 5.4 出行休整区（08 §6）

- **定义**：以每个**出口中心 / 入口落点 / 驿站落点**为圆心、半径 **3 逻辑格**的区域；由 `MapService.rest_zones(map_id)` 从数据推导（不显式存储）。
- **刷怪排除**：`MonsterSpawner._random_spawn_position()` 拒绝落在任一休整区内的格（采样循环内加判定）。
- **怪物 AI**：不进入区内攻击；远程攻击不命中区内玩家（`Monster` 攻击判定加"目标在休整区内 → 放弃"）。
- **玩家**：在休整区内**不能攻击区外怪物**（`Player.valid_target` / 攻击入口加"双方均在区外"判定），避免站安全边缘输出 Boss。
- **切图后自动状态**：清锁定目标 / 追击指令 / 地图移动目标 / 待执行攻击；**保留自动战斗 / 拾取开关偏好**；抵达后提示 `自动战斗暂停：出行休整区`，不自发离开；玩家手动离开后按既有**接管延迟**恢复（开关关则不恢复）。
- **表现**：低饱和浅色边界 + 路牌（**不用 Boss 预警色**）。仅提供停靠，不授予恢复倍率 / 复活锚点 / 任务完成效果。

### 5.5 原子提交与回滚（08 §7，🔴 核心）

**现状问题**：`travel_to()` = 校验 → **扣费** → 改 `current_map` + `save_pos` → `emit map_changed`（**触发自动存档**）→ UI 再 `reload_world()`。⇒ 若加载失败，磁盘上已存"钱扣了、图还是旧的/中间态"。

**改造为两阶段（六段式）**：

```gdscript
## 运行态：待确认的出行（不入档）。null = 无进行中出行。
## { from, to, mode("walk"/"carter"), fee, snapshot{gold, current_map, save_pos, has_save_pos} }
var pending_travel: Dictionary = {}

func request_travel(to_id: String, mode: String = "walk") -> Dictionary:
    # ① 请求：校验（存在 / 非当前 / 集群可达 / 解锁 / 到访[车夫] / 费用 / 步行须在出口交互范围内）
    #          并发锁：pending_travel 非空 → 拒绝（防双击 / 冲突请求）
    # ② 准备：快照源图状态；未结算出售托盘先完整退回背包（由 UI 层回调）
    #          扣费（fee>0）；写 pending_travel；写 current_map + save_pos（**不 emit map_changed**）
    # ③ 加载：UI 调 reload_world() → reload_current_scene()（deferred）
    # ④ 提交（在 Game._ready 中）：pending_travel.to == current_map 且装配成功 →
    #          visitedMaps.add(to)；emit map_traveled / map_changed；request_autosave()；清 pending_travel
    # ⑤ 完成：抵达提示（Game._ready 既有 _notify_arrival）
    # ⑥ 失败：装配失败 / 目标无效 → 用 snapshot 回滚（gold / current_map / save_pos）→ 重建源图 →
    #          提示「前往失败，未收取车费」，**不标记到访**
```

要点：
- **`map_changed` 只在提交段发**——自动存档因此**只写"图已成功切换"的完整状态**，不写中间态（满足 08 §7"不能让自动存档保存金币已扣但地图未成功加载的中间态"）。
- `pending_travel` 是**运行态**（不入档）：进程被杀 → 下次读最后完整快照（08 §7）。
- `MapService` 是 Autoload，`pending_travel` 可跨 `reload_current_scene` 存活（场景重载不重建 autoload）。
- **失败路径的触发条件**：目标地图数据非法 / 场景装配抛错。因启动校验已保证地图合法，此路径在**正常数据下不可达**——需**专项负向用例**构造（临时把 `current_map` 指向非法 id 或在 `Game._ready` 注入失败探针）验证回滚生效。

### 5.6 到访记录与车夫门控（08 §5 + 10 DC）

- `GameState.visited_maps: Array[String]`（**新档 = `["camp"]`**）。
- **记录时机**：目标图**装配成功且玩家实际落地后**（即 `Game._ready` 提交段）——步行、教学乘车、新档营地、合法读档**均算到访**；未完成加载 / 加载失败 / 只看菜单**不算**。
- **首次提示一次**：`已到访灰烬之地，车夫直达已开放`。
- **门控**：`destinations()` 中未到访且非教学线 → 置灰 + `先步行到访，开放直达` + 给出道路名称顺序；教学线（营地→野外 0 金）始终可用。
- **与剧情解锁 / 迷雾 / Boss 首通分别存储**（互不推导）。

## 7. 启动校验扩展（`data_loader.gd`）

在既有 `_validate_maps` 基础上追加（08 §11 + 10 §5）：

| 校验 | 规则 |
|---|---|
| `kind` | 必须为 `"hub"` 或 `"spoke"` |
| `hubId` | 存在、指向**一个 hub**；hub 自身 `hubId == id` |
| `hubLinks` | 仅 hub 可有；两端**都是 hub** 且**双向配对** |
| 每 hub ≥ 1 spoke | 集群非空 |
| `carterFare` | `{spoke, hub}` 均为**非负整数**；仅 hub 可有 |
| `carterFares` | 目标必须在**本集群 ∪ hubLinks**内；非负整数 |
| `carterFree`（如启用） | 必须在**同集群**内 |
| `exits` | `id` 唯一；`cell` 在 `size` 内；`toMap` 存在；`toEntrance` 在目标图 `entrances` 中存在；**双向配对**（A→B 的 toEntrance = B→A 的入口 id） |
| `entrances` | id 在图内唯一；落点坐标在 `size` 内 |
| `carterArrival` | 坐标在 `size` 内 |
| 备份：`carterLinks`（若 D-4 选保留） | 沿用旧校验 |

> 校验失败 → 启动报 `[maps] ...`，冒烟测试按既有机制断言（`--quit` 含「配置校验通过 ✅」）。
