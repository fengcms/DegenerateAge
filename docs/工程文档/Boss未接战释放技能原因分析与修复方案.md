# Boss未接战释放技能原因分析与修复方案

2026-11-02。玩家反馈Boss没有攻击目标也释放技能。本节点只分析并提出修复方案，不改生产逻辑。

## 结论与复现证据

确认存在“未接战仍启动技能”的入口缺陷，主要位于第三章以后共用的BossAction宿主逻辑。这里没有独立的Boss锁定目标字段；普通AI依据状态机及玩家位置判断是否接战，技能却把“场景内存在存活且不在休息区的玩家”直接当成可攻击目标。玩家没有选中Boss不等于Boss没有仇恨，修复不能依赖玩家的locked_target。

隔离Game场景中关闭自动AI推进，以手动驱动生产_update_boss_action入口排除移动干扰，分别生成c3_boss01、c4_boss01、c5_boss01、c6_boss01；每只Boss保持State.IDLE，放在距玩家1800像素处并将出生位置设为当前位置，仇恨范围512像素。重置动作后推进6次1秒，四只均出现busy=true，Boss仍是IDLE；前两只最终停在预警，后两只在其他动作阶段。真实玩家节点来自Game，未使用假的“目标有效”替身。这证明未接战条件也能触发生产技能入口；不把该探针声称为完整挂机体验测试。

数据统计：当前17个Boss模板中，13个带bossSkill.shape、3个第二章专用入口、1个旧式首章入口。13个共享动作模板及其在循环地图/随身Boss生成的实例具有相同入口风险；实际出现频率取决于地图距离、阶段和冷却，不能据此声称每只都已逐一实测。

## 根因与影响

- scripts/entities/monster.gd::_get_player只排除无玩家、玩家死亡、玩家位于休息区，不判断仇恨、Boss状态或双方距离。
- _update_boss_action的away只检查player==null或Boss自身离出生点超过leash_range。远处玩家仍存在，站在出生点的闲置Boss不会被判离场。
- 传给boss_action.update的target_valid恒为true，缺少State.CHASE/ATTACK接战门槛。BossAction按firstDelay推进倒计时，到时自然开始技能。
- _physics_process先调用_update_boss，再调用普通_update_ai；动作返回busy时跳过普通AI。因此闲置技能不仅产生无意义预警，还可能暂时拦住索敌/巡逻，表现为原地空放。
- _skill_hit仍检查固定几何、休息区和玩家有效性，所以“放了技能”不代表隔很远也必定扣血。不能把它诊断成全图必中。

第二章_update_chapter_boss已有CHASE/ATTACK及300像素触发限制，新招启动受保护；但阶段变化/召唤发生在接战检查之前，已开始预警也优先推进，需要另审生命周期，不能简单说第二章所有情况都正常。旧首章践踏有距离限制却缺少统一接战门槛，也应回归。

BossAction.update的target_valid当前只限制IDLE阶段的新动作，已开始的TELEGRAPH/GAP仍会推进。这是锁定预警与多段动作的设计，组件不能知道宿主是否真正脱战；不宜只把常量true替换成一个距离比较就结束修复。

## 推荐行为

| 状态/事件 | 建议处理 |
| --- | --- |
| IDLE/PATROL、从未接战 | 不启动技能、不消耗进战首放延迟；普通AI正常索敌 |
| 合法索敌或受到合法攻击，进入CHASE | 统一reset_for_engage，从本次接战开始首放计时 |
| CHASE/ATTACK且目标有效 | 正常技能、阶段和普攻逻辑 |
| 玩家走出本次技能图形，但战斗仍有效 | 保留已锁定预警及原几何，可躲避；不能立即跟踪转向 |
| 玩家死亡、离场或进休息区，Boss进入RETURN | 取消尚未结算动作、后续段与相关预警，禁止新招；保留原5秒归位回满规则 |
| 重新合法接战 | 重置首放、阶段动作状态；不能继承闲置期已走完的倒计时 |

接战后不宜以aggro_range作为每帧硬取消线：该范围是主动发现玩家的范围，追击与出生点牵引是另一套约束。强行统一会改变现有拉怪玩法。远离玩家但仍有有效战斗状态的Boss是否需要额外失联距离/超时，应作为单独设计，不在本次隐式增加。

## 实施节点与验证

1. 修复共享入口：只有合法接战才推进可起手的动作；普通AI仍能先完成索敌，首放计时从_enter(CHASE)开始。无目标/RETURN优先处理取消与归位，避免技能busy阻塞普通状态迁移。先通过复现回归再git commit。
2. 审核首章与第二章阶段、召唤及预警生命周期，采用同一接战语义；独立修复确有问题的分支，避免无关数值改动。验证后git commit。
3. 回归13个共享模板的未接战状态，并用代表Boss验证进入仇恨后首放延迟、CHASE/ATTACK、合法受击拉怪、玩家死亡/休息区、RETURN、再接战、多段间隙及固定预警。复核BossActionTest、BossReviewTest、BossSkillVisualTest、ChapterTwoEncountersTest、BossFieldDamageTest等；实际窗口确认闲置Boss无预警、交战Boss预警仍完整。归档结果并git commit。

新增判断应为固定数量状态/有效性检查，复用原冷却、状态机、几何和取消入口；不增加按Boss扫描全场玩家/敌人、独立定时器或每帧日志，不改技能伤害、形状、奖励或存档结构。测试必须使用隔离user目录，不能写玩家存档。临时探针与日志用后删除，不作为正式资源提交。

## 实施节点一（2026-11-02）

共享宿主仅在CHASE/ATTACK推进动作和阶段；其他状态取消异常残留动作并返回普通AI，不消耗首放计时。原无有效玩家/超出出生点牵引的5秒脱战归位路径保留。新增BossEngagementTest逐个覆盖13个共享模板：闲置/巡逻/返回、普通物理入口索敌、首放延迟、预警、目标死亡取消、归位后重新接战。BossEngagementTest与BossActionTest通过。BossActionTest原宿主夹具增加明确_enter(CHASE)，原首放/伤害/归位断言保留，属于适配合法前置条件和扩展覆盖，未放宽断言。初次隔离编辑器导入发生引擎线程崩溃，重新导入成功；新增夹具的空bossSkill类型检查已补齐。
