## 0. 四件必须先知道的事

### C-1 🔴 D-15「回收价轻缩放」目前**一行都没实现**

产品 §8 M10-8 的验收写着：

> 扣费正确、词条重掷、品质/星级/基底不变；**L60 单件回收 300–480 / L1000 5,940–9,504**；**L60 重铸 36,000 / L1000 224,000**

但 `shop.gd:204-214` 的 `sell_price()` 现在是：

```gdscript
var unit := float(base) * mult * (1.0 + float(star) * STAR_SELL_BONUS)
```

**只有 base × 品质 × 星级，没有 D-15 的 `×(1 + 0.02×(L−60))`。** 实测 L1000 装备回收 = L60 同型号，即 5,940–9,504 这条验收直接过不了。

D-15 原文（产品 13 v4 修订说明）：`回收价轻缩放 ×(1+0.02×(L−60))`。数值对得上：

| 等级 | 缩放 | 单件回收（300–480 基数） |
|---|---|---|
| 60 | ×1.0 | 300 – 480 |
| 100 | ×1.8 | 540 – 864 |
| 1000 | ×19.8 | **5,940 – 9,504** ✓ |

**这条是 M10-8 的第二件事，且最容易被漏** —— 它不在「重铸」两个字面上，但验收表里有。

### C-2 `make_equip_roll()` 是**造新装备**的函数，不能直接拿来重铸

`item_factory.gd:48-129` 一次做了 5 件事：取模板 → 算 `requiredLevel` → 掷词条 → 复制基底 → 生成新 `instanceId`。

重铸的语义正相反：**除了词条，全部原样保留**。所以必须把「掷词条」那段抽成独立函数：

```gdscript
## 按模板词条池重掷 affixes/pctAttrs；不动基底、等级、品质、星级、instanceId。
static func _roll_affixes(item_id: String, quality: String, affix_scale: float,
        rng: RandomNumberGenerator) -> Dictionary   # {ok, affixes, pctAttrs, reason}
```

🔴 **抽取的唯一硬约束：随机调用顺序逐字不变。** 现有顺序是
`randf()`（百分比判定）→ `randi_range`（选百分比属性）→ `randf_range`（百分比数值）
→ 循环 { `randi_range`（选固定属性）→ `randi_range`（固定数值） }。
把 `randf()` 挪到循环后、或把「选属性」与「滚数值」调换，**1–60 级所有掉落结果都会变**（同一存档同一时间掉落的东西不一样）。这条用固定种子快照测试锁死（见用例 14）。

### C-3 🔴 `common` 品质的词条数是 **0**，重铸它会白烧 36,000 金

`equipmentRules.json`：

| 品质 | affixCount | percentChance |
|---|---|---|
| common | **0** | 0.0 |
| uncommon | 1 | 0.0 |
| rare | 2 | 0.5 |
| epic | 3 | 0.5 |
| legendary | 4 | 0.5 |

普通品质没有词条可掷 ⇒ 重铸它 = 扣 36,000 金、装备一点没变。**必须显式拒绝**（`affixCount <= 0`），否则这是玩家会遇到的最恶劣的「花了钱没反应」。

### C-4 `c7_arena` **没有任何 NPC**，重铸必须回营地 / 城镇

实测 NPC 分布：铁匠只在 6 张图 —— `camp`（营地）、`c2_well_town`、`c3_map00`、`c4_map00`、`c5_map00`、`c6_map00`。**`c7_arena` 的 `npcs` 是空数组。**

⇒ 循环图刷出装备后想洗词条，必须先用随身车夫离开、回到有铁匠的图。随身三件套（车夫 / 商店 / 令牌）不含铁匠，这是产品口径（M10 只发三件），**本批不擅自加「随身重铸」**。在 §6 R-4 记为体验断点。

### C-5 顺带核实：重铸**不需要**动存档

`save_manager.gd` 全文没有 `affixes` / `pctAttrs` / `instanceId` 的字段级校验（grep 零命中）。重铸只改这两个数组的内容，实例的 `instanceId` / `equipmentRuleVersion` 不变 ⇒ **schema 仍 14，`_is_valid_save` 不受影响**。这是好消息，也意味着「重铸写坏存档」这类风险天然不存在。

## 1. 费用：`cost = round(baseGold × (levelBase + levelFactor × reqLv))`

产品 §6.2 / D-17：`cost = 400 × (60 + requiredLevel × 0.5)`。

| 等级 | 算式 | 值 |
|---|---|---|
| 60 | 400 × (60 + 30) | **36,000** |
| 61 | 400 × (60 + 30.5) | 36,200 |
| 100 | 400 × (60 + 50) | **44,000** |
| 1000 | 400 × (60 + 500) | **224,000** |

参数放 `data/endgame.json`（R-9 要求「实测偏多就把基数 400 调到 600」，必须可调）：

```json
"reforge": {"baseGold": 400, "levelBase": 60, "levelFactor": 0.5},
"resale":  {"levelStep": 0.02, "fromLevel": 60}
```

**实现用 `int(round(float(base) * (float(levelBase) + float(factor) * float(reqLv))))`**，不用整数除法式：
`levelFactor = 0.5` 与 `reqLv × 0.5` 都是精确的二进制小数，单次 round 无误差；而 `(×2)/2` 那种写法一旦有人把基数改成奇数就会引入截断。

缺失配置时**返回 0 并显式失败**（面板按钮禁用），不回退到写死常量 —— 否则改 json 不生效会变成静默错误。

## 2. D-15 回收价轻缩放（`Shop.sell_price`）

```gdscript
## D-15：装备回收价按等级轻缩放 ×(1 + levelStep × (L − fromLevel))，L ≤ fromLevel 时不缩放。
## 只作用于装备 —— 药水 / 杂项 / 如意没有「装备等级」概念，套上去会把 20 金药水放大 20 倍。
```
计算位置：`unit` 算出后、`× count` 前。

| 项 | 口径 |
|---|---|
| 判据 | `kind == "equip"` 且 `int(item.requiredLevel) > fromLevel` |
| 公式 | `unit *= 1.0 + 0.02 × (L − 60)` |
| 缺失 `requiredLevel` | 回退 1（`Equipment.level_req` 同口径）⇒ 不缩放，不会算出负数倍率 |
| 参数 | `endgame.json` 的 `resale`，缺失时用 `0.02 / 60` 兜底 |

⚠ **现有断言一条都不会红**：`smoke_test.gd:1686-1746` 的售价断言全部是 L ≤ 60 的装备与药水，缩放倍率 1.0。这是「改对了也不会误伤」的正常结果，不代表没改。

⚠ **溢出**：`unit` 最大约 `480 × 12（传说）× 1.4（+5 星）× 19.8 ≈ 16 万`，`× 99`（非装备不缩放，装备 count 恒 1）远低于 `int64`，无需额外护栏。

## 3. 新系统 `scripts/systems/reforge.gd`

`class_name Reforge extends RefCounted`，与 `Balance` / `Endgame` 同规格：**纯查表 + 纯计算，不引用 `GameState`**（`--check-only` 下 autoload 不可见，引了会得到假阳性）。

| 函数 | 职责 |
|---|---|
| `config() -> Dictionary` | 读 `DataLoader.get_table("endgame").reforge` |
| `cost(required_level: int) -> int` | 费用；配置缺失返回 **-1**（调用方据此禁用按钮并报错） |
| `can_reforge(item: Dictionary) -> Dictionary` | `{ok, reason}`：非装备 / 品质无词条 / 配置缺失三种拒绝，判据全部可测 |
| `resale_config() -> Dictionary` | 给 `Shop.sell_price` 用的 `{levelStep, fromLevel}` |

`can_reforge` 的拒绝文案走本地化（`msg.reforge.p001`–`p003`），不硬编码。

### 3.1 词条重掷落在 `ItemFactory`

```gdscript
## 重掷一件既有实例的词条。成功返回新的 {affixes, pctAttrs}，失败返回 {}。
## 只读 item 的 itemId / quality / requiredLevel / equipmentRuleVersion，**不改 item**。
static func reroll_affixes(item: Dictionary, rng: RandomNumberGenerator = null) -> Dictionary
```

内部：
1. `quality` ← 实例自带，缺失回退模板 `defaultQuality`（与 `Shop.item_quality` 同口径，但**不引 Shop**，避免循环依赖）
2. `dynamic` ← `requiredLevel > Balance.SOFTCAP_LEVEL`（不用 `equipmentRuleVersion`：老档实例可能缺这个字段，而等级是必有的）
3. `affix_scale` ← `affixTierScale[51] × Balance.scale(L − 60)`，**与 `make_equip_roll` 完全同一算式**
4. 调 `_roll_affixes(...)`，失败返回 `{}` 并 `push_error`

🔴 **不用 `tier_start_for_template(itemId)` 推 scale**：动态装备的实例等级由生成时决定（L1000 那件），模板所属套恒是 51。用模板套算会把 L1000 的词条砸回 L60 数值（这正是负向 N-3）。

## 4. 门面与 UI

### 4.1 `GameState.reforge_equipment(source, key, expected_id, rng)`

与 `upgrade_equipment` 同构（同签名去掉 `rune_ids`），顺序固定：

1. 定位实例 → `instanceId` 不匹配即失败（防「点了之后背包动了」）
2. `kind != "equip"` → 失败
3. `Reforge.can_reforge(item)` → 失败则原样返回原因
4. `price = Reforge.cost(requiredLevel)`；`price <= 0` → 失败
5. `gold < price` → 失败（**不扣钱**）
6. `add_gold(-price)`
7. `ItemFactory.reroll_affixes(item, rng)`：成功才写回 `item.affixes` / `item.pctAttrs`
   - 🔴 **失败必须退款**（`add_gold(price)`）—— 扣钱在前、掷词条在后的顺序天然有这个风险
   - 更稳妥的顺序：**先掷、掷成功再扣钱**（掷词条是纯函数，不产生副作用）⇒ 从根本上不存在「扣了钱没重铸」
8. emit：已穿戴 → `equipment_changed` + `player_hp_changed` + `player_mp_changed`；背包 → `inventory_changed`；两者都 toast

> 采用「先掷后扣」：`reroll` 无副作用，失败时金币与词条**双双未变**，比「扣了再退」少一条错误路径。

### 4.2 入口：铁匠服务菜单第二项

`blacksmith_panel.gd` 现在只有「升星装备」一项（`_upgrade`）。加 `_reforge` 按钮，`_show_menu()` 里同批 `visible = true`，点击 → `EventBus.reforge_panel_requested.emit()`。

`_service_card` 里的服务说明是**硬编码中文**（`"◆  装备升星\n消耗材料与金币，查看本次成功率"`），需加第二行。**建议顺手本地化**（Q-2），否则新入口硬编码、新面板全本地化，风格分叉。

### 10.4 首轮三条「假绿」的根因（必读）

答不出来就说明它测的不是你担心的那件事。
