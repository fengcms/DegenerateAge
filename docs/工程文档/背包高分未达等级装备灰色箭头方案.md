# 背包高分但未达穿戴等级装备的灰色箭头方案

本方案回应试玩中“高评分装备因等级不足没有箭头，容易被误认为不如已穿戴装备”的问题。结论：**可以直接复用现有评分比较结果实现**，不需要修改装备评分、穿戴门槛或存档结构。方案已采纳并进入实现。

## 现象与核查证据

- `scripts/ui/inventory_panel.gd::_refresh()` 已调用 `Equipment.replacement_preview()` 得到默认替换槽、候选评分、原装备评分和 `score_delta`，但设置 `upgrade_badge` 时额外要求 `Equipment.meets_level(...)`。只要玩家等级不足，即使 `score_delta > 0`，格子也没有箭头。
- 修改前 `scripts/ui/item_slot.gd` 只有布尔型 `upgrade_badge`，右上角箭头固定为绿色，无法表达“评分较高但暂不可穿戴”。
- 修改前 `tests/inventory_upgrade_badge_test.gd` 断言“等级不足时隐藏箭头”；这反映旧产品口径，而非评分算错。旧版产品文档 05 §5.8 也规定等级不足不显示。
- 已运行隔离基线 `InventoryUpgradeBadgeTest`，结果通过；测试用 Lv2 鞋验证角色 Lv2、空槽时有绿色箭头，角色降到 Lv1 后无箭头。该结果确认现象与现有规则一致，不代表灰色状态已经实现。
- 装备详情浮层由 `ItemSlot._populate_equipment_tooltip()` 渲染；当前等级不足时已有“需 LvX，当前不可穿戴”提示，但评分较高时仍可能使用绿色“更强 ↑”字样。新增灰箭头时必须同步理清这两处含义。

## 建议的产品语义

箭头只表示**按当前装备比较规则，在默认目标槽穿戴该装备后，装备评分严格增加**，不改变穿戴可行性：

| 比较结果 | 当前等级可穿 | 背包角标 | 悬停说明 |
|---|---|---|---|
| 有效装备，`score_delta > 0` | 是 | 绿色 `↑` | “评分更高，可穿戴”及默认目标槽、差值 |
| 有效装备，`score_delta > 0` | 否 | 灰色 `↑` | “评分更高，需 LvX 才可穿戴”及默认目标槽、差值 |
| 无有效目标槽、同分或低分、非装备 | 任意 | 无 | 保留正常装备属性与等级说明 |

“严格增加”沿用现有 `score_delta > 0` 且排除浮点近零的判据，不另起一套评分算法。单槽按该槽比较；戒指等双槽继续采用 `Equipment.auto_slot_for()` 选出的**默认替换槽**：先空槽，后最低品质，同品质再比评分。若一个槽空着，即使另一槽穿着更高分装备，填补空槽仍会增加总评分，灰箭头可以显示；浮层必须注明“目标槽未穿着”，避免玩家误以为新装备强过另一件。空槽且候选等级不足时同样显示灰箭头，语义是“达级后可增加装备评分”，不是“强过当前不存在的装备”。

灰箭头不是“允许穿戴”标志。双击或拖放仍执行原有等级校验并提示失败；等级达到门槛后，在下一次现有面板刷新中由灰色变绿色。颜色之外，悬停文字明确写出等级限制，避免仅靠色彩理解状态。

## 实施步骤

1. 将 `ItemSlot` 的布尔角标改为三态（无、可穿高分、等级锁定高分）；在同一右上角位置复用 `↑` 字形，按状态设置绿色或低对比但清晰可辨的灰色。状态切换须清理上一个颜色，空格和非装备不残留角标。
2. `InventoryPanel._refresh()` 只计算一次现有 `replacement_preview()`：先判断 `ok` 与正评分差，再按 `Equipment.meets_level()` 选择绿/灰。继续使用现有 `inventory_changed`、`equipment_changed`、`player_leveled` 等刷新事件，不在每帧遍历背包。
3. 调整装备详情浮层：等级不足且评分提高时，不显示绿色“更强 ↑”；改用灰色的“评分更高，需 LvX 才可穿戴”，同时保留默认目标槽、差值与完整属性卡。新增文案走 `data/localization.json`，不把固定文本写在 UI 代码中。
4. 更新 `docs/产品文档/05-装备与背包系统.md` §5.8 和 `docs/产品文档/09-UI与交互规范.md` 对角标、等级限制的描述；本方案获采纳后与实现同批提交。
5. 扩展 `InventoryUpgradeBadgeTest`：低等级高分显示灰色、升到门槛变绿色、同分或低分无箭头、空槽与双槽默认目标、换装或移走物品后刷新；并检查浮层文字与穿戴失败行为。运行装备、背包与设置缩放的相关隔离测试，实际窗口在 100%/150%/200% 比例下检查角标可见性与格内图标不遮挡。

## 成本、风险与验收边界

本次是背包 UI 展示状态扩展：数据总量为当前背包容量（初始 40、上限 200 格），只在已有刷新事件中计算；不会增加同时活动节点数量、物品实例字段、存档字段或每帧评分工作。主要风险是把灰箭头误读为“现在能穿”或把双槽的默认替换结果误读为对两个槽都更强，因此文案必须同时给出等级和目标槽。验收以“**灰色表示未来可提升，不表示当前可穿**”为准；穿戴等级和评分本身保持不变。

## 实施与验证

- 背包格角标已改为无提示、绿色可穿高分、灰色等级锁定高分三态；装备预览统一给出正评分差结果，浮层同步说明目标槽、评分差与等级要求。灰箭头不改变穿戴校验或存档格式。
- 已扩展 `InventoryUpgradeBadgeTest` 覆盖升级转绿、同分/低分、空槽、双戒指默认空槽、物品移走及等级不足穿戴失败；隔离运行 `InventoryUpgradeBadgeTest`、`EquipmentAxesTest`、`SettingsTest`、`SmokeTest` 均通过。
- 实际窗口的 100%／150%／200% 视觉检查留待玩家试玩验收；隔离测试已验证文字缩放与浮层高度的既有约束。
