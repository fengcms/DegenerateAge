# 人物面板多余高度修复与验收记录

2026-11-01。玩家截图显示人物面板内容约700像素高，外框却延伸至约1100像素，底部出现大块空白。该现象与装备适配文字重叠不同，涉及外框实际分配高度与内容最小高度的同步。

## 检查与边界

人物面板通过FloatingWindow/CenterContainer承载PanelChrome，内容通过ScrollContainer按视口限高。常规冷启动、1280×1200到1280×800再到960×640的尺寸切换，在隔离测试中能自然收缩；未完整复现玩家运行中截图的最初触发过程。旧实际分配高度或运行时界面刷新状态残留属于推断，不能把它写成已经确认的引擎缺陷。

本次在人物面板刷新后增加延迟尺寸收敛：等本轮内容变化进入布局队列后，若外框实际高度仍超过内容最小高度1像素，则重置外框与浮窗尺寸，并复用原FloatingWindow布局与边界约束。没有写死最大高度、缩小装备槽或删除提示，也不改变共享浮窗的固定分区规则。正常尺寸相等时不重新布局；窗口不置前、不重置用户拖动标记。回调只在已有数据刷新事件后执行，面板关闭时直接返回，无新增逐帧轮询或计时器。

## 验证

扩展EquipmentGapUiTest：从1280×1200冷启动，验证1280×1200、1280×800、960×640三个尺寸；人为将浮窗及外框分配高度放大到1100，再通过装备事件刷新，确认外框恢复到内容最小高度715像素。该扰动用例在旧版本容器自动排序完成后也可能自行恢复，因此不是证明原截图触发过程已复现的依据；新增处理保证刷新入口也主动清理多余实际尺寸。

继续保留提示与属性不相交、人物展示下方定位、无衰减隐藏、目标来源变化以及小窗口滚动可读断言。实际窗口EquipmentGapUiTest与PanelChromeLayoutTest均通过。已查看1280×1200渲染截图，外框贴合卡片内容，底部大块空白未出现；1280×800与960×640测试继续通过。未运行全量测试，不据此承诺整帧性能或所有运行中热重载状态均已复现。

复核入口：`python3 tools/run_isolated_tests.py --rendered EquipmentGapUiTest PanelChromeLayoutTest`。测试使用隔离user目录，不读取或写入玩家存档；临时独立检出、日志和截图在归档后删除。
