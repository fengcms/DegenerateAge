> 提出：2026-10-22。用户原话：「当前游戏，还未实现玩家从背包中，把物品拖到地面上扔掉的功能。你分析一下这个需求」

## 3. 已经现成的三块地基（不用重造）

### 3.1 拖拽链路：源、载荷、视觉都齐了

`scripts/ui/item_slot.gd`

```gdscript
func _get_drag_data(at_position: Vector2) -> Variant:
	if not [ROLE_BAG, ROLE_WAREHOUSE].has(role) or not draggable or item.is_empty():
		return null
	_spawn_drag_visual(_grab_point(at_position))
	return {"from": role, "index": index, "item": item, "token": Warehouse.item_token(item)}
```

- 载荷已带 `token`（`Warehouse.item_token`）⇒ **可以在落地时校验"拖的这 3 秒里背包有没有被整理过"**，这是防复制/防错丢的关键。
- 拖起时源格已显示为空槽（`_show_drag_origin()`），松开时 `_process` 里靠 `get_viewport().gui_is_dragging()` 收回 ⇒ **投放区可以直接复用同一个开关信号**。

### 3.2 `GroundItem` 早就为「玩家丢弃物」留了位置

`scripts/entities/ground_item.gd` 的字段注释（原文）：

```gdscript
## 生成即认领：怪物掉落 = true；**玩家丢弃物应传 false**（留地 + 60s 消失，见工程文档 10 §5）。
@export var auto_claim: bool = false
## 普通怪 / **玩家丢弃物**保持 false。
@export var persistent: bool = false
```

- `auto_claim=false` + `persistent=false` ⇒ 留地 60 秒（`LIFETIME`）后淡出，G 开启时保护期后可被靠近拾取，任何时刻可点击拾取。
- 也就是说：**地面表现、60 秒消失、点击拾取、背包满留地，全部已经写好，不需要改 `GroundItem`。**

### 3.3 死亡掉落是现成范例（照抄即可）

`scripts/systems/death_penalty.gd`：

```gdscript
var drop := GROUND_ITEM.instantiate() as GroundItem
drop.item = item.duplicate(true)
drop.auto_claim = false      # ← 玩家丢弃物同款
drop.persistent = false      # ← 60s 淡出
drop.position = layer.to_local(player.global_position)
layer.add_child(drop)
GameState.remove_item_at(index)     # ← 先保证地面容器可用，再从背包移走
```

死亡掉落已经把「玩家自己的东西掉到地上」跑通了，丢弃功能只需要把 `player.global_position` 换成鼠标世界坐标、并加上不可丢弃判定。

## 4. 缺的那一块：面板外的拖拽没人接

### 4.1 为什么必须新增一个控件

Godot 的拖放模型是：`_can_drop_data` / `_drop_data` 由**鼠标正下方的 `Control`** 接收。鼠标移出面板后下面是世界（`Node2D`），没有任何 `Control` ⇒ 松手即"取消拖拽"，引擎不会告诉你"玩家扔在了空地上"。

所以必须加一个**全屏 `Control`（下称"世界投放区"）**，它平时完全透明、不拦鼠标，仅在拖拽期间激活。

### 4.2 关键约束（都已在代码里验证过）

| 约束 | 现状 | 对实现的含义 |
|---|---|---|
| 别拦正常点击 | 战斗/行走全靠左键 | 常态 `mouse_filter = MOUSE_FILTER_IGNORE`，**仅当 `gui_is_dragging()` 为真时切 `STOP`**；松手当帧切回 |
| 别抢面板的投放 | 背包格、出售托盘、合成格都要能接 | 投放区必须排在**所有面板之前**（树序在下层），面板命中优先 |
| `settings_test` 面板矩阵 | 遍历 `UI` 下所有 `Control`，断言 `z_index == 0` 且 `size == 逻辑视口` | 新节点**默认 z_index 0** 即可；`apply_ui_scale_to()` 会自动给它设全屏尺寸 ⇒ 天然通过 |
| `DragLayer` | `mouse_filter = 2`（IGNORE）、`z_index = 4096` | 幽灵层不参与命中，投放区放它之前即可 |
| 拖到面板上不算丢 | 背包根 `mouse_filter = IGNORE`、卡片容器 `STOP` | 拖到卡片上 ⇒ 被卡片吃掉（无效投放，符合直觉）；拖到卡片外的世界 ⇒ 落到地面 |
| 松手不能触发走路 | `game.gd` 用 `_unhandled_input` 处理世界左键 | 投放区接住 drop 后事件被 GUI 消费，**不会**再走到 `request_map_move` |

### 4.3 落点坐标换算

`game.gd` 已有同款写法（L415）：

```gdscript
var world_point: Vector2 = get_canvas_transform().affine_inverse() * event.position
_player.request_map_move(_ground.clamp_to_map(world_point))
```

丢弃落点沿用 `clamp_to_map()`，再加一层「不可走格 → 退到玩家脚边」的兜底（见 Q5）。

## 5. 决策点（需要你拍板）

> 推荐项放第一位。标 🔴 的是**不选就会让功能不可用或留下真 bug** 的项。

### Q1 🔴 丢弃物会不会被自动捡回？

| 选项 | 行为 | 评价 |
|---|---|---|
| **A（推荐）丢弃物只能点击拾取** | 加 `manual_only` 标记：`GroundItem` 不参与靠近自动拾取，`AutoBattle._find_loot()` 也跳过它；60 秒后消失 | 唯一能让"扔掉"成立的做法 |
| B 丢弃后 3 秒宽限 | 3 秒内不自动拾取，之后恢复正常 | 玩家丢完站在原地不动，3 秒后照样被吸回 |
| C 沿用现有未认领语义 | 保护期 0.2 秒后即可靠近拾取 | **等于没做**：掉落物在脚边 96px 内，0.2 秒后必被捡回 |

**为什么这是硬问题（算式）**：

- `GroundItem.PICKUP_RANGE_PX = 1.5 × Iso.TILE_W = 1.5 × 64 = 96 px`
- 保护期 `hold_time = 0.2 s`
- 丢在脚下 ⇒ **0.2 秒后**若 `G` 开、玩家没走开 ⇒ `_try_pickup()` 成功 ⇒ 物品回到背包
- 且今天上线的「按 F 开战斗时一并开 G」让**挂机时 G 几乎恒为开** ⇒ 按 C 实现时，玩家丢 10 次会有 10 次被立刻吸回

产品 09 L103 现在写的是「玩家丢弃物：G 开启时靠近 ≤1.5 格自动拾取」，**与 Q1=A 冲突**，选 A 就要同步改这一句（我会一起改）。

### Q2 哪些东西不许丢？

| 选项 | 范围 | 评价 |
|---|---|---|
| **A（推荐）** | 除**任务物品**（`questItem`）、**收藏装备**（`favorite`）、**随身工具**（随身车夫/商队/追猎令牌）外都可丢 | 三类都已有现成判据，零新数据 |
| B | 只有装备可丢 | 药水/如意/材料想清理背包时还是没辙 |
| C | 全部可丢 | ❌ **会出事**：`tool_reclaim.gd` 明写「若这些工具变成可丢弃，本判据会立刻变成无限刷」；任务物品丢了会断任务链 |

### Q3 丢在地上能留多久？

| 选项 | 时长 | 评价 |
|---|---|---|
| **A（推荐）** | 60 秒（沿用 `LIFETIME`），**不落档** | 与现有未认领物一致，零新增存档字段 |
| B | 300 秒 | 体感更宽容，仍是同一个字段改常量 |
| C | 永久（`persistent = true` + 登记 `unclaimed_loot`） | 要做注销路径（C-P2-5 那条欠账）；且"丢垃圾"会长期占用地面与存档体积，不建议 |

### Q4 堆叠物丢几个？

| 选项 | 行为 | 评价 |
|---|---|---|
| **A（推荐）** | 整堆一起丢（拖的是整格） | 与"拖一整格"的心智一致 |
| B | 只丢 1 个 | 需要新的交互（右键菜单 / 数量弹窗），超出本次范围 |
| C | 弹窗问数量 | 打断感强，且要新做一个模态 |

### Q5 落点在哪？

| 选项 | 行为 | 评价 |
|---|---|---|
| **A（推荐）** | 鼠标所指的世界坐标；`clamp_to_map` 后若**不可走**则退到玩家脚边；再不行放弃并提示 | 符合"拖到哪丢哪"的直觉 |
| B | 恒定玩家脚边 | 最简单，但没有"扔远点"的手感 |

### Q6 要不要二次确认？

| 选项 | 行为 | 评价 |
|---|---|---|
| **A（推荐）** | 不确认，但**丢弃后给一条 toast**（「已丢弃：X」） | 丢了 60 秒后真没了，一条提示足够；装备本身有收藏保护（Q2） |
| B | 史诗 / 传说要确认 | 要新做一个确认框，与现有换装确认同构 |
| C | 全部确认 | 整理背包时会被打断到烦 |

## 6. 🔴 风险清单

| # | 风险 | 后果 | 对策 |
|---|---|---|---|
| R1 | **复制物品**：先 `add_child` 地面物、再 `remove_item_at`，如果 index 已被整理过 | 背包与地面各一份 | 先校验 `token`（`Warehouse.item_token`）与 `kind` 是否仍匹配该格；**先移除、再生成**；生成失败（`loot_root` 缺失）则把物品放回原格并提示 |
| R2 | **被自动捡回** | 功能等于不可用 | Q1=A：`manual_only` + `AutoBattle._find_loot()` 跳过 |
| R3 | **丢错不能丢的** | 任务链断 / 工具无限刷 | Q2=A 三道判据；判定放在 `GameState` 门面里（不依赖 UI），UI 灰显只是提示 |
| R4 | **投放区误拦点击** | 玩家点怪/点地走路失灵 | 常态 `IGNORE`；只在 `gui_is_dragging()` 为真时 `STOP`；`mouse_filter` 切换写在 `_process` 里，松手立刻回 `IGNORE` |
| R5 | **拖到面板上也落地** | 想放进背包格却丢到了地上 | 投放区排在所有面板之前（树序下层）；面板格 `STOP` 优先命中 |
| R6 | **落点不可用** | 物品落进墙里/水里，捡不到 | `clamp_to_map` + `is_walkable` 回退到玩家脚边；玩家脚边仍不可走则放弃并提示「这里放不下」 |
| R7 | **一次丢 40 件刷屏** | 40 个节点 + 40 条 toast | 丢弃提示按秒节流合并（「已丢弃 12 件」）；地面物本身有 `appear_delay` 错峰能力可复用 |
| R8 | **存档不落档被误解** | 玩家丢完退出游戏，回来发现没了 → 认为是 bug | 产品 09 明确「60 秒消失」；丢弃 toast 里写明（「已丢弃：X（60 秒后消失）」） |
| R9 | **面板矩阵断言** | `settings_test` 遍历 UI 子控件断 `z_index == 0` + 全屏 | 新节点不设 z_index、不加 group，`apply_ui_scale_to` 自动给全屏尺寸 |

## 8. 测试计划（含负向）

**正向（`DropToGroundTest`）**

1. 普通装备丢到空地：背包格清空 + 地面生成 1 件 + `auto_claim=false` / `persistent=false`
2. 任务物品 / 收藏 / 随身工具：`can_drop_item` 为 false，拖到地面**无任何变化**
3. token 失效（拖拽期间整理背包）：拒绝 + toast「物品位置已变化」，背包**一件不少**
4. 不可走格落点：物品出现在玩家脚边，且该格 `is_walkable` 为真
5. 堆叠药水（Q4=A）：整堆落地，背包格清空
6. `manual_only`（Q1=A）：`G` 开启时玩家站在 96px 内 1 秒，**物品仍在地上**
7. 点击地面物：正常入包，`manual_only` 不影响手动拾取
8. `loot_root` 缺失（极端）：`ok=false` 且背包回滚、数量不变

**负向（`tools/verify_89_drop_negative.py`）**

- N-1 去掉 token 校验 ⇒ 用例 3 变红
- N-2 `manual_only` 失效（`_find_loot` 不跳过）⇒ 用例 6 变红
- N-3 允许丢弃任务物品 ⇒ 用例 2 变红

> 命名说明：文档号取 **89**（84—88 已占，89 空缺）；负向脚本用 `verify_89_drop_negative.py`。
> 仓库里已有一个 `tools/verify_89_negative.py`（昨天的铁匠面板 2×2 版面改动，**没有对应文档**），两者靠 `_drop_` 后缀区分。
