# 启动窗口最大化与显示自动适配方案

日期：2026-11-10。本文分析当前实现和本机实测，提出待实施方案。本轮不修改游戏代码、设置或玩家存档。

## 1. 建议结论

默认在当前显示器的可用工作区内最大化启动；界面、地图和文字根据经校准的屏幕缩放参数自动确定显示百分比。用户主动设置过的项目优先使用用户值，允许逐项恢复自动。

窗口策略与元素大小分开：扩大窗口增加可见空间，不以窗口宽度持续放大人物。分辨率、工作区、系统缩放和实际视口共同参与判断，不能直接使用“2K＝100%、4K＝200%”作为通用规则。

对旧用户采用保守迁移：旧数据无法精确区分“从没修改”和“主动选择了默认值”，因此保留已保存的倍率，提供“恢复自动推荐”。这是满足“不覆盖用户自定义”的必要兼容边界。

## 2. 当前实现与根因

| 位置 | 已核对的行为 | 影响 |
|---|---|---|
| `project.godot:37–40` | 基准视口 1280×800；项目默认 canvas_items | 无窗口尺寸选择时，初始窗口沿用固定尺寸 |
| `scripts/main.gd:13`、`settings_runtime.gd::apply_display_strategy()` | 真实窗口切换为 CONTENT_SCALE_MODE_DISABLED；无头保持原策略 | 游戏视口跟随实际窗口，已有“窗口变大、可见空间增加”的基础 |
| `settings_runtime.gd:449–461` | 非全屏一律写 MODE_WINDOWED；resolution=auto 没有调整尺寸分支 | 自动不会最大化；其他设置重新应用时会撤销用户的最大化状态 |
| `settings_runtime.gd:118–128` | 显示适配 auto 固定返回 1.0 | 未读取屏幕参数选择推荐倍率 |
| `settings_panel.gd:579–583` | 任意设置改变都会 apply_all 并保存整组显示偏好 | 修改音量也可能重设窗口；偏好文件存在不代表用户修改过所有显示项 |
| `settings_runtime.gd:28–30, 59–112` | 独立文件 `user://display_preferences.json` 只记录七项值 | 已与角色进度分离，但没有版本或逐项自定义来源标记 |
| `save_manager.gd:108–121, 855–860` | 无本机偏好时导入最近角色显示设置；本机偏好覆盖角色槽 | 必须保留迁移优先级，避免新自动值抢先写入导致旧自定义丢失 |
| `settings_runtime.gd::apply_text_scale_to()` | 文字按“文字目标倍率 / UI 倍率”补偿 | 已避免 UI 与文字重复放大，应继续复用 |

现有 `displayScaleMode=auto` 仅代表统一系数为 1，并不代表 UI、地图、文字三项都没有被手动改过。不能直接据此覆盖三项倍率，也不能通过“数值是不是 100%”判断自定义。

### 2.1 本机实际测量

使用 Godot 4.7.2、macOS、GL Compatibility。先运行不含游戏服务的临时窗口探针，再在随机命名的隔离项目与 `user://` 中装配正式 Main 场景；未读取或改写玩家的真实显示偏好。

| 项目 | 实测结果 |
|---|---|
| 当前显示器索引 | 0，探针报告一块屏幕 |
| 系统显示模式报告 | 2560×1440 @ 60 Hz |
| 系统像素模式报告 | 5120×2880 |
| Godot screen_get_size | 5120×2880 |
| Godot screen_get_scale / DPI | 2.0 / 217 |
| Godot 可用工作区 | 位置 (0,60)，大小 5120×2820 |
| 初始窗口客户区 / 含装饰尺寸 | 1280×800 / 1280×864 |
| MODE_MAXIMIZED 后客户区 | 5120×2756，位置 (0,124) |
| 最大化后含装饰尺寸 | 5120×2820，与可用工作区一致 |
| 正式 Main 默认窗口 / 视口 | 1280×800 / 1280×800，content_scale_mode=0（disabled） |
| 正式 Main 默认 UI / 地图 / 文字有效倍率 | 均为 1.0 |
| 正式 Main 最大化后 | 5120×2756，UI 仍为 1.0 |
| 此后调用现有 apply_all | mode 从 2 变回 0，窗口恢复为 1280×800 |

这说明本机当前渲染坐标不能直接视为系统“看起来像”的桌面逻辑点。旧文档和注释中“系统已经全部补偿，所以自动恒为 1.0”的假设，在当前实测组合下不足以成立，应重新校准。

这些数值是操作系统与引擎报告的模式，不据此断言面板原生分辨率为 5K；缩放渲染模式可能与面板物理像素不同。当前没有实测其他 2K、4K 显示器或 Windows 平台。

## 3. 窗口策略

### 3.1 默认行为

1. 在本机偏好读取及旧档迁移完成后，识别主窗口所在屏幕，不固定使用屏幕 0，也不选所有显示器中分辨率最大的那一块。
2. 默认使用 `Window.MODE_MAXIMIZED`，让操作系统处理标题栏、菜单栏、Dock/任务栏与窗口装饰；保留普通窗口使用方式，不强制进入 macOS 全屏桌面。
3. 读取 `screen_get_usable_rect(current_screen)` 校验最终外框范围。只有最大化不受支持或结果异常时，才按工作区计算窗口位置和客户区，并扣除实际装饰尺寸。不能直接把工作区大小当成客户区大小。
4. 取得稳定客户区尺寸后，再应用画面与 UI 布局，避免初始化先后顺序引起重复跳变。
5. 启动窗口策略只执行一次；切图、返回主菜单、调整音量或修改字体不重新最大化，也不撤销玩家当前手动调整的窗口状态。

最大化和全屏在 Godot 中是不同模式；最大化保留窗口装饰并排除任务栏，全屏占满显示区域，macOS 下会使用新桌面。[Godot Window 模式说明](https://docs.godotengine.org/en/latest/classes/class_window.html#enum-window-mode)

### 3.2 用户窗口选择

| 偏好 | 启动行为 |
|---|---|
| 自动／最大可用窗口（新默认） | 当前屏幕工作区最大化 |
| 用户选择的固定尺寸或明确保存的自定义尺寸 | 恢复该尺寸，当前工作区放不下时临时夹紧并移入可见区域 |
| 用户选择全屏 | 保持全屏偏好 |
| 旧 resolution=auto 且 fullscreen=false | 迁移为最大可用窗口；旧“自动”没有固定尺寸承诺 |
| 旧固定 resolution 或 fullscreen=true | 保留对应窗口偏好 |

缩放自定义与窗口自定义独立：例如 UI 手动 150%、窗口仍为自动，则启动时最大化，UI 保持 150%。

第一版不把任意窗口拖拽自动写成长期偏好，避免系统布局变化或程序最大化被误认作用户选择。拖拽结果本次会话有效；希望下次记住时，通过设置中的“使用当前窗口尺寸”显式保存。选项文案应写“启动窗口”，明确仅影响启动与主动应用窗口设置。

编辑器嵌入运行、无头测试分别处理：嵌入窗口尊重宿主，不操纵编辑器外框；无头跳过屏幕查询和真实窗口策略，保留既有测试视口。

## 4. 自动百分比策略

### 4.1 一份屏幕快照，一套有效倍率计算

采集当前屏幕索引、引擎报告的屏幕尺寸、可用工作区、系统缩放、DPI、主窗口客户区与视口尺寸、内容缩放模式。DPI 只作辅助，不作为唯一依据；Godot 官方说明 macOS 非整数显示缩放时 DPI 可能不准确。[DisplayServer 的 DPI 与屏幕缩放说明](https://docs.godotengine.org/en/latest/classes/class_displayserver.html#class-displayserver-method-screen-get-dpi)

建立“渲染单位相对于桌面逻辑点的补偿系数 D”：

- 当前实测 macOS + disabled 路径：视口按高密度像素计数，D 候选为屏幕 scale，本机为 2.0。
- 若其他平台/渲染模式已经在视口层做了逻辑点补偿，则 D=1，不能再乘系统缩放。
- 平台信息不可靠或互相矛盾时使用保守 100% 并提供手动设置，不从显示器名字猜测物理尺寸，不在游戏启动时调用耗时的 `system_profiler`。
- 读数必须有限、为正且在合理范围；无效读取不得把零、NaN 或极端值传入 Camera2D 或 CanvasLayer。

**不能仅以“视口尺寸等于窗口尺寸”推导 D**，还需平台/HiDPI 坐标约定及对应实机校准。本机测量支持 D=2 的实现方向，不能自动推广到所有后端。

分辨率用于显示诊断信息和布局容量检查；“2K/4K/5K”可以作为解释性标签，不作为唯一计算分支。建议设置页直接显示“当前渲染尺寸、系统缩放、可用窗口、推荐百分比”，避免把缩放后的渲染模式误标成物理屏幕型号。

### 4.2 三项继续独立

| 项目 | 自动推荐起点 | 显示范围 |
|---|---|---|
| 界面大小 | 根据 D 选择推荐百分比 | HUD、按钮、背包、菜单、独立弹窗 |
| 地图显示大小 | 根据 D 选择推荐百分比 | 人物、怪物、地形与技能预警表现 |
| 文字大小 | 根据 D 选择推荐百分比 | UI 文字、头顶文字、飘字、悬浮提示 |

首版推荐值按现有档位取近似值，限制在现有 80%–200% 范围；文字默认不低于 100%。大于当前可表达范围的设备先安全封顶并允许手动调整，不在本次需求中无证据扩大所有控件范围。

下表是**规则示例与候选效果，不是新增实机验收结果**：

| 屏幕/系统条件 | 已验证坐标口径下的 D | 自动三项起点 |
|---|---:|---:|
| 2560×1440，系统 100%，一逻辑点对应一渲染单位 | 1.0 | 100% |
| 3840×2160，系统 150%，视口尚未补偿 | 1.5 | 150% |
| 3840×2160，系统 200%，视口尚未补偿 | 2.0 | 200% |
| 本机报告 5120×2880、逻辑模式 2560×1440 | 2.0 | 200% |
| 高分屏但游戏视口已完成密度补偿 | 1.0 | 100%，不重复补偿 |

因此同为 4K，推荐值可以不同。4K 配置系统 100% 也不应被未经校准的规则强制改成 200%。如果后续实机表明系统默认仍不舒适，应单独校准推荐档位，而非叠加第二个分辨率倍率。

百分比继续以现有游戏渲染基准表达，例如“自动（当前推荐 200%）”。自动值运行时计算，不写回用户手动值。玩家主动选 150% 后显示“手动 150%”，不会再在背后乘一遍自动 200%。

UI 200% 与文字 200% 的最终字形仍是 200%，继续使用现有文字/UI 反向补偿；世界文字同样沿用文字/地图补偿。主菜单背景仍按窗口铺满，无需按倍率重新生成图片。

同一屏幕内拖动窗口尺寸只重排布局，不随窗口宽高不断重新计算人物大小。跨屏或系统缩放变化时才更新自动项；手动项保留原值。画面倍率只影响显示，不修改实际碰撞、移动速度、技能伤害与地面预警判定。窗口更大后自然出现更多可见候选，须保留当前游戏已有的可见性、自动搜敌和射程规则，不额外提高刷新预算。

## 5. 自定义保护与旧数据迁移

### 5.1 新偏好记录

继续使用本机 `display_preferences.json`，不另建第二套配置文件，不把屏幕状态写入角色成长存档。为文件增加独立版本及来源元数据，旧七个字段保留为手动值/兼容值：

- `version: 2`：本机显示偏好格式版本，与角色存档 schema 分开。
- `windowPolicy`：自动最大化、固定/自定义窗口、全屏。
- `scaleSources`：uiScale、mapScale、textScale 分别记录 auto 或 manual；迁移期间可有 legacy 状态，表示按旧公式保留。
- 自定义客户区尺寸仅在显式保存时记录，加载时校验范围。屏幕索引只用于本次解析，不把不稳定索引作为永久设备身份。
- 自动推荐值、当前屏幕工作区、D 和有效倍率放运行态缓存，自动重算不写入手动来源标记。

设置面板的变更入口应携带具体字段名：修改音乐不标记任何显示自定义；修改 UI 仅把 UI 改为手动；用户即使主动选 100%，仍然记录 manual。

原有高级“手动显示适配系数”保持兼容：旧项按原来的“三轴原值 × 手动统一系数”精确保留，不再叠加自动 D。用户主动改这个全局高级系数时，明确切换整组三轴为手动；逐项恢复自动时，该项改用推荐值，设置页显示实际生效百分比以免混淆。实施时需要同步原有倍率上限组合测试，不能静默压低旧的 200%×150%=300% 效果。

### 5.2 迁移优先级

1. 已有 v2 本机偏好：严格按逐项来源执行。
2. 已有旧版本机偏好：已有合法三轴值按 legacy 保留，包括 100%；保留旧高级系数的有效结果。只对真正缺失项启用自动。
3. 无本机偏好、有最近使用的有效旧角色：先沿用当前入口迁入其显示设置，再标记 legacy；不能先保存自动默认值而阻断迁移。
4. 全新安装或无可迁移数据：自动窗口、自动 UI、自动地图、自动文字。
5. 用户点击某项“恢复自动”或“全部使用推荐”：仅改变指定来源与当前有效值，不修改其他设置、角色进度或存档槽。

旧版曾在修改音量时写入全部显示默认值，也可能在角色迁移时补齐默认值，因此无法百分之百恢复用户曾操作过哪些项。优先保留比猜测后覆盖更符合本次要求。此限制应在升级说明中说明；不能宣称所有旧用户都能准确识别“从未自定义”。

读取另一角色、导入别人的存档、新建角色与返回主菜单都不改变已存在的本机来源配置。损坏偏好应校验并保留可诊断副本，不能影响角色存档可用性；写入仍使用临时文件加原子替换，并检查失败结果。

## 6. 工程组织与成本

- `SettingsRuntime` 继续作为唯一应用入口，集中解析“手动/自动/兼容”有效值；UI、相机和世界文字继续走既有接口，不在每个面板自行读屏幕。
- 拆开启动窗口策略、用户主动修改窗口设置、常规 UI/音频设置应用；避免 `apply_all()` 无条件设置 WINDOWED 的现有问题。
- 在 `Main` 首次启动且本机偏好迁移完成后应用窗口策略。持有会话级已初始化标记，切图场景重建不重复执行；必要时增加轻量启动协调步骤，但不为此引入全新全局设置服务。
- 设置与存档校验的合法键和值域同步维护；来源元数据留在设备偏好层，不误用角色 settings 中现有字典校验规则。
- 屏幕快照缓存由显示设置模块持有；在启动、跨屏、DPI/系统缩放变化、屏幕移除和用户恢复自动时失效。优先采用当前引擎支持的窗口/DPI 通知；缺少跨屏信号的平台可在聚焦/窗口变化时检查屏幕，必要时低频检查一次，不逐帧枚举全部屏幕。
- 一次查询当前屏幕并 O(1) 解析三轴；布局按现有同帧合并入口重排，保持防重入保护。更新布局不得重载世界或重新随机选择主菜单背景。
- 不读取全部纹理尺寸、不逐实体重新载入美术，不添加渲染目标或放大图集。唯一新增持久数据为少量偏好字段。
- 最大化会增加渲染成本。本机 5120×2756 相对 1280×800 的像素数量约为 13.78 倍；按单张 RGBA8 全尺寸表面估算约 53.8 MiB，相对约 3.9 MiB。只是尺寸换算，不是总显存或帧率实测；UI/地图倍率不会减少窗口的实际渲染像素。
- 宽视野可能增加可见实体，正式验收需测密集战斗的整帧 P95/P99、绘制调用及纹理内存。不能通过缩小技能判定或减少奖励换性能；渲染分辨率调节属于独立后续功能。

## 7. 分节点实施与验收

| 节点 | 实施范围 | 通过标准 |
|---|---|---|
| 一：偏好来源与迁移 | v2 本机配置、逐项来源、旧值保护、恢复自动入口 | 手动 100% 仍受保护；修改音量不改变来源；跨档不覆盖；坏文件安全处理 |
| 二：启动窗口 | 工作区最大化、固定尺寸/全屏优先、一次性启动与重入保护 | 无 Dock/标题栏遮挡；不会把窗口放到已移除屏幕；改音量/切图不改变窗口 |
| 三：自动倍率 | 平台坐标校准、三轴有效值、现有文字与弹窗补偿复用 | 本机先完成 100/200% 对照；UI、地图、文字独立；手动与自动不会重复相乘 |
| 四：实机与性能 | 多比例、跨屏、菜单/Boss/HUD/弹窗、密集战斗 | 点击与画面同位、布局可用、背景不换图、资源不持续增长；记录性能数据 |

每个节点完成验证后单独 git commit，不在方案阶段修改运行行为。

最低测试矩阵：

- 全新偏好、旧全默认、旧非默认、手动统一系数、缺字段、非法数字、损坏文件和无权限写入。
- 主菜单→设置→新建/读取→世界→暂停→返回主菜单，跨角色保留本机偏好。
- 2K/100%、4K/150%、4K/200%、本机像素模式/200%；算法用合成输入测试，硬件实机结果另行标注，不能把合成测试称为多屏实测。
- 同屏拖大窗口、最大化恢复、全屏切换、跨屏、屏幕断开、菜单栏/Dock 工作区变化、编辑器嵌入与独立导出运行。
- 四位等级、三 Boss 同屏、技能栏与小地图避让、背包/商店、文字长标签、原生文件选择器、Tooltip、伤害数字和地面技能预警。
- 同屏同倍率扩大窗口时，元素尺寸保持稳定；自动倍率发生实际改变时，目标点击、拖放和地面判定继续与画面对齐。
