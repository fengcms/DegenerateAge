# 96 · 保星产物「暂时穿不上」的提示方案

> 状态：**已定案 / 已实施**（2026-10-23；Q1 = B、Q3 = 做，见 §8 与 §11）
> 触发：用户原话 ——「当玩家使用保星升级的功能的时候，如果升级后的装备，是玩家暂时穿不上的，要提示一下玩家。你给我一个方案。」
> 前置：工程 64（保星跨档）、工程 65（保星面板并开人物 + 身上件拖入）、D-21（十级一套）、D3（产物永远进背包）。
> 数据源：用户真实存档 `slot_3`（2026-10-23 16:00 快照，**Lv154** / 14 件 12★ 紫 / 背包 8 件 0★ 紫全在 155—160）。
> 本方案**只改提示与一个等级口径函数**，不改保星规则、不改产物落点、不改价格。

---

## 0. 结论先行

**提示已经有了，但出现的位置不对。**

`equipment_fusion_panel.gd:498—501` 现在就有一段：

```gdscript
var required := int(plan.get("required", 0))
if required > int(GameState.player.get("level", 1)):
    _summary.text += "\n" + Localization.tr_key("ui.fusion.out_level", ...)
```

它只在**选完两件材料、还没点按钮**这一段存在。而保星是**二次确认**流程，玩家真正做决定是在第二次点按钮那一刻；成功后 `_reset_materials()` 会把预览区和反馈区一起清空，只剩一条「合成成功：%s」。

所以你的体感是对的：提示在，但**在玩家做决定的那一刻和拿到手的那一刻都不在**。

---

## 1. 需求拆解

| 编号 | 需求 | 语义 |
|---|---|---|
| **A** | 产物穿不上时要提示 | 「穿不上」= `player.level < 产物.requiredLevel` |
| **B** | 提示 ≠ 拦截 | D3 已定「产物永远进背包」，跨档保星本来就是**为下一档准备**。提示是告知，**不得禁用按钮** |

---

## 2. 「穿不上」是常态，不是例外

这是本方案最重要的前提。保星跨 1 档 = 产物档 **+10 级**，而玩家此刻刚满当前档：

| 场景 | 旧件 | 新件 | 产物等级 | 玩家 | 缺口 |
|---|---|---|---|---|---|
| 跨 1 档 · 武器 | 151 档 12★ | 161 档 0★ | **161** | 154 | **差 7 级** |
| 跨 1 档 · 项链 | 151 档 12★ | 161 档 0★ | **170** | 154 | **差 16 级** |

按部位（`slot_offset` 0—9）铺开，**同一次保星十个部位的等待期差 2 倍以上**：

| 部位 | 产物等级 | 还差 |
|---|---|---|
| 武器 | 161 | 7 |
| 鞋 | 162 | 8 |
| 甲 | 163 | 9 |
| 头盔 | 164 | 10 |
| 护腕 | 165 | 11 |
| 护膝 | 166 | 12 |
| 盾 | 167 | 13 |
| 手镯 | 168 | 14 |
| 戒指 | 169 | 15 |
| 项链 | 170 | 16 |

**结论**：跨档保星**每一次**都会穿不上，缺口 7—16 级。这不是边缘场景，是主路径。所以提示不能靠「一行灰字 + 玩家自己发现」。

## 4. 方案

### P1 · 预览行升为独立高亮行（不再拼进 `_summary`）

新增 `_out_level: Label`，只在保星模式且穿不上时显示，橙色 `ffbd88`（与 `_feedback` 同色，与「警告」而非「错误」对齐）。

```
产物需 Lv161，你当前 Lv154 —— 还差 7 级才能穿。
```

**为什么另起 Label 而不是给 `_summary` 变色**：`_summary` 一个 Label 在保星模式下同时承载「预览 / 跨档数 / 费用 / 需求等级」三到四行，四金、四紫定向、四紫升紫也在用它。改颜色会波及另外三个模式，收益全在保星，风险外溢。

**位置**：`root` 里插在 `_summary` 之后、`_feedback` 之前（注意 `_star12` 被 `move_child` 挪到了 `_summary` 之前，不能按加入顺序推）。

### P2 · 二次确认里追加一条（这是最关键的一处）

`_on_confirm` 的 `lines` 数组里追加，与「两件原装备及词条都会消耗」同级：

```
产物需 Lv161，你现在 Lv154：会进背包，等 7 级后穿。
```

🔑 **必须加进 `lines` 再统一 join**，不能直接改 `_feedback.text` —— 那段代码末尾是 `_feedback.text = "\n".join(...)`，先赋值会被覆盖（R4）。

### P3 · 成功 toast 加短后缀

`合成成功：破军之刃` → `合成成功：破军之刃（需 Lv161，7 级后可穿）`

🔴 **只加短后缀**：`hud.gd:201` 的 toast 是单行 Label，**没有 autowrap**，超长会横向溢出屏幕。详细说明留在 P2，toast 只负责「让你想起来有这回事」。

### P4 · 身上件被吃 + 产物穿不上 = 叠加警告

工程 65 允许第一格从人物面板把**身上那件**拖进来。这个组合下：旧件被消耗 → 该部位空出 → 产物又穿不上 → **该部位净空一件，且无法回补**。

现有 `ui.fusion.worn_warning` 只说「该部位将空出，产物进入背包」，没说「而且你穿不回去」。

做法：`has_worn && !can_wear_after` 时换成强化文案：

```
%s 正穿在身上，合成后该部位会空出来，而产物要 Lv161 才能穿 —— 这段时间你会少一件装备。
```

这是本方案里唯一会**掉战力**的组合，值得单独一条。

### P5 · 口径加固：产物等级用产物算（不是用材料算）

`plan_transfer` 现在返回 `"required": int(new_item.get("requiredLevel", 0))` —— 这是**材料**的等级。产物是 `make_output(tier, kind)` 现造的，等级 = `dynamic_tier_start(tier) + slot_offset(kind)`。

两者在「同档同部位」时相等，靠的是隐含前提。**旧档 v4 / 逐级实例**进来就会差 1—9 级：
- 材料 115 级武器（旧规则逐级件）→ `suit_start(115)=111` → 产物 111，而预览说 115（**多报 4 级**）
- 材料 101 级鞋 → 产物 102，而预览说 101（**少报 1 级，玩家到手才发现穿不上**）

**当前真实存档实测 0 件不一致**（`slot_2` / `slot_3` 全部 v5 且落在 T 序列），所以**这不是现存 bug**，是口径加固。

新增纯函数：

```gdscript
## 保星产物的实际穿戴等级；与 make_output 同口径，不造实例、不吃 RNG。
static func transfer_output_level(tier: int, kind: String) -> int:
    var template_id := template_for(tier, kind)
    if template_id.is_empty():
        return 0
    return ItemFactory.dynamic_level_for(template_id, tier)
```

`plan_transfer` 增返 `"outputLevel"`，**`required` 保留原义**（既有断言与 UI 都读它，改名会静默断链）。UI 改用 `outputLevel`。

### 11.2 两处比方案更稳的做法

1. **成功 toast 读产物实际等级，不读预览时的预估值。** 方案里 P3 原打算复用 `locked_level`；实现时改成 `Equipment.level_req(result.item)`。理由：万一口径哪天漂了，toast 也必须说真话 —— 它是玩家唯一能看到的「事后凭证」。
2. **`_refresh_preview` 开头统一清空 `_out_level`，而不是在保星分支里清。** 因为切服务（保星 → 四金）走的是同一个 `_refresh_preview`，只在保星分支清会让上一轮的橙色提示留在四金界面上。

### 11.3 断言写歪过一次（已修）

用例 4 / 8 初版断 `contains("需 Lv141")`，而文案是「而产物**要** Lv141 才能穿」—— 断言直接红。教训与工程 08 第 32 条同族：**断文案时锚点必须是文案里真实存在的片段**，别按自己心里的措辞写。修法是把断言缩到 `contains("Lv141")` + 独有短语（`少一件装备`）两段夹逼，既不依赖单个字的措辞，也不会被「碰巧含有 Lv141」骗过。

**既有测试也会红，且必须改到新位置而不是删。** 第一次跑默认集时 `EquipmentFusionUiTest` 挂了 —— 它断的是 `panel._summary.text.contains("暂时无法穿戴")`，而我正好把提示从 `_summary` 搬到了 `_out_level`。这条不是「过时断言」，是**同一个需求的旧锚点**，所以改成断新位置 + 补一条「`_summary` 里不该再有它」（这才锁住「搬走」这件事）。同时给那条用例显式钉了 `GameState.player["level"] = 1`：它的前提是「产物高过玩家等级」，而默认等级一旦变化这条前提会静默失效，断言就变成空转。
