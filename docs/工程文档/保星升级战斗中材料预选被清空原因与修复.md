# 保星升级战斗中材料预选被清空：原因与修复

日期：2026-10-30。

## 现象与复现证据

随身铁匠的保星升级允许后台继续战斗。玩家把身上的12星旧装备拖入第一格后，击杀怪物或随后拾取时，原预选可能被清空，需要重新拖入。

已用隔离项目的 EquipmentFusionUiTest 复现：穿戴12星武器→打开保星升级→通过真实穿戴拖拽载荷放入旧装备格→调用 GameState.wear_equipment("normal")。修复前稳定出现两项失败：

- 「击杀磨损后保留穿戴材料预选」失败。
- 「耐久变化同步到预选快照」失败。

单纯拾取不是必须条件。已复现的直接触发是击杀磨损；“拾取与清空时间接近”由击杀和掉落流程相邻解释，不能将用户对拾取的猜测直接当根因。

## 根因与影响范围

`autoload/game_state.gd::wear_equipment` 每次击杀按怪物类型降低身上装备耐久，然后调用 `_after_equip_change`，连续广播 equipment_changed 和 inventory_changed。随身工作台不暂停自动战斗，这些变化属于正常游戏行为。

`equipment_fusion_panel.gd::_on_material_dropped` 原本保存整份物品深拷贝。`_revalidate_selection` 收到上述事件后，用 instanceId 找到当前物品，再直接比较整份字典。只要耐久从800变成799，当前装备就与预选快照不相等，代码将该材料格设为空，并提示材料已变化。

相同问题也存在于拖动途中：`_source_equipped` 和 `_source_item` 用整份载荷快照比较，拖拽期间发生磨损或修理，会误拒绝仍是同一件装备的载荷。修理会把耐久增加回上限，同样触发问题。

主要影响从身上拖入的保星旧装备。共享合成面板对其他背包材料仍需检查真实内容变化，不能全局改成“只认instanceId”。身份相同但收藏、星级、词条、重铸解锁标记等已经改变，仍必须撤销旧预选。

## 修复方式

在合成面板增加 `_same_material_except_durability`，只排除 durability 字段，其余字段完整比较：

1. 两份字典原本相等时直接返回，不额外复制。
2. 内容不同且均为装备时，在局部副本上仅移除 durability 后比较。
3. 仅耐久发生变化时，保留材料选择，并将当前完整物品重新深拷贝进预选，保证预览和最终结算使用最新快照。
4. 物品不存在或其他字段改变，继续清空对应格，沿用原提示。
5. 拖拽入口使用同一比较方法；仍检查原背包下标/穿戴槽、instanceId token 和材料资格。成功放入时取当前完整实例，不沿用旧耐久。

没有修改 GameState.forge_equipment 的严格终验：提交时仍要找到当前物品并与完整材料快照一致。没有修改磨损、修理、战斗、掉落或自动拾取逻辑。物品和金币变化后取消旧风险确认的现行行为继续保留；这只会要求重新确认消耗，不会要求重新拖入耐久变化的材料。

## 回归结果

隔离测试四项通过：EquipmentFusionUiTest、EquipmentFusionTransactionTest、StarTransferLevelHintTest、FullStarReforgeTest。

新增覆盖：

- 随身模式穿戴旧装备在普通怪击杀磨损后保持预选，并同步最新耐久。
- 已经开始拖动的载荷遇到耐久变化，仍能放入同一件装备。
- 修理后保持预选，完整快照同步满耐久。
- 通过真实 pickup_loot 拾取无关药水不清空材料。
- 同时变化耐久和收藏/星级/第五词条标记，仍被识别为材料变化。
- 首次确认后再次发生Boss击杀磨损，两件预选仍保留，但旧风险确认失效；重新确认后成功完成保星，穿戴槽清空、金币扣一次、产物进入背包。
- 既有装备丢失/换掉、过期拖拽载荷、重复材料和升星变化撤销预选的断言继续通过，没有放宽既有安全校验。

测试采用现有隔离项目运行器并要求完整成功标记；短异步用600帧退出上限，未修改正式测试运行器。最终随身模式新增断言复跑通过。没有运行完整长时间挂机试玩，结论基于实际业务事件、UI回调和真实结算的定向回归。

## 运行成本与复核方法

没有新增逐帧扫描、定时器、缓存或长期对象。仍只在背包/装备事件发生时检查最多4格材料；保星有效材料最多2件。查找容器路径不变。内容相等直接返回；耐久变化时短暂建立比较副本和新预选副本，随同步调用结束释放。未做整帧性能对照，不声明FPS变化。

玩家复核：自动战斗中打开随身铁匠→保星升级，放入身上旧装与背包新装，等待几次击杀和拾取，检查材料仍在；尝试修理和拖动期间击杀；最后重新确认合成。另换掉/移走真正被选中的物品，检查旧预选仍按规则失效。
