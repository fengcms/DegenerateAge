# 主菜单随机背景实施记录

用户已确认三张候选全部接入，要求每次启动随机使用其中一张。本次只调整进入游戏前的背景表现，保留暂停菜单、存档和设置原有操作。

## 节点一：素材与主菜单接入

- 新增 `assets/ui/menu_backgrounds/` 三张运行纹理及来源、规格、重建方式说明。源稿继续保留于对应设计目录；导出排除设计文档，只打包运行素材。
- 新增 `scripts/ui/main_menu_background.gd`，在 `scenes/Main.tscn` 的 HUD 与业务面板之间加入背景。设置/存档打开时菜单按钮会隐藏，背景仍然显示。
- 首次进入菜单用独立随机源等概率抽取路径，保存在本次 SceneTree 的 `main_menu_background_path` 元数据中。场景重载、切图、新建存档及返回主菜单均不重抽；退出进程后自然重置。随机允许相邻两次启动重复，不写入存档，也不影响战斗全局随机序列。
- 主菜单遮罩透明度由 0.84 改为 0.16，让已确认插画可见；暂停菜单继续使用 0.84 的原遮罩，背景隐藏。
- 按原图比例铺满、居中裁切，不拉伸。先前设计文档提出的扩图路线在本次改为保留用户确认的原图；16:10、16:9 会裁上下边缘，窄窗口裁左右边缘。
- 只加载选中的一张图片，三张总原图约 7.13 MiB，单张按 RGBA8 估算约 6.00 MiB。纹理由背景节点持有，进入世界释放引用；路径保留到进程结束。没有新增逐帧扫描或动画，窗口布局复用现有 SettingsRuntime。实际显存随导入/平台变化，不作 FPS 提升声明。
- 缺失素材时保留不透明深色底，并记录资源路径；不让游戏地图透出。

验证：Godot 无头编辑器导入成功；隔离 `user://` 下 `MenuFlowTest`、`SettingsTest` 通过。菜单测试覆盖新建、暂停、设置返回、继续和读档；不修改玩家真实存档。

## 节点二：表现与生命周期复核

- 新增 `MenuBackgroundTest`：检查独立随机源不消费玩法随机序列、选择属于素材清单、节点重建保留本次选择、三张图片导入尺寸、显示层级、背景铺满、窗口变化不重载纹理、设置/存档保持背景、暂停/恢复释放背景引用。
- 扩展已有 `MenuFlowTest`，通过真实新建、继续、读档及返回主菜单检查重载后的纹理状态与选择一致性。属于扩展覆盖，没有放宽旧断言。
- 实际窗口复核三图 × 1280×800、1600×900、1024×768 共九种组合，并检查设置、新建/读取存档与暂停画面。主菜单按钮清晰，插画没有拉伸、黑边或地图透出；守护者在常用宽高比保留人物主要轮廓，边缘仍会依比例裁切。
- 80%、100%、150%、200% UI 缩放下验证背景变换后覆盖完整视口；此断言只针对背景覆盖，不代表本轮重新验收所有业务面板的极端缩放布局。
- 首轮实际截图发现黄色“抵达幸存者营地”提示越过背景叠在菜单标题上：根因是 `scripts/world/game.gd::_notify_arrival()` 无条件发送事件，HUD 的 ToastBox 使用较高绘制层级。修复为仅在 `world` 模式发送抵达提示，不修改 HUD 错误提示通道。补充菜单无抵达、世界仍有抵达、菜单错误提示仍可见的双向回归；修复后再次实际渲染确认。
- Godot 4.7.2、GL Compatibility 下，隔离 `MenuBackgroundTest`、`MenuFlowTest`、`SettingsTest`、`FlowFeedbackTest` 均通过，其中前两项同时完成无头逻辑与实际窗口运行，FlowFeedbackTest 在实际窗口通过。
- 使用现有 `Mac OSX` 导出预设生成 PCK，在不含游戏 Autoload 的临时隔离项目中挂载，三张纹理均能加载为 1402×1122，设计目录源稿未进入导出包。此项验证资源打包，不等同于签名 macOS 应用的发布验收。
- 临时截图、探针和导出验证包均不入库，检查后删除；没有改动真实玩家存档或博客工作区修改。
