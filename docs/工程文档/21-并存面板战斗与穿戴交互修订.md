# 并存面板战斗与穿戴交互修订

> 2026-10-13 试玩反馈；对应产品 03 §3.14、05 §5.8、09 §9.2。

## 行为边界

1. 背包、人物、技能、坐骑四个常驻浮窗不绘制全屏暗色遮罩；其他模态窗口维持各自遮罩。浮窗仍拦截本体鼠标事件与手动地图指令。
2. F 自动战斗开启时，打开任何界面面板不停止自动移动、寻怪、攻击和喝药，也不冻结手动接管倒计时。真正暂停、死亡或关闭 F 仍按原规则处理。面板打开时键鼠输入不能误触发角色手动动作。
3. 人物面板左侧为 7×2 个装备图标槽围绕人物立像，右侧继续显示战斗属性；背包只保留物品格、整理和金币。素材不足的槽位用代码绘制品类轮廓标识，装备实例与等级规则仍取数据表。
4. 穿戴 / 卸下的拖放和装备双击只在人物与背包同时打开时可用。背包拖到匹配人物槽使用现有装备交换事务；人物拖到背包空格时卸至指定格，失败不丢物。双击背包装备自动选槽；双击已穿戴装备卸至首个空格。药水 / 回城卷双击使用保持原行为。
5. 地图人物头顶常显人物名称，随实体绘制而非屏幕 HUD 定位。

## 节点与验收

| 节点 | 准出条件 |
|---|---|
| A 浮窗与战斗 | 四窗叠开无变暗；自动战斗开面板后仍有移动和攻击；暂停仍停止 |
| B 面板布局 | 背包无穿戴和属性副本；人物 14 图标槽围绕立像，右侧属性保留 |
| C 装备交互 | 两窗并开拖入、拖出、双击成功；单窗装备双击无效；等级 / 类型 / 满包失败原物保留 |
| D 世界名字 | 人物头顶显示存档名称，缩放和行走时位置稳定 |

每节点完成后单独提交 Conventional Commit。回归运行 Godot 导入、SmokeTest、ChapterOneAcceptance、ReviewRegressionTest；原生试玩重点检查 4K 倍率下槽位命中与拖拽视觉。
