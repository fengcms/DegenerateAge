# 98 · 法师职业与远程法术体系方案

> 状态：**待拍板**（方案已出，未动任何代码）
> 需求原话：「当前只有武士这一个职业，是否可以增加法师职业，远程法术攻击，高蓝低血。我希望这个职业要有自己的特色，可以参考传奇游戏的风格，同时，维护职业平衡，你给我一个方案。」
> 边界：**只做「第二个职业」**，不重做战斗公式、不改装备三轴模型、不做职业专属装备经济、不做转职。
> 参照基准：本文所有数值都基于 **158 级真实存档快照**（`slot_3`，2026-10-23 探针复算，见 §4.1），不是估算。

## 1. 现状盘点

### 1.1 项目里其实没有「职业」这个概念

全代码库搜不到任何职业字段、职业分支或职业界面。现在的「武士」不是一个被命名的职业，而是**唯一一套写死的玩家规则**：

| 位置 | 现在写死的东西 | 影响面 |
|---|---|---|
| `skills.json` | 6 条技能，无归属字段 | 技能面板遍历全表 → 加新技能会直接出现在所有人眼前 |
| `HotbarConfig.ACTIVE_SKILLS` | 6 个硬编码 id | 快捷栏校验、`player.request_skill`、`cast_skill` 三处共用 |
| `player.gd::melee_range_px()` | 恒等于普攻 `range`（1.0 格） | 普攻、超距接近、自动战斗停步、寻敌，**四处共用** |
| `GameState` 派生 | `max_hp()` / `max_mp()` 无职业系数 | 血量、蓝量、保底伤害、药水百分比恢复全部跟着走 |
| `default_player()` | 无 `classId` | 存档无职业字段 |

**结论**：不是「加一个职业的数值」，而是要先补一层「职业框架」，否则第二个职业会以「同一套规则换个名字」的方式落地。

### 1.2 传奇式法师的三个硬约束（本项目物理限制）

用户要「参考传奇风格」，但本项目有三处与传奇不同的物理事实，必须正面处理：

| 传奇做法 | 本项目现实 | 后果 |
|---|---|---|
| 法师靠走位风筝，站远端输出 | 挂机 ARPG，自动战斗**不会风筝**，怪物贴身就打 | 远程只兑现「先手」，不兑现「安全」→ 低血必须另有补偿 |
| 魔法盾用蓝抵伤害，蓝=第二条血 | 蓝药按 `maxMP × 百分比` 恢复，装备把 MP 堆到 5.9 万 | 盾必须**按伤害比例转蓝**，不能按固定值，否则毫无压力 |
| 法师技能耗蓝按固定值 | 武士 6 技能蓝耗 15—60 点，对 5.9 万蓝池 = 0 | 法师蓝耗必须按 **maxMP 百分比**，否则「高蓝」是空话 |

### 1.3 一个必须先说清的坑：本项目的承伤是「差值」

`Combat.resolve`：`raw = 攻×系数 − 防×0.5`，`raw ≤ 0` 才走保底。
所以**防御每掉 1%，承伤涨的不止 1%**。158 级快照：def 58,383，Boss 实攻 36,579 → 每击 7,387；若职业把防御打到 0.9 倍（52,545），每击立刻变 10,306（**+39%**）。

🔴 **这条决定了：法师不做「低防」**。用户要的是「高蓝低血」，防御保持 1.0 倍，脆皮压力全部由「低血」承担——那是线性的，可控。

## 2. 方案总览

三层，自下而上，每层都能独立验收：

```
第三层  平衡与验收   ← 契约测试 + class_balance_probe 探针 + 负向脚本
第二层  法师技能      ← 6 技能 + 魔法盾（新引擎能力 2 项）+ 远程普攻投射物
第一层  职业框架      ← classes.json + 属性派生系数 + 存档 classId + 技能归属过滤 + 选职业入口
```

**分层理由**：第一层落地后，武士行为必须**逐位不变**（所有系数 = 1.0，所有旧档补 `classId=warrior`）。这一层过了，后面才有得谈；没过就说明改动污染了既有规则。

**为什么系数放表里而不是代码常量**：以后加第三个职业只改数据；同时「武士全 1.0」这件事变成可断言的配置事实（`tests` 直接比对默认职业必须全 1.0），而不是靠记性。

### 3.2 派生接入点（逐条标出「乘在哪」）

| 函数 | 改法 | 🔴 陷阱 |
|---|---|---|
| `GameState.max_hp()` | 最外层再 `× hpMult` | 必须在 `_base_attack()/_base_defense()` **之后**乘一次 |
| `GameState.max_mp()` | 最外层再 `× mpMult` | 同上 |
| `GameState.total_attack()` | 最外层再 `× atkMult` | **绝不能进 `_base_attack()`**：`max_hp` 内部用 `_base_attack()` 算血，进了就会二次放大（与套装 1.4→1.96 是同一个坑） |
| `GameState.total_defense()` | 最外层再 `× defMult` | 同上；法师 1.0，暂不启用 |
| `player.attack_range_px()` | 读 `classes.json` 的 `attackRange` | 新增函数；`melee_range_px()` 保留为别名，避免 4 处调用点 + 2 处测试同时改 |

### 3.3 技能归属过滤

- `skills.json` 每条加 `"class": "warrior"`（法师 6 条 `"mage"`），**缺省视为 warrior**（旧档/旧配置兼容）。
- `HotbarConfig.ACTIVE_SKILLS` → 改为 `active_skills()` 按当前职业返回；`usable_skill(skill_id)` 供 `player.gd` 两处校验调用。
- `skill_panel._refresh()` 遍历全表 → 只列本职业（否则武士能买法师技能）。
- `auto_battle.WIRED_SKILLS` / `WIRED_SINGLE_SKILLS` → 按职业分支。
- **读档迁移**：快捷栏里出现「非本职业技能」必须清成 `null`（否则法师档继承武士配置 → 点技能格无反应且无提示）。

### 3.4 存档

- `default_player()` 增 `"classId": "warrior"`。
- `_migrate_player()` 走「默认表打底 + 旧字段覆盖」→ **旧档自动补成武士，无需 bump schema**（与 `autoRepairEquip` 同口径）。`_deep_int` 只转 FLOAT，字符串安全。
- `classId` 非法值（被改档）→ 读档时回退 warrior，不拒档。

### 3.5 选职业入口（待拍板 Q1）

| 选项 | 做法 | 成本 | 风险 |
|---|---|---|---|
| **A（推荐）** | 存档面板「新的旅程」里，名字输入框下方加「职业」二选一（武士 / 法师，各带一句话说明与三项属性预览），默认武士 | 小（`save_panel.gd` 一个区块 + 5 条文案） | 低 |
| B | 进营地后找「职业祭坛」NPC，首次交互选职业 | 中（新 NPC + 交互 + 世界表现） | 中：玩家可能先打完第一章才想起来选 |
| C | 任意时刻可切换职业 | — | **不做**：装备/技能/进度全部错位，等于自毁存档语义 |

### 3.6 角色形象（美术缺口，必须如实标注）

`CharacterLook` 现有 6 套 look 全部是「守护者」形象，**没有法师形象**。方案：

- v1：法师沿用 `look_01`，用 `sample_art.modulate` 做冷色调偏移（青蓝）区分，**不新造素材**。
- 缺口清单（需美术产出，MR 前必须标「占位」）：法师 6 套阶段形象（`64×80` 帧格，八向）、法师攻击动作（施法 6 帧）、法师头像、火球/雷电/冰霜/陨石四套特效图。
- 🔴 不要用「换个颜色规避版权」的方式处理任何参考素材；本项目形象全部自绘。

## 4. 第二层：远程战斗与法师技能

### 4.1 基准数据（158 级真实快照，探针实测）

| 项 | 武士（实测） |
|---|---|
| max_hp | 631,451 |
| 防御 | 58,383（破防线 29,192） |
| 攻击 | 40,760 |
| 攻击间隔 | 0.571 s（套装后） |
| 暴击 | 7.00% × 2.10 |
| 理论 DPS | 76,822 |

Boss（`c7_boss_field` 代表 `c6_boss03`，Lv158，`atk ×3.0`）：基础攻 12,193 → 实攻 **36,579**；武士每击 **7,387**（占血 1.17%）；破防阈值倍数 **2.39**。

> 🔴 快照里的 `player.mp = 59,246` 是**当前值**，`max_mp()` 需实现后由 `class_balance_probe` 复算；下表蓝预算按 `mp ≈ max` 近似，实施后必须用探针数据替换。

### 4.2 法师属性系数与承伤推演

| 项 | 武士 | 法师 | 说明 |
|---|---|---|---|
| hpMult | 1.0 | **0.72** | max_hp 631,451 → **454,645** |
| mpMult | 1.0 | **2.0** | 蓝池翻倍，是「第二条血」的储备 |
| atkMult | 1.0 | **1.08** | 法术基础强度略高 |
| defMult | 1.0 | **1.0** | 🔴 **不降**，见 §1.3 |
| 每击伤害（无盾） | 7,387（1.17% 血） | 7,387（**1.63% 血**） | 生存 0.72× |
| 每击伤害（开盾 30%） | — | 扣血 5,171（1.14%）+ 扣蓝 2,216 | 生存 **1.03×** |
| 每击伤害（盾破/断蓝） | — | 7,387（1.63%） | 生存 0.72×，**明显更脆** |

**设计意图**：盾在线 ≈ 与武士持平，盾断线立刻掉到 0.72×。这不是「数值波动」，是**玩家必须管理的东西**——传奇法师的紧张感就来自这里。

### 4.3 远程普攻

| 项 | 设定 | 理由 |
|---|---|---|
| 射程 | **4.0 格（256px）** | 怪物 `AGGRO_RANGE = 200px`；4 格能让法师先手 1—2 发，但**挨打必仇恨**（`take_hit` 已实现 `_enter(CHASE)`），不存在「站 6 格白打不死人」 |
| 投射物 | **视觉飞行 + 伤害即时结算** | 沿用「普攻是离散事件」的既有口径；若伤害绑飞行时间，怪死时弹道白扔、自动战斗拿不到击杀反馈 |
| 自动战斗停步 | `reach = attack_range_px() - STOP_GAP` | 只改这一行（`auto_battle.gd:334`）即可让挂机在 4 格停住放技能 |
| 超距接近 | `_manual_attack_direction` 已按 `skill.range` 算 reach | 普攻改用 `attack_range_px()` 后自动生效 |

### 4.4 法师技能表（6 条，全部映射到**已实现或本次明确实现**的引擎能力）

| Lv | 技能 | 类型 | 系数 | CD | 蓝耗 | 形状 / 射程 | 引擎能力 |
|---|---|---|---|---|---|---|---|
| 1 | 火球术 `basic_fireball` | 普攻 | 1.0 | 跟攻击间隔 | 0 | single / 4.0 | 远程普攻 + 投射物视觉（新） |
| 5 | 雷电术 `lightning` | attack | 2.2 | 5 s | 5% maxMP | single / 4.5 | `defensePierce 0.5`（**已实现**）✅ |
| 10 | 火焰喷发 `flame_burst` | attack | 1.6 × 3 段 | 9 s | 8% | circle / 2.5 | `hits: 3`（**已实现**）✅ |
| 15 | 魔法盾 `magic_shield` | buff | 0 | 10 s | 开盾 8% | self / 0，持续 30 s | **新：`effects.damageToManaPct`** |
| 25 | 冰咆哮 `frost_roar` | attack | 1.5 × 2 段 | 7 s | 6% | cone / 3.5，5 目标 | `hits: 2` ✅ + **新：`debuff.slow`** |
| 40 | 陨石术 `meteor` | attack | 3.5 | 18 s | 12% | circle / 5.0 | `hits: 1`（已实现）✅ |

**单次循环总蓝耗 = 31% maxMP**，平均 CD 摊 ≈ **1.1% maxMP/s**。

#### 蓝收支（法师，按 158 级近似 maxMP 118,492）

| 支出 / 收入 | 速率 | 说明 |
|---|---|---|
| 蓝药三档全开 | **+2.13%/s** | 3%/8s + 9%/12s + 20%/20s |
| 魔法盾（挨打 0.55 次/s × 2,216 蓝/击） | **−1.03%/s** | 只在真正挨打时扣，安全期不空转 |
| 技能循环 | **−1.10%/s** | 31% / 平均 28 秒 |
| **净额** | **≈ 0.00%/s** | 刚好卡住：能持续输出但**没有余量** |

🔴 这张表是**故意算到「刚好」**的：法师必须喝蓝药才能维持「盾 + 技能」，少喝一样就降级。武士的 15—60 点蓝耗对 5.9 万蓝池等于免费，两职业的**经济结构**因此不同（这才是「高蓝」的真实意义，而不是数字好看）。

### 4.5 两项新引擎能力（不实现就是假技能）

| 能力 | 落点 | 验收判据 |
|---|---|---|
| **伤害转嫁法力** | `player.apply_damage()` 入口：有盾且 `mp > 0` 时，`to_mana = round(伤害 × 0.30)`，`mp` 不足则按剩余量转嫁、余下扣血；返回实际扣血（吸血/击退判据不变） | 开盾后 `apply_damage(1000)` 返回 **700**、蓝 −300；蓝为 0 时返回 **1000**；武士无盾行为逐位不变 |
| **减速 debuff** | `monster.gd` 增 `apply_slow(pct, duration)` + `move_speed_px` 结算时乘 `(1−slow)`；`player.gd::_apply_skill_debuff` 增 `slow` 分支 | 冰咆哮命中后 3 秒内怪移速 ×0.65；到点恢复；Boss 不吃（`boss_corrupted_beast` 等按模板 `debuffImmune` 或等级差豁免，见 Q3 备注） |

> `magic_shield` 走既有 `start_buff` / `buff_effect_total("damageToManaPct")` 通道，不新建第二套 buff 系统。

### 4.6 自动战斗适配（3 处）

1. `reach` 改 `attack_range_px()`（1 行）。
2. 新增 `_tick_mage_shield()`：法师 + 已解锁 + 不在盾期 + 冷却好了 → 开盾（复用 `cast_skill`，不绕冷却）。
3. **低蓝保盾策略**：`mp < 25% maxMP` 时停止释放攻击技能，只维持盾与普攻；蓝回升到 40% 恢复。🔴 不实现这条，挂机法师会在蓝见底时「盾断 + 继续挥技能」，两头落空。

## 5. 第三层：平衡与验收

### 5.1 平衡目标（写成可验证的判据，不写「感觉差不多」）

| 指标 | 判据 | 为什么是这个区间 |
|---|---|---|
| 对同一循环 Boss 的击杀时间 | 法师 / 武士 ∈ **[0.90, 1.00]** | 法师烧蓝换速度，快 0—10% 是「值得玩」；超过 10% 武士没人玩 |
| 站桩 60 秒掉血（**开盾**） | 法师 / 武士 ∈ **[0.85, 1.15]** | 开盾≈持平，这是「用蓝买回来的血」 |
| 站桩 60 秒掉血（**断盾**） | 法师 / 武士 **≥ 1.50** | 无盾必须明显更脆，否则盾没有存在意义 |
| 每只 Boss 蓝药消耗 | 法师 **> 0**、武士 **= 0** | 经济结构差异的最小可断言形式 |
| 单只 Boss 金币收益 | 两职业 ∈ [0.95, 1.05] | 职业不能变成收益倍率 |

### 5.4 新增探针 `tools/class_balance_probe.gd`

读**真实存档**（同 `boss_ttk_probe` 口径：只读不写），把职业系数按切换到 warrior / mage 各跑一遍，输出：

```
[CLASS] warrior  hp=631451 def=58383 atk=40760 有效DPS=76822
[CLASS] mage     hp=454645 def=58383 atk=44021 有效DPS=...
[CLASS] Boss c6_boss03 每击 7387 → 法师开盾每击扣血 5171 / 扣蓝 2216，断盾 7387
[CLASS] 击杀耗时 warrior 18.4s / mage ...s  比值 0.9x
[CLASS] 蓝收支：+2.13%/s −1.03%/s −1.10%/s = 0.00%/s
```

## 8. 明确不做（范围边界）

| 不做 | 原因 |
|---|---|
| 转职 | 装备/技能/进度全部错位，等于半个重置系统 |

| 法师专属 look | 美术缺口，见 §3.6 |
