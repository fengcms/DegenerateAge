# 任务 NPC 地点提示调整方案

本方案用于解决任务交付或找人提示只显示 NPC 名字、玩家无法在出发前判断是否应乘车的问题；实施入口是任务文案的公共行内渲染器。

## 现象与证据

- 玩家在任务栏或任务面板看到“到某 NPC 交付”时，常看不到 NPC 所在地图，只能点击后开始跨图步行。
- 检查当前 `data/quests.json` 的 100 条任务：含 `{npc:...}` 而不含 `{map:...}` 的 `turnInText` 有 **75 条**；`trackerText` 同类缺口为 **0 条**。缺口主要集中在第三至六章的交付文案。
- `scripts/ui/quest_inline_text.gd` 负责选择任务状态对应的文案并把 `{npc:ID}` 变成 NPC 名称链接，先前仅显示名字。任务栏和任务面板都调用此入口。NPC 所在地图可由 `MapService.map_for_npc(ID)` 查询。

## 根因与影响范围

数据允许省略地图标记，但显示层没有为 NPC 补地点信息；前两章较多文案手写了地图，后续章节的简短交付文案没有沿用。这是展示信息不足，不是寻路或任务目标配置错误。影响带 NPC 标记的可见任务文案，尤其是完成态交付提示；不改变任务状态、奖励、导航权限或存档。

## 调整规则与实施步骤

1. 保留任务原文的自由编辑方式，允许作者显式写 `{map:地图ID}` 与 `{npc:NPC ID}`。推荐示例：`到 {map:camp} 找 {npc:elder} 交任务。`
2. 公共渲染器遇到有效 NPC 链接时，查询 NPC 实际所在地图。如果该 NPC 前的文案尚未包含同一地图标记，则在 NPC 名字之前自动显示“可点击地图名 的 可点击 NPC 名”。文案已明确写出同一地图时不重复；文案里提到其他地图时仍补上 NPC 的真实地点。
3. NPC ID 无法解析、地图数据缺失时沿用原来的原样显示方式，不猜测位置。补出的地图链接沿用现有地图导航；NPC 链接沿用走近并对话的行为。
4. 更新任务产品规则，增加回归断言：遗漏地图、明确地图、文案提到其他地图、未知 NPC 四种情况。

## 成本与复核

任务文案只在界面更新时解析。每个 NPC 标记增加一次地图查询，配置规模为当前 100 条任务，不进入每帧移动或战斗热路径；不增加持久状态或缓存，因此没有缓存失效和迁移问题。复核时分别查看前两章已有地图提示和第三章之后的交付提示，并点击地图名与 NPC 名确认原导航行为。自动化运行 `QuestInlineNavigationTest` 及相关任务冒烟测试，记录结果于提交说明。
