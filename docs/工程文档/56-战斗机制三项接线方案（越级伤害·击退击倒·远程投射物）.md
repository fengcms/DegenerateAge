## 1. A2 · 越级伤害倍率 `dmgMult`

### 1.1 产品口径（原文）

[03-核心循环与战斗系统.md §3.13](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/docs/产品文档/03-核心循环与战斗系统.md#L136-L146)：

```text
dmgMult（越级）= 1 + (monsterLv − playerLv) × 0.02，上限 1.3
  （玩家低于怪等级时打该怪伤害略增；怪物打玩家同理）
目的：防止高等级回低图无意义刷，也允许适度越级挑战。参数为初始值，试玩校准。
```

### 1.2 现状证据

- 全库 `.gd` 无 `dmgMult` / 越级伤害逻辑。
- [level_gap.gd](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/systems/level_gap.gd) 只有**经验**倍率 `experience_multiplier`（系数 0.04、`clamp 0.2–1.5`）与 `kill_xp`，与伤害无关。

### 1.3 🔴 口径缺口（必须先拍板：产品公式没有下限）

公式只写了**上限 1.3**，没有下限。当玩家高于怪时 `(monsterLv − playerLv)` 为负：

| `monsterLv − playerLv` | 公式结果 |
|---|---|
| +15 及以上 | 1.3（封顶） |
| 0 | 1.00 |
| −10 | 0.80 |
| −25 | 0.50 |
| **−50 及以下** | **0.00 / 负数** |

> ⚠ **表述修正（2026-10-19）**：`Combat.resolve` 有 `maxf(1.0, …)` 兜底，**不会真的打出负伤害**；
> 真实症状是「伤害塌到 1 点下限」——高等级玩家回流低图变成**打不动**，比收益低更糟。

而 §3.13 的「防止高等级回低图无意义刷」**已由 `expMult` 承担**（经验衰减到 0.2 倍），
所以 `dmgMult` 的职责只剩「允许适度越级挑战」。据此有两个互斥口径，需你选一：

- **口径 ①（建议）「只奖不罚」**：`dmgMult = clampf(1 + (monsterLv − playerLv) × 0.02, 1.0, 1.3)`
  ⇒ 平级/越级向下恒为 1.0，回流低图不掉伤害；语义与 §3.13 正文括号一致。
- **口径 ②「奖惩对称」**：`dmgMult = clampf(1 + (monsterLv − playerLv) × 0.02, 0.7, 1.3)`
  ⇒ 回流低图降伤（多一层反刷保险），但需你指定下限值。

### 1.4 接线点（全仓只有 4 处 `Combat.resolve`，接线面很干净）

| 方向 | 位置 | 说明 |
|---|---|---|
| 玩家 → 怪（技能） | [player.gd:538](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/entities/player.gd#L538-L543) | `Combat.resolve(power, …)`，`power = effective_attack_power()` |
| 玩家 → 怪（普攻） | [player.gd:613](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/entities/player.gd#L613-L622) | 同上，`power = effective_attack_power()` |
| 怪 → 玩家（普攻 / 投射物命中） | [monster.gd:746](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/entities/monster.gd#L746-L754) | 投射物命中后也走 `source._do_attack(player, false)`（[monster_projectile.gd:20](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/entities/monster_projectile.gd#L20)）⇒ **同一处即可覆盖弹道** |
| 怪 → 玩家（Boss 技能） | [monster.gd:452](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/entities/monster.gd#L452-L460) | `Combat.resolve(attack_power * coeff, …)` |

### 1.5 实现形状（待确认后落地）

1. `LevelGap` 新增纯静态 `damage_multiplier(player_level: int, monster_level: int) -> float`（与既有 `experience_multiplier` 同构、同样无状态）。
2. 4 处 `Combat.resolve` 之前把入参 `power` 乘上 `damage_multiplier(...)`；投射物无需单独改。
3. 运行态计算，**不入档**（与 `expMult` 一致）。
4. **循环图天然免疫**：`c7_arena` 的 Boss 等级由玩家等级现算（`levelFromPlayer`），`Δ = 0` ⇒ `dmgMult = 1.0`。这点要在产品 13 里留一句，避免以后有人以为循环图也被缩放了。

### 1.6 边界单测（建议并入 `BalanceTest` 或新建 `LevelGapTest`）

- 同级 = 1.0；`monsterLv − playerLv = 10` → 1.2；`≥ 15` → 封顶 1.3。
- **`playerLv − monsterLv = 60` 时结果 ≥ 你选定的下限**（口径 ① 应为 1.0，口径 ② 应为下限值）——这条专门锁「负伤害」这个洞。
- 负向断言：把系数 0.02 写死成 0.01 或去掉封顶，测试必须变红。

### 1.7 影响面

- 玩家越级打怪**变容易**（伤害最多 +30%），同时**怪打玩家也 +30%**（§3.13 是对称口径）⇒ 越级是「双向更危险」，不是单向红利。**这一条需你确认是原意**（见 Q1）。
- TTK：正常平级玩法 `dmgMult = 1.0`，**本次改动对常规推图零影响**；只有玩家主动越级时生效。
- 需实机复验：越级 10–15 级打一只精英的 TTK 与死亡风险。

## 2. A4 · 击退 / 击倒 knockback

### 2.1 产品口径（原文）

[03-核心循环与战斗系统.md §3.4](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/docs/产品文档/03-核心循环与战斗系统.md#L70-L77)：

> 采用**受击硬直 + 无敌帧 + 击退**……**击退 / 击倒（knockback）**：部分攻击造成位移（击退）或短暂倒地（击倒）；倒地期间不可行动但享有无敌帧。
> 边界：死亡态、无敌帧内、过场 / 对话中不触发硬直。

### 2.2 现状证据

- 已实现：受击硬直 `HITSTUN = 0.25s`、无敌帧 `IFRAME = 0.5s`（[player.gd:20-21](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/entities/player.gd#L20-L21)），受击入口 [player.gd:351](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/entities/player.gd#L351-L363) 已带 `is_dead / _invuln / 休息区` 三重边界判断。
- **未实现**：位移（击退）与倒地状态（knockdown）。全库无 `knockback`。

### 2.3 🔴 待你定的参数（产品只说了「部分攻击」，具体量全是空白）

| 参数 | 建议默认 | 备选 | 说明 |
|---|---|---|---|
| 击退距离 | Boss 重击 `48px`（0.75 格） | 24 / 64 / 96px | 由攻击来源配置，不写死在代码 |
| 击退时长 | `0.18s` | 0.12 / 0.25s | 位移用速度衰减完成，不用 Tween（可被碰撞截断） |
| 倒地时长 | `0.5s` | 0.3 / 0.8s | 倒地 = 不可行动 + 沿用无敌帧 |
| 触发来源 | 仅 **Boss `bossSkill` 与精英重击** | 含普通怪 / 仅 Boss | 普通怪保留现有 `HITSTUN` 即可 |
| 是否作用于怪物 | **暂不**（玩家攻击不击退怪物） | 玩家攻击也击退 | 避免牵动怪物 AI / 寻路节奏 |
| 抗性 / 免疫 | 不新增，复用无敌帧 | 新增 `knockbackResist` 词条 | 倒地期间享无敌，符合 §3.4 |

> 需要你给的最小集合是**前四项**；后两项可先按建议落地。

### 2.4 实现形状（待参数确认后）

1. **数据驱动**触发条件：在 `monsters.json` 的攻击配置（`attackRange` / `bossSkill`）或 `skills.json` 增可选字段 `knockback: {distance, duration}` 与 `knockdown: {duration}`；缺省 = 不触发。
2. **运行态**：`player.apply_damage()` 拿到实际扣血后，按来源字段给 `_knockback_v`（速度）+ `_knockdown_t`（计时），二者**都不入档**。
3. **位移必须过碰撞**：用 `IsoGround.clamp_to_map()` / 可行走掩码截断，禁止穿墙、禁止推出可行走区（这是本项最容易出 bug 的地方）。
4. **与自动战斗协调**：击退期间暂停 `map_move_active` 与自动战斗决策（复用既有 `_stun` 的抑制路径，见 [player.gd:337/416/498](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/entities/player.gd#L337)），结束后重新评估目标 —— 否则会出现「挂机被连续击退 → 反复重规划 → 站桩」。
5. **边界**：死亡态、无敌帧内、休息区、过场 / 对话中不触发（与 §3.4 一致）。

### 2.5 风险

- 挂机 / 自动战斗场景下的**击退连锁**是本项最大手感风险（多怪围殴时被反复推开）。建议第一版只让 Boss 触发，样本可控。
- 击退方向依赖「攻击者 → 受击者」射线；投射物来源需要在 `MonsterProjectile` 上保留 `source`（已有）。
- 需要定向断言：击退后**玩家仍在可行走格内**、无敌帧内**不再叠加**新的击退与硬直。

## 3. A3 · 远程投射物（把 `c2_` 前缀判定改为数据驱动）

### 3.1 现状证据

[monster.gd:629](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/entities/monster.gd#L629)：

```gdscript
if is_ranged and monster_id.begins_with("c2_"):
    _begin_chapter_projectile(player)   # 0.28s 蓄力 → MonsterProjectile 飞行 → 命中
else:
    _do_attack(player)                  # 瞬发结算
```

- `is_ranged` 本身**已经是数据驱动**：取自 `template.attackRange.kind == "ranged"`（[monster.gd:195-198](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/entities/monster.gd#L195-L198)）。
- 投射物组件**已存在**：[monster_projectile.gd](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/entities/monster_projectile.gd)，固定方向、玩家可走位躲开，命中后回调 `source._do_attack(player, false)`。

### 3.2 🔴 范围纠正：这不只是第一章的事

`monsterType: "ranged"` 实测 **21 只、跨 6 章**（ch01 2 / ch02 3 / ch03 3 / ch04 4 / ch05 5 / ch06 4）。
`monster_id.begins_with("c2_")` 这道门现在的实际效果是：**只有第二章的 3 只**走弹道，
其余 18 只 ranged 怪（含第一章 `ash_wraith`、`elite_ash_wraith`）全部是**瞬发结算**。

> ⚠ **落地时修正（2026-10-19）**：真正驱动判定的是 `is_ranged`，即 `attackRange.kind == "ranged"`。
> 按这个口径实测是 **19 只**，而不是 `monsterType` 口径的 21 只 —— 差集是
> `c3_elite03`、`c4_elite03`：两只 `monsterType = "ranged"` 但 `attackRange.kind = "melee"`，
> 属**数据自相矛盾**。本批不改数据，它们继续按近战结算；该不一致单独留作待确认项。

⇒ 改成 `is_ranged` 之后，**这 19 只全部改为弹道**。这是本次改动真正的量级：

- **方案 ①（建议）全量数据驱动**：判定直接写 `is_ranged`。语义最干净，一次到位；代价是 6 章战斗节奏同时变化，需一轮实机 TTK 抽查。
- **方案 ②渐进**：`is_ranged and 章节白名单`（如先只放开 ch01+ch02）。改动小、可分批验证；代价是继续保留一处「前缀硬编码」，与 A3 的初衷（去前缀）部分背离。

### 3.3 泛化时会暴露的两个既有硬编码（必须一并处理）

| 位置 | 现状 | 泛化后的问题 |
|---|---|---|
| [monster_projectile.gd:8](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/entities/monster_projectile.gd#L8) | `remaining := 520.0`（飞行距离写死） | 各章 `attackRange.range` 不同，520px 未必等于该怪射程 ⇒ 建议改为由来源传入（`attack_range_px × 1.1` 或新增数据字段） |
| [monster.gd:769](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/entities/monster.gd#L769) | `count := 2 if monster_id == "c2_elite_gray_scribe" else 1` | 泛化后其他章的远程精英是否也要多段，需明确；建议先保持 1 段 |
| [monster.gd:758](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/entities/monster.gd#L758) | 蓄力 `_ranged_windup = 0.28`（c2 调校值） | 各章是否沿用同一蓄力，需确认；建议先沿用 |

### 3.4 实现形状（待确认后）

1. 判定行改为 `if is_ranged:`（方案 ①）或 `if is_ranged and <章节白名单>:`（方案 ②）。
2. `_fire_chapter_projectile` / `_begin_chapter_projectile` 改名去掉 `chapter`（纯命名清理，避免误导）。
3. `MonsterProjectile.remaining` 接收来源射程（见 3.3 第一行）。
4. 定向断言：**ranged 怪进入 `ATTACK` 态时必须生成 `MonsterProjectile` 节点，而不是立刻扣血**（用现有测试里同类的节点轮询方式即可）。

### 3.5 影响面

- 玩家**可以走位躲开**，所以实际 DPS 期望会低于瞬发；第一章 `ash_wraith` 的威胁曲线会变（更「温和」但更可读）。
- 需要实机复验：第一章远程怪的 TTK / 玩家被弹道命中的频率；确认不会出现「蓄力期间怪原地不动被打死」的滑稽感。
- 与 **A2 天然同批**：投射物命中复用 `source._do_attack()`，即 A2 的怪→玩家接线点同时覆盖弹道，两项一起做只需一次回归。
