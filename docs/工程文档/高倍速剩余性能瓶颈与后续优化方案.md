# 高倍速剩余性能瓶颈与后续优化方案

2026-11-02至11-03。玩家确认上一轮积压优化有效，但4/8/16倍速仍不流畅。本轮先修复装备图标与保星材料区回归，提交8cb5e249、70d9c0a4，再分析性能；本文件不代表已实施下一轮性能改动。

## 已有证据和解释边界

上一轮2400件同模板、冻结战斗夹具稳定后8倍速中位约8ms；30种组合的混合持久掉落稳定后约12ms，首次生成段中位85ms、峰值277ms。不是完整Boss战帧率。GroundLootVisualCache按一张一张的SubViewport离屏合成，包含get_image GPU读回、逐像素alpha处理、图像上传，避免了长期绘制成本，却引入首次生成开销。

Engine.time_scale改变游戏delta，不应简单解释成“16倍就每秒执行16倍物理回调”。固定物理频率下delta增大；技能、击杀、刷新与游戏时间驱动通知在现实时间内可能更密，CPU、碰撞和表现负载也取决于并发状态。不能把高倍速下的战斗时序问题全部当成掉落渲染问题。

## 代码复核的候选热点

1. scripts/entities/ground_item.gd：失败缓存阻止重复入包交易，但在它之前仍逐物理帧查询player组、计算距离。2400件约14.4万次/秒（物理频率60Hz、全部活跃时），还保留节点、点击Area及生命周期回调。此数是结构推算，不是Profiler实测耗时。
2. scripts/entities/monster.gd：100只Boss仍执行动作、状态、碰撞和预警/命中表现。Boss已经跳过_separation_push全组排斥；不能误把普通怪O(N²)排斥当作100只Boss必然瓶颈。召唤物增多时另测。
3. Monster._boss_beat每1游戏秒续期血条，高倍速使现实频率提高；scripts/ui/boss_health_bar.gd每次通知查找条目并更新绘制。应区分真实HP/阶段变化与无变化续期，不能延迟关键受击反馈。
4. autoload/save_manager.gd：120游戏秒定时存、0.6游戏秒去抖，16倍时分别约7.5/0.0375现实秒（稳定delta、未受其他条件影响时）。存档包含同步JSON序列化、写盘和校验回读；持续新掉落积压时是尖峰候选。当前未测真实存档写盘耗时，不能将其认定为已证实主因。
5. scripts/systems/auto_battle.gd：满包已采用未缩放节流，但未满包找物仍遍历全组，候选可达性与怪物搜索也需独立采样。高速消耗/整理产生空位后可能恢复全量候选搜索。

## 本轮实际窗口分项实测

Apple M1 Max、Godot 4.7.2、GL Compatibility、1280×800、120帧上限。隔离项目，固定种子4513、满200格、2400件第六章10模板×3品质的持久装备，缓存30张就绪、待生成0。参照CameraStressTest将100个真实Boss放在固定玩家附近，启用原AI和技能；冻结玩家/自动战斗并给予测试无敌，停刷新器，加入真实BossHealthBar。先预热8秒，每倍率预热1秒、采样3秒，统计实际frame_post_draw次数。没有持续击杀、没有全HUD、没有存档写盘，不等同玩家完整存档现场。此为刻意密集的最坏负载，不代表全图100只分散Boss均同时接战。

血条通知3秒内约1100/2300/4500—4600次；首轮关血条无明显中位收益，第二轮变化也混有动作状态波动，优先级低于Boss推进链路。Boss停物理后物理监视器中位约6.1ms，再停掉落回调约0.03—0.05ms；显示帧仍约15ms，说明渲染、怪物子节点动画和其他工作仍在。单纯继续压图标绘制无法解决全部稳态卡顿。

本轮只加入临时隔离探针，没有将诊断禁用、计时静态变量或测试无敌写入正式源码。首次探针完成后才加入第二轮计时，二者数据分开，不把新增计时当作免费无扰动测量。

## 推荐实施顺序

针对玩家稳定游玩卡顿，优先“积压空转与Boss推进/重绘链路”，先做单系统耗时和分配计数再逐项改；首次缓存生成作为独立尖峰任务。血条合并与存档时序调整须等对应证据，不应排在已证实的主要链路前面。以下是可分别提交的任务范围。

### 独立处理缓存建立尖峰

优先预制静止组合图集，或在地图准备阶段按实际贴图/品质/持久标记预热；避免战斗中同步GPU读回和GDScript逐像素处理。优先复用实际纹理身份，减少不同模板指向同素材时的重复组合。保留原图回退、透明混合、品质光柱、持久标记和绘制顺序，检查缩放后的像素效果。图集只改地面表现，不能再借共用SampleArt.decorate扩大到背包或穿戴格。

### 稳态优先减少积压物品空转

在距离查询之前短路已知失败状态，或建立地图拥有的集中附近拾取调度/网格索引，统一查询玩家与候选。奖励与表现分离：持久记录继续完整，手动点击立即可用，金币/可堆叠物/自动出售保留原交易入口，腾格、装备、策略和读档失效必须唤醒。对象回收、切图和死亡时移除索引；不可通过少发奖励或删除积压换性能。

### 稳态优先拆分Boss推进与重绘链路

先对Boss动作更新、预警/命中_draw、子节点动画及碰撞分别包围计时，区分脚本构建与引擎提交。优先缓存不变的表现几何、仅在动画帧或预警进度变化时更新画面；危险范围与伤害判定仍画判同源。血条不变续期与显示刷新可合并，HP/阶段/死亡反馈保留即时。保留战斗物理与技能结算频率，不直接把AI/碰撞全体降频，也不擅自改physics_ticks_per_second或引擎倍率机制。

### 单独处理存档尖峰

先测大积压快照、编码和原子写入各段，再考虑现实时间去抖、同轮变化合并或不可变快照后台编码；主线程读取节点与状态、后台文件写入边界必须明确。手动保存、退出保存与坏档回退规则不变。若调整保存间隔，明确最大未落盘时长，不能为流畅性静默扩大进度丢失窗口。

## 验收要求

使用隔离user目录；固定设备、GL Compatibility、1280×800、固定种子、满200格、2400件混合持久装备。分别测冷缓存与热缓存，4/8/16倍速，静止掉落/100只真实Boss技能/自动战斗持续产出三个层级。每阶段记录样本数、帧时间中位/P95/P99/峰值、物理耗时、绘制调用、节点与内存。固定负载与真实增长负载分开，不以隐藏节点或冻结AI的诊断样本冒充正式战斗改善。

每个优化节点独立提交。地面视觉调整验证光柱/持久标记与点击；共享UI回归至少包括背包、人物、仓库、重铸、保星和四金批量合成，且使用实际窗口与不同UI倍率。最后进行持续挂机与切图/读档复核。完整持续击杀、奖励产出、HUD和真实存档I/O尚需进一步测试。
