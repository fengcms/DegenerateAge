# 掉落积压性能优化第一阶段实施记录

2026-11-02，按《百首禁域满背包掉落积压与倍速性能优化分析》先实施重复失败拾取与倍速放大的检查预算，不改奖励、存档或战斗时序。

## 实现与成本

GroundItem生成认领和附近自动拾取共用失败缓存；同一版本内失败一次后不再调用原拾取交易。手动点击仍直接进入原入口，金币、坐骑保持原路径。统一版本服务只连接一组库存、装备、设置、数据重载、等级及金币封顶状态事件，不按物品数量创建信号或定时器。金币普通入账不改变出售可用条件，不能因此唤醒全体积压；仅封顶状态切换失效。

为兼容直接替换容器的读档以及旧调用直接腾格，每物理帧共享一次Array.find(null)空位检查，而非每件掉落遍历背包。容器整体替换与首个空位变化也失效；正常堆叠、装备、出售变化通过既有事件失效。单件仅新增失败版本整数；共享服务保留一份容器引用，不扫描全场物品。

地面重绘/距离复查与满包搜索节流改用delta除以time_scale，去除战斗倍速对这部分预算的倍增。未更改保护期、技能预警、伤害、生命倒计时或认领后飞行动画的游戏时间。此处是引擎未缩放步长预算，不宣称操作系统墙钟硬实时调度。

## 验证

LootRetryTest验证1000次同状态自动请求只实际尝试一次、手动入口不受阻、事件后恢复、普通金币不引发重试/封顶切换会重试、满格药品仍可叠加到999，以及8倍速下装饰预算不被放大。LootGridTest、GroundLootPerfTest、AutoSellPickupTest、SmokeTest通过；最后金币条件修订后LootRetryTest、AutoSellPickupTest、GroundLootPerfTest再次通过。新增测试纳入默认集，原断言未放宽。

初次回归命令误写了不存在的GroundLootTest，已改为实际存在的LootGridTest/GroundLootPerfTest；不将不存在场景算通过。SmokeTest曾发现仅事件缓存会挡住旧调用直接腾格，现以共享空位检查补齐，原腾格恢复和持久掉落注销断言复绿。

## 本阶段边界

尚未实施空间索引、集中拾取调度或静态掉落批绘；2400个节点自身物理回调及全场候选扫描仍存在。这一阶段只清除已确认的重复交易与倍率放大，不声称已解决全部幻灯片问题。尚未进行2400件、100 Boss及1/2/4/8倍速的实际窗口前后帧时间对照，1000次请求的调用次数不是FPS指标；后续应以该矩阵测量决定空间索引和渲染工作的优先级。所有验证使用隔离user目录，未读取或改写真实玩家存档。

后续已完成实际窗口测量，并根据渲染瓶颈追加静态表现缓存；数据与边界见《掉落积压静态表现缓存与窗口基准记录》。本节“尚未”描述第一阶段提交时的状态。
