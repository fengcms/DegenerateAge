## 3. 设计方案

### 3.1 总体：新建 `Consumable` 服务层，手动 / 自动共用同一入口

```
                      ┌──────────────────────────────┐
   双击背包药水 ──────▶│                              │
   快捷键 1 / 2  ──────▶│   Consumable.use(...)        │──▶ heal_player / spend_mp
                      │   （唯一的"使用"实现）        │──▶ 冷却表 _cd[item_id]
   AutoBattle  ───────▶│                              │──▶ 扣堆叠 / 耗尽移除格
   危险血量自动喝药     └──────────────────────────────┘──▶ toast 反馈
```

- **落点**：`scripts/systems/consumable.gd`（`class_name Consumable extends RefCounted`）
- **原则**：与 3.14 一致 —— 自动侧**不另写一套**，只调用 `Consumable.use()`。

### 3.2 核心接口（草案）

```gdscript
class_name Consumable extends RefCounted

## 每药水类独立冷却：item_id -> 剩余秒数（运行态，不落档）
static var _cd: Dictionary = {}

static func use(inv_index: int, from_auto: bool = false) -> Dictionary
    # 返回 {ok, reason, item_id, restored}
    # 校验链：格非空 → kind == potion → 未在冷却 → 当前值 < 上限 → 扣 CD → 回血/回蓝
    #         → 扣堆叠（耗尽移除格 → inventory_changed）→ toast

static func cd_of(item_id: String) -> float          # 供 UI 显示
static func tick(delta: float) -> void               # 冷却递减心跳
static func pick_red_index() -> int                  # 按 Q1 策略挑一瓶红药，返回背包下标（-1 = 无可喝）
static func reset() -> void                          # reset_to_defaults / 读档后清空
```

### 3.3 手动入口

1. **背包双击**（主入口）：`_on_bag_pressed` 按 `kind` 分流 ——
   - `equip` → 原有 `equip_from_inventory`（**行为不变**，🔴 必须回归锁死）
   - `potion` → `Consumable.use(index)`
   - `misc` / `quest` → 明确提示（不静默）
2. **临时快捷键**（Q3）：`use_potion_hp`（1）/ `use_potion_mp`（2）—— 与 9.1 快捷栏键位一致，M4 由正式快捷栏取代。面板打开时不响应（与 F/G 同规则）。
3. **tooltip 文案**：药水显示「恢复 80 生命 · 冷却 8s · 双击使用」，替换现有硬编码提示。

### 3.4 自动喝药（AutoBattle 改造）

```gdscript
# auto_battle.gd::_tick 危险血量分支（现 :173-182）改为：
var max_hp := GameState.max_hp()
if max_hp > 0 and float(GameState.player.hp) / float(max_hp) <= threshold:
    # ① 先尝试喝药（与手动同一入口）
    # ② 喝到 → 不停战，继续正常决策（不掉 state，回到 SEARCH/ATTACK）
    # ③ 无药 / 全在冷却 → 按 Q5 拍板结果处理
```

- 阈值取 `GameState.settings.potionThreshold`（默认 0.35），**不再用常量** `DANGER_HP_RATIO`（消除双事实源）。
- 提示节流沿用 `DANGER_TOAST_CD = 4s`，避免刷屏。
- 满血 / 冷却中**不消耗药水**（🔴 R-e：不浪费）。

## 7. 验收口径

**手动**
1. 背包双击小红药 → HP 增加 80（或补至上限）、数量 -1、再次双击提示「冷却中 7.x s」。
2. 双击装备 → **仍然穿戴**（回归 R-b）。
3. 满血双击药水 → 提示「生命已满」且**不扣药、不进冷却**（R-e）。
4. 快捷键 `1` → 喝红药；面板打开时按键无效。

**自动**
5. `F` 开自动战斗，血量降到 35% → **自动喝药**并**继续战斗**（不再停战）。
6. 药水耗尽 → **继续战斗至死**（Q5-B）。
7. 蓝药自动默认关（Q2）。

**系统**
8. 三层验证全绿（导入 0 error / 冒烟 exit 0 / 启动回归 0 SCRIPT ERROR + 配置校验通过）。
9. 存档 schema 不含冷却字段（R-f）；玩家存档 `md5` 前后一致（测试期间**先关闭游戏会话**，见工程文档 04 §5）。

### Q2 改判的执行口径（重要）

- `Consumable.use()` **红蓝都支持**；`AutoBattle` 危险血量时**红蓝都尝试**。
- ⚠️ **实测不会触发**：M1 无消耗 MP 的路径（普攻不耗蓝、技能未接线，`spend_mp` 仅被测试与 M3 技能调用），MP 长期满值 → 被 §3.4「满值不浪费」规则拒绝（不扣药、不进冷却）。
- M3 技能接线后**无需改代码**即自动生效。
- 仍需遵守 Q1 策略：按**缺口**选够用的最小档（蓝药同理）。
