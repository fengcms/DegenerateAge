# 营地地图编辑器主屏幕标签缺失排查

## 现象与实测证据

用户在 Godot「项目设置 → 插件」看到「幸存者营地地图编辑」已启用，但顶部 2D／3D／脚本旁没有「营地地图」。修复前的 `addons/camp_map_editor/plugin.gd` 已在 `_enter_tree()` 创建 `camp_map_panel.gd` 页面，并实现 `_get_plugin_name()`、`_get_plugin_icon()` 与 `_make_visible()`，但没有实现 `_has_main_screen()`。

修复后用 Godot 4.7.2 的实际编辑器进程运行 `tests/camp_map_editor_main_screen_test.gd`，找到名为「营地地图编辑」的主屏幕页面，以及文本为「营地地图」、`visible=true` 且图标非空的顶部按钮。测试进程退出码为 0。`python3 tools/run_isolated_tests.py CampMapEditorTest` 同样通过，验证原有营地数据读取、整体移动与撤销重做未受影响。

## 根因与影响范围

`EditorPlugin` 只有在 `_has_main_screen()` 返回 `true` 时才向编辑器注册主屏幕标签。原插件虽然把页面加入了主屏幕容器，但缺少这一声明，因此插件显示为已启用，顶部仍不出现入口。Godot [官方主屏幕插件教程](https://docs.godotengine.org/en/stable/tutorials/plugins/editor/making_main_screen_plugins.html)明确要求实现该回调。

影响仅限 Godot 编辑器中的营地地图入口；运行游戏时不实例化此插件，正式地图数据、NPC、碰撞和存档不受影响。

## 修复与复核方法

在 `addons/camp_map_editor/plugin.gd` 增加 `_has_main_screen() -> bool` 并返回 `true`；顶部图标改用编辑器内置的 `Node` 图标，避免图标名在不同编辑器主题中缺失。加入编辑器级回归测试，检查页面与实际可见标签，而不只实例化编辑面板。

在仓库根目录执行：

```sh
/Applications/Godot.app/Contents/MacOS/Godot --headless --editor --path . --script res://tests/camp_map_editor_main_screen_test.gd
python3 tools/run_isolated_tests.py CampMapEditorTest
```

第一条命令的进程退出码为 0 且输出 `[CampMapEditorMainScreenTest] PASS`，第二条输出 `CampMapEditorTest: PASS`，即通过自动复核。已打开的 Godot 编辑器可能仍持有旧插件实例：到「项目 → 项目设置 → 插件」关闭再启用该插件，或重新打开项目，再检查顶部标签。

## 后续建议

新增或调整编辑器主屏幕插件时，保留编辑器级测试。普通游戏场景测试不能实例化 `EditorPlugin`，只能验证面板内部逻辑，无法覆盖标签注册这一环节。
