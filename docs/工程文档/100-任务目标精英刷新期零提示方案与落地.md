# 100 · 任务目标精英刷新期零提示 —— 方案与落地

> 起因：玩家报障「C2S03 师父的旧钳子始终找不到对应的怪」。排查结论：**不是数据 bug**，是「精英刷点冷却期没有任何可视化」+「任务标记常亮」两条叠加造成的误判。
> 涉及：`data/maps/**`（5 个刷点）、`data/localization.json`（1 条文案）、新增 `tests/quest_target_respawn_hint_test.gd`、`tools/verify_100_negative.py`。
> 回退：删掉 5 个刷点的 `tombstone` 字段 + 文案改回，**零代码回退**。

---

## 一、现象

玩家接了第二章支线 C2S03（目标：在「工坊下层」击杀 1 只「断链巡检长」），按任务追踪与地图标记走到目标点，**那里什么都没有**，反复找也找不到，判断为「任务目标怪没刷 / 数据配错」。

## 二、排查（结论：生成链路完全正常）

用只读探针 `tools/quest_c2s03_probe.tscn` 实跑，逐层排除：

| 检查项 | 实测 |
|---|---|
| 任务定义 | `targetId=c2_elite_broken_inspector`、`mapScope=["c2_lower_works"]`、`count=1` |
| 刷点 | `c2_lower_works` 内**唯一 1 条**：`cell [45,87]`、`level 15`、`count 1`、`respawnTime 120`、`kind elite` |
| 网格合法性 | 该格 `walkable_rows` 为 `1`；从入口 `[10,68]` 洪水填充**可达**（连通 28,740 格） |
| 怪物模板 | 存在，`level 14`、`kind elite` |
| 外观资源 | `renderer: directional_preview`，`.ctex` 真实存在（排除「资源结构非法只在 preload 炸」那类坑） |
| **实跑装配** | 玩家置于 `[45,87]` 后装配 Main：`point_count=131`，**目标怪实例化数 = 1** |
| 任务导航 | `{"ok": true, "map": "c2_lower_works", "first_hop": ""}` |

玩家自己在对话里也确认了：**之前误杀过它，120 秒冷却未到**。

## 三、真正的缺口（两条叠加才致命）

### 3.1 精英刷点没有墓碑

`MonsterSpawner` 的冷却期提示完全依赖刷点上的 `tombstone` 字段：置 `true` 才调用 `_place_tombstone()` 生成 `BossTombstone`（世界内倒计时）。

| 档位 | 刷点总数 | 带 `tombstone` |
|---|---|---|
| `bossSpawn` | 17 | **17 / 17** |
| `spawnPoints` 的 `elite` | 58 | **0 / 58** |

⇒ 精英被杀后，那一格在冷却期**纯空白、无倒计时**。精英冷却并不短：`90s × 42 点`、`120s × 16 点`。

### 3.2 任务标记照常亮着

`map_markers.gd` 的任务标记只读 `Spawner.marker_points()`，而 `_on_monster_died()` 会**保留死亡位置**（供墓碑在原处重建）。于是：

> 地图上任务箭头指着目标格 → 玩家走到 → 那里是空地（尸体都不在，因为怪物是 `queue_free` 掉的）。

这两条单独看都不算错：一条是「省性能/省视觉噪音」的取舍，一条是「墓碑位置要稳定」。**叠在一起**才变成玩家视角的「这任务是不是坏了」。

### 3.3 一个容易误判的细节

`spawn_key = map_id#monster_id#ordinal`，**key 里含 map**。所以「断链巡检长」在 `c2_old_well` / `c2_pipe_slope` / `c2_lower_works` 三张图各有独立冷却 —— 在别的图杀同名怪**不会**让工坊下层进冷却（反之亦然）。玩家若在两张图之间来回找，很容易得出「这怪根本不刷」的印象。

## 四、方案（定稿 A）

只做两件事，**零代码改动**。

### 4.1 给「任务目标精英」的刷点开墓碑

口径：**只给被 `kill` 任务引用的精英目标**开，不做全量 58 个。理由是只有这几处会被玩家带着「任务指向」反复回来找，其余精英临时缺一只并不影响任何流程，而全量开会在每张图常驻多个倒计时文字。

实际命中 **5 个刷点**（数据推导，非手写清单）：

| 地图 | 目标怪 | 引用任务 |
|---|---|---|
| `c2_lower_works` | `c2_elite_broken_inspector` 断链巡检长 | C2S03 |
| `c2_pipe_slope` | `c2_elite_broken_inspector` 断链巡检长 | C2S06 |
| `c2_ember_furnace` | `c2_elite_copper_matriarch` 铜壳母虫 | 第二章精英支线 |
| `c2_well_core` | `c2_elite_spirit_guard` 汲灵护卫 | 第二章精英支线 |
| `ch01/wild_trial` | `elite_wolf_king` 裂爪狼王 | 第一章精英支线 |

> ⚠ 同名怪在同一 `scope` 之外的其他图**不加**：比如巡检长在 `c2_old_well` 也有一处刷点，但那不是任何任务的目标，不开墓碑。

### 4.2 文案去掉「Boss」前缀

`BossTombstone` 的倒计时文案键 `ui.boss_tombstone.p001` 当前写死 **「Boss 刷新 %02d:%02d」**。精英复用后会变成「Boss 刷新 01:20」，明显错。

改为 **「刷新 %02d:%02d」**——Boss 与精英共用同一句都成立，且改动只是**替换**而非新增键，不触碰本地化条数（919 不变，无撞号风险）。

## 五、影响面与风险

| # | 风险 | 评估 / 处置 |
|---|---|---|
| 🔴 R1 | 改 `map.json` 误伤其他字段 | 用脚本按「锚点唯一 + 收尾大括号」插入，插入后 `json.loads` 比对：除新字段外**逐字段全等**，顶层字段全等；`git diff -U0` 每文件只应 +1 行 |
| 🔴 R2 | 文案被改成带参 `tr_key(key, args)` 无法解析 | 键已是带参口径（`%02d:%02d`），只删前缀，占位符数量不变；测试用绝对期望串断言渲染结果 |
| 🔴 R3 | 去掉「Boss」后 Boss 那边看不懂 | 墓碑是**立在 Boss 死亡原地**的世界物件，语境自明；且倒计时本就是「下一刷还有多久」 |
| R4 | 墓碑常驻造成视觉噪音 | 仅 5 个刷点、仅冷却期存在；`_process` 里 `remaining <= 0` 即恢复正常刷新 |
| R5 | 距离门槛导致墓碑不出现 | `_spawn` 里墓碑分支在 `ACTIVE_DISTANCE` 判定**之前**（第 200—207 行），远距离也会补建 |
| R6 | 全量 58 个精英的取舍被后人改回/改错 | 测试只断言「任务目标精英必须有」，**不断言**「其他必须没有」，避免把设计选择钉死 |

## 六、验证

### 6.1 断言（`tests/quest_target_respawn_hint_test.gd`，已进默认集）

| 层 | 断言 | 说明 |
|---|---|---|
| 数据 | 遍历全部 `kill` 任务 → `mapScope` 内刷点 → 目标怪 `kind == "elite"` ⇒ 必须 `tombstone` | **从业务数据推导**，不写死 5 个 id；前置「至少命中 5 处」防空跑 |
| 数据 | `bossSpawn` 全部带 `tombstone`（前置 ≥ 17 处） | 防止「只加精英、改坏 Boss」 |
| 文案 | `tr_key("ui.boss_tombstone.p001", [1, 5]) == "刷新 01:05"` | 绝对期望串，不复用被测常量 |
| 文案 | 渲染结果不含 `Boss` | 精英复用同一句 |
| **行为** | 真 `mark_spawn_dead(...)` 后装配 `Main`：`Spawner` 下必须出现 ≥1 个 `BossTombstone`，且落点距目标格 **< 64px** | 数据对 ≠ 世界对，这层独立守「Spawner 是否真透传」 |

### 6.2 负向验证 `tools/verify_100_negative.py` —— **5 / 5 全部变红**

| 案例 | 注入 | 红在哪 |
|---|---|---|
| N-1 | 摘掉 `c2_lower_works` 的 `tombstone` | 数据层 + 行为层同时红（原 bug 形态） |

| N-5 | `Spawner` 不再透传（恒 `false`） | **只有行为层红**，数据层照绿 ⇒ 两层各有独立牙 |

### 6.4 实机点验（待玩家）

杀一次目标精英 → **立刻**看原地是否出现「刷新 01:xx」→ 到点后重新出现 → 任务进度 +1 / 交付正常。
另外顺带确认：Boss 墓碑文案由「Boss 刷新 09:30」变为「刷新 09:30」是否符合预期。


## 七、小结

- 这是一次**「设计取舍叠加」**而非代码错误：缺提示 + 标记常亮 = 玩家判成 bug。
- 修复只碰数据与文案，代码零改动，回退成本为「删字段 + 改回一句文案」。
- 真正的教训记进 08 坑清单：**世界里的「暂时不存在」必须在原处留痕**，否则任何「导航指向 + 目标缺失」的组合都会变成报障。
