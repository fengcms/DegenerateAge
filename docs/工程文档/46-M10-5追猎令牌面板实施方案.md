## 1. 一句话结论

令牌面板本身是**纯查询 + 两个现成动作**（同图走 `Game.request_map_move`、跨图走车夫出行），
但它踩在两个**已存在的缺口**上：`MapService._map_has_monster()` 只认单点 `bossSpawn`（`c7_arena` 的 10 只全查不到），
以及**全库没有「落地后自动走」这条一次性意图**。这两条不补，令牌在循环图上就是哑的。

## 3. 设计决策

### 3.1 跨图能力提前落地（M10-7 复用，不重复建）

产品 §5.4 要求「跨图 → 确认扣金 → `travel_anywhere` + 落地自动走」。`travel_anywhere` 原计划属 M10-7，
但令牌**离开它就只有同图能用**（27 行里 17 行在别的图），等于交一把半残的令牌。
故本批把它提前落下，M10-7 只剩「车夫面板七分组 UI + C6Q13 任务 + 翻 `shop` 的 `ready`」。

| 新增 | 与既有关系 |
|---|---|
| `MapService.fee_anywhere(map_id)` = `maxi(50, 20 × recommended_level(map_id))` | **不动 `fee_to`** —— 既有车夫仍按 `carterFares` 拓扑差异化定价 |
| `MapService.travel_anywhere(map_id)` = `travel_to` 去掉 `is_linked` 一条 | 其余校验（exists / unlocked / visited / 金币 / 原子提交 / 回滚）**逐条复用同一段代码**，不复制粘贴 |

> ⚠ 双费用并存：同一目的地，当地车夫可能比随身车夫便宜（如 `c3_map00` 当地 300、随身 420）。
> 这是产品口径（随身 = 便利溢价），不视为 bug。见 §8 Q-1。

### 3.2 令牌行：`BossToken.rows()` 一个纯查表函数

新建 `scripts/systems/boss_token.gd`（`class_name BossToken extends RefCounted`），参照 `Quest` 的写法直接读 `GameState`：

```
rows() -> Array[Dictionary]
  [{map_id, map_name, monster_id, monster_name, ordinal, level, drop_level,
    remaining, alive, world_pos, is_current_map, unlocked}]
```

| 字段 | 取法 |
|---|---|
| 数据源 | `DataLoader.get_table("maps")` 全表遍历（**只在面板打开时调一次**，产品 §5.4 性能口径） |
| boss 列表 | `bossSpawns` 数组优先，回退 `[bossSpawn]`（与 `MapService.current_bosses()` 同口径） |
| 过滤 | 只保留 `GameState.is_visited(map_id)` 为真的图（当前图强制保留，防 visited 漏标） |
| `ordinal` | 该图 boss 列表内**同 monsterId 的出现序号**（现全库无重叠、`c7_arena` 10 只全不同 ⇒ 恒 0，但按规则算，§4.4 用启动校验把假设变契约） |
| `level` | `levelFromPlayer.enabled` → `maxi(minLevel, player.level)`；否则规格 `level` → 回退 `recommended_level(map_id)` |
| `drop_level` | 同 `level`（`levelFromBoss` 掉落表的 `source_level` 就是怪物等级） |
| `remaining` | `GameState.spawn_remaining(map_id, monster_id, ordinal)` |
| `world_pos` | `Iso.grid_to_world(cell)`，`cell` 取值规则与 `spawner.gd:112` 一致（`cells[i]` 优先，回退 `cell`） |

**为什么 `_map_has_monster` 必须补 `bossSpawns`（F-1）**：`start_quest_navigation` 是 F-3 的现成跨图意图，
`BossToken` 不重造它。但补完之后 `c7_arena` 才能被任务/导航认出来 —— 这是一条**独立于令牌的正确性修复**，
不补则 `c7_arena` 里的任何 Boss 都无法被 `start_quest_navigation("c6_boss03", [...])` 定位（下一批 M10-7 的
「追踪巡逻」类任务也会踩到）。

### 3.3 落地自动走：一条一次性意图，**不入档**

```gdscript
# map_service.gd
var pending_landing_move: Variant = null      # Vector2 或 null，运行态不入档

func arm_landing_move(world_pos: Vector2) -> void:
	pending_landing_move = world_pos

## 消费一次即清空（与 save_pos 同口径）。
func consume_landing_move() -> Variant:
	var out := pending_landing_move
	pending_landing_move = null
	return out
```

消费点：`game.gd` 的 `_notify_arrival.call_deferred()` 之后追加

```gdscript
_consume_landing_move.call_deferred()

func _consume_landing_move() -> void:
	var target: Variant = MapService.consume_landing_move()
	if target is Vector2:
		request_map_move(target)
```

🔴 **三条必须写死**：
1. `rollback_travel()` 里**必须清 `pending_landing_move`** —— 否则切图失败回滚后，玩家在原图被莫名指挥走向一个别的图的坐标。
2. 只在 `commit_arrival()` **成功之后**消费（`commit_arrival` 返回 false 时 `_ready` 直接 `return`，天然满足）。
3. 读档路径不 arm ⇒ 不启用，无需额外分支。

### 3.4 面板形态：与 `carter_panel` 同构（模态、居中、可滚）

- 信号：新增 `EventBus.boss_token_panel_requested(title: String)`，与 `carter_panel_requested` 完全同构。
- `PanelRouter.open("boss_token")` → emit 该信号；`PANELS["boss_token"]["ready"] = true`。
- 面板内部行结构：`地图名` + 每条 Boss 一行 `怪物名 · 等级 L · 预计掉落 L 级装备` + 状态徽标（存活 / 冷却 mm:ss）+ 右侧按钮。
- **排序**：当前图的 Boss 行置顶（紧跟一个分隔线），其余按 `recommended_level` 升序。
- **刷新策略**：打开时构建一次行（缓存节点引用），之后 `_process` **只更新倒计时文字**，不重建列表 —— 满足产品「不要在 `_process` 里重算 35 图 × 10 条」。

### 3.5 点击行为

| 场景 | 行为 |
|---|---|
| 同图 | `world.request_map_move(row.world_pos)` → 关面板 → toast「已标记追猎目标」 |
| 跨图 | 若金币不足 → 按钮禁用 + tooltip 示价；够 → `MapService.arm_landing_move(row.world_pos)` → `travel_anywhere(map_id)` → 成功则关面板 + `reload_world()` |
| 冷却中 | 按钮**仍可点**（追猎 ≠ 打得到，玩家可能先去等）；状态文案明确「冷却中 mm:ss」 |
| 未解锁图 | 按钮禁用 + 原因（`is_unlocked` 为假时该图本来也不在 visited 里，正常不会出现） |
