> 状态：**已定案 / 已实施**（2026-10-22，提交见 §11）

> 前置：工程 91（孤王绝域）、工程 92（强度 + 必出紫）。本方案**只改落点散布**，不动掉落内容、时序、拾取。

## 1. 现状：为什么必然糊成一坨

`LootBurst._scatter()` 用**黄金角螺旋 + 松弛**把整批掉落散布在一个**环带**里：

| 常量 | 值 | 折算 |
|---|---|---|
| `RING_TILES["boss"]` | `[1.2, 2.5]` 格 | 半径 **77—160px**，环带面积 61,895 px² |
| `MIN_SPACING_TILES` | 0.35 格 | 中心最小间距 **22.4px** |

按各表件数上限代入，每件分到的等效直径是：

| 件数 | 来源 | 每件等效直径 | 结论 |
|---|---|---|---|
| 12 | 回廊 Boss / 三—六章 Boss | 81.0px | 勉强，名字会叠 |
| 23 | `DT_C7_Boss_Field` | 58.5px | 挤 |
| 86 | `DT_C7_Solo_Boss` 期望值 | **30.3px** | 图标都叠 |
| 102 | `DT_C7_Solo_Boss` 上限 | **27.8px** | 彻底糊 |

而每件物品的**实际视觉占用**是：

- 图标 **32×32**（`SampleArt.ground_for` 固定 32px）
- 落地阴影半径 11px、稀有以上光柱（高 36/60/90px）
- **稀有以上名字常显，绘制宽度 240px**（`GroundItem._draw_label`：`draw_string(..., center.x - 120, ...)`，`HORIZONTAL_ALIGNMENT_CENTER`，宽 240）

> **定量结论**：86 件的实际可用直径只有 30.3px，比图标本身（32px）还小 —— 图标必然重叠；而名字宽 240px 是格间距（22.4px）的 **10.7 倍**，名字必然叠成一片糊字。截图里的观感不是「排布不好看」，而是**物理上放不下**。

根本原因：`_scatter` 用**屏幕像素的欧氏距离**做环带，但它其实是等距地图上的一个环。在等距视角下，屏幕圆形 = 地面椭圆，横向 1 份、纵向 2 份，实际可用面积比看起来更小；且「环带」这个形状本身就要求所有东西挤在一条窄环上（内外半径只差 83px）。

## 2. 目标：传奇式「一格一件，铺满地面」

| 收益 | 说明 |
|---|---|
| **不重叠** | 一件一格（64×32 等距菱形），88 件的图标也互不遮挡 |
| **数量一眼可数** | 「爆了多大一片」本身就是爆率反馈，比文字摘要更直观 |
| **符合等距地图语汇** | 落点对齐格心，与地面格线同构，不会有「飘在半格上」的错位感 |
| **墙内不穿墙** | 逐格判定可走，落点不会跑到石头/水里去（现状靠 `clamp_to_map` 事后兜底，会挤成一堆） |

## 3. 设计方案

### 3.1 同心菱形逐格分配

以**击杀点所在格**为中心，按 Chebyshev 距离（`max(|dx|, |dy|)`）逐圈向外枚举格子：

| 圈 r | 本圈格数 | 累计 | 屏幕包围盒 | 对应件数 |
|---|---|---|---|---|
| 0 | 1 | 1 | 0×0 | 1 |
| 1 | 8 | 9 | 128×64 | ≤9 |
| 2 | 16 | 25 | 256×128 | ≤25（含回廊 Boss 12 件） |
| 3 | 24 | 49 | 384×192 | ≤49（含 Boss 战场 23 件） |
| 4 | 32 | 81 | 512×256 | ≤81 |
| 5 | 40 | **121** | **640×320** | ≤121（**孤王绝域 86—102 件**） |

- 视口 1280×800（`project.godot`，`canvas_items` + `expand`），r=5 的 640×320 包围盒在默认地图倍率下**一屏看得全**。
- 件数少的批次（普通怪 1—3 件、回廊 12 件）自动只铺 1—2 圈，**不会**因此变成一大片空地。
- 圈数由件数反推，不需要配置表。

### 3.2 内圈优先（保留现有语义）

现在 `INNER_RANK` 让**传说占最内、金币最外**。格铺保留这条：先按 `INNER_RANK` 排序，再按枚举顺序（r=0 → r=1 → …，同圈内按角度）逐格分配。效果：传说落在尸体正中间，普通件铺在最外圈。

### 3.3 逐格可走判定

新增可选参数 `walkable: Callable`（接收 `Vector2i`，返回 bool）：

- 传入时：枚举到不可走 / 越界的格子**直接跳过**，继续向后找；放不下时**自动多铺一圈**（上限 12 圈，防死循环）。
- 不传（测试 / 无地面上下文）：全部视作可走。

`Monster` 侧传一个 lambda：

```gdscript
var ground := get_tree().get_first_node_in_group("map_ground") as IsoGround
var walkable := func(cell: Vector2i) -> bool:
    if ground == null:
        return true
    if cell.x < 0 or cell.y < 0 or cell.x >= ground.grid_size.x or cell.y >= ground.grid_size.y:
        return false
    return ground.is_walkable_cell(cell)
```

> `IsoGround.is_walkable_cell()` 不判越界（`cave == null` 时恒 true），所以边界必须自己判 —— 否则孤王绝域 40×30 的图会被铺到图外。

### 3.4 精确落点

`build` 增加参数 `origin: Vector2`（击杀点世界坐标）。落点偏移：

```
offset = Iso.grid_to_world(cell) − Iso.grid_pt(center_f.x, center_f.y)
其中 center_f = Iso.world_to_grid(origin)
```

即**每件都精确落在格心**，而不是「相对死亡点平移」（后者会让整片格子随尸体位置漂移最多半格，看起来像没对齐）。`Iso` 是已有的唯一坐标来源（`TILE_W/TILE_H`），不引入新常量。

### 3.5 彻底移除的部分

| 移除 | 理由 |
|---|---|
| `RING_TILES` | 环带概念被格铺取代 |
| `MIN_SPACING_TILES` | 格距天然 64/32/71.5px，不需要松弛 |
| `GOLDEN_ANGLE` + `_relax()` | 松弛是为了在窄环里硬塞，格铺后没有意义 |

> ⚠ 这三个常量都是 **public 的 `const`**，`tests/smoke_test.gd` 第 ⑤ 段直接引用（`LootBurst.RING_TILES["boss"]`、`LootBurst.MIN_SPACING_TILES`）。删常量必须同批改测试，否则 Parse Error。

## 4. 名字重叠：必须单独决策（Q1）

图标铺开了，**名字还是会叠**：一格宽 64px，名字宽 240px（跨 3.75 格）。

### 选项 A · 大批次时名字只悬停显示（推荐）

- 规则：同批件数 **≥ 20** 时，`rare / epic / legendary` 不再常显名字，只有鼠标悬停才显示。
- 孤王绝域 86—102 件 → 地面是「图标 + 光柱」的整齐方阵，**最干净**，光柱颜色已经能区分品质（稀有 3px / 史诗 7px 双圈 / 传说 10px 星形）。
- 回廊 12 件、Boss 战场 23 件以下 → 名字照旧常显（4 件稀有也不至于叠）。
- 代价：爆一地的瞬间看不到具体名字，得悬停。

### 选项 B · 名字保留，但缩短 + 缩字号

- 去掉品质前缀与等级，只留「脉护腕」这类短名，字号 13 → 11。
- 减轻但不根治（短名约 60—80px，仍跨一格）。

### 选项 C · 保持现状（名字全显、允许重叠）

- 「满屏文字」本身有热闹感，但**一屏 100 个名字叠成糊字**，读不出任何信息。

> **推荐 A**。理由是「能看到有多少件」比「能读到每一件的名字」重要；而且光柱已经承担了品质辨识。要给玩家名字时，悬停 + 批次摘要 toast 已经够。

## 11. 实施结果

### 11.1 落成的口径

- **一件一格**：目标格由 Chebyshev 同心圈生成（r=0 中心格，r≥1 每圈 `8r` 格，环内按**地面视角角度**升序 ⇒ 确定性）。累计容量 `1+4r(r+1)`：r=1 → 9、r=2 → 25、r=3 → 49、r=4 → 81、r=5 → **121**、r=12 → 625。
- **内圈优先**：沿用 `INNER_RANK`，传说先占中心格，金币 / 杂项铺最外圈。
- **落点精确**：`row["cell"]` 是绝对格坐标，`Monster._spawn_drop` 直接 `Iso.grid_to_world(cell)`，**不再**「死亡点 + 偏移」（后者会让整片格子随尸体位置漂移最多半格）。`offset` 字段保留，但语义改成「相对击杀格心的纯格距」，供断言用。
- **越界 + 可走**：`Monster._loot_layout_context()` 里的 lambda 同时判 `[2, grid_size-3]` 与 `is_walkable_cell`。
- **名字降噪**：`batch_size` 由 `Monster._spawn_drop` 传入 `plan.size()`；判定抽成 `GroundItem.should_always_show_label(quality, batch_size)` 静态函数，使「阈值到底生不生效」可以被直接断言（否则只能靠肉眼看渲染）。

### 11.2 三处偏离方案初稿

| 偏离 | 初稿 | 实际 | 为什么 |
|---|---|---|---|
| 1 | `build(items, kind, origin: Vector2, walkable: Callable)` 两个独立参数 | `build(items, kind, ctx: Dictionary = {})` | 两个可选参数会让所有既有调用点（含 `smoke_test` 3 处、`loot_summary` 1 处）都要改；`ctx` 一处可选、按需取键，旧调用零改动。**这也是「新增可选参数前先数调用点」的教训** |
| 2 | `ground_item.gd` 加 `@export var suppress_name: bool` | 加 `@export var batch_size: int` + 静态判定函数 | 传 `bool` 等于把阈值判断散落到 `Monster`（生产者）身上，且 **bool 本身不可测** —— 测试只能断「有没有传 true」，断不出「几个件才该传 true」。传件数 + 静态函数让阈值有一条真判据 |
| 3 | 负向 3 条 | 负向 **6 条** | 实施时发现三类「同形但功能测试抓不到」的退化：格位没落到 row、名字阈值被抬到无效值、`MAX_RING` 被顺手调小（容量塌陷）。见 §11.4 |

### 11.4 六条负向（`tools/verify_93_grid_negative.py`）

| 编号 | 注入的退化 | 变红在哪 |
|---|---|---|
| N-1 | 每件都记成击杀格（格位没落到 row 上） | 「两件掉落落在同一格 (0,0)」 |
| N-2 | 忽略 `walkable` 回调 | 「格 (25,16) 落进了不可走区（x≥23）」 |
| N-3 | 内侧优先反向 | 「传说应占中心格（r=0），实际 r=5」 |
| N-4 | 名字降噪阈值抬到 100000 | 「名字降噪阈值应为 20 件，实际 100000」 |
| N-5 | 容量公式 `1+2r(r+1)`（算少） | 硬编码表「9 件应需 1 圈，实际 2 圈」 |
| N-6 | `MAX_RING` 12 → 2 | 「两件掉落落在同一格 (-1,-1)」 |

> 🔑 **N-5 是「期望值复用被测常量」那条铁律的现场演示**：`_test_ring_growth` 第二组断言用 `LootBurst.rings_for()` 算期望，只靠它必假绿（函数改坏，期望跟着坏）。所以第一组必须是**硬编码表** `{1:0, 9:1, 10:2, 25:2, 26:3, 49:3, 50:4, 102:5, 121:5, 122:6}` —— N-5 红的正是这张表。

### 11.5 给后来者的三条前提

1. **格位必须写进 `row`**：`_layout` 同时写 `cell` 与 `offset`，`_spawn_drop` 以 `cell` 为准。只写 `offset` 会让实机退回「死亡点 + 偏移」，症状是「格子歪、靠边时挤成一堆」，而所有单元断言仍绿。
2. **`walkable` 回调必须自己判边界**：`IsoGround.is_walkable_cell()` 在 `cave == null` 时恒 `true`，而 `clamp_to_map()` 的合法范围是 `[2, grid_size-3]`。少判这一层 = 掉落铺到图外再被 clamp 挤回一堆。
3. **`MAX_RING` 不是「性能旋钮」**：12 圈 = 625 格是保命线，调小到 2 会立刻让 102 件重叠，而且**没有报错、没有日志**，只有玩家看得见。
