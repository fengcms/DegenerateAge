## 1. 一句话结论

**M10-3 真正要做的不是「新建一张地图」，而是给 Boss 加一条「形象与数值解耦」的数据通道（`norm`），并让「等级」从装配期常量变成每次生成时现算。**

地图本身只是载体：一张 160×90 的环形回廊 + 20 个固定 Boss 点。真正会出事的是三处：

| 位置 | 现状 | 不处理的后果 |
|---|---|---|
| `spawner.gd:65-80` | 有 `tierRange` 就 `clampi` | 100 级玩家进图，Boss 被夹回 60 级，`S(d)` 全废（P-4） |
| `spawner.gd:88` → `:190` | `point.level` 装配期写一次，`_spawn` 只读 | 600s 复活出来永远是进图那天的等级（P-5） |
| `monster.gd:159-167` | 数值只从模板 `hpBase/attack/defense` 取 | 复用 Lv10 的 `boss_corrupted_beast`（HP 3,000）会变成纸 Boss（§4.2，差 8.1 倍） |

## 3. 三处「产品口径 vs 代码事实」的偏差（必须先说清）

### 3.1 🔴 `tierRange` 不是「建议别写」，而是「不写就启动报错」

产品 13 §4.1 写「`tierRange` **绝对不要写**」。但 `data_loader.gd:328-330` 对**每一张**地图都要求它是长度 2 的合法数组，`mp.get("tierRange", [])` 取到空数组就报错。

所以必须新开一个校验分支：

| 地图类型 | `tierRange` | 刷新点 `level` |
|---|---|---|
| 存量（35 张） | **必填**且 `[lo, hi]` 合法 | 必须在区间内（原样保留） |
| `levelFromPlayer.enabled = true` | **必须缺席** | 允许缺席（等级现算），写了则必须 ≥ `minLevel` |

两个方向都要报错。写成「都可选」会让一张既写 `tierRange` 又写 `levelFromPlayer` 的坏表静默走夹紧分支，症状就是「100 级进图还是 60 级 Boss」——和 M10-2 的 `levelFromBoss` 同一个坑。

### 3.2 🟠 「进图 20 只」与 `ACTIVE_DISTANCE = 760` 冲突

`_spawn` 对 `fixed` 点有距离预算：距玩家 > 760px 不建实体（`spawner.gd:176-178`）。160×90 的回廊里，玩家从西门进图时只有 **2–4 只**在 760px 内。

**20 席只是登记的刷新点，实体仍受 `ACTIVE_DISTANCE=760px` 限制，同屏实际远小于 20。**

- **建议保留**距离预算。理由：这是既有性能设计（`AGENT.md` §2 明确「小地图静态底图 / 静态地形批量 / 刷新预算」不可退），且产品 §4.1 自己写着「避免 20 只同时追人」。
- **验收口径应改成**：「装配 **20 个点** + 20 条墓碑/标记；就近生成 2–4 只；走近后补建」。硬要 20 只同时在场，等于把 20 只 Boss 的 AI + 血条 + 技能一起拉满，与 3b 未做的多目标血条叠加会更难看。

> 墓碑不受此限：M4-10 修复已把「等待期落墓碑」提到距离判断之前（`spawner.gd:167-175`），所以远处也应能看到倒计时。

### 3.3 产品 §4.6 的掉落已经由 M10-2 落地，本批只做「接线」

`DT_C7_Arena_Boss` 已存在（M10-2，+75 行），三个 `equip` 条目全是 `levelFromBoss: true`、金币固定 3000–3400。本批只需要让 10 条 `bossSpawns` 的 `dropTableId` 指过去 —— **否则新表无人引用，白建**。

## 5. 代码改动

### 5.1 新增 `scripts/systems/endgame.gd`

```gdscript
class_name Endgame
extends RefCounted
## M10-3：满级后循环玩法的静态数据门面。与 Balance 一样不引用 GameState。

static func arena_bosses() -> Array:
	var cfg: Variant = DataLoader.get_table("endgame")
	return (cfg as Dictionary).get("arenaBosses", []) if cfg is Dictionary else []

## 归一化基底（hp/atk/def）；未登记返回空字典 ⇒ 调用方回退模板数值。
static func norm(monster_id: String) -> Dictionary:
	for entry in arena_bosses():
		if entry is Dictionary and String(entry.get("monsterId", "")) == monster_id:
			var n: Variant = entry.get("norm", {})
			return n if n is Dictionary else {}
	return {}
```

### 5.3 `scripts/entities/monster.gd`

新增三个字段：

```gdscript
@export var stat_norm: Dictionary = {}   # M10-3：{hp, atk, def} 归一化基底
@export var scale_stats: bool = false    # M10-3：攻/防随 S(d) 缩放
@export var xp_from_curve: bool = false  # M10-3：经验由 Balance.boss_xp 反推
```

`_load_template()` 里改为：

```gdscript
var scaled := Balance.scale(level - Balance.SOFTCAP_LEVEL)
if not stat_norm.is_empty():
	max_hp = maxi(1, int(round(float(stat_norm.get("hp", 1)) * scaled)))
else:
	max_hp = _derive_max_hp(tpl_level)          # 存量口径一字不动
...
attack_power  = float(template.get("attack", 0.0))
defense_power = float(template.get("defense", 0))
if not stat_norm.is_empty():
	attack_power  = float(stat_norm.get("atk", attack_power))  * scaled
	defense_power = float(stat_norm.get("def", defense_power)) * scaled
elif scale_stats:
	attack_power  *= scaled
	defense_power *= scaled
```

`_settle_rewards()` 里：

```gdscript
var base_xp := Balance.boss_xp(level) if xp_from_curve else int(template.get("xpReward", 0))
var xp := LevelGap.kill_xp(base_xp, int(GameState.player.get("level", 1)), level)
```

> 为什么 `norm` 存在时不走 `_derive_max_hp`：`_derive_max_hp` 的 `d` 是「相对模板等级」（Lv10 模板在 60 级时 d=50），而 `S` 的 `d` 是「相对 60 级」。两者锚点不同，混用会得到 24,300×7 = 17 万这种错值。

## 8. 两个待拍板点的结论

### Q-10：P-9 并入本批 ✅（用户 2026-10-18 拍板）

产品排期原本把它放在 M10-3b。但 M10-3 一上线，它就从「潜在问题」变成「必然问题」：10 只 Boss × 每只 7–10 件，背包 40 格打满 4 只后，未领取记录必然超 20 → `_evict_unclaimed_overflow()` **丢最旧**，玩家打第三只时第一只的掉落已经没了。

**落地方式（D-13：普通 20 / 循环 200）**：上限改为**按图取** —— `GameState.unclaimed_loot_cap(map_id)` 读 `maps.json` 的 `unclaimedLootCap`，缺省 `UNCLAIMED_LOOT_CAP = 20`；`c7_arena` 配 **200**。

⚠ 附带一处**语义修正**：原实现是「跨全部地图总数 ≤ 20」，一张图刷满会把别的图的记录挤掉。改为**逐图判定**后，记录只受本图上限约束。代价是理论上限从 20 变成「各图上限之和」，实际不可能堆满（玩家要主动在每张图都留满且不去捡），但记入 R-8。

### Q-11：入口钥匙 = `campaign_complete` ✅（用户 2026-10-18 拍板）

C6Q12 奖励产出（已核实 `data/quests.json`）：「循环玩法是主线通关后的去向」语义最准，也避免 57 级玩家误闯 60 级 Boss。

出口 `c6_map00_exit03` **自己也带 `requiresUnlock: campaign_complete`**（双保险）：`request_walk` 先查 `_exit_open` 再查 `is_unlocked`，地图锁被改档绕过时出口仍拦得住。
