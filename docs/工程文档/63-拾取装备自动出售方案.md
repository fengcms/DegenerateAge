| 你的原话 | 我的理解 |

| 设置 → 游戏选项卡增加「自动出售背包内的装备」 | 「游戏」页（`_build_game`，现在只有 4 项）新增一个勾选框 |
| 玩家勾选后，捡到装备会自动出售成金币 | **拾取那一刻**判定，判定通过就不进背包、直接入账 |
| 该功能 60 级才允许勾选 | 界面 <60 灰显；**运行时也要拦一次**（改档 / 导入档可能带 true） |
| 筛选最多「积极」，不能「暴力」 | 用与出售面板同一套三档预设（谨慎 / 标准 / 积极） |

⚠️ 有一处需要你先确认口径：**「积极」并不等于「全都卖」**。现有 `SellGearPolicy` 的积极档 `max_quality = "rare"`，品质高于稀有的（史诗 / 传说）会被 `quality` 理由拦下。也就是说积极的实际行为是「稀有及以下、且不比身上好的，全卖；史诗传说留包」。如果你的本意是「积极 = 背包里所有能卖的装备」，那要另开一档或改积极的上限 —— 这会连带改动手动出售面板的既有语义，**不建议**。本方案按「积极 = 现有积极」实现。

## 2. 现状勘察（接线为什么不能只加一行）

### 2.1 拾取链路

```
Monster._settle_rewards()          # 掉落
  → LootBurst.build()              # 展示编排
  → Monster._spawn_drop()          # 生成 GroundItem（auto_claim / silent_pickup / persistent）
      → GroundItem._ready()        # auto_claim ⇒ _try_claim()
          → GroundItem._try_pickup()
              → Inventory.add(GameState.inventory, item)   ← 直接调静态，绕过 GameState
```

**关键事实：`GroundItem` 不用 `GameState.add_item()`。** 全项目 `add_item()` 的调用方只有 `shop_buy`（买货）和 `quest.gd`（任务奖励）。

由此得出两条硬结论：

| 接错的位置 | 后果 |
|---|---|
| 🔴 改 `GameState.add_item` | 商店买的装备、任务奖励的装备也会被当场卖掉 —— **灾难** |
| 🔴 在 `Monster._settle_rewards` 里过滤 | 只覆盖怪物掉落，不覆盖「未领取战利品重新拾取」「玩家丢弃物回来捡」，且金币 / 经验结算顺序会乱 |

✅ 正确接法：**新增 `GameState.pickup_loot(item)` 门面**，`GroundItem._try_pickup()` 的装备分支改为调它。理由：

1. 判定需要 `settings` / `player.level` / `equipment` / `Shop.sell_price` / `add_gold`，全在 `GameState` 手边；
2. 单一入口便于测试（测试直接调函数，不用搭场景树）；
3. `add_item` 的语义（商店 / 任务）保持一字不动。

### 2.2 现有可复用的筛选规则

`SellGearPolicy.entry()`（`scripts/systems/sell_gear_policy.gd:35`）已经实现了全部价值判断，自动出售**不应另写一套**，否则两处规则必然漂移。现有理由集：

| reason | 含义 | 自动出售时 |
|---|---|---|
| `favorite` | 收藏 | 不卖 ✅ |
| `unsellable` | `Shop.can_sell` 失败（任务物品 / 无价 / 非可售品类） | 不卖 ✅ |
| `upgrade` | 该槽装着东西，且新件评分更高 | **不卖（必须）** |
| `starred` | 已升星 | 不卖 ✅ |
| `quality` | 品质高于预设上限 | 不卖 ✅ |
| `level` | 等级差（仅谨慎档） | 不卖 ✅ |
| `suit` | 旧套档（仅标准档） | 不卖 ✅ |

### 2.3 🔴 我发现的一个设计黑洞：空槽位装备会被卖掉

`sell_gear_policy.gd:63`：

```gdscript
# V1：空槽（评分基准 0）不计入保护 —— 该槽类还有空位时不再整类卖不掉。
var stronger := not bool(preview.get("empty", true)) and bool(preview.get("score_increase", false))
```

空槽 ⇒ `stronger = false` ⇒ 不加 `upgrade` 理由 ⇒ `default_selected = true`。

这在**手动面板**里是合理设计：玩家看得见清单，可以自己取消勾选。
但在**自动出售**里是致命的：玩家某槽还空着（新角色、刚换下来的部件、某套装没凑齐），捡到该槽第一件装备 → **当场卖掉 → 永远穿不上那件**。

这条必须在自动出售里单独否决。这是本方案唯一的 P0 级设计分歧。

## 3. 四个待拍板的决策点

### D1 预设从哪来

| 选项 | 行为 | 代价 |
|---|---|---|
| **A（推荐）** | 复用 `settings.sellGearPreset`，设置页放一个三档下拉，与出售面板**同一键双向同步** | 在设置里改 = 面板里也变（反过来说这是「单一真相」） |
| B | 新开 `autoSellPreset` 独立键，默认「谨慎」 | 两处可能不一致：设置里选积极、面板里选谨慎，玩家会困惑「我到底卖的是什么标准」 |

选 A 顺带满足「不能选暴力」：`SellGearPolicy.PERSISTABLE` 只有三档，`set_sell_gear_preset()` 拒绝 `brutal`，`CHOICE_VALUES["sellGearPreset"]` 也只登记三档。**暴力根本进不了这个键**，不需要额外写拦截。

### D2 空槽位装备

| 选项 | 行为 | 风险 |
|---|---|---|
| **A（推荐）** | 该槽为空 ⇒ **不卖**，进背包 | 背包会多几件「本来也该卖」的装备，玩家自己手动卖 |
| B | 沿用现有规则（空槽也卖） | 见 §2.3：新角色第一件装备必被卖，可能永久卡装备进度 |

### D3 金币已满（`GOLD_CAP = 999999999`）

| 选项 | 行为 |
|---|---|
| **A（推荐）** | 金币满 ⇒ **不自动出售**，装备照常进背包；节流提示一次「金币已满，装备未自动出售」 |
| B | 照卖，溢出部分丢弃 | 等于把装备白扔。工程 59 刚把「满金币照卖只提示」用在**手动**出售上（玩家自己点的，知情），但自动出售是**玩家没点**的，不能默认他愿意扔 |

### D4 手动点击拾取是否也自动卖

| 选项 | 行为 |
|---|---|
| **A（推荐）** | 也卖 —— 勾了「自动出售」就是对这件物品的整体态度，点一下也是捡 |
| B | 只对自动拾取生效，手动点击视为「我想留着」 | 需要区分 `_try_claim` / `_on_click_area_input_event` 两条路径，多一个隐式语义 |

## 4. 方案设计

### 4.1 数据

| 项 | 内容 |
|---|---|
| 新设置键 | `autoSellEquipOnPickup: bool = false`（`GameState.default_settings()`） |
| schema | **不 bump**（铁律：给 `default_settings()` 加 bool 键绝不 bump；旧档缺键由 `_migrate_settings()` 补默认值，`_is_valid_save` 逐键查 bool 类型已通用） |
| 预设 | 复用 `sellGearPreset`，不新增键，不改 `CHOICE_VALUES` |
| 等级门槛 | `const AUTO_SELL_MIN_LEVEL := 60`，放 `SellGearPolicy`（规则的单一来源），UI 与运行时都读它 |

### 4.2 判定链（`SellGearPolicy`）

把 `entry()` 里算 `reasons` 的那 20 行抽成私有静态函数 `_reasons(item, player_level, equipment, preset) -> Array[String]`，`entry()` 与新增的 `auto_sell()` 共用。

```gdscript
## 拾取瞬间的自动出售判定。返回 {sell, reason, price}。
## 与 entry() 共用同一份理由集，额外三条自动出售专属否决（顺序即优先级）：
##   ① 等级门槛 ② 金币已满 ③ 空槽位（见方案 63 §2.3）
static func auto_sell(item, player_level, equipment, preset, gold_capped: bool) -> Dictionary
```

判定顺序（短路，可读性优先）：

1. `kind != "equip"` → 不卖（不回这里，由调用方先分流）
2. `player_level < AUTO_SELL_MIN_LEVEL` → 不卖，`reason = "level_gate"`
3. `gold_capped` → 不卖，`reason = "gold_capped"`
4. `_reasons(...)` 非空 → 不卖，`reason = reasons[0]`
5. `Equipment.replacement_preview(...).empty == true` → 不卖，`reason = "empty_slot"`（D2 选 A 时）
6. 全过 → `sell = true, price = Shop.sell_price(item)`

⚠️ 第 5 步要**重新调用一次** `replacement_preview`（`_reasons` 内部也算过一次）。为避免重复计算，把 `preview` 作为参数在内部传递，不重复算 —— 掉落雨峰值 20 件/秒，重复算虽然也不慢，但没必要。

### 4.3 拾取门面（`GameState`）

```gdscript
## 拾取一件地面物。装备在开启自动出售且判定通过时直接入账，不入背包。
## 返回 {ok, auto_sold, gold}；ok=false 表示入包失败（背包满，沿用旧语义）。
func pickup_loot(item: Dictionary) -> Dictionary
```

内部：

```
if kind != "equip"  → 走原 Inventory.add 分支（金币 / 坐骑 / 药水 / 如意 / 杂项）
if not auto_sell_enabled() → Inventory.add
var d := SellGearPolicy.auto_sell(...)
if not d.sell → Inventory.add
var gained := _gold_gain(d.price)
EventBus.item_picked.emit(itemId)      # 保留：拾取音效 + 任务统计都挂在这个信号上
EventBus.trade_done.emit("sell", itemId, gained)
if gained < d.price: _notify_gold_gap(...)   # D3 选 A 时理论到不了，防御性保留
return {ok: true, auto_sold: true, gold: gained}
```

`auto_sell_enabled()`：

```gdscript
func auto_sell_enabled() -> bool:
    return bool(settings.get("autoSellEquipOnPickup", false)) \
        and int(player.get("level", 1)) >= SellGearPolicy.AUTO_SELL_MIN_LEVEL
```

🔴 等级判断放在**运行时**而不是只放 UI。理由：`settings` 是随存档走的，改档 / 导入别人的档 / 未来出现降级机制，都可能出现「等级 <60 但开关是 true」。只拦 UI 等于没拦。

### 4.4 `GroundItem` 改动

`_try_pickup()` 第 332 行那段改为：

```gdscript
var res := GameState.pickup_loot(item)
if bool(res.get("ok", false)):
    EventBus.item_picked.emit(...)   # 已由 pickup_loot 发出，此处删除
    ...
```

具体细节：

| 项 | 处理 |
|---|---|
| 拾取提示 | 自动出售时 `_pickup_msg = "自动出售：<名> +<N> 金币"`，**替换**原来那条「拾取：<名>」，总条数不变（不新增刷屏源） |
| `silent_pickup`（精英/Boss 装备） | 保持不变，自动出售同样静默 —— 由批次摘要统一说明 |
| 新增只读字段 | `auto_sold_gold: int`（0 = 未自动出售），供 `Monster._settle_rewards` 统计 |
| `persistent` 未领取登记 | 自动出售成功 ⇒ `is_claimed() = true` ⇒ 不登记，逻辑天然正确，无需改 |

### 4.5 批次摘要（`LootNotify`）

`summary_text()` 新增两个**带默认值**的参数：

```gdscript
static func summary_text(monster_name, rolled, unclaimed_equip, manual_pickup := false,
        auto_sold := 0, auto_sold_gold := 0) -> String
```

追加形如 `· 自动出售 3 件 +900 金币`（仅 `auto_sold > 0` 时）。

🔴 必须带默认值：`smoke_test.gd:1403 / 1408 / 1412 / 1434` 四处按 3–4 个参数调用，加必填参数会直接编译失败。

`Monster._settle_rewards()` 侧：循环里额外累加 `if gi != null and gi.auto_sold_gold > 0: auto_sold += 1; gold += gi.auto_sold_gold`。

### 4.6 设置界面（`_build_game`）

在「游戏」页现有 4 项之后追加：

```
☐ 拾取装备时自动出售          ← CheckBox，<60 disabled + 灰字说明
   筛选： [ 标准 ▾ ]          ← OptionButton，三档，写 settings.sellGearPreset
   不会出售：收藏、任务物品、比身上更好的、以及空槽位的第一件  ← 说明文字，autowrap
```

要点：

- `_checkbox()` 现有实现只接 `field`，不支持 disabled；新增一个带 `enabled` 与 `hint` 的变体，或在 `_build_game` 里手工构造（**不改进 `_checkbox` 的签名**，避免动到另外 4 个调用点）。
- 等级不足时：`disabled = true`，`tooltip_text = "60 级后可开启"`，文案后缀直接写进 label 更直观（玩家不会去悬停一个灰按钮）。
- 🔴 **等级变化要能刷新**：`set_open(true)` 时重算 `disabled`（等级只升不降，但读档 / 切角色会变）。挂在 `_refresh_keys()` 同级的位置，不要只算一次。
- 预设下拉与出售面板共用同一个键 ⇒ 两边都读 `settings.sellGearPreset`。面板侧已经每次 `_reload_entries()` 重读，天然同步；设置侧 `set_open` 时重读。
- 勾选不改 `_changed()` 的既有职责（`apply_all` + `save_display_preferences` + `settings_changed` → autosave 已接好，见 `save_manager.gd:302`）。

## 8. 一个提醒

自动出售是**不可撤销的资产销毁**。它跟「暴力预设」的区别是：暴力是玩家当下面板的主动点击，自动出售是「一次授权、长期生效」。所以本方案在三处都取了保守侧：金币满不卖、空槽不卖、收藏不卖。

如果你希望「勾选时给一次确认」，我建议**不弹窗**（和现有设置项一致），改为首次勾选时弹一条说明 toast。这条你一句话定即可。
