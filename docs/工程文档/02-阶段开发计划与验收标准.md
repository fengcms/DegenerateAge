# 02 阶段开发计划与验收标准

本文档是《末法纪元：最后的守护者》的**工程执行基线**。它把 `docs/产品文档/`（产品事实源）翻译成"按什么顺序做、每步做出什么、如何验证通过"的施工图。

- 设计依据：`docs/产品文档/`（00–12 + 附录A）。
- 排期依据：产品文档 1.6《开发排期原则（最小闭环）》+ 12.2-G《分阶段实施路线》。
- 验收依据：产品文档 10.5《质量与验收标准》（16 项测试场景 T01–T16）。
- 工程环境：Godot **4.7.2** / GDScript；仓库 `master` 为开发主线。

## 1. 核心原则：每个阶段都是"可运行 + 可验证"的最小增量

```
        ┌──────────────────────────────────────────────────┐
        │  一个阶段 = 一批子步骤 + 一份验收清单              │
        └──────────────────────────────────────────────────┘
                 │
   ┌─────────────┼──────────────┬────────────────────┐
   ▼             ▼              ▼                    ▼
 编码子步骤   自动回归       手动验收清单        提交 & 推送
 (M-x 编号)  (无头校验)     (逐条勾选)          feat(阶段名)
   │             │              │                    │
   └─────────────┴──────────────┴────────────────────┘
                 ▼
        通过 → 阶段标记 ✅ → 进入下一阶段
        未通过 → 修到通过为止（不带着问题前进）
```

**铁律**：
1. **不带病前进**——上一阶段的验收清单未全绿，不开下一阶段。
2. **每步可测**——每个子步骤都必须有一条"能亲自验证"的判据，不接受"写了就算完成"。
3. **数据驱动**——新增内容改 `data/*.json`，不改代码（产品文档 10.1）。
4. **每阶段一次提交**——中文约定式提交（`feat(阶段): …`），推送 `origin/master`。

## 2. 三层验证机制（"可验证"如何落地）

| 层 | 手段 | 命令 / 方法 | 何时跑 |
|---|---|---|---|
| **A 自动 · 冒烟测试** | 无头断言脚本：数据校验 + 等距公式往返 + 出生点 + 边界碰撞 | `"$GODOT" --headless --path . res://tests/SmokeTest.tscn`（退出码 0 = 通过） | 每次提交前 |
| **B 自动 · 启动回归** | 跑主场景捕获脚本错误 + 数据校验（ID 唯一 / 引用合法 / 掉落权重 / 等级范围） | `"$GODOT" --headless --path . --quit`，断言含 `配置校验通过 ✅` 且无 `SCRIPT ERROR` | 每次提交前 |
| **C 手动 · 验收清单** | 每阶段一份可勾选清单（人操作 / 或经 AI 驱动） | 见本文档各阶段"验收清单" | 阶段收尾 |

> 命令中 `GODOT=/Applications/Godot.app/Contents/MacOS/Godot`。首次运行或**新增 `class_name` 脚本后**，须先执行一次 `"$GODOT" --headless --path . --import` 注册全局类（否则报「类型未声明」）。
> 说明：A 层无法覆盖"手感/画面/交互"这类只能人眼判断的项，因此 C 层不可省。B 层随数据规模增长持续加规则。
