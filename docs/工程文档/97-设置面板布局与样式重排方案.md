# 97 · 设置面板布局与样式重排方案

> 状态：**已定案 / 已实施**（2026-10-23，按 Q1=B 卡片+分隔线、Q2 改页签名、Q3 高度 680、Q4 不折叠落地）
> 需求原话：「设置面板里面的内容比较杂乱，没有主次，整理一下，看怎么优化各个选项卡的布局和样式」
> 边界：**只动布局与样式**。不改任何设置键名、默认值、存档结构、控件行为与判据语义；不加新功能（仅新增分组标题文案）。

## 1. 现状盘点

`scripts/ui/settings_panel.gd` 464 行，5 个页签、**44 个可交互控件**、**9 条说明文字**、**1 条改键列表（29 项）**。

| 页签 | 控件 | 说明文字 | 内部结构 |
|---|---|---|---|
| 音频 | 2 滑块 | 1 条（24 字） | 平铺 |
| 画面 | 3 档位下拉 + 1 色盲下拉 + 1 适配下拉 + 1 手动滑块 + 1 勾选 + 1 分辨率下拉 | 2 条（86 字） | **全部平铺，无分组** |
| 游戏 | 1 滑块 + 4 勾选 + 1 自动出售勾选 + 1 筛选下拉 | **4 条（294 字）** | **全部平铺，无分组** |
| 控制 | 29 个改键按钮 | 1 条（26 字） | **29 行全平铺** |
| 数据 | 1 按钮 | 1 条（25 字） | — |

### 1.1 量化：垂直空间根本不够

字号 16（`default_theme.tres` 的 `default_font_size`），行高约 26—28，页内容间距 12。
面板高度上限 600（`_update_layout` 的 `minf(600, ...)`），减去标题带 40、`make_title_gap` 1、页签条约 44、四周边距约 40 ⇒ **内容区可用高约 475**。

| 页签 | 估算内容高 | 可用高 | 结论 |
|---|---|---|---|
| 音频 | ≈ 110 | 475 | 宽裕 |
| 画面 | ≈ 400 | 475 | 刚好 |
| 游戏 | **≈ 520** | 475 | **溢出约 2 行，进场就要滚** |
| 控制 | **≈ 820** | 475 | **溢出约 12 行，滚 1.7 屏才能找到「快捷格 7」** |
| 数据 | ≈ 90 | 475 | **一个页签只装 90px 内容** |

> 这是「塞满」和「找东西要滚」的物理来源，不是错觉。

## 2. 根因（三条，互相独立）

### 2.1 缺一整个「分组层」

`PanelChrome` 早就提供了两件套：`style_card()`（深底 + 细边 + 内距 12/10）与 `style_section()`（16 号 TEXT 色小标题）。
全项目 **13 个面板**在用（人物 / 铁匠 / 坐骑 / 技能 / 仓库 / 存档 / 任务 / 大地图 / 重铸 / 流程反馈 …），
**唯独设置面板一个都没用**。

结果：页签之下直接就是控件，于是「标题 20 号」与「正文 16 号」之间空了一整级——玩家看到的是 44 个等权重的控件排成一条线。

### 2.2 每一行各写各的规格

| 行类型 | caption 宽 | 控件宽 | 出处 |
|---|---|---|---|
| 滑块行 | 160 | 300 | `_slider` |
| 档位下拉行 | 160 | **无（随内容）** | `_option_row` |
| 色盲行 | 160 | **无** | `_build_visual` 内联 |
| 显示适配行 | 160 | **无** | `_build_display_adapt` 内联 |
| 自动出售筛选行 | 160 | **无** | `_build_auto_sell` 内联 |
| 改键行 | **300** | 140 | `_refresh_keys` |
| 勾选行 | **无 caption** | — | `_checkbox` |
| **分辨率下拉** | **完全没有 caption** | 无 | `_build_visual` 第 211—222 行 |

三条后果：

1. **控件起点不齐**：`160 + 间距` 与「裸挂的勾选框」和「300 的改键行」三种左边界并存，右边缘也参差（下拉框宽度随文字长度变，「80%」和「自动（推荐）」不等宽）。
2. **分辨率下拉是一个孤儿**：它直接 `box.add_child(resolution)` 挂在「全屏显示」勾选框下面，**没有标签**。玩家看到一个孤零零的下拉框，只能靠猜。
3. **控制页 300 的 caption 是浪费**：最长功能名「打坐 / 起身」只有 7 字 = 112px，实际用了 300，中间空 188px，而右侧按钮只有 140 —— 一页 29 行都在浪费同一条空白。

### 2.3 说明文字与它解释的对象失联

7 条说明全部用默认 Label：与正文**同字号、同颜色、无缩进、无任何「这是注解」的视觉信号**。其中两处已经失联：

- **`p024`（38 字，讲「界面 / 地图 / 文字三轴独立缩放」）排在「分辨率」之后**——它解释的三个下拉在它上方隔了色盲、显示适配、手动滑块、另一条说明共 5 行。
- **`p052` / `p053`（工程 95 的自动修复 / 自动合成说明）挂在页尾**，各自 75 / 67 字，紧挨着 84 字的 `p049`。三条长说明连成一片，读完分不清哪条对应哪个开关。

### 2.4 因果顺序反了（画面页）

`显示适配`（自动 / 手动）决定**基准倍率**，三轴百分比是在基准上再乘。
但现在的顺序是「界面大小 → 地图 → 文字 → **显示适配**」，玩家先调了半天百分比，才看到决定基准的那个选项，会本能以为百分比被覆盖了——而唯一能解释这件事的 `p028` 还排在更后面。

### 2.5 页签命名不达意

- 「**控制**」：里面全是改键，玩家找改键不一定想到「控制」。
- 「**数据**」：实际只有「存档管理」一个入口，叫「数据」太抽象。

L1  页签（TabContainer，16 号，金色选中）

现状只有 L1 和 L3，且 L3 的规格不统一。补齐后 4 级字号/颜色层次：20 / 16 TEXT / 16 默认 / 14 MUTED。

## 4. 逐页改造

### 4.1 音频（2 滑块）—— 不分组

两个滑块不值得套卡片。仅统一行规格 + 说明降级。

### 4.2 画面 —— 拆 2 张卡，且调正顺序

| 卡 | 标题（新增 key） | 内容（顺序即新顺序） |
|---|---|---|
| ① | **显示适配** | 显示适配（自动/手动）+ 手动系数滑块（仅手动可见）+ 注解 `p028` |

### 4.3 游戏 —— 拆 3 张卡（最需要）

| 卡 | 标题（新增 key） | 内容 |
|---|---|---|
| ① | **战斗辅助** | 自动喝药阈值 / 自动战斗允许 Boss / 死亡后自动原地复活 + 注解 `p034` |
| ② | **拾取与出售** | 拾取飞行动画 / 拾取装备时自动出售 / 自动出售筛选 + 注解 `p049` |

### 4.4 控制 —— 29 项分 3 组，**不用卡片**

`控制页是长列表：卡片边框会把列表切碎，且每张卡上下内距吃掉 20px × 3。改用**小标题 `style_section` + 分隔线 `style_separator`**（项目里 `quest_panel` / `save_panel` / `inventory_panel` 的既有做法），只增加 3 行小标题的高度。

| 组 | 标题（新增 key） | 条目 |
|---|---|---|
| ① | **移动与战斗** | move_up / down / left / right、attack、target_next、sit_toggle（7） |
| ② | **自动与交互** | auto_battle、auto_pickup、interact、pause（4） |
| ③ | **面板与快捷格** | panel_inventory / character / map / skill / mount、mount_toggle（6）+ hotbar_1—12（12） |

同时把 caption 宽从 300 收到 **140**、键位按钮从 140 收到 **110**，整行合计 140 + 14 + 110 = 264，在高倍率窄面板下也不再被截断。

### 4.5 存档（原「数据」）—— 保留页签，改标题

一个按钮的页签确实浪费，但「存档管理」是玩家会主动找的入口，藏进别的页更难找。保留，只把标题从「数据」改为「**存档**」，按钮文案保持「打开存档管理」。

## 6. 风险

### 6.1 🔴 三条测试断言**锁死扁平结构**，加分组层必红

`tests/settings_test.gd` 有三处按「扁平」写的结构断言：

| 位置 | 现断言 | 加卡片后 | 修法 |
|---|---|---|---|
| `_check_visual_tab` 第 217—224 行 | `for row in visual.get_children()` 只扫**一层**收集「标签→下拉」 | 下拉进了卡片，`visual.get_children()` 只剩卡片 ⇒ **四个下拉全部找不到**，连带下面 6 条档位/模式/写入断言全红 | 改为**递归收集**（沿 VBox/PanelContainer 向下），断言本体不动 |
| `_check_visual_tab` 第 191 行 | `visual_tab.get_child(0) as VBoxContainer` | 若在 `_tab()` 里多包一层就红 | **不改 `_tab()` 返回结构**，卡片只加在返回的 VBox 内部 |
| `_check_controls_tab` 第 129 行 | `rows.get_parent() == controls.get_child(0)` | `_key_list` 的父变成分组容器 ⇒ 红 | 改为「`_key_list` 是控制页的**后代**」，条数断言 `== ACTIONS.size()` **保留不动** |

> 这三条不是「过时断言」，而是**同一功能的结构锚点**。改法是**换锚点、不删判据**——删掉就等于放弃「四个下拉都在」「29 条改键都在」这两件事。

### 6.2 🔴 拆卡会让游戏页更高，必须同时抬高面板上限

每张卡带来 上下内距 20 + 小标题 22 = 42，同时省掉原来的页间距 12。
游戏页 3 张卡：净增 3×42 − 3×12 ≈ **+90**，内容高从 520 涨到 ≈ 610。

若不抬高原上限，溢出从 2 行变 4 行，**玩家会觉得「改完更乱了」**。
`_update_layout` 里上限 600 → 680：`minf(680, maxf(260, logical.y - 64))`。
在 1280×800 / uiScale 1.0 下可用高 736，680 合法且仍留 56px 安全边距。
**高倍率下（uiScale 2.0 → 逻辑视口 640×400）上限被 `logical.y - 64 = 336` 夹住，照样滚动**——这是物理限制，不承诺解决。

### 6.3 ⚠ 改页签标题会连带改测试锚点

`_find_by_name(panel, "控制")` 是按**标题**找页容器的。改名「控制 → 按键」后这条必红，需同步。
`_find_by_name(panel, "画面")` 若不动「画面」则不受影响。

### 6.4 ⚠ `style_card` 会引入 `PanelContainer` 节点

`_check_panels_matrix` 里有 `responsive.find_children("*", "PanelContainer", true, false)` 并取**面积最大**者做越界断言——但它只对 `QuestPanel / MapBigPanel / WarehousePanel` 跑，**不涉及 SettingsPanel**，安全。
另外新增控件都只挂在面板内部，不改 `UI` 层子节点数，`panels.size() >= 16` 不受影响。

### 6.5 ⚠ 文案：新增分组标题必须查重复键

按铁律，加完核对总条数 + 断言新键解析出预期正文。预计新增 **7 条**分组标题 key（画面 3 / 游戏 3 / 控制 3，音频 0 —— 共 9，其中复用 2 条现有文案可减到 7）。
「显示适配」可复用现有 `p025`，不新增。

## 10. 实施记录（2026-10-23）

### 10.1 与方案的偏离（三处，都是落地时才发现）

| # | 方案原写法 | 实际做法 | 原因 |
|---|---|---|---|
| 1 | 新增 7 条分组标题 | **新增 11 条** | 除了 3+3+3 分组标题，还多出「适配方式」「窗口尺寸」「手动系数」三个**行标签**。原方案想复用 `p025`（显示适配）当行标签，但那张卡的标题也只能叫「显示适配」，同字重复；改成「卡标题=显示适配 / 行标签=适配方式」后必须新增一条 |
| 2 | 控制页小标题 + 分隔线放在 `_key_list` 外层的分组容器里 | 小标题与分隔线**放进 `_key_list` 内部** | 放外层要拆成 3 个行容器，29 条就被切成 7/4/18，`_key_list` 不再是「全部改键行」的容器。放进内部后 `_key_list` 仍是页容器的直接子节点 ⇒ 测试的 `rows.get_parent() == controls.get_child(0)` **原样保留**，只需把「数子节点」改成「数 HBox 行」 |
| 3 | 未提及下拉框外观 | 顺带把 7 个 `OptionButton` 套上 `PanelChrome.style_option_button()` | 设置面板里这部分**一个都没套过**，玩家看到的是 Godot 默认灰框，与其余 13 个面板的金属边语言不一致。「样式」也在需求原话里，顺手统一 |

### 10.2 落地时补的细节

- **勾选框左列留空、不搬 caption**：勾选框自带文字，把文字搬去左标签列会丢掉「点文字也能勾」的热区。改为在行首塞 `CAPTION_WIDTH` 宽的空 spacer，控件起点仍与滑块/下拉对齐。
- **`_refresh_keys()` 改用 `remove_child()` + `queue_free()`**：原来只 `queue_free()`，同一帧内二次刷新时旧节点仍在树上，行数与「第一行」会多出一批幽灵行（测试里 `_input` 之后同帧读第一行就会中招）。
- **按键分组用「最后一组兜住未列出动作」**：`KEY_GROUPS` 显式列举 17 个动作，快捷格 12 条靠「未列出即归最后一组」自动进入。新增动作漏写只会归错组，**不会丢行**。
- **`KEY_GROUPS` 用 `as Dictionary` / `as Array` 取值**：`const` 数组下标是 Variant，直接赋给强类型局部变量在 `warnings_as_errors` 下会失败。

### 10.3 🔴 一条差点变成假绿的断言

面板高度断言最初写成「按 `minf(680, logical.y - 64)` 算期望」，**复用了被测的钳位公式**：测试视口是 1152×648 时 `logical.y - 64 = 584`，600 与 680 都被夹到 584 ⇒ 把常量改回 600 也照样绿。

改法：把面板放进 **1280×800 的独立 `SubViewport`**，此时可用高 736 > 680，断言直接钉死 `680.0`（不参与任何公式）。负向 N-6 已验证：改回 600 时红在「应为 680，实际 600」。

### 10.4 🔴 重排时真的弄丢了一句 —— 靠「键读写齐平」对比抓回来的

`_build_auto_sell()` 原来是「读设置 → 连线」，重写时只留下连线，`_auto_sell_check.button_pressed = …` 被漏掉。
后果：**已经开着自动出售的存档，打开面板显示成未勾选**；而且 `_refresh_auto_sell_gate()` 只管灰显与预设档，**不会补这一句**，既有测试也只断灰显与文案 ⇒ 全绿。

抓法：把旧版与新版的「设置键读取/绑定清单」逐项对比（18 个字段的出现次数必须一致）。已补断言「设置已开启时勾选框应为勾选态」并加负向 N-9。
**教训**：文案重排类改动不要只对比「有没有这个控件」，要对比「这个控件还对接着同一个设置键、且仍读初值」。
