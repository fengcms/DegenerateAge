# 高倍速战斗背包与人物面板卡顿分析

## 现象与代码证据

- 人物面板在 `scripts/ui/character_panel.gd:30` 将装备、生命和法力事件接到同一个整页刷新。即使窗口隐藏也会执行。每次刷新遍历 14 个穿戴槽，更新提示、图标和角标，创建样式对象，重算装备适配、战斗属性及套装提示，并排入外框尺寸检查。切目标也会刷新整页，但目标变化只需要更新装备适配卡。
- 击杀耐久磨损在 `autoload/game_state.gd:1299` 原地修改穿戴装备，再经 `_after_equip_change` 广播装备、背包、生命、法力事件。高倍速下同一显示帧可能收到多轮信号。人物面板每轮可能整页刷新三次。
- 背包在 `scripts/ui/inventory_panel.gd:354` 已把事件合并到显示帧，也会比较槽位快照，但它把整份穿戴装备、等级、参考目标等级和人物面板可见性放在同一个比较上下文。穿戴耐久从正数降到另一正数也会使整份比较失效，导致一整包装备重新构建样式、图标、提示及评分角标。打开人物面板也会直接让背包刷新，因提示文案变化而触发同样的全包工作。
- 品质框在 `scripts/ui/quality_frame_overlay.gd:34` 为每个有品质的装备独立处理动画，使用受游戏倍速影响的 delta 修改图集区域。设置同一品质也会重启动画。父面板隐藏后处理仍继续。它的持续渲染成本需要另测。

## 实测

隔离 Godot 实际窗口，固定 200 件紫装、14 个穿戴槽，取五次样本中位数。直接测量同步脚本调用耗时，包含面板信号订阅开销，不含 GPU、完整战斗和后续容器布局。

| 操作 | 中位耗时 |
| --- | ---: |
| 人物面板关闭，连续发 20 个生命变化事件 | 60.28 ms |
| 人物面板打开，连续发 20 个生命变化事件 | 54.34 ms |
| 背包打开，200 格比较条件未变 | 0.44 ms |
| 背包打开，正常击杀磨损后刷新 200 格 | 55.83 ms |
| 背包打开，等级变化后刷新 200 格 | 55.98 ms |

磨损行先调用实际耐久入口，再单独计时背包刷新。关闭背包后，200 个品质框仍处于处理状态，持续耗时尚未单独量测。人物开关两组都在执行相同整页刷新，两个耗时的差距不代表打开更快。背包单次全量刷新约为 16.67 ms 整帧预算的三倍，尚未计入战斗或渲染。

## 分步优化与验收

1. 拆分人物面板刷新。生命法力仅更新对应显示，装备变更刷新受影响槽位和属性，切换目标仅刷新适配卡。复用已有帧调度器，隐藏时记录失效，打开时读取最新状态。耐久仍为正时更新该槽的耐久显示，破损或修复跨过零点时重新计算受影响的属性。沿用现有游戏结算门面。
2. 拆分背包物品展示与比较状态。普通穿戴磨损与人物窗口开关不重建背包图标和样式。评分角标在穿戴目标、评分或等级门槛确实变化时更新。适配提示与详细装备对比沿用悬停时读取最新数据的结构化提示，保留拖拽和双击的实例校验。增量刷新继续使用已提交的快照和帧调度，兼容原地叠加与背包扩容。
3. 单独测品质框。优先让隐藏面板停更，避免同品质反复重置。若打开满背包仍有明显持续开销，再验证品质框采用显示时间节奏及只更新可见格，保留原有图标大小和动画风格。

各节点用相同夹具比较同步耗时，再以百首禁域固定 Boss 和掉落压力、4×/8×/16× 倍速测试无面板、单开及双开。记录中位和 P95 帧耗时、尖峰和实际击杀数。验收包含升级、耐久跨零及修理、拾取/整理、滚动、装备拖拽与评分提示。每个节点验证后分别提交。

## 实施与窗口对照

人物面板按血蓝、目标和装备分别标记更新，同一显示帧合并。普通穿戴磨损更新耐久显示，跳过装备图标及样式重建。背包比较快照区分完好与破损，比较变化只刷新角标，装备详细对比在悬停时生成。品质框按现实时间推进，隐藏时停止处理，相同品质不重启。200 格背包仍保留原有节点与外观，新增状态为穿戴槽快照及人物属性展示缓存。

从同一固定种子实际窗口夹具对照三项改动前后。百首禁域各轮保留 100 个 Boss、2,400 个持久掉落、200 件背包装备，固定玩家并按每 0.4 模拟秒调用实际装备磨损入口。每个组合预热 0.35 秒后采样 1.2 秒。下表每格为中位帧耗时 / P95，单位 ms。

| 倍速 | 面板 | 改动前 | 改动后 |
| --- | --- | ---: | ---: |
| 4× | 背包 | 189.3 / 248.5 | 66.0 / 170.4 |
| 4× | 人物 | 53.1 / 76.4 | 47.4 / 63.5 |
| 4× | 双开 | 199.7 / 237.4 | 50.7 / 89.1 |
| 8× | 关闭 | 100.7 / 116.4 | 58.4 / 73.6 |
| 8× | 背包 | 253.7 / 285.2 | 64.2 / 84.5 |
| 8× | 人物 | 127.2 / 143.4 | 68.5 / 103.0 |
| 8× | 双开 | 282.1 / 292.7 | 68.1 / 111.6 |
| 16× | 关闭 | 185.7 / 204.9 | 99.8 / 122.0 |
| 16× | 背包 | 313.7 / 324.3 | 132.9 / 147.4 |
| 16× | 人物 | 181.7 / 201.4 | 132.5 / 137.1 |
| 16× | 双开 | 328.8 / 345.3 | 139.6 / 153.9 |

4× 关窗样本仍在建立静止掉落缓存，排除该行。16× 前后入睡掉落分别为 2,400 和 2,388，总量同为 2,400。16× 双开期间磨损事件数由 26 升至 48，帧率改善后引擎推进了更多物理步。夹具无实际击杀，P95 样本量小，适合观察变化方向。真实存档的走位、击杀、拾取和持续帧率未包含在本次对照。16× 极限场景仍有明显帧开销。
