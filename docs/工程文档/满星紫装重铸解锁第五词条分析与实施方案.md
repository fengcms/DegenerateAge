# 满星紫装重铸解锁第五词条分析与实施方案

日期：2026-10-30。状态：用户确认后已实施；原设计分析保留，实际改动、数据和验收见《满星紫装第五词条开发与验收记录》。

## 1. 目标与推荐规则

让紫色装备达到12星后仍有明确的打造目标，引导玩家使用重铸。

建议采用：**紫装已经达到12星，再成功执行一次装备重铸，词条总数由4永久解锁为5。** 不单独收取解锁材料，不新增解锁失败概率，使用这次重铸原有金币、精炼材料和如意规则。解锁是重铸成功的必然结果，与随机词条是否更强无关。

这里的紫装对应内部品质 `legendary`，不是 `epic`（界面金装）。第五条计入 `affixes + pctAttrs` 的总数，不另建一套特殊属性计算。

| 装备状态 | 本次行为 | 结果 |
|---|---|---|
| 紫装0—11星、4条 | 重铸 | 仍4条 |
| 紫装11星、曾重铸 | 升到12星 | 仍4条，提示可重铸解锁 |
| 紫装12星、4条 | 成功重铸 | 解锁5条 |
| 紫装12星、已解锁5条 | 再次重铸 | 保持5条，不会增加到6条 |
| 紫装12星、4条 | 金币不足、材料失效等失败 | 仍4条，不扣资源 |
| 非紫装 | 升星或重铸 | 保留原品质规则 |

不建议首版采用“任意星级重铸过一次，后来升到12星自动补第五条”：旧装备未记录重铸历史，无法可靠回溯；同时升星、保星和重铸会共同承担解锁结算，提示与随机规则更复杂。若用户要求两种顺序都成立，需要额外记录重铸历史，并设计升星时的追加随机结算，不能拿旧词条值推断是否重铸过。

## 2. 当前实现与证据

本节为源码与配置静态检查，未运行战斗模拟或整帧性能测试。

- `data/equipmentRules.json`：`maxStar=12`，`qualities.legendary.affixCount=4`，`percentChance=0.5`。固定词条仅 atk、def、hp、mp；百分比词条为 hpPercent、mpPercent、cdr。
- 用Python汇总 `data/equipments.json`：当前60个装备模板全部提供4种固定数值和3种百分比词条，没有缺少第五候选的模板。
- `scripts/systems/item_factory.gd::_roll_affixes`：从品质读取总词条数，最多先抽1条百分比，再抽不重复固定词条。不改该算法、只将数量设为5时，未抽中百分比的分支会因固定池只有4种而生成失败。
- `scripts/systems/reforge.gd::can_reforge`：实际条数必须与品质条数严格相等。直接造出5条会被下次重铸拒绝。
- `Reforge.max_lock_count`：按品质条数减1，目前紫装最多锁3条。费用按 `1 + lockFactor × 锁数`，当前 lockFactor=0.5。
- `autoload/game_state.gd::reforge_equipment`：先完成资格、锁定、材料、如意与金币校验，再抽取结果，最后同批扣费与替换词条。是解锁的正确提交位置。
- `RuneCharge` 与重铸取优：最多17次抽样，按既有 Equipment.score 取最高；第五条必须出现在每个候选中。
- `GameState.upgrade_equipment`：升星成功只增加星级，当前没有重铸历史字段。
- `GameState` 保星合成路径：生成一件新装备，然后设为12星；如意可让新装备词条多次取优。它是新实例，不是修改旧实例。
- `autoload/save_manager.gd::_valid_item`：总词条最多4条、百分比最多1条，重复stat拒绝。当前存档schema为15；装备规则版本4/5分别代表静态/动态等级实例，不能直接拿来充当第五词条标记。
- `DataLoader` 的品质基线校验目前也限定条数最多4；保留基础紫装4条不需要将该限制全局放宽。

所以这不是只改一处 `affixCount=5`：必须共同处理实例状态、生成、重铸资格、锁定、取优和存档。

## 3. 第五条的组成与强度

### 推荐：沿用现有词条种类，5条为4固定＋1百分比

不新增尚未接线的暴击、闪避等属性。五条互不重复，总百分比仍最多1条。重铸时若百分比被锁定就保留它，否则从模板百分比池重新抽取；四种固定数值按既有锁定与数值范围生成。

这意味着五词条装备必有 atk、def、hp、mp，加一条 hpPercent/mpPercent/cdr。优点是范围明确、现有属性结算可复用；代价是固定词条组合趋同，差异主要来自数值、百分比种类、等级和锁定。对不依赖攻击的部位也同样生效，因为当前所有模板的池相同。

不建议在本期同时开放“两条百分比”：这会改变百分比叠加、cdr封顶概率与词条组合，需要独立数值设计。也不建议允许相同stat重复或凭空新增未实现词条来凑数。

### 不等于战力直接提升25%

词条数量4→5是25%，但总战力还包括基底、星级、技能和战斗公式；百分比词条出现率还会从普通紫装的50%提高到五词条装备的100%。增加多少有效伤害、生存和冷却缩减，需要按部位、流派与整套14件装备测量，不能用25%代替实测结论。

首版建议维持现有单条上下限、等级倍率、精炼下限、如意权重、掉落和重铸基础费用。用户当前授权的是增加词条的设计分析，未确认的额外数值补偿不直接落地。

实施前以固定种子对比4条/5条的裸词条评分、整套属性、cdr命中上限比例及典型战斗耗时，至少覆盖前期满星、60级、100级、循环高等级和两职业。先形成结果，再决定是否需要调第五条数值；结果必须给出分布而非只看一件最高分装备。

## 4. 解锁、锁定、精炼与如意

### 首次解锁

从12星4条的合法实例作为输入，构造“本次目标词条数=5”的候选；成功后同一提交写入解锁标记和5条词条。原有未锁定词条仍会重掷，不承诺保留所有旧词条再免费补一条。面板必须明确显示“本次4→5条，未锁定词条同时重掷”。

首次解锁最多锁3条，沿用输入装备当前上限；不允许临时锁住全部4条后只抽新条。这样至少有1条原词条参与重铸，与现有规则一致。

### 解锁后

建议遵循“至少1条变化”：5条装备最多锁4条。锁定费用继续按现有公式计算，无额外解锁费。当前参数下锁3倍率2.5，锁4倍率3.0，锁满状态相较原锁满费用增加20%；这是锁数增长的自然结果，应在报价中明确展示。

如用户希望最高锁数仍为3，应作为另一项产品选择明确冻结，而不是让不同面板各自猜测。推荐统一采用4以保持规则一致。

精炼继续对未锁定词条生效，新解锁第五条也适用相同下限。锁定词条原值完整保留。多次如意取优必须每次都生成合法的5条候选，再按同一个评分函数比较，不能把4条与5条放进同一候选池，也不能“先4条取优、再补1条”。首次解锁概率100%指解锁本身，不保证新结果综合评分一定高于旧装备。

## 5. 生命周期和存档

### 实例字段

建议新增 `reforgeAffixTier` 整数，缺失或0表示基础条数，1表示已通过满星重铸解锁。可另设独立规则配置（例如equipmentRules的fullStarReforge组）登记品质、解锁星级、奖励条数和解锁后组成，品质基线 `affixCount=4` 保持不动。

集中提供基础条数、当前合法条数、本次重铸目标条数三个接口，分清“输入仍合法的4条”和“本次输出应该为5条”；不要用一个含糊的 `affix_count_of` 到处兼顾两种含义。UI、生成器、锁定和存档共用这套规则。

存档合法条件建议：tier=1必须是legendary、12星、恰好5条、恰好1条百分比、stat合法互不重复；无标记基础实例沿用已有校验范围，不为了此次升级把历史不相关装备校验突然收紧。拒绝无标记5条、有标记4条、低星5条、非紫5条和未知tier。不能简单将 `>4` 改为 `>5` 放行所有品质。

### 旧存档

当前schema15，建议实施时升到16（若届时已有新版本，以实际下一个版本为准）。新版本可迁移现行可读旧档：无字段默认0，原属性快照不变；所有旧12星紫装都先保留4条，下一次成功重铸再解锁。旧档中重铸过也不追溯，原因是缺乏可靠历史记录。

五词条实例必须在背包、穿戴、仓库、未领取战利品、地面装备等所有持久容器使用一致校验。导出/导入、读档迁移、自动存档及实例深拷贝不得漏字段。旧客户端应因新schema拒绝打开新档，避免旧4条校验将合法新装备判为坏档。

### 保星及其他出口

推荐**保星产物回到12星4条、未解锁状态**：它是新装备实例，不继承旧装第五条资格。即使旧装或新档材料带解锁标记也不转移；玩家对新产物再重铸一次解锁。这与本功能希望鼓励重铸的目标一致，也避免保星直接绕过触发。

保星内部的如意多次取优仍只按新产物4条生成，不得因为它被设为12星就误触第五条。只有真正的装备重铸提交才能首次置标记。已解锁装备后续合法重铸必须保持5条，不能被通用reroll函数降回4条。

普通掉落、四金合紫、四紫定向、四紫升紫仍生成4条基础紫装。普通升星不解锁；未来若加入降星/降品质规则，需先确定tier如何处理，当前玩法不存在这个正常路径，不提前创建静默修复。

## 6. 实施拆分

1. **规则与生成节点**：新增实例解锁规则接口和配置校验；实现指定目标数量的词条抽取、5条组成及锁定；现有4条入口保留原随机调用序列。检查全部60模板候选充足，至少1条可重掷。单独commit。
2. **业务与存档节点**：重铸唯一入口生成候选并原子提交tier；所有如意候选一致；资格和锁数读取实例规则；schema迁移与所有持久容器校验；明确保星新产物4条。单独commit。
3. **界面与反馈节点**：重铸目标显示4/5条、12星解锁提示和首次4→5预告；锁数3/4与报价一致；成功提示解锁第五条。装备tooltip、背包比较、评分浮层和属性面板显示全部5条；小窗口滚动适配。单独commit。
4. **数值与回归节点**：固定种子量化属性/战斗变化，覆盖存档、失败原子性、如意精炼组合及窗口显示，更新产品05/06/10/13与交接文档。每个可验证成果单独commit，失败不标记完成。

不新增全局单例、不引入逐帧扫描。最多17个五词条候选，每次只增加1条属性的生成/评分处理，成本应随候选数有界增加；结果更新沿用现有装备/背包信号，局部候选随同步调用结束释放。实际耗时应在同样种子、模板与如意投入下对比，未测量前不承诺性能无变化。

## 7. 核心验收

- 阈值和顺序：11星重铸不解锁；升12不解锁；12星成功重铸解锁；重复重铸始终5条；非紫装不受影响。
- 生成：覆盖所有部位、60模板、静态/动态等级、大量种子、0—4锁；必须5条唯一stat且1百分比。锁定值不变，候选不足明确失败。
- 资源原子性：金币不足、材料/rune快照失效、目标失效、候选生成失败均不扣资源且不置tier；成功只扣一次，实际穿戴属性同步刷新。
- 组合：精炼0—4有效材料、如意1/17候选都满足5条；新词条也受精炼下限影响；不能比较不同条数样本。
- 保星：输入已解锁旧装后新实例仍4条，12星保持，需重铸解锁；如意取优不提前解锁。
- 兼容：旧schema和无标记装备保持原属性；五词条跨背包/仓库/穿戴及JSON存档往返保留；伪造低星/错品质/重复stat/两百分比/6条/错误tier拒绝。
- 无关回归：原掉落条数不变；0—11星重铸固定种子结果与随机流不变；其他品质、原费用、如意消耗与保星基础语义不变。不得为适配5条而放宽全品质断言。
- 窗口：第五行、锁4、长词条、解锁提示和费用均可见；默认、窄窗口及大UI/文字倍率有实际渲染证据。

## 8. 建议确认的产品口径

推荐按以下四项作为实施基线：

1. 必须先12星，再成功重铸一次解锁；历史低星重铸不计入。
2. 五条采用4固定＋1百分比，承认组合趋同及百分比必出带来的强度变化。
3. 首次最多锁3条，解锁后最多锁4条，费用沿用锁数公式。
4. 保星新产物不继承解锁，仍需重铸一次；旧存档不追补第五条。

其中第2项是最值得先评估的设计取舍。若希望五词条仍保留更多组合差异，应先另定词条池扩展或百分比条数规则，再进入编码，而非在生成失败时临时塞入属性。
