# 装备跨级伤害衰减开发与验收记录

按[20级缓冲方案](装备跨级20级缓冲与百首禁域换装压力分析及优化方案.md)于2026-11-01分节点实施。规则只降低玩家对61级以上目标的输出，保留已有角色等级差、怪物承伤上限与主线规则，不迁移装备属性或存档。

## 节点一：规则与配置

新增equipmentGap配置和EquipmentGap模块，14槽逐件扣20级缓冲后加权；主武器超额差与综合超额差取max，每超额20级伤害减半。空槽等级0不缩小分母，左右槽各占该类一半。配置加载校验阈值、14槽覆盖及权重和；禁止影响前60级。

为避免读档/测试直接替换和UI信号顺序带来陈旧值，采用每次攻击/预览读取固定14个穿戴等级的轻量签名，与DataLoader.revision共同决定上下文复用。没有扫描背包、装备属性或JSON；同一技能多段共用快照。上下文按目标等级最多缓存64项；签名或规则修订变化整体替换，旧施法上下文由调用者释放，无全局信号引用、节点或存档字段。

EquipmentGapTest、BalanceTest、DynamicEquipTest全部通过，覆盖20/21/30/40/60/67级边界、混装、主武器与脱装绕过、双槽权重、闪避/暴击元信息、缓存与配置异常。后续节点接入实际战斗与提示，再做实战验证。

## 节点二：战斗链路

玩家普攻和攻击技能在Combat.resolve之后、飘字/伤害事件/take_hit之前应用同一EquipmentGap.apply。技能每次取一份等级快照，逐目标以怪物实际等级计算，多段复用缓存；闪避不变成1点，暴击标记保留，最低伤害1点。原LevelGap、穿透与怪物自己的扣血上限保持原次序；怪物攻击玩家完全未改。没有实际等级的测试桩/通用目标不拿人物等级制造虚假装备差。

EquipmentGapCombatTest通过真实PlayerCharacter普攻、换装恢复、60级边界、5阶三段群攻混合450/510/517级目标验证每段只乘一次、目标实际扣血一致、随机流未变；SkillCombatTest、BossFieldDamageTest、BalanceTest、ClassBalanceTest一并通过。

## 节点三：目标提示、换装预览与有限保留

Boss条持续显示真实目标/武器等级、伤害保留比例和建议最低等级，装备/规则变化更新现有条目；三条上限与原位置稳定规则不变，行距增加以容纳短提示。普通目标卡与人物面板也可查看当前参考目标的信息，总攻击属性不被改写。没有有效目标时人物/装备预览明确按人物等级参考，实际结算始终用怪物实例level。

背包的原生fallback和实际结构化对比卡共用同一短行预览，显示指定替换槽的系数变化；双槽优先提示较旧的一侧并引导手动拖放，不改变原双击自动选槽或降品质确认。保星穿回原槽后的等级签名立即更新，不等待旧缓存失效。

常规出售预设把“能补足人物当前等级的装备跨级差”纳入升级候选，优先按可补足等级差、再按原评分/格序排序；保留额度仍为原单槽1件、双槽2件，不无限保留。金紫不卖、收藏/任务/升星等保护继续保持；暴力预设仍按用户明确选择跳过价值保护。此处用人物等级作长期备装参考，不读取未探索怪物或当前Boss隐蔽刷新信息。

EquipmentGapUiTest验证真实Boss提示、换装即时清除、实际结构化卡片、低分高等级物品保护、重复品按额度可出售、预览不改真实装备。SellGearPreviewTest、SellGearPolicyTest、SellGearQuotaTest、AutoSellPickupTest、EquipmentAxesTest、BossReviewTest全部通过。1280×800真实窗口截图已复核：提示与两列对比卡没有被截断，截图仅写/tmp。测试夹具的类型声明与变量重名已修正；一次隔离编辑器资源导入发生引擎线程崩溃，重跑同源导入与场景通过，未放宽任何断言。

## 节点四：实战、成本与回归收口

EquipmentGapAcceptance以真实Game、PlayerCharacter、AutoPilot、技能冷却进行六轮对照。人物500级，同一份固定种子440级紫装12星，对500级Boss；关闭Boss AI排除承伤与走位，固定60Hz推进并记录游戏秒。新装是同一份装备升至500级的受控属性投影，保留品质、星级和词条种类，不代表任意随机掉落装备。

| 职业 | 旧规则旧装 | 新规则旧装 | 新规则同品质星级新装 |
| --- | ---: | ---: | ---: |
| 武士 | 14.70秒 | 54.52秒 | 10.62秒 |
| 法师 | 11.73秒 | 44.40秒 | 8.82秒 |

跨60级后的实际击杀约慢3.7～3.8倍，换装后恢复。普攻理论伤害保留25%；技能、整数取整和冷却导致击杀时间不必恰好4倍。这是可复现的受控实战，不冒充517级导入存档现场计时；原存档分析仍以原方案的只读数据为准。

成本测试120次“100目标各3段”，复测无层CPU中位0.245ms、p95 0.249ms，启用后中位0.636ms、p95 0.645ms，额外约0.39ms/300次结算；不代表GPU或整帧60FPS保证。实际施法只取一次14槽签名，同等级目标复用最多64项缓存，不增加定时器、节点或持久化字段。随机流状态逐次一致。

最终补齐异常配置类型/过大数值校验，以及悬停装备卡切换目标/重载规则时的即时刷新。隔离运行EquipmentGapTest、EquipmentGapUiTest、EquipmentGapAcceptance再次全部通过；MapPerformanceTest、AutoRoamPlanTest一并通过。新增三项短回归纳入默认集，六轮实战独立作为长用例。复现：`python3 tools/run_isolated_tests.py EquipmentGapTest EquipmentGapCombatTest EquipmentGapUiTest EquipmentGapAcceptance`。

此前14项定向回归全部通过，覆盖技能、Boss承伤上限、动态装备、拾取出售、出售额度/交易、保星交易、存档导入导出与综合冒烟。全量扫描记录183项通过、3项失败，另跳过已登记美术欠账3项；不宣称全量全绿。三个失败均在独立检出78f0427e后复现：

- SuperPortablePanelTest缺少运行器认可的完成标记，保持既有失败记录。

实际517级存档仅只读检查：14件保星升级供体匹配成功，11,200,989金币预算低于390,527,186持有量，未替玩家交易、发奖或写档。旧存档无需迁移；极端低装等且无物资角色仍需回低等级目标积累装备。≤60级目标和特殊怪物原承伤上限保留，达到上限时提速幅度不一定与系数倒数相同。
