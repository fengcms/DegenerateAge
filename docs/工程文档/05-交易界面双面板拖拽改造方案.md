# 05 交易界面双面板拖拽改造方案

> 状态：✅ 已实施（M1-8 追加改造）。
> 触发：玩家反馈「出售装备的交互与预期不符」——期望**打开两个面板**（货郎面板 + 背包），
> **从背包拖拽装备到货郎面板完成出售**；当前实现是货郎面板内嵌一份背包格、点选后批量结算。
> 依据：产品文档 06 §6.4（出售面板：双击 / 拖拽装备到面板；一键出售移入清单；确认结算）。

---

## 1. 现状与预期差异（原文对照）

**玩家原话**：

> 在我的想象中，应该是打开两个面板，一个是货郎的面板，一个是背包，玩家从背包里，把要卖的东西，
> 拖动到货郎的面板里。当前你的实现，是在货郎的面板里，直接展示背包物品，然后通过点选来选择出售。
> 这样虽然方便，但是和我的想法不一样。

**产品文档 06 §6.4 原文**：

> **出售面板**：类背包格子面板；下方为结算金币数与「确认」+「一键出售」按钮。
> - 双击装备 / 拖拽装备到面板；
> - 「一键出售」将背包全部装备批量移入（一格一件）；
> - **属性高于已穿戴的装备不会被一键移入**；
> - 手动将高于自身穿戴的装备拖入面板时，点确认需**弹二次确认对话框**。

**判定**：产品文档本来的描述就是「**拖拽装备到面板**」+「一键出售=**移入**清单」两步。
M1-8 首版为了省事做成了「面板内嵌背包 + 点选 + 直接结算」，属于**实现简化偏离设计**，
玩家反馈成立。本次改造回归文档口径。

---

## 2. 交互重规划

### 2.1 布局：并列双面板

```
┌──────────────────────────────┬────────────────────────────┐
│  背包与装备                   │  货郎（营地）　买卖   金币 ×  │
│  装备 3/14                    │  ┌──────┬──────┐            │
│  ┌──┬──┐                     │  │ 购买 │ 出售 │            │
│  │  │  │                     │  └──────┴──────┘            │
│  ├──┼──┤   背包 7/40          │  ┌──┬──┬──┬──┬──┬──┐        │
│  │  │  │  ┌──┬──┬──┬──┐      │  │  │  │  │  │  │  │ ← 出售托盘
│  └──┴──┘  │  │  │  │  │      │  ├──┼──┼──┼──┼──┼──┤   （拖入暂存）
│           ├──┼──┼──┼──┤      │  │  │  │  │  │  │  │        │
│           │  │  │  │  │      │  └──┴──┴──┴──┴──┴──┘        │
│           └──┴──┴──┴──┘      │  暂存 3 件 · 结算 195 金币    │
│                              │      [取回][一键移入][确认出售] │
└──────────────────────────────┴────────────────────────────┘
        ↑ 左：背包面板（可拖出）        ↑ 右：货郎面板（可接收）
```

- 打开货郎时**同时打开背包面板**（不再互斥，改为**交易会话**）；
- 从背包格**按住拖拽**到右侧托盘格松手 → 该件装备从背包移入托盘（暂存，未结算）；
- 点托盘格 → 取回背包；`确认出售` → 结算托盘内全部装备为金币；
- `一键移入` → 把背包中所有可售装备批量移入托盘（**优于已穿戴者不移入**，6.4）；
- 关闭面板（E / Esc / ×）时托盘内未确认的装备**自动退回背包**，不静默丢失。

### 2.2 与旧实现的差异

| 维度 | 旧（M1-8 首版） | 新（本次） |
| --- | --- | --- |
| 打开形态 | 货郎面板单开，背包面板被互斥关闭 | 货郎面板 + 背包面板**并列** |
| 出售来源 | 货郎面板内嵌一份背包格 | **直接用左侧背包面板的格子** |
| 移入方式 | 点击点选 | **拖拽到托盘格**（保留点击取回） |
| 结算时机 | 点选后「确认出售」直接结算 | 拖入**托盘暂存** → 「确认出售」结算 |
| 一键出售 | 直接结算（简化） | **批量移入托盘**（6.4 原文），再确认 |
| 误操作保护 | 无 | 关闭面板自动退回托盘内装备 |

## 3. 技术实现

### 3.1 新增拖拽控件 `ItemSlot`

`scripts/ui/item_slot.gd`（`class_name ItemSlot extends Button`）：

| 成员 | 说明 |
| --- | --- |
| `enum { ROLE_BAG, ROLE_TRAY }` | 格子角色：背包格可拖出；托盘格可接收 |
| `role / index / item` | 角色、下标（背包下标 / 托盘下标）、当前物品实例 |
| `draggable` | 是否允许拖出（交易模式下才打开） |
| `signal item_dropped(tray_index, payload)` | 托盘收到投放时回传载荷 |
| `_get_drag_data` / `_can_drop_data` / `_drop_data` | Godot 4 拖放三件套 |

拖拽载荷：`{"from": ROLE_BAG, "index": int, "item": Dictionary}`；
拖拽预览为一个带物品名与品质色描边的小面板（占位素材 R5）。

### 3.2 交易会话（跨面板状态）

新增事件（`autoload/event_bus.gd`）：

```gdscript
signal trade_mode_changed(active: bool)   # 进入 / 退出交易会话
signal shop_close_requested()             # 由背包面板发起关闭整场交易
```

时序（进入）：

1. `game.gd` 就近交互 → `EventBus.shop_open_requested(shop_id)`；
2. `ShopPanel`：`_trade_active = true` → `set_open(true)` → 广播 `trade_mode_changed(true)` → 广播 `panel_opened("shop")`；
3. `InventoryPanel`：收到 `trade_mode_changed(true)` → 进入交易模式（左半屏、去遮罩、背包格 `draggable = true`）→ 若未开则 `set_open(true)`；
4. `ShopPanel._on_panel_opened` 在交易会话中**忽略** `"inventory"`，避免把刚拉起来的背包面板又关掉。

时序（退出）：任一面板关闭 → `trade_mode_changed(false)` → `InventoryPanel` 退出交易模式并关闭 →
`ShopPanel` 把托盘内装备退回背包。

### 3.3 布局与遮挡

- 两个面板根节点均为全屏 `Control`。**背包面板在上层时需要保证左半屏可交互、右半屏不挡货郎面板**：
  将 `ShopPanel` 根节点 `mouse_filter` 设为 `IGNORE`，只让内部的 `PanelContainer`（默认 `STOP`）吃鼠标；
- 交易会话中**双方遮罩（dim）都隐藏**，避免两层黑色叠加把对面面板压暗；
- 面板位置：背包面板居中于左 60% 区域，货郎面板居中于右 42% 区域。

### 3.4 逻辑层改动

`autoload/game_state.gd`：

| 函数 | 说明 |
| --- | --- |
| `shop_sell_staged(items)`（新） | 结算一批暂存装备（6.4「确认出售」），返回 `{count, gold}` |
| `shop_sell(inv_index, silent)`（保留） | 单件出售原语（供测试 / 后续 NPC 复用） |
| `shop_sell_all()`（**移除**） | 旧「直接结算」路径，已被托盘流程取代 |

托盘状态由 `ShopPanel` 持有（UI 会话态），`GameState` 只提供移出 / 结算 / 退回原语——
避免把界面暂存塞进存档数据结构。

## 4. 🔴 风险

| 编号 | 风险 | 处置 |
| --- | --- | --- |
| 🔴 R1 | 拖拽中 `remove_item_at` 会使背包下标位移，若载荷携带旧下标可能移错件 | 投放时**以载荷中的物品实例为准**，用实时下标取出并校验实例一致；托盘存实例副本 |
| 🔴 R2 | 两个全屏 Control 叠加互相挡鼠标 | `ShopPanel` 根节点改 `IGNORE`；仅面板本体 `STOP`；冒烟测试断言两面板可同时可见 |
| 🔴 R3 | 关闭面板时托盘内装备若直接丢弃 = 资产丢失 | `set_open(false)` 统一执行**退回背包**；背包满则逐件提示并保留在托盘 |
| 🔴 R4 | 「一键移入」若与「一键出售」语义混淆，玩家以为已卖出 | 按钮更名「一键移入」，文案明确「移入后需确认出售」；结算区实时显示暂存件数与金额 |
| 🔴 R5 | 手拖优于已穿戴装备时，6.4 要求二次确认对话框 | 本次以**结算区警示行 + 确认 toast 提示**代替弹窗，完整二次确认对话框按文档留 M4 |
| 🔴 R6 | 开发期测试便利（11 只怪 + 999 攻测试武器）使金币/装备产出快，易掩盖托盘满格边界 | 托盘容量 24 格；冒烟测试覆盖「托盘满 → 拒绝投放并提示」 |

## 6. 验收方式

1. **无头回归**：`Godot --headless --path . res://tests/SmokeTest.tscn` → 退出码 0，
   含拖入 / 取回 / 确认结算 / 一键移入保留升级件 / 关闭退回 / 托盘满 六组断言。
2. **启动回归**：`Godot --headless --path . --quit` → 0 SCRIPT ERROR。
3. **渲染截图**：`tests/ShopShot.tscn` 输出三张图——双面板并列（交易会话）、拖入 3 件后的托盘、
   确认出售后的金币与背包变化。
4. **手动验收**：走近货郎按 E → 背包面板与货郎面板**并列出现** → 拖动背包里的装备到右侧托盘 →
   托盘出现该装备、结算金额增长 →「确认出售」→ 金币增加、装备从背包消失；
   按 Esc 关闭时托盘内装备退回背包。
