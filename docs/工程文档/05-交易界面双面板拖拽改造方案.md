# 05 交易界面双面板拖拽改造方案

> 状态：✅ 已实施（M1-8 追加改造）+ ✅ 拖拽预览层级追加修复（见 §7）。
> 触发：玩家反馈「出售装备的交互与预期不符」——期望**打开两个面板**（货郎面板 + 背包），
> **从背包拖拽装备到货郎面板完成出售**；当前实现是货郎面板内嵌一份背包格、点选后批量结算。
> 依据：产品文档 06 §6.4（出售面板：双击 / 拖拽装备到面板；一键出售移入清单；确认结算）。

---

## 1. 现状与预期差异（原文对照）

**玩家原话**：

> 在我的想象中，应该是打开两个面板，一个是货郎的面板，一个是背包，玩家从背包里，把要卖的东西，
> 拖动到货郎的面板里。当前你的实现，是在货郎的面板里，直接展示背包物品，然后通过点选来选择出售。
> 这样虽然方便，但是和我的想法不一样。

**产品文档 06 §6.4 原文**：

> **出售面板**：类背包格子面板；下方为结算金币数与「确认」+「一键出售」按钮。
> - 双击装备 / 拖拽装备到面板；
> - 「一键出售」将背包全部装备批量移入（一格一件）；
> - **属性高于已穿戴的装备不会被一键移入**；
> - 手动将高于自身穿戴的装备拖入面板时，点确认需**弹二次确认对话框**。

**判定**：产品文档本来的描述就是「**拖拽装备到面板**」+「一键出售=**移入**清单」两步。
M1-8 首版为了省事做成了「面板内嵌背包 + 点选 + 直接结算」，属于**实现简化偏离设计**，
玩家反馈成立。本次改造回归文档口径。

## 2. 交互重规划

### 2.1 布局：并列双面板

```
┌──────────────────────────────┬────────────────────────────┐
│  背包与装备                   │  货郎（营地）　买卖   金币 ×  │
│  装备 3/14                    │  ┌──────┬──────┐            │
│  ┌──┬──┐                     │  │ 购买 │ 出售 │            │
│  │  │  │                     │  └──────┴──────┘            │
│  ├──┼──┤   背包 7/40          │  ┌──┬──┬──┬──┬──┬──┐        │
│  │  │  │  ┌──┬──┬──┬──┐      │  │  │  │  │  │  │  │ ← 出售托盘
│  └──┴──┘  │  │  │  │  │      │  ├──┼──┼──┼──┼──┼──┤   （拖入暂存）
│           ├──┼──┼──┼──┤      │  │  │  │  │  │  │  │        │
│           │  │  │  │  │      │  └──┴──┴──┴──┴──┴──┘        │
│           └──┴──┴──┴──┘      │  暂存 3 件 · 结算 195 金币    │
│                              │      [取回][一键移入][确认出售] │
└──────────────────────────────┴────────────────────────────┘
        ↑ 左：背包面板（可拖出）        ↑ 右：货郎面板（可接收）
```

- 打开货郎时**同时打开背包面板**（不再互斥，改为**交易会话**）；
- 从背包格**按住拖拽**到右侧托盘格松手 → 该件装备从背包移入托盘（暂存，未结算）；
- 点托盘格 → 取回背包；`确认出售` → 结算托盘内全部装备为金币；
- `一键移入` → 把背包中所有可售装备批量移入托盘（**优于已穿戴者不移入**，6.4）；
- 关闭面板（E / Esc / ×）时托盘内未确认的装备**自动退回背包**，不静默丢失。

### 2.2 与旧实现的差异

| 维度 | 旧（M1-8 首版） | 新（本次） |
| --- | --- | --- |
| 打开形态 | 货郎面板单开，背包面板被互斥关闭 | 货郎面板 + 背包面板**并列** |
| 出售来源 | 货郎面板内嵌一份背包格 | **直接用左侧背包面板的格子** |
| 移入方式 | 点击点选 | **拖拽到托盘格**（保留点击取回） |
| 结算时机 | 点选后「确认出售」直接结算 | 拖入**托盘暂存** → 「确认出售」结算 |
| 一键出售 | 直接结算（简化） | **批量移入托盘**（6.4 原文），再确认 |
| 误操作保护 | 无 | 关闭面板自动退回托盘内装备 |

## 3. 技术实现

### 3.1 新增拖拽控件 `ItemSlot`

`scripts/ui/item_slot.gd`（`class_name ItemSlot extends Button`）：

| 成员 | 说明 |
| --- | --- |
| `enum { ROLE_BAG, ROLE_TRAY }` | 格子角色：背包格可拖出；托盘格可接收 |
| `role / index / item` | 角色、下标（背包下标 / 托盘下标）、当前物品实例 |
| `draggable` | 是否允许拖出（交易模式下才打开） |
| `signal item_dropped(tray_index, payload)` | 托盘收到投放时回传载荷 |
| `_get_drag_data` / `_can_drop_data` / `_drop_data` | Godot 4 拖放三件套 |

拖拽载荷：`{"from": ROLE_BAG, "index": int, "item": Dictionary}`；
拖拽跟随视觉见 §7（`DragGhost`，**不用**引擎的 `set_drag_preview`）。

### 3.2 交易会话（跨面板状态）

新增事件（`autoload/event_bus.gd`）：

```gdscript
signal trade_mode_changed(active: bool)   # 进入 / 退出交易会话
signal shop_close_requested()             # 由背包面板发起关闭整场交易
```

时序（进入）：

1. `game.gd` 就近交互 → `EventBus.shop_open_requested(shop_id)`；
2. `ShopPanel`：`_trade_active = true` → `set_open(true)` → 广播 `trade_mode_changed(true)` → 广播 `panel_opened("shop")`；
3. `InventoryPanel`：收到 `trade_mode_changed(true)` → 进入交易模式（左半屏、去遮罩、背包格 `draggable = true`）→ 若未开则 `set_open(true)`；
4. `ShopPanel._on_panel_opened` 在交易会话中**忽略** `"inventory"`，避免把刚拉起来的背包面板又关掉。

时序（退出）：任一面板关闭 → `trade_mode_changed(false)` → `InventoryPanel` 退出交易模式并关闭 →
`ShopPanel` 把托盘内装备退回背包。

### 3.3 布局与遮挡

- 两个面板根节点均为全屏 `Control`。**背包面板在上层时需要保证左半屏可交互、右半屏不挡货郎面板**：
  将 `ShopPanel` 根节点 `mouse_filter` 设为 `IGNORE`，只让内部的 `PanelContainer`（默认 `STOP`）吃鼠标；
- 交易会话中**双方遮罩（dim）都隐藏**，避免两层黑色叠加把对面面板压暗；
- 面板位置：背包面板居中于左 60% 区域，货郎面板居中于右 42% 区域。

### 3.4 逻辑层改动

`autoload/game_state.gd`：

| 函数 | 说明 |
| --- | --- |
| `shop_sell_staged(items)`（新） | 结算一批暂存装备（6.4「确认出售」），返回 `{count, gold}` |
| `shop_sell(inv_index, silent)`（保留） | 单件出售原语（供测试 / 后续 NPC 复用） |
| `shop_sell_all()`（**移除**） | 旧「直接结算」路径，已被托盘流程取代 |

托盘状态由 `ShopPanel` 持有（UI 会话态），`GameState` 只提供移出 / 结算 / 退回原语——
避免把界面暂存塞进存档数据结构。

## 7. 追加修复：拖拽跟随元素被货郎面板遮挡（层级）

> 状态：✅ 已修复。
> 玩家原话：「我拖动装备到货郎面板时，货郎面板的 z-index 好像高于鼠标拖动的元素，
> 导致元素被货郎面板遮挡了。」

### 7.1 根因（实测，非推断）

Godot 的 `Control.set_drag_preview()` **不提供层级控制**，挂载点由引擎自定。用真实
鼠标输入注入复现（`tests/DragLayerProbe.tscn`），拖拽中扫描全树得到预览节点路径：

```
⚠ 新增 Control：path=/root/DragLayerProbe/Main/UI/InventoryPanel/@PanelContainer@195
                 class=PanelContainer pos=(880.4, 281.0) size=(122.0, 27.0)
UI 层：CanvasLayer layer=1 子节点=[Hud, InventoryPanel, ShopPanel]
货郎面板：visible=true z_index=0
```

三点结论：

1. 引擎把预览**插进了发起拖拽的面板内部**（`UI/InventoryPanel` 之下），而不是「最上层」；
2. 因此预览与其余面板**同处一个 canvas、`z_index` 同为 0** ⇒ 绘制顺序由树的先后决定，
   而货郎面板排在背包面板之后 ⇒ **预览被整块盖住**（截图确认：拖动时屏幕上完全看不到被拖动的元素）；
3. `z_index` 只在**同一 canvas 内**比较，无法跨 canvas 纠正；而本项目 UI 位于
   `CanvasLayer(UI, layer=1)`，任何挂到默认 canvas 的节点都会被整层覆盖。

另有一条**时序事实**（同一次实测）：`_get_drag_data` 内 `gui_is_dragging()` 已为 `true`
（`[Lab] _get_drag_data 内 gui_is_dragging=true`）——引擎在调用本方法前已置拖拽态，
故「仅在拖拽态创建跟随视觉」是安全契约（Godot 官方亦推荐在此调用 `set_drag_preview`）。

### 7.2 修复

新增 `scripts/ui/drag_ghost.gd`（`class_name DragGhost`）：**自绘**跟随鼠标的拖拽幽灵，
显式挂到 UI 层内**层级最高**的专用图层，不再使用引擎预览。

| 项 | 内容 |
| --- | --- |
| 图层 | `Main.tscn` → `UI/DragLayer`（`Control`，`mouse_filter=IGNORE`，`z_index=4096`，组 `drag_ghost_layer`） |
| 幽灵 | 物品名 + 品质色描边小面板；`z_index = 4096`（同 canvas 内上限）；鼠标穿透 |
| 跟随 | 自身 `_process` 中 `global_position = get_global_mouse_position() + (14, 10)` |
| 回收 | 拖拽结束即 `queue_free()`；宽限期内未见拖拽态亦自毁（防无头测试控件泄漏） |
| 兜底 | 场景无该图层时（独立测试场景）仍走引擎预览，并尽量抬高其 `z_index` |
| 触发条件 | 仅在 `gui_is_dragging()` 为真时创建（非拖拽调用零副作用） |

`z_index` 取值说明：同 canvas 内有效上限为 `RenderingServer.CANVAS_ITEM_Z_MAX = 4096`。

- 渲染截图：修复前拖动时看不见任何跟随元素（整块在货郎面板背后）；修复后

- 导入扫描 / 启动回归 / 掉落回归均无错误。

### 7.4 同类发现（未修，待确认）

`Hud` 是 UI 层第一个子节点，`z_index=0` ⇒ 面板打开时 **HUD 的 toast 提示被面板遮挡**
（如交易中「货郎只收购装备」「背包已满」等提示看不见）。修法只需给 HUD 的 toast 容器抬高
`z_index`（低于 4096），但涉及 HUD 结构，**未擅自改动**，待确认后再处理。

### 7.5 复用约定（写入项目记忆）

> 凡需要「恒在其它 UI 之上」的浮层（拖拽跟随、toast、tooltip），一律挂
> `UI/DragLayer`（或同层级的专用图层）并给高 `z_index`；
> **不要依赖 Godot 引擎自定挂载点的 API**（`set_drag_preview` 即属此类）。
