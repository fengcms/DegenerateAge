## 1. 需求拆解与验收判据

### 1.1 从玩家诉求到工程目标

| 玩家诉求 | 工程目标 |
|---|---|
| 想知道"我正往哪走、走哪条路" | 画一条从人物到目标的虚线，且**在洞穴里必须绕墙**（不能穿墙直连） |
| 在大地图／小地图都能看到 | 两处共用同一投影与绘制，避免出现两套不一致的路线 |
| 不要在世界视图里画 | 不碰 `Game.tscn` 世界节点，只在 UI 的 `MapCanvas` 上绘制 |
| 不能拖慢游戏 | 沿用既有节流与底图缓存策略，不进入每帧热路径 |

### 1.2 验收判据

| 编号 | 判据 | 落地位置（预期） |
|---|---|---|
| A1 | 寻路进行中，小地图出现人物→目标虚线；到达/取消后虚线消失 | `MapCanvas._draw_markers` + `Player.map_move_route` |
| A2 | 打开大地图时同样出现虚线，且与人物同步推进 | 同上（同一 MapCanvas 实例） |
| A3 | 世界视图（`Game.tscn`）**没有**任何路线绘制 | 不改世界节点 |
| A4 | **洞穴地图**虚线沿可走区域绕行，不穿墙 | 读 `player._cave_path`，非直线 |

| A7 | 虚线颜色/线宽/节距集中为常量，不散落硬编码 | `map_canvas.gd` 顶部常量 |

## 2. 现状勘查（证据）

### 2.1 两处地图是同一个脚本的两个实例（这是本方案成本极低的原因）

| 界面 | 实例位置 | 关键参数 |
|---|---|---|
| HUD 右上角小地图 | [Hud.tscn#L456-L465](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scenes/ui/Hud.tscn#L456-L465) 的 `MapPanel/Minimap`（Control，164×164，挂 `ExtResource("2_map")`） | `minimap = true`、`ornamental_frame = true` |
| 大地图面板 | [map_big_panel.gd#L98-L103](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/ui/map_big_panel.gd#L98-L103) 运行时 `MapCanvas.new()`（最小 800×400） | `minimap = false`（默认值） |

两者挂的是**同一个** [map_canvas.gd](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/ui/map_canvas.gd)（`class_name MapCanvas`，`extends Control`）。
→ 在 `MapCanvas` 内新增绘制，**自动同时生效于两处**；而世界视图没有 `MapCanvas` 实例，所以 A3 天然满足、无需额外加开关。

### 2.2 坐标映射：已有现成且唯一的投影入口

[map_canvas.gd#L129-L140](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/ui/map_canvas.gd#L129-L140)：

```gdscript
func world_to_canvas(world: Vector2) -> Vector2:
	_ensure_projection()
	return _project(world)

func _project(world: Vector2) -> Vector2:
	return size * 0.5 + (world - _world_rect.get_center()) * _scale
```

- 世界像素 → 控件像素 = `居中 + 平移缩放`，**无旋转**；绘制路点与绘制标记走同一个函数，天然无偏差。
- `_world_rect` / `_scale` 由 [\_ensure_projection()#L98-L116](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/ui/map_canvas.gd#L98-L116) 在"地图/尺寸/minimap 模式/洞穴布局"变化时重建。
- 关键：**投影不跟随玩家**——小地图显示的是**整张当前地图**在圆内的缩略图（不是以玩家为中心滚动的雷达）。这决定了虚线是"全图上的行进示意"，而不是"雷达箭头"。

### 2.3 现有绘制分层：底图与动态层已经分离

| 层 | 载体 | 内容 | 刷新时机 |

而 [refresh()#L69-L95](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/ui/map_canvas.gd#L69-L95) 已经把**玩家位置**与**标记列表**读进来，并用"变化才重绘"的守卫条件决定是否 `_overlay.queue_redraw()`：

### 2.4 自动寻路的数据源（唯一入口，生命周期明确）

**唯一的自动寻路入口**：[player.gd#L162-L170](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/entities/player.gd#L162-L170) `request_map_move(point)`
→ 置 `map_move_active = true`，`reset_move_progress(point)` 把 `_map_destination` 设为**世界坐标**、清空 `_cave_path`。

状态变量（[player.gd#L76-L84](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/entities/player.gd#L76-L84)）：

| 变量 | 类型 | 含义 |
|---|---|---|
| `map_move_active` | bool | **是否正在"地图寻路"**（唯一可靠判据） |
| `_map_destination` | Vector2 | 目标世界坐标 |
| `_cave_path` | Array[Vector2] | **洞穴地图**的平滑路点序列（世界坐标） |
| `_cave_path_index` | int | 已走过的路点下标 |
| `_cave_target_cell` | Vector2i | 路线对应的目标格（换目标格才重算） |

`map_move_active` 何时变 false（即虚线应消失），逐条有据：

| 场景 | 位置 |

| 卡住超限（STUCK_LIMIT 次无进展） | [player.gd#L216-L220](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/entities/player.gd#L216-L220) |

| 发起攻击（含普攻空放 / 技能追敌） | [player.gd#L292-L296](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/entities/player.gd#L292-L296)、[#L444](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/entities/player.gd#L444) |

→ 结论：`map_move_active == true` 就是"该画虚线"的**充要判据**，覆盖 A1/A5/A6，无需额外埋点。

**路线的几何来源**（[player.gd#L178-L221](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/entities/player.gd#L178-L221) `_map_direction`）：

| 地图类型 | 判定 | 路线形态 |
|---|---|---|
| 营地 / 无洞穴布局 | `ground.cave == null` | **不生成路点**，`waypoint = _map_destination` 即**直线**（[ground.gd#L265-L272](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/world/ground.gd#L265-L272)：无 `layoutPath` 时 `route()` 只返回目标点） |

### 2.6 跨图导航的现状行为（必须在文档里说清，避免被当成 bug）

### 2.7 是否需要裁剪：量化论证 → **不需要**

小地图的可视边界是"画出来的圆"，而 `MapCanvas` 全仓**没有任何 `clip_contents`**（已检索确认）。所以必须确认虚线会不会画到圆外、压到面板框上。用实际的投影参数计算：

- 小地图尺寸 164×164 → `available = min(size) - 24 = 140`（[#L115](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/ui/map_canvas.gd#L115)）；可视圆半径 = `min(size)/2 - 2 = 80`。
- **营地**（矩形白盒，`worldRect` 来自 [map.json#L147-L152](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/data/maps/ch01/camp/map.json#L147-L152)：3200×1800）→ `scale = 140/3200` → 投影矩形 140×78.75 → **半对角 = √(70² + 39.4²) ≈ 80.3**，与圆半径 80 相差 **0.3 px**。
- **洞穴**（无 `worldRect`，走等距外框）→ 投影为菱形，最远点在中点左右顶点，距中心 = `140/2 = 70 < 80`。
- 且矩形与菱形**都是凸的**，两端点都在区域内的线段不会离开该区域（距离函数在线段上是凸的，最大值只可能出现在端点）。

→ 结论：虚线两端点必然落在可视圆内，营地最坏情况溢出仅 0.3 px（不可见）。**无需圆形裁剪、无需 `clip_contents`、无需遮罩纹理**。
（大地图侧 `available = size - Vector2(40,40)`，内容本就在控件内，同样无需裁剪。）

> 仍需一次实机验证：把路线沿着营地地图对角方向设置，确认圆边缘无可见溢出（列入 §6 T6 的人工确认项）。

## 3. 方案设计

### 3.1 绘制落点：`MapCanvas._draw_markers()` 的**开头**

- 放在 `_draw_markers()` **最前面**（在标记循环之前）→ 虚线画在标记**之下**，不遮挡 NPC / Boss / 出口 / 玩家的字形与图标（`_draw_markers` 里既有 `draw_string` 文字标签）。
- 复用 `_overlay.draw_*`，与既有玩家标记同层、同步重绘。

不选另外两个方案的取舍：

| 方案 | 结论 |
|---|---|
| A. 画进 `MapCanvas._draw()` 底图 | ❌ 底图有缓存与 `background_draw_count` 计数语义；路线每 0.2s 变，会击穿底图缓存，需重建地形网格（性能与语义双输） |
| B. 新建独立子节点专门画路线 | ⚠️ 可行但多一层节点与重绘联动；`_overlay` 已具备"动态层"语义，无必要 |
| **C. 加进 `_overlay` 的 `_draw_markers()` 头部** | ✅ 采用 |

### 3.2 数据接口：给 `Player` 加只读访问器

现状 `_map_destination` / `_cave_path` 是下划线私有约定，UI 直接 `get("_map_destination")` 属于越界访问且易随重构失效。建议新增两个只读方法（[player.gd](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/entities/player.gd)）：

```gdscript
## 自动寻路进行中时返回行进路线折线（世界坐标，首点=人物当前坐标，末点=目标）；
## 未在寻路时返回空数组。无洞穴布局的地图为两点直线，洞穴地图为绕障路点序列。
func map_move_route() -> Array[Vector2]:
	if not map_move_active:
		return []
	var world := get_tree().get_first_node_in_group("map_world")
	var ground := world.get_node_or_null("Ground") as IsoGround if world != null else null
	if ground != null and ground.cave != null:
		# 洞穴：路线尚未算出时先不画，避免画出穿墙直线。
		if _cave_path.is_empty():
			return []
		var points: Array[Vector2] = [global_position]
		for i in range(_cave_path_index, _cave_path.size()):
			points.append(_cave_path[i])
		points.append(_map_destination)
		return points
	return [global_position, _map_destination]
```

设计要点：

1. **首点用 `global_position`**（而非第一个路点）→ 虚线起点永远吸附在玩家标记上，与标记不会"脱钩"。
2. **末点统一补 `_map_destination`** → 保证虚线真正抵达目标点（`smooth_path` 末点只到目标格附近，差一格时视觉上"没走到"）。
3. **洞穴且路线未算出时返回 `[]`**（不退化画直线）→ 满足 A4，宁可短暂不显示也不画穿墙线。因为 `_map_direction` 每物理帧都会算一次，实际只会有极少帧为空。
4. 不新增信号、不新增全局状态 → 零耦合，UI 侧沿用 `refresh()` 轮询（已是既有模式）。

### 3.3 绘制规格（常量集中在 `map_canvas.gd` 顶部，符合 A7）

| 项 | 小地图 | 大地图 | 说明 |
|---|---|---|---|
| 线色 | `Color("6eebe6")` | 同左 | 与玩家标记同色系 = "这是你的路线" |
| 线宽 | 2.0 | 3.0 | 与玩家标记半径（4 / 6）成比例 |
| 虚线节距 | `dash = 5.0` | `dash = 8.0` | 逐段调用内置 `draw_dashed_line` |
| 终点标记 | 空心金环 `Color("f2cb5b")`，半径 4 / 6，线宽 2 | 同左 | **可选**（§5 D2）：避免"线到哪结束"含糊；金环与任务目标标记 `f2cb5b` 同色 |
| 起点 | 不额外画 | 不额外画 | 玩家标记已存在 |
| 流动动画 | 不做 | 不做 | 见 §3.4 的理由 |

实现骨架（在 `_draw_markers()` 头部）：

```gdscript
for i in range(_route.size() - 1):
	_overlay.draw_dashed_line(world_to_canvas(_route[i]), world_to_canvas(_route[i + 1]),
		ROUTE_COLOR, ROUTE_WIDTH_MINIMAP if minimap else ROUTE_WIDTH_BIG, ROUTE_DASH_MINIMAP if minimap else ROUTE_DASH_BIG)
```

- 用 Godot 内置 `CanvasItem.draw_dashed_line` 逐段绘制（无需自研虚线算法）。代价是**拐点处节距会重新起算**；对"绕障折线"而言观感可接受。若要跨拐点连续节距，再自研累进算法（列为可选项，本期不做）。
- 若 D2 采纳终点标记：在路线绘制后加 `_overlay.draw_arc(world_to_canvas(_route[-1]), 半径, 0, TAU, 20, GOLD, 2, true)`。

### 3.4 刷新与性能

- 路线几何**跟随现有 0.2s 节流**刷新，理由：玩家标记本身就是 0.2s 步进（`_player_position` 只在 `refresh()` 里更新），若虚线每帧动而标记每 0.2s 动，两者会**视觉错位**。让两者同步跳步反而更自然。
- `refresh()` 的守卫条件追加路线比较，避免静止时无效重绘：

```gdscript
var route: Array[Vector2] = player.map_move_route() if player != null else []
...
if GameState.current_map != _map_id or position_now != _player_position or markers != _markers or route != _route:
	_map_id = GameState.current_map
	_player_position = position_now
	_markers = markers
	_route = route          # 换图时该分支同样执行，天然清空上一张图的残留
	_overlay.queue_redraw()
```

- 成本量级：每次重绘只多画"路点数 − 1"条线段（洞穴路径通常十几~几十段），与既有的标记绘制同量级；**不触碰底图与地形网格**，`background_draw_count` 语义不受影响。
- 大地图打开时世界继续模拟（[map_big_panel.gd#L2](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/ui/map_big_panel.gd#L2) 头注释：沿用关闭式面板互斥/屏蔽指令规则，**世界继续模拟**），因此大地图上的虚线会**实时跟随人物推进**，不是一张静态快照。
