# 99 · 破损装备快速出售失效 —— 排查与修复

> 报障：**背包中耐久为 0 的装备无法快速出售。**
> 结论：不是出售链路坏了，是工程 77 留下的一条**过宽防线**把破损件整体挡在「预设默认勾选」之外；附带一条本地化键缺失，让玩家看到的是裸 key。
> 本文记录排查过程、改动边界与守门方式。**本次不改任何数值**（售价、修理费、耐久上限均未动）。

---

## 一、现象与复现路径

玩家的操作路径是：背包 → 「出售」→ 选一档预设（谨慎 / 标准 / 积极）→ 期望一键勾好该卖的 → 确认成交。

在修复前，凡是 `durability == 0` 的装备：

| 现象 | 实际情况 |
|---|---|
| 不出现在清单里 | ❌ 错，**会出现**（清单只按 `kind == "equip"` 过滤） |
| 勾选框灰掉 | ❌ 错，**可以手勾**（`manual_selectable` 不看耐久） |
| 默认不勾 | ✅ **这才是 bug**：三档常规预设一律不勾 |
| 原因那行文字 | ✅ **第二个 bug**：显示裸 key `ui.sale_preview.reason_damaged` |

净效果：玩家每次批量卖装都要在几十件里**逐件手勾**破损件，勾了还要多按一次「再次确认珍贵装备」（因为手勾预设外条目会进 `risky` 名单）。对「挂机几小时回来清背包」来说，这等同于快速出售对破损件完全失效。

---

## 二、根因（两条，都在规则层）

### 2.1 主因：`damaged` 被当成「否决默认勾选」的原因

`scripts/systems/sell_gear_policy.gd::_judge()`：

```gdscript
if Durability.is_broken(item):
    reasons.append("damaged")
```

`entry()` 里默认勾选的判定是「原因集为空」：

```gdscript
var automatic := reasons.is_empty() and bool(preview.get("ok", false))
```

⇒ 只要这件装备破损，`reasons` 就非空 ⇒ `default_selected` **恒为 false**，与它的品质、等级、星级、是否比身上好统统无关。

对照实验（`tools/sell_broken_probe.tscn`，Lv40 玩家，同款同品质白/蓝装，唯一差异是耐久）：

```
== preset=standard ==
   满耐久 白   default_selected=false  reasons=[]
   耐久0 白    default_selected=false  reasons=["damaged"]
   满耐久 蓝   default_selected=false  reasons=[]
   耐久0 蓝    default_selected=false  reasons=["damaged"]
```

（该探针里「满耐久也不勾」是因为传了空 `equipment`、不构成升级；真实存档里同档白装本来会被勾上，破损那份则永远掉队。）

### 2.2 附带：`ui.sale_preview.reason_damaged` 从来没有登记过

`data/localization.json` 里 `reason_` 系列只有 `favorite / unsellable / upgrade / starred / quality / level / suit` 七条，**唯独缺 `damaged`**。`Localization.tr_key()` 遇缺键返回 key 本身并打 warning：

```
WARNING: [Localization] 缺失文案 key：ui.sale_preview.reason_damaged
```

所以那件装备在清单里写着「ui.sale_preview.reason_damaged」——玩家看到的是故障感的英文串，进一步确认「这功能坏了」。

---

## 三、为什么工程 77 的规则在这里变成了 bug

工程 77 §五把这条写成：「破损件 `score()` 归 0 后会失去『属性更高』保护 ⇒ 可能被静默卖掉可修的稀有件 ⇒ **已损坏件不参与自动出售 / 一键出售**」。

这个推理在 77 当时成立，但**前提已经被工程 88 推翻**：

| 时期 | `Equipment.score()` 对破损件 | 「可修好装备被误卖」的风险 |
|---|---|---|
| 工程 77 | 整件属性不计 ⇒ **0 分** | 真实存在（任何候选都能压过它） |
| 工程 88 之后（现行） | 只砍词条、**给基底分** | 已由 `upgrade` 判据兜住 |

也就是说，阻断「可修好装备被误卖」的真正守门员现在是 `upgrade`（评分可提升）与 `starred`（已升星）两条，它们对破损件一样生效。`damaged` 这条**只剩下副作用**：把破损的白装垃圾也一并锁在背包里。

这正是本次 bug 的形态 —— **一条为修某个问题加的拦截，在前提消失后没有回收，于是变成了新问题**，而且当时没有测试守门（全项目 grep `damaged` 只有 3 处代码/注释，零断言）。

---

## 四、修复方案

### 4.1 把 `damaged` 从「否决项」降级为「提示项」

新增一个显式分类，而不是悄悄改判定条件 —— 让「哪种原因只提示、哪种原因真否决」变成可读、可测的事实：

```gdscript
## 「仅提示」原因：写进 reasons 供界面展示，但不否决默认勾选。
const NOTES_ONLY := ["damaged"]

static func blocking_reasons(reasons: Array[String]) -> Array[String]:
    # 滤掉 NOTES_ONLY，得到真正否决默认勾选的原因
```

`entry()` 的判定改为：

```gdscript
- var automatic := reasons.is_empty() and bool(preview.get("ok", false))
+ var automatic := blocking_reasons(reasons).is_empty() and bool(preview.get("ok", false))
```

### 4.2 刻意保留的口径差异

| 入口 | 吃哪份原因 | 理由 |
|---|---|---|
| `entry()`（手动清单 / 快速出售） | `blocking_reasons()` | 玩家能看见、能取消勾选，破损件不该被硬锁 |
| `auto_sell()`（拾取瞬间自动出售） | **完整** `reasons` | 自动出售没有「取消勾选」这一步，卖错就不可逆 ⇒ 保留最保守口径 |

### 4.3 界面：勾选时也要显示「已损坏」

原来 `_reasons_text()` 在 `default_selected == true` 时只显示「符合当前预设」，破损件现在会被勾上 —— 若不改这里，玩家就再也看不到「已损坏」这条标注。改为：**仅提示项任何情况下都显示**，否决项只在未勾选时显示。

```gdscript
for reason in row.reasons:
    if SellGearPolicy.NOTES_ONLY.has(String(reason)) or not selected:
        labels.append(Localization.tr_key(text_key))
```

### 4.4 补文案

`data/localization.json` 新增一条（总条数 918 → **919**，无重复键）：

```json
"ui.sale_preview.reason_damaged": "已损坏（耐久为 0，修好仍可用）",
```

## 五、验证

### 5.1 探针（改前 → 改后）

`tools/sell_broken_probe.tscn`（只读，跑完还原 `GameState.inventory`）四段输出：预设勾选矩阵 / 清单条数 / 事务层是否放行 / 文案键是否存在。改前 `reason_damaged` 缺键、破损件全档不勾；改后同档同品质的破损件与完好件勾选结果一致。

### 5.2 断言（两处，均带「非空跑」前置）

**`tests/sell_gear_policy_test.gd`** —— 规则层 7 条：

1. 破损白装与完好白装在「谨慎」下**同样被默认勾选**（核心判据，修复前必红）
2. 破损件仍可手选
3. 只有破损件带 `damaged` 标注（完好件不得出现）
4. `blocking_reasons()` 只滤 `damaged`、保留 `starred`
5. 破损 + 已升星 **仍不被勾选**（保护没被误删）
6. 破损 + 评分可提升 **仍不被勾选**（工程 77 R2 的核心保护仍在）
7. `auto_sell()` 对破损件仍返回 `reason == "damaged"`（口径差异是刻意的）
8. `reason_damaged` 能解析出正文而不是裸 key

**`tests/sell_gear_preview_test.gd`** —— UI 端到端 3 条：破损件出现在清单 / 被预选 / 原因行是人话；成交后背包与金币同时正确。

> ⚠ 第一版用例踩了一个坑：`old_common` 在上面的收藏用例里已被标记收藏，`duplicate()` 把 `favorite` 一起带过来，导致「破损件仍可手选」直接假红。修复用例里显式 `erase("favorite")` —— **收藏件本来就既不能勾选也不能手售**，会把判据搅成两个原因叠加。

### 5.3 负向验证 `tools/verify_99_negative.py`（6 条全部变红）

| # | 注入的 bug | 变红的断言 |
|---|---|---|
| N-1 | `entry()` 退回用完整 `reasons` 判默认勾选（原 bug 形态） | 破损/完好同样被勾选 |
| N-2 | 破损不再写 `damaged` 标注 | 只有破损件带标注 + 自动出售拒绝 |
| N-3 | 把 `starred` 也塞进 `NOTES_ONLY`（保护被误删） | 已升星不被默认勾选 + `blocking_reasons` + 破损且升星 |
| N-4 | `auto_sell()` 改用 `blocking_reasons()` | 自动出售仍拒绝破损件 |
| N-5 | `_reasons_text()` 退回旧实现 | 原因行显示「已损坏」（勾选时不再显示） |
| N-6 | 摘掉本地化键 | 原因行露出裸 `ui.sale_preview.reason_damaged` |

## 六、影响面与风险

| 面 | 影响 |
|---|---|
| 售价 / 修理费 / 耐久上限 | **零改动**，破损件卖的仍是 `Shop.sell_price()` 的原价 |
| 自动出售（拾取瞬间） | 行为不变，仍拒绝破损件 |
| `Shop.matches_low_gear()` / `GameState.sell_low_gear()` | **不动**（另一条独立链路，目前无 UI 入口，只被测试调用） |
| 「暴力」预设 | 本来就不走 `_judge`，破损件一直能卖，不受影响 |
| 风险：可修好的破损件被批量卖掉 | 由 `upgrade` + `starred` 两条继续兜；玩家若已收藏也不会被卖（`favorite` 仍是硬拦） |

**回退方式**：把 `NOTES_ONLY` 改回空数组 `[]` 即可恢复「破损件一律不勾」的老口径（一处常量，不需要动判定逻辑）。
