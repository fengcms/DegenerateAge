## 2. 环境准备（换机时逐项安装）

### 2.1 安装 Godot 4

| 平台 | 方式 | 说明 |
|---|---|---|
| macOS（Apple Silicon） | 官网下载 `Godot_v4.7-stable_macos.universal.zip` 解压即用；或 `brew install --cask godot` | 建议把 `Godot.app` 拖入「应用程序」，便于命令行调用 |
| Windows | 官网下载 `Godot_v4.7-stable_win64.exe.zip` | 免安装，解压即用 |
| Linux | 官网下载 Linux 版 / 或用发行版包管理器 | 若走命令行验证，需确保 `godot` 在 PATH |

> 官网：<https://godotengine.org/download>
> 只做 2D 的项目**用标准版即可，不需要 .NET/Mono 版**。本项目首版使用 GDScript；仅当将来引入 C# 时才需要 Godot 的 .NET 版 + .NET SDK。

**命令行验证（可选）**：若 Godot 在 PATH 中：
```bash
godot --version            # 应输出 4.x.stable...
godot --headless --editor --quit   # 首次导入资源、生成 .godot/ 缓存（在项目根目录执行）
```

### 2.2 安装 Git 并配置 SSH

```bash
git --version
# 若尚未配置 SSH key：
ssh-keygen -t ed25519 -C "your_email@example.com"
# 将 ~/.ssh/id_ed25519.pub 内容加到 GitHub → Settings → SSH and GPG keys
ssh -T git@github.com      # 看到 "Hi <user>!" 即成功
```

### 2.3 代码编辑器（可选）

- **VS Code** + 插件 `godot-tools`（GDScript 高亮 / 补全 / 运行）。
- **JetBrains Rider**（仅当使用 C#）。
- Godot 内置脚本编辑器已可用，可不额外安装。

### 2.4 AI 协作接入（可选，本项目核心收益点）

- 部署 `godot-mcp`，使 AI agent 能直接读写 `.tscn` / `.gd` / `.tres` / `.json`。
- 工作流约定：**PRD（设计事实源）→ `data/*.json`（数据事实源）→ Godot 工程（运行事实源）**。

## 6. 本轮脚手架是如何搭起来的（复现步骤）

> 换机后若需从零重建同样结构，按下列步骤即可。

**步骤 1 — 建工程与目录**
- 用 Godot 新建 2D 项目（或直接写 `project.godot`），建立 `scenes/ scripts/ autoload/ data/ assets/ addons/` 目录。

**步骤 2 — 填写 `project.godot`**
- `[application]`：名称、主场景 `res://scenes/Main.tscn`、图标、`config/features=PackedStringArray("4.7", "GL Compatibility")`。
- `[display]`：视口 **1280×800**（最小分辨率，见 9.11），`stretch/mode="canvas_items"`、`aspect="expand"`。
- `[rendering]`：`rendering_method="gl_compatibility"`（跨平台最稳）；`default_texture_filter=0`（像素最近邻）。
- `[autoload]`：按顺序登记 `EventBus / GameState / DataLoader / SaveManager`。
- `[input]`：登记全部快捷键（见 §7 输入映射）。

**步骤 3 — 写 4 个 Autoload 脚本**（`autoload/*.gd`，见 §5 说明）。

**步骤 4 — 写 14 个 JSON 数据**（`data/*.json`，见 §7 与 `docs/产品文档/10`）。

**步骤 5 — 写启动场景与脚本**（`scenes/Main.tscn` + `scripts/main.gd`）。

**步骤 6 — 校验**
- 所有 JSON 用任意 JSON 校验器 / `python -m json.tool` 过一遍。
- 用 Godot 运行，确认输出「配置校验通过 ✅」。

## 8. 数据驱动约定与校验规则

**约定**：装备 / 技能 / 怪物 / 掉落 / 任务 / 商店 / 升星 / 坐骑 / 如意 / 仓库 / 杂项 / 药水 / 地图 / 文案**全部文本可编辑**；新增内容只需加 JSON 条目 + 配图标，不改代码。

**启动校验**（`DataLoader.validate_all()`）：

1. **ID 唯一**：数组型表按各自「唯一键」字段去重（缺省 `id`；`shops` 用 `npcId`）。
2. **引用合法**：`monsters.dropTableId` 必须存在于 `dropTables`；`maps` 的 `spawnPoints[].monsterId` 与 `bossSpawn.monsterId` 必须存在于 `monsters`。
3. **等级范围**：地图 `tierRange` / 怪物 `level` / 装备 `levelReq` 的取值合理性（可扩展）。
4. 文件缺失 / JSON 语法错误 → 明确报错，不静默。

## 10. 常见问题

**Q1：界面/标签里的中文显示为方框？**
Godot 内置默认字体不含中文字形。解决：把一款中文字体（如思源黑体 / 霞鹜文楷）放入 `assets/fonts/`，在 Project Settings → GUI → Theme → Default Font 指定，或建立主题资源统一设置。**属已知待办，不影响逻辑。**

**Q2：`.godot/` 目录要不要提交？**
不要。它是由引擎生成的导入缓存，已在 `.gitignore` 忽略。换机后由引擎首次导入自动生成。

**Q3：换机后打开提示 Godot 版本不同？**
工程当前以 **4.7** 打开（Godot 首次打开会自动把 `config/features` 升到本机版本，属正常现象）。用更高的 4.x 一般可平滑升级；请在 Project Settings → Rendering 确认渲染器仍为 `gl_compatibility`。

**Q4：我想在别处重建同样工程？**
按 §6 的步骤，或直接 `git clone` 本仓库（工程即目录，天然可迁移——这正是选用 Godot 的收益之一）。

## 12. 验证命令（每次改动后运行）

本项目提供**两层无头自动验证**，无需打开编辑器即可确认"没写坏"：

```bash
GODOT=/Applications/Godot.app/Contents/MacOS/Godot
cd <项目根目录>

# 0) 首次运行 / 新增 class_name 脚本后：注册全局类（否则运行报「类型未声明」）
"$GODOT" --headless --path . --import

# 1) 冒烟测试：断言数据校验 / 等距公式往返 / 出生点 / 边界碰撞
"$GODOT" --headless --path . res://tests/SmokeTest.tscn   # 退出码 0 = 通过

# 2) 启动回归：跑主场景，应输出「配置校验通过 ✅」，且无 SCRIPT ERROR
"$GODOT" --headless --path . --quit
```

判读：
- 退出码非 0 或出现 `SCRIPT ERROR` → 未通过，先修复再提交。
- 新增 / 重命名 `class_name` 全局类后，务必重跑第 0 步，否则运行时识别不到新类型。
