# 自动找怪范围与巡游疏密开发验收记录

对应[分析方案](自动找怪范围与巡游路径疏密分析.md)，记录2026-10-31起的逐节点实施、兼容边界和验证证据。世界像素与地图格分别标注，所有测试使用隔离项目与独立user目录。

## 节点一：自动选怪范围

保留原可视候选，额外接纳760世界像素内且位于已探索区域的屏外怪物。扫描使用一次活动敌人组遍历，先距离/探索筛选，再走原Boss开关、黑名单及连通性判定；只为最终目标寻路。未扩大刷新范围、活动预算和Tab可视锁定列表；原手动、粘性目标优先级不变。搜怪间隔仍为0.35秒，不更改旧存档searchRadius的兼容语义。

新增AutoSearchRangeTest，在真实世界/相机下覆盖屏外已探索/未探索、760边界、可视远目标保留、镜头缩放、Tab列表、Boss开关、黑名单与隐藏节点。既有洞穴绕障和自动控制测试一并回归。

## 实施节点

12格主巡游和支路补漏、战斗后游标接续、实际路线与性能对照按以下节点分别完成验证和提交。

节点一验证：AutoSearchRangeTest、CaveAutoBattleTest、AutoControlAcceptance全部通过；编辑器导入无脚本错误。增加覆盖，未修改既有断言。

## 节点二：12格主路线与分帧补漏规划

新增AutoRoamPlan，复用现有通行掩码和连通分量。主路线每12地图格蛇形采样，保留首尾边界；按现有Fog的8格揭示/4×4区块规则，为粗路线无法覆盖的可达区块补少量锚点。不读怪物刷新表、不修改探索集合、不对候选执行A*。粗巡一轮后仍有未探索区块才访问补点，已探索地图跳过细扫。极小可达孤岛可通过补点回退，完全封闭区域保留合法空缓存。

正式掩码实测（主点/补点）：腐化源头112/4，余烬炉房107/9，无尽回廊54/4，百首禁域144/26；下层作业区226/2。真实Fog.reveal独立复核：可达区块全部可由主点和补点覆盖，规划过程不提前揭图；动态井心门禁关闭/开启后区域变化正确。该覆盖证明以到达所有规划点为前提，实际移动遇阻与战斗插入仍须动态回归。

一次性构建在当前M1 Max无头采样中约25–72ms，不能直接放到单物理帧。正式入口改为每帧约1500微秒软预算、每8个工作单元检查时限；实测分片P95约1.52–1.67ms、峰值1.69ms（单轮采样，非硬实时保证）。主采样完成即开始移动，其余区块扫描在后续巡游物理帧继续。完整规划约17–48个分片，不代表同等游戏延迟：有怪时先追击，主路线先发布。重建由地图/导航版本/连通区域变化触发，取消或旅行释放旧工作状态。

CaveConnectivityTest的旧624点断言随12格规则更新为226主点+2补点，仍严格检查候选不调用完整路线；合法空缓存夹具改成真正全封闭布局，原先“无7格采样的可达孤岛”现应补点，不再误当空规划。新增用例单独覆盖窄支路、分帧结果一致、探索补漏开关及门禁；这是适配新玩法并扩展覆盖，不是取消连通/碰撞断言。

节点二验证：AutoRoamPlanTest、AutoExplorationSurvival、CaveAutoBattleTest、CaveConnectivityTest全部通过。异步主点先发布解决了早期版本等待完整规划导致原巡游响应断言不稳定的问题；未放宽既有自动探索移动断言。

## 节点三：中断后的巡游接续

遇怪和走向掉落时保存游标，仅在首次打断记录出发位置；战斗后清理旧导航方向及卡住计时，接续原下一点，不重新挑最近旧点。离开出发位置超过760世界像素时，按“接续距离＋每跨一个前向巡游点64像素代价”选接续点，避免长追击后跨地图返回，也避免毫无代价地跳回上一点。下轮仍可访问跳过的区域，未知区块补漏保持有效。

手动接管、F/G状态重置、导航重建及旅行清理接续标记；旅行还丢弃分帧工作状态，不保留旧地图引用，不新增存档字段。

AutoRoamResumeTest以真实决策入口验证遇怪游标、短距离接续、长距离前向重接、实际掉落拾取、手动接管和旅行取消规划。该测试及AutoExplorationSurvival、AutoControlAcceptance、CaveAutoBattleTest四项全部通过。


## 节点四：综合回归与对照

### 搜索成本

100个冻结真实怪物、相同相机/位置与探索状态，各120轮交替采样旧可视收集排序入口和新入口。旧分支保留原可视收集、Boss/连通性及距离血量筛选，未包含手动/粘性分支，测试中这两分支均不活动。最终加入“已有更近合格目标则跳过无效候选、只有可能胜出的候选查连通性”的早期过滤，保留等距低血量判据。

|倍率|旧P50/P95/P99/峰值 µs|新P50/P95/P99/峰值 µs|
|---|---|---|
|0.8|4476/4714/5047/6472|200/264/302/365|
|1.0|4364/4565/4768/4967|207/266/341/351|
|2.0|1918/2063/2110/2177|184/251/320/352|

该对象排列较早遇到最近合格目标，所以早期过滤收益较高；最坏情况下所有目标逐个更近或不可达，仍需遍历和筛选全部候选，不能将0.2ms作为所有场景上限。搜怪仍每0.35秒一次，没有改成每帧执行。CPU数据来自无头专项，不能证明GPU或整帧提升。

### 持续真实玩法与窗口

AutoRoamSoakTest实例化正式Game场景，真实执行AI、寻路、战斗、拾取和掉落，不直接删掉落或跳过奖励。隔离测试注入高生存属性：Lv100，前两图攻防500，回廊攻防50000，额外生命100万；原低攻防回廊样本无法击杀Boss并最终死亡，因此修正测试角色配置，未移除持续战斗/存活断言。测试不是正常角色平衡验证。

三图各600游戏秒，共1800秒/108000物理帧的固定60Hz步长长跑通过。固定步长取消墙钟等待，首轮通过样本实际用时63.36秒，622击杀、1008次拾取；不应写成“真实等待30分钟”或GPU性能结论。每图确实移动、击杀且持续开启自动战斗，退图后节点均回到18。回廊节点随保留的掉落增至909，300–600游戏秒保持909，静态内存约263.775–263.778MB；未发现持续新建规划节点或退图残留。最后一轮复测另记于末尾。

窗口使用Godot 4.7.2、Apple M1 Max、GL Compatibility、1280×800、最高60FPS；三图各真实运行30秒，跳过各图前60绘制帧预热，以frame_post_draw墙钟间隔采样，截图确认真实渲染。测试使用Game场景，未挂Main完整HUD；也未覆盖百首禁域100Boss全负载。窗口短跑时另有隔离回归进程，尾部尖峰可能受系统竞争影响，未归因于本次修改。
