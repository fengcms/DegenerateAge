# 倍速相机稳定跟随修复与验收记录

对应[原因分析](百首禁域倍速视野剧烈跳动原因分析.md)，记录2026-11-01分节点修复。相机视觉采用真实时间，玩法时间倍率、伤害、移动和奖励规则不变。

## 节点一：稳定跟随骨架

Player相机接入StableFollowCamera，关闭原生线性平滑。相机仍由玩家节点持有和释放，但使用top_level避免父节点运动直接带走镜头；每渲染帧以Time.get_ticks_usec真实时间推进指数跟随，alpha=1-exp(-8×dt)，真实dt上限0.1秒，长暂停/卡顿后不突然追赶。每帧O(1)，不创建节点、资源、Tween或计时器，无全局信号及存档字段。

地图装配完成后显式snap_to_target，清除旧位置和时钟。StableCameraTest覆盖0/1/2/4/8/16倍率相同真实时间的逐帧轨迹一致、单调收敛、父变换隔离及0～30秒的大步长；测试、CaveAutoBattleTest及AutoExplorationSurvival全部通过。后续节点补齐边界、异常恢复、缩放/旅行和窗口压力验收。

## 节点二：边界、异常与明确复位

内部跟随位置和目标均按当前viewport/zoom约束至现有矩形camera limit；地图小于视口时按中心显示，不产生反向clamp。有限值检查在写入节点变换前执行，损坏内部状态恢复到玩家的合法镜头目标；非法时间步长不传播NaN。每帧仍为固定数量向量/指数计算，边界变化无需全图扫描。

StableFollowCamera.snap是明确传送/装配/缩放统一入口，普通Camera2D保留reset_smoothing语义；未入树相机跳过复位。随机传送券落位后、SettingsRuntime应用倍率后、Game出生/切图后均清理旧内部位置和时钟。真正暂停依旧冻结镜头，零时间倍率不依赖除法，原地复活不产生位置跳转；返回城镇/读档通过已有世界重建装配。

测试中有意移动玩家后立即截图/点选的夹具改为调用新复位入口；固定全图截图关闭相机脚本process，避免跟随覆盖测试取景。原有点击、NPC、穿行与范围断言未放宽。冻结地图渲染基准在修改玩家位置后显式复位，保持原确定性相机路线。

验证通过：StableCameraTest（加入三档zoom、非有限内部状态、异常dt、视口大于地图）、CameraLifecycleTest（正式百首禁域装配、明确位移、缩放、零倍率、暂停恢复及释放）、RandomTicketTest、SettingsTest、SmokeTest、AutoSearchRangeTest、CampLiveIntegrationTest、CampFullArtAcceptanceTest。最初新增测试有一处Variant类型推导报错，已显式声明Vector2并复跑通过，未放宽断言。

## 节点三：综合回归与百首禁域窗口压力

最终十一项隔离回归全部通过：StableCameraTest、CameraLifecycleTest、RandomTicketTest、SettingsTest、SmokeTest、AutoSearchRangeTest、CaveAutoBattleTest、AutoControlAcceptance、MapCanvasCacheTest、MapRouteOverlayTest、MinimapViewportTest。两项新契约加入默认集（108项），默认集仍为常用子集，未宣称全量回归。

CameraStressTest使用正式百首禁域Game、100个真实Boss与2400个真实GroundItem场景。玩家物理移动/自动决策冻结，仅注入100像素阶跃；测试角色无敌，掉落设置手动拾取并延长测试寿命，以保持固定负载，不改生产刷新预算或奖励入口。该场景强制把100Boss集中在视野附近，是超过地图通常按距离激活的极端压力夹具，不等于普通玩家的完整挂机过程。

每档1/2/4/8/16倍率90个绘制样本，加入一次160ms人为停顿。逐帧检查相机中心有限、朝固定目标单调推进且不越过玩家，并检查2400掉落没有被静默裁掉。第一轮真实窗口通过：最大相机单步约55.07像素，所有档位最终误差0；未再出现分析阶段的8960像素往返跳转。测试还验证整张世界退出后节点回到基线，镜头未留下独立节点或信号引用。

第二轮将渲染循环改为每帧显式force_draw，并统计frame_post_draw次数，避免测试窗口遮挡影响绘制有效性；截图只写/tmp，不进入正式资源。该测试必须--rendered，无头--all明确排除它。

### 代价与限制

稳定跟随每个镜头一份小状态（目标引用、位置、时钟），每渲染帧O(1)计算和滚动更新，没有额外相机、缓存、Tween、粒子、计时器或全局信号。退出随玩家释放；缩放、首帧/装配和明确传送重置位置与时钟；暂停继承原场景处理模式。未改物理频率、Engine.time_scale或角色运动/击退规则。

真正暂停恢复或卡顿超过0.1秒时，镜头本帧最多按0.1秒真实时间追赶；这是防突然追赶的视觉限制，不减慢玩法。跟随有意保持短滞后，显式传送则立即落位。地图仍用原矩形包围盒，不声称消除等距菱形边缘所有地图外留白。

极端压力场景仍很慢：第一轮帧间隔中位约190～615ms。该结果说明当前100Boss集中加2400掉落负载没有达到60FPS；本次修复解决“低帧/倍速导致镜头发散”，不是解决所有Boss/掉落性能问题。另有无头回归曾同时运行，帧时间不能当作独占设备的精确性能基线。不删除奖励或缩减判定换取镜头稳定。

```bash
python3 tools/run_isolated_tests.py StableCameraTest CameraLifecycleTest RandomTicketTest SettingsTest SmokeTest AutoSearchRangeTest CaveAutoBattleTest AutoControlAcceptance MapCanvasCacheTest MapRouteOverlayTest MinimapViewportTest
python3 tools/run_isolated_tests.py --rendered CameraStressTest
```

正常角色长时间挂机、更多窗口尺寸/DPI与多显示器移动仍可继续体验复验；本轮没有将极端夹具和有限回归冒称全场景覆盖。产品09、分析交接状态及工程交接已同步。节点提交：b6fa4f60（真实时间跟随）、56d4bde2（边界与生命周期）；最终压力验证随本记录节点提交。
