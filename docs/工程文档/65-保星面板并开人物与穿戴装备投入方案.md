# 保星面板与人物面板并开、穿戴装备可直接投入（工程 65）

> 状态：**已完成（2026-10-20）**。拍板结果：**D1 = A（只第一格）、D2 = C（只解除互斥，不做布局）、D3 = A（产物永远进背包）**。
> 落地记录见 §9。核对日期：2026-10-20。
> 需求原话：打开铁匠「保星升级」面板时按 C 打开人物面板，保星面板就关了 —— 期望**不关闭**，
> 并且**支持从人物身上把装备拖进保星面板**。

---

## 1. 需求复述

| 你的原话 | 我的理解 |
|---|---|
| 打开保星面板时按 C 开人物面板，保星面板就关闭了 | 两面板当前是**互斥**关系，任一打开会把另一个顶掉 |
| 不期望关闭 | 两者要能**同屏共存**，人物面板开着时保星面板照常可见可操作 |
| 支持从人物身上拖装备到保星面板 | 材料格要能接收**穿戴槽**来的拖拽，并且**能被真正消耗结算**（不是拖进去摆看） |

这条需求**改的是产品规则**，不是修 bug：产品 05 §5.13 现在明确写着「已穿戴件不可直接投入」。
所以除了代码，产品文档也要同步改（见 R8）。

---

## 2. 现状勘察：三层阻断，缺一层都做不成

我按「按 C → 拖装备 → 点确认」这条链路逐层查了一遍，**有三处独立的阻断**，只拆一处都没用：

| # | 层 | 位置 | 现在的行为 |
|---|---|---|---|
| 1 | 面板互斥 | `autoload/game_state.gd:1377 panels_coexist()` | 白名单只有 `equipment_fusion × inventory`；`character` 与 `equipment_fusion` **互斥**，打开任一方都会关掉对方 |
| 2 | 拖放接收 | `scripts/ui/item_slot.gd:351 _can_drop_data()` / `fusion_material_grid.gd:22` | 材料格（`ROLE_TRAY`）**只接 `ROLE_BAG`**（背包）。人物槽拖出的是 `ROLE_EQUIP`，连 hover 都不接受 |
| 3 | 结算 | `autoload/game_state.gd:929 forge_equipment()` | **只扫 `inventory`**。就算前两层放开，`by_id` 找不到穿戴件 ⇒ 返回「材料已变化，请重新选择」 |

### 2.1 已经具备、不用改的部分

这条链路里有一半能力是现成的，先说清楚，免得实施时白改一遍：

| 已有能力 | 位置 | 说明 |
|---|---|---|
| 人物槽能拖出 `ROLE_EQUIP` 载荷 | `scripts/ui/equipment_slot.gd:8` | 载荷 = `{from, slot_id, item, token}`，`token` 已是 `Warehouse.item_token()`，可做防换装校验 |
| 人物槽 `draggable` 在保星会话里已是 true | `character_panel.gd:186` | 条件是 `item is Dictionary and _bag_visible()`；**保星面板一开，背包会自动打开**（`inventory_panel.gd:126 _on_fusion_mode_changed`）⇒ 条件已成立 |
| 材料格的行语义 | `equipment_fusion_panel.gd:261 _material_error()` | 第 0 格 = 旧件 12★，第 1 格 = 新件 0★，已按 `row` 区分校验 |
| 保星规则层 | `equipment_fusion.gd:138 plan_transfer()` | 品质 / 星级 / 部位 / 收藏 / 跨档全在这里判，**不需要为「来自身上」加规则** |
| 穿脱收尾 | `game_state.gd:911 _after_equip_change()` | 广播 `equipment_changed` + `inventory_changed` + 把 HP/MP 收敛到新上限 |

### 2.2 两个必须正视的语义后果

🔴 **消耗身上那件 = 角色当场变弱甚至裸奔。** 保星本来就是「吃掉 12★ 旧件换一件全新 12★」，
旧件在背包里吃掉只是少一件库存；在**身上**吃掉，面板关掉那一刻玩家的战力是真掉的，
而且产物要等进背包才穿得上（如果等级够）。

🔴 **产物可能穿不上。** 工程 64 已允许跨档，产物需求等级可能远高于玩家等级。
所以产物**不能**默认放回原穿戴槽 —— 那会造出「穿着穿不上的装备」这种非法状态。

## 3. 方案

### R1 并开：只加一对白名单

```gdscript
# game_state.gd  panels_coexist()
if (opened_id == "equipment_fusion" and self_id in ["inventory", "character"]) \
        or (opened_id in ["inventory", "character"] and self_id == "equipment_fusion"):
    return true
```

`panels_coexist` 是并开的**唯一权威**（F-P3-1），面板侧都只查询不自带名单，所以这一处改完，
合成面板不会再被人物面板顶掉，人物面板也不会被合成面板顶掉（双向）。

⚠ 不要顺手把 `equipment_fusion` 加进 `FLOATING_PANEL_IDS` —— 那会让它和技能 / 坐骑面板也并开，
还会改变 `bring_forward()` 的层级排序逻辑。

### R2 拖放接收：加一个**实例开关**，不要全局放开

`ROLE_TRAY` 有两个使用者：**合成材料格**和**货郎出售托盘**（`shop_panel.gd:363`）。
如果在 `ItemSlot._can_drop_data()` 里直接加 `role == ROLE_TRAY and source == ROLE_EQUIP`，
**货郎托盘也会开始接收身上装备** —— 玩家能把正在穿的装备拖进出售托盘，那是另一场事故。

```gdscript
# item_slot.gd
var accept_equip_source: bool = false   # 默认 false；只有保星第一格打开

# _can_drop_data()
	or (role == ROLE_TRAY and source == ROLE_EQUIP and accept_equip_source)
```

`fusion_material_grid.gd` 的整块投放区同步判：目标格 `slot_at(point)` 的 `accept_equip_source` 为真才接。

**只有保星模式的第一格打开这个开关**（`set_open()` 里按 `_mode` 与行号设）。四金 / 四紫保持只接背包 ——
理由见 D1。

### R3 来源校验：`_source_item()` 增加穿戴分支

现在只认 `ROLE_BAG` 并把载荷与背包下标逐字段比对。新增：

```gdscript
func _source_equipped(payload: Dictionary) -> Dictionary:
	var slot_id := String(payload.get("slot_id", ""))
	if slot_id.is_empty(): return {}
	var worn: Variant = GameState.equipment.get(slot_id)
	if not worn is Dictionary: return {}
	if worn != payload.get("item", {}) or not Warehouse.token_matches(worn, String(payload.get("token", ""))):
		return {}
	return worn
```

`_on_material_dropped()` 按 `payload.from` 分派到 `_source_item` / `_source_equipped`，
**任何来源最终都只保存一份 `duplicate(true)` 快照**，与现在一致。

### R4 定位口径统一（关键）

新增一个**唯一的实例定位入口**，UI 与结算共用，避免两处各写一遍「先查背包再查身上」：

```gdscript
## 返回 {loc: "bag"|"worn", index: int, slot: String, item: Dictionary}；找不到返回 {}
func find_owned_item(instance_id: String) -> Dictionary
```

优先级：**先背包、后穿戴**。理由：脏档（同一 instanceId 同时出现在两处）时保持旧行为不变，
不走「突然改吃身上的」。

### R5 结算改造 `forge_equipment()`

| 步骤 | 现状 | 改为 |
|---|---|---|
| 定位 | `by_id` 只扫 `inventory` | 逐个 `find_owned_item()`；任一找不到 / 快照不一致 ⇒ 「材料已变化，请重新选择」 |
| 消耗 | `inventory[index] = null` | 背包件置 `null`；穿戴件 `equipment[slot] = null` |
| 产物落点 | 写回 `indices[0]` | **背包里第一个被消耗的格子**；没有则取背包空位；**都没有（背包满）在扣费前拒绝** |
| 收尾 | `inventory_changed` | 若动过 `equipment`，改走 `_after_equip_change()` |

产物**永远进背包**（D3 见 §5）。`make_output()` / `plan_transfer()` / 存档**零改动**。

### R6 预选失效联动

材料来自穿戴槽后，`_on_inventory_changed()` 里 `_find_item()` 只查背包 ⇒ 背包一有变化就把
穿戴来源的预选判成「已失效」清掉。改为走 R4 的 `find_owned_item()`，并**同时监听 `equipment_changed`**
（在 `equipment` 被换 / 卸下 / 被合成消耗后，重跑同一次失效检查）。

### R7 布局：人物面板加「装备栏紧凑模式」—— ❌ 已作废（用户拍板 D2 = C）

> 本节仅留作决策留证：**没有实现**。下面这些改动一条都没落地，人物面板保持原样浮窗。

这是本次唯一需要设计的部分。当前宽度账算不过来：

| 面板 | 宽 | 说明 |
|---|---|---|
| 背包 | ≈ 540 | `bag._center.panel_box` 最小宽（合成会话已 dock 到左 48%） |
| 人物 | **670** | `content.custom_minimum_size.x = 670`（装备区 378 + 属性卡 245 + 间距） |
| 保星 | 430 | `equipment_fusion_panel.WIDTH` |

三者相加 = 1640，默认视口 **1280×800**，放不下。所以人物面板在保星会话里要进紧凑模式：

```
[背包 0 — 0.42] [人物紧凑 0.42 — 0.54] [保星 0.54 — 1.0]
     538              154                538（面板 430 居中）
```

紧凑模式只保留 14 个装备槽（左右两列 52px），隐藏**形象展示框（258）**与**属性卡（245）**，
面板宽降到 ≈ 150。1280 宽下 538 + 154 + 430 = 1122 + 间距，余量充足。

**窄视口 / 200% 缩放的兜底**：`logical.x < 980` 时不进紧凑模式、也不做三栏 ——
保星面板维持现有位置，人物面板照旧是居中浮窗（可拖标题栏挪开），**但绝不关闭**。
核心诉求（不关闭 + 能拖）在任何缩放下都成立，只是窄屏下需要玩家自己挪一下窗口。
