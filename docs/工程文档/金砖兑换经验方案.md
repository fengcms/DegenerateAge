# 金砖兑换经验方案

## 现状与取舍

金砖是绑定储值物品，十根金条合成一块，可在仓库兑回一千万金币。现有兑换只读仓库，先做库存与余额计划，再一次性落账。参考 `data/exchange.json`、`data/miscItems.json` 和 `autoload/game_state.gd:1055`。紫装献祭已有消耗物品换经验的先例，经验可通过 `GameState.add_xp` 保留正常升级、属性成长和余量结转。上限为 9999 级。

建议用金砖补进度。按升级需求比例计算能让后期的金砖仍有价值，但无限量会把金币积累直接变成等级。首版按角色等级限制额度，刷怪和献祭继续承担大部分升级进度。已有装备等级适配仍生效，兑换不会同时提升装备等级。

## 首版规则

- 100 级解锁。仓库兑换台新增「金砖 → 经验」，城镇与随身仓库共用入口。只扣仓库中的金砖，允许跨堆扣除。
- 每块经验为当前等级升下一级所需经验的 1%，向下取整。每个角色在同一等级最多兑换 20 块，约补该级 20%。额度与存档绑定，升级后按新等级恢复，关闭窗口或重启游戏不会恢复。
- 每次兑换最多用掉本级剩余额度。整批按确认时的等级计价，跨级后的剩余经验正常结转，已花额度计入结算前等级。满级禁用。接近满级时，按可到达满级的经验限额缩小可选数量，若最后一块有溢出，明确预览实际入账后由玩家确认。
- 数量框默认 1，显示仓库持有、该级剩余额度、预计经验和兑换后的等级与进度。确认时若等级、经验进度或可用额度导致预览变化，更新预览并等待再次确认。

## 开发与验收

1. 新增经验兑换配置与计划函数，复用仓库资产扣除和升级曲线。GameState 按实时状态复核，先确定库存、额度和经验，再同步提交库存及额度并调用现有经验入口。库存不足、超额、未解锁或预览失效时整笔拒绝。用提交中的防重入和确认界面的单次提交保护处理连点。沿用统一存档入口，把库存、等级、经验和额度保存在同一快照；旧档默认本级已用 0，验证读档后额度保持一致。
2. 复用仓库数量框与本地化提示，接通城镇和随身入口。确认前展示扣除和实际到账，成功只触发一次仓库刷新，正常升级反馈沿用经验入口。验证不同 UI 缩放、快捷操作和仓库其他兑换。
3. 隔离存档验证 99/100 级、1/20/21 块、跨堆、库存或预览变化、连点、重启、跨级、9998/9999 级，以及旧档兼容。用 517 和 659 级存档记录正常刷怪一小时的金砖净积累、经验和装备开销，再复核定价。各开发节点验收后独立提交。
