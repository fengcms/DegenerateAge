# 面板打开中断自动寻路 / 自动战斗 —— 根因分析与修复

## 1. 问题现象

角色处于**自动寻路**状态（点击世界地面、点击大地图目的地，或从任务面板点击任务目标链接）行走过程中，
打开任意界面面板（大地图、技能、设置、背包、角色、任务、仓库、铁匠、车夫、商店、升星、存档……），
角色立刻**停止行走**，且关闭面板后**不会自动恢复**（路线已被丢弃，需要重新点击目标）。

自动战斗（F 挂机）在面板打开时**大部分情况仍继续**，但当 F 挂机未开启、仅靠自动寻路行走时，
面板打开会让角色完全冻结。

用户诉求：面板打开**不应**中断自动寻路与自动战斗，需排查全部面板的影响。

## 3. 根因链

自动寻路有两条驱动路径：

1. **地图点击路线**：点击世界地面 / 大地图 → `Game.request_map_move()` → `Player.request_map_move()` 置 `map_move_active = true`；
2. **任务导航**：任务面板点击目标 → `MapService.quest_nav_target` → `Game._tick_quest_navigation()` 逐帧下发 `request_map_move`。

两者最终都靠 `Player.map_move_active` 在 `_physics_process()` 的 `_map_direction()` 分支里驱动角色移动。

### 3.1 根因一：面板打开即整帧早退冻结角色

[player.gd](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/entities/player.gd#L275-L282)：

```gdscript
# 面板接管手动输入；F 挂机已开启时仍执行自动战斗的移动意图。
if GameState.panel_open and not GameState.auto_battle_on:
    auto_move = Vector2.ZERO
    manual_input_active = false
    velocity = Vector2.ZERO
    move_and_slide()
    _update_blink()
    return
```

面板打开且 F 挂机未开时，函数在**到达 `map_move_active` 分支之前**直接 `return`，`_map_direction()` 永不执行 → 自动寻路路线虽然仍在，但本帧移动被彻底跳过，角色静止。

### 3.2 根因二：面板打开即无条件清空 `map_move_active`

[player.gd](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/entities/player.gd#L287-L290)：

```gdscript
if GameState.panel_open:
    manual_attack_active = false
    _pending_skill_id = ""
    map_move_active = false          # ← 面板打开即取消自动寻路路线
```

即使 F 挂机开启、走过了早退分支，`map_move_active` 仍被置 false，**也就是把已发出的自动寻路路线永久取消**；关闭面板后不会自愈，必须重新点击目标。这是「关闭面板后仍不走」的直接原因。

### 3.3 根因三：任务导航在面板打开时暂停下发

[game.gd](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/world/game.gd#L79-L82)：

```gdscript
if GameState.panel_open:
    # 普通面板会暂停角色的手动移动；关闭后应重新发出任务导航，而非误报道路失败。
    _quest_nav_issued = false
    return
```

面板打开时 `_tick_quest_navigation()` 直接返回：任务的「到达出口自动切图 / 到达 NPC 自动交互」在面板打开期间不会触发，只能等面板关闭后补发。与根因一、二叠加，使任务链接式寻路同样表现为「一开面板就停」。

### 3.4 根因四：面板打开时清空到点待触发目标并跳过迷雾揭示

[game.gd](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/world/game.gd#L38-L41)：

```gdscript
if GameState.panel_open or _player.is_dead:
    _pending_npc = null
    _pending_exit = null
    return
```

面板打开时清空 `_pending_npc` / `_pending_exit` 并提前返回：点击 NPC / 出口发起的「走到位后自动交互」在面板打开时被丢弃；同时后续的迷雾揭示（第 61-64 行）也被跳过。

## 4. 修复方案

统一规则：**普通关闭式浮窗只接管「手动输入」（方向键、攻击键、点击世界），不再影响任何自动行为；自动寻路、自动战斗、任务导航与到点触发均继续运行。** 模态面板（暂停场景树）保持冻结一切，属预期。

### 4.1 `scripts/entities/player.gd`

删除早退分支，并停止在面板打开时清 `map_move_active`；面板打开时仅屏蔽手动输入：

```gdscript
# 普通面板只接管手动输入：忽略按键与点击，但自动寻路（地图点击 / 任务导航）
# 与自动战斗（F 挂机）继续运行，打开面板不再中断自动行走。
# 暂停整棵场景树的模态面板（主菜单 / 死亡 / 装备确认）由引擎自动冻结本节点。
if GameState.panel_open:
    manual_attack_active = false
    _pending_skill_id = ""

# Input.get_vector 已做归一化：斜向不会比正向更快（八向移动）
var dir := Vector2.ZERO if GameState.panel_open else Input.get_vector("move_left", "move_right", "move_up", "move_down")
manual_input_active = dir.length() > MANUAL_EPS
if manual_input_active:
    map_move_active = false
    manual_attack_active = false
    _pending_skill_id = ""
```

移除的代码：第 276-282 行的早退冻结块、第 290 行的 `map_move_active = false`。

### 4.2 `scripts/world/game.gd`

- `_tick_quest_navigation()`：移除 `GameState.panel_open` 早退，任务导航在面板打开时继续（路线续走，到点切图 / 交互照常触发）。
- `_process()`：将第 38 行条件由 `GameState.panel_open or _player.is_dead` 改为 `_player.is_dead`，令到点触发与迷雾揭示随自动行走继续。

### 4.3 同步测试契约（旧断言与新规则冲突）

- [smoke_test.gd](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/tests/smoke_test.gd#L3898-L3910)：原断言「打开地图后手动路线应停下」需改为「打开地图后自动寻路路线应继续推进」，并同步后台失焦段的基准坐标。
- [quest_navigation_recovery_test.gd](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/tests/quest_navigation_recovery_test.gd#L33-L42)：原场景以「面板暂停移动」为前提，改为断言「面板打开期间任务导航不被中断」。
