# 保星升级自动穿回原槽开发记录

日期：2026-10-30。

## 行为

按用户要求，从身上拖入的保星旧装备，在成功升级后直接穿回原槽位。为遵守既有穿戴门槛，跨档后产物等级高于角色时，继续放入背包并提前提示旧槽将空出。旧料来自背包则继续产物进背包。

来源以最终提交时instanceId定位到的实际位置为准：若选择后已卸下旧料，它属于背包材料，不自动覆盖当前新穿的其他装备。戒指等双槽严格使用旧料实际槽，不按空位/评分自动挑槽。保星新实例仍12星四词条，不继承旧料第五词条解锁；需重铸解锁。

## 实现

- `GameState.forge_equipment` 在完整快照核验材料时记录第一件旧料的实际穿戴槽。
- 产物生成、如意取优、存档结构验证后，检查角色等级及原槽部位；确定原槽或背包落点后才提交扣费和材料消耗。
- 原槽路径在同一同步调用中清除材料、扣除如意并放入新装备，之后才广播变更；不会对外暴露临时空槽。HP/MP按最终装备上限收敛，不先按卸下旧装后的临时上限截断，也不会因新装备上限提高而补满。
- 背包路径继续优先使用消耗材料腾出的格子，空间不足原子失败。没有改变普通合成和等级不足时的物品落点。
- 返回新增`equipped`与`slot`。自动穿戴时`index=-1`；背包时index为产物格子。UI读取equipped显示「成功并已穿戴」，旧调用方不能假定所有产物都在背包。
- 原有风险确认保留，足够等级时说明自动穿回；穿不上时保留明确警告。继续保留完整快照终验和战斗耐久同步预选。

没有新增存档字段/schema、费用、世界节点或逐帧扫描。只在一次合成事件中多记录原槽和做一次等级/部位检查，复用已有装备刷新与存档链。未进行整帧性能对照，不声明FPS变化。

## 验证

新增StarTransferAutoEquipTest已加入默认回归（99项）。覆盖：

1. 全部14个穿戴槽成功升级后回原槽，产物只存在一次；四种双槽不改动另一件。
2. 背包旧料仍进背包，等级不足仍进背包。
3. 满背包时通过消耗新材料释放格子，产物直接穿回原槽。
4. 四钻石如意的17次取优完成并只扣一次；新产物保持12星与未解锁四词条。
5. 自动穿戴的装备通过JSON存档校验和恢复，仍在原槽。
6. 金币不足时原装备、材料不变；HP/MP仅按最终穿戴上限收敛。
7. 随身保星真实拖入、两次确认和成功结算路径，显示自动穿回提示并完成穿戴。

定向隔离回归六项通过：StarTransferAutoEquipTest、EquipmentFusionUiTest、EquipmentFusionTransactionTest、StarTransferLevelHintTest、FullStarReforgeTest、RuneRerollTest。最后补充的HP/MP最终状态断言定向运行通过；编辑器导入通过。首次隔离导入发现UI布尔变量类型推导问题，已显式标注bool并复跑通过。

没有放宽原测试断言。原交易/UI测试仍覆盖等级不足进背包、满包失败、穿戴材料被换走/消耗时失效、战斗磨损保留预选及保星等级提示。尚未进行长期自动战斗手动试玩；本次无新面板布局。
