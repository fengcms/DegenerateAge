# 存档文件选择器统一面板外观

- 日期：2026-10-17
- 范围：存档面板「导出 / 导入」使用的内置 `FileDialog` 外观
- 结论：**可行，已实现。** 保留 `FileDialog` 的全部导航能力（收藏夹、最近、路径栏、过滤下拉、右键菜单），
  仅通过一份 `Theme` 把外框与内部控件换成游戏内面板素材，观感与原生的浅灰窗口彻底脱钩。

---

## 0. 结论摘要

| 项 | 结论 |
|---|---|
| 能否用游戏内面板素材替换原生窗口外观 | 能。`Window` 类的内嵌弹层完全遵循 `Theme`，外框与内部控件都可被主题覆盖 |
| 是否保留 `FileDialog` 功能 | 是。收藏夹 / 最近目录 / 路径栏 / 过滤下拉 / 新建文件夹 / 隐藏文件开关等全部保留 |
| 外框能否 100% 复刻 `PanelChrome` | 约 95%：切角、双层描边、标题渐变带、左右角标、金色操作按钮均已复刻；**底部菱形装饰与标题的「◆」左对齐前缀无法复刻**（原因见 §3） |
| 代码量 | 新增 1 个 SVG + 1 个主题构建脚本，改动 2 个既有文件，无内联样式 |

---

## 1. 需求与验收判据

用户诉求（原文）：「既然这个窗口是在游戏内绘制的，是否可以使用游戏内统一的面板素材，而不是现在原生的窗口模式？」

判据：

1. 弹层与游戏内其余面板（设置、背包、存档等）视觉同源：同底色、同金边、同切角、同标题带、同按钮素材；
2. 功能不减：文件与目录导航能力不能被砍；
3. 不引入平台原生对话框（`use_native_dialog` 仍为关闭，跨平台行为一致）；
4. 不新增内联样式。

---

## 2. 技术依据（实测）

以下事实通过隔离临时探针（`--rendered` 真窗口 + 截图采样）在 Godot 4.7.2 上确认，探针用后已删除：

| 编号 | 实测结论 | 影响 |
|---|---|---|
| E1 | `dialog.theme` 对内嵌 `FileDialog` **完全生效**：`Window/embedded_border` 与 `AcceptDialog/panel`、`Button` 等主题条目全部被读取 | 主题路线可行 |
| E2 | 内嵌窗口的**外框（边框带 + 标题 + 关闭钮）由引擎按 `Window/embedded_border` 这个 `StyleBox` 绘制**，绘制区域为窗口矩形**向外扩张**（expand margin）得到的矩形 | 外框样式只能通过 `StyleBox` 表达 |
| E3 | 脚本化 `StyleBox`（`extends StyleBox` + 重写 `_draw`）**无法**承载该外框：基类 `StyleBox` 没有 expand margin，且 `_draw` 收到的 `rect` 是未扩张的窗口矩形，而窗口内容铺满该矩形，自绘内容被完全遮蔽 | 排除「自绘外框」 |
| E4 | `StyleBoxTexture` **支持** `expand_margin_*`（`StyleBoxFlat` 亦支持；仅基类 `StyleBox` 不支持） | 可用九宫格纹理做外框 |
| E5 | FileDialog 的**内部控件恒定贴在窗口矩形左上角**，`embedded_border` 的 `content_margin` **不会**把它们推下去 | 标题带必须外扩到窗口矩形**之外**，内部控件才会自然落在标题带下方 |
| E6 | 标题由引擎绘制在**上方外扩带内且水平居中**；`close_h_offset` / `close_v_offset` 以**扩张后矩形**的右上角为基准 | 关闭钮可重新定位到标题带内 |
| E7 | 关闭钮图标取自 `Window/close`，可换成 `PanelChrome` 的圆形关闭素材 | 关闭钮可复用游戏素材 |

## 3. 方案取舍

| 方案 | 做法 | 评价 |
|---|---|---|
| **A（采用）** 保留 `FileDialog` + `Theme` 换素材 | 九宫格外框纹理 + 全量主题条目 | 功能零损失、改动小、无结构性耦合；代价是底部菱形与标题左对齐无法复刻 |
| B 弃用 `FileDialog`，用 `PanelChrome` 自建 Control 文件浏览器 | 自建目录浏览 / 导航 / 过滤 / 文件名输入 | 观感 100% 统一，但需重写导航与覆盖确认、丢失收藏夹与最近目录等功能，代码与测试量大 |
| C 清空引擎外框 + 在窗口内塞一个 `PanelChrome` | `embedded_border` 置空，窗口内放真 `PanelChrome` | 探针证实**不可行**：FileDialog 内部控件恒贴窗口矩形（E5），标题带会与「Path / 收藏夹 / 文件列表」重叠；且窗口对 Control 子节点的布局内距与内部控件不一致，外框无法同时贴合窗口边缘又让内容落在带下方 |

无法复刻的两点及原因：

1. **底部菱形装饰**：菱形位于面板水平中央，而九宫格只保护四角与上下边距，底部中段必然被横向拉伸——菱形会被拉成一条横线；
2. **标题「◆」前缀与左对齐**：标题由引擎在扩张带内**居中**绘制，画布被裁在窗口矩形内，无法在带内另放一个左对齐的 `Label`。

两者均为「装饰性差异」，不影响面板识别度；如需 100% 一致只能改走方案 B。

### 4.2 关键参数

| 参数 | 值 | 说明 |
|---|---|---|
| `texture_margin_*` | 左/右 44、上 61、下 44 | 四角切角、标题带、角标全部落在保护区内，不被拉伸 |
| `expand_margin_*` | 左/右 12、上 64、下 14 | **上 64** 把标题带推到窗口矩形之外（E5）；左右下留出框线安全距离 |
| `title_height` | 54 | 引擎标题垂直居中高度，与 `PanelChrome` 标题行（行高 40 + 上边距 10）对齐 |
| `close_h_offset` / `close_v_offset` | 34 / 28 | 关闭钮移回标题带右侧，与 `PanelChrome` 关闭钮位置一致 |
| 操作按钮 | `PanelChrome.ACTION_*` 九宫格 | 复用既有 `action_normal/hover/pressed/disabled` 素材 |
| 底板 | `AcceptDialog/panel` 全透明 | 外框已由 `embedded_border` 提供，不再叠矩形底 |

## 5. 局限与已知偏差

1. **底部菱形缺失、标题居中无「◆」前缀**（§3），属装饰性差异；
2. 文件 / 目录图标仍是引擎默认图标（灰白文件夹），`PanelChrome` 未提供对应素材，本次不新增；
3. 外框是「纹理九宫格」，切角与描边在放大界面倍率下会随窗口整体缩放，与 `PanelChrome` 的矢量重绘在极端倍率下可能有亚像素差异；
4. 同源遗留：设置面板的档位下拉等 `Popup` 类弹层仍不吃界面倍率（工程文档 17 号 §7），本次未一并处理。
