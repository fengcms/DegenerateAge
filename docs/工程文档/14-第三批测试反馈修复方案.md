## 1. 问题与根因

### 1.1 🔴 Boss 墓碑跨图失效（功能缺陷）

**用户原话**：
> 我在 BOSS 地图，打败 BOSS，BOSS墓碑出现，等待刷新。但是，只要跨地图，BOSS 就立即复活了，应该跨地图回来，BOSS 还是在墓碑状态，等时间到了再刷新。

**现场核实**（`scripts/world/spawner.gd` / `autoload/map_service.gd` / `scripts/world/game.gd`）：

| 环节 | 现状 | 结论 |
|---|---|---|
| 刷新倒计时存储位置 | `MonsterSpawner._points[i].timer`（**场景运行态变量**） | ❌ 随场景销毁 |
| 墓碑实体 | `BossTombstone` 节点，挂在 `Spawner` 下（`_points[i].marker`） | ❌ 随场景销毁 |
| 切图机制 | `MapService.reload_world()` → `reload_current_scene()` → **整个 `Game.tscn` 重建** | — |
| 重建后 | `Game._ready()` → `_spawner.spawn_from_map()` → **无条件生成 Boss** | ❌ 立即复活 |

**根因（一句话）**：**刷新倒计时与墓碑状态是「场景级」的，而切图是「整场景重载」——状态在重载中被清零。**
这不是参数问题，**改任何数值都无法修复**；必须把刷新状态提升到**跨场景存活**的层。

**已自述的边界**：工程文档 `08` §5.10 已写明「地图刷新点及其墓碑仍为当前场景运行态，离图释放、重进重建；跨图保留刷新倒计时**不是本次交付**」。本次即**关闭该边界**。

### 1.2 英数与中文同一字体（非等宽）

**用户原话**：
> 英文和数字，最好换成等宽字体。

**现场核实**：`assets/themes/default_theme.tres` 是全局主题（`project.godot` 的 `gui/theme/custom` 指向它），其 `default_font` 是**唯一一个** `SystemFont`：

```gdscript
font_names = ["PingFang SC", "Hiragino Sans GB", "Heiti SC", "STHeiti", ...]
```

`PingFang SC` 的拉丁字形是**比例字体**（proportional），数字宽度 > 字母宽度 → 数值列（金币、HP 倒计时、`12:34` 等）**逐位跳动、无法纵向对齐**。

**实测证据**（Godot 4.7.2 headless，16px）：

| 字体 | `"0123456789"` 宽 | `"ABCDEFGHIJ"` 宽 | 等宽？ |
|---|---|---|---|
| 当前（PingFang SC） | 92.0 | 100.0 | ❌ **否**（差 8px） |
| 候选（Menlo + CJK 回退） | 97.0 | 97.0 | ✅ **是**（完全一致，空格亦 97.0） |

**补充现状**：有 **4 处自绘文字绕过主题**，直接用 `ThemeDB.fallback_font`（引擎兜底字体，**不随主题变化**）：

| 位置 | 内容 |
|---|---|
| `scripts/entities/boss_tombstone.gd:20` | `Boss 刷新 %02d:%02d` |
| `scripts/entities/monster.gd:458` | `践踏预警` |
| `scripts/entities/monster.gd:470` | 精英 / Boss 名字（含数字） |
| `scripts/ui/map_canvas.gd:117` | 小地图 glyph |

## 3. 方案设计

### 3.1 墓碑跨图（G1 + G2）

**核心思路：把「刷新状态」从场景运行态提升到 `GameState`（跨场景存活），并用一个「世界时钟」驱动倒计时。**

#### ① 世界时钟（`GameState`）

```gdscript
## 世界时钟（秒）：仅「世界运行时」推进 —— 与 Consumable 冷却共用 _process 心跳，
## 因此面板打开不暂停（照常走）、Esc 暂停菜单时**冻结**（get_tree().paused 生效）。
## **落档**（拍板 Q1-B）：随存档序列化为 worldTime，读档后从该值续算
## —— 离线真实时间**不计入**（游戏内时钟语义，可预测）。
var world_time: float = 0.0

## 怪物点刷新状态表：key = "<map_id>#<monster_id>#<同种序号>"
##   → { "readyAt": float（到点 world_time）, "pos": Vector2（死亡处） }
## 仅记录**未刷新完成**的点；到点后自动清除（表不会无限增长）。
## **落档**（Q1-B）：序列化为 { key: { "readyAt": float, "pos": [x, y] } }。
var spawn_respawn: Dictionary = {}
```

`_process` 追加一行（与既有药水心跳同址，天然对齐暂停语义）：

```gdscript
func _process(delta: float) -> void:
	Consumable.tick(delta)
	world_time += delta          # ← 新增
```

新增 API（统一出口，便于测试直接驱动）：

```gdscript
func spawn_key(map_id: String, monster_id: String, ordinal: int) -> String
func mark_spawn_dead(map_id, monster_id, ordinal, respawn_time, pos: Vector2) -> void
func spawn_remaining(map_id, monster_id, ordinal) -> float   # >0 = 仍在墓碑；<=0 = 可刷新
func clear_spawn_state(map_id, monster_id, ordinal) -> void
func encode_spawn_respawn() -> Dictionary   # Vector2 → [x, y]（存档用）
func apply_spawn_respawn(raw: Variant) -> void   # [x, y] → Vector2（读档用）
```

#### ② `MonsterSpawner` 接线

| 改动 | 说明 |
|---|---|
| 新增 `var _map_id: String` | 在 `spawn_from_map()` / `spawn_from_specs(specs, map_id)` 时记录 |
| `_points` 增加 `key` 字段 | 生成时按 `(map_id, monster_id, 同种序号)` 计算**稳定 key**（不依赖数组下标 → 数据加减点不错位） |
| `_spawn()` 前先问状态 | `remaining = GameState.spawn_remaining(key)`；**`> 0` 则不生成怪物，只建墓碑 marker**（位置取 `spawn_dead_pos[key]`） |
| `_on_monster_died()` | 改为 `GameState.mark_spawn_dead(key, respawn_time, 死亡位置)` + 建墓碑 |
| `_process()` | 已死亡点：`remaining = GameState.spawn_remaining(key)` → 更新墓碑显示；`<= 0` → `_spawn()` 并 `clear_spawn_state` |
| 移除 `p.timer += delta` | 倒计时改由**全局 `world_time`** 统一驱动（不再有第二套时钟） |

**效果**：

```
图 A 击杀 Boss（respawnTime=300）
  └─ GameState: spawn_respawn_at["corruption_source#boss_corrupted_beast#0"] = world_time + 300
  └─ 墓碑显示倒计时

切图 → 图 B（世界时钟继续推进，因为 GameState._process 不随场景重载而重置）
  └─ 图 A 状态表仍在 GameState 里 ✅

切回图 A
  └─ Game._ready → spawn_from_map → _spawn()
      → remaining = 300 - 已流逝时间（>0）→ **不生成 Boss，在 spawn_dead_pos 处重建墓碑** ✅
      → remaining <= 0（时间到）→ 正常生成 Boss ✅
```

**关键点：`world_time` 由 `GameState._process` 推进，而 `GameState` 是 Autoload —— 切图重载的是 `Game.tscn`，不是 `GameState`。所以时钟跨图连续。** ✅

#### ③ 墓碑位置（G2）

- 位置随状态表一并持久化（`spawn_respawn[key].pos`），**不改 `maps.json`**。
- Boss 首次生成仍走随机位置（现状不变）；死亡后位置固定 → 跨图回来墓碑与重生**同在死亡处**，不会"漂移"。
- ⚠ 备用选项：给 `bossSpawn` 加固定 `cell`（Boss 固定巢穴）—— 属**玩法改动**，本方案**不采用**，如需另议。

#### ④ 落档（拍板 Q1-B；存档 schema **6 → 7**）

| 位置 | 改动 |
|---|---|
| `SaveManager.CURRENT_SCHEMA` | `6` → `7` |
| `_collect()` | 追加 `"worldTime": GameState.world_time` + `"spawnRespawn": GameState.encode_spawn_respawn()` |
| `_migrate()` | 追加 `if v < 7: data.worldTime = 0.0; data.spawnRespawn = {}`（旧档补默认，不报错） |
| `apply_to_game_state()` | `GameState.world_time = maxf(0.0, float(data.get("worldTime", 0.0)))` + `GameState.apply_spawn_respawn(data.get("spawnRespawn", {}))` |
| `_is_valid_save()` | 追加校验：`worldTime` 非负有限数；`spawnRespawn` 为字典且每项含合法 `readyAt`（数）与 `pos`（长度 2 的数对）。**宽松容错**：不认识的 key 直接忽略，不因数据表变动而拒档 |

**落档语义（重要）**：

```
存档时：world_time = 1234.5s，墓碑 readyAt = 1400.0s（还剩 165.5s）
关游戏 → 隔 1 小时再读档
读档后：world_time = 1234.5s（从存档续算），剩余 = 1400.0 - 1234.5 = 165.5s ✅
        —— 离线真实时间**不计入**（游戏内时钟语义）
```

**为什么离线时间不计入**：① 语义可预测（"关掉游戏不推进世界"与暂停一致）；② 避免"隔天回来 Boss 早就刷了"这类反直觉结果；③ 无需引入绝对时间戳与作弊风险。**如需改为"离线也计时"，是另一个决策，本方案不做。**

`_is_valid_save` 对 `schemaVersion` 的校验范围会因 `CURRENT_SCHEMA` 提升自动放宽到 `0..7` → **旧档（v6）照常可读** ✅

### 3.2 等宽字体（G4）

**核心思路：新建独立的字体资源（单一源），主题与自绘脚本共同引用它。**

#### ① 新建 `assets/themes/mono_font.tres`

```gdscript
[gd_resource type="SystemFont" format=3]

[sub_resource type="SystemFont" id="SystemFont_cjk"]      # 中文回退（保持原字体链）
font_names = PackedStringArray("PingFang SC", "Hiragino Sans GB", "Heiti SC", "STHeiti",
	"Microsoft YaHei", "Noto Sans CJK SC", "Source Han Sans SC", "WenQuanYi Micro Hei", "sans-serif")

[resource]
# ① 主字体：等宽（macOS = Menlo，Windows = Consolas，Linux = DejaVu Sans Mono）
font_names = PackedStringArray("Menlo", "SF Mono", "JetBrains Mono", "Consolas",
	"DejaVu Sans Mono", "Courier New", "monospace")
# ② 缺字回退到 CJK 字体（中文 / 符号 → PingFang SC）
fallbacks = Array[Font]([SubResource("SystemFont_cjk")])
```

**实测结论**（§1.2）：`fallbacks` 链有效；英数空格**完全等宽**；中文/「刷」「你」**有字形覆盖**。

**为什么是「等宽主字体 + CJK 回退」而不是反过来**：Godot 的 `fallbacks` 语义是「主字体缺字时才回退」。若主字体是 CJK 字体（本身含拉丁字形），则永远不会回退 → 数字仍是非等宽。必须**主字体只含拉丁**，中文才会落到回退链。

#### ② 主题引用

`default_theme.tres` 的 `default_font` 改为 `ExtResource` 指向 `mono_font.tres`，`default_font_size` 保持 16（**不改字号**）。

#### ③ 自绘 4 处同步（G4）

| 文件 | 改动 |
|---|---|
| `boss_tombstone.gd` | `ThemeDB.fallback_font` → `preload("res://assets/themes/mono_font.tres")`（常量） |
| `monster.gd` ×2 | 同上 |
| `map_canvas.gd` ×1 | 同上（glyph 多为符号 → **须实测字形**，见 §5 R-c） |

### 3.3 背包数量角标（G3）

**核心思路：把 `HotbarSlot` 已验证的范式下沉到 `ItemSlot`，用属性 setter 让所有面板零改动生效。**

#### ① `ItemSlot` 增加数量角标

```gdscript
var item: Dictionary = {}:
	set(value):
		item = value
		_refresh_count()        # 所有面板「赋值即生效」，无需逐处调用

var _count: Label

func _ready() -> void:
	_count = Label.new()
	_count.set_anchors_preset(Control.PRESET_FULL_RECT)
	_count.horizontal_alignment = HORIZONTAL_ALIGNMENT_RIGHT
	_count.vertical_alignment = VERTICAL_ALIGNMENT_BOTTOM
	_count.add_theme_font_size_override("font_size", 11)
	_count.add_theme_constant_override("override", 2)   # outline_size，深底深字也清晰
	_count.mouse_filter = Control.MOUSE_FILTER_IGNORE
	add_child(_count)
	_refresh_count()

func _refresh_count() -> void:
	if _count == null:
		return                       # _ready 前赋值 → 守卫
	_count.text = _count_text()

func _count_text() -> String:
	if item.is_empty() or not ItemUtil.is_stackable(item):
		return ""
	var n := int(item.get("count", 1))
	return str(n) if n > 1 else ""   # 阈值见 §4 Q3
```

**为什么用 setter**：`InventoryPanel._refresh()`、`WarehousePanel._rebuild_grid()` 现有写法都是 `b.item = it` —— setter 让**两处面板零改动**自动获得角标；托盘（装备）因不可堆叠自动不显示。

#### ② 覆盖范围

| 面板 | 是否显示 | 说明 |
|---|---|---|
| 背包（`InventoryPanel`） | ✅ | 药品 / 材料 / 任务物显示数量 |
| 仓库（`WarehousePanel`） | ✅ | 同上（自动生效） |
| 出售托盘（`ShopPanel`） | — | 只收装备（`Shop.can_sell`），不可堆叠 → 自动为空 |
| 快捷栏（`HotbarSlot`） | ✅ 已有 | 不改动 |

### 9.4 实施中的两处偏差（记录在案）

1. **JSON 往返精度**：`readyAt = world_time + respawnTime`，其中 `world_time` 为逐帧累加的长小数；`JSON.stringify` 往返会丢浮点末位精度（**亚毫秒级、无害**）。故冒烟断言由「严格逐字段相等」改为**数值容差比较**（`is_equal_approx`），条目数 / key 集仍严格相等。存档语义不受影响（离线时间本就不计入）。
2. **既有 `boss_review_test` 适配**：其原用 `spawner._process(299)` 以 delta 手动推进倒计时；改为世界时钟后该调用不再生效 → 已改为驱动 `GameState.world_time`（读 `readyAt` 后 ±1s），测试保持全绿。
