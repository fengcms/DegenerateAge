# 四紫升紫：可行性与实施方案

> 状态：方案待确认，尚未修改产品规则或游戏代码。依据 2026-10-20 的仓库现状。

## 一、需求与结论

玩家希望在铁匠处投入四件**同一十级档**的紫色装备，换取一件**高一档、随机部位**的紫色装备；界面沿用“四金合紫”的四格材料区、背包拖入和“随机放入”。目的是为低档紫装提供持续消耗出口。

**结论：合理且可实现，建议作为独立的第四项铁匠服务。**现有系统已具备四件材料预选、档位判断、随机部位生成、交易前重核及产物落袋能力，主要工作是增加一种规则模式并接入界面。它与现有“四紫定向”的定位清楚：前者牺牲部位确定性换取**升一档**，后者保留**同档**并指定部位。设计上必须限制顶档、保护 12 星材料，并明确“随机放入”仅预选、不立即消耗。

## 二、现状证据与差距

| 位置 | 当前事实 | 对新功能的影响 |
|---|---|---|
| `docs/产品文档/05-装备与背包系统.md` §5.13 | 四金合紫取输入最低档，随机部位；四紫定向要求同档，指定部位；二者都产出重新随机词条的 0 星紫装且不另收费 | 新模式需单独定义“同档输入、下一档输出、随机部位”，不能复用四金的混档降档规则 |
| `scripts/systems/equipment_fusion.gd` | `plan_four()` 只允许 `GOLD_TO_PURPLE` / `PURPLE_TARGET`；`random_materials()` 已能从 0 星、未收藏、同档装备中随机预选四件；`make_output()` 可按档位和部位造紫装 | 扩展模式与目标档计算即可，不需新建装备生成器 |
| `scripts/systems/item_factory.gd` | `suit_start()` 以穿戴等级按十级归档；61 级以上使用第 51 套型号生成动态实例；实例等级上限 9999 | 51—60 → 61—70、61—70 → 71—80 均有现成生成路径；顶档必须先检查 |
| `autoload/game_state.gd` 的 `forge_equipment()` | 服务端式重核实例快照、生成并验证产物、先确定背包落点再扣材料；只有四金模式会随机选部位 | 新模式必须纳入模式白名单与随机部位分支，保持失败不扣料 |
| `scripts/ui/equipment_fusion_panel.gd`、`scripts/ui/blacksmith_panel.gd` | 四金和四紫共用四格工作台及双面板交互；菜单目前只有三项合成服务，部分标题和预览用模式二选一判断 | 需要补新标题、提示、材料过滤、随机预选、预览与菜单入口，避免落入保星分支 |

以上是代码和文档核查结论，尚未进行新模式运行实测；本方案中的收益与操作成本属于设计推演。

## 三、建议确定的产品规则

| 项目 | 建议口径 |
|---|---|
| 材料 | 背包中的四件 `legendary` 紫装，按**装备实例穿戴等级**归档，四件必须同档；部位可不同，可四件完全同部位。收藏件、非装备、重复实例不能投入。穿在身上的装备先脱下，维持现有四件合成的背包材料规则。 |
| 星级 | 手动可投入 0—11 星紫装；**12 星紫装禁止投入**，与四紫定向的保护一致。投入 1—11 星时首次点击只显示“星级将消失”的确认，第二次才结算。随机放入只选 0 星、未收藏材料。 |
| 产物 | 输入档起点 `T`，输出档起点固定 `T + 10`；从 `Equipment.slot_kinds()` 的十种装备类型中**等概率**随机一种，生成该档全新的紫色 0 星装备，属性和词条重新随机，不继承材料的部位、星级、词条或评分。没有指定部位、保底与重掷功能。 |
| 等级门槛 | 不按玩家当前等级禁止合成；产物暂时穿不上时在预览中提示。由于部位随机，其实际穿戴等级是目标档起点加部位偏移，预览应写“产物档位 X—Y；随机部位；可能暂时无法穿戴”，产出后显示准确需求等级。 |
| 成本与失败 | 首版仅消耗四件材料，不另收金币，沿用四金 / 四紫既有定价；合成失败不吞材料。若未来经济监测显示升级过快，再统一调整配方或额外费用，避免本次同时改动多套经济规则。 |
| 档位上限 | 目标档必须能为**所有可能的随机部位**生成有效物品。最高可用输入档为 9971—9980，升至 9981—9990；输入 9981—9990 时下一档会是 9991—10000，应在预览阶段直接拒绝，不能等随机出错。 |

例如，四件穿戴等级分别为 61、63、67、70 的紫装属于 61—70 档，合成一件 71—80 档随机部位紫装；61 档混一件 71 档应提示“必须同档”。51 档四件升到 61 档。随机出的 71 档武器可能要求 71 级，项链可能要求 80 级，取决于部位偏移，并非“每件材料的等级直接 +10”。

## 四、交互方案

1. 铁匠菜单增加“**四紫升紫**”，说明文案写清“四件同档紫装 → 高一档随机部位紫装，0 星，词条重随机”。保留“四金合紫”“四紫定向”“保星升级”的原入口。菜单合成组继续两列：第一行放四金、四紫定向；新服务单独占下一行，保星仍独占一行。窗口较矮或界面 200% 时通过已有滚动区访问，不压住底部离开按钮。
2. 进入后沿用四金工作台：背包与工作台并排，窄窗口上下排；四格可拖入或撤出材料，背包原格显示“已选”，关闭不扣料。无目标部位下拉框。
3. “随机放入”从至少有四件合格 0 星紫装的档中随机挑一个档，再无放回抽四件；只**替换预选**，玩家仍需点“装备合成”。没有合格组合时保持原预选并说明原因。可考虑在材料格上方展示“当前材料档：61—70”，减少误放不同档的试错。
4. 预览固定显示“61—70 → 71—80 · 部位随机 · 紫色 0★ · 词条重随机”；选入带星材料时再加“原星级不会继承”。结果提示最终部位和穿戴等级。默认结果不承诺评分高于现有穿戴，因为部位与词条都随机。
5. 连续点击、背包整理、材料转移、收藏状态改变或关闭重开都应在最终确认时重新核对实例；任何校验失败均保留现存背包与装备，不生成产物。成功后四件变一件，产物落在被消耗材料腾出的背包格。

## 五、经济影响与风险

- 每次交易消耗四件紫装、生成一件紫装，装备存量净减少三件，符合“消耗低档紫装”的目的。若靠该功能连续升 `n` 档，单件目标产物理论上至少需 `4^n` 件同起点材料，跨档增长很快，不能用来廉价直通许多档。
- 当前代码有十种装备类型；若各类型等概率，指定部位一次命中的概率为 **1/10**。只看这一功能，从同一输入档追求某一种下一档部位，期望约四十件该档紫色材料；实际掉落速度、其他合成路线和玩家已有材料会改变耗时，不能据此承诺“需刷多少只 Boss”。
- 它允许玩家在较低地图先合出下一档装备，但现有穿戴等级门槛仍生效。真正的平衡风险是大量紫装积累时，新档装备获取节奏可能早于去新地图刷 Boss。首版建议不加额外等级门槛，验收时记录实际紫装来源、合成次数和目标档穿戴时点，再决定是否调整材料数或费用。
- 12 星保护避免玩家误把高投入装备当肥料；1—11 星二次确认仍允许玩家自愿回收低档升星件。若将来要支持 12 星回收，应先给出独立的保星或明确损失方案，不在本功能中暗含。
- 性能成本很小：随机放入扫描一次背包并分档；单次确认核验四个实例、检查十个部位模板、生成一件装备。仅在玩家交互时运行，没有逐帧处理、新贴图或额外存档字段。

## 六、技术实施顺序

1. **规则层**：在 `equipment_fusion.gd` 增加独立模式，例如 `PURPLE_UP_TIER`。四件紫装沿用现有质量、收藏、唯一性与同档约束；目标档改为 `T + ItemFactory.TIER_SPAN`；验证目标档不超过安全上限，且十种部位都有可生成型号。随机预选扩展为同档 0 星紫装。新模式与定向合成共用紫色材料限制，但不共用“指定部位”要求。
2. **交易层**：`GameState.forge_equipment()` 接纳新模式，并像四金模式一样在规则通过后随机选择部位；保留快照重核、产物有效性校验、背包落点预判和一次性扣料。不改保存结构：产物仍是现有普通装备实例。
3. **界面与文案**：铁匠菜单加入口；工作台四格、随机按钮与无目标下拉框模式；补齐紫装单格验证、升档预览、顶档和未达穿戴等级提示；新增本地化键并更新菜单的可滚动布局。
4. **产品与测试同步**：确认后修改 `docs/产品文档/05-装备与背包系统.md` §5.13 与相关帮助文案。扩展 `equipment_fusion_rule_test.gd`、`equipment_fusion_transaction_test.gd`、`equipment_fusion_ui_test.gd`，保留原三模式的断言而非放宽；UI 服务数应由三项更新为四项。每个可用关键节点按仓库规则独立提交。

## 七、验收口径

- 规则：同档四紫 51→61、61→71 成功；混档、金装/低品质、收藏、重复实例、12 星紫装、无效等级、9981 档继续升档均明确失败；手动投入 11 星会二次确认，产物始终 0 星。
- 交易：固定随机种子覆盖十种部位中的代表项，输出档位、质量、实例合法性和存档往返均正确；材料快照过期、重复提交、背包落点不可用等失败路径不消耗、不复制。测试使用隔离存档，不覆盖玩家槽位。
- UI：拖入、撤出、随机预选、关闭、重开均不改变材料；“随机放入”只预选；目标部位选择器隐藏；预览目标档、随机部位及星级损失准确。100% 与 200% 界面、宽/窄窗口下四格、确认按钮和菜单入口完整可见或可滚到，背包与工作台不重叠。
- 经济：用实际存档副本统计低档紫装库存和紫装来源，试玩验证该功能能消耗积压材料，但不使新地图 Boss 掉装失去价值；若未实测，不宣称已经达到特定紫装消耗速度。

**建议实施口径**：四件同档、0—11 星紫装；升且只升一档；随机部位与词条，产物 0 星；随机放入限 0 星未收藏件；不额外收费；12 星禁投。该口径与现有铁匠规则最一致，且不引入新的存档或数值配置。
