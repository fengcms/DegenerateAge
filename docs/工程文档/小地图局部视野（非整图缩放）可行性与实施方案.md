## 0. 结论摘要

**可以实现，且不需要动寻路算法、存档或大地图。** 但这不是"改一个缩放系数"，而是**把小地图的视口从「整图适配」改成「跟人平移的局部视野」**，由此引出三处必须一并解决的耦合点：

| 编号 | 耦合点 | 现状为什么没问题 | 改局部视野后为什么必须处理 |
|---|---|---|---|
| **A** | 视野跟随 | 投影由 `_world_rect` 一次算定，人物移动不动视口 | 视口要跟人走 → 底图与标记每 0.2s 都要整体平移 |
| **B** | 圆形裁剪 | 整图缩小时地图轮廓天然落在圆内，**全仓没有裁剪** | 放大后地形格、虚线、终点环必然越出圆边，会糊在 HUD 框上 |
| **C** | 底图缓存语义 | `map_canvas_cache_test` 断言「人物移动**只重绘 overlay**，不重建底图」 | 朴素实现会让底图每帧重建（ch2 已探索最多 2.8 万格），性能与既有判据双输 |

推荐架构（§3 方案 A）能把 A/B/C 一次性解决：**把「投影」拆成「地图锚定的标准坐标」+「跟随节点位移」**，人物移动只改节点 `position`，底图网格缓存完全不失效；圆裁剪用一层材质 `discard` 统一解决。

**工作量预估**：改动集中在 [map_canvas.gd](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/ui/map_canvas.gd)（1 个文件为主）+ 1 个新 shader + 1 处 HUD 层级/材质配置；隔离测试新增 1 个场景、既有 `MapCanvasCacheTest` 需按新语义补断言。不新增存档字段。

## 1. 需求复述与判据

**需求原文**：小地图圆圈内不再显示大地图的整图缩放，而是"适当缩小"的**局部视野**；看全景必须打开大地图。

**验收判据**：

| 编号 | 判据 |
|---|---|
| A1 | 小地图圆内只显示以人物为中心（或视野窗口内）的**局部区域**，不再出现整张地图轮廓 |
| A2 | 局部视野下的**放大倍数明显大于**现在（现在每格约 2.8 px，目标是能看清道路与地形格走向） |
| A3 | 大地图**完全不变**：仍是整图全景 + 点击寻路 + 虚线/金环 |
| A4 | 圆内**无内容越出圆边**（地形格、虚线、标记都不糊到 HUD 框上） |
| A5 | 人物移动时小地图**平滑跟随**，不闪、不抖、不掉帧（沿用 0.2s 节流） |
| A6 | 不新增存档字段；不改寻路算法、不改大地图交互 |

## 2. 现状勘查

### 2.1 小地图与大地图共用同一个绘制源

`MapCanvas` 同时充当两处视口：HUD 右上角 `MapPanel/Minimap`（164×164，`minimap = true`、`ornamental_frame = true`，以及 `map_big_panel.gd` 运行时 `MapCanvas.new()` 的 `minimap = false`）。

绘制分两层（[map_canvas.gd](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/ui/map_canvas.gd)）：

- **静态底图**（`_draw()`，含 `background_draw_count` 计数）：圆形/矩形底、地图外框、已探索地形网格（`FlatTileMesh` 合批）、营地专用公路等。
- **动态层**（子节点 `_overlay` 的 `draw` 信号 → `_draw_markers()`）：NPC/出口/车夫/任务/Boss 标记、玩家标记、以及 2026-10-17 新增的自动寻路虚线 + 终点金环。

### 2.2 投影：一次算定的整图适配

```gdscript
# _ensure_projection()
var available := Vector2.ONE * (minf(size.x, size.y) - 24) if minimap else size - Vector2(40, 40)
_scale = maxf(0.001, minf(available.x / _world_rect.size.x, available.y / _world_rect.size.y))
# _project()
return size * 0.5 + (world - _world_rect.get_center()) * _scale
```

→ 视口恒为「整张地图」，人物位置**不参与**投影，只有玩家标记在动。小地图可用直径 140 px，营地 `worldRect` 3200×1800 时 `scale ≈ 0.0438`，**1 格 ≈ 2.8 px**——这正是"整图缩小"的观感来源。

### 2.3 无任何裁剪

全仓检索确认：**没有 `clip_contents`、没有蒙版纹理用于地图**。整图模式下不需要；局部视野下必需（判据 A4）。

### 2.4 已有的圆裁剪先例（好消息）

[assets/ui/portrait_circle.gdshader](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/assets/ui/portrait_circle.gdshader) 已经是"UV 圆形 discard"范式（用于圆形头像）。本项目已有此约定，局部视野的圆裁剪可直接沿用同一思路，不引入新范式。

### 2.5 `mapScale` 与小地图无关（避免误判）

设置项「地图显示大小」`mapScale`（0.8–2.0）是**世界相机的 `zoom`**（[settings_runtime.gd](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/systems/settings_runtime.gd#L352-L354)、[game_state.gd](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/autoload/game_state.gd#L204)），**不参与小地图投影**。所以本需求无法复用该键，也不应顺手改它。

### 2.6 越界标记的现有判据已"语义失效"

`_marker_visible()` 在 `minimap` 模式下对 `exit` / `carter` 用的是**世界相机可视矩形**（[map_canvas.gd#L194-L201](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/ui/map_canvas.gd#L194-L201)），其余按迷雾。改局部视野后，"是否在相机可视区内"与小地图圆内可见性**不再是同一件事**，必须改为按小地图自身视野判定（→ D3）。

### 2.7 网格构造器只吃四边形

`FlatTileMesh.add_quad()` 断言 `points.size() == 4`（[flat_tile_mesh.gd#L18-L19](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/systems/flat_tile_mesh.gd#L18-L19)）。若走"CPU 把多边形裁到圆内"的路线，裁完是 N 边形，需要另写一个扇形三角化构造器 → 这是 §3 方案 B 的额外成本。

## 3. 三种实现路径

### 方案 A（推荐）：地图锚定坐标 + 跟随节点位移 + 材质圆裁剪

**核心改动**：把 `_project()` 拆成两级——

1. **标准坐标（canonical）**：`canonical(world) = size*0.5 + (world - map_center) * zoom`，顶点、标记、虚线全部按它计算，**与人物位置无关**。
2. **跟随位移**：新建 `_terrain` 节点（承载缓存的静态网格）与既有 `_overlay` 同挂在 `MapCanvas` 下，每 0.2s 只需 `position = -(player_pos - map_center) * zoom`。
3. **圆裁剪**：给 `MapCanvas` 挂一个 canvas_item 材质（`discard` 圆形外的片元），`_overlay.use_parent_material = true`；仅 `minimap = true` 时启用，大地图不受影响。

**为什么这是最优解**：

- **底图网格缓存完全不失效**：人物移动只改节点 `position`（GPU 平移），不触发 `_draw()` → `background_draw_count` 语义与 `map_canvas_cache_test` 的「移动只重绘 overlay」断言**继续成立**（大地图 `minimap = false` 时位移恒为 0，行为与今天逐像素一致）。
- **裁剪一处生效**：地形、标记、虚线、金环共用同一层材质，不需要为每种绘制各写裁切逻辑（也不需要按 §2.7 改网格构造器）。
- **大地图零风险**：`minimap = false` 时 zoom 走原整图适配、位移为 0、无材质 → 现有大地图与 2026-10-17 的虚线功能不受任何影响。

**代价与风险**：

- 材质 `discard` 依赖片元内 `VERTEX` 的坐标语义，**必须实测确认**（实施第一步先做一个 164×164 的小样验证；若语义不符，退化为方案 C）。
- 小地图"视野跟随"后，`refresh()` 里"位置变化才重绘 overlay"的守卫阈值需要跟着视野走：人物移动**小于 1 格**时不必重算标准坐标，避免抖动（沿用 0.2s 节流即可，无需新机制）。
- 视野平移到地图外会露出空底 → 需拍板 D5（建议夹紧）。

### 方案 B：每 0.2s 重建"视野内局部网格"

只统计视野矩形内的已探索格，重建一份小网格。**不推荐**：需要自己写圆裁剪的多边形三角化（§2.7），且每次跟随都要重建网格，`background_draw_count` 语义被迫改写（C 点），换来的只是"不引入材质"。

### 方案 C：SubViewport + 圆形蒙版纹理

把小地图内容渲染进 164×164 的 `SubViewport`，再用带 [portrait_circle.gdshader](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/assets/ui/portrait_circle.gdshader) 的 `TextureRect` 显示。裁剪最彻底、最不依赖引擎细节，但引入第二棵渲染树与输入穿透处理，且与现有 HUD 结构耦合更重。**作为方案 A 的兜底**。

## 4. 视野尺度建议（量化）

小地图可用直径 140 px。以"每格在圆内的像素宽度"衡量（格宽 64 px）：

| 视野直径（格） | 圆内每格像素 | 相对现状倍数 | 观感 |
|---|---|---|---|
| 14 格 | ≈ 10.0 px | ≈ 3.6× | 很贴近，只看脚下几条路，容易失去方向感 |
| **18 格（建议）** | ≈ 7.8 px | ≈ 2.8× | 能看清当前通路走向与邻近岔路，同时保留"我在哪一段" |
| 24 格 | ≈ 5.8 px | ≈ 2.1× | 偏全景，放大感不强 |

**建议采用固定格数视野（而非固定倍数）**：这样**不同大小的地图小地图观感一致**，也天然避免"大地图反而缩得更小"的问题（现状 `scale = available/worldRect` 使大地图每格更小）。

## 6. 影响面与风险

| 影响对象 | 影响 | 处理 |
|---|---|---|
| 大地图（`minimap = false`） | 无（同文件但走独立分支） | 保持零改动，`MapCanvasCacheTest` 中大地图相关断言不动 |
| [map_canvas_cache_test.gd](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/tests/map_canvas_cache_test.gd) | 该测试用的是 `minimap = true`，"移动只重绘 overlay" 断言在方案 A 下**仍成立**（位移不改 `_draw()`） | 追加"位移量随人物变化"的新断言 |
| HUD 小地图外观 | 圆内内容变局部；玩家标记恒在圆心附近 | 实机确认 4 种界面倍率下的观感与线宽 |
| 性能 | 每 0.2s 只改 2 个节点 `position`（方案 A），无网格重建 | 沿用 `MapPerformanceTest` / `MapRenderBenchmark` 做前后对照 |
| 迷雾与探索 | 局部视野天然只见已探索区域；未探索处仍为底图底色 | 无需改 `Fog` |
| 自动寻路虚线（2026-10-17 功能） | 小地图侧改为圆内截断（D4）；大地图侧不变 | 现有 `MapRouteOverlayTest` 断言"路线纳入重绘守卫"仍成立 |

**风险清单**：

1. 材质 `discard` 的坐标语义未经验证 → 实施第一步做 164×164 小样，失败即切方案 C（半天内可判定，尚无代码沉没成本）。
2. 圆边裁剪后地图轮廓不再可见，玩家可能"不知道地图边界在哪" → 建议圆内保留地图**外框线**在视野内时照常绘制（外框本就按标准坐标画，视野内可见部分自然显现）。
3. 视野夹紧（D5）与"恒锁人物居中"（D2）在角落会同时生效 → 角落处人物偏离圆心，需实机确认可接受度。

### 10.3 三处耦合点的实际解法（与 §3 方案 A 的差异）

| 耦合点 | 实际实现 |
|---|---|
| **A 视野跟随** | 位移不写进投影公式，而是写进内容层节点的 `position`：`_terrain.position = _overlay.position = (地图中心 − 视野中心) × 倍率`。因此底图渲染命令**不失效**，`MapCanvasCacheTest` 的「移动只重绘 overlay」断言继续成立 |
| **B 圆形裁剪** | 材质挂在**内容层**（`_terrain` / `_overlay`）而不是 `MapCanvas` 本体：挂本体的话，圆盘底盘自身也会被裁。裁剪半径取「圆盘半径 − 1px」，让圆盘自身画出的边缘成为可见边界，避免圆盘内接多边形与精确裁剪圆之间的透明缝 |
| **C 底图缓存语义** | `_draw_terrain()` 承接原 `_draw()` 的全部地图内容，`background_draw_count` 随之移到该回调；位移只改 transform，计数不变 |

一处与文档原方案的偏差：文档原写 `_overlay.use_parent_material = true`，实现改为**每个内容节点各挂同一份 `ShaderMaterial`**。原方案要求材质挂在 `MapCanvas` 上，而 `clip_center` 是节点**局部坐标**，父节点与子节点的局部原点相差一个跟随位移（本图可达约 90px），共用一份材质会算错圆心。

### 10.4 已知取舍

1. **视野夹紧与居中冲突**：地图小于视野（2×半径）时退化为居中；贴边时人物会偏离圆心（D2① + D5② 的必然结果），需实机确认可接受度。
2. **`discard` 边缘无抗锯齿**：`discard` 是二值裁剪，圆边缘可能出现 1px 锯齿；若实机观感不佳，可改为方案 C（SubViewport + 圆蒙版）或把裁剪半径再内收 1px 让圆盘边缘完全遮挡。
3. **圆内每格像素 ≈ 8.8px**（文档 §4 按 140px 直径估的是 7.8px）。实现以圆盘直径（`min(边) − 4`，再内收 1px）为基准，故比建议值略大，仍落在「18 格」这一档。
4. **小地图不再显示地图轮廓全貌**：视野内可见的外框线自然显现，但「地图边界在哪」只剩打开大地图才能确认，这是本需求的本意。
