# 启动失败诊断：资源导入缓存未就绪引发的脚本连锁编译失败

> 诊断日期：2026-10-17　现象：打开 Godot 加载项目后界面卡顿，多次启动游戏均不成功，控制台无明显输出
> 关联：本次诊断仅做勘查与验证，未修改任何工程文件，也未产生代码提交。

---

## 1. 结论

**不是玩法或逻辑 Bug，而是资源导入缓存（`.godot/`）未就绪导致的"整局编译不通过"。**

一批新素材（wild/ash 地砖 3×3 扩充、汲灵幼虫八方向预览图集）在采集中/落地后，其 **导入产物尚未生成**，而脚本已用 `preload()` 引用了它们；`preload()` 解析失败沿依赖链扩散，进而引发全局标识符（autoload 与 `class_name`）的**连锁解析失败**，入口脚本无法编译，主场景构建中断 → 游戏起不来。

当前工程已恢复可用（见 §5 验证）。

---

### 2.3 一个旁证

把工程复制到临时目录（未带 `.godot` 缓存）后启动，复现出**同一类**大面积报错：

```
Identifier "Consumable"/"Inventory"/"Warehouse"/"Equipment"/"SettingsRuntime"/"HotbarConfig" not declared

```

说明：**当 `.godot` 的脚本/类名缓存未完整建立时，会成片出现"标识符找不到"，而不是只报某一个脚本。** 这正是本次启动失败的形态。

---

## 3. 根因链（逐步）

1. 脚本新增了对**新素材**的 `preload()`：`monster_directional_preview_art.gd:6` → `directional_preview_atlas.png`。
2. 运行游戏那一刻，该 PNG 的**导入产物**（`res://.godot/imported/**`）尚未生成 / `.godot` 缓存处于半成品状态 → Godot 判定资源"不存在"。
3. 编译错误沿依赖链扩散：`monster_directional_preview_art.gd` → `monster_appearance.gd` → 相关实体脚本。
4. 同一时刻 `.godot` 的全局类名与 autoload 注册表也未完整建立，于是进一步出现 `GameState` / `DataLoader` 等标识符解析失败。
5. 入口链路无法编译 → `Main` 场景构建中断 → **游戏启动失败**。

**触发器**：编辑器仍在扫描/导入新素材（现场扫描动作 474 项）时，就去启动游戏。

---

## 4. 为什么是"卡顿"与"没有输出"

| 现象 | 解释 |
|---|---|
| 界面卡顿 | 编辑器正在对数百个新素材做导入/重导入，且并行任务持续写入文件，反复触发文件系统重扫 |
| 控制台"没有输出" | 失败发生在**脚本编译阶段**，错误实际写在 `user://logs/` 与编辑器**输出面板**；用户当时看的是游戏窗口，所以"看不到" |

## 6. 处置建议

### 6.1 即时恢复

1. 先让编辑器的导入进度跑完（状态栏进度条结束）再启动游戏。
2. 若仍异常：关闭编辑器 → 删除 `.godot/` → 重新打开项目（触发全量重新导入）。

### 6.2 长期预防

- 新增**会被 `preload()` 引用**的素材时，务必先让编辑器完成导入、本地验证通过后再提交；提交必须同时包含 PNG 与 `.import`。
- **不要在编辑器扫描/导入进行中启动游戏**。
- 批量素材落地，尽量与引用它的脚本改动**分离提交**，缩小"半成品窗口"。
- 对地基/图集类引用，可考虑改为惰性 `load()` + 存在性兜底，避免**单个素材导入异常直接拖垮整局启动**。
