# 如意爆率与物品说明文案修正

整理日期：2026-10-17
状态：已实施（本轮修复）

## 1. 问题来源

玩家实测反馈三项：

1. **如意没有爆率**——按产品计划，如意应当只由 BOSS 掉落。
2. **很多物品仍提示「未实现」**（玩家举例提到随机券一类）。
3. **回城卷文本不对**——应描述为「回到最近的城市」。

三项均可在仓库内定位到确定性根因，其中①③为真实缺陷，②为文案口径缺陷（功能已接入但提示误导）。

---

## 2. 问题一：如意无爆率

### 2.1 现状链路

- 如意是升星材料，`data/runes.json` 定义四档（铁 +5% / 玉 +10% / 金 +15% / 钻石 +20%），四档均 `dropBossOnly: true`。
- 掉落结算入口 `Loot.roll(drop_table_id, rng, source_monster_id)`（[loot.gd](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/systems/loot.gd#L73-L87)）按 `runes.json` 的 `dropBossOnly` 校验来源怪物 `kind == "boss"`。
- 怪物死亡时以 `Loot.roll(table_id, null, monster_id)` 传入真实来源（[monster.gd](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/entities/monster.gd#L827)），因此「非 BOSS 不掉如意」的保护是生效的。

### 2.2 根因

`data/dropTables.json` 中**只有第一章 BOSS 表 `DT_Boss_L1` 含如意槽**：

```json
{ "kind": "rune", "chance": 0.3, "itemIds": ["rune_iron", "rune_jade"] }
```

其余 7 张 BOSS 表全部缺失该槽：

| 掉落表 | 对应章节 | 如意槽 |
|---|---|---|
| `DT_Boss_L1` | 第一章（腐化巨兽） | 有（30%，铁/玉） |
| `DT_C2_Boss` | 第二章 | **缺失** |
| `DT_C2_Boss_Slag` | 第二章（炉渣吞噬者） | **缺失** |
| `DT_C2_Boss_Final` | 第二章（井心） | **缺失** |
| `DT_C3_Boss` | 第三章 | **缺失** |
| `DT_C4_Boss` | 第四章 | **缺失** |
| `DT_C5_Boss` | 第五章 | **缺失** |
| `DT_C6_Boss` | 第六章 | **缺失** |

后果：玩家离开第一章后，任何 BOSS 都不再产出如意，升星材料断供。

### 2.3 产品口径依据

- `docs/产品需求梳理.md` §6.16.2：四档如意「仅 Boss 掉落，不可购买」。
- `docs/工程文档/18-M6-0战利品持久化与装备雨实施方案.md` 决策 A：「金 / 钻石如意定位为**后续章节** Boss 产出，第一章仅掉铁 / 玉」。
- 第三～六章各 `05-装备奖励与成长.md`：「如意**沿当前已实施 Boss 规则接入，不改变概率**或额外添加装备件数」。

即：第二～六章 BOSS 应沿用已实施的第一章规则（**30%，铁/玉 各 50%**），金/钻石仍按决策 A 留给更后续章节。

### 2.4 修复

给 7 张第二～六章 BOSS 表逐张追加与第一章一致的如意槽：

```json
{ "kind": "rune", "chance": 0.3, "itemIds": ["rune_iron", "rune_jade"] }
```

同时在各表 `desc` 追加「含如意槽」以便配置自述与复核。

### 2.5 遗留（不在本轮范围）

`rune_gold` / `rune_diamond` 仍无任何投放条目（`docs/产品文档/当前游戏技能装备与物品全量清单.md` 已登记该现状）。按工程 18 决策 A，二档定位为后续章节 Boss 产出，本轮**不新增**，待后续章节制作单再落地。

## 3. 问题二：物品提示「未实现」

### 3.1 现状链路

背包格非装备物品的悬停提示统一走 `InventoryPanel._bag_tooltip()` → `_non_equip_tooltip()`
（[inventory_panel.gd](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/ui/inventory_panel.gd#L390-L444)）。

### 3.2 根因

`_non_equip_tooltip()` 只对 `potion`、`quest`、`misc_town_scroll`、`misc_random_ticket` 四类显式分流，
**其余全部落到兜底分支** `ui.inventory_panel.p036 = "杂项物品，暂未开放使用（M4）"`。

被兜底误命中的实际物品：

| 物品 | 实例 kind / itemId | 实际状态 | 兜底误报 |
|---|---|---|---|
| 铁/玉/金/钻石如意 | `kind = "rune"` | 升星材料，已可用 | 「暂未开放使用（M4）」 |
| 复活卷 | `misc` / `misc_revive_scroll` | 死亡面板已接入 | 「暂未开放使用（M4）」 |
| 灵能碎片等任务收集物 | `misc` / `spirit_shard`（`useType = quest`） | 任务收集物 | 「暂未开放使用（M4）」 |
| 烟花 | `misc` / `misc_firework` | 确未接入 | 文案本身合理，但「（M4）」为内部分期口径泄漏 |

两个附加问题：

- 兜底文案把**内部分期编号「M4」**写进了玩家可见文本。
- 随机券本已有专用分支（`p035`），但分流用的是**硬编码 itemId**（`HotbarConfig.TOWN_SCROLL` / `RANDOM_TICKET`），
  新增同类杂项（如复活卷）必须再改代码；提示口径与数据表的 `useType` 字段脱钩。

### 3.3 修复

把 `_non_equip_tooltip()` 改为**按 `miscItems.useType` 数据驱动分流**：

| `useType` | 提示键 |
|---|---|
| `townPortal`（回城卷） | `p034` |
| `randomTeleport`（随机券） | `p035` |
| `revive`（复活卷） | `p039`（新增） |
| `quest`（任务收集物） | `p033` |
| 其它 / 未知 | `p036`（改写） |

并新增 `kind == "rune"` 专用分支（`p038`，含成功率加成与投入方式），兜底文案去掉「（M4）」。

## 4. 问题三：回城卷文本

### 4.1 现状与根因

回城卷真实行为是**回到当前地图所属安全城镇**（`MapService.safe_town_for`，见 [travel_item.gd](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/systems/travel_item.gd#L12-L35)），
但两处文案仍停留在「只写第一章」的旧口径：

- `data/miscItems.json` → `misc_town_scroll.desc`：「传送回安全区起始位置。」
  （该 `desc` 会在货郎购买面板经 `Shop.describe()` 展示。）
- `data/localization.json` → `ui.inventory_panel.p034`：「…从野外返回幸存者营地」。

「幸存者营地」是第一章安全城镇名，第二章起应为沉井镇等，文案与实际行为不一致。

### 4.2 修复

两处统一为**位置无关**表述：

- `misc_town_scroll.desc` → 「使用后回到最近的安全城镇。」
- `ui.inventory_panel.p034` → 「双击或拖到快捷栏使用；回到最近的安全城镇」
