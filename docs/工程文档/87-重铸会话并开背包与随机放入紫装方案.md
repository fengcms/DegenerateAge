# 87 重铸会话并开背包与「随机放入紫装」方案

> 需求来源：2026-10-21 用户提出「打开重铸面板的同时要打开背包面板」，并在精炼区加一个「随机放入紫装」按钮，自动从背包抓取紫装。
> 本文只做现状核对、方案设计与实施计划；拍板后再改代码。

## 1. 需求拆解

两个需求分别解决不同的摩擦点，但共用同一个「重铸会话」概念：

| # | 需求 | 玩家痛点 | 本质 |
|---|---|---|---|
| R1 | 打开重铸面板时自动打开背包 | 重铸目标可能来自穿戴槽，但**精炼材料只能从背包拖**；玩家要先按 I 开背包，再自己把两个窗口摆开不重叠 | 会话并开 + 布局 |
| R2 | 精炼区增加「随机放入紫装」 | 背包几百格，手动翻找 4 件紫装拖入非常繁琐；四紫升紫已有同类按钮，重铸没有 | 规则层选料 + 一键预选 |

两条都不改变重铸的结算口径：金币、锁定、精炼折算与「先掷后扣」全部沿用工程 86 的既有实现。

## 2. 现状核对

### 2.1 重铸面板目前是「孤立会话」

- [reforge_panel.gd](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/ui/reforge_panel.gd) 的 `set_open(true)` 只发 `EventBus.panel_opened("reforge")`，自己居中显示，**不通知背包**。
- 它的 `_on_panel_opened()` 仍是「任何其他面板打开就关闭自己」：
  ```gdscript
  if panel_id != PANEL_ID and visible:
      set_open(false)
  ```
  即使外部先打开背包，再开重铸也会把背包关掉；反过来先开重铸再按 I，重铸会被背包的 `panel_opened("inventory")` 顶掉。
- [game_state.gd](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/autoload/game_state.gd) 的 `panels_coexist()` 只给 `equipment_fusion` 开了与背包 / 人物的并开例外，`reforge` 不在其中。
- 背包的 `_on_panel_opened()` 同样按 `panels_coexist` 判断，因此两边都会互踢。

结论：R1 不是「顺手调用一下 `InventoryPanel.set_open(true)`」就能完事。直接调用还会出现：
1. 背包打开时发出 `panel_opened("inventory")`，重铸立刻自我关闭；
2. 两个面板都居中，1280×800 下重铸 520 宽 + 背包容宽会重叠；
3. 关闭顺序没有约定，容易只关一半。

### 2.2 四金合紫工作台已经跑通同一套范式

[equipment_fusion_panel.gd](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/ui/equipment_fusion_panel.gd) 是现成参照：

- 打开时发 `EventBus.fusion_mode_changed.emit(true)`；背包监听后**自动 `set_open(true)`** 并切到左半屏。
- `panels_coexist("equipment_fusion", "inventory")` 双向放行。
- `_resize()` 做宽屏左右并排、窄屏上下分区；宽屏下把背包 dock 到左侧，工作台 pin 到背包右侧。
- 背包在会话中按 I / Esc 会先发 `equipment_fusion_close_requested`，整场会话一起退出；工作台按 Esc 只关自己、背包保留。
- `EquipmentFusion.random_materials()` 是纯规则函数，UI 的「随机放入」只做预选，不动背包。

重铸应复用这套范式，而不是另造一套互斥规则。

### 2.3 随机放入的既有口径

四紫升紫的「随机放入」有两条明确约束（[equipment_fusion.gd](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/systems/equipment_fusion.gd)）：

- 只从**最低合格档**取，**高档紫装不被「省事」按钮吃掉**；
- 只取**0 星、未收藏、非目标**的装备。

精炼不能照抄「最低档优先」：精炼的折算规则是「低 1 档 0.5、低 2 档及以下 0.25」，4 件最低档可能只值 1.0 有效件数（下限 15%），玩家会觉得按钮给了他一个坏交易。因此精炼的选料轴要按**折算价值**重新设计，详见 §4。

## 3. R1 方案：重铸会话并开背包

### 3.1 会话信号

在 `EventBus` 增加与合成对称的一组信号：

```gdscript
signal reforge_mode_changed(active: bool)
signal reforge_close_requested()
```

`ReforgePanel.set_open()`：

- 打开：先发 `reforge_mode_changed(true)`，再发 `panel_opened("reforge")`；
- 关闭：发 `reforge_mode_changed(false)`，再清空锁定与精炼材料。

### 3.2 并开白名单

`GameState.panels_coexist()` 增加双向例外：

```gdscript
(opened_id == "reforge" and self_id == "inventory")
or (opened_id == "inventory" and self_id == "reforge")
```

`ReforgePanel._on_panel_opened()` 改成与合成工作台一致：

```gdscript
if visible and not GameState.panels_coexist(panel_id, PANEL_ID):
    set_open(false)
```

这样背包自己打开、玩家按 I、其他 NPC 面板打开都不会误踢重铸。

### 3.3 背包侧联动

`InventoryPanel`：

- 新增 `_reforge_active`；
- 监听 `reforge_mode_changed`：true 时切「工作台布局」并在未打开时 `set_open(true)`；false 时恢复普通布局；
- `set_open(false)` 时若 `_reforge_active`，先发 `reforge_close_requested`，保证按 I / Esc 是整场退出；
- 输入分支与 `_fusion_active` 平行：会话中按 I = 结束重铸会话，Esc 先关重铸再关背包；
- `_apply_trade_layout()` 的会话判据改为 `_trade_active or _fusion_active or _reforge_active`。

合成与重铸不会同时打开：重铸的 `_on_panel_opened` 会把合成踢掉，反之亦然。

### 3.4 布局

重铸面板新增 `_resize()`，直接复用合成工作台的几何算法：

- 逻辑视口 = `get_viewport_rect().size / SettingsRuntime.ui_scale_value()`；
- 宽屏（`视口宽 ≥ 背包宽 + 520 + 12 + 24`）：背包 dock 在中间偏左，重铸 pin 在背包右侧，两者作为一组居中；
- 窄屏：背包占上 48%，重铸占下 52%，均钉住不可拖；
- 监听 `settings_changed` 与 `get_viewport().size_changed` 重新布局。

1280×800（默认视口）下走宽屏分支：背包约 520 宽、重铸 520 宽、间距 12，左右并排后仍有余量；不需要玩家手动摆窗。

### 3.5 关闭语义

| 操作 | 结果 |
|---|---|
| 重铸面板 Esc / 关闭按钮 | 只关重铸，背包保留（与合成工作台一致） |
| 背包 I（会话中） | 整场退出：先关重铸，再关背包 |
| 背包 Esc 且重铸在最上层 | 整场退出 |
| 打开其他 NPC / 菜单面板 | 重铸与背包按既有互斥规则退出 |

不采用「关重铸就关背包」：玩家可能想接着整理刚重铸完的装备；合成工作台已经验证这个口径更顺手。

## 4. R2 方案：随机放入紫装

### 4.1 按钮位置与行为

- 精炼区标题行右侧一个次按钮，文案「随机放入紫装」，tooltip 写明「只从背包取未收藏、0 星、同档或更低档的紫装，替换当前 4 格」。
- 点击后**替换**当前 4 格预选（与四紫升紫的「随机放入」同口径），不打开确认框、不扣任何物品。
- 没有合法候选时不清空已有预选，只给反馈「背包里没有可自动投入的紫装」。
- 每次点击在候选池内重新随机，方便玩家刷出不同组合。

### 4.2 候选判据

与手动拖入共用 `Reforge.can_refine()`，再额外加三条自动投放约束：

| 判据 | 手动拖入 | 自动随机 | 理由 |
|---|---|---|---|
| `legendary` 紫装 | 必须 | 必须 | 精炼只收紫装 |
| 未收藏 | 必须 | 必须 | 收藏是玩家的保留意图 |
| 非目标本身 | 必须 | 必须 | 同一实例不能既当目标又当材料 |
| 在背包 | 必须 | 必须 | 穿戴 / 仓库件不参与 |
| `star == 0` | 允许任意星 | **只取 0 星** | 升星件是金币成果，不能一键烧掉；12★ 需手动投入 |
| 档位 | 允许更高档 | **只取目标同档或更低档** | 更高档紫装应留给穿戴与四紫升档，不能被「省事」按钮吃掉 |

「更高档不自动投」是刻意与手动能力不对称：手动仍可把 12★ 或高档紫装拖进去，那是玩家明确决策；自动按钮不做这种不可逆选择。

### 4.3 选料顺序（已拍板）

按折算价值从高到低选，但不碰更高档：

1. **同档 0 星**（1.0 有效/件）；
2. **低 1 档 0 星**（0.5 有效/件）；
3. **低 2 档及以下 0 星**（0.25 有效/件）；
4. 同档内随机、无放回；填满 4 格为止。

典型结果：

| 背包情况 | 自动放入 | 有效件数 | 未锁定词条下限 |
|---|---|---|---|
| 同档 ≥4 件 | 4 件同档 | 4.0 | 60% |
| 同档 2 件 + 低 1 档若干 | 2 同档 + 2 低 1 档 | 3.0 | 45% |
| 只有低 2 档 | 4 件低 2 档 | 1.0 | 15% |
| 只有更高档 | 不放入，给提示 | — | — |

为什么不选「最低档优先」：精炼的折算让低档料价值极低，最低档优先会稳定给出 15% 下限，按钮看起来像在坑玩家。为什么不选「有效值最大化」：那会优先吃高 1 档（2.0/件），两件就封顶，一键消耗掉最值钱的紫装，和四紫升紫「保护高档」的既有原则冲突。

### 4.4 规则层实现

在 `Reforge` 增加纯函数：

```gdscript
static func random_refine_materials(inventory: Array, target: Dictionary,
        slots: int = 4, rng: RandomNumberGenerator = null) -> Array[Dictionary]
```

- 只读 `inventory`，返回**实例快照**（`duplicate(true)`），不改背包；
- 调用 `can_refine()` 做基础判定，再过滤 `star != 0` 与 `tier_index(material) > tier_index(target)`；
- 按档位分组，按 §4.3 顺序取件，组内随机；
- 全部为空时返回空数组，UI 据此提示。

### 4.5 与结算的关系

随机放入只改面板的 `_refine_selected`。确认重铸时仍走既有 `GameState.reforge_equipment(..., refine_ids)`：

- 按实例 ID 重新定位背包、逐件复核 `can_refine`；
- 先掷词条、再同批扣金币与材料；
- 任一材料在预览后被整理 / 卖出 / 穿到身上，整单拒绝、一件不扣。

因此随机放入不新增任何结算分支，也不新增存档字段。

## 6. 测试计划

### 6.1 规则层（追加到 `RefineTest`）

1. **同档优先**：同档 5 件 + 低档若干 → 取 4 件同档，有效 4.0、下限 60%；
2. **低档兜底**：同档 1 件 + 低 1 档 3 件 → 有效 2.5、下限 37.5%（显示 38%）；
3. **不取更高档**：只有高 1 档紫装时返回空数组；
4. **排除项**：收藏、目标本身、金装、紫装以外的品质、升星件全部不进池；
5. **上限**：同档 8 件只取 4 件且实例不重复；
6. **零副作用**：调用前后 `inventory` 逐格 `==`；
7. **随机性**：固定种子能取到不同组合（不是永远取前 4 件）。

### 6.2 UI 与会话（新增 `ReforgeSessionTest`）

1. `panels_coexist("reforge", "inventory")` 与反向均为 true；
2. 打开重铸 → 背包自动打开且可见；
3. 重铸关闭 → 背包仍打开；
4. 背包 `set_open(false)` → 重铸同步关闭（整场退出）；
5. 打开其他 NPC 面板 → 重铸关闭，不被背包「续命」；
6. 随机按钮：点击后 4 格填满、背包未被修改、再次点击可换组合；
7. 无候选时保留原选择并给出提示；
8. 面板宽度不足时走上下分区且重铸可操作（不遮住背包拖拽区）。

### 6.3 回归

- 定向：`RefineTest`、`ReforgeTest`、`ReforgeLockTest`、`EquipmentFusionUiTest`；
- 默认全量 60 项（新增会话测试后 61 项）必须全 PASS；
- 随机流红线不动：`ItemFactory` 与 `Reforge` 的既有随机调用顺序不变，`ReforgeTest` 快照继续守住。

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 背包打开事件把重铸顶掉 | 先改 `panels_coexist` 与 `_on_panel_opened`，再接自动打开；顺序反了会「开一个关一个」 |
| 两个 Session 信号互相打架 | 合成 / 重铸互斥由既有 `panel_opened` 保证；布局判据统一为「三个会话任一激活」 |
| 窄屏下重铸内容被 52% 高度裁切 | 实施时实测 1280×800 与更窄窗口；若裁切，精炼材料区跟随合成工作台加滚动 |
| 随机按钮吃掉升星件 / 高档紫装 | 自动池硬性限定 0 星、≤ 目标档；手动拖入仍是唯一入口 |
| 整理后实例下标漂移 | 随机只存实例快照，结算按实例 ID 重新定位，沿用工程 86 既有路径 |
| 按钮点击后没有反馈 | 提示区显示「精炼 N 件（有效 X）· 下限 Y%」，无候选时明确说明原因 |

## 8. 已拍板（2026-10-21）

1. **随机选料顺序**：按 §4.3「同档 → 低 1 档 → 低 2 档及以下」，不取更高档。
2. **12★ / 升星件**：自动按钮只取 0 星；升星件必须手动拖入。
3. **关闭语义**：关重铸时背包保留；背包按 I / Esc 才整场退出。

改动范围与测试范围按 §5 / §6 执行，不再保留其他候选口径。
