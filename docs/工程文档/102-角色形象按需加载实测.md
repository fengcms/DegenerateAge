# 角色形象按需加载试验与撤回记录

2026-11-19。检查初始角色加载成本，目标是避免未使用装备档位占用纹理；不改变换装规则、动画帧数或存档。

## 现象与根因

CharacterLook.LOOKS原先在脚本常量中preload全部六档图集与面板，初始形象也提前加载49张纹理。独立最小Godot进程加载同一脚本并调用definition("look_01")，ResourceLoader.has_cached逐路径检查证实49张已缓存，按尺寸×4的理论RGBA8合计43352064字节。不是仅依据代码推断。

## 修改与资源生命周期

登记表改为资源路径；definition首次按形象递归解析纹理并缓存，后续调用只查表。全工程调用点均通过definition/panel_texture取得Texture2D；未登记档位仍回退默认并限频提示。每档只加载一次，最多缓存六档，与旧实现相同的上限；已访问的档位保持缓存至进程退出，以免往返换装重复IO。面板与世界精灵共享ResourceLoader纹理。首次切到新档仍有同步加载成本，尚未实现后台预热。

## 同场景前后测量

Godot 4.7.2，headless独立进程，复用同一已导入资源。最小探针移除class_name并将本次未调用的Equipment.template_of替为参数本身，以隔离项目其他Autoload；除此之外使用修改前后实际CharacterLook代码。每组3次新进程；不是清除OS文件缓存后的冷磁盘测量，也不是完整游戏启动测量。

| 指标 | 修改前 | 修改后 |
|---|---|---|
| 加载脚本ms，三次 | 118.223 / 119.336 / 117.783 | 2.668 / 2.738 / 2.896 |
| definition初始形象ms | 0.003 / 0.004 / 0.003 | 33.428 / 32.305 / 33.374 |
| 纹理数量 | 49 | 12 |
| 理论RGBA8字节 | 43352064 | 12533760 |

初始形象加载范围减少30818304字节，约29.39MiB；实际显存、解码峰值与完整游戏加载仍受其他资源影响，不能把这个数直接当作进程内存下降。脚本加载+初始定义总耗时约118ms降至35–36ms，仅限此隔离探针。

## 验收与复核

CharacterLookLoadingTest在独立测试进程中检查初始形象不会加载look_06、首次高级换装才加载、重复查询复用资源、缺失档位回退。CharacterLookTest、MountShortcutTest、ArtSampleTest通过，覆盖所有档位、面板与骑乘切换。导出使用all_resources，需要继续验证最终ZIP包含所有动态路径；此方案不依赖preload确保入包。

复核：运行上述四个隔离场景及全量测试；导出ZIP后运行tools/check_export_package.py，并检查LOOKS全部res://纹理路径存在。不得把headless探针结论当作GPU帧率提升。

## 最终结论：未采用

全量211项中210通过、MonsterCrowdTest失败；同版本定向复跑仍失败，冻结其他改动只恢复旧CharacterLook预载后通过。临时探针观察到分离后狼距离玩家约82.8与90.5px，仍处CHASE，而测试要求2秒后全部进入ATTACK。狼可见半宽61.5px、攻击距离80px；_separation_push完全重合时使用get_instance_id()%8派生方向，加载顺序改变实例编号，因此推断这是资源分配顺序与站位决策耦合导致的差异。未修改怪物规则或放宽测试来交付优化。

已撤回f965017d的实现与该功能新增测试，正式版本仍采用原预载。上述数据仅是未采用方案的测量，不能作为已交付收益。后续应先将重合站位与资源实例编号解耦，并覆盖不同创建顺序，再重新评估按需加载。
