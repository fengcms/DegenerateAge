## 0. 30 秒上手（新机器最短路径）

```bash
# 1) 装 Godot 4.7.2 + Git（推送时按仓库权限配置 GitHub 凭据）
# 2) 拉代码
git clone https://github.com/fengcms/DegenerateAge.git
cd DegenerateAge
# 3) 首次必须注册全局类（新机器没有 .godot/ 缓存）
GODOT=/Applications/Godot.app/Contents/MacOS/Godot      # macOS；其它平台换成自己的 Godot 可执行文件
"$GODOT" --headless --path . --import
# 4) 验证环境（应输出「配置校验通过 ✅」且无 SCRIPT ERROR）
"$GODOT" --headless --path . --quit
# 5) 用 Godot 打开本目录（选 project.godot），按 F5 运行
```

- 主分支 `master`（**现行开发分支**）；`bak` 是旧 Swift/SpriteKit 归档，**不要在其上开发**。
- 详细环境安装 / 换机清单见 **`docs/工程文档/01-脚手架搭建与换机复现指南.md`**（§0 一页速览 / §2 环境 / §9 换机清单）。
- **`.godot/`、`.workbuddy/`、`bak/`、`docs/history/`、`.vscode/` 已在 `.gitignore` 中**，不会随 clone 过来 —— 每台新机器都要跑一次 `--import`。

## 1. 项目是什么

**《末法纪元：最后的守护者》**——2D 等距（isometric）单机实时战斗、打怪升级 ARPG（Diablo-like），首发 macOS。

| 项 | 值 |
|---|---|
| 引擎 | **Godot 4.7 stable**（`config/features = "4.7", "GL Compatibility"`） |
| 语言 | **GDScript**（必要时可切 C#） |
| 分辨率 | 1280×800；`project.godot` 保持 `stretch/mode = canvas_items`（**无头基线**），真实渲染策略 **`disabled` 由运行时应用**（`SettingsRuntime.apply_display_strategy()`，M5-9a 已完成，见 §5.18 / 工程文档 17） |
| 主场景 | `res://scenes/Main.tscn`（UI 层 + 世界层）；世界场景是 `scenes/Game.tscn` |
| Autoload | `EventBus` / `GameState` / `DataLoader` / `SaveManager` / `QuestService`（M2） / `MapService`（M3-1） / `Localization`（M5-4，骨架已入库、尚无调用方） |
| 设计事实源 | **`docs/产品文档/`**（总纲 + 12 章 + 术语表）—— 一切设计以它为准 |
| 工程实现 | `docs/工程文档/`（本目录，01~19；**08 为滚动交接文档**） |
| 产品创意 | `docs/游戏创意/`（**非基线**；`10` 为车夫可达范围权威口径，`08` 为执行规格，见 §5.17） |

**商业模式**：买断制优先；**无联网 / 无账号 / 无抽卡 / 无氪金 / 无 PvP / 无交易市场**。
**开发排期原则**：先做最小闭环（货郎经济 → 任务 → 多图 → 坐骑/升星），但**产品设计是完整的**，讨论产品时不要因"排期"裁剪功能描述。

## 6. 项目铁律（违反会被打回）

1. **数据驱动**：新增装备 / 怪物 / 任务 / 地图 = **只加 `data/*.json` 条目 + 图标，不改代码**。
   （C3 修精英掉落就是加一张表，不是加 `if kind == "elite"` 分支。）
2. **单一事实源**：改设计先改 `docs/产品文档/`，再同步 `data/*.json` 与代码。
3. **四层验证，每步必跑**：
   ```bash
   GODOT=/Applications/Godot.app/Contents/MacOS/Godot
   "$GODOT" --headless --path . --import                    # A0 新增 class_name 后必跑
   "$GODOT" --headless --path . res://tests/SmokeTest.tscn  # A 冒烟：退出码 0
   "$GODOT" --headless --path . res://tests/SettingsTest.tscn  # 设置 / 旧档迁移 / 逐面板复验矩阵
   "$GODOT" --headless --path . --quit                      # B 启动回归：0 SCRIPT ERROR + 「配置校验通过 ✅」
   "$GODOT" --headless --path . --check-only --script res://<某脚本>.gd   # 单文件语法快速检查
   ```
4. **提交规范**：每完成一个功能或关键节点，使用 Conventional Commits：`type(scope): 中文描述`，立即 `git commit`。是否推送远端取决于当前任务的明确范围，不把本地提交误写成已推送。
5. **文档分工**：`docs/产品文档/` = 需求基线（设计事实源）；`docs/工程文档/` = 实现文档（01 换机 / 02 计划 / 03~13 各专项方案，**08 为滚动交接文档**）。
6. **非静默失败**：任何失败都要有可见提示（`EventBus.toast_requested.emit(msg, "danger")`），不允许静默吞错。

## 7. 已踩过的坑（**先读这一节，能省半天**）

| # | 坑 | 结论 |
|---|---|---|
| 1 | **Godot 拖放** | 只能用 `Control` 虚方法 `_get_drag_data` / `_can_drop_data` / `_drop_data`；**代码构建的 UI 无法给 `Button` 实例挂虚方法** → 必须抽独立控件（本项目是 `scripts/ui/item_slot.gd`）。 |
| 2 | **`set_drag_preview` 挂载点不可控** | 引擎会把预览塞进任意祖先节点（实测 `Main/UI/InventoryPanel/@PanelContainer@195`），同 canvas 同 z → 被面板挡住。解法：**自绘跟随元素** `scripts/ui/drag_ghost.gd` 挂到 `UI/DragLayer`。 |
| 3 | **`z_index` 只在同一 `CanvasLayer` 内有效** | 本项目 UI 全在 `CanvasLayer(layer=1)`。层级秩序：**面板 `0` ＜ HUD `ToastBox` `2048` ＜ 拖拽幽灵 `DragLayer` `4096`**。 |
| 4 | **JSON 往返会改变字典键顺序** | 断言"实例逐字段一致"必须做**键集 + 逐键深比较**；直接 `str(dict)` 比较会**假失败**。 |
| 5 | **无头模式不锁帧** | 等待必须用 `await create_timer(秒)`，别用帧数或 `process` 累计。 |
| 6 | **截图工具要加载 `Main.tscn`** | 加载 `Game.tscn` 会**没有 HUD**（UI 在 Main 层）。 |
| 7 | **`var x := <Variant 来源>` 在"警告视为错误"下直接编译失败** | `SaveManager._read_file()` 这类返回 `Variant` 的函数，接收变量必须显式写 `var x: Variant = ...`。 |
| 8 | **`max_hp()` 由攻击派生**（4.3：攻×2 + 防×4） | 调试时直接改 `player.attack` 会连带改 HP 上限与占比 → 会误触发 3.14「危险血量保护」。测试时**必须同步补满 HP**（`AutoBattleProbe` 里踩过）。 |
| 9 | **`String.join` 需要 `PackedStringArray`** | 普通 `Array` 会报类型错误。 |
| 10 | **掉落物被瞬间吸走 → 挂机丢件** | 根因：近战射程 64px < 自动拾取半径 96px，掉落物约 1 帧即被吸走；而「落地保护期」方案又与自动战斗「击杀后不逗留」互斥（保护期内玩家已走远 → 掉落物等 60s 消失 → **丢件**）。**正解（工程文档 10）**：`GroundItem` 改为**生成即认领**（当帧入包、不可逆）+ `remove_from_group("ground_items")`（顺路拾取自动看不见它）+ 停驻 0.2s + 追踪抛物线 1.0s。字段 `pickup_delay` → `hold_time`（0.2），新增 `auto_claim` / `stagger_delay`。 |
| 11 | **编辑事故** | 避免同一条消息里对**同一文件**做 `old_string` 重叠的批量 Edit —— 曾导致整章静默丢失。 |
| 12 | **中文字体** | 用 **`SystemFont` 回退链**（`assets/themes/default_theme.tres`：PingFang SC → 微软雅黑 → Noto Sans CJK …），**不需要内置字体文件**，跨平台自动选系统字体。 |
| 13 | **改完脚本必须先跑一次实跑自检，再上长测** | 若被指定的场景脚本**解析失败**，Godot 会**静默回退加载 `run/main_scene`（Main.tscn）**——即"测试脚本没生效，真游戏跑起来了"，还会因 `SaveManager` 的续档 + 定时存**写玩家真实存档**。本次实测踩到：一次编辑把 `return` 与下一行粘连 → 解析失败 → 回退跑主场景 2 分钟 → 自动存写进 1 号槽。**防护**：`--check-only --script …` 先查解析（它仍会报 autoload 不可见的预期错误，但 `Parse Error` 一定先出现），再跑 3~5 秒极短实跑确认流程走通。 |
| 14 | **测试工具会写坏玩家存档（已修复）** | 启动续档后 `SaveManager.active_slot` 指向**玩家真实槽位**；测试工具 `GameState.reset_to_defaults()` + 大量击杀升级 → 关键事件自动存 → **把玩家档覆盖成测试态**（实测 `SmokeTest` 日志出现 `已保存到槽 1`）。**修复**：`SaveManager._autosave_allowed()` 增加**测试场景闸门**——`current_scene` 在 `res://tests/` 下时拒绝自动存 / 退出存；`autosave_in_tests` 可显式放开（`SoakTest` 已放开，因其自行快照 / 还原存档目录）。**写新测试工具时不要绕过它。** 详见工程文档 06 §10。 |
| 15 | **自动搜怪旧锚点限制已废弃** | M4-9 后以 `Game.visible_enemies()` 作为候选；`searchRadius` 仅为旧档兼容字段。更新回归时别再断言 `_anchor`，不要恢复固定半径。 |
| 16 | **恢复按未受击时间分段结算** | 2026-10-14 修订：`_tick_regen(delta)` 每满 3 秒结算一次，实际受击重置计时；移动、攻击和窗口失焦继续计时，死亡与暂停不结算。单次按最大值百分比、未满至少 1 点；打坐提高单次恢复量。旧版“小数逐帧累积、脱战等待 5 秒”规则不再适用。 |
| 17 | **M6-0：测试里杀带「召唤」词缀的精英要挂 `Node2D` 父节点** | `Monster._spawn_summons` 用 `get_parent().to_local(...)`；挂裸 `Node`（如 `smoke_test` 自身是 `Node`）会 SCRIPT ERROR（断言仍过但「0 SCRIPT ERROR」铁律破防）。另：**未领取战利品登记必须 `call_deferred`**（掉落方 `add_child` 后才设落点，当帧登记会拿到 `(0,0)`，负向验证实测确认）。 |
| 18 | **本地化 key 撞号是静默的** | `data/localization.json` 是扁平大字典，重复键**后者胜出**，不报错也不警告，你的新文案就这么没了。**连续踩两次**：M10-5 `msg.map_service.p022/p023`、M10-6 `ui.shop_panel.p020`。防护：**加完文案核对总条数**（加一条就必须 +1），并给新键写一条「该键解析出预期正文」的断言。 |
| 19 | **「渲染对了」不等于「行为对了」** | UI 面板的测试若只断言「分组数 / 行数」，**按钮里调的是哪条 API 完全测不出来**（M10-7 实测：面板漏改 `travel_to`，7 组 / 35 行全部照过）。防护：让**失败文案**成为判据 —— 同一目标在两条 API 上报不同原因（`金币不足` vs `车夫无法直达`），断言文案才能区分「真走了另一条路」与「只是长得像」。 |
| 20 | **负向注入必须与要防的错误「同形」，否则是假绿** | M10-8 首轮 10 组负向里 N-3 / N-5 / N-8 **全部没红**，问题不在代码也不在断言，而在**注入打偏**：① N-3 只把 `scale_key` 换成模板套、却保留了 `factor` ⇒ 结果依然正确（那不是 bug）；真正的 bug 是「不乘实例等级因子」。② N-5 把 `add_gold` 挪到 `reroll` 之前 ⇒ 该路径被 `can_reforge` / 金币检查挡死，**正常状态不可达**；真正可测的形态是「金币检查**之前**就扣、后续失败不退款」。③ N-8 只删 `maxi(0, …)` ⇒ 被 `over <= 0` 早退吸收（双保险，删一层不改变行为）；要验「L ≤ 60 恒 1.0」必须连早退守卫一起删。**结论：负向没红先怀疑注入，别急着改代码；每条注入都要能说出「哪条断言、为什么必须红」。** |
| 21 | **实现方案一换，产品指定的负向注入就可能失效** | M10-10 产品 R-21 明确写了负向「把大红 pct 提到 0.25（=597>500）⇒『L60 恢复量仍为 500』必须失败」。但本批落地时加了 `level ≤ 60` 等级守护（因为纯公式在 L60 穿 `rare` 时越界 2 倍），**L60 恒取固定值、改 pct 根本不影响它** ⇒ 这条注入必然假绿。真正同形的注入是「守护阈值错位」（`PCT_FROM_LEVEL` 60 → 59）或「删掉守护」。**教训：产品给的负向注入是按「产品的实现方案」写的，换实现就要重新推导，不能照抄。** 另：`maxi(fixed, …)` 要验得出，必须有一条「61 级以上且百分比 < 固定值」的采样点（本批补 `cap=2000/lv=61`）。 |
| 21 | **产品表的「口径漏项」会让「按表验收」变成「按错表验收」** | M10-8 按产品 §6.1 的「8 件 × 中位 360 = 2,880」定下重铸费 400，M10-9 用真实掉落一跑，装备回收是 **5,894（2.05 倍）** —— 表里漏了**品质倍率**（`rare75/epic25` 均价 ×3.75、传说 ×12）与**件数**（8.55 而非 8）。于是「按表验收 5–9 次/h」在实测下变成 7.6–16.0，L1000 超 1.8 倍。**防护：凡是拿「文档估算值」当输入去定数值，先用真实表跑一遍均值；产出类口径必须含品质倍率与掉率，不能只乘中位单价。** 教训与 §7 第 20 号坑同源：**断言/数值的输入本身可能是错的**。 |
| 22 | **同一份产品文档里两条相反的口径并存，落地时「后写的」吞掉「先写的」** | 产品 13 第 39 行写「60/70/…/1000 级复用同一批型号」（= 十级一档），§4.6 又写「等级 = Boss 生成等级」。工程 41/42 照后者实现，于是 60+ 变成 61/62/63… 逐级装备，**实机反馈才发现**（D-21）。两句话都写在「单一事实源」里，评审时都看过，但没人把它们并排放。**防护：写「等级」「倍率」「上限」这类贯穿全案的口径时，先全局搜同名词并逐条对齐；出现「复用同一批」+「按 X 生成」并存，多半是两套规则打架，必须当场合并成一条，不许两句都留着。** |
