# 仓库经验兑换确认与弹框居中方案

## 确认反复失效

`autoload/game_state.gd:1089` 在扣费前重算报价，并用整个字典与已确认报价比较。`scripts/systems/gold_exchange.gd:63` 的报价同时包含当前经验、预计结余经验、库存、额度和实际到账经验。打怪走 `scripts/entities/monster.gd:1136` 的经验入口。同级击杀即使只增加一分经验，也会改变报价中的进度字段，导致确认失败。重新打开数量框后，下一次击杀可以再次触发相同路径。

背包拾取会触发仓库界面刷新，但报价的支付来源是仓库。单纯拾取且角色经验、仓库库存及额度均未变化时，按现有代码推演不会改变确认结果。上述判断来自代码核对，尚未采集用户战斗场景的复现数据。

## 确认规则

- 结算前仍从实时仓库库存和本级额度验证当前数量。确认只比较兑换类型、批数、消耗、计价等级、实际到账经验和本级已用额度。已用额度参与比较可拒绝旧确认重放。库存增减后只要仍足够支付，允许原数量提交。
- 同级刷怪导致的进度变化直接按最新经验结转，包括本笔兑换恰好使角色升级。预览将消耗和到账作为确定值，兑换后等级及进度标明为预计值。
- 如果打怪已令角色升到新等级，或距满级更近而实际到账变化，更新报价并要求重新确认。库存或额度不足时整笔拒绝并显示原因。保留防重入和单次提交保护，不自动改小数量成交。

## 数量框居中

`scripts/ui/panel_amount_dialog.gd:91` 已使用 CenterContainer。它只能在自己的实际矩形内居中。遮罩和 CenterContainer 在挂入父节点前设置全铺锚点，外层则依赖仓库根控件尺寸。左上角现象与覆盖层或居中容器未取得完整视口尺寸一致，具体偏移来源需用实际窗口记录父节点、遮罩、容器和对话框的矩形确认。

复用现有数量框。挂载节点后明确将覆盖层铺满仓库的逻辑视口，居中容器与遮罩四边锚定、偏移清零。随窗口和 UI 缩放使用同一逻辑坐标系，由容器在两个轴上对齐视口中心。保留鼠标遮罩、键盘焦点和 Esc 只关闭弹框的行为，仓库所有使用该数量框的兑换一并受益。

## 验收与提交

1. 在连续发放同级经验以及仅背包拾取的场景下，分别确认金砖和如意各一次即可成交。检查仓库扣除数量、重复提交、跨级变价、满级截断及库存不足。验证库存变动仍足额时正常成交。
2. 在实际窗口验证城镇和随身仓库，覆盖宽屏、窄窗口、1 倍与 2 倍 UI 缩放及弹框打开时调整窗口。测量对话框与可见视口中心在两个轴上的误差，目标不超过 1 个逻辑像素，并验证焦点、Esc 和遮罩。两个节点分别验收提交。
