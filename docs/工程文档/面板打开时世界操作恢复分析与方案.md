# 面板打开时世界操作恢复分析与方案

本文记录“面板打开后 WASD 与快捷栏失效”的原因、产品口径调整和实施验收。

## 现象与证据

玩家试玩反馈指出：任意普通面板打开后，WASD、攻击、Tab、自动拾取 G 和数字快捷栏不能控制面板后的人物；F 和骑乘 R 则已有个别例外。代码检索确认，`scripts/entities/player.gd` 在每次物理帧用 `GameState.panel_open` 把移动向量置零并拒绝普攻，`scripts/ui/hud.gd` 用同一标志拒绝快捷栏，`scripts/world/game.gd` 用它拒绝 Tab/G/地图点击，`scripts/systems/auto_battle.gd` 也不把面板内按键视为手动接管。`GameState.panel_open` 的注释和旧测试说明明确把所有面板视作世界输入屏蔽，故不是单个控件焦点异常。

## 根因与产品决定

“面板可见”与“模态接管世界输入”被同一个布尔值合并，导致可并开、无全屏遮罩的普通信息窗也禁用角色键盘。现按玩家的新要求修订产品规则：普通信息面板和 NPC 会话允许手动控制角色及快捷栏；NPC 会话只暂停自动战斗决策。暂停菜单、设置/改键、存档、死亡、装备确认及聚焦文字输入仍接管键盘，以免误操作。面板覆盖区域的鼠标点击继续由 GUI 接收；全屏遮罩的既有鼠标行为不因本次键盘修复而改变。

## 实施范围

1. 在 `GameState` 中增加统一的“世界输入是否被模态接管”查询；保留 `panel_open` 作为面板可见状态，避免改变现有面板共存、Esc 层级和 NPC 自动战斗暂停逻辑。
2. 角色移动、普通攻击、手动技能追击、世界快捷操作、HUD 快捷栏及自动战斗的手动接管统一使用新判据。Tab 在 GUI 焦点处理前分发，背包按钮持有焦点时也能切换世界目标；面板内鼠标右键不误触发挂机的手动接管。普通面板打开时手动移动仍可取消旧寻路/连续攻击，并启动原有 1.5 秒自动战斗恢复倒计时。
3. 更新产品文档和旧测试的“面板阻断操控”口径；使用真实主场景的输入路由验证打开面板时的 WASD、Tab、F/G、快捷栏药品，以及模态设置面板阻断。

## 成本、边界与复核

只增加一个查询，不改存档、物品或面板数据。按键轮询沿用原物理帧频率；查询的最坏工作量是检查 5 个模态面板 ID 和当前焦点控件，不做数据表扫描或资源加载，无缓存与失效成本。复核应在背包、大地图和 NPC 会话中分别操作键盘，并检查面板控件点击不穿透、设置改键输入不驱动角色、死亡与暂停仍冻结世界。隔离项目中 `InputFeedbackTest`（真实主场景按键）、`HotbarUiTest`、`SettingsTest`、`NpcAutoBattleTest`、`SmokeTest` 均通过；游戏窗口中的实际手感仍需试玩确认。
