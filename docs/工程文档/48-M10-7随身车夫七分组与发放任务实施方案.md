## 0. 三件必须先知道的事

### C-1 车夫面板是**同一个节点两种模式**，而信号现在只传一个字符串

`carter_panel_requested(npc_name: String)`（`autoload/event_bus.gd:69`）被四个地方用到，其中两个语义不同：

| 位置 | 现在传什么 | 语义 |
|---|---|---|
| `scripts/world/game.gd:503` | `npc.npc_name`（如「石辕」） | **当地车夫**，只列同集群 |
| `scripts/ui/quest_panel.gd:404` | `npc.npc_name` | **当地车夫**（任务面板里点 NPC 服务） |
| `scripts/systems/panel_router.gd:49` | `title("carter")`（「随身车夫」） | **随身车夫**，应列全部 36 图 |
| `scripts/ui/carter_panel.gd:50` | 收 `npc_name` 拼标题 | 无法区分上面两者 |

M10-5 时 `ready=true` 只是把标题接上，**面板内部仍走 `destinations()`（`map_service.gd:411`，只到同 hub）**，所以现在双击随身车夫打开的是**当地车夫列表** —— 面板亮着但功能不对，正是 M10-4a 说的「点亮 ≠ 能用」。

解法：信号加第二个参数 `portable: bool`。
`warnings_as_errors` 开着 ⇒ 漏改任一 `emit` / `connect` 会**编译失败**，不会静默跑偏。四个点必须同批改。

### C-2 🔴 七分组不能只按推荐等级分桶 —— `c7_arena` 的 `recommendedLevel` 也是 60

实测 36 张图的等级：

| 组 | 图数 | 说明 |
|---|---|---|
| 1–10 | 4 | camp 1 / wild_trial 2 / ash_land 6 / corruption_source 10 |
| 11–20 | 6 | c2 全部（11–18） |
| 21–30 | 6 | c3 全部（21–30） |
| 31–40 | 6 | c4 全部（31–40） |
| 41–50 | 7 | c5 全部（41–50） |
| 51–60 | 6 | c6 全部（51–**60**） |
| 60+ | 1 | **c7_arena（也是 60）** |

`c7_arena` 与 `c6_map05` 推荐等级都是 60，**按等级分桶必然把它们并进「51-60」**，产品要求的「60+」组就是空的。

判据改用数据里已有的 `levelFromPlayer.enabled`（`data/maps/ch07/c7_arena/map.json`，全库唯一一张图带这个字段，它就是「等级随挑战者成长」的循环图标记）。**不新增地图字段、不改 `c7_arena` 数据。**

### C-3 加发放任务会撞两处既有断言，且有一处数据契约会直接让校验失败

1. `tests/chapter_six_quests_test.gd:51` 断言 `_c6_quests().size() == 18`（12 主线 + 6 支线）。加一条支线 → **必须改 19**，并写明「12 主线 + 7 支线」。这是**数量真的变了**，不是放宽。
2. `autoload/data_loader.gd:1242-1245`：`reward.gold` / `reward.xp` **即使为 0 也必须写**（缺字段时 `rd.get("gold", null)` 是 null，`_nonnegative_whole(null)` 返回 false ⇒ 启动校验报错）。这条不写，第一层 `--quit` 就红。
3. 🔴 `unlocks` 必须是**数组**：`reward.unlock`（单数）不进 `save_manager._known_unlock_ids` 白名单（`save_manager.gd:1325-1329` 只扫 `unlocks` 数组），写了单数会让**读档判「unlocks 含未登记键」= 存档损坏**。全库现在只有 `Q005→chapter2` 用了单数，靠 Boss 首杀键恰好兜住。本条（`C6S07`）**必须用 `unlocks: [...]`**。

### C-4 交付提示根本不列 `reward.items`

`quest.gd:368-380` 的 `parts` 只拼 `gold` / `xp` / **主奖励 `item`** / 单数 `unlock`；`bonus_items`（`reward.items`）**一个字都不进 toast**。现库唯一用的是 `C2S01`（半碗汤，2 瓶中药），玩家交付后提示里也看不到药 —— 是既有欠账，本批顺手修。

## 2. 设计

### 2.1 `MapService`：七分组 + 跨章目的地列表

```gdscript
# ---- 随身车夫（M10-7，产品 13 §5.3）----
## 七个分组，顺序即 UI 顺序。**不要按数据动态生成**：
## 空组也要按固定顺序占位，否则某章暂时无图时组序会塌。
const LEVEL_GROUPS := ["1-10", "11-20", "21-30", "31-40", "41-50", "51-60", "60+"]

## 地图 → 分组键。判据顺序不能反：
## ① `levelFromPlayer.enabled`（循环图，现仅 c7_arena）→ "60+"；
## ② 否则按 recommendedLevel 落到 10 级一档（60 → "51-60"）。
func level_group_of(map_id: String) -> String:
	var lfp: Variant = data_for(map_id).get("levelFromPlayer", null)
	if lfp is Dictionary and bool((lfp as Dictionary).get("enabled", false)):
		return "60+"
	var lv := clampi(recommended_level(map_id), 1, 60)
	var start := int(floorf(float(lv - 1) / 10.0)) * 10 + 1
	return "%d-%d" % [start, start + 9]

## 跨章目的地（`travel_anywhere` 的镜像列表）。与 `destinations()` 的区别只有两点：
## ① 遍历**全表**而不是 `links()`；② 报价用 `fee_anywhere`。
## 放行判据与 `_travel_checks` 逐字同源（含 camp→wild_trial 教学例外），
## 否则会出现「面板写着能去，点了报无法前往」的双轨。
func anywhere_destinations() -> Array:
	var out: Array = []
	for entry in DataLoader.get_table("maps"):
		if not entry is Dictionary:
			continue
		var id := String((entry as Dictionary).get("id", ""))
		if id.is_empty() or id == GameState.current_map:
			continue
		var visited := GameState.is_visited(id)
		var taught := GameState.current_map == DEFAULT_MAP and id == "wild_trial"
		var open := is_unlocked(id) and (visited or taught)
		var reason := ""
		if not is_unlocked(id):
			reason = Localization.tr_key("msg.map_service.p011")
		elif not open:
			reason = Localization.tr_key("msg.map_service.p012")
		out.append({
			"id": id, "name": display_name(id),
			"recommendedLevel": recommended_level(id),
			"cost": fee_anywhere(id), "unlocked": open, "visited": visited,
			"reason": reason, "group": level_group_of(id),
		})
	out.sort_custom(_sort_anywhere)
	return out

## 稳定排序：组序 → 推荐等级 → id。给定同一份数据，结果必须逐条可复现
## （测试会对连续两次调用做逐条比对，字典序/随机序都会红）。
func _sort_anywhere(a: Dictionary, b: Dictionary) -> bool:
	var ga := LEVEL_GROUPS.find(String(a.get("group", "")))
	var gb := LEVEL_GROUPS.find(String(b.get("group", "")))
	if ga != gb:
		return ga < gb
	var la := int(a.get("recommendedLevel", 0))
	var lb := int(b.get("recommendedLevel", 0))
	if la != lb:
		return la < lb
	return String(a.get("id", "")) < String(b.get("id", ""))
```

⚠ **两个 GDScript 坑**（都踩过/都能踩）：
1. `(lv - 1) / 10 * 10 + 1` 是 `int/int`，撞 `warnings_as_errors` 的 `INTEGER_DIVISION` → 上面用 `floorf(float(lv-1)/10.0)`。
2. `sort_custom` 的比较函数必须**全序**（本函数在 id 上收尾），否则同等级同组的多张图顺序不稳定。

**不动 `destinations()` 与 `_travel_checks()`**：前者被 `smoke_test.gd:3229`、`map_gate_test.gd:68`、`chapter_one_acceptance.gd:43` 三处锁着（营地 4 行、置灰顺序），后者文案顺序被既有测试锁着。新增只做加法。

### 2.2 `CarterPanel`：双模式 + 分组渲染

- 新增 `_portable: bool`，由信号第二参设定；`_refresh()` 与 `_on_travel()` 是唯一两处读它的地方。
- 当地模式：**渲染完全不变**（平铺 `destinations()`、`travel_to`）。
- 随身模式：按 `LEVEL_GROUPS` 顺序渲染 7 个分组标题 + 组内行；空组整段跳过（不显示空标题）。出行调 `travel_anywhere`。
- 分组标题：`60+` 用 `ui.carter_panel.p013`（「满级循环（60+）」），其余用 `ui.carter_panel.p012 % key`（「1-10 级」…「51-60 级」）。
- 提示行：随身模式追加一行 `ui.carter_panel.p011`（计价规则），当地模式保持 p004 原文 —— 随身价（20 × 等级、下限 50）与当地 `carterFares` **是两套价**，玩家会发现同目的地两个价，必须解释。
- 为测试暴露两个只读访问器：`section_keys() -> Array[String]`（当前渲染的分组键，当地模式为空）、`row_count() -> int`。与 `BossHealthBar.bar_count()` 同规格，**不加业务分支**。

```gdscript
func _on_requested(npc_name: String, portable: bool = false) -> void:
	_portable = portable
	if not npc_name.is_empty():
		_title.text = PanelChrome.title_text(Localization.tr_key("ui.carter_panel.p001") % npc_name)
	set_open(true)
```
（信号两参时 `default` 不参与，但保留默认值可让直接调用方少写一处。）
