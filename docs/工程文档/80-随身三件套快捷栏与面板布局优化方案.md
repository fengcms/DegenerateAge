# 80 · 随身三件套：快捷栏拖放 + 车夫 / 令牌面板布局优化

> 状态：**已落地**（Q1—Q5 全部按建议拍板）｜2026-10-21
> 背景：用户反馈三件事 —— ① 三件随身工具（随身车夫 / 随身商队 / 追猎令牌）无法从背包拖到快捷栏；
> ② 随身车夫面板要拉滚动条；③ 追猎令牌面板布局不合理。
> 本文给出根因、实测数据与分层改造方案；**拍板结果与实施记录见 §6**。

---

## 0. 一句话结论

| 问题 | 根因 | 建议做法 |
|---|---|---|
| ① 拖不到快捷栏 | `HotbarConfig.valid_entry` 的 `item` 白名单**只写了两个 id**（回城卷 / 随机券），三件 `useType: "panel"` 的工具不在其中 ⇒ `entry_for_item` 返回空 ⇒ `_can_drop_data` 直接拒 | 把放行口径改成「与执行层同源」：`useType ∈ {townPortal, randomTeleport, panel}`。**执行逻辑零新增**（`_activate_hotbar` 已走 `use_item` → `_use_misc` → `PanelRouter.open`） |
| ② 车夫要滚动 | 内容自然高 **2493px**，可用约 **716px** ⇒ 3.5 屏。单列 35 行 + 每行两层文字（56px） | 紧凑行（56→约 36）+ **分组折叠（默认展开当前等级组与 60+ 组）**；可选加宽双列 |
| ③ 令牌布局不合理 | 内容自然高 **2788px**（营地）/ **3428px**（在无尽回廊）⇒ 4~4.8 屏。15 个折叠按钮各占整行，行内三段横排拥挤 | 组按钮横排（15 行 → 2 行）+ 紧凑行 + 过滤（全部 / 仅存活）+ 手风琴式单组展开 |

**共性根因**：两个面板都把「长列表 + 每行两层文字」塞进固定宽（560 / 600）的单列里，
而视口宽 1280 只用了约 45%；纵向又全部摊平不做折叠 ⇒ 内容高度必然是可用高度的 3~5 倍。

## 1. 问题 ①：三件工具无法拖到快捷栏

### 1.1 根因（`scripts/systems/hotbar_config.gd`）

```gdscript
const TOWN_SCROLL := "misc_town_scroll"
const RANDOM_TICKET := "misc_random_ticket"
...
    "item": return (id == TOWN_SCROLL or id == RANDOM_TICKET) and DataLoader.get_entry("miscItems", id) is Dictionary
```

`entry_for_item()` 用它过滤 ⇒ 三件 `tool_*` 得到 `{}` ⇒ `HotbarSlot._can_drop_data` 返回 false ⇒ **拖不进去**。

⚠ 这是「白名单漏配」，不是机制不支持：拖入后的**执行链路是现成的**——

```
HotbarSlot._drop_data → hud._on_binding_dropped → GameState.set_hotbar_entry
点击 / 数字键 → hud._activate_hotbar → GameState.use_item(背包下标)
             → GameState._use_misc → useType == "panel" → PanelRouter.open(panelId) → 打开面板
```

`PanelRouter.PANELS` 三件全部 `ready: true`，`useType: "panel"` 的道具**不消耗**。

### 1.2 改造方案（R1—R3）

| # | 项 | 做法 |
|---|---|---|
| R1 | 放行口径 | `"item"` 分支改为**与执行层同源**：miscItems 存在且 `useType ∈ USABLE_TYPES`（`townPortal` / `randomTeleport` / `panel`）。🔴 不用「useType 非空」这种宽松口径 —— `revive` / `quest` 等 `_use_misc` 尚未实现的类型拖上去会点出「该物品无法使用」，那是**做出一个假功能** |
| R2 | 数量角标 | panel 类不消耗，`_binding_count` 现在会显示角标 `1`（无意义且像消耗品）。建议 panel 类返回 `-1`（不显示） |
| R3 | 格内辨识（🔴 真问题） | 三件工具**没有图标资源**（`SampleArt.ICONS` 与 `assets/sprites/items/` 都没有 `tool_*`）；`decorate()` 拿不到图标就显示 `text = 名称首字` ⇒ **「随身车夫」与「随身商队」都显示「随」，快捷栏上分不清**。见 Q2 三选一 |

### 1.3 边界（需要知道的现存行为）

- **仓库里的工具不生效**：`_activate_hotbar` 用 `_first_item_index()` 只搜背包，工具被放进仓库后点格子会弹「没有该物品」。见 Q3。
- 默认布局已占 3 格（红药 / 蓝药 / 普攻），`HotbarConfig.SIZE = 12`，再放 3 件工具后仍余 6 格。
- 绑定存的是**模板 id**（`{"kind":"item","id":"tool_portable_carter"}`），不存背包下标 ⇒ 背包整理、切图后绑定保持（既有语义，零改动）。

## 2. 问题 ②：随身车夫面板（实测）

### 2.1 量化现状（`--headless` 实测，全图到访）

| 项 | 实测值 |
|---|---|
| 目的地行数 | **35**（38 图 − 当前图 1 − 步行限定 2：`c7_gold_field` / `c7_boss_field`） |
| 分组数 | 7（4 / 6 / 6 / 6 / 7 / 6 / 3） |
| 单行最小尺寸 | **56px**（外框内边距 6+6 + 标题 15px + 间隔 2 + 副标题 12px） |
| 内容自然高 | **2493px**（宽 560） |
| 面板外框固定开销 | 84px（标题行 + margin） |
| 可用内容高 | 约 **716px**（视口 800 − 84，`FloatingWindow.fit_content` 的上限） |
| ⇒ 需要滚动 | **3.5 屏**（2493 ÷ 716） |

### 2.2 根因三条

1. **单列 35 行全摊平**：七分组只有标题、不做折叠 ⇒ 高度随地图总数线性增长（38 图是现状，加图会更长）。
2. **每行两层文字**：标题（推荐等级）+ 副标题（费用）纵向堆叠 + 外框内边距 ⇒ 56px/行，信息密度低。
3. **宽度只用了 44%**：`PANEL_WIDTH = 560`，视口 1280 ⇒ 右侧 700px 全空着，纵向却在挤。

### 2.3 分层方案（可组合，见 Q4）

| 层 | 改动 | 预期内容高 | 屏数 |
|---|---|---|---|
| L0 现状 | — | 2493 | 3.5 |
| **L1 紧凑行** | 外框内边距 6→4、行间隔 8→6、副标题 12→11px，费用并入标题行右侧 | 约 1736 | 2.4 |
| **L3 分组折叠** | 分组标题变可点击按钮；默认展开「当前等级所在组 + 60+ 组」，其余收起 | 约 **460** | **0.6（一屏内）** |
| L2 双列（可选） | `PANEL_WIDTH` 560→900，每组内用 `GridContainer(columns=2)` 排列卡片 | 全部展开约 988 | 1.4 |

**推荐 L1 + L3（必做）+ L2（可选）**：默认视图一屏内零滚动，需要时点开分组。

🔴 约束：`row_count()` / `section_keys()` 是 `PortableCarterTest` 的既有断言面。折叠**只改可见性，不改统计口径** ——
`row_count()` 仍返回 35、`section_keys()` 仍返回 7 个分组；另加 `visible_row_count()` 供新测试断言折叠行为。

## 3. 问题 ③：追猎令牌面板（实测）

### 3.1 量化现状

| 项 | 实测值 |
|---|---|
| `BossToken.rows()` 全库 | **137**（`c7_boss_field` 100 / `c7_arena` 20 / 其余 17） |
| 面板列表项数（在营地） | **48**（17 普通行 + 15 个折叠按钮 + 分隔线等） |
| 内容自然高（在营地） | **2788px** ⇒ 3.9 屏 |
| 列表项数（在 `c7_boss_field`） | **58**，内容高 **3428px** ⇒ **4.8 屏** |
| 单行最小尺寸 | 约 56~58px（与车夫同构） |
| 面板宽 | 600 |

### 3.2 根因四条

1. **折叠按钮各占整行**：`c7_boss_field` A—J 十组 + `c7_arena` A—E 五组 = **15 个整行按钮**（约 870px），
   按钮文案还是「地图名 · A 组（10 席）· 展开」这种长句。
2. **行内三段横排拥挤**：信息（可伸展）+ 状态列（固定 120，右对齐）+ 按钮（112），600 宽下「地图名 · Boss 名」容易折行。
3. **多组可同时展开**：每展开一组 +10 行，全展开就是 +100 行（约 5600px），没有任何上限保护。
4. **没有过滤**：后期 137 个 Boss 里绝大多数在冷却，玩家真正关心的「已刷新可打」混在里面靠人眼找。

### 3.3 分层方案（见 Q5）

| 层 | 改动 | 效果 |
|---|---|---|
| **L1 紧凑行** | 外框内边距与行间隔收紧、状态列 120→96、按钮 112→96 | 行高 58 → 约 38 |
| **L2 组按钮横排** | 15 个整行按钮 → 一行 5 个的 `FlowContainer`（「A 组 ▸ 10 席」），占 2~3 行 | 省约 700px |
| **L3 过滤条** | 顶部三档：全部 / **仅存活** / 冷却中 + 「只看当前图」开关 | 常用视图通常 < 10 行 ⇒ **一屏内** |
| **L4 手风琴** | 展开新组自动收起旧组（同时最多一组展开） | 上限锁死：17 + 10 = 27 行 ≈ 1030px（1.4 屏） |

**推荐 L1 + L2 + L3 + L4 全做**。L4 是「全展开 +100 行」的唯一硬约束，不能省。

🔴 约束：`BossTokenTest` 断言的是规则层 `BossToken.rows()`（137 行 / 排序 / 序号同源），
UI 侧的过滤与折叠**不得回写规则层** —— 过滤只在 `_rebuild()` 里做视图裁剪，`rows()` 保持原样。

## 4. Q1—Q5 拍板结果

> 2026-10-21 用户拍板：**Q1—Q5 全部采纳建议项**（Q1 与执行层同源 / Q2 简称文字 / Q3 提示取回 / Q4 紧凑+折叠 / Q5 四层全做）。

**Q1 · 快捷栏放行口径**（R1）
- **(a) 与执行层同源**：只放 `useType ∈ {townPortal, randomTeleport, panel}` —— **建议**
- (b) 宽松：miscItems 有条目且 useType 非空 ⇒ 可拖（会把 `revive` 等未实现类也放进去，点了报「无法使用」）

**Q2 · 三件工具在快捷栏上怎么辨识**（R3，🔴 现在两件都显示「随」）
- **(a) 简称文字**：新增 3 条本地化简称（车夫 / 商队 / 令牌）作为快捷栏显示名，tooltip 用全名 —— **建议**（零美术、当天可验）
- (b) 画三张 32×32 SVG 图标（马车 / 钱袋 / 靶心）进 `SampleArt.ICONS`（多一轮美术产出，视觉最好）
- (c) 保持首字（两个「随」分不清，不建议）

**Q3 · 工具被放进仓库后快捷栏失效**
- **(a) 提示**：点格子时明确提示「随身工具已放入仓库，请取回背包」—— **建议**（改动小、不越权搬物品）
- (b) 自动从仓库取回背包再打开（行为更贴心，但「静默移动玩家物品」需要谨慎）

**Q4 · 车夫面板改到哪一档**
- **(a) L1 紧凑 + L3 折叠**（默认一屏内，容器结构不变）—— **建议**
- (b) a + L2 加宽双列（全部展开时也更短，但要改容器结构、窄窗口下更挤）

**Q5 · 令牌面板改到哪一档**
- **(a) L1+L2+L3+L4 全做**（组按钮横排 + 紧凑 + 过滤 + 手风琴）—— **建议**
- (b) 只做 L1+L2（改动小；但「全展开 100 行」的爆炸面仍在）

1. 🔴 **`row_count()` 是统计口径，折叠只改可见性**。车夫默认 `visible=7 / total=35`、全展开 `visible == row_count`、全收起 `visible=0` 但 `row_count` 仍 35。
   一旦让 `row_count` 跟着可见行走，UI 状态就冒充了业务口径（负向 N-6 守着）。

### 6.4 ⚠ headless 测不出真实面板高度（本次最大教训）

实测时 `get_combined_minimum_size()` 得到「车夫 1912px、令牌 1242px」这类数字，**不能当真实高度用**：
无头视口是 64×64，带 `autowrap` 的 Label 在**最小宽度**下逐字换行 —— 实测 greet 标签 `min.x=1, min.y=569`、
hint `min.y=711`，占了大头。给 `_root.size` 强行设成 1280×800 也无效（minimum size 不依赖实际布局）。

**可复算的判据只有「可见项数」**（`visible_row_count()`），按行高约 40px 折算：

| 视图 | 改前项数 | 改后可见项数 | 折算高度 | 屏数 |
|---|---|---|---|---|
| 车夫（默认折叠） | 35 行 + 7 标题 | 7 行 + 7 按钮 | 约 580px | **0.8 屏** |
| 车夫（全展开） | 35 | 35 | 约 1700px | 2.4 屏 |
| 令牌（营地） | 48 项 | 17 行 + 组按钮横排 | 约 900px | **1.2 屏** |
| 令牌（在无尽回廊） | 58 项 | 27 行（含展开的 A 组） | 约 1250px | 1.7 屏 |
| 令牌（切「仅存活」） | 同左 | 通常 < 10 行 | < 500px | < 0.7 屏 |

**如实说明**：车夫已做到一屏内零滚动；令牌营地视图约 1.2 屏 —— 从 3.9 屏降到 1.2 屏，
但**默认档仍是「全部」**，还会剩一点滚动条。这是刻意取舍：默认隐藏冷却中的 Boss 会让玩家误以为令牌失灵。
若实机觉得仍嫌长，可把默认档改成「仅存活」（改 `set_open` 里的 `_filter = FILTER_ALL` 一行）。
