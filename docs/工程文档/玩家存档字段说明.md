## 1. 存档文件在哪、怎么打开

| 来源 | 路径 | 说明 |
|---|---|---|
| 游戏内槽档 | `user://saves/slot_N.json`（N = 1/2/3） | macOS 实际位置：`~/Library/Application Support/Godot/app_userdata/末法纪元：最后的守护者/saves/slot_1.json` |
| 面板导出的文件 | 由玩家在文件选择器里自选（默认桌面） | 文件名形如 `save_角色名_Lv57_2026-10-17-130236.json` |

**推荐改档流程**：面板「导出」→ 用编辑器改导出文件 → 面板「导入」写回槽位。
不建议直接改 `slot_N.json`：那是**当前正在使用的档**，改坏后自动存档会顺着往下写，损失会扩散。

旁文件（不要手改）：

| 文件 | 作用 |
|---|---|
| `slot_N.json.bak` | 上一份有效档的自动备份（读档失败时自愈回退用） |
| `slot_N.json.tmp` | 原子写入的中间文件；正常情况下不应存在 |
| `slot_N.json.corrupt` | 判定损坏时的现场保留件 |
| `display_preferences.json` | **本机屏幕偏好**，不属于角色档，不入导出文件（见 §4.10） |

## 2. 文件格式基础

- **编码**：UTF-8。
- **缩进**：制表符（`\t`）。
- **内容**：单个 JSON 对象（`{...}`），没有外层数组或包装键。
- **数值**：整数与浮点混用；`0.05` 这类是浮点，`1` 这类是整数。手改时保留小数点与否通常不影响（校验接受 int / float）。
- **布尔**：`true` / `false`，**不要**写成 `"true"` 字符串。
- **坐标**：JSON 里没有向量类型，一律写成 `[x, y]` 两元数组。
- **空槽位**：背包 / 仓库 / 装备栏的空位写成 `null`。

## 4. 字段详解

### 4.1 元信息

| 键 | 类型 | 说明 |
|---|---|---|
| `schemaVersion` | int | 当前版本 **14**。校验要求 `11 ≤ 值 ≤ 14`。手改小会触发旧档迁移逻辑（见 §9），改大会被直接拒绝 |
| `slotId` | int | 目标槽写入时会**被强制改写**成目标槽号，所以玩家改它没有意义 |
| `savedAt` | string | `Time.get_datetime_string_from_system()` 输出的本地时间串，形如 `2026-10-17T13:02:36`。只用于存档卡显示，随便改不影响游戏逻辑 |

### 4.2 `player` —— 角色属性

| 键 | 类型 | 默认值 | 允许范围 | 含义 |
|---|---|---|---|---|
| `name` | string | `守护者` | **非空**，导入时截断到 16 字 | 角色名 |
| `level` | int | 1 | 1 – 999 | 等级 |
| `xp` | int | 0 | ≥ 0 | 当前等级的经验值 |
| `hp` | int | 102 | ≥ 0（无上界） | 当前生命值；**上限是派生的**（见下） |
| `mp` | int | 35 | ≥ 0（无上界） | 当前法力值；上限派生 |
| `attack` | number | 12 | ≥ 0 且 ≤ **999999** | 基础攻击力 |
| `defense` | number | 5 | ≥ 0 且 ≤ **999999** | 基础防御力 |
| `dodge` | number | 0 | ≥ 0 且 ≤ **999999** | 闪避（首版占位） |
| `block` | number | 0 | ≥ 0 且 ≤ **999999** | 格挡（首版占位） |
| `cdr` | number | 0.0 | ≥ 0 且 ≤ **0.5** | 冷却缩减（加法累加，上限 0.5） |
| `criticalChance` | number | 0.05 | ≥ 0 且 ≤ **0.75** | 暴击率 |
| `criticalMultiplier` | number | 1.5 | **1.0 – 5.0** | 暴击倍率 |
| `attackInterval` | number | 0.8 | ≥ **0.2**（无上界） | 攻击间隔（秒），越小越快 |
| `movementSpeed` | number | 4.0 | ≥ 0 且 ≤ **100** | 移动速度 |

补充说明：

- `hp` / `mp` 存的是**当前值**，上限由公式派生，改大上限要动 `level` / `attack` / `defense` 或装备：
  - 最大生命 = `(50 + 等级×8 + 总攻击×2 + 总防御×4) × (1 + 生命%) + 生命固定值`
  - 最大法力 = `(30 + 等级×5) × (1 + 法力%) + 法力固定值`
  - 「总攻击」= `player.attack` + 装备固定加成；装备加成永远不进 `attack` 本身。
- 想看血量上限：改完 `level` 后 `hp` 建议一并改高（`hp` 本身没有上界，写大也只是被上限截断读取）。
- `player` 里**多出来的键不会被拒绝**（例如 `hpFlat` / `hpPercent`），但不能是负数。

### 4.3 `gold` —— 金币

- 整数，范围 `0 – 999999999`。超上限会被拒。
- 金币**不是背包物品**，不要往 `inventory` 里塞 `kind: "coin"` 的对象（会被判非法）。

### 4.4 地图与位置

| 键 | 说明 |
|---|---|
| `currentMap` | 必须是对应 `map.json` 存在的 ID（如 `camp`）。写未知 ID 会被拒 |
| `visitedMaps` | 每个元素也必须是已知地图 ID。用于车夫直达 / 传送的可选目的地 |
| `playerPos` | `[x, y]` 世界坐标（像素）。可写 `null`（表示按地图出生点进入）。写错位置可能卡进障碍，谨慎改 |
| `mapLayoutVersion` | **不要手改**。此值不等当前版本时会触发坐标重映射与营地迷雾重置：玩家可能被搬到营地图中、已探索区域被清空 |

### 4.5 背包与仓库

| 键 | 说明 |
|---|---|
| `inventory` | 数组，空位 `null`。**长度必须严格等于容量**，否则被拒 |
| `inventoryExpansions` | 扩容次数，整数 `0 – 16` |
| `warehouse` / `warehouseExpansions` | 与背包同规则 |

容量公式：`容量 = min(200, 40 + 扩容次数 × 10)`。

也就是说：**想扩充背包格数，必须同时改 `inventoryExpansions` 和 `inventory` 的数组长度**（多出来的格子填 `null`）。只改一个会被判非法。

### 4.6 `equipment` —— 已穿戴装备

- 对象，**必须恰好 14 个键**，键名固定，缺一个就非法：

| 槽 id | 部位 |
|---|---|
| `weapon` | 武器 |
| `shield` | 盾牌 |
| `helmet` | 头盔 |
| `armor` | 护甲 |
| `shoes` | 鞋子 |
| `necklace` | 项链 |
| `bracer_1` / `bracer_2` | 护腕 ×2 |
| `knee_1` / `knee_2` | 护膝 ×2 |
| `bracelet_1` / `bracelet_2` | 手镯 ×2 |
| `ring_1` / `ring_2` | 戒指 ×2 |

- 每个槽的值要么是 `null`（空槽），要么是一个**装备实例**（结构见 §5.1），且该装备的部位必须与槽 id 匹配（武器只能进 `weapon` 等）。

### 4.7 坐骑

| 键 | 说明 |
|---|---|
| `ownedMounts` | 坐骑 ID 数组，元素必须来自坐骑配置表，**不可重复** |
| `activeMount` | `""`（未骑乘）或 `ownedMounts` 里的某个 ID。写列表外的 ID 会被拒 |

### 4.8 任务

| 键 | 类型 | 说明 |
|---|---|---|
| `questStates` | object | `任务ID → {"state": 状态, "progress": 进度}` |
| `questItems` | object | 任务物品 ID → 数量（整数） |
| `questRewardPlans` | object | `任务ID → {"item": 装备/物品, "bonus": [物品…]}`，是「已抽好、尚未发放」的奖励实例 |

`state` 的 6 种合法值：

| 值 | 含义 |
|---|---|
| `locked` | 未解锁（前序任务未完成） |
| `available` | 可接取 |
| `active` | 进行中 |
| `completed` | 已完成待交 |
| `rewarded` | 已领奖 |
| `abandoned` | 已放弃 |

- `progress` 为非负整数；若某任务的进度已达需求值而状态仍是 `active`，读档时会自动补为 `completed`。
- 值合法但任务 ID 不认识时：键会保留，但任务层按「不存在」处理。
- 直接把某任务写成 `rewarded` 可以跳任务，但**不会**自动补发奖励（奖励在正常流程里发）。

### 4.9 首杀与解锁

| 键 | 说明 |
|---|---|
| `firstClear` | `{boss_id: true}`，键必须是怪物表里 `kind = "boss"` 的 ID |
| `unlocks` | `{unlock_id: true}`，键必须是任务奖励或 Boss 首杀奖励里登记过的解锁 ID（例如 `chapter2`） |

两个表的值都必须是布尔。想解锁第二章之类的章节入口，就往 `unlocks` 里加对应的键。

| `autoBattleDefault` | bool | false | 开局自动战斗默认开关 |
| `autoPickupDefault` | bool | false | 开局自动拾取默认开关 |
| `potionThreshold` | number | 0.35 | **0.0 – 1.0**（喝药血量阈值） |
| `searchRadius` | number | 12 | **1 – 99**（旧档兼容字段） |
| `allowBoss` | bool | false | 自动战斗是否打 Boss |
| `dropFlyAnim` | bool | true | 拾取飞行动画 |
| `autoReviveOnDeath` | bool | false | 死亡后自动原地复活（需背包有复活卷） |
| `masterVolume` | number | 1.0 | **0.0 – 1.0** |
| `sfxVolume` | number | 1.0 | **0.0 – 1.0** |
| `musicVolume` | number | 1.0 | **0.0 – 1.0** |
| `screenShake` | bool | true | 震屏 |
| `strongFlash` | bool | true | 强闪光 |
| `qualityFilter` | string | `all` | `all` / `rare` / `epic` / `legendary`（自动拾取过滤） |
| `colorblindMode` | string | `off` | `off` / `friendly` |
| `tutorialSeen` | bool | false | 教学已看 |

| `keyBindings` | object | `{}` | `动作名 → 物理键码（正整数）`，键不可重复 |
| `uiScale` | number | 1.0 | **0.8 – 2.0** |
| `textScale` | number | 1.0 | **0.8 – 2.0** |

`keyBindings` 的可选动作名（键名写别的会被拒）：

```
panel_map, panel_skill, panel_mount, mount_toggle,
hotbar_1 … hotbar_12
```

### 4.11 `hotbar` —— 快捷栏

- 数组，**恰好 12 个元素**。空位写 `null`。
- 有内容的格子必须是**恰好两个键**的对象：`{"kind": ..., "id": ...}`。

| `kind` | `id` 允许值 |
|---|---|
| `auto_potion` | `red` / `blue` |
| `potion` | 药品配置表里的 ID |
| `skill` | `basic_slash` / `earth_cleave` / `whirlwind` / `battle_focus`（且技能表里有） |
| `item` | `misc_town_scroll` / `misc_random_ticket` |

默认布局：第 1 格红药、第 2 格蓝药、第 3 格基础斩击，其余空。

### 4.12 `exploredMaps` —— 地图迷雾

结构：`{地图ID: [已探索区块编号…]}`。

- 每张地图按 **4×4 格**划分一个区块。
- 区块编号 = `(格子y / 4) × 行内区块数 + (格子x / 4)`，其中 `行内区块数 = ceil(地图宽 / 4)`。
- 举例：营地 110×110 → 每行 `ceil(110/4) = 28` 个区块 → 共 `28 × 28 = 784` 个，编号 `0 – 783`。
- 写整段 `0 … 783` 即可把营地整图点亮。
- 读档时会被归一化：未知地图、非整数、负数或超出该地图区块总数的编号会被**丢弃**（不会拒档）。

### 4.13 `worldTime` 与 `spawnRespawn` —— 时钟与怪物刷新

| 键 | 说明 |
|---|---|
| `worldTime` | 世界时钟，单位**秒**，浮点，≥ 0。读档后从这里继续累计；真实离线时间不计入 |
| `spawnRespawn` | 怪物点刷新倒计时表 |

`spawnRespawn` 结构：`{"<地图ID>#<怪物ID>#<同种序号>": {"readyAt": 秒, "pos": [x, y]}}`

- `readyAt`：到该 `worldTime` 时该怪物点刷新（**墓碑**就是靠它跨图保留的）。
- 只记录**尚未刷新完成**的点，到点即从表里删除。
- **清空整张表**（写成 `{}`）= 所有怪物点立刻可刷新，墓碑全部消失。
- 未知 key 不会拒档（地图数据变动不该导致读档失败）。

### 4.14 `unclaimedLoot` —— 未领取战利品

结构：`{地图ID: [ {"uid": 串, "batchId": 串, "item": 物品对象, "pos": [x, y]} … ]}`

- 精英 / Boss 掉落**入包失败**时保留在地面的物品（跨图、跨档保留，直到领取或丢弃）。
- `item` 可以是普通物品、装备，也可以是两种「地面专用」对象：金币（`kind: "coin"`）与坐骑（`kind: "mount"`）——它们只在未领取记录里允许出现。
- 清空 `{}` = 地面遗留物全部消失。

## 5. 物品实例结构

### 5.1 装备实例（`kind = "equip"`）

| 键 | 类型 | 约束 | 含义 |
|---|---|---|---|
| `kind` | string | 固定 `equip` | 类别 |
| `itemId` | string | 必须在装备配置表存在 | 模板 ID |
| `instanceId` | string | **非空** | 实例唯一编号（生成一次后永久不变） |
| `equipmentRuleVersion` | int | **必须恰好 = 4** | 装备规则版本 |
| `requiredLevel` | int | ≥ 1，且**必须等于模板的 `requiredLevel`** | 穿戴等级 |
| `level` | int | **必须等于 `requiredLevel`** | 同值冗余字段 |
| `quality` | string | 5 品质之一 | 品质 |
| `star` | int | **0 – 12** | 星级 |
| `rawBaseAttrs` | object | **非空**；键限 `atk` / `def` / `hp` / `mp`；值 ≥ 0（**无上界**） | 生成时的基底数值快照 |
| `qualityMultiplierSnapshot` | number | **> 0 且 ≤ 100** | 生成时的品质系数快照 |
| `starMultiplierSnapshot` | number | **0 – 1** | 星级成长系数快照 |
| `affixes` | array | 见下 | 固定值词条 |
| `pctAttrs` | array | 见下，**最多 1 条** | 百分比词条 |
| `count` | int | **必须 = 1** | 装备不可堆叠 |

- 词条（`affixes` 与 `pctAttrs` 的元素）结构：`{"stat": 属性名, "value": 数值}`。
  - `stat` 白名单：`atk` / `def` / `hp` / `mp` / `hpPercent` / `mpPercent` / `cdr`。
  - 同一件装备内 `stat` **不可重复**，`value` ≥ 0（**无上界**）。
  - `affixes` + `pctAttrs` **合计最多 4 条**，其中 `pctAttrs` 最多 1 条。
- 品质取值：`common`（普通）/ `uncommon`（优秀）/ `rare`（稀有）/ `epic`（史诗）/ `legendary`（传说）。
- **可改**：`rawBaseAttrs` 的数值、词条 `value`、词条 `stat`（在白名单内且不重复）、`star`（≤12）。
- **不可改**：`itemId`（改成不存在的模板会被丢）、`requiredLevel` / `level`（必须与模板一致）、`equipmentRuleVersion`（必须 = 4）、`count`（必须 = 1）。
- 迁移时**无法识别的装备实例会被逐件丢弃**（不会整档拒绝），例如引用了已下架模板的装备。

### 5.2 消耗品 / 杂项 / 如意（可堆叠）

| 键 | 类型 | 约束 |
|---|---|---|
| `kind` | string | `potion` / `misc` / `quest` / `rune` |
| `itemId` | string | 必须存在于对应配置表（`misc` 与 `quest` 都在杂项表） |
| `count` | int | **1 – 堆叠上限**（默认 99；药品以 `potions.json` 的 `stackMax` 为准） |

> 这条约束很关键：**把 `count` 改成 999 会被拒**，因为超过堆叠上限。

### 5.3 地面专用对象（只出现在 `unclaimedLoot`）

| 结构 | 约束 |
|---|---|
| 金币：`{"kind": "coin", "itemId": "coin", "gold": N, "count": 1}` | `gold` 整数 `1 – 999999999` |
| 坐骑：`{"kind": "mount", "itemId": "坐骑ID", "count": 1}` | `itemId` 必须是已知坐骑，`count` 必须 = 1 |

## 6. 校验规则：能改什么、不能改什么

### 6.1 导入流程（改了之后会发生什么）

1. 读取文件并解析 JSON —— 解析失败 → 拒绝，**目标槽不变**。
2. 版本前置检查 —— `> 14` 提示「来自更新版本」；`< 11` 提示「版本过旧」；两者都拒绝落盘。
3. 全量结构校验（即本节规则）—— 任何一条不满足 → 拒绝并给出**字段级原因**，**目标槽不变**。
4. 通过后：目标槽已有**有效**档 → 先复制成 `.bak`；再原子写入。
5. **不自动读取**：导入只是写文件，要在槽卡上再点「读取」才进入该角色。

### 6.2 硬上界一览（改不进去的值）

| 字段 | 上界 |
|---|---|
| `player.attack` / `defense` / `dodge` / `block` | 999,999 |
| `player.criticalChance` | 0.75 |
| `player.criticalMultiplier` | 1.0 – 5.0 |
| `player.cdr` | 0.5 |
| `player.attackInterval` | ≥ 0.2 |
| `player.movementSpeed` | 100 |
| `player.level` | 999 |
| `gold` | 999,999,999 |
| 装备 `star` | 12 |
| 堆叠物 `count` | 堆叠上限（默认 99） |
| 装备词条条数 | 合计 4（`pctAttrs` 最多 1） |

### 6.3 结构性约束（改了会被拒）

- 顶层 27 个键**一个不能少**。
- `inventory` / `warehouse` 的数组长度必须等于 `容量 = min(200, 40 + 扩容次数 × 10)`。
- `equipment` 必须恰好 14 个槽，装备部位必须与槽匹配。
- 背包 / 仓库**不允许出现金币**；`count` 必须是整数。
- 地图 / 坐骑 / 任务物品 / 装备模板 ID 必须能在配置表里找到。
- `hotbar` 必须恰好 12 项，有效项必须恰好两个键。
- `settings` 中枚举键只能取表内值，数值键只能落在区间内（§4.10）。

### 6.4 「改得进去」的空间（合法作弊面）

- 金币、等级、经验；
- 物品数量（在堆叠上限内）；
- 装备基底数值（无上界）、装备词条数值（无上界）、词条类型（白名单内）、星级（≤12）；
- 任务状态、任务物品计数、首杀、解锁；
- 迷雾全开、墓碑清空、未领取战利品增删；
- 快捷栏、设置（区间内）。

## 7. 常用改档配方

> 所有示例都基于自己在编辑器里改**导出的文件**，然后导入。改完保存时注意保持 UTF-8。

**① 加金币**

```json
"gold": 999999999
```

**② 升级并补满血蓝**

```json
"player": { "level": 60, "attack": 800, "defense": 300, "hp": 99999, "mp": 99999, "...": "其余键保留" }
```

注意 `attack` / `defense` 别超过 999999；`hp` / `mp` 没有上界，写大即被上限截断读取。

**③ 点亮整张营地地图**

```json
"exploredMaps": { "camp": [ …0 到 783 的整数… ] }
```

（区块编号范围取决于地图尺寸，算法见 §4.12。）

**④ 清掉全部怪物墓碑（立刻全刷）**

```json
"spawnRespawn": {}
```

**⑤ 扩充背包 5 次（容量变成 90 格）**

```json
"inventoryExpansions": 5,
"inventory": [ …长度必须是 90，多出来的位置填 null… ]
```

**⑥ 给一件装备加满词条**

在原装备实例上修改 `affixes` / `pctAttrs`（合计 ≤4，`pctAttrs` ≤1，`stat` 不重复）：

```json
"affixes": [
  { "stat": "atk", "value": 500 },
  { "stat": "def", "value": 300 }
],
"pctAttrs": [ { "stat": "hpPercent", "value": 2.5 } ]
```

**⑦ 解锁第二章**

```json
"unlocks": { "chapter2": true }
```

（键必须是配置表里登记过的解锁 ID。）

**⑧ 跳任务**

把 `questStates` 里某任务的 `state` 改成 `rewarded`。注意不会补发奖励。

## 8. 改坏会怎样、怎么安全改

**改坏的真实后果**（按严重度）：

1. **被拒绝落盘**（最常见）：界面提示字段级原因，目标槽**原封不动**——这种情况没有任何损失。
2. **通过校验但游戏内表现异常**：例如坐标写进障碍里导致角色卡住、`equipment` 里放了部位不符的装备。
3. **损坏已有的 `.bak`**：只有在你先导入一个**校验通过**的档覆盖了有效主档时才会发生；原主档会转成 `.bak`，所以仍可恢复。

**安全改档步骤（建议照做）**：

1. 在游戏内先「保存」一次，确认当前进度已落盘。
2. 用面板「导出」拿到文件，**另外复制一份**作为原始备份。
3. 在编辑器里改副本，只改本文档标明「可改」的字段。
4. 导入到一个**非活动槽**（活动槽禁止导入），先「读取」验证效果。
5. 确认无误后，正常保存即可。
6. 万一不对：把之前复制的原始文件导入回去覆盖。
7. 连导入都进不去：把导出的原始文件重命名放到 `saves/` 目录下成为 `slot_N.json` 也可以（但**先备份当前 `slot_N.json`**）。

**几条容易踩的坑**：

- 别改 `schemaVersion` / `mapLayoutVersion`（会触发迁移，可能把角色搬走、清空迷雾）。
- 别把 `count` 写超过堆叠上限。
- 别只改 `inventoryExpansions` 而不改 `inventory` 长度。
- JSON 里不能有尾随逗号、注释、单引号；`true` / `false` 不加引号。
- 编辑时把文件另存为其它编码（如 GBK）会导致解析失败。

## 9. 版本与迁移

| 概念 | 值 | 说明 |
|---|---|---|
| 当前版本 | `CURRENT_SCHEMA = 14` | 新存 / 导出的都是 14 |
| 可读下限 | `MIN_READABLE_SCHEMA = 11` | 低于 11 的档**明确拒绝**（提示「版本过旧」） |
| 版本上限 | 同当前版本 | 高于 14 的档**明确拒绝**（提示「来自更新版本」，需升级游戏） |

导入 / 读档时会执行**迁移**：为旧档补齐新增字段的默认值。与玩家改档相关的迁移行为：

| 情况 | 行为 |
|---|---|
| 缺 `mapLayoutVersion`（或值过旧） | 执行营地坐标重映射 + 营地迷雾重置（角色可能被搬到营地图中） |
| `schemaVersion` ≤ 6 | 快捷栏重置为默认布局 |
| `schemaVersion` ≤ 7 | `worldTime` 归零、墓碑清空 |
| `schemaVersion` ≤ 8 | 未领取战利品清空 |
| `schemaVersion` ≤ 9 | `visitedMaps` 重置为 `["camp"]`（外加当前地图） |
| `schemaVersion` ≤ 10 | 背包扩容次数归零、背包压缩回 40 格 |
| 装备实例无法识别（模板已下架等） | **逐件丢弃**，不整档拒绝 |
| `questItems` / `questRewardPlans` 缺键 | 补为空集合，不报错 |
| 角色名超过 16 字 | 导入时截断，并提示已截断 |

> 因此：**手改 `schemaVersion` 会触发上面这些迁移**，通常只会造成损失，不建议动。
