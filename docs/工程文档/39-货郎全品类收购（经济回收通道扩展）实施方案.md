## 1. 一句话结论

**改动面小（4 个代码文件 + 2 个数据文件 + 15 条文案），但有三个必须先修的静默坑**：① `sell_price()` 不读 `count` —— 直接放行会「一叠 99 瓶只算 1 瓶钱」；② `matches_low_gear()` 依赖 `can_sell()` —— 放行后药水会被「一键移入」误判成低价值装备批量塞进托盘；③ **（实施期新发现）托盘拖入按 `instanceId` 反查，而药水 / 材料没有 `instanceId`** —— 不放行时表现为「不可售」，放行后表现为「拖不进」，功能照样不可用（§3.3）。

无存档 schema 变更、无迁移、无跨系统耦合。**真正的成本不在代码量，在「价格口径」这个产品决策上。**

## 3. 🔴 两个必须先修的静默坑（重点）

### 3.1 G2 整叠计价 —— 最危险

现状 `sell_price()`：

```gdscript
static func sell_price(item: Dictionary) -> int:
	var base := base_value(item)          # 只看模板单价
	var mult := float(QUALITY_SELL_MULT.get(item_quality(item), 1.0))
	var star := int(item.get("star", 0))
	return int(round(float(base) * mult * (1.0 + float(star) * STAR_SELL_BONUS)))
```

**完全忽略 `count`**。装备 `count` 恒为 1，所以从未暴露；药水一叠 `count` 可以到 99。

⇒ 若只改 `can_sell` 就上线：玩家拖一叠 99 瓶中红药进托盘，界面显示「结算 60 金币」。**这是玩家能直观看到并投诉的损失型 bug**，必须在同一批内修掉。

修法：`sell_price` 末尾乘 `maxi(1, int(item.get("count", 1)))`（装备恒 1，行为不变）。

### 3.2 G4 一键移入误伤

`Shop.matches_low_gear()` 是「货郎一键移入」与「背包一键卖出」共用的筛选：

```gdscript
static func matches_low_gear(item, level_limit, max_quality) -> bool:
	if not can_sell(item) or level_limit < 1:
		return false
	var quality_rank := QUALITY_ORDER.find(item_quality(item))
	var maximum_rank := QUALITY_ORDER.find(max_quality)
	return quality_rank >= 0 and maximum_rank >= 0 \
		and Equipment.level_req(item) < level_limit and quality_rank <= maximum_rank
```

药水：`item_quality()` 回退 `"common"`（rank 0）、`level_req()` 回退默认 `1` → **默认筛选（< Lv5 且 ≤ 普通）全部命中**。

⇒ 玩家点「一键移入」，会把自己全部药水塞进托盘。随后点「确认出售」= 身上一瓶药都不剩，打 Boss 时无药可喝。**这是「卖光保命资源」级别的事故**。

修法：`matches_low_gear` 首行改为 `if String(item.get("kind","")) != "equip" or not can_sell(item) or level_limit < 1: return false`。**筛选语义永远是「装备」**，与收购范围解耦。

### 3.3 G9 托盘拖入按 instanceId 反查（实施期新发现，阻断级）

原 `ShopPanel._on_tray_drop` 用 `_index_of_instance(item.instanceId)` 反查背包下标（工程 05 🔴R1 的防下标位移设计）。而 `ItemFactory.make_any` 对药水 / 杂项 / 如意只产出 `{kind, itemId, count}` —— **没有 `instanceId`**（`instanceId` 只由装备生成入口写入）。

⇒ `instanceId` 为空 → 反查恒返回 -1 → 一律提示「该装备已不在背包」。**即使 `can_sell` 放行，药水也拖不进托盘**，功能完全不可用。

修法：拖拽载荷本来就带背包下标（`ItemSlot._get_drag_data` 的 `index`），改为**优先用载荷下标 + 逐字段核对**（kind / itemId / count / instanceId 全等才认），核对失败再回退 `instanceId` 反查。既修掉 G9，也保持对「拖拽期间背包变动」的防护。

## 4. 决策点（✅ 已拍板）

### 4.1 D-1 非装备回收比例（🔴 决定经济平衡）

药水的 `potions.price`（20 / 60 / 150）**同时是货郎卖价**（`shops.json` 的 `buyItems.price` 同值）。若原价回收 = 无损，等于「金币 ⇄ 药水」自由兑换，金币掉落的意义被稀释。

| 选项 | 口径 | 中红药一叠 99 瓶 | 评价 |
|---|---|---|---|
| A | 全价 1.0 | 5940 金 | 玩家最爽，但药水≈硬通货 |
| B（原推荐） | 非装备统一 **0.5** | 2970 金 | 「半价回收」直觉清晰；装备不动，现有售价断言零改动 |
| **C ✅ 拍板** | 非装备统一 **0.6** | **3564 金** | 略宽松；玩家囤积量下回收额更「解气」，仍远低于买价 ⇒ 无套利 |
| D | 按品类分级（药水 0.5 / 材料 0.3 / 如意 1.0） | — | 精细但要维护更多常量 |

**结论（用户拍板）：取 C —— `SELL_RATIO_NON_EQUIP := 0.6`，只作用于非装备。** 装备继续 1.0 ⇒ 现有 50 / 150 / 162 三条装备售价断言数值不变。

### 4.2 D-2 整叠出售口径

| 选项 | 说明 |
|---|---|
| **A（推荐）** | 整叠一次卖完（`单价 × count`）。托盘显示「中红药 ×37」，摘要显示总价 |
| B | 拖一次只卖 1 瓶（99 瓶要点 99 次，不可接受） |
| C | 弹出数量选择器（多一层 UI，收益低） |

推荐 A。误卖风险由「暂存 → 确认出售」两步 + 托盘可取回兜住。

### 4.3 D-3 可售白名单

| 品类 | 可售 | 理由 |
|---|---|---|
| `equip` | ✅ | 现状 |
| `potion` | ✅ | **本次主诉求** |

### 4.4 D-4 任务物品兜底

`miscItems` 里 21 条 `c2_*` / `c3_*` … 是**任务收集物**（当前走 `quest_items` 独立袋，不入包）。仍建议给它们打 `"questItem": true` 标记，`can_sell` 直接排除 —— **零成本兜底**，防止将来改动把任务物塞进背包后玩家能卖掉。

### 4.5 D-5 一键清理入口

现状只有「一键移入」（只筛装备）。药水动辄 4~6 格、几十上百瓶，手动拖不可接受。

| 选项 | 说明 |
|---|---|
| **A（推荐）** | 出售页新增第二个按钮「一键移入材料」：药水 + 杂项 + 如意，排除任务物品，填满 24 格为止 |
| B | 让现有筛选支持品类多选（控件改造大） |
| C | 不做，全靠手动（体验差，用户诉求打不满） |

⚠ 按钮栏现有 3 个 96px 按钮 + 弹性空白；加第 4 个需确认最小宽度不撑破面板（`BUY_ROW_MIN.x = 430`），必要时把按钮宽度降到 84 或让按钮栏换行。

### 4.6 D-6 如意可售性

如意是**升星唯一材料**（`runes.json` 四档，铁/玉已投产，金/钻石暂无产出源）。用户口径是「爆出来的都能卖」，故**可售**；但建议在托盘告警行（`_tray_warn`，现用于「N 件优于已穿戴」）追加一条：**「含 N 件升星材料」**，防止手滑清空升星资源。

### 4.7 D-7 启动校验

`DataLoader` 增加一条：**可售品类（potions / miscItems / runes）中，未被 `questItem` 排除的条目必须 `price > 0`**。否则新加物品忘配价 → 静默卖 0。这是 G3 的长期防线。

## 6. 落地方案（按层）

### 6.1 判定与计价（`scripts/systems/shop.gd`）

```gdscript
## 6.4（2026-10-17 修订）：货郎收购全部掉落品类，任务物品除外。
const SELLABLE_KINDS := ["equip", "potion", "misc", "rune"]
## 非装备回收比例（D-1-B）；装备保持 1.0，不动现有售价断言。
const SELL_RATIO_NON_EQUIP := 0.5

static func can_sell(item: Dictionary) -> bool:
	if not SELLABLE_KINDS.has(String(item.get("kind", ""))):
		return false
	if String(item.get("kind", "")) == "misc" \
			and bool(_template(String(item.get("itemId", ""))).get("questItem", false)):
		return false
	return base_value(item) > 0          # 无价 ⇒ 拒绝，不静默卖 0

static func sell_price(item: Dictionary) -> int:
	var base := base_value(item)
	if base <= 0:
		return 0
	var mult := float(QUALITY_SELL_MULT.get(item_quality(item), 1.0))
	var star := int(item.get("star", 0))
	var unit := float(base) * mult * (1.0 + float(star) * STAR_SELL_BONUS)
	if String(item.get("kind", "")) != "equip":
		unit *= SELL_RATIO_NON_EQUIP
	var count := maxi(1, int(item.get("count", 1)))       # G2：堆叠计价
	return int(round(unit)) * count
```

> ⚠ `int(round(unit)) * count`（先取整单价再乘数量）而不是 `round(unit * count)`：保证「单价 × 数量 = 总价」可被玩家手算复核。

**`matches_low_gear()` 加装备硬门槛（G4）**：

```gdscript
		return false
	...
```

## 7. 经济影响测算（供 D-1 决策参考）

以玩家现有体验「药爆仓」为基准，估算半价（0.5）方案下的一次性回笼：

| 场景 | 库存 | 半价回收 | 参照 |
|---|---|---|---|
| 中期（L30 左右）囤 2 叠中红 + 1 叠中蓝 | 297 瓶 | 297 × 36 = **10692** 金 | ≈ 13 个 Boss 金币（Boss 720–880） |
| 后期（L50）囤 4 叠大红 | 396 瓶 | 396 × 90 = **35640** 金 | ≈ 42 个 Boss |
| 单件参照 | 1 瓶中红 | 36 金 | 精英掉金币 48–72 |

**判断（按拍板的 0.6 重算）**：药水仍是可观金源，但**不会压倒 Boss / 精英的金币产出**（一次清空 ≈ 十来个到四十个 Boss，而那是几十小时的积累）。回收价恒低于买价（20 买 → 12 卖），不存在套利。

> 注：如意售价较高（铁 180 / 玉 480），但 Boss 如意掉率 30%、单只 Boss 期望 0.3 个，且如意是升星唯一材料，玩家大概率不会卖 —— 实际影响小。
