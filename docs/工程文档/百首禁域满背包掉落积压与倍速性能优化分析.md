# 百首禁域满背包掉落积压与倍速性能优化分析

2026-11-02。玩家反馈满背包、地面装备大量积压后开启倍速，画面退化为幻灯片。本轮为代码分析和优化规划，尚未按玩家实际掉落量、倍率与视口进行窗口性能采样；下文是已确认的执行路径及待测热点，不是已完成的瓶颈占比测量。

## 当前仍有优化空间

百首禁域配置unclaimedLootCap=2400。已有优化包括掉落物远处停止重绘、附近约10Hz更新，以及AutoBattle满包时0.25游戏秒扫描节流。不能重复把这些已实现功能当成新方案，也不能称远处物品完全没有成本。

GroundItem._physics_process仍对每个掉落节点推进时间、检查显示与生命状态；自动拾取开启时，每件未认领物品仍查找玩家并检查距离。附近物品会反复执行_try_pickup，进入GameState.pickup_loot的入包或自动出售判定。失败提示有冷却，不等于失败尝试有冷却。AutoBattle的满包早退没有覆盖这条物品自身的拾取路径。

AutoBattle._find_loot仍以get_nodes_in_group收集并遍历全部地面物；满包也需要搜索金币，无法简单全部关闭。_bag_full每次通过Inventory.is_full扫描占用数量，且“格子全占用”不能等同于“任何物品均不能领取”：已有可叠加余量、金币以及自动出售/替换装备可能仍可处理。这些例外必须保留或修正，不能用粗略满包判断提升速度。

GroundItem的0.1秒重绘、0.3秒距离复查及AutoBattle的0.25秒扫描均使用传入delta推进。修改Engine.time_scale会缩短这些游戏时间间隔对应的现实时间，导致表现与失败检查更频繁；大倍率还会加快击杀、掉落和特效生成。time_scale本身不必然让物理回调次数等比例增加，不能笼统地说8倍速就执行8倍物理帧；还要检查physics_ticks_per_second是否另被修改。

## 推荐优化顺序

1. **先消除不能成功的重复拾取。** 统一附近自动拾取入口，共用背包/装备/出售策略的版本号；一次失败后，在相关状态未变时不重复扫描背包或执行出售评分。腾出空间、堆叠消耗、换装、金币变化、出售预设变化后失效缓存。手动点击仍立即尝试并反馈，金币、叠加与自动出售不可被一刀切屏蔽。
2. **把全场遍历改为附近候选查询。** 为地面物建立空间桶，玩家只查附近桶；出生、认领、消失、切图维护索引。集中调度拾取和远近状态检查，避免2400个节点各自寻找同一个玩家。保留收益认领唯一入口与不可重复结算。
3. **分离真实时间的表现预算。** 拾取候选复查、失败重试和地面浮动重绘按现实时间限频并处理状态变化即时失效；技能冷却、预警、伤害、掉落归属仍保持原游戏时间。不要通过降低碰撞频率、延迟手动输入或修改奖励换性能。
4. **根据测量减少地面对象和透明绘制。** 保留真实掉落记录，把静止掉落的显示集中批绘，附近交互对象再激活；视野外休眠。先做可见数量、绘制调用和CPU节点成本对照，再决定是否需要合批或对象池。不能把“相同模板装备”合并成同一个装备实例，不能删掉持久奖励。
5. **复测Boss与掉落生成峰值。** 若积压处理已改善但仍掉帧，再针对同帧大量死亡、掉落节点装配、伤害数字及技能装饰做分批或表现预算；真实结算和奖励记录不能延后丢失。现有积压上限保护继续保留，不用缩小上限假装优化。

## 验收方式

先建立隔离、可重复的合成场景：固定人物、窗口、地图、Boss数量与设置；掉落0/600/1200/2400件，空包/满包，倍率1/2/4/8，分别开关自动拾取。记录实际倍率设置方法、引擎物理频率和活跃Boss数。

实际窗口测整帧中位数、P95/P99、峰值，另记脚本/物理耗时、绘制调用、节点数、纹理与内存。用诊断开关分别冻结掉落表现、停止拾取查询、冻结Boss AI做对照，只在探针里使用，不进入正式玩法。根据差值确定优化优先级，不先承诺FPS。

优化后必须覆盖满包仍可领金币、堆叠余量、自动出售与换装保护、手动点击、腾格后恢复、保护期、拾取开关、切图与读档、持久掉落及认领恰好一次。随后持续运行固定时长，检查节点/内存与帧时间是否增长。所有测试使用独立user目录，不读写玩家真实存档。

建议每个节点验证后独立commit。本轮尚未修改游戏逻辑，也未声称找到了全部实际瓶颈。
