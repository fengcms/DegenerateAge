## 1. 一句话结论

**M10-4 真正要修的不是「加三条 JSON」，而是 `useType` 这条断掉的执行链。**

现状是：`useType` **有校验、有文案、没有执行**（P-6）。只往白名单里加 `"panel"`，结果是启动校验通过、说明文案写「可使用」、双击却弹「不能直接使用」——**文案与行为互相打脸**，比直接报错更难查。

所以本批交付的是「**一条可执行的 `useType` → 面板 通道**」+ 三件道具 + 一个 60 级门槛的发放任务。面板内容由 M10-5/6/7 分别填。

## 3. 设计决策

### 3.1 P-6：一条分发链，三处必须同批改

| 层 | 现状 | 改法 |
|---|---|---|
| 校验（启动期） | 白名单 5 项 | 加 `"panel"`；`panel` 必须带**已登记**的 `panelId`；**非 `panel` 带 `panelId` 也报错**（互斥两个方向都报，同 `levelFromBoss` / `levelFromPlayer` 的坑） |
| 执行（运行时） | 硬编码 itemId | `GameState.use_item` 的 misc 分支 → `_use_misc()`：按 `useType` 分发 `townPortal / randomTeleport / panel`；其余保持原「无法使用」兜底 |
| 文案 | match 4 项 | 加 `"panel"` → 「使用：打开%s」，面板名取 `PanelRouter` 的标题 key |

**为什么按 `useType` 分发而不是继续加 itemId**：三件道具的 id 会写进数据，若执行层再硬编码一次，以后每加一件「面板道具」就要改一次代码 —— 这正是 P-6 的病根。`townPortal / randomTeleport` 的现有实现（`TravelItem.use_town_scroll / use_random_ticket`）原样调用，行为零变化。

### 3.2 `PanelRouter`：`panelId` → 面板，`ready` 按批点亮

```gdscript
class_name PanelRouter
extends RefCounted

const PANELS := {
	"carter": {"ready": true, "title": "ui.panel.portable_carter"},
	"boss_token": {"ready": false, "title": "ui.panel.boss_token"},
	"shop": {"ready": false, "title": "ui.panel.portable_shop"},
}
```

| panelId | 本批 | 理由 |
|---|---|---|
| `carter` | **ready = true** | `CarterPanel` 已存在且能独立打开（F-12）。M10-7 只把「可达范围」扩成 `travel_anywhere` + 七分组，**面板本身现在就能用** |
| `boss_token` | ready = false → **M10-5** | 面板还不存在 |
| `shop` | ready = false → **M10-6** | 现在打开会是**空商店**（无店铺 id），比不打开更糟 |

`open(panel_id)` 返回 `{ok, reason}`，失败文案由 `GameState._use_fail` 统一 toast（**单一出口**，不各写一份）。`useType: panel` **不消耗道具**（永久工具，与卷轴/券的差异必须写死在这里）。

`PANELS` 是 `data_loader` 校验与运行时执行的**同一张表** ⇒ 脏 `panelId` 在启动期就死，不会走到运行时；运行时再查一次只是兜底。

### 3.3 道具数据：**不新增 `bound` 字段**

产品警示 `bound` 全库零命中。核对后确认它要防的两件事都已有现成机制：

| 想防的 | 现成机制 | 结论 |
|---|---|---|
| 卖给货郎 | `questItem: true` ⇒ `Shop.can_sell()` false | 够 |
| 死亡掉落 | `death_penalty` 只挑 `kind == "equip"` | 够（杂项根本不在候选里） |
| 玩家主动丢弃 | **本作没有「丢弃」功能**（`remove_item_at` 只被出售/消耗/死亡调用） | 无对象 |

⇒ 新增一个既不校验也不生效的字段，只会让下一个人以为有防护。**记入文档，不落数据**。

### 3.4 任务 `C6Q13`：`side` + `requiresLevel: 60` + `unlocks` 数组

| 项 | 取值 | 理由 |
|---|---|---|
| 类型 | **`side`** | 不抢 `next_main_lead()` 的「主线末端」（C6Q12 已是第一章主线收口）。`main` 会让交付提示链指到「去领三件套」，把章节结局冲淡 |
| `requiresLevel` | `60` | 门槛本身是本批要落的能力；低于 60 时 NPC 头顶不亮「可接」标记（F-8 自动跟随） |
| `prev` | `C6Q12` | 必须先跑完第六章主线 |
| `objective` | `talk` → `c6_npc01`，`count: 1`，`talkOnAccept: true` | 与 `C6Q01` 同款：接取即完成 → 再点交付领奖（`quest.gd:183` 已支持） |
| `reward.items` | 三件各 `count: 1` | F-10 现成机制；发奖前会先在背包副本上试放（满包整体拒绝，不半发） |
| `reward.unlocks` | 三个 id | 🔴 **必须数组**，见 R-1 |
| `abandonable` | `false` | 三件套是能力入口，不做「放弃后重领」的分支 |

**权限位（`GameState.unlocks`）的定位**：**只做「已发放」的事实记录与丢道具补发依据**，不做功能判定 —— 功能判定一律看背包（否则会出现「背包没了但权限位还在，双击不到入口」或反之的幽灵态）。

### 4.3 `scripts/systems/panel_router.gd`（新）

```gdscript
class_name PanelRouter
extends RefCounted
## M10-4（P-6）：`useType: "panel"` 的唯一执行入口。
## `panelId` 必须先登记在 `PANELS`（`data_loader._validate_misc_items` 用的是同一张表），
## `ready` 由各面板批次点亮；未点亮时**明确失败**，绝不静默。

const PANELS := {...}   # 见 §3.2

static func has(panel_id: String) -> bool:
	return PANELS.has(panel_id)

## 打开面板。返回 {ok, reason}；失败文案由调用方统一 toast。
## ⚠ 不消耗道具 —— 三件套是永久工具。
static func open(panel_id: String) -> Dictionary:
	if not PANELS.has(panel_id):
		return {"ok": false, "reason": Localization.tr_key("msg.panel_router.p001") % panel_id}
	var entry: Dictionary = PANELS[panel_id]
	if not bool(entry.get("ready", false)):
		return {"ok": false, "reason": Localization.tr_key("msg.panel_router.p002")}
	match panel_id:
		"carter":
			EventBus.carter_panel_requested.emit(Localization.tr_key(String(entry.get("title", ""))))
			return {"ok": true, "reason": ""}
	return {"ok": false, "reason": Localization.tr_key("msg.panel_router.p002")}

## 物品说明用：已登记的 panelId → 本地化标题。
static func title(panel_id: String) -> String:
	if not PANELS.has(panel_id):
		return ""
	return Localization.tr_key(String((PANELS[panel_id] as Dictionary).get("title", "")))
```

### 4.4 `autoload/game_state.gd`

misc 分支改为一行转发，新增 `_use_misc`：

```gdscript
		"misc":
			return _use_misc(inv_index, it)
...

## M10-4（P-6）：misc 按 `useType` 分发，不再按 itemId 硬编码 ——
## 否则每加一件「面板道具」都要回来改这段，正是 P-6 的病根。
## 未登记用途（playAnimation / revive / quest / 空）保持原「无法使用」兜底，行为不变。
func _use_misc(inv_index: int, item: Dictionary) -> Dictionary:
	var tpl: Variant = DataLoader.get_entry("miscItems", String(item.get("itemId", "")))
	var use_type := String((tpl as Dictionary).get("useType", "")) if tpl is Dictionary else ""
	match use_type:
		"townPortal":
			return TravelItem.use_town_scroll(inv_index)
		"randomTeleport":
			return TravelItem.use_random_ticket(inv_index)
		"panel":
			var res := PanelRouter.open(String((tpl as Dictionary).get("panelId", "")))
			if not bool(res.get("ok", false)):
				return _use_fail(String(res.get("reason", "")))
			return {"ok": true, "reason": ""}
	return _use_fail(Localization.tr_key("msg.game_state.p027") % ItemUtil.display_name(item))
```

## 6. 风险

| # | 级别 | 风险 | 对策 |
