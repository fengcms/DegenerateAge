# 血蓝条悬停数值实时刷新修复报告

## 现象与影响

玩家将鼠标停在左上角血条或蓝条上时，提示会显示当前值与上限。若期间受伤、回血、施法或回蓝，血蓝条本身会更新，但已显示的提示仍保留弹出时的数字；移开并再次悬停后才显示新数字。影响范围是左上角玩家血量和法力的悬停提示，不改变战斗结算或存档。

## 定位证据与根因

- `scripts/ui/hud.gd` 的 `_on_hp`、`_on_mp` 已订阅 `EventBus.player_hp_changed`、`EventBus.player_mp_changed`，每次数值变化都会更新血蓝条的 `value` 和 `tooltip_text`。
- 原实现只修改来源控件的 `tooltip_text`。Godot 已弹出的原生提示拥有自己的显示内容；更新来源控件的属性不会让这个现存提示重新生成。因此数值模型和血蓝条正确，停留在屏幕上的提示内容却过期。
- 隔离回归 `HudLiveTooltipTest` 保持血蓝两种提示处于打开状态，再分别触发受伤、回血、耗蓝、回蓝事件，覆盖了过去需要重新悬停才能看到新数值的场景。

## 处理方式

`HudStatusBar` 在提示弹出时创建自己的轻量 `PanelContainer` 和文字节点；血蓝条收到 HUD 已有事件写入的新值时，直接更新仍然存活的提示文字。控件只以弱引用持有提示节点，提示关闭后不会遗留强引用或访问失效节点。字号沿用当前文字倍率。没有新增每帧轮询、数据缓存或存档字段：每次数值事件只做一次常数规模的文字更新，提示销毁后弱引用自动失效。

## 复核方法与边界

运行 `python3 tools/run_isolated_tests.py HudLiveTooltipTest SmokeTest`，两项均应输出通过标记。手动验收时让鼠标停在血条上并受伤、回血，再停在蓝条上施法、回蓝；数字应在鼠标不移动时变化。隔离测试验证了提示节点与真实 HUD 事件链，不能代替原生窗口下的视觉位置和样式验收。
