# 幸存者营地地面与碰撞可视化编辑扩展

本次在项目内 Godot「营地地图」主屏幕增加地面排布和单体碰撞编辑。保持正式营地的画布尺寸、NPC、出入口和现有物件美术不变；用户点击「应用到游戏」前，改动只存在于内存或独立草稿。

## 操作方式

「绘制地面」模式在右侧选择草簇、碎石、石板、土纹或擦除，左键点涂与拖涂 128×128 参考画布格。快速拖动补齐经过的格；擦除露出原来的循环地纹。四种笔刷来自现有 `ground_diagonal.png` 源图，透明边缘与基础地表过渡。道路仍在地面覆盖层之上。

「编辑碰撞」模式先在画面或右侧列表选择房屋、树、灯、马车、营火或围栏。拖动橙色顶点调整阻挡区域，Shift 点击边插入顶点，右键点击顶点删除顶点。至少保留三点。视觉矩形及前沿脚底锚点与碰撞轮廓分离，调房屋碰撞不会拉伸房屋贴图。整体物件平移和道路控制点功能保持原有用法。四种模式共用撤销、重做、保存草稿和应用。

## 数据与应用边界

地面笔刷清单在 `data/map_art/camp_ground_palette.json`，排布以 `ground_patches` 格子数组存在营地白盒草稿中。默认正式布局没有该字段时视为空覆盖。正式应用后，生成器把最多 14×8＝112 格合成一张 1672×941 透明地面层；没有已绘制格时，不生成、不加载该贴图。运行时仍是一张循环地纹和按需一张覆盖图，不产生逐格节点。四种 128×128 笔刷共约 0.25 MiB 原始 RGBA；覆盖图解码后约 6.0 MiB，只有实际绘制地面时加载，增加一个绘制层。

实体 `footprint` 和围栏 `polygon` 仍是通行掩码与 Godot 单个 `CollisionPolygon2D` 的共同源。旧围栏数据打开时，从现有美术清单补齐独立的 `art_rect`、`art_foot_y`，应用后保存在布局中，碰撞编辑不再重排围栏贴图。正式应用拒绝越界、零长边、折返、自交、面积过小和超过 32 顶点的多边形；并继续检查固定 NPC、出生、入口、出口、训练场刷新格、马车落点及四邻连通性。源哈希不一致时拒绝覆盖他人的正式修改。生成失败时恢复正式源和原有运行素材，并删除这次新建的图像。

## 验证

- `python3 -m unittest tests/test_camp_map_editor_apply.py`：4 项通过，覆盖房屋与围栏碰撞编辑、拒绝非法轮廓、透明地面合成，以及在临时项目完整执行应用与生成。
- `python3 tools/run_isolated_tests.py CampMapEditorTest CampFullArtAcceptanceTest`：通过。前者包含画布实际鼠标点涂和碰撞顶点拖拽，以及数据模型撤销重做；后者确认全图 11 个整体实体、固定服务点、开放外围和四条实走路线。
- Godot 4.7.2 编辑器主屏幕回归脚本：顶部「营地地图」按钮可见。真实窗口截图检查了默认、地面笔刷和房屋碰撞三个模式；橙色顶点与地面格线可辨。

当前笔刷用于调整局部草、石、土纹的分布，不会改变道路控制点或自动改通行。需要新的地面美术种类时，在同一笔刷清单与生成器中补充源图裁片即可；本版不引入新的 TileMap 系统。
