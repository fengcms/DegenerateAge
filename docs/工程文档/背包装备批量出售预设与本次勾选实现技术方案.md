# 背包装备批量出售：预设＋本次勾选实现技术方案

本文对应 [产品方案](../产品文档/14-背包装备批量出售预设与本次勾选产品方案.md)。方案已获确认并实施，保留本文件作为设计与验收依据。实现共用候选计算，同时保留「背包直卖」与「货郎先入托盘」的不同交易时机。

## 1. 现状与必须守住的接口

| 现有入口 | 当前行为 | 本方案处理 |
|---|---|---|
| `scripts/ui/inventory_panel.gd` | 显示出售按钮、数字等级 SpinBox、品质 OptionButton；按钮直接调用 `GameState.sell_low_gear()` | 改为打开共用清单，Lv15 前维持禁用 |
| `scripts/ui/shop_panel.gd` | `_on_stage_all_pressed()` 按 `GameState.is_low_gear()` 扫背包并填入 6×4 托盘；可能只移入前 24 件 | 改为清单确认后**整批**移入，不做无提示的部分成功 |
| `scripts/systems/shop.gd` | `matches_low_gear()` 只看穿戴等级与品质；`sell_price()` 为统一价格入口 | 新预设由独立策略层计算；售价继续调用 `Shop.sell_price()` |
| `autoload/game_state.gd` | 数字阈值保存在 `settings`；`sell_low_gear()` 立即移除并入账；`shop_sell_staged()` 对已暂存物品结算 | 新增按已核对实例 ID 的直卖命令；货郎批量暂存使用同一策略结果；防止旧接口绕开新保护 |
| `scripts/systems/equipment.gd`、`scripts/ui/item_slot.gd` | `replacement_preview()` 决定默认替换槽与正评分差，背包格据此显示绿/灰上箭头 | 策略层读取同一预览结果，不另写一份评分/双槽选择算法 |
| `autoload/save_manager.gd` | `settings` 随角色存档，装备字典经 `_valid_item()` 校验；货郎托盘未结算时暂停自动存档 | 增加预设设置与实例收藏字段校验；保持暂存期间不把「背包已扣、托盘未存」写进正式档 |

现有 `GameState.shop_sell_staged()` 到金币上限时会按 `add_gold()` 的实际可入账额截断，却仍清空货郎托盘；这与产品方案的「不吞物品」验收冲突。实现时须把金币容量作为结算前置校验，失败时保留托盘，不能只改预览数字。

## 2. 数据契约与兼容性

1. 在角色 `settings` 中新增 `sellGearPreset: "cautious" | "standard" | "aggressive"`，默认 `cautious`。只保存预设 ID，不保存展开清单、勾选索引或预估金币；UI 文案通过本地化键展示。`SettingsRuntime` 登记合法枚举，`SaveManager._migrate_settings()` 为旧档补默认值。现有 `lowGearLevelLimit` / `lowGearMaxQuality` 先保留为**废弃但可读取的旧档字段**，新 UI 和策略不再依赖；不能把旧数字阈值自动映射成风险更高的预设。完成旧档覆盖验证后再单独决定何时删除旧字段。
2. 装备实例增加可选 `favorite: bool`，未包含该键的旧实例按 `false` 读取。新生成实例显式写 `false`；`SaveManager._valid_item()` 对存在的键严格要求布尔值，且从背包、穿戴、仓库、掉落、托盘等容器流转时保留字段。装备不可堆叠，因此不会发生收藏标记冲突的合堆。售价和装备评分忽略此字段。
3. 收藏切换通过 `GameState.set_equipment_favorite(instance_id, value)` 之类的统一入口执行：只定位真实装备实例，失败不修改数据，成功广播对应容器与自动存档事件。单件出售、手拖入托盘、批量直卖、托盘最终结算均检查收藏；只在 UI 禁用按钮不足以防止其他路径绕过。
4. 不把清单的背包下标当作物品身份。每个装备已有稳定 `instanceId`；清单行保存 `instanceId`、打开时的实例数据快照、价格与保护判定。实例 ID 是重定位键；同一实例的数据、收藏状态、当前装备比较结果或价格变化时必须重新审阅。预设配置升级与收藏字段迁移都不得导致旧档被判损坏；是否提升 `schemaVersion` 由实现时的存档兼容测试决定，若提升须同步迁移与导入检查。

## 3. 单一策略层与清单模型

新增无 UI 依赖的 `SellGearPolicy`（建议 `scripts/systems/sell_gear_policy.gd`）。暴露纯函数：

```text
default_selected(item, player_level, equipment, preset) -> bool
protect_reasons(item, equipment) -> Array[String]
build_preview(inventory, player_level, equipment, preset) -> Array[Entry]
```

`Entry` 包含：`instance_id`、`bag_index`（仅用于显示）、`item_snapshot`、`required_level`、`quality`、`star`、`score_delta`、`price`、`default_selected`、`protect_reasons`、`locked`。策略先用 `Shop.can_sell()` 限定装备且排除不可售，再以 `Equipment.replacement_preview()` 判定正评分差。等级差、成色和零星条件按产品方案表单一配置；保护优先级为**收藏锁定／不可售 → 高分绿灰箭头 → 预设条件**。收藏和不可售永远不可勾选；其余仅影响默认勾选，可由玩家本次手动选择。

策略构建清单只在打开、切预设、相关状态变化及确认前执行。背包上限 200 格，一次扫描 O(背包格数)；托盘空位至多 24 格。不得把这项扫描放入 `_process()`，也不为每格建立额外常驻对象。装备评分计算复用现有函数；清单关闭即释放控件和快照引用。背包/穿戴/等级/设置变化使清单标记为待重核，但只更新受影响的打开窗口，避免为每个掉落重建整张游戏 UI。

## 4. 共用窗口与两条提交路径

建议新增 `scripts/ui/equipment_sale_preview.gd`，由背包与货郎以 `mode = DIRECT | STAGE` 打开。窗口沿用 `FloatingWindow`、`PanelChrome`、文字缩放和现有并窗规则；列表按背包格序稳定显示，不能因勾选导致位置跳动。按预设重算勾选，手动勾选只存在本次窗口。手动选入被默认保护的高价值件，在最终按钮前出现独立的风险确认，列出名称与原因。UI 只传实例 ID 与本次选择意图，不直接计算价格、扣物或加金币。

**背包直卖**：`GameState.sell_selected_equipment(selection, reviewed_snapshot)` 先检查 Lv15、所有实例仍存在且未收藏、实例内容与快照一致、价格与装备比较结果仍一致、无重复 ID、总价不超过金币上限；然后一次性移除这些实例、入账、广播一次背包/金币/交易事件。任何前置检查失败都不改变任何装备或金币；返回刷新原因供窗口重新展示。空选择不执行。手工选入预设外装备也走同一验证，只是把额外风险确认作为命令所需的显式选择意图记录。

**货郎暂存**：先检查当前店铺与对话仍有效、所选实例及风险状态有效、空闲托盘格足够；再将所选装备整批从背包取走，按格序放入剩余空格。避免循环调用 `remove_item_at()` 产生每件一次的背包刷新与半批成交；应提供一次批量移出入口。将托盘计数和自动存档抑制状态与移出过程保持一致；货郎面板关闭时沿用原有全部退回逻辑。选入托盘后直到最终结算，金币仍为零变化。`shop_sell_staged()` 在清空托盘之前验证每件仍可售且金币容量足够，并以 `{ok, count, gold, reason}` 回报；失败不得清空托盘。手动拖入与材料移入最终也受此规则保护。

确认前的重核采用**稳定 ID＋真实实例快照**，允许同一装备因整理变换格子；丢失、强化、重铸、换装、收藏、售价或可提升性变化则停止交易并刷新清单。若自动战斗中新增了其他掉落，但选中实例没变，可继续成交；新掉落不会偷偷加入本次选择。货郎模式检查所选数 `<= 空托盘格数`，超出则整批不移动。

## 5. 存档、旧功能与文档改造顺序

1. 先实现并测试策略纯函数和收藏字段，验证旧装备实例无 `favorite` 时加载为未收藏。更新实例生成、存档校验和容器流转；确保收藏的装备无法通过 `GameState.shop_sell()`、托盘和旧批量入口卖出。
2. 增加共用清单与本次勾选、预设存档；先接背包直卖，再接货郎暂存。旧 `sell_low_gear()`、`is_low_gear()` 与 `Shop.matches_low_gear()` 若仍被测试或工具使用，先做明确的兼容处理并清点调用方，**不允许旧 UI 入口暗中按原数字条件卖出**。
3. 最后补齐货郎金币上限原子结算、托盘容量及高价值手选确认；更新产品文档 05/06/09、存档字段说明、本地化文案和交接文档。每个可独立验证的节点按仓库惯例单独提交，提交时只暂存本方案涉及文件，避开其他 AI 的工作区改动。

## 6. 回归与试玩验收

- **策略单测**：三个预设在 Lv15、Lv20、60+ 动态等级下的边界；品质枚举、0 星/升星、无效物品、无可替换槽、单槽与双槽、绿箭头与灰箭头、已收藏；检查默认勾选与清单理由一致。
- **交易单测**：直卖 Lv15 门槛、手动取消/加入、重复 ID、整理后重定位、选中实例消失或重铸、角色升级/换装、金币上限、无可售项；失败时背包与金币逐字段不变，成功只广播一次结算。货郎空位 0/1/24、已有手动暂存、超容量整批拒绝、关闭退回、收藏物绕过尝试，以及最终结算失败不清托盘。
- **存档单测**：旧档无 `favorite` 和无 `sellGearPreset`、新档收藏装备在背包／穿戴／仓库之间转移、保存重载及导入；畸形收藏字段拒读；旧数字阈值不被误用。
- **界面与实际试玩**：100%／150%／200% 下清单可读且不出屏；并开背包与货郎位置稳定；切预设、逐件勾选、空清单、风险二次确认与键鼠操作；自动战斗持续掉落时预览变化不误卖。

隔离测试使用 `python3 tools/run_isolated_tests.py` 运行新增出售策略/事务场景、`SmokeTest`、`EquipmentAxesTest`、`InventoryUpgradeBadgeTest` 与相关货郎场景，保护真实槽位。完成后再做实际窗口验收；headless 结果不代替 4K 高缩放交互检查。

## 7. 已确认的产品口径

本方案按「**三个预设；默认谨慎；收藏不可批卖且手动单卖先解锁；未锁高价值件可在本次清单手选并二次确认；货郎超过空位时整批拒绝**」实施。如果要改变其中任一项，应先修改产品方案再动交易代码，避免把安全行为藏在实现细节中。
