# 技能面板高度异常膨胀：根因分析与修复

> 现象来源：2026-10-16 用户反馈「打开技能面板，技能面板变得非常高」，附截图（窗口 618×1199 逻辑单位，界面倍率 200%）。
> 交付物类型：单项缺陷修复记录（含根因链、修复点、验证证据）。

## 1. 现象

技能面板打开后，面板高度几乎占满整个窗口：标题行与 8 条技能行（6 条技能 + 自动红药 / 自动蓝药）只占面板顶部约 55%，其下方是**约 1000 物理像素的大片空白**，且**不出现垂直滚动条**。

对截图的像素测量（1236×2398 物理像素）：

| 量 | 物理像素 | 说明 |
| --- | --- | --- |
| 面板左/右金框 | x ≈ 26 / 1208 | 面板宽 ≈ 1182 |
| 面板上/下金框 | y ≈ 47 / 2358 | 面板高 ≈ 2311 |
| 最后一行卡片下沿 | y ≈ 1280 | 内容实际只占到高度的一半 |
| 面板宽 / 代码最小宽 590 | 1182 / 590 = 2.00 | 得出界面倍率 = 2.0 |

按倍率 2.0 反推：面板逻辑高度 ≈ 1155，而 8 行内容的正常面板高度应为 **642**（内容自然高 539 + 非滚动开销 103）。多出的 ≈ 513 逻辑单位全部是无内容的空白。

## 2. 根因

高度由 `FloatingWindow._layout()` 的 `size = panel_box.get_combined_minimum_size()` 决定，面板最小高度 = 非滚动开销 103 + 内容区滚动容器的最小高度。链条如下：

1. [skill_panel.gd](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/ui/skill_panel.gd#L113-L115) 的 `_refresh()` 清理旧行时**只调 `queue_free()`，没有先 `remove_child()`**。`queue_free()` 要等到本帧结束才真正释放，因此旧行在**当帧剩余时间内仍留在 `_list` 里**并参与最小尺寸计算。
2. 同一帧内第二次进入 `_refresh()` 时（关闭后复开、或面板关闭期间升级触发 `_refresh` 后再打开），`_list` 会瞬时持有 **16 行**，内容自然高度从 539 翻倍到约 1058。
3. 紧接着同一帧的 `_center.show_window()` → `_layout()` → `static fit_content()` 读到的是**翻倍后的自然高度**。此时 `natural.y > room.y`，于是 `scroll.custom_minimum_size.y` 被设为可视区上限，面板被撑到**整个可用高度**。
4. **缺陷之所以固化、不会自愈**（这是观测到"永久变高"的关键）：一旦 `scroll.custom_minimum_size` 大于内容自然高，`panel_box` 的最小尺寸就只由该值决定（103 + custom），**与内容无关**。旧行随后被真正释放时，`panel_box.minimum_size_changed` 不再变化、不再触发，`_layout()` 不会重算 —— 面板便停在撑满状态，只有窗口尺寸或界面倍率再次变化（触发 `owner_panel.resized`）才可能回落。

`floating_window.gd` 的注释（[第 35 行](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/ui/floating_window.gd#L35-L36)）本就假设"旧行 `queue_free` 后最小尺寸稳定 → 重新夹紧浮窗"，但第 4 条的机制让这个假设在**内容被钳制过**的情况下不成立。

## 3. 复现与证据

用一个临时探针场景（已用后删除、未入库）在 1280×1025 的视口下实测：

| 场景 | 面板最小尺寸 | 滚动容器 custom | 内容自然高 | 结论 |
| --- | --- | --- | --- | --- |
| 正常打开一次 | 590 × **642** | (540, 539) | (540, 539) | 正常 |
| 同帧再刷新一次后再布局 | 598 × **1025** | (548, **922**) | (540, 539) | 撑满可用高，且**后续多帧仍为 1025** |

`rows=8 / inner_nat=(540,539)` 说明列表实际只有 8 行、内容只有 539 —— 面板的 1025 完全来自被钳制后未回收的 `custom_minimum_size`，与截图"8 行 + 大片空白 + 无滚动条"完全一致。

## 4. 修复

只改一处：`skill_panel.gd` 的 `_refresh()` 清列表时先同步移出容器，再 `queue_free()`。

```gdscript
	for child in _list.get_children():
		_list.remove_child(child)
		child.queue_free()
```

- 旧行当帧即从 `_list` 移除，最小尺寸立刻回落到 8 行，`fit_content()` 不会再读到翻倍的自然高度，也就不会把 `custom_minimum_size` 钳到可视区上限。
- 该写法与既有面板一致：[mount_panel.gd](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/ui/mount_panel.gd#L155-L157)、[inventory_panel.gd](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/ui/inventory_panel.gd#L352-L355) 早就使用 `remove_child` + `queue_free`；技能面板是四个常驻浮窗里唯一漏掉 `remove_child` 的。

修复后同一探针在「关闭再打开」连续 3 轮 + 同帧双刷新场景下，面板稳定为 590 × 642。

- 默认隔离回归 28 项 —— 全部通过。

## 6. 影响面与后续加固（未在本轮实施）

- 改动仅限技能面板，其余面板不受影响。
- 可选的加固方向：把 `content_scroll` 内层内容的 `minimum_size_changed` 也接入 `FloatingWindow._layout()`。这样即便将来出现"内容被钳制后又变小"的其他路径，面板也能自愈；本轮按"改动尽量小"未做。
