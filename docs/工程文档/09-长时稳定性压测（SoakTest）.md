# 长时稳定性压测（SoakTest）

> 目的：为 M1 出口清单最后一项「**连续游玩 ≥ 10 分钟不崩溃、不卡死**」提供**客观数据**支撑。
> M1 出口该项有两条路：**甲**人工挂机试玩（主观手感）、**乙** `tests/SoakTest.tscn` 自动压测（客观数据）。
> 本文是**乙方案**的方案说明与实测报告。
>
> 状态：✅ 已执行（2026-10-12）
> 关联：`docs/工程文档/02-阶段开发计划与验收标准.md`（M1 出口）、`04-开发期测试便利清单.md`（工具清单 / M5 移除）、`07-首次数值校准方案.md`

---

## 1. 为什么需要自动压测

人工试玩（甲）能发现"肉眼可见的崩、卡、闪"，但**发现不了缓慢泄漏**：节点数、对象数、静态内存
在 10 分钟内慢慢涨，只要没到崩溃点，人眼看不出来。而这类问题在 M2 之后（任务 / 多图 / 坐骑）
只会放大。

`SoakTest` 用**自动战斗常开**把游戏跑在真实负载上，每 5 秒采样一次，把"是否有泄漏"变成**可读曲线 + 判据**。

---

## 2. 工具与运行方式

```bash
GODOT=/Applications/Godot.app/Contents/MacOS/Godot

# ① 无头长跑（默认 600s / 10 分钟，不弹窗、不干扰；正式压测用这条）
"$GODOT" --headless --path . res://tests/SoakTest.tscn

# ② 开窗短跑（额外采真实渲染帧率；勿与长跑同时进行）
"$GODOT" --path . res://tests/SoakTest.tscn -- --soak=120

# ③ 快速自检（30 秒，验证脚本本身）
"$GODOT" --headless --path . res://tests/SoakTest.tscn -- --soak=30 --interval=3
```

| 参数（写在 `--` 之后） | 默认 | 说明 |
|---|---|---|
| `--soak=秒数` | `600` | 压测总时长 |
| `--interval=秒数` | `5` | 采样间隔 |
| `--no-ui-stress` | 关 | 跳过「交互脉冲」（纯挂机，测基线） |

**输出**：
- 控制台逐采样一行（可实时观察）
- 报告：`/tmp/degenerateage_soak_report.md`（含判定与降采样曲线）
- 原始数据：`/tmp/degenerateage_soak_samples.json`（全部采样点，便于二次分析）

**退出码**：`0` = 全部判据通过；`1` = 有失败项（失败原因打印在末尾）。

> ⚠ 压测会写 3 号槽（顺带压测自动存路径）。开始前脚本**快照整个 `saves/` 目录**
> （含各槽 `.bak` / `.tmp` / `.corrupt` 与 `last_slot.json`），结束后**原样还原**；
> 另在 `/tmp/ea_soak_save_backup/` 落一份，万一被 Ctrl+C 打断也能手工恢复。

## 3. 压测内容

### 3.1 负载（把游戏跑在真实循环上）

- 加载真实主场景 `Main.tscn`（**不是** `Game.tscn`——后者没有 UI 层，HUD / 面板不参与压测）
- 起步角色 L5（与 4.4 成长公式一致：每级 攻 +2 / 防 +1），保证长跑期间**持续作战**
- **自动战斗 + 自动拾取常开**（3.14 / 9.9），持续跑：搜怪 → 接近 → 攻击 → 击杀 → 掉落结算 →
  拾取 → 升级 → 自动存
- 怪物点按 `game.gd::TEST_SPAWNS` 的刷新时间（6~20s）持续重生（7.9）

### 3.2 采样指标（每 `interval` 秒）

帧率 ｜ 节点数 ｜ 对象数 ｜ **孤儿节点** ｜ 静态内存 ｜ 场上怪物数 ｜ 地面掉落物数 ｜
累计击杀 ｜ 等级 ｜ 金币 ｜ 背包占用 ｜ 自动战斗状态

另记录**采样实际间隔**：明显超出设定值即说明主线程被阻塞过（卡顿检测）。

### 3.3 交互脉冲（每 60s，压 UI 与非战斗分支）

| 动作 | 压什么 |
|---|---|
| 背包面板开 → 关 | UI 构建 / 销毁、面板互斥（9.2）、物品格 `ItemSlot` 重建 |
| 存档面板开 → 关 | 3 张存档卡摘要读取（`read_slot` 解析 + 迁移路径） |
| 按住方向键 0.6s 后松开 | 手动接管分支（4.6）：自动战斗应转「手动接管」并在松开后恢复 |
| 清空场上怪物 → 观察 4s | 「搜索掉落 → 顺路拾取」路径（3.14 / 9.9），验证自动状态机能从"有怪"切到"捡东西"再切回 |
| 扫地面掉落物入包 + 卖装备 | 物品流转闭环（掉落 → 入包 → 出售 → 金币），见下 |

### 3.4 后勤（保证负载可持续，且不掩盖真实信号）

- **扫掉落**：自动拾取只覆盖「顺路」范围；持续刷怪会让地面掉落物**单调堆积**。
  那是设计行为，不是泄漏，但会让节点数曲线一路上扬，**掩盖真正的泄漏信号**。
  → 脉冲时把地面掉落物扫进背包（金币入账、物品入包），模拟玩家主动拾取。
- **回城卖装备**：背包占用 ≥ 30 格时，把非测试武器的装备全部卖出（模拟玩家清包），
  避免"背包满 → 不再拾取 → 掉落物堆积"。
- **低血注水**：M1 没有自动喝药（3.14 的 RECOVER 只是停手），HP 低于 50% 时补满。
  这是**压测注水**，只为保证持续负载；次数在报告中单独统计。

## 4. 判据

| 判据 | 阈值 | 含义 |
|---|---|---|
| 孤儿节点 | 全程 **= 0** | 有孤儿节点即对象未正确释放（硬性失败） |
| 真实负载 | 击杀 **> 0** | 否则压测没有实际跑起来（空转） |
| 节点数漂移 | 后段均值 ≤ 前段均值 × 1.3 + 30 | 无节点泄漏 |
| 对象数漂移 | 后段均值 ≤ 前段均值 × 1.3 + 30 | 无对象 / 资源泄漏 |
| 静态内存 | 后段均值 ≤ 前段均值 × 1.6 | 无显著内存增长 |
| 背包实例 | 无重复 `instanceId` | 无"物品复制"类状态 bug |
| 背包占用 | ≤ 40 格 | 不越界 |
| 玩家死亡 | = 0 | 持续刷怪不应把玩家打死（M1 无死亡处理） |

「前段 / 后段」的比较会跳过前 10% 采样点（场景初始化 + 怪物首次生成），
再取剩余序列的**前 1/4** 与**后 1/4** 均值，避免开局爬坡污染判据。

采样间隔超阈值只**打印告警并计数**（不直接判失败）——无头模式下偶发调度抖动是正常的。

## 6. 已知边界

1. **无头模式的帧率不是真实性能指标**：无头不渲染，帧率只反映主循环节奏（本机稳定在 ~145）。
   真实渲染帧率需开窗运行（§5 附）。
2. **压测注水**：低血补满、扫掉落、卖装备三件事都是"模拟玩家行为"，不是游戏自动行为。
   它们的作用是**维持可持续负载**，不是为了验证这三条链路本身（那由冒烟 / 专项工具覆盖）。
3. **不做的事**：不模拟鼠标拖拽（拖拽已由 `DragLayerProbe` 覆盖）、不读档重载场景
   （读档链路由 `SaveSeed` 跨进程端到端覆盖）、不跨地图（M3 才有第二张图）。
4. **本工具是开发期工具**：M5 打包前随其余测试工具一并移除（见 `04-开发期测试便利清单.md` §3）。
5. **开窗模式必须保持窗口在前台**：失焦时 3.14⑥ 会停决策（状态「暂停中」），负载会暂停；
   工具已采样并标注该标志，但正式压测请用无头模式。
6. **跑之前先确认脚本能解析**：若指定的场景脚本解析失败，Godot 会**静默回退加载
   `run/main_scene`（Main.tscn）** —— 看起来"测试在跑"，实际是主游戏在跑，而且 `SaveManager`
   会续档 + 定时存**写玩家真实存档**。防护：先 `--check-only --script res://tests/soak_test.gd`
   看有没有 `Parse Error`，再跑 3~5 秒极短实跑确认流程走通（见 08 交接文档坑 13）。
