# 自动找怪范围与巡游路径疏密分析

本文针对“自动找怪走得过密，希望放宽搜索与巡游路线”的反馈，核对2026-10-31当前代码、正式地图掩码及已有行为测试。本轮仅分析，不修改玩法参数或寻路代码。静态地图测量能证明采样点数量和几何路线长度；玩家实际重复往返程度尚未录制，因此相关体验判断明确作为推断。

## 1. 结论

建议采用“扩大屏外搜怪补充范围＋巡游间距7格改为12格起测＋战斗后继续原巡游进度”的组合。只调一个搜索半径无法解决蛇形路线过细，只把路径节点删掉也不能保证不漏窄通道。

当前底层绕墙路线已经做平滑，不建议放宽角色与墙体的安全间距，也不建议通过忽略转角节点减少路径密度。本次要调的是地图上的找怪路线，而非碰撞精度。

## 2. 已核实的现状与成因

|环节|当前行为|对反馈的影响|
|---|---|---|
|选怪范围|`auto_battle.gd:719`的`_find_target()`调用`world.visible_enemies()`；`game.gd:325`按实际视口投影过滤|新目标主要来自当前屏幕；屏外近处怪物不能参与普通自动选怪。手动目标和短期粘性目标另有优先分支|
|镜头倍率|`settings_runtime.gd:369–377`将地图倍率应用到相机，支持0.8–2.0|同窗口下，倍率2.0的世界可见宽高约为1.0的一半，面积约四分之一；选怪范围随之变化，不是固定世界半径|
|巡游间距|`auto_battle.gd:67`为7地图格；`:863–891`按横纵网格蛇形取点|大地图中存在数百巡游点，偏向细密扫图，而不是走较稀的主路线|
|战斗中断后续走|`:351`每次找到目标将`_roam_index`置为-1；`:820–827`恢复巡游时重新选最近采样点|可能回到刚刚走过的点、反复扫邻近地带；这是代码支持的风险推断，尚无玩家轨迹录屏证明发生频率|
|搜怪频率|无目标时每0.35秒搜索一次|响应频率已经足够；没有证据支持靠加快扫描解决路线过密|
|底层路径|`cave_layout.gd:177`用最多向前12节点的安全直连平滑；`segment_walkable()`以14像素净空、每6像素采样检查；`cave_navigator.gd`缓存路线|路线小拐点与巡游网格是不同层。放宽净空会增加撞墙/切角风险，不能作为首选|
|怪物生成|`spawner.gd:16–17`固定点760世界像素内激活，1100像素外具备退场距离条件；受刷新预算和解锁控制|单独把选怪范围扩成全图，不会自动得到尚未实例化的远处怪物，还可能带来无效扫描|
|探索迷雾|`fog.gd`以8地图格揭示、4×4格区块记录探索|屏外补充选怪应限制在已探索区域；放宽巡游不能直接揭示未探索地图|

旧存档`searchRadius`已不再限制找怪范围，产品03 §3.14已有明确约定；因此重新调这个旧字段不会产生预期效果。`visible_enemies()`还用于Tab手动切目标，扩展自动搜索时不能直接扩大它，否则手动锁定也会无意改变。

## 4. 推荐行为

### 4.1 扩大自动选怪，保持当前画面体验

候选集合采用“原本可视的有效怪物＋玩家760世界像素内、已探索区域的屏外有效怪物”。这里760是世界平面像素距离，与固定怪物点激活距离的口径一致，不是760屏幕像素，也不能简单称为多少地图格。原可视范围保留，避免缩小镜头时反而漏掉已可见的远处目标；屏外补充半径不随镜头倍率变化。

保留手动目标、有效粘性目标的优先级；普通候选继续距离优先、同距离低血量优先。Boss开关、黑名单、存活、可达性、区域解锁规则保持原义。普通自动目标选中后继续追击，不因离开屏幕立即换怪。760为首轮建议值，尚未实机证明最优；先与现有生成范围对齐，不同步提高怪物活动上限。

自动搜索建立单独入口或参数，Tab继续只选屏幕内目标。禁止为找怪读取未探索的全图刷新点、墓碑或未实例化怪物作为实时目标；若以后需要“直奔已知刷新点”，应独立设计成另一种挂机策略。

### 4.2 拉开巡游间距，并保留补漏

主巡游从7地图格调整为12地图格起测，小地图和窄通道允许局部降为10格。14格作为对照组暂不默认采用：点数更少不等于覆盖更好，较小窗口、大倍率和走廊岔路更容易出现盲区。

保留地图边界补点与连通区域筛选；窄通道没有采样点时，应从通行布局/已探索边界补入少量分支锚点，不能把所有12格采样都落墙的支路当成无怪区域。补点须按区域缓存和去重，不能每帧扫全地图。粗巡一轮仍无目标时才做局部补漏/探索推进，避免默认回到原来的细密全图扫描。

本期不扩大Fog揭示半径；更稀路线是否仍能完成原来的探索覆盖，需要测试证明。如有盲区，通过补漏路线处理，不能靠自动揭图掩盖。

### 4.3 战斗/拾取后接着巡游

将“当前巡游进度”与“正在追击的移动路线”分开维护。遇怪时清除移动方向和追击路线缓存，但保存巡游游标与已推进信息；战斗/顺路拾取结束后，继续下一个尚未完成的巡游点，避免无条件重新选最近点。

切图、导航版本改变、玩家进入另一连通区域时重建巡游；读档、关闭自动战斗及手动接管后按实际状态重新定位，不能保留旧地图游标。若战斗把人带到远处，应按当前位置选择合理的前向接续点，不能为了保留游标跨越整张地图回头。

### 4.4 保留已有安全行为

不改攻击范围、拾取半径、墙体净空、禁止穿角、卡住检测、怪物仇恨/脱战和掉落规则。本次不提供“全地图透视找Boss”，不新增怪物数量，不扩大刷新预算。路线显示点数属于可视化问题，如仍觉得小地图折线密，另查显示抽稀，不能删掉运动所需转角。

## 5. 性能和维护边界

继续每0.35秒搜一次；每轮至多一次活动怪物遍历，先过滤距离/状态/探索，再用现有连通性缓存检查可达性。只给最终移动目标建立完整路线，不对每个候选执行A*。避免自动搜索复用“收集后排序”的可视列表再二次全量遍历，距离与血量比较可在一次遍历内完成。

巡游列表属于当前AutoBattle实例，按地图、导航版本及连通区域缓存；新增游标、补漏状态仅为运行态，不需要存档版本迁移。12格网格候选数约按面积/144增长，7格约按面积/49增长；狭窄支路补点设独立有界预算。实际降低多少CPU耗时，须实施后同场景测量，当前没有性能提升结论。

不需要为每个怪物新建定时器、导航器或独立线程；不默认添加新的玩家设置，先用统一推荐参数验证体验。旧`searchRadius`继续作为历史兼容字段处理，不应复用而造成旧存档行为不一致。

## 6. 开发节点与验收方法

1. 独立自动选怪候选范围：回归760像素内屏外已探索怪、原画面远怪、未探索屏外怪、Boss开关、隔墙不可达目标；确认Tab仍只选可视目标。完成后commit。
2. 12格主巡游＋分支补点：比较7/10/12/14格，保留动态门禁、边界和窄支路覆盖；小地图/大倍率不得出现永久漏区。完成后commit。
3. 巡游进度保留：战斗/拾取插入后不反复返回旧点，远距离追击后合理接续；手动接管、死亡、读档、切图清理正确。完成后commit。
4. 同设备同地图、相同角色/刷新状态和窗口设置，采集首怪时间、单位时间击杀数、无目标移动距离、重复路段占比、覆盖率、A*调用与搜怪耗时P50/P95/P99，另记整帧分位数。全探索地图比较刷怪效率，未探索地图比较覆盖完整性；再做30分钟挂机及资源增长检查。完成验收文档和commit。

优先复验腐化源头、余烬炉房、无尽回廊、百首禁域，覆盖宽场地/窄通道/动态门禁、允许与禁止Boss、0.8/1.0/2.0地图倍率。候选验收目标是减少重复空走、保持可达怪物与探索覆盖，不能简单以点数越少越好。

已有测试基线结果另列于下；这些测试只能证明当前行为的部分正确性，不能证明提案的覆盖率或效率。
