# 74 · 面板点击置前失效（点击铁匠系面板「掉不了头」）原因分析与修复方案

> 现象提出：当面板与面板重叠时，用鼠标点击靠后的面板（如**保星升级** / 人物属性），期望它「到前面来」（常见窗口逻辑），但实际仍停在其它窗口后面。
> 结论一句话：**置前逻辑被写死成了一份四个名字的白名单**（`floating_window.gd:5` 的 `PEERS`），只有背包 / 人物 / 技能 / 坐骑四扇窗装了置前入口；铁匠系的保星升级、升星、重铸、铁匠菜单等面板**既没有置前入口，也不在置前的判定名单里**，且它们的 GUI 命中顺序由场景树位置决定 —— 所以点它不会有任何反应。这不是某个面板的孤例，是**面板层级机制的整体缺口**。

---

## 1. 现象与可观测判据

| 组合 | 点击「靠后」那扇窗 | 期望 | 现状 |
| --- | --- | --- | --- |
| 四常驻浮窗之间（背包 / 人物 / 技能 / 坐骑） | 被点到的那扇浮到最前 | 置前 | **正常**（`bring_forward()` 生效） |
| **保星升级 + 人物属性** | 保星升级浮到最前 | 置前 | **无反应**，仍被人物面板压住 |
| 保星升级 + 背包 | 保星升级浮到最前 | 置前 | 同上 |
| 铁匠菜单 / 升星 / 重铸 ↔ 任何并开面板 | 被点到的那扇浮到最前 | 置前 | 同上（这些面板按规则不与别的面板并开，见 §3.2） |
| 货郎 + 背包（并排） | 点背包应置前 | 置前 | 视觉上「点哪都在货郎之下」，命中序与视觉序不一致 |

补充判据：**后打开的面板不一定在上面**。四常驻浮窗在打开时会调用 `show_window() → bring_forward()`，所以「后开的压住先开的」；而铁匠系面板完全不做任何层级调整，它能否盖住别人纯由 `Main.tscn` 的固定节点顺序决定。

---

## 2. 根因（代码事实）

### 2.1 置前只服务四个硬编码名字

[floating_window.gd](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/ui/floating_window.gd#L5-L5)：

```gdscript
const PEERS := ["inventory", "character", "skill", "mount"]
```

[bring_forward()](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/ui/floating_window.gd#L54-L72) 与 [is_top_window()](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/ui/floating_window.gd#L74-L80) 都只认这份名单，判定方式是把兄弟节点的**节点名**做字符串推导：

```gdscript
if sibling is Control and sibling.visible \
        and String(sibling.name).to_lower().replace("panel", "") in PEERS:
```

`UpgradePanel → "upgrade"`、`EquipmentFusionPanel → "equipmentfusion"`、`BlacksmithPanel → "blacksmith"` —— **一个都不在 `PEERS` 里**，于是：

- 这些面板**永远不会**被纳入「浮窗层」的排序重算；
- 别的浮窗置前时，`last_peer_index` 只取「可见 PEERS 的最大下标」，它们被当成不存在的路人，天花板算不出来。

顺带一提，`replace("panel", "")` 是全串替换，名字里任何位置出现 `panel` 都会被删掉 —— 这是在用节点名当 ID，本身就是脆弱写法。

### 2.2 其余面板根本没有任何置前入口

[floating_window.gd](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/ui/floating_window.gd#L35-L36) 把置前挂在这两个信号上：

```gdscript
header.gui_input.connect(_on_header_input)     # 标题栏按下 → bring_forward + 起拖
panel_box.gui_input.connect(_on_box_input)     # 面板体按下 → bring_forward
```

而 `FloatingWindow.new()` 全仓库只有 4 处（`inventory_panel.gd:164`、`character_panel.gd:63`、`skill_panel.gd:50`、`mount_panel.gd:58`）。铁匠系面板用的是**裸 `CenterContainer`**，没有 `FloatingWindow`：

| 面板 | 宿主 | 内层容器 | 置前入口 |
| --- | --- | --- | --- |
| UpgradePanel（升星） | `Control` 全屏 + `MOUSE_FILTER_IGNORE`（`upgrade_panel.gd:21-22`） | 裸 `CenterContainer`（`:66-68`） | **无** |
| EquipmentFusionPanel（保星升级） | 同上（`equipment_fusion_panel.gd:29-30`） | 裸 `CenterContainer`（`:161-162`） | **无** |
| ReforgePanel（重铸） | 同上（`reforge_panel.gd:23-24`） | 裸 `CenterContainer`（`:68-70`） | **无** |
| BlacksmithPanel（铁匠菜单） | 同上（`blacksmith_panel.gd:24-25`） | 裸 `CenterContainer`（`:77-80`） | **无** |

全仓库 `gui_input.connect` 一共只有 5 处（`inventory_panel` 的背包格、`equipment_sale_preview` 的标题、`floating_window` 的两处、`hud` 的战斗图标），**没有一处服务于这些面板的置前**。

### 2.3 为什么「顺手把 z_index 提上去」也不行

Godot 里 `Control` 的**鼠标命中顺序看的是兄弟节点顺序，不是 `z_index`**。这一点在本工程已实测过（[08-浮窗标题与叠放输入问题分析.md](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/docs/素材设计/08-浮窗标题与叠放输入问题分析.md#L19-L19) 的临时运行探针：两个完全重叠的 `Control`，先入树者 `z_index=10`、后入树者 `z_index=1`，点击重叠处收到事件的是**后入树、低 `z_index`** 的那个；真实背包 + 技能面板复现同一结果）。

这解释了 [floating_window.gd:62](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/scripts/ui/floating_window.gd#L62) 的既有注释「Godot 的 GUI 命中看兄弟节点顺序，不能只提高 z_index」，也是它必须 `move_child()` 的原因。

→ **结论：置前 = 改树序（顺带同步 z_index 让视觉序跟上），只改 z_index 会让「看到的」和「点到的」继续分裂。**

### 2.4 为什么会重叠：非浮窗面板是「固定居中」而不是「窗口」

四常驻浮窗可由玩家拖动、位置有记忆；铁匠系面板是**全屏宿主 + 居中容器**，位置写死、不可拖 —— 它们一开就压在同一块屏幕中央，与其它居中面板必然大范围重叠，且各自还带一层全屏暗色遮罩（`reforge_panel.gd:63-66` 0.42、`blacksmith_panel.gd:72-76` 0.36）。

它们按规则彼此互斥（见 §3.2），所以**遮罩不会叠两层**；但「谁在谁上面」完全没有玩家可干预的手段 —— 这正是本次诉求的来源。

### 2.5 用户所报组合的复现路径

1. 找铁匠 → 打开铁匠菜单 → 点「保星升级」→ `EquipmentFusionPanel` 打开（`Main.tscn` 索引 **11**）。
2. 按 `I` 打开人物属性 → `CharacterPanel` 复用 `FloatingWindow`，打开即 `show_window() → bring_forward()`，被抬到浮窗层末尾（索引 **14** 附近），于是**压住**保星升级面板。
3. 此时用鼠标点保星升级面板 → 它没有置前入口，索引仍是 11 < 14 → **纹丝不动**。

（步骤 2 中人物属性之所以能压住保星升级，不是「后开所以在上」这个通用规则在起作用，而是**恰好**因为人物面板装了 `bring_forward`、而保星升级面板没装 —— 同一条规则，一扇窗有一扇窗没有。）

### 3.2 实际「可达」的重叠组合（受并开规则约束）

[game_state.gd:1386](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/autoload/game_state.gd#L1386) 与 [:1414-1420](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/autoload/game_state.gd#L1414-L1420) 确定了谁能和谁同屏：

```gdscript
const FLOATING_PANEL_IDS := ["inventory", "character", "skill", "mount"]
# panels_coexist: equipment_fusion ↔ inventory / character 例外；其余仅同组可并开
```

再叠加「铁匠系各面板一旦有其它面板打开就自行关闭」（`upgrade_panel.gd:49`、`blacksmith_panel.gd:55`、`reforge_panel.gd:51` 的 `_on_panel_opened`），实际可达的重叠只有：

1. **四常驻浮窗之间**（已有置前 ✅）；
2. **保星升级 ↔ 背包 / 人物**（`panels_coexist` 显式放行，**本次报的就是这一档，无置前 ❌**）；
3. **货郎 ↔ 背包**（并排特例，命中序与视觉序不一致，❌）。

→ 所以「原因是否普遍」的准确回答是：**机制是普遍缺失的（除四常驻浮窗外没有任何面板有置前入口），但当前真正能被玩家撞到的只有第 2、3 档**。第 3 档严格说是「并排布局下命中序与视觉序不一致」，与「点击置前」是同一根源的两个症状。

## 4. 修复方案

| 编号 | 做法 | 效果 | 代价 / 风险 |
| --- | --- | --- | --- |
| **P1**（推荐） | 把置前从 `FloatingWindow` 的硬编码名单提升为**统一的浮窗层级服务**：① 面板集合以 `GameState` 面板 ID 为单一事实源（不用节点名字符串推导）；② 置前 = `move_child` 到「当前可见浮窗层的最末位」，天花板 = 可见的模态 / 覆盖层（设置 / 菜单 / 存档 / 死亡 / 确认罩 / Toast / 拖拽幽灵）之前；③ 各浮窗面板在面板体 `gui_input` 上发起置前；④ `is_top_window()` 同源改造，保证 Esc 目标 = 视觉最前 | 真正满足「点哪个窗口，哪个窗口到前面来」，且**新面板自动纳入**，不再漏 | 触及 `Main.tscn` 树序与多面板互斥；需全量回归并实机复验；产品文档 09 §9.2 的口径要从「四窗」扩到「所有浮窗」 |
| P2 | 保留现状结构，逐个给铁匠系面板补 `gui_input → bring_forward`，并把 `PEERS` 扩成显式清单 | 修掉当前可达的坏组合 | 又多一份需要人肉维护的清单；下次加面板继续漏；不解决四常驻浮窗与非浮窗面板之间的命中序一致性 |
| P3 | 只把 `"equipmentfusion"` 加进 `PEERS`（一行） | 只修「保星升级 ↔ 背包/人物」这一档 | **止血档**。不满足用户「点哪个窗口哪个到前面」的普遍诉求；货郎并排档仍不一致 |

不建议的做法：① 直接把所有 UI 节点在点击时 `move_child` 到场景树末尾 —— 会越过 `FlowFeedback`(Toast)、`DragLayer`(拖拽幽灵)、`EquipmentConfirmation`(模态罩)，破坏已验收的浮层层级约定（[09-UI与交互规范.md:49](file:///Users/fungleo/Sites/GameProjects/DegenerateAge/docs/产品文档/09-UI与交互规范.md#L49) 明确要求「跟随鼠标的元素必须绘制在所有面板之上」）；② 只提 `z_index` 不调树序 —— 见 §2.3，命中序不会跟着变。

## 5. 连带风险与必须守住的边界

1. **天花板不能越**：`FlowFeedback`(Toast) / `DragLayer`(拖拽幽灵) / `EquipmentConfirmation`(模态确认) 以及**打开中的**设置 / 菜单 / 存档 / 死亡面板，必须始终在浮窗之上。
2. **模态仍要压住一切**：设置 / 菜单 / 存档 / 死亡打开时，其它面板不应被点置前到它们之上。
3. **`BossTokenPanel` 的节点位置反常**（排在模态之后）：若纳入统一置前，需先决定是「把它移入浮窗层」还是「单独排除」，否则天花板计算会出现 18 > 16 的越界。
4. **Esc 目标必须同源**：现在 `is_top_window()` 只看四常驻浮窗；一旦非浮窗面板也能置前，Esc 会关掉「不是最上面那扇」的窗。这一条必须与置前一起改，否则会引入新的不一致。
5. **货郎并排布局**：货郎 + 背包是「左右并排」的特殊布局（`set_docked`），置前逻辑不得把并排关系打散。
6. **拖拽中的物品不得被面板遮挡**：任何 `move_child` 都不能把面板越到 `DragLayer` 之上。
7. **不改拖动**：本次诉求只涉及「点击置前」。是否把铁匠系面板也做成可拖动窗口，是另一个产品决定，建议**不在本次混入**。
