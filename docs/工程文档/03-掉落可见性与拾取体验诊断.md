# 03 · 掉落可见性与拾取体验诊断

> 触发：实测反馈「打死怪物后地面没有出现物品，但有提示文案提示获取了金币和物品；按 I 无反应」。
> 结论：**掉落经济逻辑无 bug，物品与金币均已正确入账**；问题出在「地面可见性」与「按键空档期」两处体验缺口。
> 状态：✅ **已修复**（2026-10-11）。落地保护期 1.2s + 掉落提示已落地；I 键背包仍属 M1-7 范围。

---

## 1. 结论速览

| # | 现象 | 判定 | 根因 |
| --- | --- | --- | --- |
| 1 | 地面看不到掉落物 | ✅ 已修复 | 近战击杀距离 ≤ 64px，而自动拾取半径 = 96px（1.5 格）→ 掉落物在**下一个物理帧（≈16.7ms）**被吸走，存留 ≈1 帧，肉眼不可见。修复：落地保护期 1.2s + 落地弧线 + 新掉落高亮圈 |
| 2 | 提示「获取了金币和物品」 | ✅ 已修复 | 原提示为**自动拾取** toast（`拾取：金币 +N` / `拾取：xxx`）；缺「掉落」阶段的提示。修复：死亡结算聚合广播一条「`腐化野狼 掉落：金币 ×6 · 生命药水`」 |
| 3 | 金币 / 物品去向 | ✅ 已正确入账 | 金币入 `GameState.gold`，其余入 40 格背包（含完整装备实例属性） |
| 4 | 按 I 无反应 | 🟡 计划内空档 | `project.godot` 已定义 `panel_inventory`（I 键），但**全项目无任何脚本监听** → 背包面板属 **M1-7**，尚未实现 |

## 2. 复现与证据

诊断脚本：`tests/pickup_repro.gd` + `tests/PickupRepro.tscn`（开发期回归工具）。

```
/Applications/Godot.app/Contents/MacOS/Godot --headless --path . res://tests/PickupRepro.tscn
```

实测输出（一次真实近战击杀）：

```
[Repro] 击杀前：金币=0 背包=0 地面掉落=0
[Repro] 普攻 6 次后 狼.is_dead=true
[Repro] 死亡当帧：地面掉落=3 玩家→最近掉落物=61.3px（自动拾取半径=96.0px）
[Repro] 第 1 物理帧后：地面掉落=0 最近距离=infpx      ← 1 帧内被全部吸走
[Repro] A 结果：金币=8(+8) 背包=2(+2) 地面剩余=0
[Repro] B 结果：150px 外掉落物 5 物理帧后仍在地面=true  ← 留地逻辑本身正常
[Repro] C 结果：近身装备 3 物理帧后 仍在场景=false     ← 已被自动拾取并释放
[Repro] 背包条目：potion_hp_small ×1
[Repro] 背包条目：shoes_cloth(uncommon) baseAttrs{def:1,mp:5} affixes[mp+11]   ← 实例属性完整
[Repro] 背包条目：helmet_cloth(rare)
```

**对照结论**：掉落物放 150px 外可正常留存 → `GroundItem` 的生成、渲染、计时（60s）、点击拾取链路**均正常**；唯一变量是距离与自动拾取半径的冲突。

---

## 3. 根因分析：三个参数互相矛盾

| 参数 | 取值 | 出处 |
| --- | --- | --- |
| 普攻射程 | 1.0 格 = **64px** | `skills.json: basic_slash.range` |
| 掉落散落半径 | ≤ **18px** | `monster.gd: DROP_SCATTER` |
| 自动拾取半径 | 1.5 格 = **96px** | `ground_item.gd: PICKUP_RANGE_PX`（产品文档 9.9 / 3.14） |

```
击杀瞬间几何关系（近战必经）
玩家 [—— ≤64px ——] 怪物 → 掉落物在其 ±18px 内
最坏情况：64 + 18 = 82px  <  96px  ──► 必定落在自动拾取范围内
```

即：**近战击杀的掉落物 100% 必被立即吸走**，产品文档 7.6 / 9.9 设计的「地面拾取物（可看、可点、超时消失）」体验路径在近战场景下完全不可达。

> 讽刺的是，M1-6 的验收工具 `loot_shot.gd` 自己就写明了这一点：
> 「代表性掉落物（半径 150 > 1.5 格，避免被立刻拾取，便于截图）」—— 验收时人为挪到 150px 才看得见。

## 4. 改造方案（三选项）

### 方案 A：落地保护期（推荐）
`GroundItem` 增加 `PICKUP_DELAY ≈ 0.7s`：生成后的前 0.7s 内**不响应自动拾取**（点击拾取不受限），配合出场弹跳，让玩家先「看到掉落」再被吸走。

- 优点：改动最小（1 常量 + 1 计时器）；不破坏 9.9 的 1.5 格规则；符合 ARPG 通用手感。
- 代价：自动拾取延后 ~0.7s；极端情况（保护期内玩家迅速跑开）物品会留地 60s 后消失。

### 方案 B：缩小自动拾取半径至 < 64px
- 违反产品文档 9.9「≤1.5 格自动拾取」，**不推荐**。

### 方案 C：提示语义与掉落表现（与 A 叠加）
- 掉落瞬间新增一条 toast：`腐化野狼 掉落：稀有 · 布甲头盔`（按品质着色）；
- 拾取时保留 `拾取：xxx`。玩家从此可区分「掉」与「捡」。
- 附加：掉落物出场弹跳 + 落地反馈（可延至 M5-3 打磨）。

### 方案 D：取消地面产物，掉落直接入包
- 破坏 7.6「掉落物为地面拾取物」设计，**不推荐**。

**建议：A + C 组合。**

## 5. 🔴 风险

> 本次已按缓解措施落地：保护期**只限制自动拾取**，点击拾取保持即时；风险 2/3 转入后续阶段复核。

- 🔴 **R-风险1**：保护期内玩家若已走远，物品会留在地面 60s（原为「即打即收」）。缓解：仅限制**自动**拾取，点击拾取保持即时；0.7s 远短于玩家正常位移时间。
- 🔴 **R-风险2**：M1-9 自动战斗（F 键顺路拾取）、M4 自动拾取开关需复核该延迟是否冲突，避免出现「自动战斗时物品捡不到」。
- 🟡 **R-风险3**：连续击杀多怪时 toast 堆叠（现状已存在），掉落提示加入后会加剧；统一在 **M5-5** 做 toast 队列/合并。
- 🟡 **R-风险4**：`panel_inventory` 已占用 I 键，若 M1-7 之前有临时界面占用同键位需先清理。
