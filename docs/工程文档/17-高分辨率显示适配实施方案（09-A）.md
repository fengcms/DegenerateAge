# 17 高分辨率显示适配实施方案（09-A）

日期：2026-10-12。状态：**实施方案（未执行）**。本文只给方案，不改代码。

依据：创意 `09`（v1.0，§9 三判断已确认）· 工程 `16`（D1 纳入 M5、D2 出规格）· 产品 `09` §9.11。
范围：**09-A 基础适配（必做）**；09-B 高级项（175/200% 跨屏热重算、低配渲染清晰度）不在本文内。
归属：**M5 收口，排在 M5-8 打包之前**（15 §2 新增批次 ②B）。

---

## 1. 目标

已确认的三条判断（创意 09 §9）：

| # | 目标行为 |
|---|---|
| 1 | 放大窗口 = **增加地图视野与排版空间**，人物不随窗口同比变大 |
| 2 | 高分辨率屏幕 = **自动保持清晰与可读**，避免一律 200% 密度补偿 |
| 3 | **UI 大小与地图显示大小分开**；人物小可单独放大地图，字小可单独放大 UI / 文字 |

对应验收（创意 09 §8）：六条，见本文 §7。

---

## 2. 根因（现状核对，2026-10-12）

| 层 | 现状 | 后果 |
|---|---|---|
| `project.godot` `[display]` | `window/stretch/mode="canvas_items"` + `aspect="expand"`，基准 1280×800 | 窗口放大 ⇒ **整块画布按比例放大**，元素一起变大、**视野不增**（＝用户"4K 太小 / 放大后全体变大"的直接原因） |
| `Player.tscn` `Camera2D` | **无 `zoom`**，仅 `position_smoothing` | 没有"地图显示大小"入口 |
| `game.gd` 装配相机 | `limit_left/top/right/bottom` = 地图包围盒 | 与缩放配合需复验（见 §6 RK-4） |
| `settings_runtime.gd` | UI 缩放（CanvasLayer 变换，clamp 0.8–1.5）、文字缩放（font_size 覆盖，clamp 0.8–1.5）、窗口 3 档 | 有 UI/文字双入口，但**无地图倍率**、无密度口径 |
| `main.gd` | 已接 `get_viewport().size_changed` → `_apply_ui_scale()` | 窗口变化的重算**已有接线**，可直接复用 |

> 结论：**不是"缺功能"，是渲染策略与产品意图不符** + 缺一个相机倍率入口。

---

## 3. 总体设计：三条独立轴

```
最终视觉 = 地图显示大小(Camera2D.zoom) × 界面大小(CanvasLayer 变换) × 文字大小(font_size 覆盖)
           三者互不影响；各自独立设置项，各自独立默认值
系统密度补偿：由引擎/系统在「逻辑单位」层完成，游戏内**只应用一次**（不重复乘）
```

| 轴 | 载体 | 档位（建议） | 默认 | 影响 |
|---|---|---|---|---|
| **地图显示大小** | `Camera2D.zoom` | 80 / 100 / 125 / 150% | 100% | 人物、地形、技能范围形状、可见怪 |
| **界面大小** | `UI` CanvasLayer `transform` | 80 / 100 / 125 / 150 / **175 / 200%** | 100% | HUD、面板、按钮 |
| **文字大小** | 逐控件 `font_size` 覆盖 | 100 / 110 / 125 / 150% | 100% | Label / Button / LineEdit 文本 |
| **显示适配** | 全局系数（见 M5-9c） | 自动 / 手动（75–150%） | **自动** | 三轴同时乘一次，用于平台信息不可靠时 |

> `zoom = 0.8` ⇒ 等比例可见宽高 ×1.25、面积 ×1.56，**不改变**碰撞、射程、怪物数量、拾取距离（创意 09 §4）。

## 4. 分步实施

### M5-9a 渲染策略切换（核心）

- `project.godot`：`window/stretch/mode` 由 `canvas_items` **改为 `disabled`**。
  - `disabled` 下**逻辑视口尺寸 = 窗口逻辑尺寸**，窗口变大 ⇒ 可见世界变大、元素像素尺寸不变。基准 1280×800 时与现在表现一致（比例 1:1），**不存在"改基准"**。
  - `window/stretch/aspect="expand"` 在 `disabled` 下失效，**保留不删**（便于回退，且在文档/注释里注明失效）。
  - 确认 `display/window/dpi/allow_hidpi` 未被显式设为 `false`（Godot 4 默认 true）——**Retina 清晰度依赖它**。
- **交付证据**：同一位置、同一倍率下窗口 1280×800 与 1920×1200 各截一张，比对"人物像素高度不变、可见地砖数增加"。

### M5-9b 地图显示大小（相机倍率）

- 新设置键 `mapScale`（float，0.8–1.5，默认 1.0），入 `GameState.settings`。
- `SettingsRuntime` 新增 `_apply_map_scale()`：取当前场景 `Game/Entities/Player/Camera2D`，设 `zoom = Vector2.ONE * mapScale`；在 `apply_all()` 末尾调用。
- **切图重载会重建 Player** ⇒ 需在 `game.gd` 装配完 Player 后（现有 `_camera` 已在此处设置 limit）**补一次** `SettingsRuntime._apply_map_scale()`，与 limit 设置放同一段。
- 与 limit 的配合：数据不变时 `zoom < 1` 可见范围更大，相机被 limit 夹住后**地图外围会出现底色空白** —— 这是"地图真实边界外仍受相机限制"的预期行为（创意 09 §4），**不视为缺陷**；是否给边界外做装饰留 M6。

### M5-9c 窗口尺寸变化与「显示适配」

- 现有 `main.gd` 的 `size_changed` → `_apply_ui_scale()` **可直接复用**：
  - `canvas_items` 下窗口变化不改逻辑尺寸，所以此前几乎不触发；改 `disabled` 后**每次拖窗口都会触发**，需确认根 `Control` 的 `size` 重算正确（`_apply_ui_scale` 已按 `viewport/scale` 重设，逻辑成立）。
  - ⚠ 需**节流**：拖动窗口会高频触发，重排 15 个面板可能掉帧 ⇒ 用 `call_deferred` 合并同一帧的多次触发（或 100ms 去抖）。
- 「显示适配 自动 / 手动」：
  - **自动（默认）**：不额外补偿。macOS 上系统缩放已把物理像素换算成逻辑单位，引擎完成密度补偿 ⇒ **游戏内不得再乘一次**。
  - **手动（P1）**：新设置键 `displayScale`（0.75–1.5，默认 1.0，仅手动模式生效），作为**统一系数**乘到三轴最终值上：
    ```
    生效值 = (界面/地图/文字 各自倍率) × (手动 ? displayScale : 1.0)
    ```
  - 实现**不引入** `Window.content_scale_factor`：口径可预测、可无头断言（见 §5 U2）。

### M5-9d 设置面板

`settings_panel.gd` 的「显示」分组调整为：

| 控件 | 改动 |
|---|---|
| 界面大小 | 档位 80/100/120/150 → **80/100/125/150/175/200**（对应 `SettingsRuntime.apply_ui_scale_to` 的 clamp 上限 1.5 → **2.0**） |
| **地图显示大小** | **新增** OptionButton：80/100/125/150% ⇒ `mapScale` |
| 文字大小 | slider 0.8–1.5 → **OptionButton 100/110/125/150%**（`_apply_text_scale` 的 clamp 保持 0.8–1.5，兼容旧档值） |
| 显示适配 | **新增** 自动 / 手动；选「手动」时显示 75–150% 滑杆 ⇒ `displayScale` |
| 窗口大小 / 全屏 | 保留现档位（1280×800 / 1440×900 / 1600×900 + 自动）；建议**补 1920×1200 档**以便直接验证"窗口更大看得更多" |

- **存档兼容**：`GameState.settings` 自 schema 5 入档；三个新键走"缺键取默认值"，**无需 schema 升级**（不写默认值时按 1.0 / "auto" 处理即可，参考现有 `get("uiScale", 1.0)` 写法）。

### M5-9e 世界文字保持可读（反向补偿）

创意 09 §7：**人物 / 地形 / 技能范围形状跟随地图缩放**；**头顶名称、伤害飘字、交互提示保持可读文字尺寸**，但位置仍跟随世界坐标。

- 涉及点：`Fx` 伤害飘字、NPC / Boss 头顶名称、`GroundItem` 名称、出口提示。
- 实现：给这些节点打组 `world_text`，在 `mapScale` 变化时设 `scale = Vector2.ONE / mapScale`（位置不动）。
  - ⚠ 若某节点本就有 `scale`（如飘字动画的伸缩），改为**父节点承载反向缩放**，子节点只做自身动画，避免互相覆盖。
- `zoom < 1` 时若不补偿，世界里的字会跟着变小 —— 这正是"看不清"的来源，**必做**。

### M5-9f 复验与回归

- **逐面板复验**（`Main.tscn` `UI` 下 15 个面板 + `Hud` + `DragLayer`）：在 80 / 100 / 150% 界面倍率 × 80 / 150% 地图倍率 × 1280×800 / 1920×1200 窗口下检查：四边锚点贴合、不越界、不重叠、可滚动。
- **点击与坐标一致**：点选怪物、点地面移动、拖装备到托盘、点击大地图/出口提示 —— 所有倍率下"看到哪点到哪"（创意 09 §8-5）。
- **HUD / Toast / 拖拽幽灵层级不变**：`z_index` 取值约定（面板 0 ＜ `ToastBox` 2048 ＜ 拖拽幽灵 4096）在新策略下**必须复验**。
- **无头回归**（`tests/smoke_test.gd` 新增，按现有冒烟风格）：
  - `_test_display_settings`：设 `mapScale=0.8` → 相机 `zoom == 0.8`；设 `uiScale=1.5` → UI 根 `Control.size == 视口逻辑尺寸 / 1.5`（沿用 `tests/settings_test.gd` 现有断言写法）。
  - `_test_world_text_scale`：`mapScale=0.8` 时组 `world_text` 的节点 `scale ≈ 1.25`。
- **M5-7 回归**：补"倍率无关"用例（工程 16 R3）。
- ⚠ `tests/settings_test.gd` 现有断言依赖 `get_visible_rect().size / 1.5` —— 切到 `disabled` 后语义不变，但**需重跑确认**。

## 5. 需实测确认的不确定点（执行时先验，不要猜）

| 编号 | 待验问题 | 影响 | 验证方式 |
|---|---|---|---|
| **U1** | macOS Retina 下 `Viewport.get_visible_rect().size` 返回**逻辑点**还是物理像素 | 决定密度补偿是否要额外处理（若返回物理像素，需除以 `screen_get_scale()`） | 开窗打印 `get_visible_rect().size` / `DisplayServer.screen_get_scale()` / `window.size`，对照屏幕设置 |
| **U2** | `disabled` 模式下 `Window.content_scale_factor` 是否仍生效 | 若生效，「显示适配手动」可直接用它，实现更短 | 临时设值打印 `get_visible_rect()` |
| **U3** | 切到 `disabled` 后现有 15 个面板的锚点/硬编码尺寸是否仍成立 | 决定 M5-9f 的工作量 | 一次性截图比对（`tests/feedback_shot.gd` 风格） |
| **U4** | 漂字 / 头顶名称是否已有自身 `scale` 动画 | 决定 M5-9e 的反向缩放挂哪一层 | 读 `fx.gd` / `npc.gd` / `ground_item.gd` |

> U1 是**最关键**的一项：结论直接决定"手动显示适配"是否必要。

## 7. 验收清单（对照创意 09 §8）

| # | 验收项 | 判据 |
|---|---|---|
| 1 | 同屏同倍率下扩大窗口 | 角色显示尺寸基本一致，可见地图明显扩大 |
| 2 | 双轴互不干扰 | 改界面大小不改变地图范围；改地图大小不改变 HUD 字体与按钮 |
| 3 | 高密度屏幕 | 字体清晰、按钮可点，默认不小到难辨；**不重复应用 200% 补偿** |
| 4 | 宽高比 / 最大化 / 全屏 / 跨屏 | 不拉变形，关键 UI 不越界 |
| 5 | 点击一致 | 点怪、拖装备、点大地图与出口提示在所有倍率下位置一致 |
| 6 | 逻辑不变 | 地图边界、怪物数量、战斗射程不因显示尺寸改变 |

## 8. 明确不做（09-B / 后续）

- **不**按 3840 / 5120 硬设 200%，**不**按分辨率强制扩大视野（创意 09 §5 不推荐：会让小尺寸高密屏上人物过小）。
- 不做 175/200% 之外的新档位、跨屏热重算、低配"渲染清晰度"选项（09-B）。
- 不做色盲模式 / 独立字号（15 D5 已定：留第一章版）。
- 不把显示器瞬时物理像素写进角色成长数据（创意 09 §7）；显示设置作为**设备偏好**保存。
