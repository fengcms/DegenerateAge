# 随身商店出售页「多件装备」界面变形修复方案（工程 60）

> 触发：实机反馈 —— 随身商队「出售」页里暂存多件高价值装备并点过「确认出售」之后，
> 托盘整体右移、右侧列被裁、底部出现横向滚动条，整个面板看起来「被撑坏了」。
>
> **状态：方案待确认（2026-10-20）。** 未改任何代码。

---

## 一、先说结论

| 议题 | 核实结果 | 结论 |
|---|---|---|
| 托盘右移 / 右侧列失踪 | **是真的，可稳定复现** | `_tray_warn` 没开换行，单行 853px 把内容区顶到 869px，而滚动视口只有 430px |
| 横向滚动条 | 同一根因的副产物 | 兜底开关 `SCROLL_MODE_AUTO` 放行了横向滚动，必须关掉 |
| 是否普遍问题 | **不是**：15 个面板的说明文字都已换行，只有这里两处漏了 | 只改随身商店，不动其它面板 |

一句话：**不是「装备多了」导致的，而是「一句话太长」导致的。**
把 4 件装备的名字拼成一行（853px），而面板内容区只有 430px 宽。

## 二、实测证据

用 `tools/probe_shop_layout.gd`（临时探针，纳入交付前删除）在同一进程里跑四种状态，
逻辑视口 1280×720：

| 状态 | 滚动视口宽 | 内容最小宽 | 横向滚动条 | 托盘 x 坐标 |
|---|---|---|---|---|
| A 打开面板（购买页） | 430 | 430 | 无 | 0 |
| B 托盘 4 件（未点确认） | 430 | 430 | 无 | 0 |
| C 点确认（仍在购买页） | 430 | 430 | 无 | 0 |
| **D 切到出售页** | **430** | **869** | **有** | **273** |

C 行值得单独说一句：风险提示文本已经变成 853px 宽了，但**界面还是好的** ——
因为 `TabContainer` 的最小尺寸只算**当前可见页**，购买页还在正常宽度上。
玩家切到「出售」页的那一瞬间（D），869px 的内容才进入布局，于是：

- 内容区宽 869，滚动视口宽 430 → 右侧 439px 被推到视口外；
- 横向滚动条占掉底部高度，提示行与按钮继续被挤；
- 托盘用「左右各一块弹性空白」居中，在 869px 里居中 ⇒ 从 x=0 挪到 **x=273**，
  即截图里「左边一大块空、右边两列不见了」。

这正是截图呈现的样子，逐项对得上。

## 三、根因链

```
_risky_sale_names() 拼出 4 件装备全名
        ↓  ", ".join(...)
ui.sale_preview.risk = "珍贵装备：传说 镇脉护腕 Lv105 +12, 传说 守誓盔 Lv104 +12, ..."（92 字）
        ↓
_tray_warn.text += "\n" + 上面那行        ← shop_panel.gd:665
        ↓
_tray_warn 是普通 Label：autowrap_mode = OFF（默认）
        ↓  最小宽度 = 整行文本宽度 = 853px（随件数线性增长，无上限）
出售页 VBox → TabContainer → ScrollContainer 内容最小宽 = 869px
        ↓
_scroll.horizontal_scroll_mode = AUTO（:220）⇒ 横向滚动条放行
        ↓
托盘两枚 EXPAND_FILL 空白在 869px 内居中 ⇒ 网格右移 273px、右侧两列被裁
```

三点必须点明，否则容易修偏：

1. **不是「托盘格子太多」**。6×4 固定 306px，从没变过，四个状态下都是 306。
2. **不是 `fit_content` 失职**。它按设计把滚动区夹到 `room.x`（= 视口宽），
   但夹完仍放不下 869px 的内容，此时它的兜底就是「让内容横向滚动」——问题在
   **内容本不该有 869px**，而不是兜底不够。
3. **为什么只在「出售」页发作**。`TabContainer` 的最小尺寸只统计当前页，
   所以购买页时一切正常，切页才炸。这也解释了「以前没发现」。

## 四、同类问题扫描（结论：只有这一处）

扫描 `scripts/ui/*.gd` 全部 24 个面板：15 个含说明文字的面板都已设 `autowrap_mode`，
`shop_panel.gd` 自身也有 5 处（页签提示、随身溢价说明、商品名、商品描述、底部提示）。

**唯独 `_tray_summary` 与 `_tray_warn` 这两行没设**，而这两行恰好是唯一会随
「件数」线性变长的文本（其余都是固定模板或已有换行）。

其余长名单出处均已换行，属安全：
`reforge_panel._affixes/_feedback`、`upgrade_panel._preview`、`warehouse_panel._detail`、
`equipment_fusion_panel._summary`、`carter_panel.greet`。装备出售预览窗
（`equipment_sale_preview._warning`，同一句 risk 文案）**已经开了换行，是正确范例**——
随身商店这处是漏抄。

## 五、修改方案

### P0（必改，三行）

| # | 位置 | 改动 |
|---|---|---|
| R1 | `shop_panel.gd:280` `_tray_warn` | 补 `autowrap_mode = AUTOWRAP_WORD_SMART` + `size_flags_horizontal = EXPAND_FILL` |
| R2 | `shop_panel.gd:276` `_tray_summary` | 同上（金币到 9 位数时「暂存 24 / 24 件 · 结算 999999999 金币」也会顶宽） |
| R3 | `shop_panel.gd:220` `_scroll` | `horizontal_scroll_mode` 由 `AUTO` 改 `DISABLED`（与购买页一致），彻底关掉横向滚动这条兜底 |

### P1（加固，建议同批）

| # | 内容 | 理由 |
|---|---|---|
| R4 | 风险名单折叠：超过 5 件只列前 5 件 + 「等 N 件」 | 托盘上限 24 件，全传奇时 92 字 → 500+ 字 ≈ 20 行，即使换行也会把按钮顶到滚动区外。属于**玩家可见文案变化**，需你拍板（见 §7） |
| R5 | `_tabs.tab_changed` 接 `_update_layout.call_deferred()` | 切页会改变最小尺寸，而现在没有任何信号通知外层重算。本次 bug 的表面症状就是它放大的 |
| R6 | `_tray_warn.text += "\n" + ...` 首行会多一个空行（实测输出以空行开头） | 纯观感，`if text.is_empty()` 分支即可 |

### P2（不做，仅记录）

- 把 `_tray_warn` 拆成「升级件 / 如意 / 风险」三个独立 Label：语义更清，但会动到
  `_on_confirm_pressed` 的二次确认状态机，收益不值风险。

## 六、风险与副作用（🔴）

- 🔴 **R3 关掉横向滚动后，若仍有内容超宽，表现会从「滚动条」变成「直接裁字」**。
  因此 R1/R2 **必须与 R3 同批上线**，不能只做 R3。验收里专门有一条
  「风险文本必须完整可见」来咬这一点。
- 🔴 **R1 会让出售页在窄窗口下变高**（换行多占行高）。面板纵向本来就是
  `EXPAND_FILL` + 纵向滚动，实测 A–D 四态滚动区高度 447 未受挤压；但 800 逻辑宽
  下需复测一次（见 §8）。
- ⚠ 既有测试无一条覆盖该布局（`PortableShopTest` 只测数据与购买链路），
  所以本次**不会让任何现有用例变红**——也正因如此必须新增 R7，否则修完没人守。
- ⚠ `_tray_summary` 增宽改换行后，`暂存 4 / 24 件 · 结算 69262 金币` 在窄面板里可能
  折成两行。属可接受观感，不做额外对齐处理。

## 七、需要你拍板的一件事

**R4 的折叠口径**（影响玩家看到的文字）：

| 选项 | 示例 | 说明 |
|---|---|---|
| A（推荐） | `珍贵装备：A、B、C、D、E 等 9 件。再次点击确认后才会处理。` | 只列 5 件，其余计数；最坏 24 件也只占 3 行 |

| C | 只给件数不给名字 | 最省空间，但玩家看不到自己卖了什么，削弱二次确认的意义 |

我倾向 **A**；若你不想动文案，则只做 P0 + R5/R6，B 方案下最坏情况会很难看但不会崩。

## 八、验收标准

### 自动化（新增 `tests/portable_shop_layout_test.gd`，隔离集 47 → 48）

同一进程内构造面板 → 塞 4 件传奇 + 星 12 → 切出售页 → 点确认，断言：

1. `content.size.x <= scroll.size.x + 0.5`（内容不得宽于视口）

### 与方案的四处差异（都是「预测错了」，逐条记下来）

| # | 方案里的预测 | 实际 |

| R2 | 「去掉 `_tray_summary` 的 autowrap 会让断言 1 红」 | **无牙**。汇总行最长约 300px，永远够不到 430px 阈值；硬造一段超长文本只会变成自证式断言。R2 保留为**同批防御**，**不立独立断言**，也不假装它能被负向验证咬住 |

### 新增测试 `PortableShopLayoutTest`（隔离集 47 → 48）

三条判据，少一条就会「看起来修好了」：

| 判据 | 为什么必须是它 |
|---|---|
| `content.get_combined_minimum_size().x <= scroll.size.x` | **必须断最小尺寸，不能断 `size`** —— `size` 会被父容器钳到视口宽，于是「文字 853px 溢出一屏」的坏实现照样通过。首版断的就是 `size`，是负向验证把它抓出来的 |
| `h_scroll_bar.visible == false` | 横向滚动条正是「网格右移」的直接成因，也是玩家看到的那条灰条 |
| 托盘左右留白之差 ≤ 16 | 玩家截图里看到的「变形」本身；也是唯一咬得住「只钳宽度、不换行」这条错路的判据（那种改法下文字被裁，宽度断言却是绿的） |

覆盖 **1280 宽 / 4 件**（截图场景）、**1280 宽 / 12 件**、**800 宽 / 4 件**，外加一个纯函数折叠断言（12 件只列前 5 件 + 「等 12 件」，且第 6 件之后的名字不得泄漏）。

### 负向验证：2 组有牙、1 组无牙（如实记录）

| 注入 | 结果 |
|---|---|
| 去掉 `_tray_warn.autowrap_mode` | **6 红**：托盘右移（左留白 273）+ 风险文本仍 1 行 + 内容最小宽超视口 |
| `RISK_LIST_LIMIT` 改 99 | **2 红**：折叠断言 |
| `horizontal_scroll_mode` 改回 `AUTO` | **0 红 —— 无牙**。R1 修好后内容不超宽，横向滚动条本就不会出现；不为它硬造场景，如实标注为纯防御 |
