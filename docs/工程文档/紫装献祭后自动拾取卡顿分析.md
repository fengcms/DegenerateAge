# 紫装献祭后自动拾取卡顿分析

献祭批量腾格后，GroundLootIdle 在下一物理步扫描静止集合，并通过 wake(item, true) 同步尝试附近物品入包。扫描没有每步交易预算。每件成功入包都会同步发出 inventory_changed，InventoryPanel._refresh 全量重设格子样式、图标、提示和替换评分，EquipmentFusionPanel 则重算献祭预览。200 格连续回填 20 件会访问约 4000 个背包格。

隔离窗口探针使用 200 格背包，预填 180 件装备，再连续调用真实 pickup_loot 入口 20 次，每次断言成功。未挂载面板耗时 89.9 ms，挂载背包与随身献祭面板并等待布局后耗时 1035.0 ms。每种条件各采样一次，计量交易与同步通知，不含后续绘制。探针使用同一物品样本的副本，未模拟地面走位、活动 Boss 或存档写盘。

建议先让背包和献祭预览每显示帧最多刷新一次，并只更新变化格及受影响评分。库存变动仍应立即撤销旧确认，提交时按最新实例终验。逐件拾取事件继续供任务与交易使用。若仍有尖峰，为积压装备自动回填设置跨物理补步的显示帧预算，下一物理步开始领取，余量分帧处理。

献祭本身的逐 ID 查找、自动出售评分、持久奖励记录删除及同步存档分别计时后再决定优化。存档去抖使用游戏时间，高倍速下可能很快触发写盘，目前未证实是主因。复核应使用同一隔离存档，在 4/8/16 倍速满包积压时执行实际献祭，分别记录确认帧、回填帧 P95 和峰值、刷新次数及回填总时长，并验证奖励、任务计数和确认失效。

## 实施与复核

背包订阅库存、穿戴和等级变化后通过既有 FrameLayoutScheduler 合并展示刷新。逐格比较独立快照，只有内容或对比条件发生变化才重设对应格子。隐藏面板延至打开时刷新。延迟展示期间，格子点击和投放会核对当前库存与显示快照。献祭预览按帧合并，库存变化即时撤销风险确认，提交仍重新构建计划并校验实例。

密集掉落静止调度每个显示帧最多尝试两次附近装备自动领取。同帧的物理补步共享预算，候选未处理完时下一帧续扫。手动拾取和其他地面物入口沿用各自的处理路径。正常回填结束后恢复原来的低频检查。

16 倍速隔离窗口复测使用同一固定种子的 200 格满包，随身献祭 20 件紫装，附近放置 20 件持久待领取装备。探针固定玩家和掉落密度，保留真实献祭、静止调度、拾取、奖励记录及两个面板。自动出售关闭。基线为 8d812420，两组各采样一次。

| 指标 | 优化前 | 优化后 |
|---|---:|---:|
| 献祭确认同步耗时 | 45.3 ms | 1.1 ms |
| 单显示帧最多领取 | 20 件 | 2 件 |
| 领取占用显示帧 | 1 帧 | 10 帧 |
| 拾取调度单显示帧累计峰值 | 992.0 ms | 9.5 ms |
| 确认到回填完成的墙钟时间 | 1115.6 ms | 357.7 ms |

两组均恢复满包并清除 20 条未领取记录。调度峰值包含该调度器调用的同步交易和信号处理。渲染、活动 Boss 和写盘各有独立开销，表中数据对应隔离操作链路。

背包评分、紫装献祭、铁匠、重铸布局、掉落、自动出售和 SmokeTest 定向通过。七项实际窗口回归通过，新增断言覆盖同帧库存变更后重新确认、背包展示更新、多个物理补步共享预算和剩余候选全部领取。全量套件本轮未重跑。存档及自动出售策略维持现有实现，真实存档写盘尖峰仍待实测。
