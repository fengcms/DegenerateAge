# 77-装备耐久度与铁匠一键修理方案

> 状态：**已落地**（2026-10-20，Q1—Q5 全部按建议采纳）
> 需求原话：装备加入「耐久」属性；耐久为 0 时该件自身属性失效（**套装加成还在**）；铁匠新增「一键修理装备」扣金币修理全身。
> 关联：产品 05 §5.15 / 06 经济｜工程 66（套装加成）｜工程 63（自动出售）｜工程 76（槽位角标）｜D-20 节奏锚点｜D-22 金币上限

## 一、结论先行

**需求合理，建议做。** 三个数字问题的直接回答：

| 问题 | 答案 | 锚点 |
|---|---|---|
| 耐久能持续战斗多久？ | **1.5—2.5 小时**（约一章或一次挂机小节） | D-20：一章 500—700 只 ≈ 1.5—2h |
| 一次修满全身多少钱？ | 升级期 **≈ 一章金币收入的 5—10%**；61 级后 **≈ 一次重铸的费用** | 重铸 = `500 × (60 + 0.75L)` |
| 耐久归零怎么失效？ | 只掐该件**自身属性**，**套装加成照常**（按你的规则） | 摘要卡口只有一处，见 §4.2 |

但有一个真风险必须先摆在桌面上：**挂机断装死亡螺旋**（§6 R1）。方案里给了防护层，需要你在 Q3 拍板。

## 二、合理性分析

### 2.1 为什么值得做

1. **补上经济缺口。** 现有金币出口都是低频大额（升星 128,747/件、重铸 5 万+/次），缺一个高频小额的持续消耗口。D-22 已经出现金币顶到上限的迹象，循环图单只金币 9,759（D-21）还在涨——**修理正好是「持续税」型出口**，与重铸互补而不竞争。
2. **给「回城」一个理由。** 现在回城只有卖装 / 合成 / 交任务三个动机。「该修装备了」是经典 ARPG 的回城节拍器，能把城镇重新串进核心循环。
3. **你的「套装加成保留」规则很聪明。** 如果破损连套装一起掉，一件坏 = 全套崩，挫败感是乘法叠加的。只掉自身属性，坏一件只坏一件，惩罚清晰可预期。
4. **实现面小、卡口少。** 属性汇总只有两个消费点（战斗汇总 + 评分），套装评估遍历的是槽位而不是属性——「套装保留」这条规则**天然成立，一行都不用改**（§4.2）。

### 2.2 三个真风险（先说丑话）

| # | 风险 | 说明 | 缓解 |
|---|---|---|---|
| 🔴 R1 | **挂机断装死亡螺旋** | 挂机 2h → 装备陆续归零 → 属性塌 → 在循环图被秒 → 死亡还掉背包装备（death_penalty 现状就是掉一件）→ 螺旋 | 预警阈值 + **随身商店付费修理**（Q3） |
| ⚠ R2 | **修复成本被低估** | 破损件若继续参与「属性更高」评分与出售保护，会出现两个反常：对比时残值虚高、或反向被自动出售**卖掉可修的好装备** | `score()` 与生效属性同源掐断；**自动出售排除已损坏件**（§5） |
| ⚠ R3 | **存档白名单红线** | 给实例加字段动到 `_valid_item`，历史上有「加严格校验 ⇒ 旧档逐件剔除 = 静默毁档」的事故（D-21 教训） | 字段做**可选**，缺失 = 满耐久，`_valid_item` 只在字段存在时校验（§4.7） |

### 2.3 我否掉的两个替代方案

| 替代 | 为什么不做 |
|---|---|
| **按受击 / 按攻击次数损耗**（暗黑 2 式） | 损耗随攻速缩放 ⇒ **装备越好、磨损越快**（反向激励）；按受击则惩罚坦克流派。按击杀损耗对所有流派中性 |
| **按战斗时长损耗**（每分钟 −N） | 「在战斗中」判定模糊（赶路 / 引怪 / 脱战边界），且惩罚谨慎打法。按击杀的判定是无歧义的（有奖励结算 = 一次磨损） |

## 四、设计方案

### 4.1 数据模型与配置

**实例字段**（装备实例新增，唯一新字段）：

```
"durability": 800      # int，0 — maxDurability；缺省视为满（旧档）
```

**新配置 `data/durability.json`**（全部旋钮集中一处，数值调优不改代码）：

```json
{
  "maxDurability": 800,
  "wearPerKill": { "normal": 1, "elite": 4, "boss": 12 },
  "warnThresholds": [0.20, 0.0],
  "repairCost": {
    "earlyPerLevel": 5,
    "earlyMaxLevel": 60,
    "reforgeShare": 0.075
  }
}
```

- `wearPerKill`：按怪物档次取值（`Monster._kind()` 已产出这三个值）。
- 修理费公式见 §4.4，全部参数在配置里，**实测偏贵 / 偏便宜时只改 JSON**。

### 4.2 失效语义（「0 耐久 = 自身属性失效、套装还在」）

**唯一实现（两个卡口）：**

```
Equipment.bonus()   → 破损件 continue（不计入 equip_bonus）
Equipment.score()   → 破损件按 0 分（不参与「属性更高」判断）
```

`equip_bonus()` 是 `total_attack / total_defense / max_hp / max_mp / total_cdr / 暴击 / 闪避 / 移速…` 全部门面的唯一原料 ⇒ **一处跳过，所有属性自动正确**，派生层零改动。

**套装为什么天然保留：** `SetBonus.evaluate()` 数的是「穿了几件、最低品质、最低星级」，根本不读属性字典。破损件仍在 14 个槽里 ⇒ 仍计数 ⇒ **+40% 照常**。这正是你要的语义，而且是白捡的。

**展示层故意不动：** tooltip 照常列出这件装备的攻击/防御/词条（灰显），另加一行红字「已损坏，属性未生效」。这样玩家能看见「修好后拿回什么」，而不是一件空白格子。

### 4.3 损耗节奏：能持续多久（校准表）

**口径：每次击杀结算（`suppress_rewards = false` 时）**，已穿戴 14 件各自按怪物档次扣点，到 0 截止。

以 **maxDurability = 800**、wear = 1 / 4 / 12 为例：

| 玩法 | 节奏锚点 | 耗点速率 | 800 点 ≈ 时长 |
|---|---|---|---|
| 升级推进（一章 ≈ 600 普通 + 40 精英 + 6 Boss） | D-20：一章 500—700 只 ≈ 1.5—2h | ≈ 830 点/章 | **≈ 1.5—2h（刚好一章）** |
| 循环图挂机（30 Boss/h，产品 13：L500 每级 91 只 ≈ 3h） | 每级 91 Boss | 30 × 12 = 360 点/h | **≈ 2.2h（每级修 1—2 次）** |
| 聚金地脉刷金（≈ 350 只/h 普通怪） | 单只 500 金 | 350 点/h | **≈ 2.3h** |

三种主流玩法全部落在 **1.5—2.5 小时** 区间——这就是我对「持续多少时间合适」的回答：

> **约等于一章 / 一次挂机小节。** 短于 1h 会变成琐事（每小时点一次修理），长于 4h 则没人回城，这个出口等于不存在。1.5—2.5h 是「打完一章顺手回城」的自然节拍。

**分档的理由（关键）：** 若统一 1 点/杀，循环图 30 Boss/h 只耗 30 点/h ⇒ 800 点要 26 小时，修理在后期直接消失；而后期恰恰是金币最需要出口的地方（D-22）。Boss 加权让三个玩法的「小时数」对齐，**后期修理依然是常驻出口**。

### 4.4 修理费用：扣多少金币（校准表）

**口径：**
- 单件实收 = `ceil(单件修满价 × 缺失耐久 / maxDurability)`，**只按缺失比例收**，无缺失不收（单件不足 1 金按 1 金）。
- 单件修满价按**装备自身等级**（实例 `level`）计，与玩家等级无关：
  - **L1—60：`5 × level` 金/件**（升级期费率，刻意压低）
  - **L61+：`0.075 × 重铸费(level)` = `37.5 × (60 + 0.75L)` 金/件**（沿用重铸曲线形状，系数 7.5%）

**锚定原则（写进文档防止后人乱调）：**

> **全身修满（14 件）≈ 一次重铸的费用**（61 级后）；**≈ 一章金币收入的 5—10%**（60 级前）。
> 修理是「高频小额」出口，永远不该贵过一次重铸，也不该便宜到无感。

| 等级 | 单件修满 | 全身 14 件修满 | 参照 | 占比 |
|---|---|---|---|---|
| L20 | 100 | **1,400** | 一章收入 ≈ 19,600（700 × 28 金） | **7%** |
| L60 | 300 | **4,200** | 一章收入 ≈ 35,000（700 × 50 金） | **12%** |
| L70（循环） | 4,219 | **59,066** | 一次重铸 56,250 | **≈ 1.05 次重铸** |
| L100 | 5,063 | **70,882** | 一次重铸 67,500 | ≈ 1.05 次重铸 |
| L1000 | 30,375 | **425,250** | 一次重铸 405,000 | ≈ 1.05 次重铸 |

> 61 级后「全身修满 ≈ 一次重铸」在全等级恒成立（两者共用同一条曲线）。
> L60 的 12% 略高是过渡期现象（60 后收入跳 10 倍）；嫌高把 `earlyPerLevel` 从 5 改 4（→ 9.6%），一行 JSON。

**刻意不做的事：不按品质 / 星级加价。** 按星加价会惩罚玩家穿好装备（12 星修理 = 天价 ⇒ 大家穿白装挂机），与升星养成的方向相反。修理费只认等级。

### 4.5 铁匠「一键修理」+ 随身修理（Q3）

**铁匠菜单新增第三组「维护」**（与「强化组 / 合成组」并列，共用 `_build_group` 结构）：

- 按钮文案：**「一键修理（4,219 金）」**——价格直接写在按钮上，**点击即修，不再二次确认**（价格已可见，多一层确认就是纯摩擦）。
- 全身无破损：按钮置灰「装备完好」。
- 金币不足：点击弹 toast「金币不足：需要 N 金」，**一件不修**（与合成的「校验失败不消耗」口径一致）。
- **修理范围 = 身上 14 件**（严格按你的原话「全身」）。背包里的破损件**故意不修**——那些可能是留给出售 / 合成的料，一键修了是白花钱；背包破损件只在 tooltip 标红提示。

**随身商店 / 车夫加「修理」服务（Q3，推荐做）：** 循环图挂机玩家不回城，但断装风险恰恰在循环图最高。随身修理收 **1.5× 溢价**（便利费）：

| 修理点 | 费率 | 场景 |
|---|---|---|
| 铁匠 | 1.0×（基准） | 回城顺手修，最优价格 |
| 随身商店 / 车夫 | 1.5× | 挂机途中应急，买个安心 |

这样「回城修理」仍然是最优解（你的设计意图保留），但挂机玩家不至于眼睁睁看着装备归零。

### 4.6 UI 反馈（不挤占四角）

槽位四角已被占满（工程 76：左上星级 / 右上收藏◆ / 右上↑ / 右下等级），耐久**只用底部 2px 细条**，不进角标：

| 位置 | 内容 |
|---|---|
| 槽位底边 y=50—52 | 耐久细条：**< 100% 才显示**；绿（>50%）→ 黄（20—50%）→ 红（<20%）；允许右段被等级角标黑底压住 |
| 槽位图标 | 耐久 = 0 时整体降饱和（灰显），一眼可辨 |
| tooltip | 「耐久 640 / 800」一行；归零时红字「已损坏，属性未生效」；属性行照常列出（灰显） |
| 预警 toast | 首次跌破 **20%** 与 **归零** 各提示一次（每档一辈子一次，修理后复位）；归零提示带装备名 |

预警必须有节流（每件每档只提示一次），否则 14 件同时破损时 toast 会刷屏。

### 4.7 存档兼容（红线自查）

| 红线 | 本方案的做法 |
|---|---|
| `_valid_item` 绝不加必填校验（D-21 静默毁档教训） | `durability` 是**可选字段**（`favorite` 先例）：**缺失 = 满耐久**，旧档零迁移 |
| 字段存在时怎么校验 | 只校验「是数字、≥ 0、≤ 宽松上界 10000」；**不写死 800**（配置可调），读取时 clamp 到当前 `maxDurability` |
| schema | **不 bump**，保持 14。旧档读入视为满耐久，首次损耗才写入字段 |
| 新实例 | `make_equip_roll` 产出带 `"durability": max`；**必须加在固定字段区**，不得插进 `_roll_affixes` 的 rng 调用序列（随机数顺序红线，ReforgeTest 用例 14 锁死） |
| 重铸 / 升星 / 保星 | 同一实例变异，`durability` 自然保留（降星保星都不重置耐久） |
| 合成产物 | 新实例 = 满耐久（天然正确） |
