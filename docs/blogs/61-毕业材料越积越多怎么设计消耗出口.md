# 末法纪元·游戏开发61：毕业材料越积越多，怎么设计消耗出口

### 前言

各位看官，游戏做到后期，玩家装备已经养起来，背包里却还有越来越多的紫装、如意和金币。继续掉落当然热闹，可没有用途，收获很快会变成清理负担。

最直接的办法，是加一个兑换按钮，把剩余材料换成经验。但如果什么都能无限换，原本的刷怪、装备投入和等级节奏又会被这条新路挤掉。

《末法纪元》逐步增加了紫装献祭、如意重掷取优，以及金砖和钻石如意经验兑换。这篇把这些出口放在一起，看看怎样给积累价值，同时保留选择与边界。

{{IMG:GAME-61-封面}}

### 先确认是多余，还是暂时还没用上

一件低档紫装可能没必要再穿，却可以保星、合成、精炼或献祭；一枚如意升星时很有用，保星成为常用路线以后，原来唯一的用途就可能变弱。

因此新出口不是简单看到库存多，就把兑换比例往上加。需要先画出材料来源和已有用途，看看是哪一阶段的供需关系发生变化。

[第五十一篇]({{LINK:GAME-51}})讲过精炼与抽样，它们消耗材料却服务于不同目标。新增经验出口以后，玩家是在装备优化与等级推进之间分配资源，而不是所有多余材料都自动归经验系统。

这也要求文案避免替玩家判定“垃圾”。系统可以提供默认筛选，真正有投入的装备仍需要保护和明确选择。

### 紫装献祭，经验按装备等级算

当前献祭六十一级开放，只使用背包里的合格紫装，收藏不参与。单件经验锚定装备需求等级对应的循环Boss经验，再按星级加成。

实际计算节选如下：

```gdscript
var raw := float(Balance.boss_xp(Equipment.level_req(item))) * RATIO \
    * (1.0 + float(star) * STAR_BONUS)
return maxi(0, int(round(raw)))
```

为什么不按人物等级？如果高等级角色回低档图快速刷紫装，再按当前等级兑换，就可能用低成本材料换高等级收益，绕开原来的供给约束。

按材料自身等级计价，让旧物仍有用途，又不自动变成当前最高档资源。星级投入也有明确贡献，但默认排除满星底件，避免一键把准备保星的旧装烧掉。

### 一批二十件，是操作边界而非每日配额

当前献祭单批最多二十件，低档优先，满星需要额外选择。这主要控制一次操作与升级反馈的规模，不等于玩家一天只能献祭二十件。

[第四十八篇]({{LINK:GAME-48}})讲过确认锁定本批身份，新拾取的低档紫装不会在第二次点击时挤掉原材料。经验出口也必须遵守同一条玩家意图边界。

最终从当前背包定位原批，资格或计价相关内容改变则整批拒绝。不能为了给出更大经验数字，自动补齐下一批装备，再沿用旧确认。

这里没有把整个装备比较历史都搬进条款，锁定的是消耗与计价相关内容，耐久与格位可以按当前规则变化，减少连续战斗中不必要的打断。

### 如意的第二用途，不直接制造更高上限

如意原来主要提高升星成功率，保星常用以后，可以通过增加词条抽样次数继续服务装备成长。

这个出口的设计重点是多抽取优，而不是再加一条数值倍率。玩家得到的仍是原本合法范围内可能出现的结果，品质、星级与词条上限不因此继续膨胀。

不过它也不是无风险升级券。共用评分选择本次候选的最好一份，不承诺一定胜过旧装备，也不代表适合所有流派。[第五十一篇]({{LINK:GAME-51}})已详细说明这一边界。

给材料找用途时，能改善机会与选择，不一定总要提高绝对上限。否则每一个新出口都继续加战力，平衡工作会被不断推到下一轮。

### 金砖先是储值物，再有经验去向

金币可以在仓库兑换成金条、金砖，再按明确汇率兑回。它先解决储值与资产形态，不代表转换一次就产生经济收益。

后来增加金砖换经验，一百级开放，每块按当前等级升级所需经验的百分之一计算，并按规则取整。每级最多二十块，约补两成进度。

比例的作用在于让兑换价值随当前升级需求变化。固定经验到高等级会逐渐失去价值，按比例又需要额度，避免无限财富直接变成无限等级。

兑换不同时提高装备等级。玩家通过经验跨档以后，穿戴与换装压力仍然存在，不能把等级收益描述成完整战力自动跟上。

### 钻石如意兑换，有独立额度和库存来源

当前每四枚钻石如意作为一批，兑换本级升级需求的百分之一，每级最多十批，与金砖额度独立。

两项大约提供本级三成的补充，但取整与当前进度会影响具体结果，尤其接近满级时不能机械照搬整批理论经验。

这两类经验兑换只扣仓库。背包里的如意仍可供铁匠使用，不能因为全局总数足够，就跨容器自动替玩家扣掉另一处材料。

数量框按批显示，还应明确实际物品消耗。十批不等于十枚，若界面只突出预计经验，玩家很容易看漏四十枚如意这份成本。

### 额度跟等级保存，重开窗口不能刷新

当前角色分别保存金砖与钻石经验兑换已用额度，升级后进入新等级的额度周期。关闭面板或重启游戏，不能把本级已用数清零。

提交前按实时状态重新生成报价，比较兑换类型、次数、成本、等级、收益与已用额度。当前检查的核心如下：

```gdscript
for key in ["exchange_id", "times", "cost", "level", "gain", "used"]:
    if offer[key] != confirmed.get(key):
        return _exchange_fail(Localization.tr_key("msg.brick_xp.stale"))
```

同级战斗增加一点经验，若没有改变本单成本与收益，可以按最新进度结转，不必把旧方案里所有进度变化都重新确认的设想照搬成现状。

但跨级、额度改变或最终到账被满级边界截断，就必须重核。数据更新不一定意味着意图改变，影响条款的变化则不能忽略。

### 一次提交，先记旧等级投入，再走正常升级

当前成功提交会扣仓库材料、增加对应已用额度，再调用统一经验入口，让正常升级、属性成长与剩余结转继续工作。

这样若本单跨级，花掉的额度计在结算前等级，新等级恢复自己的额度。不能先升级清零，再把旧单次数写到新等级，凭空占掉下一轮权益。

防重入也不能只靠确认按钮。经验增加可能广播升级等同步事件，当前提交标记要覆盖这段过程，避免回调再次使用同一份确认。

库存、经验与额度需要进入同一存档快照。只存经验却漏存额度，重新读取以后就能重复购买本级补充，经济规则会从保存边界漏出去。

### 储值兑回，不能照搬出售截断口径

[第五十八篇]({{LINK:GAME-58}})讲手动出售允许按金币上限截断，但金砖兑回金币不一样：玩家是在取回储值，不是在明确清掉冗余装备。

当前兑换规划若发现兑回超过金币上限，会拒绝整笔，不让多余储值静默消失。仓库目标放不下也在副本规划阶段拒绝，不提前扣源材料。

共享加钱能力不表示共享同一产品决定。每个业务入口仍要说明成功是什么、是否允许部分收益，再决定能不能使用截断。

这也是分析消耗出口时必须画清流向的原因。储值转形态、材料换经验、出售清包，表面都是少一个东西多一个数，承诺却完全不同。

### 先验证规则，再观察真实净积累

后续可以沿集中规则和已有回归检查：

```sh
rg -n 'xp_offer|xp_store_after|perLevelLimit' scripts/systems/gold_exchange.gd data/exchange.json
python3 tools/run_isolated_tests.py GoldExchangeTest PurpleSacrificeTest
```

本文未运行游戏测试。实际应覆盖跨堆、额度边界、两项独立、满级、跨级、重复提交，以及保存重读额度不恢复。

经济评价还需要长期样本：固定角色与路线，记录材料净积累、装备投入和升级进度。当前规则提供了出口，不等于已有证据证明所有后期阶段都恰好收支平衡。

### 小结

给毕业材料增加用途，首先要尊重已有投入与来源成本。装备经验看材料等级，比例兑换配每级额度，储值兑回保全资产，几种出口各守自己的承诺。

真正有价值的消耗，不是把库存清零，而是让玩家愿意在几个清楚的目标之间作选择，并且每次选择都能正确扣除、结转和保存。
