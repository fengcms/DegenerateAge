## 0. 一句话结论

**百首禁域的数值比例从 Lv140 起就没变过**（当时 14.7 秒/只，现在 15.9 秒/只，同一口径）。
但那个「15 秒」是**纯普攻**口径算的；你的技能栏已经装满 4 个技能，实际轮转让输出再乘 **1.75 倍（单怪）/ 4.10 倍（3 只同拉）** ⇒ 真实体感约 **8.7 秒/只**，三只一起清 **10.8 秒**。
而 Boss 侧的血量与攻击，**从来不吃「装备」和「技能」这两个乘数**。

## 2. 四层归因（按影响大小排序）

### 层一 · 等级是清白的（必须先排除）

玩家基础攻 `Balance.base_attack(516)` 与 Boss 血量用的是**同一条 `S(d)` 曲线**：

```
S(d) = 1 + 0.12·d + 0.0022·max(0, d−12)²        d = level − 60 = 456
S(456) = 1 + 54.72 + 433.70 = 489.42
```

所以「等级从 140 涨到 516」这件事**本身不改变击杀时间**：

| 口径 | Lv140（工程 94 实测） | Lv516（本次实测） | 倍率 |
|---|---|---|---|
| Boss 血量 | 1,009,558 | 23,785,773 | ×23.6 |
| 玩家普攻 DPS | 68,452 | 1,614,746 | ×23.6 |
| **击杀一只（纯普攻）** | **14.7 s** | **15.3 s** | **×1.04** |
| Boss 每击占血 | 1.28% | 1.23% | ×0.96 |

**结论：从 Lv140 到 Lv516，两端同比例放大，TTK 与承伤占比都没动。** 这是 `Balance.scale` 的设计意图（「升级不改变手感，只改变量级」），本身没问题。

---

### 层二 · 真正的乘数来自装备，而 Boss 侧没有这一项（影响最大）

玩家总攻 / 总血 / 总防都是这个形状：

```
总攻击 = (基础 63,624 + 装备 atk) × (1 + 套装 0.40) × 职业 1.08
总生命 = (50 + 516×8 + (基础攻+装备atk)×2 + (基础防+装备def)×4) × (1+hpPercent) × 1.4 × 0.64
```

单件装备的乘数：**品质 2.4 × 星级 2.2 = 5.28**，14 件叠加后再乘**套装 1.40** ⇒ 相对裸装的等效乘数约 **7.4 倍**。

裸装 vs 当前（同为法师、同等级）：

| 量 | 裸装（只有等级基础） | 当前（14 件紫 12 星） | 倍率 |
|---|---|---|---|
| 总攻击 | 96,199 | **856,743** | **×8.9** |
| 总生命 | 230,019 | **11,448,904** | **×49.8** |
| 总防御 | 43,852 | **951,405** | **×21.7** |
| 击杀一只（纯普攻） | **131 s** | **15.3 s** | 快 ×8.6 |
| Boss 每击 | 594,742（**一击秒杀**，2.6 倍血量） | 140,966（1.23% 血） | 承伤 ÷4.2 |

**同一只 516 级 Boss：裸装被一击打死，满装站着打 81 击才倒。** 中间 200 倍的落差全部来自装备。

而 Boss 的数值公式里**没有装备等价项**：

```
Boss 血量 = norm.hp × S(d) × 2.0        （2.0 是地图写死的 hpMultiplier）
Boss 攻击 = norm.atk × S(d) × 3.0        （3.0 是地图写死的 atkMultiplier）
```

`norm` 是「投影到 60 级的定值」（`hp 24,300 / atk 420 / def 141`），**不随装备、不随技能、不随星级变化**。

> 🔴 结构问题：**装备是「玩家独有的乘数」**。玩家每提升一档装备，TTK 与承伤就再除以一个倍数，而 Boss 只有一条 S 曲线陪着。等级拉不开差距，装备能拉开 8 倍。

---

### 层三 · 技能系统上线后，「15 秒」这个判据已经失真（本次「感觉更快」的直接原因）

`boss_ttk_probe` 与 `class_balance_probe` 算的都是：

```
DPS = 总攻击 × 暴击期望 / 普攻间隔      ← 纯普攻，不含任何技能系数
```

但你的快捷栏已经装了 `frost_roar` / `flame_burst` / `lightning` / `meteor`（全部 rank 5）。技能**占用攻击槽位**（`_attack_cd` 与普攻共用），所以真实输出是「槽位约束下的技能轮转」，不是普攻。

按 `tests/mage_rotation_test.gd` 同一套槽位模型（价值高者先抢槽位、余额给普攻 1.0）：

| 技能 | 总系数（系数×段数） | CD | 可用速率 | 系数 |
|---|---|---|---|---|
| 火焰喷发 `flame_burst` | 0.95 × **3 段** = **2.85** | 3.2 s | 0.313/s | circle r3.5，**无目标上限** |
| 陨石术 `meteor` | **2.10** | 3.8 s | 0.263/s | circle r7，**无目标上限** |
| 冰咆哮 `frost_roar` | 0.85 × **2 段** = **1.70** | 2.8 s | 0.357/s | cone r4.5，最多 5 目标 |
| 雷电术 `lightning` | **1.25** | 0.6 s | 1.667/s | 单体 |
| 火球术（普攻） | 1.00 | 0（靠间隔节流） | 余额 | 单体 |

槽位速率 = `1 / 0.571 = 1.75 次/s`。技能可用速率合计 **2.60/s > 1.75/s** ⇒ **普攻几乎不出现，每个槽位都在放技能**。

| 场景 | 平均系数 | 折算 TTK |
|---|---|---|
| 纯普攻（探针口径） | 1.00 | 15.3 s / 只 |
| **技能轮转 · 单怪** | **1.755** | **8.7 s / 只** |
| **技能轮转 · 3 只同拉（AOE 全中）** | **4.098**（对 3 只总额） | **10.8 s 清 3 只 ≈ 3.6 s / 只** |

百首禁域的席间距决定「同拉约 3 只」（工程 98-b），所以**三只一起清才是你实际看到的节奏**。

> 🔴 这就是「为什么 94 调完当时合适、现在又觉得快」：
> 94 是 2026-10-22 按**纯普攻 14.7 秒**定的 `atkMultiplier 3.0`；
> 法师技能体系（工程 98 / 106）与武士技能重做（工程 107）都在那之后上线，
> **把实际输出抬了 1.75—4.10 倍，而这个增益从未回灌到 Boss 侧**。
> 探针至今仍按纯普攻算，所以「跑探针看着正常」与「实机觉得快」可以同时成立。

### 层四 · 防御是减法公式，没有收益递减（「打不疼」的结构原因）

`Combat.resolve`：`raw = floor(攻 × 系数 − 防 × 0.5)`，`raw ≤ 0` 才走保底。

把两边都投影回 60 级（除 `S(456)=489.42`）：

| 量 | 投影值 | 说明 |
|---|---|---|
| 玩家总防御 | **1,944** | `951,405 ÷ 489.42` |
| 玩家 `def × 0.5` | **972** | 这就是「免伤线」 |
| Boss 基础攻 | **420** | `norm.atk` |
| Boss 需要的最小倍率才破防 | **2.31** | `972 ÷ 420` |
| 当前倍率 | **3.00** | 只超出破防线 29% |

也就是说：**Boss 的攻击倍率只要低于 2.31，对你的伤害恒为保底 60 点**；当前的 3.00 是「刚好破了防」。

反方向（你打 Boss）：

| 量 | 投影值 |
|---|---|
| 玩家总攻击 | **1,750** |
| Boss 防御 | **141** |
| 被防御吃掉的伤害 | **4.0%** |

**双向不对称：你的防御吃掉 Boss 攻击的 77%，Boss 的防御只吃掉你攻击的 4%。**

原因是减法公式没有收益递减 —— 防御只要能顶到「攻击的一半」，承伤就归零；而玩家防御（含装备）已经是 Boss 攻击的 1.54 倍，且**永久封顶在「永远刚好破防」的边缘**，以后每多一件装备，承伤就再掉一截。

## 3. 顺带核对：这算「配错」吗？

按设计口径「打 K 只 Boss 升一级」（`Balance.kills_per_level`）：

| 量 | 值 |
|---|---|
| `K(516)` | 12 + 0.18 × 456 = **94 只** |
| 百首禁域 `xpMultiplier` | **0.25** ⇒ 实际 **376 只 / 级** |
| 单只经验 | 85,595 |
| 升一级耗时（3.6 s/只体感） | **约 22.6 分钟** |
| 升一级耗时（8.7 s/只单怪） | 约 54.5 分钟 |

**升级速度并不失控。** 失控的只有「战斗手感」——怪倒得太快，血条不动，没有任何压力信号。

## 4. 三个可选方向（**需你确认后我才动手，本轮代码零改动**）

| | **A. 回灌技能增益**（推荐） | B. 上调 Boss 血量 | C. 只加压力不加时长 |
|---|---|---|---|
| 做法 | 百首禁域 `hpMultiplier 2.0 → 5.0` 或 `atkMultiplier 3.0 → 4.0`，按「技能轮转后 TTK」回算 | 同上，但只动血量 | 给该图加「多条同拉 + 攻速」，不加血 |
| 依据 | 94 的判据已失真，**这次是把判据修回来** | 只调时长，手感仍无压力 | 保留爽快感，加风险 |
| 副作用 | 击杀变慢 ⇒ 经验/金币效率下降（需同步核 K 值） | 单只更肉，但每击仍 1.23% 血 | 需要新机制（席间距/仇恨），改动面大 |
| 风险 | 🔴 会同时影响 `xpMultiplier` 的收益比 | 🔴 与 A 同 | 🔴 牵动 aggro/leash 硬约束 |

**我的建议**：先做 A 的「校正版」——**用技能轮转后的 TTK（8.7 秒）当新判据重跑一遍**，再决定倍率。因为现在所有循环图的倍率都是按「纯普攻」定的，四张图可能有同样的偏差，值得一次性复核（工程 67 的老口径已经过时）。

**另外两件事建议单独决策**：
1. `hpMultiplier` 只乘一次，而玩家的生命来自「装备 def × 4」的二次放大 —— 若以后继续拉高等级，承伤占比还会继续掉。要不要给 Boss 血量加一个「随玩家装备等级」的项，是个结构问题，不适合现在拍。
2. 探针判据该升级：`boss_ttk_probe` / `class_balance_probe` 现在算的是纯普攻，**和实机差 1.75—4 倍**。以后每次调倍率都会被它误导。
