## 1. 存档有效性与备份保护

**原因确认**：旧 `_is_valid_save()` 只要求存在 `player` 字典，确实会接受 `{"player":{}}`，之后默认值回填可能清空进度，并使损坏主档替换有效备份。

**已修改**：[save_manager.gd](../../autoload/save_manager.gd)。

- 读档、备份准入、直接应用、保存运行态共用完整性校验。
- schema 2 要求进度容器完整，校验角色核心字段、正整数等级与非负整数经验/HP/MP、金币上限、已知地图、有限坐标、背包长度及物品、装备槽匹配、任务状态和设置类型。
- 无版本、未来版本、当前版本缺必需字段、关键字段类型错误的数据不能被当作新游戏导入；主档不合格时尝试备份，主备均不可用则明确失败且不修改运行态。
- 明确声明的 schema 0 保留历史最小格式迁移（至少有合法等级与金币）；完整 schema 1 补入探索、已知新增设置和解锁字段，再完整校验。迁移使用副本，不修改传入原始数据。
- 保存前先校验待写数据；无效主档不会进入备份。备份先写临时副本再替换，复制失败不会先删除旧备份，也不会继续覆盖主档。
- 主档缺失时也能尝试备份；恢复写盘失败给出准确提示，避免把“已读到备份”误说成“已成功修复主档”。直接应用无效字典不改变当前角色。

**建议的适用边界**：不对角色等级引入产品未定义的满级限制；校验其正整数与可序列化数值范围。HP/MP 的负值、错误类型拒绝；合法数值超出当前装备派生上限时，仍按既有规则在应用后收敛，以兼容装备与数值配置变更。探索块内部仍按既有 `Fog.normalize` 过滤非法条目，不因一个过期探索块丢弃整份角色进度。

**验证**：覆盖不完整 JSON 结构、逐项删除核心字段、未来版本、错误容器、未知地图、负金币/HP、错误 MP 类型、直接应用坏档、主备均坏、主档缺失、v0/v1 迁移及备份字节不变。额外验证：不先读取坏主档而直接保存新进度，也不会破坏旧备份。

## 2. 满背包装备交换

**原因确认**：空间预检发生在新装备离开背包之前，错误拒绝了可利用原格的交换。

**已修改**：[equipment.gd](../../scripts/systems/equipment.gd)。

保留物品类型、槽位、等级等前置校验；通过后将旧装备放回 `inv_index`，新装备放入穿戴槽。直接保留两个实例及其属性，不依赖第二次入包操作，不重新生成装备。没有旧装备时，该背包格清空。

**验证**：40 格满包时替换成功，占用仍为 40 格，新旧实例与属性完全一致；满包单独卸装仍被拒绝；错误槽位不修改背包或穿戴状态。

## 3. 多件堆叠入包

**原因确认**：旧实现只查一个未满堆，再用上限截断，确实会丢失本次超出的数量。

**已修改**：[inventory.gd](../../scripts/systems/inventory.gd)。

先合计同种物品所有堆的剩余容量及空格容量，必须装得下完整数量才修改背包。分配时先填已有堆，再按上限拆分新堆；容量不足返回失败且完全不变。拒绝零、负数、非整数数量；输入物品不被修改，包括调用方物品与已有堆为同一字典的情况。

**验证**：98 + 105 正确得到 99 / 99 / 5；只剩 94 容量却添加 95 时完整失败且逐项不变；添加 94 恰好装满；没有空位时可利用多个未满堆；非法数量和别名输入均覆盖。

## 4. Boss 计划缺口

**分类意见**：赞同报告的限定。审阅时这些字段确实尚未接线，但路线图已经列明 M3-5 未完成；它是第一章交付前的阻断项，不是普通怪战斗逻辑的偶发故障。本次按既定方案补齐功能，不改写先前进度记录。

**已修改**：

- [monster.gd](../../scripts/entities/monster.gd)：读取 `bossSkill.phases`，接入实际 AI。
- [spawner.gd](../../scripts/world/spawner.gd)、[boss_tombstone.gd](../../scripts/entities/boss_tombstone.gd)：Boss 刷新点与墓碑。
- [event_bus.gd](../../autoload/event_bus.gd)、[save_manager.gd](../../autoload/save_manager.gd)：首通事件与自动保存。
- [monsters.json](../../data/monsters.json)：显式记录已确认的 `warnDelay: 0.8`。

**运行行为**：

1. 生命达到或高于 60% 时保持普通追击/爪击；严格低于 60% 后增加周期性践踏。
2. 践踏先显示固定位置的圆形预警，0.8 秒后仅对圈内玩家结算；期间不再同时发动普通攻击，离开圆圈可躲避。自动战斗不会跳过预警。
3. 严格低于 30% 时攻击间隔除以 1.3，召唤两只同等级普通野狼；每次 Boss 出生只触发一次，保留第二阶段践踏。
4. 死亡取消未结算预警；首次击杀写入 `first_clear`，按配置设置 `chapter2` 解锁，再广播击杀推进 Q005。首通事件接入去抖自动存档；后续击杀保留正常经验/掉落，不再发首通解锁事件。
5. Boss 死亡生成 300 秒墓碑，显示剩余时间；计时结束移除墓碑并在其位置刷新 Boss。普通怪/精英原刷新流程不变。

**数值与范围说明**：预警半径沿用 Boss 已配置攻击范围，预警结束后的冷却沿用当前攻击间隔，伤害仍走通用结算，不新增伤害倍率。第二章本身的地图内容没有在本次新增；这里落实的是配置要求的解锁标记。刷新点/墓碑计时仍属于当前地图实例，离图释放、重进重建；本次不实现跨图或离线累积刷新倒计时。首杀与解锁则会持久化。

**验证**：60%/30% 边界、真实 AI 入口、0.79 秒不扣血而结束后圈内扣血、离圈免伤、自动模式保留预警、召唤唯一、重复死亡、Q005、首次/再次击杀、首通存读一致、299 + 1 秒刷新边界、世界释放清理；图形窗口核对预警圈及“Boss 刷新 05:00”墓碑。
