## 发现清单

### R01 · P1 · 交易托盘保护只覆盖事件请求，定时与退出存档会漏存物品

**证据与定位：** `autoload/save_manager.gd:289–308` 中，`request_autosave()` 检查 `GameState.trade_staged_count`，但 `_autosave_allowed()` 没有该检查。`_process()` 的定时分支直接调用 `autosave()`，`save_on_quit()` 也直接经统一许可检查进入 `save_slot()`。`_collect()` 只收集背包/仓库/装备，没有托盘内容。托盘由 `scripts/ui/shop_panel.gd` 的 `_tray` 持有，暂存时物品已离开背包。

**隔离实测：** 新建独立项目名与独立 `user://`，在背包第 0 格放入 `weapon_iron` 并保存；移出该物品、设置暂存计数为 1，模拟真实托盘状态；调用正式 `autosave("定时")`。日志：

```text
PROBE initial_save=true
PROBE held=weapon_iron allowed=true
PROBE autosave=true
PROBE read=true slot0=<null>
```

**根因与影响：** 保护在上游请求处而非提交边界，存在绕过路径。打开出售托盘跨过定时存档周期，或带暂存物品关闭程序，主档可能记录为“物品已经移出，但尚未收到货款”。本轮实测覆盖定时入口；退出入口按调用链具有相同风险，未操作真实窗口退出。既有 `tests/review_regression_test.gd:182` 只测试去抖字段，未覆盖真正写盘。

**建议：** 将交易暂存视为独立业务状态，在统一保存边界保护全部入口；退出前需安全回收或持久化托盘，不能仅跳过退出存档而丢弃会话进度。长期把托盘所有权从 UI 下移至交易服务。确认交易应消费一次有效会话，而不只接收任意物品数组。

**复核：** 带托盘分别触发定时、已排队去抖、手动、退出保存，再读档核对物品/金币守恒；补充背包被新掉落或购买填满、关面板退回失败、切图及重复确认的场景。

### R02 · P2 · 测试运行器可能把启动日志当作测试完成

**证据：** `tools/run_isolated_tests.py:260–270` 的完成正则接受任意行尾 `✅` 或 `PASS`。实际调用 `has_completion_marker('[Main] 配置校验通过 ✅')` 返回 `True`。该日志来自 `scripts/main.gd:27`，多个测试会实例化 Main，例如 `tests/menu_flow_test.gd:17`。

**根因与影响：** 完成标记不验证测试身份。某异步测试在主场景启动后未到达最终断言，运行到 `--quit-after` 正常退出，只要没有 `SCRIPT ERROR` / `FAIL`，就可能被算成通过。现有超时与脚本异常检测仍有价值；这里指出的是另一条漏网路径，并不宣称现有全部绿灯无效。

**建议：** 每个测试输出唯一最终标记，例如 `TEST_COMPLETE:<scene>:PASS`，运行器按当前场景精确匹配，帧上限退出且缺该标记必须失败。

**复核：** 添加“只启动 Main 后永不完成”“中途普通 PASS 日志”“正常到达最终断言”三类运行器验证。

### R03 · P2 · 正式导出包含可确认的试作预览资源

**证据：** `export_presets.cfg:9–11` 和第二预设同样采用 `all_resources`，排除列表没有 `outputs/*`。在临时隔离项目使用 Windows Desktop 预设执行 `--export-pack`，导出退出码 0；ZIP 中有 10 份 `outputs/camp_ab_sample_live/*.png.import`，追踪其 `.ctex` 后，压缩载荷合计 **7,692,564 字节（约 7.34 MiB）**。仅 `camp_style_b_blacksmith_200` 对应纹理就占 821,881 压缩字节。运行代码/场景/数据/插件中未检出该 outputs 路径引用。

包中还包含旧 `assets/maps/camp_style_sample/` 的 18 份导入纹理（2,809,765 压缩字节）及 `camp_style_full_b/` 的 25 份（1,560,646 字节）。这两组应进一步核对动态引用后收紧导出边界。

**边界：** 隔离导出未复制 `docs/`、`art_source/`，因此上述是已证实的试作资源混入量，不是完整正式包的冗余总量。数据 JSON 本次正常导出（207 个，含地图索引），没有把空 `include_filter` 误判为“必定漏 JSON”。未运行 Windows 可执行文件。

**建议与复核：** 显式排除试作、设计预览和非运行目录，建立导出清单检查；重新导出后校验所有数据、动态路径资源与 UID，启动全部章节并确认回退正常。不要直接删除整个旧素材目录。

### R04 · P2 · 闪避的显示、缩放和战斗解释不一致（潜伏问题）

**证据：** `autoload/game_state.gd:463` 的 `total_dodge()` 将缩放后数值夹到 0–1；`scripts/ui/character_panel.gd:310` 把它乘 100 当百分比显示。`scripts/entities/monster.gd:974` 附近却把原始 `GameState.player.dodge` 传给 `Combat.resolve()`；`scripts/systems/combat.gd:31` 用评分公式 `dodge/(dodge+50)` 算闪避率。

**影响：** 例如基础值 0.5、无套装时，面板显示 50%，公式却约为 0.99%。套装缩放也绕过实际承伤入口。当前默认 dodge 为 0，本轮未证明正常现有成长能获得非零闪避，所以这是启用该属性前必须解决的潜伏契约问题，不计为当前所有角色都存在的战斗故障。

**建议与复核：** 明确字段是评分还是概率，提供唯一“最终闪避率”入口；面板与战斗消费同一结果。测试非零值、套装前后、上限和旧存档语义。

### R05 · P2 · 怪物能力仍由稳定 ID 和章节前缀决定

**证据：** `scripts/entities/monster.gd:443–447` 按具体 Boss ID 决定狂暴攻速/召唤；`:908–940` 按三个怪物 ID 决定冲锋或横扫及距离；`:1020` 让 `c2_elite_gray_scribe` 固定双发；`:1033–1040` 的治疗固定 4 秒、180 像素、10%，且只治疗 `c2_` 普通怪。文件共 1,564 行。

**根因与影响：** 身份同时承担能力定义。同一种能力复用到其他章节时只复制数据不生效，重命名/复制模板会改变行为；能力参数无法通过既有数据校验完整覆盖。

**建议：** 优先把已经出现复用需求的射弹数、支援治疗、冲锋/横扫和狂暴参数写入能力配置；运行代码保留通用执行器。无需为每个怪物建设复杂继承层级。

**复核：** 保留第二章既有数值与行为断言，再给不同 ID 的模板配置同一能力，确认行为等价、非法参数启动时能被发现。

### R06 · P2 · GameState 职责过载，临时业务状态却分散在 UI

**证据：** `autoload/game_state.gd` 有 2,500 行、162 个函数，同时处理派生战斗属性、背包、掉落、坐骑、装备、仓库兑换、自动维护、合成/重铸、交易、面板协调等。`SaveManager` 1,679 行、`DataLoader` 1,848 行；合成/重铸/商店面板分别 972/887/872 行。R01 是所有权分散产生实际故障的具体例子，而不只是“文件太长”。

**建议：** 保留 GameState 为兼容门面与跨场景状态，按交易、锻造、战利品登记等业务提取服务，明确条件校验、提交、通知三阶段。UI 只保存选择和展示状态，不拥有唯一未落盘物品；迁移/校验可从存档 I/O 中分离，但维持一个保存提交入口。

**复核：** 每次只迁一条业务链，以现有结果测试锁住随机流、收费、事件次数及失败原子性；不一次性全仓重命名和换架构。

### R07 · P2 · 外观体宽缓存没有配置重载失效机制

**证据：** `scripts/entities/monster_appearance.gd:63–70` 的静态 `_body_half_width_cache` 只以 `appearance_id` 为键，命中后直接返回；全仓检索没有清空入口，也未读取 `DataLoader.revision`。同模块 `attach()` 会重新读外观配置。`DataLoader.load_all()` 则明确支持重载并递增 revision。

**影响：** 同 ID 换纹理、帧尺寸后，新视觉可以与旧分离半径并存；第一次素材不可用缓存为 0 后也可能长期沿用回退值。影响热重载、测试和后续编辑工具，未证明当前普通玩家会触发。

**建议与复核：** 用数据修订号失效或显式外观失效事件，并处理失败结果；同一 ID 先装小图、重载为大图，再检查返回半宽及实体间距，覆盖首次缺失后恢复。

### R11 · P3 · 注释与工程入口存在过时口径

### R13 · P3 · 简化怪物纹理仍整表预载，与按图加载策略不一致

### R14 · P2 · 已有 UI 回归测试与当前实现不匹配，验收基线不绿

**实测：** 全量运行中出现 `PortableBlacksmithTest`、`QualityFrameTest`、`RefineTest` 失败；再用新隔离项目单独运行这三个场景，三项均再次失败；随后对 `SetBonusTest`、`SellGearPreviewTest` 各自使用新隔离项目复跑，也都再次失败，排除了仅由前序场景串扰引起的解释。本轮没有修改业务或测试代码，属于当前基线已有问题。

**已定位原因：**

- `tests/portable_blacksmith_test.gd:262、308` 把目标装备放进背包；当前升星/重铸面板的 `_refresh_choices()` 只枚举已穿戴装备，导致目标为空、价签解析为 -1、实际扣费为 0。单独运行报告 6 个失败断言。它不能据此证明正式随身服务费公式算错，但说明这条“显示价等于扣费”的保护没有有效执行。
- `tests/refine_test.gd:242–263` 同样把重铸目标放进背包；`ReforgePanel._selected_item()` 找不到目标，拖入材料直接返回，3 个断言失败。
- `tests/quality_frame_test.gd:31` 调用 `frame._process(0.2)` 后要求跳帧；`scripts/ui/quality_frame_overlay.gd:61–65` 已忽略 delta，改用 `Time.get_ticks_usec()`。手调回调不会推进真实时钟，失败不能直接解释为实机动画不动。

- `SetBonusTest` 另有 6 项显示断言失败：`tests/set_bonus_test.gd:322–340` 实例化默认隐藏的面板直接 `_refresh()`；`CharacterPanel._refresh()` 在 `visible == false` 时提前返回，故文本为空。应通过正式打开入口验收。

## 性能与规范：需要继续测量的候选

以下不计入已证实功能缺陷，也不据此承诺 FPS 提升：

1. `scripts/entities/monster.gd:861` 的同类排斥对普通怪逐帧扫描整个 enemies 组。Boss 自身提前返回，普通怪预算有限，不能仅写成“所有 Boss 平方扫描”。在满普通怪预算、召唤物和多 Boss 同场情况下测脚本 P95/P99，再决定是否建空间索引。
2. `scripts/systems/loot.gd:154` 每抽一件装备重新扫描装备表构建匹配列表。多倍件数 Boss 掉落可能重复这项工作；可考虑按配置 revision、套档、掉落池缓存候选，并保持随机调用顺序。需测真实密集掉落峰值。
3. `SaveManager._collect()` 深拷贝、校验、JSON 编码、读回核对与备份均同步执行。保全大量地面奖励时可能增长；应按真实大存档测保存时间，不能随意删除未领取奖励换性能。
4. `scripts/systems/crash_trace.gd:84–98` 默认启用，关键事件即时 flush，心跳已有节流、日志已有轮转。应评估慢盘尾延迟，不能简单指认为无限日志泄漏，也不宜不加分析地删除崩溃取证。

本轮未运行真实渲染窗口/GPU 基准、长时间窗口挂机、完整手工通关与 Windows 可执行版本。不把无头逻辑测试的耗时当作 60 FPS 证明。
