## 1. 问题域划分总览

按「内容数据的四个层面（数据 / 地图 / 战斗 / 任务与成长）+ 横切的验证与交付」切分为 **6 个问题域**，每域一份独立报告。

| 编号 | 问题域 | 一句话目标 | 优先级 | 产出文档 |
|---|---|---|---|---|
| **A** | 数据契约与引用完整性 | 三章登记的八张表是否自洽、可解析、与创意文档逐项一致 | 高 | `A-数据契约与引用完整性.md` |
| **B** | 地图拓扑、交通与门禁 | 六图/章拓扑、出口入口配对、车夫报价、门禁解锁链是否成立 | 高 | `B-地图拓扑交通与门禁.md` |
| **C** | 战斗与首领动作 | 三档次敌人、共享线/扇/圈预警、二/三阶段、脱战归位、首通与复刷是否正确 | 高 | `C-战斗与首领动作.md` |
| **D** | 任务链、发奖与结局状态机 | 前置链、三态分离、发奖计划持久化、放弃重接、结局幂等是否可靠 | 高 | `D-任务链发奖与结局状态机.md` |
| **E** | 装备掉落与存档迁移 | 三轴模型、掉落表与池、词条与品质、存档 schema 迁移是否自洽 | 中 | `E-装备掉落与存档迁移.md` |
| **F** | 测试覆盖与交付可复现性 | 断言是否真实、是否进回归集、提交与产物纪律是否达标 | 中 | `F-测试覆盖与交付可复现性.md` |

执行顺序：先 A（数据是一切的地基），再 B/C/D/E（四层内容），最后 F（验证与交付）。
收尾追加 `Z-交付物清单与总评.md`（仅清单与总体结论，**不合并各域正文**）。

## 2. 各问题域执行细则

### A · 数据契约与引用完整性

**要回答的问题**

1. 三章地图（第四、六章各 6 图，第五章 7 图）是否都登记齐全，八张表（maps / monsters / quests / equipments / dropTables / lootPools / miscItems / shops）跨表引用是否**全部可解析**？`DataLoader.validate_all()` 是否真的零问题？
2. `tierRange` 与刷新等级的关系是否成立：刷新等级是否等于 `clamp(模板等级, 该图 tierRange)`？三章是否用同一口径，有无某章特例？
3. 怪物数值（HP/攻/防/经验）是否与创意文档 `第六章/03-怪物精英与Boss.md` 等逐项一致？职责（近战/远程/盾卫/重型）与 `attackRange.kind`、`moveSpeed` 是否与文档表格一致？
4. `shops.json` 的买入条目格式是否沿用"元素单行内联"约定？有无把整表重写成多行缩进而污染 diff？
5. `miscItems.json` 的任务袋物品是否都 `useType=quest`、是否与任务 `objective.sourceMonster` 对上？

**证据来源**：`data/maps.json`、`data/monsters.json`、`data/quests.json`、`data/equipments.json`、`data/dropTables.json`、`data/lootPools.json`、`data/miscItems.json`、`data/shops.json`；`autoload/data_loader.gd`（校验口径）；创意文档 `docs/游戏创意/21-60级内容规划/第四|五|六章/03-*.md`、`04-*.md`；`docs/工程文档/32|33|34-*.md`。

**判定标准**：跨表引用做**静态交叉校验**（以校验器口径为准并逐表复核）；数值逐项比对文档；发现不一致给 P1，内部不自洽给 P1/P2。

### B · 地图拓扑、交通与门禁

**要回答的问题**

1. 三章的枢纽图 / 野外图分工（`kind` = hub / spoke、`hubId`、`safeZone`）是否与规划 §1/§3 一致？枢纽是否真的零刷新点、零首领位、服务点集中在 `safeArea` 内？
2. 跨章枢纽门户的**双向边配对**是否严格成立：源图 exit 的 `cell` 在源图、`toEntrance` 指向目标图 entrances 的 key、目标图存在反向 exit、且**目标图 entrance 的 cell 等于该图反向 exit 的 cell**？三章是否用同一约定（早期章顶中、后期章西侧）？
3. `hubLinks` 是否只出现在 hub ↔ hub 且双向、相邻章不越级？`carterFare` / `carterFares` 的取值（普通野图 150、首领图 250、枢纽间 400/500）是否一致？
4. 每个 `requiresUnlock` 是否**确有**某任务的 `reward.unlock/unlocks` 产出？三章的门禁链（c3_access_* / c4_access_* / c5_access_* / c6_access_* / campaign_complete）是否首尾相接、无悬挂键？
5. 布局文件（`data/layouts/*.json`）的掩码、`walkable_rows`、出口格可达性是否与 maps 数据一致？是否存在"出口落在不可走格"或"入口不可达"？
6. 三章的构建脚本 `tools/build_chapter_*_layouts.py` 是否可重复执行（幂等）、是否依赖外部素材路径、是否会把中间产物写入 `assets/`？

**证据来源**：`data/maps.json`、`data/layouts/c4|c5|c6_map*.json`、`tools/build_chapter_*_layouts.py`、`autoload/map_service.gd`、`scripts/world/cave_layout.gd`（或等价实现）；测试 `Chapter[Four|Five|Six]RoutesTest` / `Chapter[Four|Five|Six]MapTest`；`docs/工程文档/32|33|34-*.md` §1/§3/§5。

**判定标准**：拓扑与配对做**逐边枚举核对**（写一次性只读脚本枚举，不入库）；门禁做"产出方—消费方"双向匹配；布局做"掩码 ↔ 数据"对照。

### C · 战斗与首领动作

**要回答的问题**

1. 三章的怪物档次（normal / elite / boss）与外观半径、`ai_enabled`、`affixPool` / `affixCount` 是否与文档一致？精英词缀池三章是否统一？
2. 共享 `BossAction` 组件的语义是否被三章正确使用：`shape` 三选一、`segments` 的"同一段只结算一次"、`MIN_LOCK`、预警期间不结算、按**锁定几何**结算？
3. `phaseB`（50% 血）与新增 `phaseC`（25% 血）的触发与效果是否与创意文档第六章/03 第 33、60 行一致？`phaseC` 是否只影响 A 招重复间隔、**不缩短预警、不改变安全通路、不召唤新实体**？非空天之眼首领是否**不受影响**？
4. `phaseC` 的接入是否是最小改动、是否改变了原有 `phaseB` 行为？有无引入对既有章节首领（c1—c5）的回归风险？
5. 脱战 5 秒归位回满、离场心 18 格判定、复刷 600 秒 + 墓碑 + `bossCap=1`、首通去重（同 id 只广播一次）是否三章口径一致？
6. 刷新预算（`normalCap` / `eliteCap` / `bossCap`）是否与规划一致？"按地图 kind 配置"的机制是否对非章节图（营地/第一章）产生副作用？

**证据来源**：`scripts/entities/boss_action.gd`、`scripts/entities/monster.gd`、`scripts/world/spawner.gd`、`data/monsters.json`、`data/maps.json`（caps/bossSpawn）；测试 `Chapter[Four|Five|Six]CombatTest`、`BossActionTest`、`BossReviewTest`；创意文档 `第四|五|六章/03-*.md`。

**判定标准**：动作状态机逐阶段核对；`phaseC` 做"阈值前后行为差异"的定向验证；对既有章节首领做**回归确认**（原测试是否仍全绿）。

### D · 任务链、发奖与结局状态机

**要回答的问题**

1. 三章主线/支线的 `prev` 前置链是否首尾相接、无环、无断点？每条任务的 `giver` / `turnIn` 是否可定位到真实 NPC，且 NPC 所在图在 `mapScope` 内？
2. `mapScope` 与目标是否匹配：击杀目标是否**真的**在该 scope 图刷新（`spawnPoints` / `bossSpawn`）？收集来源怪是否在该 scope 图？交谈目标 NPC 是否在该 scope 图？
3. 三章的"三态分离"是否严格：击杀/收集达标 → 回城交付 → 结局标记，**击杀不直接写 `campaign_complete`**，且各章终章任务是否真的把章门禁键写在 `reward.unlock/unlocks`？
4. 持久发奖计划（`GameState.quest_reward_plans` + schema 14）是否可靠：满包失败**不静默丢奖**、重试**复用同一实例与词条**、成功后清除计划、不重复发金币/经验？
5. 支线放弃/重接是否清空计数与任务袋物品？主线是否**不可**放弃？章节门禁是否因放弃支线而被误回收？
6. 结局幂等与"不清成长"是否成立：重复读档奖励只一次、等级/金币/背包不回退、旧章枢纽与后续支线仍可达？会不会出现"结局后旧内容不可达"的死锁？

**证据来源**：`data/quests.json`、`scripts/systems/quest.gd`、`autoload/game_state.gd`（`quest_reward_plans` / `quest_items`）、`autoload/save_manager.gd`（schema 14 迁移）；测试 `Chapter[Four|Five|Six]QuestsTest`、`QuestRewardPlanTest`、`MapGateTest`；创意文档 `第四|五|六章/04-任务链与任务卡.md`。

**判定标准**：前置链做静态拓扑核对；三态分离做"阶段间断言"复核；发奖计划做**失败注入**路径复核；结局做读档往返复核。

### E · 装备掉落与存档迁移

**要回答的问题**

1. 三章各 10 个型号是否满足三轴模型约束：`tierBases` 只登记**一个**套起点（31 / 41 / 51）、`requiredLevel` 与 `slotOrder` 一一对应（`slotOrder` 第 i 位 → `requiredLevel = 套起点 + i`）、错档型号**没有**可借用基底？
2. `equipmentRules.json` 的 `tiers` / `affixTierScale` / `tierValueMultiplier` 是否已覆盖 31 / 41 / 51？是否有"数据已登记但规则键缺失"的悬空？
3. 掉落表 `DT_C4_*` / `DT_C5_*` / `DT_C6_*` 的 `tierStart` / `levelRange` / 质量权重合计是否与规划一致？三章是否都用 `lootPools` 共用十型号（`c*_normal` 与 `c*_legendary` 同池）？
4. 传说追加槽能否覆盖不同部位（而非总是武器）？Boss 池是否只产本章型号？
5. 旧存档迁移：按实例版本收敛 + 逐件丢弃不可识别装备的策略是否真的"坏一件不坏全档"？schema 版本与迁移链是否与既有版本兼容（不重复迁移、不重复发奖）？
6. 三轴的 `ruleVersion` 是否统一？新增章节后 `equipment_axes_test.gd` 的扩展是否**只加数据**而没有放宽既有断言（防止把闸门改松）？

**证据来源**：`data/equipments.json`、`data/equipmentRules.json`、`data/dropTables.json`、`data/lootPools.json`、`scripts/systems/item_factory.gd`、`scripts/systems/loot.gd`、`autoload/save_manager.gd`、`autoload/item_util.gd`；测试 `Chapter[Four|Five|Six]LootTest`、`EquipmentAxesTest`、`ReviewRegressionTest`；`docs/工程文档/26-装备等级品质星级三轴模型实施规划.md`、`docs/工程文档/07-首次数值校准方案.md`。

**判定标准**：三轴约束做**枚举校验**；`equipment_axes_test.gd` 的 diff 逐行审，确认是"扩展覆盖"而非"放宽断言"；迁移做"构造坏件存档 → 读档"复核。

### F · 测试覆盖与交付可复现性

**要回答的问题**

1. 三章各自 5 个场景（Routes / Combat / Quests / Loot / Map）是否**都**存在且可独立跑通？断言是真实业务断言，还是只判断"字段存在/数组非空"的形态断言？
2. 新场景**是否进了默认隔离回归集**（`tools/run_isolated_tests.py` 无参数运行时是否包含三章场景）？若未进，为什么、是否有意为之？
3. 是否存在**假绿**：断言恒真、`check()` 被吞、或"未输出完成标记也算通过"被反过来利用（runner 是否真的把无标记判 FAIL）？
4. 三章提交是否遵守纪律：每批独立提交、`git add` 指定具体文件、无临时探针入库、无 `.gd.uid` / `__pycache__` 入库、无把协作者文件夹带？
5. 构建脚本与临时脚本的边界：`tools/build_chapter_*_layouts.py` 入库（可复现），`tools/_tmp_register_c*.py` 一次性脚本是否已删除且未入库？
6. 文档同步：`30`（总览）的 E0—E5 行、`32/33/34` 的交付状态是否与代码实际一致？"待确认/待开始"等旧标注是否清除？
7. 可复现性：三章验收是否能由他人按文档独立复跑？复跑命令、通过判定（退出码 0 + 出现"全部通过/PASS"+ 无 `SCRIPT ERROR`）是否写明？

**证据来源**：`tools/run_isolated_tests.py`、`tests/chapter_[four|five|six]_*.gd` 与其 `*.tscn`、`tests/test_registry*`（若存在）；`git log --name-only` 逐提交核对；`docs/工程文档/30|32|33|34`、`AGENT.md` §10。

**判定标准**：断言逐条人工审读，标出形态断言与恒真断言；回归集做**清单核对**；提交纪律做逐提交文件清单审计。

## 3. 复跑与验证方式

- 隔离回归（默认 25 项）：`python3 tools/run_isolated_tests.py`
- 定向场景：`python3 tools/run_isolated_tests.py ChapterFourRoutesTest ChapterFourCombatTest ... ChapterSixMapTest`
- 通过判定：退出码 `0` + 输出含「全部通过 ✅」/`PASS` + 无 `SCRIPT ERROR`。
- 注意：Godot 需写用户目录（`~/Library/Application Support/Godot`），**必须在非沙箱环境执行**；沙箱下会出现 `hit restricted` 类假失败，不可作为结论依据。
