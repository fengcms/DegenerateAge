# 核心完整度审查 · 审计计划

> 配套：`00-总体方法论.md`。本文件定义**问题域划分、每域要查什么、证据来源、判定标准、产出文档清单**。
> 基线快照：`773b7d1`。范围与排除项同方法论 §2，不再重复。

---

## 1. 问题域划分总览

按「核心循环链路 + 系统横切关注点」切分为 **8 个问题域**，每域一份独立报告。

| 编号 | 问题域 | 一句话目标 | 优先级 | 产出文档 |
|---|---|---|---|---|
| **A** | 核心循环与战斗结算 | 战斗到底算得对不对、闭环有没有断点 | 高 | `A-核心循环与战斗结算.md` |
| **B** | 系统架构与数据驱动 | 结构是否清晰、数据是否单一事实源、接口是否稳定 | 高 | `B-系统架构与数据驱动.md` |
| **C** | 存档与兼容 | 进度会不会丢、迁移与备份是否可靠 | 高 | `C-存档与兼容.md` |
| **D** | 性能与长时稳定 | 会不会越玩越卡、长挂机是否安全 | 高 | `D-性能与长时稳定.md` |
| **E** | 装备/成长/经济系统逻辑 | 数值链路是否自洽、缓存会不会过期 | 中 | `E-装备成长与经济逻辑.md` |
| **F** | UI/输入健壮性 | 面板互斥、输入接管、缩放、本地化是否可靠 | 中 | `F-UI与输入健壮性.md` |
| **G** | 错误处理与边界 | 异常输入与极端状态是否被正确处理 | 中 | `G-错误处理与边界.md` |
| **H** | 测试覆盖与发布就绪度 | 验证是否可信、能否真正交付 | 中 | `H-测试覆盖与发布就绪度.md` |

执行顺序：先 A/B/C（决定「核心是否完整」的骨架判断），再 D/E/F/G/H（健壮性与交付）。
最后追加 `Z-交付物清单与总评.md`（仅汇总清单与总体结论，**不合并各域正文**）。

## 2. 各问题域执行细则

### A · 核心循环与战斗结算

**要回答的问题**

1. 产品 00 核心循环图每个节点是否都有运行实现与反馈？（探索→战斗→掉落→拾取/使用→升级→挑战精英/Boss→解锁）
2. 伤害公式（产品 03 §3.2）、概率 Miss/上限（§3.5/§3.8）、受击保护是否与文档一致？
3. 死亡与复活（产品 04 §4.8）两条路径是否闭环、能否重复结算？
4. 等级差经验（§3.x）、精英词缀、Boss 三阶段/首通/墓碑是否真正接线（第一轮审阅 P1 是否闭环）？
5. 是否存在「数据已配置但代码未读取」的机制悬空项？

**证据来源**：`scripts/systems/combat.gd`、`scripts/entities/monster.gd`(1059 行)、`scripts/entities/player.gd`、`scripts/systems/auto_battle.gd`、`scripts/systems/death_penalty.gd`、`scripts/world/spawner.gd`、`scripts/entities/boss_tombstone.gd`、`data/monsters.json`、`data/skills.json`；测试 `CombatShot`/`BossReviewTest`/`DeathChoiceTest`/`SkillCombatTest`；产品 03/04。

**判定标准**：链路节点逐项给 A–E 分级；公式逐项比对文档；死亡/首通做重复触发检查（E2+E1）。

### B · 系统架构与数据驱动

**要回答的问题**

1. Autoload 是否只放跨场景必需服务？有无把地图/临时对象长期挂全局？（AGENT.md §9）
2. 数据加载器（721 行）启动校验覆盖哪些规则？跨表引用是否校验存在性、类型、范围、重复项？
3. 模块职责边界：系统/实体/UI/世界分层是否清晰，有无 UI 重复结算业务逻辑？
4. 公共接口（信号载荷、数据字段）修改是否同步了所有调用方？有无散落字符串/节点路径耦合？
5. 共用规则是否有唯一入口，有无重复维护的常量？

**证据来源**：`autoload/*.gd`(8 个)、`scripts/systems/*`、`scripts/world/*`、`scripts/ui/*`、`data/*.json`(22 个)、EventBus 信号清单；工程文档 01/08。

**判定标准**：对照 AGENT.md §2/§6/§9 逐条核；跨表引用做静态交叉校验（E3+E2）。

### C · 存档与兼容

**要回答的问题**

1. 当前 schema（以 `save_manager.gd` 的 `CURRENT_SCHEMA` 为准，实测为 **13**；`game_state.gd` 的 `SCHEMA_VERSION=6` 为陈旧常量）必填字段与校验覆盖是否完整？第一轮审阅 P1 修复是否闭环且无新漏洞？
2. 迁移链（低版本→当前版本）是否可重复执行、不重复发奖/扣费/迁移坐标？
3. 写入原子性与备份：写盘失败、主备均坏、主档缺失三条路径是否明确、不静默？
4. 运行态与落档边界：哪些该存、哪些不该存（技能冷却、自动战斗开关、menu_mode 等）是否与文档一致？
5. 跨图/跨档状态（spawn_respawn、未领战利品、world_time）序列化是否正确、不无限增长？

**证据来源**：`autoload/save_manager.gd`(1076 行)、`autoload/game_state.gd`(1100 行，含 encode/apply)、`tests/ReviewRegressionTest`、`tests/SmokeTest`；工程文档 06；产品 10。

**判定标准**：schema 字段逐项核对；迁移与备份路径做注入测试（E1 优先）。

### D · 性能与长时稳定

**要回答的问题**

1. AGENT.md §2「必须保留的性能架构」7 项是否仍在？有无退回逐格绘制/逐候选全量计数？
2. 热路径（`_process`/`_physics_process`）是否含资源加载、JSON 解析、全表查询、深拷贝？
3. 缓存键/所有者/生命周期/失效事件是否明确？读档、切图、门禁变化是否覆盖？
4. 节点/内存是否随长时间挂机增长？既有 SoakTest 基准是否仍成立？
5. 掉落/特效/地面物是否有明确创建→认领→回收入口，有无脱组残留？

**证据来源**：AGENT.md §2 表中入口（`map_canvas.gd`/`flat_tile_mesh.gd`/`ground.gd`/`spawner.gd`/`cave_layout.gd`/`cave_navigator.gd`/`map_service.gd`）、`scripts/systems/loot_burst.gd`、`scripts/entities/ground_item.gd`；测试 `MapPerformanceTest`/`SpawnerBudgetTest`/`MapCanvasCacheTest`/`FlatTerrainMeshTest`/`MapLoadingCacheTest`；工程文档 09；审阅报告性能相关系列。

**判定标准**：静态核对架构约束（E2）；必要时跑基准测试对照历史数据（E1）。无实测则标注推断。

### E · 装备/成长/经济系统逻辑

**要回答的问题**

1. 装备三轴（等级/品质/星级）、14 槽、双槽、穿戴等级门槛逻辑是否自洽？第一轮 P2 换装修复是否闭环？

4. 大幅数值链路：升级 HP/MP 结转（T05）、金币上限、随机词条/词缀范围越界？
5. 仓库/背包/坐骑/快捷栏（模板引用）状态一致性。

**证据来源**：`scripts/systems/equipment.gd`、`equipment_math.gd`、`inventory.gd`、`upgrade.gd`、`item_factory.gd`、`warehouse.gd`、`shop.gd`、`hotbar_config.gd`、`scripts/ui/equipment_confirmation.gd`；`data/equipments.json`/`upgrade.json`/`affixes.json`/`shops.json`/`equipmentRules.json`；测试 `EquipmentAxesTest`/`ReviewRegressionTest`/`SkillCombatTest`；产品 05/06。

**判定标准**：逐项比对产品公式；缓存失效做静态路径覆盖检查（E2）。**不含具体数值调平**。

### F · UI/输入健壮性

**要回答的问题**

1. 面板互斥（`_open_panels`/`set_panel_open`）是否正确？输入接管与手动接管语义（4.6：立即接管、3 秒恢复）是否可靠？

4. 关闭面板未确认的中间状态（如交易托盘、装备确认）是否回退正确？
5. 面板打开时世界时钟/战斗暂停语义是否一致？

**证据来源**：`scripts/ui/*`(约 30 个)、`scripts/systems/settings_runtime.gd`、`autoload/localization.gd`；`docs/素材设计/08/10`；测试 `PanelChromeLayoutTest`/`FloatingWindowInputTest`/`SettingsTest`/`HotbarUiTest`/`InputFeedbackTest`/`FlowFeedbackTest`；产品 09。

### G · 错误处理与边界

**要回答的问题**

1. 存档异常、数据非法、背包满、金币不足、技能不可用、路径不可达等失败路径是否有明确反馈、不静默？（AGENT.md §9）
2. 重复输入/重复信号/异步重入是否会造成重复结算？（发奖、购物、旅行、Boss 首通）
3. `await`/延迟恢复后是否重新校验节点/目标/场景/版本？
4. 信号有无重复连接/未断开？切图后是否仍向旧节点更新？
5. 日志是否限频、不泄漏敏感存档内容？错误信息是否含模块/ID/场景？

**证据来源**：`autoload/save_manager.gd`、`scripts/systems/quest.gd`、`shop.gd`、`upgrade.gd`、`travel_item.gd`、`consumable.gd`、`scripts/world/game.gd`、`scripts/systems/auto_battle.gd`；测试 `ReviewRegressionTest`/`RandomTicketTest`/`DeathDropTest`/`DeathChoiceTest`。

**判定标准**：逐条对照 AGENT.md §9；关键复合操作做重入/重复触发推演（E2，必要时 E1）。

### H · 测试覆盖与发布就绪度

**要回答的问题**

1. 测试场景（实测约 61 个，其中默认回归集 22 个）覆盖了哪些核心路径？有无关键路径无测试？
2. 测试判定是否可信（退出码、异步完成标记、无 SCRIPT ERROR）？有无「重述实现」的空测试？
3. 已核实失败基线的当前状态；有无工作区（协作者）改动影响结论？
4. 发布就绪：导出配置、调试入口/作弊开关是否泄漏、启动日志、`user://` 保护、本地化缺 key 可检测？
5. 全量隔离回归是否可一次跑通？结论是否可复现？

**证据来源**：`tests/*`（约 61 个测试场景）、`tools/run_isolated_tests.py`、导出预设、`project.godot`、工程文档 15/25、`.gdignore` 相关。

**判定标准**：测试与核心路径做覆盖矩阵；执行全量隔离回归记录结果（E1）；发布项逐条核对（E2+E3）。

## 4. 裁定门槛：「核心是否比较完整」的汇总规则

在 `Z-交付物清单与总评.md` 中给出总结论，规则如下：

- **核心完整（可交付 MVP）**：A–G 域中，核心循环链路节点无 C/D 级；无未闭环的 P0；P1 已闭环或有明确计划。
- **核心基本完整**：主路径 A 级，但存在少量 B 级项或 P2 未处理（不阻断交付）。
- **核心不完整**：存在任一链路节点 C/D 级，或存在未闭环 P0。

总结论须**逐域引用**各自报告的完整度分级，不脱离证据给结论。已声明为「后续工作」的排除项单列，不参与判定。

## 6. 风险与限制

- **静态为主的偏差**：不跑完整游戏手动流程，手感/观感类结论不可得；已标注推断。
- **工作区非干净**：协作者改动可能影响个别测试结论，须在报告中注明快照状态。
- **性能实测成本**：4K/长时间压测按需执行，若未测则不承诺帧率类结论。
- **范围蔓延**：审查中若发现排除项（美术/后续内容）相关问题，只记录事实，不展开修复方案。
