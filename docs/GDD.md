## 0. 文档目的与约束

本文件是项目的**唯一首版需求基线**，供开发者和 Codex 共同使用。除明确标注“后续版本”或“可选”的内容外，第一章版本的实现应遵循本文件。开发任务须小步迭代、每阶段具备可运行版本及验收记录，不允许为追求功能数量而牺牲完整的打怪—掉落—成长闭环。

**产品定位**：玩家在末法时代的人类失地上创建守护者，探索斜角地图、实时击败怪物，获取经验、金币、药品和装备，逐步解锁技能与地图，击败各章节 Boss，最终关闭异界裂隙，拯救人类。

**明确不做**：联网、多人、服务器、交易市场、公会、抽卡、氪金、PvP、账号系统、在线挂机收益、复杂制造系统、程序自动替玩家购买物品。游戏内自动打怪是单机玩法的一部分，**进程退出后不继续自动运行或计算离线收益**。

**原创性约束**：可借鉴经典斜角 RPG 的操作和玩法，但不使用《传奇》或其他游戏的受版权保护的角色、地图、名字、音效、贴图和代码。

## 1. 游戏愿景

### 1.1 核心体验

1. **成长感**：几分钟内能观察到等级或装备属性提升，力量变化可感知。
2. **打宝感**：普通怪有小惊喜；精英怪更值得打；Boss 有独特奖励和挑战。
3. **探索感**：进入新地图意味着新敌人、新资源、剧情与阶段目标。
4. **操作自由**：手动操作体验战斗，或在普通刷怪区域开启自动战斗与自动拾取。
5. **单机友好**：随时暂停/退出、离线游戏、本地保存，不以多人竞争或付费设计数值。

### 1.2 游戏核心循环

`探索地图 → 寻找/击败怪物 → 获得经验与掉落 → 升级、穿戴更好装备 → 挑战精英/Boss → 解锁下一区域 → 继续成长`

每个节点需要有明确反馈：命中/受伤动画、浮动伤害值、经验提示、物品掉落、装备比较、升级效果、Boss 奖励及地图解锁提示。

### 1.3 发布范围

| 内容 | 可玩 MVP（阶段 2） | 第一章完整版（阶段 3） | 远期完整剧情版 |

## 2. 世界观、章节与故事

### 2.1 世界背景

纪元 3172 年，灵气衰竭的末法时代。人类依靠科技建立繁荣文明，修行者成为传说。然而，大规模开发古代灵脉造成世界屏障损坏，紫色异界裂隙开启，异族军团入侵，城市沦陷，幸存者退守最后营地。

主角是一名在废墟中苏醒的年轻守护者，能够吸收异族消散时释放的灵能，并将其转化为战斗经验。主角承担夺回家园、查明裂隙真相、击败异族统帅的使命。

| 第三章 | 21–30 | 断刃矿脉 | 寻找锻造资源，揭示末法原因 | 熔岩魔将 |

## 3. 角色创建、操控及死亡规则

### 3.1 创建角色

首次进入可创建角色，输入名称（2–16 个字符），选择初始外观（先提供少量预设），职业固定为“灵刃战士”；初始等级 1，进入幸存者营地。正式版可加入职业与丰富外观。允许多个独立存档槽，第一版建议 3 个。

### 3.2 角色操作（macOS）

| 输入 | 功能 |
|---|---|
| `W/A/S/D` | 按屏幕方向移动；组合按键形成八方向移动 |
| 鼠标左键点击怪物 | 选中目标；手动操作时若超出攻击距离则尝试接近 |
| `Space` | 对当前目标普通攻击（开发期可调整键位） |
| `1 / 2 / 3` | 技能快捷栏；未解锁的技能不可使用 |
| `I` | 背包及装备面板 |
| `C` | 角色属性 |
| `M` | 地图 |
| `F` | 开关自动战斗 |
| `G` | 开关自动拾取 |
| `Esc` | 关闭面板 / 游戏暂停菜单 |

移动方向相对屏幕显示；斜向输入必须归一化，不能比直线移动快约 41%。玩家可随时通过键盘接管角色；当自动战斗已开启时，手动移动/攻击令自动行为暂时挂起，**连续 3 秒无手动输入后恢复**；界面明显显示“自动中/手动接管/暂停中”。关闭自动战斗后不得自动恢复。

### 3.3 角色死亡

首版：HP 降到 0 时进入死亡状态、取消目标与行动、停止自动战斗，随后由玩家选择“返回营地复活”。恢复满 HP/MP；不掉等级、不掉装备、不扣金币。后续如需加入死亡惩罚，另行评审，不隐式新增。

### 3.4 暂停与后台行为

打开暂停菜单时停止战斗模拟、敌人 AI、刷新计时和掉落过期计时。macOS 应用切到后台时默认暂停；恢复前台继续。退出游戏后不累积离线经验、金币或挂机掉落。

## 4. 等级、属性与数值初稿

### 4.1 基础属性

- `level`、`currentXP`、`requiredXP`。
- `maxHP/currentHP`、`maxMP/currentMP`、`attack`、`defense`。
- `criticalChance`、`criticalMultiplier`、`attackInterval`、`movementSpeed`。
- 预留：闪避、格挡、技能冷却缩减；MVP 未涉及的复杂机制不启用。

初始参数（需调优）：1 级角色 HP 100、MP 50、攻击 12、防御 5、暴击 5%、暴击倍率 1.5、普通攻击间隔 0.8 秒。每级基础 HP +12、MP +4、攻击 +2、防御 +1。装备与技能效果在基础属性之后叠加。

### 4.2 经验公式

升级 `L → L+1` 所需经验：`round(100 × L^1.6)`，每升一级扣除当次所需经验，剩余经验结转；一次获得大量经验时可连续升级。最高等级首版限制为 10，完整剧情版为 60；达到上限后不再升级。经验负值禁止输入。

参考值：1→2 为 100；5→6 约 1,313；10→11 约 3,981；20→21 约 12,068。**经验函数只是起始参数，必须用试玩时长测试平衡。**

### 4.3 战斗伤害（MVP）

物理伤害初稿：

`base = max(1, floor(attacker.attack × skillMultiplier - defender.defense × 0.5))`

随后按暴击率判定，暴击时 `damage = floor(base × criticalMultiplier)`；非暴击伤害为 `base`。不允许负伤害、HP 不得小于零。技能伤害系数可由技能等级提升。对敌人和玩家采用同一套可测试的伤害结算方法。

示例：攻击 20、目标防御 10、技能系数 1.5，则非暴击伤害为 `floor(30 - 5) = 25`。不将角色动画帧数作为伤害次数来源。

### 4.4 升级与成长体验

升级时更新最大 HP/MP、基础属性和需要的经验，显示升级特效和属性变化；同时保留当前 HP/MP 百分比（例如升级前 50% 血量，升级后仍为约 50%），避免隐式满血的平衡问题。技能在指定等级解锁。

| ID | 技能 | 解锁等级 | 作用 | MVP |
|---|---|---:|---|---|
| SK001 | 普通斩击 | 1 | 单体近战，系数 1.0 | 是 |
| SK002 | 裂地斩 | 5 | 前方扇形范围，系数 1.4，消耗 MP | 是 |
| SK003 | 旋风斩 | 10 | 角色周边范围，系数 1.2，消耗 MP | 是 |
| SK004 | 战意觉醒 | 15 | 临时提升攻击速度 | 否 |
| SK005 | 破甲重击 | 25 | 单体高伤害、短期减防 | 否 |
| SK006 | 灵刃风暴 | 40 | 大范围攻击 | 否 |

技能字段至少包括：ID、解锁等级、攻击类型、范围/半径、MP 消耗、冷却时间、伤害系数、动画标识。未解锁、冷却中、MP 不足、目标死亡或超出范围时不能执行技能并显示可理解的原因。

自动战斗首版规则：能够攻击时优先施放已解锁且可用的范围技能（周围命中至少 2 个目标），否则使用单体技能或普通攻击；不能通过高频循环绕过冷却时间。初版无复杂技能加点与洗点。

## 6. 装备与背包系统

### 6.1 十个装备槽位

| 槽位 | 主属性定位 |
|---|---|
| 头盔 | 防御、生命 |
| 服装 | 防御、生命 |
| 武器 | 攻击、攻击速度 |
| 护肘 | 攻击、防御 |
| 护膝 | 防御、生命 |
| 盾牌 | 防御、格挡（MVP 可只提供防御） |
| 鞋子 | 移动速度、防御 |
| 手镯 | 攻击、暴击 |
| 戒指 | 攻击、生命 |
| 项链 | 生命、法力 |

初版只能穿戴一件每类物品，戒指只有一个槽位，避免“左右戒指”歧义。武器与盾牌允许同时装备。装备后需要立即更新派生属性，不允许基础值被永久污染。卸下装备需要背包有空位。

### 6.2 装备品质与词条

品质为 `common / uncommon / rare / epic / legendary`（普通灰、优秀绿、稀有蓝、史诗紫、传说橙）。装备记录必须区分**模板 ID**和**实例 ID**；同一模板生成的两个物品可有不同词条。

- 普通：只有基础属性。
- 优秀：可有 1 条随机附加属性。
- 稀有：可有 1–2 条。
- 史诗：可有 2–3 条。
- 传说：可有独特被动效果；首章仅提供预留数据结构，不强制实现复杂特效。

要求等级低于装备 `requiredLevel` 时不能穿戴。装备的属性随机范围由配置决定；生成后作为实例属性永久保存，不能每次打开背包重新随机。

### 6.3 背包与消耗品

初始背包 40 格。装备不可堆叠、药品/材料最多堆叠 99；装备与药品均需要占用背包格数，**已穿戴装备不占背包格**。背包支持查看、比较、穿戴、卸下、使用药品、丢弃（带二次确认）、自动整理。

MVP 药品：初级生命药水，恢复 50 HP，6 秒公共使用冷却；恢复量不得超过最大 HP。后续增加 MP 药水和强化版本。金币独立存储，不占用背包。

自动拾取开启时，角色向距离近且可到达的战利品靠近并拾取；关闭时只能手动拾取。目标距离拾取点 ≤ 1.5 个逻辑格方可完成拾取。金币、药水、装备适用同一总开关，后期可加品质过滤。背包满时，物品保留在地上并显示提示，不覆盖已有物品。地面掉落在**运行且未暂停**的 180 秒后消失；切地图时清理当前地图地面掉落。单机不存在归属权争抢。

## 7. 怪物、战斗及掉落

### 7.1 怪物类型

- 普通怪：分布密集，提供稳定经验与金币。
- 精英怪：血量和攻击提升，有明显外观标识、至少一个特别攻击，奖励更优。
- Boss：剧情/副本触发，有独立血条、技能预警、阶段行为和首次通关奖励。

第一章建议：腐化野狼（近战）、裂壳虫（高防）、灰烬游魂（远程或缓慢追击）；精英“裂爪狼王”；Boss“腐化巨兽”。

### 7.2 怪物状态

`spawn → idle/patrol → aggro → chase → attack → (return) → dead → respawn`。

每种怪物配置警戒半径、最大追击半径、攻击范围、攻击间隔、出生区域和刷新间隔。怪物离出生区域太远时停止追击并返回；怪物死亡后只触发一次击杀事件、经验奖励、掉落和任务进度，不允许重复结算。

### 7.3 首版掉落概率（可调，独立判定）

| 目标 | 金币 | 药品 | 任意装备 |
|---|---:|---:|---:|
| 普通怪 | 100% | 15% | 8% |
| 精英怪 | 100% | 40% | 40% |
| Boss 重复击杀 | 100% | 70% | 65% |

上表的“装备概率”是**是否出现一件装备**，出现后才按怪物等级、掉落表、品质权重、模板和词条抽取；不同奖励通道相互独立，不保证三者互斥。Boss 首次通关额外保证一件满足角色等级的**稀有或以上**装备，单独标记 `firstClearClaimed`，不得重复领取。

第一章品质权重初稿：普通怪的装备品质为普通 75%、优秀 22%、稀有 3%；精英怪为普通 40%、优秀 45%、稀有 14%、史诗 1%；Boss 为优秀 20%、稀有 60%、史诗 19%、传说 1%。MVP 可以将尚未制作的传说模板回退到同章史诗模板，但必须显式记录规则，不能随机生成无效物品。

### 7.4 Boss 设计：腐化巨兽

- 生命 100%～60%：普通追击和爪击。
- 生命低于 60%：周期性使用范围践踏，在伤害前显示明显地面警示。
- 生命低于 30%：短期狂暴、攻击速度增加，并召唤少量普通怪。
- Boss 被击杀：结算第一次通关奖励、推进任务 Q005、解锁第二章入口。

Boss 在剧情上可以重复挑战；重复挑战不再发放首次通关任务奖励。

## 8. 自动战斗与自动拾取（核心功能）

### 8.1 原则

自动系统只能调用与玩家相同的移动、寻路、技能、喝药和拾取接口，不得直接瞬移、无距离攻击、无冷却施法、从远处直接获得掉落。自动功能**默认关闭**，玩家主动开启。

### 8.2 玩家自动战斗状态机

建议定义：

`off / searchTarget / pathToTarget / attackTarget / searchLoot / pathToLoot / pickUp / recover / manualOverride / blocked`

状态流：

1. 检查玩家存活、未暂停、自动开关开启。
2. 如果 HP ≤ 配置阈值（初始 35%），尝试使用有库存且不在冷却的药品；若无法治疗且 HP 很低，可停在 `recover/blocked` 并提示，不能无限自杀式送怪。
3. 在**挂机锚点**附近、初始半径 12 逻辑格内搜索存活且可到达的普通怪/精英怪，默认排除 Boss。
4. 优先选择寻路代价较低的目标；同距离优先较弱目标，防止跨地图追怪。
5. A* 寻路接近目标；若目标死亡/失效/进入不可达区域，立即取消并重新选择。
6. 距离达到有效攻击范围后选择技能、攻击直至目标死亡、逃离或中断。
7. 击杀后如自动拾取开启，拾取拾取半径/挂机区域内可到达物品；然后继续搜索怪物。
8. 无有效目标时待机/小范围巡逻，避免每帧重新寻路。

挂机锚点为开启自动战斗时所在位置。角色不得因追逐目标离开半径超过 12 格的活动区（允许路径局部偏移，但超过限界要回归）；传送/手动切图后若继续开启自动战斗，重新设置锚点。所有半径初稿皆可调。

### 8.3 交互设置

- 自动战斗开关 `F`。
- 自动拾取开关 `G`。
- 是否允许挑战 Boss：默认否，需玩家明确开启。
- 血量低于百分比自动喝药：默认 35%，可在设置中修改。
- 搜索半径：默认 12 格；可在 3–30 格间设置，受地图约束。
- 自动拾取品质过滤：第二期加入；MVP 默认拾取全部。

### 8.4 异常处理硬性规则

- 寻路返回空、终点被障碍占据或连续 3 次无法推进：目标加入短期黑名单（例：10 秒），重新搜索。
- 目标消失、死亡、传送或切地图：停止对旧实体下发操作。
- 战斗途中手动控制：立刻取消自动当前指令，3 秒无输入后再尝试恢复。
- 背包满：停止拾取该物品，提示用户，仍可继续战斗；不能循环到同一物品卡住。
- 技能 MP 不足：回退到可用技能/普通攻击。
- 药品不足：给出提示；达到危险血量则停止主动寻怪。
- 玩家死亡：自动战斗切换到 `off`。
- 暂停/后台：停止自动决策与游戏时间推进。
- Boss 的范围技能不能由无敌帧或自动算法跳过，若允许自动挑战 Boss，也承担相同伤害风险。

## 9. 地图、坐标、移动、寻路与渲染

### 9.1 视觉与地图格式

采用 2D 等距斜角（isometric）瓦片地图；候选地表瓦片尺寸为 **64×32 像素**（逻辑资源尺寸，实际显示可按屏幕缩放）。地面、装饰、遮挡、碰撞、交互触发、出生点、刷新点、导航信息应分层储存。

瓦片逻辑坐标 `(col,row)` 对应屏幕坐标的示意转换为：

`screenX = (col - row) × tileWidth / 2`  
`screenY = -(col + row) × tileHeight / 2`

上述 Y 方向为“向下画地图”的约定，实际 SpriteKit 场景坐标需统一定义，不得在不同系统中自行颠倒轴向。**游戏逻辑位置统一采用世界/网格坐标，绘制坐标在渲染层转换。**

### 9.2 八方向移动

- WASD 为屏幕相对方向；组合键提供八向。
- 对输入向量归一化，保持所有方向的**世界空间速度**一致。
- 网格用于地图阻挡与寻路，角色视觉运动可插值实现连续位移。
- 碰撞以角色脚底/地面碰撞体为准，不用整个立绘包围盒进行走路碰撞。
- 斜向寻路不得穿越两侧均阻挡的地图格角落（禁止 corner cutting）。

### 9.3 寻路

首选采用 `GameplayKit.GKGridGraph` 等工具构建静态通行网格；是否自定义 A* 由实际需求决定。地图障碍动态改变时需要更新寻路图。常规移动路径重新计算需有节流机制，不得每个渲染帧为全部怪物算路。

### 9.4 遮挡与镜头

玩家、怪物、NPC、树木等动态/高物体按**脚底 Y 坐标**或确定的深度规则排序，使前后遮挡正确。静态瓦片按图层层级绘制，不能假设 `SKTileMapNode` 每个瓦片都可独立设置 zPosition。摄像机平滑跟随玩家，防止露出地图边界。

### 9.5 地图加载与入口

进入地图时读取静态定义、创建场景实体、确定出生点和怪物刷新器；离开时释放旧场景实体、取消旧地图的计时器/自动 AI 引用，保存需要持久化的任务/Boss 信息。地图入口有解锁条件并明确提示失败原因。

## 10. UI/UX、音效和美术

### 10.1 主界面区域

- 左上：角色头像、等级、HP/MP、当前经验进度。
- 右上：地图名、小地图入口、任务摘要、设置入口。
- 底部：技能快捷栏、药品快捷槽、自动战斗与自动拾取状态。
- 背包弹窗：道具网格、金币、装备栏、悬浮属性对比。
- 世界画面：伤害数字、怪物血条、地面战利品图标、掉落提示。

在高分辨率 Mac 屏幕上 UI 应可缩放，避免 2D 场景随窗口大小变化导致布局溢出。游戏分辨率先以 1440×900 的可用视区为设计参考，同时支持窗口化调整大小。

### 10.2 美术方向

首版采用**原创复古像素风 / 斜角 2D**，允许临时几何形状、色块或自制占位素材；不要等待所有美术完成后再开发逻辑。正式资产由统一方向、尺寸、锚点、透明背景和命名规则管理。

人物动画计划：八方向待机、移动、普攻、受击、死亡；技能动画按需要扩展。可适当镜像复用，但武器手持与盾牌位置必须检查。**MVP 换装备只改变数值，不实时更换角色精灵外观。**

### 10.3 音效与可访问性

最少包含攻击命中、受伤、怪物死亡、拾取、升级、装备、Boss 警示等反馈。设置支持分别调整音乐与音效音量、关闭屏幕震动/闪烁强效果、UI 缩放。不能让声音成为唯一提示方式。

## 11. 单机存档与数据可靠性

### 11.1 存档数据

存档至少记录：`schemaVersion`、`slotId`、`savedAt`、角色基础信息/等级/经验/血量、技能解锁、背包**装备实例**、已穿戴实例、金币、当前地图与坐标、任务状态、首次 Boss 击杀标记、用户设置与自动开关状态。

**游戏再次启动时自动战斗默认保持关闭**，即使退出前开启，也不应打开游戏立即攻击。读取旧存档需要迁移，未知/损坏数据要有明确错误提示并保留备份。

### 11.2 保存策略

- 关键事件即时触发保存：升级、重要物品获取/穿戴、任务领取/完成、切地图、Boss 首杀。
- 常规每 120 秒自动保存（游戏非暂停状态时计时）。
- 退出游戏时保存；写入临时文件成功后原子替换主存档，并保留至少一个最近有效备份。
- 文件写入期间不可产生部分截断的主档；写入失败要提示，不可静默丢失进度。
- 玩家数据需序列化为稳定类型，不直接持久化 SpriteKit 节点或运行时对象。

### 11.3 本地数据安全

游戏无需云端授权、登录或网络访问。建议将存档放在应用专属用户数据目录，并提供“打开存档目录”与可选手动备份入口；不要求玩家自行编辑配置才能玩游戏。

## 12. 技术架构与模块边界

### 12.1 技术栈

- 语言：Swift。
- 渲染、动画与场景：SpriteKit（`SKScene`、`SKSpriteNode`、`SKTileMapNode`、`SKCameraNode`）。
- macOS UI：SwiftUI；必要时通过 AppKit 处理窗口、焦点、输入适配。`SpriteView` 可承载 SpriteKit 场景。
- 2D 寻路辅助：GameplayKit（如 `GKGridGraph`）。
- 内容配置：JSON + `Codable`，技能、怪物、掉落表、地图、任务与装备都走配置驱动。
- 存档：本地 JSON + 版本化数据模型 + 原子写入；首版不引入数据库。
- 构建：Xcode；测试：XCTest/Swift Testing（根据项目工具链确定）。

官方技术文档：
- SpriteKit Tilemap：https://developer.apple.com/documentation/spritekit/sktilemapnode
- SpriteKit TileSet：https://developer.apple.com/documentation/spritekit/sktileset

│   ├── Models/          # GameState、角色、怪物、装备、物品实例
│   ├── Combat/          # 伤害、冷却、技能效果、仇恨
│   ├── Progression/     # 经验、等级、属性推导
│   ├── Inventory/       # 背包、穿戴、交易操作

### 12.3 工程原则

1. **规则与画面分离**：数值结算不能依赖动画帧事件、UI 或 SpriteKit 实例。
2. **单一真实状态**：战斗、背包、穿戴、任务都修改同一个受控游戏状态，视图只反映它。
3. **事件驱动**：`monsterKilled`、`itemCollected`、`levelUp`、`bossFirstCleared` 用于任务、音效与 UI，不得重复广播奖励。
4. **时间步固定/限幅**：区分模拟时间和渲染帧率，大量卡顿后避免角色瞬移或瞬间多次攻击。
5. **随机可测试**：战利品生成注入随机数生成器或随机种子；测试能验证概率权重和实例合法性。
6. **配置有校验**：启动时验证 ID 唯一、掉落表权重、引用合法、等级范围、技能参数，防止空模板导致崩溃。
7. **不要过度设计**：首版不引入服务端、通用脚本引擎、ECS 框架大改造或无限扩展插件系统。

## 13. 质量、性能与测试验收

### 13.1 第一版目标

- 1440×900 的 Mac 窗口中，普通战斗场景争取稳定 60 FPS；具体负载和测试机器须记录。
- 在 30 个左右同时存在的敌人与常规效果下，不能出现明显持续卡顿。
- 打开背包/切图/连续击杀不能持续增长内存，不能重复注册事件或定时器。
- 玩家离开游戏并重新加载后，等级、背包、装备实例属性、金币、任务与地图位置一致。
- 自动打怪连续运行 30 分钟不会卡死在墙边、无限重选不可达目标或无限尝试拾取满背包物品。

### 13.2 必须覆盖的测试场景

| 测试编号 | 场景 | 必须满足的结果 |
|---|---|---|
| T01 | WASD 任意方向移动 | 八向操作正确，斜向速度不超标 |
| T02 | 角色撞到墙 | 不能穿墙，贴墙移动可控 |
| T03 | 斜向穿越两格障碍夹角 | 不得斜切穿障碍 |
| T04 | 重复攻击同一死亡怪物 | 只结算一次经验、掉落和任务计数 |
| T05 | 满足经验阈值 | 正确升级、多余经验结转 |
| T06 | 穿戴/卸下装备 | 属性实时正确，装备实例不复制丢失 |
| T07 | 掉落品质随机 | 品质合法、词条范围合法、权重总和通过校验 |
| T08 | 目标在不可达区域 | 自动打怪改选目标，不永久卡住 |
| T09 | 自动打怪期间手动操作 | 立即接管，3 秒后按规则恢复 |

### 13.3 可观测与调试

开发版提供可开关的调试覆盖层：FPS、实体数量、当前目标 ID、AI 状态、路径节点数、挂机锚点/半径、最近一次行为失败原因。游戏日志对存档失败、配置引用错误和循环路径异常给出清晰信息。

## 14. 分阶段开发交付与准入准出标准

### P0：工程初始化与规则骨架

- Swift macOS 可运行空项目，嵌入 SpriteKit 视图。
- Core/ 渲染/UI/存档分层；建立基础配置加载与校验。
- 建立单元测试与最基本构建命令，能在本地复现。
- **通过标准**：全新环境执行文档中的构建命令可成功启动示例场景。

### P1：地图、移动、怪物、手动战斗（技术原型）

- 斜角瓦片、障碍碰撞、WASD 八向移动、摄像机和前后遮挡。
- 一种怪物的巡逻、追击、普攻、死亡与刷新。
- 玩家攻击、生命与伤害显示。
- **通过标准**：玩家可以绕过障碍击败怪物，无法穿墙/斜穿障碍，死亡事件只结算一次。

### P2：完整可玩 MVP（优先级最高）

- 等级经验、十装备槽、背包、装备实例、金币、药水、随机掉落。
- 自动寻怪、A*、自动战斗、自动拾取和挂机区域控制。
- 至少 2 个技能（普攻之外）、本地存档和重载。
- **通过标准**：能够持续刷怪 30 分钟，自动行为无死循环，装备真实提升战斗力，退出重进数据不丢失。

### P3：第一章剧情版本

- 幸存者营地、灰烬之地、Boss 区域；3 普通怪 + 1 精英 + 1 Boss。
- 第一章 5 个任务、对话、剧情触发、Boss 阶段技能与首次通关奖励。
- 10 级成长闭环、约 20 个装备模板、美术/音效初步完善。
- **通过标准**：新角色可由 1 级完成全部第一章任务，击败 Boss 并解锁下一章节入口。

### P4：内容扩张（第二章至终章）

- 按章节逐步新增地图、怪物、装备、技能、剧情、Boss 机制。
- 在前一章节数据和玩法完成测试后，再新增下一章节。
- **通过标准**：1–60 级剧情、地图入口、Boss 奖励和最终结局贯通。

### P5：正式版打磨

- 更换正式原创美术、音效、平衡数值、适配多种 Mac 屏幕与缩放。
- 存档升级兼容、稳定性/性能测试、安装包与签名流程。
- **通过标准**：关键功能测试通过、无阻塞型 Bug、可干净安装和运行。

**阶段工作纪律**：每个阶段应有独立 Codex 开发任务、范围说明、测试与实际验收记录。未通过当前阶段，不同时开启后续章节的批量制作。

## 15. 第一版尚需确认但不阻断启动的问题

下列事项按本版默认值实现，未来可在不改核心架构的前提下调整：

1. 美术：先复古像素占位素材；正式美术采购/生成另行确定。
2. 职业：仅战士；新职业不是第一章验收条件。
3. 背包：40 格；每种药品堆叠 99。
4. 死亡：无经验/金币/装备惩罚。
5. 自动挂机：默认关闭、12 格寻怪半径、35% 血量喝药、默认不打 Boss。
6. 经济：首版金币仅购买药品或基本商店物品；强化、锻造后续加入。
7. 版本策略：macOS 优先，未来若移植 iOS，需要重做触控适配与界面尺度设计。
8. 配置调参：先确保功能正确，再通过实际击杀耗时、升级耗时和掉落统计调平衡。

## 16. Codex 实施原则（写入项目协作规则）

1. **先阅读完整 GDD**，不得私自扩大范围或改变核心规则。
2. 每次只实现一个可验收功能集合；开始前说明涉及的文件与风险。
3. 修改业务规则时优先补充单元测试，使用固定随机种子校验掉落与伤害。
4. 渲染层不能直接更改存档结构；存档层不能引用 SpriteKit 节点。
5. 使用占位资产可以，但必须能真正启动、移动、攻击，不允许用静态截图冒充可玩功能。
6. 不为尚未实现的后期系统提前引入大型抽象或外部依赖。
7. 完成每一步时汇报：实现内容、构建结果、自动测试、手动验收步骤、遗留风险。
8. 遇到系统 API、引擎能力不确定时，先验证最小可运行样例再大规模开发。
